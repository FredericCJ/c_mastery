# C Mastery authoring constitution

## Principles

1. **Contract before implementation.** Follow system requirement, abstract contract,
   algorithmic argument, C representation, failure behavior, hardware observation,
   revised design and independent transfer.
2. **Preserve depth.** Retain in-scope objectives and first-principles mechanisms.
   Repeated encounters add distinct obligations. No hour/exercise quota replaces
   evidence of understanding.
3. **One authority.** The active manifest selects the route; canonical catalogs,
   contracts and disposition sources own identity/state. Specifications and tasks
   link to those records without superseding them.
4. **Separate claims.** Source/schema checks, author execution, hardware measurement
   and independent human assessment remain distinct. Unavailable inputs and
   inconclusive results never become passing evidence.
5. **Public reproduction and solution boundaries.** Public validation works without
   private captures. Stronger author/release gates remain mandatory for their
   claims. Learner exports exclude assessor solutions and withheld tasks.
6. **Continuity.** Continue the approved revision, preserve unrelated work/history,
   and make no unsolicited commits, pushes, remote uploads or privileged changes.

7. **One readable house style.** All C in labs/ and assessor/ follows
   curriculum/guides/c-style.md (BARR-C:2018 layout, SEI CERT C conversions,
   context-dependent MISRA C:2023 rules, Linux kernel style for kernel modules),
   enforced by the pinned clang-format and tools/check_c_style.py. Formatting,
   renaming and semantic changes are separate, equivalence-checked steps.

## Implementation and verification

Preserve the C17 baseline and manifest target dependency rules. Separate language,
compiler, ABI, OS and hardware facts. Edit generators with canonical inputs. Use
independent small models, failure injection and meaningful negative controls. Run
focused checks and source-bound final integration. Tools do not imply acceptance.

## Governance

Explicit user instructions and existing authorization take precedence over generic
workflow defaults. Keep the canonical obligation and migration records authoritative.

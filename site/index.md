# C Programming Mastery

Build small C components, explain their behavior, and carry them into Linux systems and Cortex-M firmware.

Start with {ref}`guide-entry`, then use the {ref}`guide-roadmap` to select the next evidence gate. The curriculum has **45 domains, 497 topics and 1,491 objectives**, preserving the original definitions and both earlier editions. Numbered domains are coverage keys; prerequisites determine the learning order.

Use {ref}`guide-enhancement` for the assembly-to-abstraction progression and {ref}`guide-communication-stacks` for the three complete communication project families: a seven-layer educational protocol, Ethernet through HTTP, and an HTTP server over operating-system sockets.

Use {ref}`guide-performance-debugging` for complexity models, hosted/bare-metal profiling, component and I/O measurements, progressive debugger practice and memory-failure experiments. Reuse earlier components; predict, observe, explain, repair and retest a changed case.

Use the module catalog for teaching notes and bounded readings, then open a project for its contract, inputs, expected results, hints and acceptance evidence. Supplied fixtures are downloadable on each project page. Search supports topic IDs as well as names.

The default portable baseline is C17, with parallel C23 investigations. Linux x86-64 and NUCLEO-F439ZI share a portable core. QEMU MPS2 AN386 is a separate emulated target with its own limits. Hardware gates require actual hardware evidence.

Read {ref}`guide-laboratory` for the learner repository, build/test profiles and local handbook rebuild instructions. Read [research and source selection](research/index.md) for the staged search, reflection and passage-verification record.

# Integration synthesis and authoring follow-ups

The three focused searches support seven added domains. The SWE and data-structure graphs supplied discovery leads; actual held passages and official primary documents supplied teaching authority. Existing T14/T15/T18 implementations remain the reusable base. The extension adds narrow handwritten assembly kernels, invariant and representation certificates, architecture models, interface adapters and protocol state. This keeps the project work small while exposing the complete progression from a mathematical relation to a public C contract.

The source hierarchy matters. Textbooks explain mechanisms; historical papers supply their original arguments and assumptions; ISA/ABI, MCU, board, transceiver and PHY documents establish different machine boundaries. X.200 defines a reference model rather than a wire suite. Internet RFCs establish their own protocol obligations. EDU7-v1 is therefore an explicitly original seven-layer teaching protocol. The Ethernet-to-HTTP family implements a restricted Internet subset; the hosted HTTP family receives its lower stack from the OS. Each family publishes implementation ownership and separate physical, synthetic and actual execution gates.

The searches also identified reasons to exclude or narrow sources. A secondary communications overview reversed SPI signal direction and CAN dominant values; it was rejected as teaching authority. A newer board manual was discovered without deep Ethernet passage inspection; its identity is a lead, while the exact inspected earlier edition remains the bounded board source. The selected F439 provides classic bxCAN, an external Ethernet PHY route and CPU-only CCM for the studied DMA boundary. Another core's cache behavior or a CAN FD transceiver cannot silently supply missing device capabilities. A physical FD extension needs an actual controller, correct separate supplies and additional exact setup inspection.

Necessary authoring follow-ups were kept bounded and returned through research review. The same RM0090 revision's detailed normal Ethernet descriptors and selected registers resolve a conflicting summary reference and support exact ownership, polling and ring operations. A further SMI/MII register inspection supports MDIO clock, address, busy and data-valid obligations. RFC1952's appendix supports the declared reflected CRC arithmetic oracle only; it is not Ethernet framing or IEEE conformance authority. The scoped gate pins these additional records before publication.

The custom transport/session design now distinguishes matching fragment ACKs, completed-transfer receipts, retained upper messages, dialogue-token handoff and application checkpoint commitment. Transfer IDs do not wrap within a session; one bounded last-final receipt prevents a lost final ACK from publishing the message twice. TOKEN_PENDING prevents both endpoints from starting new dialogue during an uncertain handoff. RAM-only resume refuses a peer that lost its state. These are original protocol decisions, not properties inferred from the OSI model.

The HTTP audit separates malformed framing from unsupported decoding. Under the inspected RFC 9112 sections 6.1/6.3, a request without final chunked transfer coding receives 400 and close; a valid unsupported preceding coding followed by final chunked receives 501 and close. The original strict syntax profile and resource limits are identified separately. HEAD suppresses response content even for errors; route-specific Allow and representation length remain metadata. Interim 100 responses preserve pipelined request association. The inspected RFC 9931 update supplies scoped transition-security background; rejecting unsupported CONNECT/Upgrade and closing is the original origin-server policy.

Independent review and reproducible publication follow source acceptance. The original inputs, taxonomy, 207 project briefs and 194 fixture files are preserved; changed base lessons contain bounded extension handoffs. New fixtures verify finite arithmetic, byte layouts and state policies. They do not execute learner C, establish electrical/PHY observations or certify general protocol conformance. The final receipts distinguish source support, teaching review, publication checks and archive rebuilding from those future learner activities.

# Networking enhancement research synthesis

Research recommends three separate project families with explicit ownership and evidence boundaries. The proposed taxonomy has eight substantive topics and 24 measurable objectives per domain. The original contracts in `networking_contracts.json` define bytes, capacities, addressing, routing and state policies before teaching authoring. They contain no solved C implementation. Research inspection and design are complete enough for a scoped teaching gate; physical execution and learner implementation have not occurred.

The authoritative spine has 22 bounded records. X.200 supplies layer/service purpose vocabulary. Current and historical RFCs supply precisely identified protocol contracts and conformance limits. ST and Microchip passages establish actual controller, board and PHY boundaries. TI passages establish the declared RS-485 transceiver and medium constraints. Two held edition-specific textbook passages explain layering and short stream I/O. The IEEE contribution is an architecture supplement, never a normative Ethernet compliance certificate. Each record lists only inspected locators and preserves its limitations.

T40 demonstrates seven explicit educational layers using EDU7-v1. It is an original protocol, rather than an implementation of ISO's OSI protocol suite. The lab has A—R—B across two physically distinct RS-485 segments; R relays at the network layer and has two independent UART/transceiver interfaces. Segment-local link addresses differ from network node IDs, transport ports, session IDs/checkpoints, presentation schema and application request IDs. This makes routing and encapsulation observable: R changes the next-hop frame/CRC and hop limit while preserving end-to-end addressing and transport/session/presentation/application payload.

The physical adapter uses THVD1400 at 3.3 V, bounded short twisted-pair segments, two end terminations per segment and master-granted half-duplex turns. Actual voltage, bit timing, direction control after the final stop bit, contention avoidance and cable loss must be captured. Host-injected octets prove none of those physical facts. L2 uses a bounded delimiter/escape/CRC format. L3 has an exact static route table and hop limit. L4 segments/reassembles complete messages with matching fragment acknowledgments, bounded retries, credit and probe state. L5 negotiates schema/units, controls dialogue token and resumes retained RAM checkpoints independently of transport transfer IDs. L6 canonical TLVs encode typed values independently of host struct layout and validate units/UTF-8/range before publication. L7 implements bounded fixture GET/SET semantics and unchanged-state errors. Session resume explicitly fails after lost peer state; it is neither authentication nor durable exactly-once execution.

The recommended T40 milestones are: (1) service/ownership map and full nested trace, 4h; (2) actual two-segment physical adapter and grant schedule, 8h; (3) framing/CRC and recovery, 6h; (4) routed relay with hop/route faults, 6h; (5) segmented reliable/credit-controlled transport, 10h; (6) session token/checkpoint/resume, 8h; (7) canonical representation and original application contract, 8h; (8) integrated physical/fault evidence, 8h. These 58h are implementation plus verification only; theory, reading and assessment categories will be budgeted separately in the module. They are eight milestones of one family, counted once.

T41 implements a custom minimal embedded Ethernet-to-HTTP stack on the declared NUCLEO-F439ZI and LAN8742A. The STM32 ETH peripheral owns MAC/DMA; the external PHY, magnetics, connector and cable perform actual physical signaling. Cortex-M software constructs and validates Ethernet/IP/TCP content and manages descriptors; writing an Ethernet byte array does not implement analog Ethernet signaling. RMII is a digital MAC–PHY boundary and its 50-MHz clock is not the cable's raw bit waveform. Negotiated PHY speed/duplex must agree with MAC mode before service readiness.

The controller source scope covers actual MAC/frame features, RMII selection, initialization and selected normal descriptor ownership/length/error operations. The adapter deliberately retains RX CRC bytes and subtracts four exactly once when exposing the frame span; IPv4 total length excludes Ethernet padding. OWN transfer requires complete buffer/descriptor publication and memory ordering, plus DMA-accessible placement. Before authoring extra bit-specific register assignments, the researcher must inspect those exact register passages and extend this ledger. Prior driver/DMA leaf material remains a prerequisite; a complete supplied vendor Ethernet driver cannot stand in for the custom implementation.

T41's controlled link uses static documentation-prefix addresses, one configured peer, untagged Ethernet II, bounded ARP resolution, fixed IPv4 headers and unicast ICMP echo. It emits atomic IPv4 datagrams, where RFC6864 permits an arbitrary ID, and treats ID as no duplicate-message oracle. Incoming IP options/fragments and most ICMP services are explicitly omitted. RFC1122 requires host reassembly, and RFC791 requires options implementation, so successful same-link HTTP is not a full Internet-host conformance claim. Old RFC791 Type-of-Service encodings are not taught as current DSCP/ECN.

TCP is a passive-open, one-connection teaching profile. It verifies the mandatory checksum/pseudo-header, parses bounded options and MSS, uses modular sequence arithmetic, validates ACK/window bounds, retains exactly the accepted in-order byte stream, handles duplicates/prefix overlap and drops out-of-order gaps with duplicate ACKs. One unacknowledged segment gives conservative sending, not evidence of general congestion recovery. Receive-window pressure and zero-window probes remain real state. The timer follows inspected RFC6298 estimator/update/sample/backoff rules; the 60s maximum cap is distinct from a finite application resource timeout. FIN consumes sequence space, peer half-close is not HTTP body termination, and physical TIME-WAIT retains the declared 2MSL duration. Virtual clocks speed deterministic tests without changing the actual physical contract. General simultaneous-open/event/congestion coverage remains excluded.

The recommended T41 milestones are: (1) subset/API/packet contracts, 4h; (2) actual PHY/RMII readiness and fault capture, 8h; (3) custom bounded MAC/DMA rings, 10h; (4) Ethernet/ARP state, 8h; (5) IPv4/checksum/echo, 8h; (6) handshake/sequence/close state, 12h; (7) loss/timer/flow traces, 12h; (8) reuse HTTP core and close actual cable/interoperability evidence, 10h. Total implementation plus verification is 72h. This is substantial original stack work, so implementation complexity is split across separate bounded chunks rather than hidden in a single nominal small project.

T42 starts at OS sockets. Its original C owns HTTP parsing, routing, serialization, buffer/descriptor lifecycle, deadlines and output queues; the OS owns TCP/IP and lower layers. It introduces the shared portable HTTP core first, which T41 later adapts to its custom TCP service. That dependency direction avoids a cycle and counts parser hours only once. Root owns T42 authorship. The proposed eight topics cover socket lifecycle, incremental grammar/authority, framing, chunks/trailers, semantics, persistence/output, deadlines and parsing/interoperability evidence. Suitable milestones are a 4h contract trace followed by seven 6–10h increments, with separate implementation and verification budgets made explicit by its author.

The shared HTTP profile has GET/HEAD `/health` with representation hex `6f6b0a`, POST `/echo`, exact octet lengths, bounded origin and absolute-form authority, single valid Host and strict syntax policy. RFC9112's origin-server absolute-form requirement informed the added bounded support. Chunked data is decoded incrementally; extensions are bounded and ignored only after syntax validation, while trailers stay separate and cannot replace framing/routing headers. TE+CL and duplicate Content-Length are rejected and connection closure is mandatory policy. Admissible 100-continue gets an immediate interim response or a header-determined final error. Persistence/pipelining preserve FIFO response order and bounded backpressure; close policy stops later dispatch and stages output shutdown/drain to avoid losing the final response. Date uses root's separately inspected injected-clock generation scope. Plain loopback HTTP includes no TLS, proxy, filesystem or Internet deployment claim.

The current RFC Editor identity shows RFC9112 updated by RFC9931 (March2026). Its inspected optimistic CONNECT requirements apply to proxy transitions; they are not falsely recast as all origin-server obligations. Our unsupported CONNECT/Upgrade policy closes and never dispatches following optimistic bytes as another request. Packet segmentation, socket read boundaries, HTTP messages and application representations remain different units. The Linux adapter must preserve offsets under short recv/send, EINTR and EAGAIN; POLLHUP can coexist with buffered readable data. Successful send means local acceptance, not peer application processing.

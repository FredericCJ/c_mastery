# Algorithms and architecture enhancement research synthesis

Research completed 2026-10-09. This is a source and scope proposal for the enhancement research gate. No T36/T37 teaching modules, project contracts or solved C implementations have been authored.

## Evidence and discovery boundaries

The two reference graphs were read across their canonical corpus and relation collections, including SWE works present only in elements. The actual snapshot contained 110 data-structure nodes and 1,257 distinct SWE works after ID deduplication. Twenty Knowledge metadata searches exposed strong held coverage of algorithm analysis, C interfaces, assembly and architecture. Broad `algorithm` and `architecture` searches reached their 100-result limit; this is useful discovery, not a complete-library absence test. Focused named works and actual passages followed the saved reflection. No Knowledge payload, metadata, database, pointer or registry was edited, and opaque documentation packages and `_old` were excluded.

The data-structure graph is a lineage map. `verified` origin metadata does not mean that a passage was read, and an editorial/derived edge is not a quotation from a paper. Arrays, linked representations and queues retain diffuse or folklore provenance when the graph says so. A textbook exposition is not relabeled as an invention. Exact editions and bytes distinguish library copies; historical F:/Cours paths were rebased only after the ordinary file existed at the current root. Current Knowledge pointer/manifest identities, registry hash and graph hashes are pinned privately. Raw book text and local library paths stay private.

The public resource contribution contains eight new resources, five expanded inspected records and three unchanged inspected-scope reuses. The latter reuses retain their previous inspection dates. New inspection claims identify actual headings and bounded pages, rather than chapters found only in contents. Publisher records resolve Hennessy/Patterson's sixth-edition publication to November 2017 despite the held copyright2019, and Plantz's ARM edition to December2024 despite copyright2025. Those differences are retained rather than silently collapsed.

## Resulting source spine

T36 begins with Knuth's Algorithm E, gcd-preserving state changes and decreasing positive remainder. Hoare's accepted small-language reasoning and Dijkstra's accepted stepwise-refinement passages provide historical contrast; neither establishes modern C object or arithmetic semantics. CLRS4 supplies insertion invariants, the RAM cost model, moving heap violations, probe coverage/deletion, BFS frontiers and bounded naive string matching. The original Dijkstra1959 paper was inspected in full from its originating institution's archive: its tentative/settled sets supply an origin mechanism for shortest-path refinement and distinguish the spanning-tree problem from the shortest-path problem. Modern nonnegative weights, unreachable vertices, distance overflow and heap costs remain explicit adaptation obligations.

Hanson Chapter2 now has actual inspected interface, implementation, opaque-type and client-responsibility passages. These explain how one contract can support a typed implementation, an assembly kernel and a context/callback adapter. The historical division example requires correction for C17. Morin's already inspected linear-probing section supplies a second explanation of tombstones and conditional expected/amortized reasoning. Neither text permits casting an aligned declared unsigned-char array to arbitrary T pointers: preserve the earlier T14/T16 byte-copy/actual-typed-array/genuine-allocated-backing distinction.

The machine spine is narrow: Intel SDM revision093 register/address/flag definitions plus CMP/Jcc entries; pinned AAPCS32 release2025Q1 register and stack constraints; and exact Cortex-M4 DUI0553B load/store/condition/branch definitions. The additional Armv7-M DDI0403E.e passage supplies actual Thumb width and T1 compare bitfields. The Linux scalar SysV ABI uses the already captured explicitly old0.99.6 draft with newly inspected preserved-register and stack-frame passages. Teaching must name that draft and constrain kernels to stable scalar integer/pointer interfaces. It does not cover Windows x64, syscalls, aggregate/variadic/vector classification or VFP variants. Register liveness and public-call preservation are testable obligations rather than informal comments.

T37 combines Plantz's inspected full-adder, clocked-state and instruction-cycle explanations with Hennessy/Patterson's performance, cache and pipeline models. Plantz uses AArch64; its instruction width, PC and register-count details are not Thumb rules. Hennessy's small RISC pipeline and AMAT model are declared educational models, not actual x86 or Cortex-M timing. Several held-book examples contain inconsistent numerical inputs, so original fixtures independently derive units and arithmetic instead of repeating those numbers. STM32 RM0090 Rev21 supplies exact CPU/DMA master-to-target reachability and CCM restrictions. It is not relabeled Rev22 and does not establish physical throughput, electrical timing or WCET.

Only a few pages from each spine component need be required in a given milestone. Reference manuals are consulted for a named mechanism when the learner uses it; they are not assigned cover to cover. Source inspection is an exercise in extracting preconditions and consequences, not an excuse to supply a complete C solution.

## T36 proposal: deepen existing implementations

The taxonomy contribution has ten topics and thirty original measurable objectives. Proposed entry requirements are T03 lifetimes/control, T04 arithmetic, T05/T06 representation and pointer bounds, T07 reproducible builds, T08 machine/ABI inspection, T18 ownership/API contracts, and completed relevant T14/T15 kernels. Full existing vector/list/queue/hash/heap/AVL and sorting builds are reused. Their original hours are not charged again. Basic induction, half-open ranges, logarithms and weighted/expected costs have short diagnostic preludes. No prerequisite depends on T37, so the extension remains acyclic.

## T37 proposal: architecture with bounded models

Ten topics and thirty objectives separate architectural state, Boolean/ALU derivation, register/address representation, encoding, datapath, pipeline, cache, MCU bus integration, exception boundaries and measurement. Entry is the relevant T03/T04/T07/T08 material. T36's small callable kernel is a late measurement prelude, not a full T36 dependency for earlier architecture models. Selected T27 startup and T29 exception leaves are preludes before the frame/bus milestones; their earlier firmware builds are reused. This ordering does not create a T36↔T37 cycle.

Eight milestones total58 implementation+verification hours:

| Proposed milestone | Hours | Topics | New work and measurable evidence |
|---|---:|---|---|
| PR-T37-01: Four-bit ALU from truth tables | 6 | .01,.02 | Derive eight full-adder rows; original four-bit add/subtract model; exhaustively check256 operand pairs per operation, carry/no-borrow/overflow/sign/zero; identify C versus machine arithmetic assumptions. |
| PR-T37-02: Instruction bytes to state | 8 | .03,.04 | Hand-decode a small Intel CMP/Jcc byte sequence and Thumb T1 CMP halfword; widths, fields, endian bytes, register effects and relative target arithmetic. | PR-T37-03: Clocked toy datapath | 8 | .01,.05 | Original tiny register/ALU/load/store state model with a declared toy ISA and read/write/commit ordering. | PR-T37-04: Pipeline schedule and hazards | 8 | .06 | Table-driven five-stage in-order schedule for a fixed short sequence; RAW, load-use, forwarding, stall and taken-branch flush. Compare no-forwarding/forwarding retirement and cycle counts. No generic CPU or high-performance timing simulator. |

Suggested budget: reading14, implementation42, verification16, assessment6, consolidation6 =84hours. The toy ISA, pipeline/cache models and tiny truth-table oracles are original learner algorithms; no full solved C is supplied. Firmware use preserves the real C object-storage constraints and implementation contracts. Hardware-dependent evidence is distinguishable from reproducible model fixtures. A successful synthetic cache/pipeline/frame verifier does not certify the learner's machine code, a physical board, bounded latency or production safety.

## Rejections and remaining limits

Hyde's held x86-64 volume has useful depth but centers Windows/MASM; it is not the required SysV ABI authority. The held Cortex-M development guide explicitly does not aim to teach deep assembly and architecture, so it remains a discovery lead. Wirth, Princeton's Java/C++ material, functional structures, large-data algorithms, Fenwick trees and timing wheels are useful later expansion leads, not additional required work for this bounded progression. The graph's unverified Fenwick origin record is not promoted to a verified original publication. AVL's original Russian paper was located bibliographically but not read or assigned; use the already implemented AVL plus inspected textbook invariant reasoning and clearly label origin metadata.

Whole-book content, every ISA instruction, advanced cache coherence, out-of-order simulation, FPGA synthesis, physical MCU timing and formal whole-program proofs are outside this gate. Any later reading expansion requires another actual passage inspection and public receipt update before assignment. Source access is sufficient for the proposed core; there is no blocking topic gap. The source list supports authorship, not evidence that a learner has completed these future experiments.

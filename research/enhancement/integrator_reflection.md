# Integrator reflection before teaching

The first searches found enough material to risk overloading the curriculum. The existing T14/T15 container and algorithm work should remain the reusable implementation base. New work must deepen representations, invariants, machine execution and abstraction boundaries rather than charge for recreating each complete data structure in two instruction sets. Handwritten assembly kernels need an actual ABI contract and an adversarial harness; compiler output alone would not satisfy the requested progression.

Processor architecture, microcontroller integration and electrical interfaces require separate evidence. An ISA states instruction effects; a CPU implementation explains pipeline and memory behavior; an MCU reference manual defines peripheral and bus integration; a particular board schematic and transceiver/PHY datasheet establish a physical route. Host experiments and saved traces cannot establish voltage, termination, PHY link behavior or real DMA timing. The original F439 path can be extended without silently importing another Cortex-M variant's caches or a CAN FD capability that it does not provide.

Direct inspection of X.200's scope and contents confirms that it supplies a conceptual layering framework, not an implementation specification or a protocol-conformance test. This justifies an explicitly original seven-layer educational protocol with independently observable session and presentation services. The Internet family instead needs its own normative Ethernet/IP/TCP/HTTP contracts. A socket-based HTTP server is a third boundary: operating-system transport is supplied and application parsing is learner work. These distinctions must be visible in the family guide and mastery gates, not only in footnotes.

The current HTTP search identified RFC 9931 (March 2026), which updates RFC 9112 regarding optimistic protocol transitions. The networking researcher is inspecting its actual update and integrating a bounded policy for Upgrade/CONNECT. Old HTTP textbook chapters cannot override current framing/security obligations. Analogously, the original Bosch CAN FD document is historical evidence and must not be presented as an interchangeable ISO FD contract.

Before opening the teaching gate, the focused searches must resolve exact ABI and MCU locators, reading edition identity, all requested serial/electrical/bus interfaces, the actual Ethernet board/PHY route, and bounded current HTTP/TCP requirements. A concrete original protocol contract must define limits, routing/addressing, sequencing, session identity and presentation encoding. Each family must have fault cases and closure conditions. Bibliographic access limitations are acceptable when another inspected source supports the mechanism; an unsupported essential claim is not.

The preserved October 4 acceptance applies to the prior edition. New taxonomy, source assignments, fixtures, guides and publication will receive independent reviews and new receipts. Rebuilding the public handbook must remain possible without local library payloads or private source excerpts.

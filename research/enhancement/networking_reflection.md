Three project families should remain distinct. T40 needs an original seven-layer teaching protocol whose session and presentation layers perform observable work. Calling a TCP socket session management or calling arbitrary bytes a presentation layer would evade the intended lesson. An RS-485 physical adapter permits actual transceiver, half-duplex direction, termination and cable evidence; deterministic host traces can test the higher layers but cannot close its physical gate. The original protocol may demonstrate OSI responsibilities without claiming implementation of the ISO OSI protocol suite.

T41 has a different risk: a very small TCP implementation can exchange an HTTP response with a cooperative client while omitting mandatory behavior. The research must distinguish a controlled same-link subset from a conforming Internet host. In particular, packet options/fragmentation, sequence arithmetic, retransmission, receive-window pressure, duplicated segments, connection teardown and congestion behavior need explicit included/excluded policies. A desktop client's handshake/options are interoperability inputs, not details to assume away. The F439 MAC/DMA path, LAN8742A PHY, RMII clock, magnetics and cable belong to the physical closure; TAP/pcap traces do not replace that evidence.

T42 begins at OS sockets and introduces the portable HTTP parser reused by T41. It must own incremental octet parsing, bounded headers/bodies, chunked decoding, Host validation, unambiguous request framing, premature EOF, timeouts, queued output and partial writes. It must distinguish application error responses from transport completion. Plain HTTP bound to loopback has no TLS or Internet-deployment claim. This direction removes a curriculum dependency cycle and counts the parser implementation hours once.

The focused pass will therefore inspect: X.200 layering/data-unit concepts and each layer purpose; current HTTP semantics/framing and ambiguity rules; current TCP plus timer/congestion specifications; IPv4/ARP/ICMP/checksum passages; the board Ethernet section, controller DMA descriptors and actual PHY interface/status passages; RS-485 physical constraints; current POSIX/Linux socket I/O contracts; and selected edition-specific textbook explanations. Old HTTP material, AUTOSAR stack specifications and broad SWE architecture leads remain supplementary or rejected when they do not answer these exact contracts. Source discovery, inspected passages, original subset design and later physical execution will be recorded separately.

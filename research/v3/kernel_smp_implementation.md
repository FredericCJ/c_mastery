# CMK2 implementation and verification

The new family is `labs/kernel_smp`; reference implementation is `assessor/kernel_smp`. Original kernel packages are unchanged. Source and artifact hashes, exact QEMU commands, CPU counts and negative-control results are recorded in `kernel_smp_verification.json`.

Actual final author runs passed write, reboot/verify and interactive modes with 1, 2 and 4 CPUs. The learner package builds with its unsolved stubs and fails the first valid MADT assertion as expected. Positive staged/host/integration CTests passed; mutation controls separately confirm detection of a missing TLB acknowledgement (configured host deadline after real startup/affinity evidence) and masked MSI-X (guest failure).

Implemented mechanisms include original AP INIT/SIPI, per-CPU tables/stacks, APIC timers and IPIs, per-CPU cooperative kernel threads, bounded channel waits/wakes, preemptive SMP ring3 threads, explicit affinity/migration, acknowledged CR3 invalidation, integer reduction, reusable dispatch rounds and dependency DAGs. User processes have generation-tagged reusable identities, at most 8 process slots, 32 total threads and 4 live threads per process. Spawn/exit/wait, last-thread cleanup, demand-zero, restricted COW, close/drain/destroy channels, shared objects and interrupt-driven virtio block requests are actual guest mechanisms. The VM client and store owner communicate in separate processes, with durable commit/indeterminate reply and reboot recovery.

Focused regression markers cover per-process admission, repeated process-generation reuse, concurrent zero/COW faults, close/drain, orphan queue reuse, remote sibling quiescence before wait, and unconsumed completed-I/O owner exit. Review found and corrected a device-IRQ priority inversion: a high-priority reschedule IPI must acknowledge before contending for a kernel lock whose holder needs a lower-priority MSI-X interrupt. Idle CPUs also switch to the permanent boot page table before a process slot becomes reusable.

Workload logs record TSC intervals, job counts and CPU participation masks. These are emulator observations, not hardware cycle measurements or proof of speedup. This remains a bounded teaching kernel: no physical target validation, FP/SIMD context, hotplug, POSIX, full VFS, general DMA/IOMMU or multithreaded COW-fork claim. Independent review records remain the authority for their own accepted scope and hashes.

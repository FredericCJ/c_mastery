# Second-edition research synthesis

The overhaul began with the existing curriculum, accepted source records and
v1 Git snapshot. The main gap was executable support and a usable project
sequence across a broad specification. We retained historical objective identities,
introduced component contracts and early selected prerequisites, then added original
programs whose boundary behavior can be tested independently.

## Search, reflection and follow-up

The actual document library is F:\Knowledge; the SWE and datastructures corpora
are discovery graphs. A graph title does not establish holdings or passage inspection.
Family records identify held-document IDs/hashes where used, official public
alternatives and assigned scope. No licensed source payload enters the distribution.

Runtime research narrowed the language and VM to checked integer operations,
explicit frames, bytecode validation, bounded resources and explicit GC roots.
The Nystrom manuscript passages and held compiler-book pages support these
mechanisms; unexpanded code-inclusion markers were not treated as inspected code.
The original implementation has its own bytecode and memory contracts.

Storage research combined held persistent-storage passages with original tree
literature and official SQLite documents. The ARIES abstract remains a bibliographic
lead; its presence does not authorize assigning the full paper. The resulting store
has a declared failure model, bounded page format, redo/recovery and explicit flush
boundary. Finite tests do not establish all real storage-device failure behavior.

Kernel research separates boot/architecture specifications, ELF, the educational
process model and concrete device interface. The bounded kernel lets a learner
trace a user operation through a syscall and block request. Integration checks
exercise the boundary across a reboot.

The physical FD follow-up inspected Microchip DS20006027B sections 1.1–1.3 for
controller/pin/power responsibilities. Register initialization is a separate scope.
The prior TCAN4550 synthetic case remains specific to that device. Physical
milestones retain raw measurements and peer evidence.

## Decisions and remaining evidence

| Decision | Reason | Learner evidence still required |
|---|---|---|
| Keep x86-64 and Thumb | Deep comparisons with a manageable target set | ABI explanation and actual target observations |
| Compile unsolved scaffolds | Reproducible entry | Correct implementation and independent changed cases |
| Separate assessor bundle | Review checks against working and wrong implementations | Delayed transfer after assistance |
| Preserve claims through migration | Detect silent coverage loss while improving teaching | Objective-specific evidence |
| Separate host, emulator and physical receipts | Keep claims tied to actual observations | Raw board/instrument/peer records |
| Keep effort estimates provisional | Author test duration is not learner calibration | Planned/actual study time from learners |

Follow each family's source and validation record for exact passages, execution
scope and limits. Current receipts bind to current source hashes; historical
reviews do not silently accept changed teaching or code.

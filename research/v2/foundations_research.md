# Hosted foundations: search, reflection and bounded implementation

The implementation starts from the existing T01–T07/T12/T18–T22/T32–T35/T43–T45 project contracts. Their current reading assignments remain authoritative; this support family does not claim new inspection of every assigned textbook or complete every project. The useful shared mechanisms are small checked arithmetic, spans/ownership, deterministic cleanup, partial output, state transitions and stable ordering. These admit independent finite oracles and recur in later runtime/storage/kernel work.

Reflection narrowed the package deliberately. A generic test runner cannot certify language understanding, a parser's entire threat model or physical cycle behavior. Therefore each project mapping names its actual anchor and remaining obligations. Optional/manual-only mappings have an empty required-test list so the common runner leaves their execution unavailable until a specific adapter is supplied. Guided fault/repair controls are separately described; their already-passing harness tests cannot establish learner repair ability. No extra curriculum hours are charged for reusing this support package.

Focused tool inspection on 2026-10-10 used primary documentation: GCC's `-finstrument-functions`/`no_instrument_function` entries; Clang's ASan usage and limitations; LSan usage and the LLVM `lsan_flags.inc` root-set options; GDB's watchpoint semantics/limitations; and Linux cgroup v2 CPU interface accounting. Exact URLs and inspected bounds are in `foundations_source_scope.json`. This review supports the recipes' tool behavior only, not broader language/algorithm source coverage.

The leak experiment changed after an actual observation: default LSan returned success for the intentionally lost allocation in an initial AddressSanitizer-only build. Its conservative root set can retain stale stack/register words. The final combined ASan/UBSan build did detect the default leak; changing instrumentation can change this observation. The package records each actual default outcome, then separately compares a root-reduced closed child with a paired repaired child. It never treats that configuration as a general leak-proofing recommendation. Likewise, a cgroup snapshot accounts for a group; it is not a per-component control experiment. Perf permissions and missing formal tools stay unavailable rather than becoming fabricated successful measurements.

All C mechanisms and fixtures in this family are original, bounded teaching implementations. External installation consumers, source identities, actual child execution and fresh exported-workspace builds are recorded in `foundations_execution_receipt.json`. Full project-specific implementations, formal proofs, genuine withheld assessment and physical MCU experiments remain their respective project obligations.

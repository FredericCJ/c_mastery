The actual C11 N1570 passages distinguish generally permitted signed
representations from optional exact-width types, which already require no padding
and two's complement. Therefore a proposed non-two's-complement `int32_t` is not a
valid changed assumption under that draft. A hypothetical target without that
type instead needs an admitted representation and a numeric order map. Unsigned
value conversion is not a reinterpretation of host object bytes. The active
implementation baseline stays C17; exact published C17/C23 wording remains an
explicit source-access gap.

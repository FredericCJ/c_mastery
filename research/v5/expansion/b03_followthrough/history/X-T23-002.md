# X-T23-002: Short-write progress without duplication or busy retry

## Prerequisites

Read PR-T23-02 and labs/b03_depth/CONTRACTS.md version1. Required prior exercises are listed in metadata. Bring an event/state trace notebook and a C17 test workspace; no unlisted accepted artifact is imported. Knowledge: object lifetimes, integer bounds and the parent's I/O, concurrency or device model. State which earlier ownership arguments are reused and which platform assumptions are new.

## Environment

The default CMake build uses learner stubs. Components use C17/profile C; Python and libc are host verification tools. All experiments are unprivileged local models with synthetic bytes/events. C17 atomic mailbox code is distinct from the sequential device/I/O models. Record compilers, optimization, target data model and undefined symbols. Actual OS, ISA, ABI and board guarantees require separate evidence; the host run supplies none automatically.

## Problem

Implement b3_pump with persistent byte cursor and per-turn callback quota. For five bytes and callback results[2,-1,-2,1,2], budget3 returns WAIT at cursor2; the next budget1 yields at3; the next completes at5. Observed callback offsets must be[0,2,2,2,3]. Completed calls make no further writes. Add zero-progress, fatal-after-prefix, impossible oversized response, zero budget and empty-buffer traces. The -1/-2 callback values are synthetic statuses, not POSIX errno constants.

Use supplied include/depth.h, src/depth.c, tests/tests.c and fixtures/b03_depth/cases.json. The complete API, pointer, state, ownership and failure contract in labs/b03_depth/CONTRACTS.md is explicitly incorporated. Preserve all admission and termination rules.

## Necessity

A short positive write is committed progress. Restarting at byte0 duplicates data; advancing by requested length loses bytes. Readiness and interruption are not permission for an unbounded retry loop.

## Reasoning

Prove 0<=position<=length, exactly-once confirmed byte-prefix progress, callback count<=budget and terminal idempotence. Keep failed backend effects separate from stored cursor. Compare write interruption before/after transfer, no-progress, would-block and terminal errors. Explain why direct I/O, datagrams and durability cannot inherit this stream contract blindly.

Distinguish enforcement by C, diagnostics, runtime state checks, proof/model and caller/environment discipline. Show one plausible wrong explanation and a minimal counterexample. State precisely what each experiment cannot establish.

- D3: Independent model or oracle cases below, error/state snapshots, minimized discrepancy and a mutation demonstrating that the checked property is discriminating.

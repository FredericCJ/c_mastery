## Problem

Implement finite-generation operation state. Start request1, timeout, complete, cancel_ack reports exactly one COMPLETED result; timeout retains ownership. Start request2, inject request1 completion, timeout2, ack2: stale event does not change request2, then one CANCELLED result. At most3 generations may start; further start fails permanently. Repeated timeouts stay pending and do not authorize reclamation. This is an explicit backend-quiescence protocol model, not an OS cancellation call.

Use supplied include/depth.h, src/depth.c, tests/tests.c and fixtures/b03_depth/cases.json. The complete API, pointer, state, ownership and failure contract in labs/b03_depth/CONTRACTS.md is explicitly incorporated. Preserve all admission and termination rules.

## Necessity

Timeout is an observation of elapsed waiting, not proof that work stopped. Numeric descriptor/request reuse can let a late callback mutate a new owner; finite IDs need an exhaustion policy.

## Reasoning

List all phase/event transitions and ownership of context before/after each. Prove reports increments exactly once per started request, ownership persists until winning terminal event, stale identity never mutates live state and no ID is reused. State the real-backend guarantee required to reclaim context after ACK/COMPLETE; it is not supplied by C.

Distinguish enforcement by C, diagnostics, runtime state checks, proof/model and caller/environment discipline. Show one plausible wrong explanation and a minimal counterexample. State precisely what each experiment cannot establish.

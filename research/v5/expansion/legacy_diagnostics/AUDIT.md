# T43–T50 depth audit and implemented expansion

The retained curriculum already specifies substantial performance, diagnosis,
memory, VM, storage, kernel, Linux and MCU work. A mathematical fixture, a named
CTest and a successful earlier campaign have different scopes. This expansion
preserves the original module/project/fixture bytes and historical receipts,
then adds 92 project supplements with 288 individually authored leaf criteria.
The canonical cards are `T43.cards` through `T50.cards`; `author.py` renders the
repository schema and separate assessor analyses. Every criterion has concrete
reasoning, implementation or analysis, expected relations, a differentiated
rubric, hints and a changed-condition assessment delayed at least seven days.

| Domain | Consequential finding | Required added work |
|---|---|---|
| T43 | Cost models and synthetic measurement fixtures do not execute every required native benchmark; an existing direct-mapped cache is not a two-block LRU writeback cache. | Variable-length comparison cost, amortized failure/shrink behavior, distinct cache model, paired measurements, clock/PMU/cgroup scope and causal uncertainty. |
| T44 | Correct output or a tool finding can conceal an incorrect causal/lifetime explanation. | Competing hypotheses, tri-state minimization, debugger observation limits, optimized state, partial I/O and first-cause repair. |
| T45 | Sanitizer/address observations do not establish object lifetime, initialization or quiescence. | Multi-stage extent arithmetic, stack/startup accounting, partial acquisition cleanup, resize generations, callback/DMA lifetime and custom-pool tool limitations. |
| T46 | Structural/height verification does not establish types, initialization, termination or bounded callback time. | Unreachable malformed bytecode, relative versus total stack bounds, precise temporary roots, failed collection without sweeping, distinct resource budgets and uncertain service effects. |
| T47 | The 12 fixtures are contract indexes; real crash evidence comes from the separate C simulator. | Structural validation beyond CRC, split/merge/free-list failure atomicity, uncertain commit, validate-before-redo, checkpoint authority and interrupted recovery. |
| T48 | Real guest integration exists, but arithmetic fixtures cannot establish machine transitions or all isolation cases. | Per-level permissions, cross-page copies, partial mapping rollback, DMA ownership after timeout, narrowed ELF support, source/image provenance and commit/reply ambiguity. |
| T49 | Real process/thread/I/O probes are narrower than raw-syscall, all-policy, namespace and constrained-cgroup assignments. | Raw ABI wrapper, partial lifecycle failure, yield-aware policy extension, four replacement policies, descriptor reuse, readiness/completion separation and controlled resource observations. |
| T50 | The retained cooperative stage switches through PendSV; stack faults stop the whole image; periodic idle is not complete tickless operation. | Separate call-boundary switch, generation-safe public handles, full FP-state evidence, task-local fault policy, race-safe tickless adapter and explicit physical limits. |

The additions refine existing taxonomy leaves rather than create duplicate
domains. Cross-domain transfer is explicit: VM/store/kernel error translation,
descriptor/callback/task lifetime, source-level versus machine-level dependency
audits, and measured versus derived resource bounds. Required difficult work is
kept in the main assessment contract; it is not moved to an optional appendix.

Actual passage inspection is recorded in `resources.json`, including bounded
local implementation sections and primary documentation. A failed GRUB fetch,
the forbidden POSIX2024 close page, exact published C17, uninspected books and
unrenewed architecture authorities remain gaps. The generic ELF ABI and AAPCS
are not substituted for the original kernel profile or Cortex exception manual.
The Nystrom manuscript's code-inclusion markers are not counted as C listings.

The kernel security exercises target original teaching guests or bounded address
models, with synthetic sentinels and explicit attacker capabilities, transitions,
success conditions, repairs and regression obligations. No network targets,
host devices, host security changes or hardware flashing are part of authoring.

Run `.venv/Scripts/python.exe research/v5/expansion/legacy_diagnostics/validate.py`.
The recorded run passed 92 project contracts, 288 leaf mappings, 92 fixture
checks (80 finite oracles and 12 storage contract indexes), and 14 negative
controls. This is structural/source and finite model evidence. It does not
execute all supplemental tasks, administer delayed assessment, establish an
independent reviewer or validate physical hardware. Exact results and input
hashes are in `validation.json`; the complete task-level remaining obligations
are in `remaining_work.json` and `traceability.json`.

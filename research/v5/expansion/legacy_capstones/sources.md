# Capstone source inspection and scope

Inspected 2026-10-17 for eight additive capstone supplements. Read all eight PR-CAP-LINUX/MCU project briefs, the complete integration guide and assessment guide, the complete wire/pressure/irq/recovery fixtures, and the actual selected parent-topic teaching passages. There is no CAP-LINUX or CAP-MCU module file: their canonical project owner is INTEGRATION. This expansion preserves that identity and maps each new criterion to an actual Txx leaf within the parent project's topics.

Read the integration family metadata, complete public header and handoff contracts, actual linux/mcu public test bodies and assessor implementations, neighboring handoff code, and LAB-IN-07/08 contracts. The Linux executable anchor tests a CVM expression stored in a checked page. The MCU anchor tests a host ADC/filter/watchdog composition. Neither establishes the complete capstone contract. The integration family's one-byte signed-decimal stream format differs from the integration guide's A5/version/CRC telemetry protocol; their evidence is not interchangeable.

Fresh external inspection is precisely bounded by `resources.json`: Linux man-pages 6.19 epoll LT/ET, descriptor/open-file-description identity, starvation and cached-event closure; write partial progress, interruption, no-progress errors and durability limits; zlib 1.3.1 crc32 initialization/update convention. These are actual passages, not search-result or title evidence. Linux interface documentation is not ISO C semantics; zlib is a host oracle and is not an allowed shortcut in the first-principles target core.

The MCU supplements explicitly reuse earlier inspected records from `research/v5/expansion/legacy_depth/resources.json`: selected FreeRTOS CM4F function bodies, RM0090 Rev21 watchdog/Sleep pages and Arm fault overview/status passages. Their previously recorded inspection bounds remain intact. They do not newly inspect the full F439 memory map, MPU/DMA authority, flash atomicity, board errata or complete reset/low-power recipes. Those source and physical-evidence gaps remain required where the capstone uses the mechanism.

For modern composition, read actual registry entries for errors.result, cleanup.scope and coro.frame, the ownership and errors public headers and the complete coroutine contract. The registered producer identities are used in prerequisites. The fixed cleanup scope has eight entries and prohibits callback reentry/nonlocal escape. The tagged result does not preserve output progress automatically; a separate cursor is necessary. The coroutine readiness frame accepts only 1-8 bytes and requires synchronous disarm/quiescence. These limits prevent a false drop-in equivalence to a 42-byte frame or an asynchronously cancelling backend. Header/runtime dependencies must be re-audited before a strict freestanding import.

No whole-book inspection, hardware measurement, firmware flashing, native service campaign, formal proof run or independent learner assessment was performed by this capstone authoring wave. The new bounded fixture oracle is executed separately and has a source-bound receipt. Its first run caught an incorrect authored RAM sum (100 bytes too high); the expected total and related prose were corrected to 1896 bytes, with the independent assertion retained. The initial failed check is preserved rather than credited as success.

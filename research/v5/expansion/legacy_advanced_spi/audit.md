# T28.07 SPI depth reconciliation

The original PR-T28-04 brief supplies a three-byte SPI fixture and correct TXE/RXNE/BSY reasoning, but does not implement its per-criterion changed conditions. The prior firmware_io reference is a synthetic register adapter, not the selected F439 map. Its real fw_spi function releases CS even after a BSY timeout; the new composition test preserves and demonstrates that contract difference. The serial_depth edge/poll functions are reused as actual providers, with a separate string/poset oracle and a true selected-register successor.

This increment covers three original ordinary criteria and three original seven-day variants, without changing their tasks or baseline binding. It supplies PIO and independent TX/RX DMA ownership, one CS interval for command/response, distinct bus/application results, protocol change, reset recovery and exact target registers. The I2C half of this project remains required and separately tracked. T28 ADC, general DMA/layers and T29 ISR/board integration remain work, not external blockers.

Source inspection exposed a width mismatch in the first draft: SPI permits16/32-bit register accesses, while direct DMA uses identical memory/peripheral widths. The implemented successor uses aligned uint16_t arrays for each8-bit frame, explicit pack/unpack, correct2*count extents, and PSIZE/MSIZE halfword. It does not invent a byte-access exception. Review also exposed the stale pre-start SR snapshot and potential CPU DR read while RX DMA was active; dedicated compiled controls and ownership tests now discriminate these defects. Reset hold time takes an explicit current time. A stuck hardware acknowledgement remains ownership-held containment.

The first pilot is preserved as reviews/v5/expansion/legacy_advanced_spi/pilot_validation.json. It overlaps source development, includes an intermediate test-identifier compile error and a missing freestanding stdio declaration, and is not acceptance evidence. Its source-stability failure is intentional evidence that changed sources cannot inherit a prior run. The final current campaign must run after all public/private runtime sources and teaching files are fixed.

Evidence separates native controller-model execution, actual provider composition, PPC64 endian execution, Cortex-M4 emitted-object/link audits, and synthetic trace analysis. None is physical board validation or an independent learner attempt. The blank board capture template cannot pass until completed with actual provenance; synthetic records remain labeled. Publication uses the existing additive legacy_advanced hook and actual cmastery init export, preserving assessor exclusion and original criteria.

The first fixed-source run passed all native/model/M4 and trace-analysis cells, but all27 PPC64 links rejected unresolved printf/puts because the deliberately minimal bootstrap exports pm_printf/pm_puts. That failure is preserved in attempt01_before_be_diagnostics.json. The test-only big-endian diagnostic aliases are corrected; the same three-endian optimization profiles and every semantic mutant must execute before closure. No libc is linked to suppress the failure.

The actual Clang-O3 target uses STR [r0,#-8] for DMA_LIFCR. The local decoder now recognizes signed offsets instead of rejecting that valid emitted address. Required addresses, word-only MMIO and wrong-base negative checks are unchanged; the frozen timer/UART decoders are untouched. This structural decoder is not a control-flow proof.

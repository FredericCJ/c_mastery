# PR-T59-07: Dual-core update quiescence

## Contract

Implement lc_peer_ready(local_epoch,ack_epoch,outstanding) accepting only equal epochs and zero outstanding transfers. Use it in a two-core shutdown model: close admission, drain DMA/IPC owners, obtain an epoch-specific acknowledgement, then permit update. A stale acknowledgement must never unlock a new generation.

Shared requirements: [B06 exercise contract](../v5/contracts/b06.md). Stable
unit IDs are `LAB-LC-07A` and `LAB-LC-07B`. Families: A, B, C, D, F, G, I, J;
source records: R-B06-STIPC in
`research/v5/b06_resources.json`, using only its inspected locators.

Prerequisite knowledge: Explain flash erase/program asymmetry and reconstruct a recoverable page-store commit. Distinguish reset, power loss, brownout and interrupted CPU execution before proposing an update protocol.

subject to the named outstanding evidence requirements.

## Steps

- **T59.07:** A core reset invalidates assumptions about peer-owned buffers and cached metadata. A notification is not the payload and does not prove every old-generation operation completed. Update coordination needs generation and quiescence together.
- **T59.07:** Implement lc_peer_ready(local_epoch,ack_epoch,outstanding) accepting only equal epochs and zero outstanding transfers. Use it in a two-core shutdown model: close admission, drain DMA/IPC owners, obtain an epoch-specific acknowledgement, then permit update. A stale acknowledgement must never unlock a new generation.
- **T59.07:** Prove no old-generation peer can retain writable storage at update commit. Separate cache visibility, notification delivery and logical acknowledgement.

## Failure cases

Repair acceptance of a stale acknowledgement after independent peer reboot. A memory barrier cannot repair the missing generation check.

Retain the first divergent transition and distinguish the cause from a symptom.
The named mutation control must fail for its intended reason; compilation
failure is not a successful mutation kill.

# Inspected source passages and adaptation limits

The source register is passage-level author evidence dated2026-10-18. It does
not claim new inspection of every library book found during metadata screening.
Public captures stay under ignored build/corpus_index_sources; no private book
extracts or full copyrighted articles are published with the curriculum.

- Fenwick's1994 article was read through its principles, operations, scaling
  and performance discussion (printed329–336), with its earlier introductory
  context. The published one-page July correction (printed677) was read through
  the publisher browser PDF: its zero-origin find routine must first subtract
  Tree[0], and its scaling pseudocode calls PutValue rather than AddValue.
  Direct private capture of that correction returned403; browser inspection
  is recorded separately and no local hash is invented. The curriculum uses
  a one-based tree and derives its own zero-based rank contract. Inverse linear
  build followed by point rounding avoids the article's documented aggregate
  rounding problem. The original paper is captured from a third-party mirror,
  not misrepresented as an author-hosted copy.
- The official AtCoder segment and lazy-segment API documents were read,
  including associativity/identity, oracle-cost qualifications, half-open ranges,
  map closure/distribution and composition(f,g)=f after g. Their C++ templates
  do not statically prove these algebraic laws; neither does the C implementation.
  The original residue polynomial, read-only query action and checked fixed
  capacity are independently derived. No library implementation performs the
  exercise mechanism.
- Demaine/Leiserson lecture11 slides9–25 were read from the actual captured PDF:
  augmentation, closed intervals, subtree maxima, rotations, search and both
  directions of the pruning proof. The source uses red-black balancing. This
  exercise uses actual typed AVL nodes and separately derives half-open equality
  changes, deletion repair and transactional all-result publication. The source's
  repeated-search/delete enumeration is not the same as this O(n) read-only scan.
- Manber/Myers1990 conference paper sections2–4 (printed320–324) were read:
  ordinary versus accelerated search, rank doubling/buckets, adjacent-prefix
  minima and range queries. This is not the1993 journal article. The curriculum
  independently uses stable integer-key pair sorting and derives a linear LCP
  scan; it does not pretend those exact implementation details were copied from
  this paper. Plain range search is O(m log n), LCE scans O(n), and the bounded
  disjoint-repeat transfer scans O(n²); none inherits a stronger paper bound.

ISO C17 remains the implementation baseline. The exact published final C17 text
is an existing separate access gap; N1570 must not be relabeled C17. The four
mechanisms use no edition-sensitive new construct. Exact-width integer and
8-bit-byte assumptions, caller pointer premises, host-only verification tools
and target helper costs are explicit in the common contract.

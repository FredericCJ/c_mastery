# Fixed corpus relevance screen and mechanism resolution

`screening_map.json` preserves the pinned library catalogue and SWE discovery
identities. The library catalogue contains 4,869 documents in 56 category paths;
the SWE index contains 922 works and 1,083 design elements. This is metadata
discovery, not a claim to have read those works. Exactly 84 descriptions in the
selected data-structure, numerical and parsing groups plus compression/coding
were actually read and examined for transferable mechanisms. The other 999
elements remain metadata routing; the current source assignments, modern census
and objective inventory assess their own explicit obligations separately.

`mechanism_resolutions.json` resolves each of those 84 descriptions to concrete
representations, operations, invariants, exact exercise/rubric IDs and inspected
implementation evidence. Its limits distinguish genuine reuse from omissions:
an existing deque realizes a stack end contract; a persistent HAMT does not
stand in for a path-copy B-tree; a Michael–Scott queue does not implement a
Treiber stack. The latter two missing mechanisms received complete new exercises.
The secondary-index description is realized by the actual query family's staged
base-row and derived term-mask/posting update, with a stale-index mutant and
independent scan oracle. The text pair now exposes and repairs the real template
numeric-apostrophe/event-parser named-entity mismatch. No heading alone receives
implementation credit.

The map is a finite relevance decision under stated bounds, not a declaration
that every possible variant of each named structure or every book chapter has
been implemented. Required changed conditions remain in their canonical briefs.
Named discovery books are not automatically inspected sources: actual primary
passages, editions, substitutes and access failures remain in each provider's
source register. Author execution, external review, independent learner work
and physical observations stay separate. Passing finite tests proves none of
the latter three and does not prove absolute mastery.

Regenerate only this map with `author_resolutions.py`, then `build_screening.py`;
the latter reads the same pinned catalogue under its library governance. Run
`check_resolution.py --self-test` to check exact identities, concrete evidence,
source hashes, rubric references and overclaim controls. This map producer does
not edit accepted baseline records, global manifests, historical receipts or
the four index exercises' separate passage-inspection gate scope.

## Problem

Derive and implement d_swar_add for four unsigned8-bit lanes inside uint32_t using shifts, masks and unsigned arithmetic only. No intrinsics, scalar per-lane loop in the assessed implementation or signed overflow is allowed. A separate scalar oracle extracts each lane, adds in unsigned int and clamps to255. The packed numerical lane convention is independent of how a uint32_t is stored as bytes.

Supplied artifacts: labs/dod/include/dod.h, deliberately incomplete labs/dod/src/dod.c, executable anchors, fixture PR-T70-03.json and the shared CONTRACTS.md. Expected example: 0xff00ff00 plus0x01010101 produces0xff01ff01. A255+1 low lane must saturate without adding1 to the adjacent lane. Every pair of byte inputs must agree with min(255,a+b).

## Necessity

Ordinary word addition is not lane-wise addition; carries and saturation require a proof. A benchmark over only identical lanes can miss a carry leaking into a different neighboring lane.

## Reasoning

T70.03.a: Derive low7-bit addition, high-bit combination and saturation masks, proving which intermediate carries can occur and why neighboring lanes remain independent.

T70.03.b: Implement the unsigned SWAR expression and an independent scalar oracle without relying on char signedness, endian memory reinterpretation or vector extensions.

T70.03.c: Exhaust all65,536 lane input pairs in every position and with neighboring boundary lanes, then add deterministic mixed-lane random words; kill ordinary packed-add and inverted-overflow-mask mutants.

T70.03.d: Compare scalar and SWAR code under equal saturation semantics at multiple optimization levels, checking generated instructions and a changed16-bit-lane derivation. Distinguish source-level branchlessness from timing guarantees and ISA support.

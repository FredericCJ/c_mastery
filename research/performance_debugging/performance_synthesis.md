# T43 research synthesis and proposed teaching boundary

This proposal deepens complexity and measurement through fourteen topics, forty-two distinct objectives and twelve bounded milestones. It adds analysis certificates and observation adapters to accepted algorithms/components/harnesses. It does not rebuild or recharge the existing T13 effect audit, T14 containers, T15 algorithms, T30 scheduler, T34 benchmark/optimization work or T37 assembly/cache experiments. Canonical teaching remains gated on the parent research review.

The inspected spine has sixteen records. Existing editions keep their canonical IDs: CLRS fourth edition, Hennessy/Patterson sixth edition, Armv7-M DDI0403E.e and Linux read/write/fsync 6.19. New exact editions cover Vitter’s 2001 primary external-memory survey, NIST SP 500-235, versioned Linux 6.18 cgroup/PSI/perf-security, current man-pages 6.19 clocks/perf/AIO, GCC 16.2 instrumentation/developer options and GNU gprof 2.47. The source registry records actual headings and passage limits; private captures retain raw text, hashes and held stable IDs. Book passages are not republished.

## What the evidence changes

CLRS 3.1/3.2 allows a precise upper/lower/tight bound exercise with constants and thresholds, rather than a rule to drop terms blindly. The new activity will derive a counter vector for original input families on the learner’s existing implementation and distinguish multi-parameter input/output sizes. A finite slope cannot prove the asymptotic class. Upper bounds alone cannot rank two implementations at a finite input size. The chosen cost primitive and case must accompany the expression.

CLRS 16.1–16.4.1 supports aggregate, nonnegative credit and telescoping potential certificates on reused stack/table traces. A large individual operation can coexist with a small worst-case sequence average; no input distribution is required. The certificate must identify initial potential and hold at every relevant prefix. Elementary insert/copy cost excludes allocator latency and silicon stalls unless separately modeled. Table contraction and a complete new amortized data structure are outside scope.

The quantitative architecture spine connects an instruction mix to a weighted-CPI and clock model. It does not make linear abstract work universally imply linear cycles. Target code generation, stalls, working-set boundaries, branch behavior, frequency, contention and scheduling remain explanatory variables. Model speedup/Amdahl limits are checked dimensionally with original numbers; known inconsistent textbook examples are excluded. Reused C/assembly execution supplies actual instruction observations, while physical cycles require an identified target counter.

Vitter 2.1/2.2 supplies explicit fixed-item N,M,B and disk/processor parameters. The bounded activity chooses D=P=1 and compares sequential/random reference traces under a declared buffer policy. It keeps model block transfers distinct from syscall calls, buffered/file bytes, cgroup device bytes and physical bus/media traffic. Historical magnetic-disk capacities and timings are not contemporary inputs. Amplification names the useful and transferred layer; a zero useful-byte denominator is reported undefined, including 0/0.

Storage analysis starts with allocation and lifetime events. Logical live bytes, capacity, retained storage, overlapping scratch and simultaneous peaks differ. Compiler .su records describe individual static/dynamic/bounded frames, not a complete program peak; recursion, indirect calls and interrupt nesting require separate bounds. Static sections, process resident observations and cgroup memory accounting are distinct spaces. Sampled watermarks cannot certify an unobserved maximum. Shared/aliased ownership is counted once at the declared boundary.

## Runtime and I/O observation boundaries

Every runtime ledger names submit, return, completion and any requested external persistence/peer boundary. Linux AIO provides a concrete inspected comparison: successful submission accepts a request, completion has a separate status, the return value is collected once after completion, and the control block/buffer must remain valid. This is a terminology and lifetime comparison, not another AIO/backend implementation project. Reused T13/T23/T24 adapters may have different backends; their actual contracts are audited before measurement.

Elapsed time, thread CPU and all-threads process CPU have different scopes. Process CPU can exceed elapsed time during parallel work. Subtracting process CPU from wall time does not universally yield wait time. Inclusive/exclusive sums require serial nesting and an explicit call/event model; asynchronous stages overlap, so a phase-duration sum is not automatically latency. Throughput names completed items and a measurement window, while latency names an individual start/finish pair. Clocks distinguish resolution from measured accuracy/read overhead and identify adjustment, suspend and wrapping assumptions.

Read/write exercises count actual returned positive bytes, retain short-transfer/EOF/error/retry events and keep nonblocking operations bounded. Successful write does not establish durable storage; fsync adds a requested synchronization boundary and may expose delayed errors. Directory-entry synchronization is a separate requirement when the operation creates/renames a file. The experiment reports warm/cold state, buffering, target filesystem/device and the exact requested boundary. It does not flush global caches or infer power-loss resilience from timing.

## Tool-supported profiling and its limits

Linux PMU work extends the existing T34 enabled/running ledger rather than replacing the harness. Generic hardware events have target-dependent meanings. Event values, permissions, group membership, lost/unsupported outcomes, compiler/target identity and raw observations stay visible. Scaling requires positive running time and is an estimate from partial observation, not reconstructed truth. Sampling profiles, retired instructions and cache references are not interchangeable. The core route records permitted per-process results or explicit unavailable evidence; it does not alter system-wide perf policy.

Linux 6.18 cgroup documentation supports observation of keyed CPU-time/throttle, current/peak memory and per-device read/write bytes and IOs, with PSI stall units and scope. Reading these files is distinct from configuring resource controls. The no-root route inspects permitted existing files and supplied original snapshots, preserving missing controllers/denied reads. A prepared delegated subtree supports a bounded quota comparison; parent restrictions, top-down/no-internal-process constraints and cleanup remain explicit. No root hierarchy, global policy, real-time scheduling or deliberate OOM test is required.

CPU quota is temporal allocation, not a guarantee of processor frequency or PMU cycles. memory.peak resets only for subsequent reads through the same descriptor; read-only snapshots do not claim a fresh isolated peak. memory.current includes descendants and multiple accounted memory categories, not just the learner’s allocation bytes. IO writeback attribution depends on filesystem support/inode ownership and may misattribute shared-inode workloads. PSI resource stalls cannot be relabeled component-exclusive wait time. Controlled settings and observed effects are separate evidence.

Compiler-based profiling uses matching build artifacts and bounded single-threaded work. Entry/exit hooks are excluded from their own instrumentation and have bounded storage/dropped-record evidence. Inline conceptual calls, code/stack changes, incomplete nonlocal exits and profiling runtime assumptions remain visible. The same reused component supplies an uninstrumented baseline, compiler-hook measurements, and a small gprof comparison when the prepared runtime supports it. Existing coverage artifacts may be reused to contrast execution counts with time. GNU gprof samples running time; its child-time propagation assumes caller-independent callee cost and misses off-CPU delay. The source retains its glibc mcount thread-safety warning.

## Bare-metal and other measures

The inspected Arm architecture defines optional 32-bit CYCCNT, its enable/presence fields, processor-clock increments, wrap and halt behavior. A focused follow-up inspected the actual DEMCR address/TRCENA field and DWT address summaries before any direct setup recipe. DWT reads are UNKNOWN while DEMCR.TRCENA is clear, so that state cannot establish feature-presence evidence. The setup must respect trace/counter ownership and other active debug users. A prepared target activity verifies implementation/access/clock/debug/interrupt conditions before measuring a reused kernel. Modular deltas require a declared interval shorter than one wrap; a single pair of counter values cannot reveal multiple wraps. Empty brackets and controlled interrupt variants expose instrumentation cost and disturbance. Existing timer/GPIO drivers may provide a separately documented alternative. Board-specific clock accuracy, power, errata and actual silicon observations remain conditional evidence, not properties proved by the architecture manual or emulator.

NIST SP 500-235 supplies the static connected-function control-flow metric e−n+2 and basis/path-vector distinction. Its graph circuits are neither CPU cycles nor Big-O. The activity compares original graphs with the same static metric but different work bounds and uses the metric as a design/test aid. Feasible program paths still need data constraints; graph/basis coverage is not fault freedom. Code size, comparisons/moves/probes/branches, traffic/amplification, latency/throughput, deadline/jitter and resource pressure form an explicit decision vector. Energy is reported only with a documented actual instrument/counter; elapsed time alone is not energy. Sample quantiles/maxima are observed tails, not WCET.

## Rejections, gaps and authoring controls

Catalog search is metadata-prefix search, not full-book retrieval. Broad zero hits for amortized/external memory/Tarjan are not an absence assertion. SWE graph verification and lineage/editorial/folklore edges locate candidates but do not authorize readings. The Tarjan 1985 publisher abstract is an origin lead only; no uninspected passage is required. The McCabe 1976 origin and cache-oblivious lineage remain historical leads; the actual assigned static-metric publication is NIST SP 500-235. AUTOSAR profiling requirements and secondary tool tutorials are not the C measurement spine.

Guessed Duke links failed, but the primary Vitter publication was actually captured from its institution mirror and inspected. The official ST AN4989 attempt timed out; the already pinned Arm architecture suffices for the bounded DWT scope, so there is no retry or gate delay. Current GCC 16.2 and Binutils 2.47 were checked against their official manuals; Linux 6.18 is a deliberate maintained LTS baseline rather than a relabeling of current stable 7.2.9. Moving man-pages captures are version/footer/hash pinned and cannot prove the learner’s installed kernel/libc.

No blocking reading gap remains for this scope. Actual target PMU/device/board/power behavior and cgroup delegation are environment-dependent observations still to be supplied or marked unavailable by the learner. The future original JSON fixtures will specify strict IDs/types/catalog/file correspondence and independently recomputed finite results for counts, credit/potential, cost vectors, storage peaks, block references, event spans, transfers, quantiles, multiplex scaling, keyed cgroup deltas, bounded call traces and wrap arithmetic. Corruption controls must reject wrong IDs/results, numeric-as-boolean coercion, invalid events/ranges, ambiguous denominators/wraps, unsupported modes and flat/nested orphan files. Passing those finite models will not certify the learner’s C implementation, runtime performance, hardware, energy or WCET. Canonical module/brief authorship begins only after the parent’s recorded research gate.

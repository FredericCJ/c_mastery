# T45 broad-search reflection

The first audit found strong existing coverage in T03 object lifetime/indeterminate values/resize, T16 allocator and lifetime contracts, T21 transactional cleanup, T27 fixed startup sections, T29 DMA ownership, T31 fault/stack evidence, T32 instrumentation and T35 memory/resource resilience. T11/T13 already distinguish dependency effects and measured stack consumption. T45 should reuse those implementations and add controlled failure-observation-repair experiments, rather than teach another allocator or duplicate whole prior laboratories.

The pinned current Knowledge catalog is a discovery layer. A multiword query for debugging/memory/embedded returned no results, while the narrower debugging query found actual held books; the absence is a retrieval limitation, not proof that no relevant literature exists. An exact-pointer-book title and Small Memory query returned no held result. The SWE graph points to Small Memory Software, GCC/ld, FreeRTOS heap policies, the ASan paper and allocator surveys, but its verification labels do not establish inspected passages or local possession. The data-structure graph's dynamic array, linked list and queue nodes guide ownership examples; their origin labels are not memory-safety authorities.

The focused second search must close these gaps: exact fixed-region/link/startup meaning of `.bss`; compiler per-function stack reports versus whole-call-path/interrupt bounds; sampled high-water marks versus worst case; watchpoint width/count/scope and debugger perturbation; uninitialized-use versus addressability; stale aliases after successful resize, including same-address reuse; and failure cleanup/leak classification. Instrumented executions change resource usage. A native crash, signal, diagnostic wording or address is environment-sensitive and cannot be an exact portable fixture expectation. No diagnostic on a selected path is not a proof of correctness. Unsigned size wrap is defined arithmetic but can still violate an allocation contract.

Candidate public manuals are being captured at exact versions: LLVM 21.1.0, GCC 15.2.0 and binutils 2.45; Valgrind's current manual identifies 3.27.1. These are passage authorities, not claims that those tools are installed or learner programs have run. Actual Arm stack/fault scope is reused only where already inspected; additional DWT/watchpoint passages require direct inspection before assignment. General attack/exploit literature is unnecessary for this own-program defect laboratory.

Proposed progression: evidence/observation contract; bounds and NUL defects; checked sizes; stack exhaustion versus corruption; fixed-region/startup/collision evidence; leak/failure cleanup; resize/invalid free/stale aliases; initialization state; DMA/reentrancy lifetime; unseen diagnosis/repair transfer. Ten 4–12-hour milestones can cover these without allowing a synthetic fixture to stand in for actual learner C or board evidence.

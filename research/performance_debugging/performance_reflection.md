# Reflection after the broad search

The existing curriculum already supplies the implementations that make a performance investigation meaningful: T15 sorts/searches/graphs and their work counters, T13 component effect ledgers, T30 release/start/finish/resource traces, T34 paired consumed-result benchmarking and PMU enabled/running accounting, and T37 actual C/assembly executions and cache models. T43 should extend their analysis and observation boundaries. Rebuilding a sort, allocator, event loop, benchmark runner or driver would duplicate accepted work and hide the requested new mechanisms inside old budgets.

Broad discovery searched eight catalog queries and both graph collections. The held catalog produced 25 performance and 11 complexity candidates, seven mostly AUTOSAR profiling requirements, and the exact held fourth-edition CLRS. Queries for amortized, external memory and Tarjan returned zero. These are metadata/heading projections with limited-evidence enrichment, not full-book search; their negative results are not an absence claim. The SWE search found 241 work/element-linked records across its collections; data-structure lineage contributed 16 candidates, including dynamic-array amortization, self-adjustment and the cache-oblivious model. Graph verification labels and editorial/diffuse-origin distinctions remain discovery evidence rather than proofs or inspected teaching passages.

The first web pass located official Linux cgroup/perf documentation, GCC instrumentation and GNU gprof manuals, plus author/publisher candidates for I/O and amortized analysis. Several returned secondary discussions will be rejected as technical authorities. The current gprof landing page identifies Binutils 2.47; live kernel/GCC pages require a versioned source snapshot or explicit access-date/hash scope. Existing GCC 15.2 records can be reused only for the exact edition/URL and inspected options; new compiler versions get distinct IDs. Held textbook editions will be checked from front matter, not catalog date placeholders.

The main gap is a *cost contract*. An operation count has no seconds until a target/workload/clock model connects it to instruction and memory behavior. A linear operation bound does not establish linear cycles; working-set changes, stalls, code generation, contention and scheduling can alter the mapping. Big-O hides constants and lower-order terms; a measured slope does not prove an asymptotic class. Amortized analysis bounds a sequence without assuming random inputs. External-memory transfers concern declared blocks and fast-memory capacity, not arbitrary filesystem reads or bus transactions.

Space also needs a boundary: logical live elements, allocated capacity, retained freelists, peak simultaneous scratch, stack/static sections, process RSS, page cache and file/device bytes are different quantities. Shared or overlapping lifetimes must not be summed as though every allocation were simultaneously live. A sampled stack watermark is not a complete static or WCET proof. Traffic amplification must name useful and transferred bytes and the layer at which they are observed.

Runtime has at least four relevant events: request accepted, component returned, operation completed, and external persistence/peer observation established. Blocking wall time can include off-CPU waits. An asynchronous submit returning quickly does not close completion latency or release borrowed buffers. CPU/process/thread time differs from elapsed time; function attribution and nested inclusive/exclusive measurements need an explicit call/event model. Successful write is not durable persistence. Warm page cache, buffering, partial transfers, EINTR/EAGAIN and fsync alter the experiment and its interpretation.

Profiling tools observe and perturb different things. perf can be unavailable or multiplexed; scaling assumes representativeness and cannot recover events never observed. cgroup quota/pressure/accounting is not an algorithmic complexity measure; controllers/delegation/device accounting vary. The core no-root route must inspect permitted files and analyze captured data honestly, while a prepared delegated environment supports actual controlled runs without changing system-wide policy. Compiler entry/exit/arc instrumentation needs bounded records, recursion/exclusion rules, matching builds and an uninstrumented control. Bare-metal DWT/timers require exact presence/enable/clock/wrap and debug/interrupt conditions; emulator timing is not silicon evidence.

Cyclomatic complexity is a static control-flow measure used for design/test discussion. Its graph circuits are not CPU clock cycles and its value is not Big-O. Useful comparisons/moves/probes, branch/cache/traffic counts, code size, deadline/jitter and energy must each be justified by a declared model and available observation. Energy is conditional on an actual source-backed instrument or supported hardware counter; it will not be fabricated from wall time.

Focused follow-up will inspect CLRS asymptotic and amortized sections, an actual primary external-memory passage, a primary control-flow metric passage, official clocks/read/write/perf/cgroup/instrumentation and exact Cortex-M4 DWT/timer scopes. The proposal should contain about fourteen assessable topics and twelve bounded milestones, each reusing a named prior artifact. Reject an exhaustive tool catalog, inferred performance guarantees, uninspected textbook chapters and any automatic equivalence among measurements.

The parent’s subsequent boundary review adds four required negative interpretations to the focused protocol: concurrent process CPU can exceed elapsed time; wall-minus-process-CPU is not a universal waiting measure; asynchronous spans overlap rather than form a partition of latency; and zero useful-byte amplification is undefined. Sample quantiles and observed maxima remain finite observations rather than WCET. These corrections sharpen the planned observation contracts without expanding implementation scope.

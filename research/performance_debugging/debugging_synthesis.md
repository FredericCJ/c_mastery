# T44 debugging synthesis

T44 is a repeated diagnosis route: predict competing causes, reproduce a bounded same-failure trigger, find the first invalid state, reduce irrelevant input, repair the violated contract and replay regression/transfer cases. The failure signature is a semantic classification with a build/input identity, not an exact tool message or prescribed UB outcome.

The shared dossier has nine fields: expected contract; pre-run symptom predictions; source/image/configuration/environment identities; bounded replay and actual observation; earliest invalid transition with supporting state; two competing hypotheses and a discriminating test; reduced trigger with PASS/FAIL/UNRESOLVED results; causal repair and remaining limits; matched regression matrix and delayed unseen variant. Static expected histories are labelled models; only collected runtime/tool/hardware records are labelled observations. Logging, debugger stops and instrumentation can perturb the system being diagnosed.

Reused mechanisms are explicit. T21 supplies durable validation, first-cause context, cleanup/ownership and bounded logs. T24 supplies partial cursors, generation-qualified descriptor identity and lost-event state machines. T25 supplies predicate waits, forced schedules, happens-before and deadlock graphs. T29 supplies basic exception state, bounded ISR work and DMA completion ownership. T31 supplies image matching, startup/fault/peripheral triage and halt perturbation. T32 supplies minimized reproducers, dynamic/static/fuzz/differential tests and regressions. T33 supplies analysis context and alarm limits. T35 supplies resource/error and memory invariants; exploit practice is unnecessary.

PR-T21-03, PR-T24-04, PR-T25-05, PR-T31-01/02 and PR-T32-05/07 are concrete reused patterns. Existing implementations or completed learner artifacts are adapted rather than rebuilt. A learner who has not completed a selected prelude first performs that already-budgeted exercise; T44 hours cover only the changed defect/dossier/transfer. T44's memory milestone uses T03/T16/T21/T32. T45 later offers deeper bounds, lifetime, stack and linker-region practice, without a prerequisite cycle.

Input reduction operates on at most16 declared chunks with finite replay and memoized tri-state outcomes. UNRESOLVED covers a malformed candidate, a different failure or an unclassified timeout. A returned FAIL configuration is 1-minimal only after every single-deletion test is non-FAIL. Two different independent triggers give a useful counterexample to global-minimum inference. Repair is a separate contract argument.

Debugger practice starts with a valid-object, defined-state defect so stepping and watches have a meaningful comparison. A pure conditional breakpoint stops before the violating transition. Hardware watches can identify an instruction while software watches may stop at a later statement; either can miss inaccessible state, expire with local scope or be constrained by threads and target resources. Fallback is narrower valid-object watching, bounded logs or a replay harness, with the unsupported claim stated. Optimized images are inspected through matching symbols, instruction/source maps and the selected ABI, rather than assuming every local still exists. Cores are optional, bounded to a learner-owned process, and paired with their image; a saved state is not full history.

I/O histories preserve every positive byte count before another call. Zero read is EOF under the declared positive-count stream contract. EINTR before progress and EAGAIN/EWOULDBLOCK are distinct from positive short progress. Capture errno at failure before logging; pthread return codes remain direct status values. EPIPE can be masked by SIGPIPE termination. FD exhaustion is isolated and capped well below system-wide limits; compare an injected EMFILE model with an actual learner-process observation only if permitted. Linux close releases the descriptor early; do not retry and risk closing a reused number. The inspected POSIX.1-2024 EINTR rule differs, so this cleanup claim is explicitly Linux. Positive write is not a durability claim.

Concurrency diagnosis separates a forced schedule from all-schedule correctness. A wait-for graph can establish a cycle in a finite model; a detector run observes only exercised executions. Predicate checks under the same mutex and happens-before/lifetime arguments explain the repair. Sleeping longer is a competing symptom patch. Bare-metal diagnosis retains F439/basic-frame assumptions, fault-address-valid bits and precise/imprecise distinction. Reset/startup, MMIO clock/pin sequencing and DMA ownership use existing accepted contracts. Do not read arbitrary side-effecting registers in the debugger. Cache-maintenance recipes from cached Cortex-M7 targets do not apply to the selected F439 SRAM/DMA path, which has no core data-cache maintenance requirement. A halted CPU need not stop DMA; a timeout/cancel request is not completion.

Tool triage uses separate ASan/UBSan and unsanitized Memcheck tracks, bounded fuzz seeds and a differential reference for the same contract. Static alarms need context; sequential Eva analysis does not directly model asynchronous interrupts. Tool availability, platform and flags are recorded. No tool was executed during this source research. Neither clean reports nor an emulator snapshot establish safety, timing or physical peripheral behavior.

The proposed twelve topics have36 measurable leaves. Ten projects total82h; module reading18h, implementation56h, verification26h, assessment8h and consolidation6h total114h. Project time is the implementation+verification allocation, not an additional82h. All projects are4–12h. Late I/O/concurrency/firmware milestones have selected existing preludes; first milestones remain approachable after coreC. A future targeted source addition reopens the scoped gate before it is assigned.

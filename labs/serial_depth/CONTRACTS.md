# Serial depth: original bounded contract, revision 1

All APIs use ISO C17 with 8-bit octets, uint8/16/32 types and live, adequately sized, aligned objects. Build assertions and record the data model. Do not substitute an existing serial/CAN implementation. C type checking does not enforce ownership, semantic booleans, electrical validity or operation ordering. Host Python, ctypes, CTest and sanitizers are verification dependencies only. The target core uses scalar operations, fixed arrays and type/limit headers; no heap, libc, OS, MMIO or board access. The Cortex-M4 link audit must list implicit compiler helpers and the explicitly supplied byte-loop helper implementation. No board execution follows from that audit.

All control objects begin zero-initialized, remain single-owner and are modified only through these APIs. There are no callbacks or concurrent interrupts in this model. All input spans, controls and output objects are distinct/nonoverlapping; caller-owned inputs stay immutable for a call. Scalar null outputs and invalid ranges return INVALID without publication. BUSY can mean documented progress; it is not uniformly unchanged. STALE means no effect. FULL means the stated operation cannot publish, except the explicitly sticky CAN FIFO overrun flag. State storage remains live through cancellation/quiescence. Tokens are positive uint32 values increasing strictly per control, never wrapping: exhaustion retires the control after outstanding events drain, not reset-and-reuse with old events present. A real interrupt adapter must preserve these rules with an explicit synchronization and hardware-quiescence argument.

## UART

sd_uart accepts width 7 or 8 payload bits, parity 0 none/1 even/2 odd, one or two stop bits and a value fitting width. The wire is start0, payload LSB first, optional parity, stop1. Width is payload width, not the F439 M field: hardware word length includes parity. A 7-bit/no-parity model frame is not claimed to be an F439 M configuration. Up to 12 bits fit. sd_uart_decode requires the exact count, bits0/1, valid start, parity and every selected stop bit; malformed syntax is INVALID, bad frame is IO, and value is unchanged on either failure.

Clock and baud are positive uint32. Choose divisor N=round(clock/baud), ties upward, by quotient/remainder without overflowing their sum. Scale is16 or8. Require scale<=N<=scale*4096-1. BRR=(N/scale)<<4 | N%scale, keeping bit3 clear for OVER8. Realized baud is the rational clock/N; derive signed ppm from that rational with a sufficiently wide host oracle, not a rounded integer rate. The model does not establish oscillator tolerance. sd_uart_receive accepts synthetic status bits RXNE1,ORE2,FE4,PE8,TXE16,TC32 and byte0..255. Its conservative application policy publishes a byte only for RXNE without any error; value0 otherwise, plus an error mask. This does not mean F439 loses the old RDR byte on ORE. Real SR-then-DR clearing remains a separate adapter obligation. TXE and TC are distinct observations; the RS485 exercise tests their ownership consequence.

## Synchronous USART

sd_sync takes booleans CPOL,CPHA,LBCL,TE,RE,changing. Reconfiguration while TE or RE is set returns BUSY unchanged. Reconfiguration with both disabled succeeds with an empty trace. A transfer requires TE even when RE is enabled. Eight LSB-first data bits have16 edges with LBCL or14 without; neither start nor stop adds clocks. Edge i after the transition has level CPOL xor ((i+1) mod2); sample is true iff i mod2 equals CPHA. data[0..7] is the TX bit order. Unused edge cells are zero. This finite edge predictor omits analog setup/hold, phase delays and register writes; required hardware evidence remains separate.

## I2C single-register read

sd_i2c_begin takes address0..127, a register byte, fresh token and idle state. It returns START_WRITE and address<<1, then retains register and token. The caller's immutable transaction record retains the address for RESTART_READ. ACK in phase1 emits WRITE_REGISTER and the register byte; ACK in phase2 emits RESTART_READ (same address with direction1); ACK in phase3 emits READ_NACK_STOP, requesting exactly one received byte followed by the controller's terminal NACK and STOP. BYTE in phase4 publishes the byte, emits STOP and returns idle. Final NACK is an action, not an erroneous incoming NACK. Unexpected event/phase pairs reject unchanged.

Incoming NACK in phases1/3 returns ADDRESS_NACK, phase2 DATA_NACK; timeout returns TIMEOUT. These release transaction state and emit STOP. Arbitration loss returns ARBITRATION_LOST, releases state and emits RELEASE, never STOP. Previously emitted bus actions are not rolled back. The adapter must wait for bus-free before a separately bounded retry; no automatic retry or hidden repeated write. An old token cannot complete a new operation.

sd_i2c_clear models only a released-line observation: scl/sda are booleans; release_after1..9 means SDA rises on that pulse,0 or10 means no release. SCL low returns RESET with zero pulses; SDA already high succeeds with zero; otherwise issue at most nine and stop immediately on release. Continued SDA low returns RESET with nine. This is not a target I2C register recovery recipe, and clock stretch timeout is not proof of a broken electrical device.

## SPI

One transfer has1..16 bytes, fresh token, mode0..3 (CPOL=mode>>1, CPHA=mode&1). Edge prediction returns clock level, sample predicate and MOSI logical bit associated with each pair of edges; bytes are MSB-first and the original peer supplies an independently chosen byte. MOSI cells are logical setup values, not analog transition-time samples. The resulting MISO byte must equal that peer byte under all four modes. Electrical setup/hold remains unmodeled.

State1 waits for TXE before one logical send; state2 waits for RXNE and always drains one byte into rx[position], including send-only clients. A single poll can observe both and complete that byte. After all bytes, DONE and state0 require TXE and !BSY. No extra send occurs after the final receive. Intermediate polls return BUSY with progress. cancel(stopped0) sets state3, holds ownership and returns BUSY; ordinary polls while cancelling cannot complete. Only cancel(stopped1), based on a real adapter's quiescence evidence, returns DONE and releases. Device error flags and timeout detection must be added by the required register adapter, not inferred from this boolean trace.

## Electrical decisions

kind0 is an original bounded RS232 receiver decision model: mv<=-3000 means logic1, mv>=3000 logic0, otherwise unknown(-1). kind1 is a declared differential A-minus-B convention: mv>=200 means1, mv<=-200 means0, otherwise unknown. swapped complements known decisions only. Both require exactly one driver; model admits one receiver for kind0 and1..10 for kind1. These are exercise premises, not universal transceiver ratings or a generic connector pinout. Actual MAX3232/RS422 power, common-mode, loading, termination and ground limits require the selected datasheet/board and measurements. Disconnection cannot be inferred from zero alone; unknown is deliberately distinct from logic0.

## RS485 byte channel

Original timing fixture uses nanoseconds in uint32 strictly monotonic time without wrap; reject backwards time or infeasible additions. Begin copies1..16 bytes, then waits600ns enable delay (phase1). phase2 accepts one byte per TXE observation; each observation is an adapter assertion of readiness, not a modeled baud generator. Final TC must follow all bytes. Then phase3 waits200ns disable plus2000ns guard before publishing TXDONE and releasing. Buffer ownership includes the guard. A two-byte100kbaud trace starts at0, first send600, second100600, TC200600, readiness202800ns. TXE alone never proves the last stop bit ended.

cancel(stopped0) moves to phase4 and retains ownership; stopped1 starts the same2200ns guard with a pending ABORTED event. Poll completes it after that deadline. Missing stop confirmation cannot be converted into success by a timeout. Receive events are admitted only in idle: RX stores a byte and event, FRAMING/OVERRUN store an error event with no byte. There are16 queued bytes and32 events; capacity failure preserves queues. sd_485_take removes one event and its RX byte if applicable, returning value0 for non-byte events; empty is FULL unchanged. Consumer backpressure is explicit. No concurrent producer/consumer, event preemption, transceiver sleep state, arbitrary device timing or physical turnaround claim is implied.

## Classic CAN

SDCan stores11-bit or29-bit identifier, booleans extended/remote, DLC0..8 and8 byte slots. Data frames transmit DLC bytes; remote frames request that DLC and transmit none. Arbitration compares actual dominant0/recessive1 prefix bits, including SRR/IDE/RTR, and returns -1 A wins,+1 B wins,0 indistinguishable prefix. Equal prefixes do not prove both payloads may differ safely. Identifiers are content selectors, not destination addresses.

Encode emits SOF, standard/extended arbitration, zero reserved bits, DLC, optional payload MSB-first, CRC15 and dynamic stuffing through the CRC sequence; then recessive CRC delimiter, transmitter ACK slot, ACK delimiter and seven EOF bits. CRC uses polynomial x^15+x^14+x^10+x^8+x^7+x^4+x^3+1, initial0, no reflection/complement. Decode removes mandatory complementary bits after each run of five, checks exact length/DLC, reserved0, CRC and fixed trailer; ACK slot accepts0 or1 but does not establish ACK receipt or application delivery. Any semantic/frame error preserves the entire output. Encoder capacity failure preserves count and bytes; maximum160 cells is sufficient for the admitted model. All cells must be bits.

This intentionally strict teaching subset accepts all in-range numeric identifiers, including ranges restricted in the historical Bosch1991 standard-format text, but rejects recessive reserved bits which that text allows receivers to accept. EOF requires all seven recessive although the historical receiver validity rule treats the final EOF bit differently. These are explicit API boundaries, not hidden conformance claims. It omits full intermission/error/overload frames, fault counters, resynchronization and bus-off recovery. CRC/stuffing/oracle comparisons cannot establish full ISO11898 conformance.

## bxCAN models

Timing prescaler1..1024, BS1=1..16, BS2=1..8, SJW=1..min(4,BS2). BTR stores each minus1 at shifts0,16,20,24. rate is floor(clock/[prescaler*(1+BS1+BS2)]); exact rate and sample point(1+BS1)/(1+BS1+BS2) must be derived separately. Filter is the11-bit predicate(id&mask)==(filter&mask), not full hardware filter-bank packing.

FIFO capacity3: locked overflow discards incoming, sets sticky overrun and returns FULL; unlocked overflow replaces the most recently stored entry, not oldest, sets overrun and returns OK. Pop returns/removes oldest once; empty FULL leaves output unchanged. Mailbox submit needs idle/fresh token. complete outcome0 success,1 arbitration loss (remains pending/BUSY for explicit retry observation),2 error,3 stopped cancellation. Others become ready. take publishes a ready result once, transitions idle and rejects duplicate/stale events. This is an original controller model, not an MMIO write/clear recipe or complete bus-off state machine.

## CAN FD boundary

Raw metadata must be validated before converting to bool: DLC0..15, FDF1, BRS/ESI0..1, remote0, capability0..1. Non-FD controller returns UNSUPPORTED unchanged. Lengths0..8 then12,16,20,24,32,48,64; CRC width17 for length<=16,21 otherwise. brs/esi are preserved. spi_bytes=4+4*ceil(length/4) is an original four-byte-header, padded-word transport-cost fixture, not the MCP2518FD two-byte command/address codec. A valid zero-length FD frame is required. Protected stuff count, fixed stuffing, pre-ISO differences, transmitter delay compensation and actual external-controller framing remain required parent work; this metadata routine is not an FD encoder.

Each named anchor has two compiled semantic mutants and a compiling failing learner stub. The independent Python oracle uses arbitrary-precision division, explicit edge/queue models and polynomial long division. Record exact compiler, flags, command, output, source hash and scope. A passing finite suite is falsification evidence, never proof of absolute mastery. Solutions stay under assessor/. All deliberately flawed targets are original local programs with synthetic frames, statuses and voltages. No external bus/service, deployed equipment, host security change or real hardware access is authorized.

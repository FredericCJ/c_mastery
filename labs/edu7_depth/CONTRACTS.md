# EDU7 depth: original portable contracts, revision 1

These additive C17 mechanisms resolve named implementation gaps in the existing EDU7-v1 projects. The original wire format remains in research/enhancement/networking_contracts.json. No accepted baseline source, identity, hours or receipt is rewritten. The retained EduSession.effects counter counts L5 publications, not successful L7 SET operations; new receipt transactions below make the application commit boundary explicit. Existing separate per-direction baseline objects require composition; this model owns both direction receipts under one dialogue authority.

Use the public header. Controls begin zeroed, remain live, are owned by one serialized caller and are mutated only through the API. All input/output/control regions are disjoint, with exact live capacities. Inputs need remain live only until return; all pending work copies its bounded bytes. Read-only snapshots of exposed controls may be used for verification. No ISR, thread or actual DMA concurrency is established by this serialized model. Scalar/output contracts below are runtime checked; pointer lifetime, nonaliasing and correct external acceptance/stop evidence remain programmer discipline. Target code uses only type/limit headers and explicit audited compiler byte-copy helpers, no allocation or protocol library. Host tools and imported codec composition are separate.

Reject invalid arguments without altering state/output unless the documented timeout, tick or cancellation transition says otherwise. All token IDs are nonzero, strictly increasing, never wrap; exhausted generation space returns FULL. Clear memory only after proving all prior tokens/incarnations irrelevant; zeroing a live object to evade retirement is invalid. Status numbers are in the public header. BUSY, WAIT and STALE are distinct: resource/ownership unavailable, deadline not due, and invalid incarnation/state. Local success does not prove physical or peer delivery.

## Grant and admission: X-T40-002

Times are nonwrapping uint32 microseconds. `e7_grant_begin(now)` is called when the local POLL has completed through final UART TC, not at TXE. The supplied lower adapter has already released DE; begin establishes earliest peer start now+200 guard, last permitted first byte now+2200 and next turn no earlier than now+25000. Start time must leave room for25000; generation exhaustion rejects. One turn is active at a time.

`first(token,now)` accepts the first actual peer byte only in phase1, at or after the guard and at or before the inclusive start deadline. Early returns BUSY without progress; late transitions idle and returns START_TIMEOUT. Success enters phase2 and sets the completion deadline to first-byte time+10000. `finish` requires phase2 and exact token; at or before the inclusive deadline it completes, later returns END_TIMEOUT, both transition idle. Once first byte arrives, the old start deadline no longer limits this reply. `tick` advances monotonic last time and expires phase1/2 only strictly after the corresponding deadline. Finish twice or first after expiry is STALE. Next turn still respects the original25000 schedule; this model never deliberately overlaps drivers.

Example begin0, first1500, tick2300, finish9500 succeeds. A2ms start deadline cannot truncate the legal8ms reply. Begin25000 with no first byte remains active at27200 and expires27201. All operations O(1), fixed control storage. Physical UART/DE and bus measurement remain independent; this API assumes the begin event's actual TC/guard premises rather than manufacturing them.

`e7_link_admit` is the explicit adapter after a validated retained L2 frame. Kind0 DATA,1 POLL,2 EMPTY; local/destination1..2; grant/transmitting/fault boolean. Locally transmitting echo produces deliver0 with OK and cannot become a peer packet, including faulted echo. For a nonlocal echo candidate, UART fault, wrong destination or POLL addressed to master1 returns REJECTED without output publication. DATA/EMPTY additionally require grant. POLL addressed to slave2 is admitted as control; only DATA sets deliver1. Source/header/CRC validity and actual frame boundary are prerequisites supplied by the retained decoder and adapter; this function does not revalidate wire bytes or authenticate the sender. UART errors must still be counted by the lower adapter even when echo is ignored.

## Offer versus accepted transmission: X-T40-003

Time is nonwrapping uint32 milliseconds, nondecreasing per sender and at most UINT32_MAX-500. `begin` copies1..120 bytes for ports7->8 or8->7, positive16-bit transfer ID strictly greater than prior ID, and admits one active message. Transfer IDs exhaust instead of wrapping; reopen into a separately proven epoch before reuse. Count=ceil(length/24), index0, credit1. The caller must establish initial peer credit separately; the transport is not an inter-message admission authority.

`offer(now)` returns a copied DATA fragment of1..24 bytes or zero-length PROBE and a fresh32-bit offer token. All nonfinal DATA fragments are24 bytes. A pending offer blocks another; modify neither its bytes nor its identity through the caller's copy. Offer is staging: it does not start a100ms timer, set waiting or consume a retry. The lower adapter then calls `accept(token,accepted,now)` once. False clears the staged offer with BUSY, leaving existing protocol deadlines/retries unchanged. True starts the next100ms due time from acceptance; DATA marks waiting, and only an accepted retransmission increments retries. Old/duplicate accept token is STALE.

When waiting, exactly three accepted retransmissions after the original are permitted. At the next due time after retry3, offer returns TIMEOUT and logically releases the active message without publishing partial upper data. Example first accepted250 yields retry opportunities350,450,550 and terminal650, irrespective of earlier rejected offers. Lower BUSY does not consume a retry. The fragment's copied bytes/index remain identical until matching ACK.

ACK type2 has zero length, reversed ports, exact transfer ID/index/count and boolean credit. It cannot arrive while a staged offer remains unresolved; resolve that lower admission first. A matching ACK while waiting advances exactly one fragment; final ACK completes the message regardless of credit. A mismatched ACK changes nothing. A blocked sender can accept a matching PROBE response without advancing data. Credit0 starts one independent500ms blocked deadline if not already blocked. Repeated credit0 replies/probes do not renew it. Credit1 before expiry reopens DATA immediately. At/after deadline, offer/accept/ack/expire returns TIMEOUT, releases active/offered state where present and cannot revive the message. `expire` is an explicit tick for a blocked sender even when no lower calls occur. Frame delivery, tuple node IDs and session epochs remain an explicit higher/lower adapter duty.

State retains bounded bytes after logical release for reuse; it does not promise cryptographic erasure. Original message staging O(n), subsequent fixed24-byte offers O(24), other operations O(1);120-byte owned payload plus one fragment. No unbounded retry loop or allocation.

## Transactional per-direction session receipts: X-T40-004

`open` accepts nonzero16-bit session/epoch, schema1/unit1. A duplicate current identity is DUPLICATE; another identity while open is BUSY. On reopening this original stricter local profile requires epoch greater than every prior epoch in this control, even if session ID changes. Exhausted epoch cannot wrap. Initial holder is node17; peer is51. Both direction checkpoints start0. Generation history persists across reopen. Identity fields are replay namespaces, not authentication.

`prepare(sender,session,epoch,checkpoint,bytes,n)` accepts1..80 copied bytes, matching open identity and a valid sender. Each direction has its own receipt. An identical request at that direction's last committed checkpoint returns DUPLICATE with copied cached response, token0 and exact response length, even after token transfer. Changed bytes at that checkpoint reject. Insufficient cached-output capacity returns FULL transactionally. Such replay does not grant new DATA permission or repeat an effect.

A new request requires current holder, no TOKEN_PENDING and no pending request, next positive per-direction checkpoint, and nonexhausted generation. It copies bytes into pending storage and returns a fresh token; committed checkpoint/receipt and application state remain unchanged. Caller independently validates presentation and stages any application update and response in private storage. `commit(token,accepted,response,n)` accepts response0..80. Rejection requires n0 and discards pending state without checkpoint/effect; success atomically copies the pending request and response into that direction receipt, commits the checkpoint and clears pending. A callback must not perform an irreversible external effect before this decision: this RAM model does not provide crash atomicity with devices, files or remote services. In the supplied synthetic application adapter, stage the new setpoint locally, encode response, commit receipt, then publish the local setpoint in the same serialized operation. An ERROR response to an application-level invalid SET can be a committed request without being a successful SET effect. Malformed L6 is rejected before commit.

`token_begin(sender,next)` requires holder, open session, no pending request/token and the other valid peer. It enters TOKEN_PENDING without restoring permission on lost confirmation. `token_complete(next,confirmed)` accepts only matching pending destination; false returns BUSY and keeps the pending state, true transfers holder and clears it. This is the coordinator side of an explicit delivery proof; a real two-endpoint adapter still needs matching token transport incarnation, receive idempotence and uncertain-reset recovery. No timeout may simply assign permission back. Close is BUSY while request/token pending; reject a prepared request explicitly first. Unconfirmed token recovery remains an external quiescence/renegotiation obligation.

`resume` requires matching retained session/epoch and the selected sender's exact committed checkpoint; closed or zeroed/rebooted controls refuse. Close ends authority while retaining epoch retirement history; reopen clears both receipt lengths/checkpoints. RAM does not establish durable exactly-once effects.

The supplied `retained_adapter.c` is a host composition witness using actual `com_edu7.h` codec/application APIs via explicitly supplied source files. It stages the synthetic setpoint and response, rejects malformed schema without committing, replays cached duplicate SET response, commits invalid-SET ERROR without a SET effect, and confirms GET returns the separate plant value1800. It does not execute the complete reverse routed dialogue or hardware topology. Learners provide their completed communications sources explicitly; assessor code is never copied into learner work. Receipt preparation/commit O(n), two80-byte requests and responses plus80-byte pending storage. Duplicate comparison is bounded byte equality, not a collision-prone hash identity.

# Parsing depth contract 1

X-T15-010 through013 are required additions. The public `parsing.h`, original fixtures and compiling `src/parsing.c` are learner material. Implementations, extra model oracles and technical solutions under assessor remain withheld. Accepted project IDs and historical hours are unchanged.

## Shared environment and admission

Use C17, profile C, caller-owned typed storage. No regular-expression, parser-generator, interval, container or arbitrary-precision library may implement a studied mechanism. The host harness and independent Python models are profile A and are not target dependencies. Exact-width uint64_t/int32_t availability and8-bit bytes are selected premises. Audit generated copy/zero/64-bit-shift support explicitly; named compiler support is allowed by profile C, not evidence of a complete freestanding image. Do not claim language-level memory safety or a physically validated target from these host tests.

All supplied pointers must name live aligned objects of the declared extents; nonnull diagnostic and output objects must be distinct from each other and from input/control storage. Null input is permitted only with zero length. Grammar/input objects remain immutable throughout a call. Components allocate no heap, retain no caller pointers and invoke no callbacks. No concurrent mutation or reentrancy assumption is needed beyond independent object ownership. A malformed pointer itself cannot be safely validated by portable C.

Codes are OK0, NO_MATCH1, PENDING2, RANGE3, INVALID4, CONFLICT5, FUEL6, EMPTY_LOOP7, DOMAIN8. INVALID means structural admission failure, RANGE means an admitted capacity/numeric bound cannot be met, and NO_MATCH means syntax/language rejection. PENDING is used only for nonfinal scannerless input. Result objects and scalar outputs are unchanged on every non-OK return. A valid supplied diagnostic may be reset/updated even on failure; it is evidence, not a partial result. Do not compare unspecified object padding for successful values. Public rejection tests compare byte snapshots only where no write is permitted.

## X-T15-010: finite regular languages

Compile a pattern of at most24 bytes under `expr := concat ('|' concat)*; concat := repeat+; repeat := atom ('*')*; atom := 'a' | 'b' | '~' | '(' expr ')'`, with any number of successive stars permitted. `~` is the empty string. Concatenation binds tighter than alternation and star tighter than concatenation. Empty patterns/branches, unmatched parentheses and other pattern bytes are NO_MATCH; excessive length or state demand is RANGE. These are a deliberately explicit regular-language syntax: no backreferences, Unicode, captures, wildcards or lookaround are implemented or implied. Diagnose an offending byte position, not just an unspecified compile error.

`rx_compile` owns an at-most64-state Thompson-style NFA with BYTE, EPSILON, SPLIT and ACCEPT states. Indices replace raw internal pointers. Its output copies the compiled representation and does not borrow pattern bytes. `rx_match` accepts a valid immutable NFA and arbitrary input bytes of length0..256. `search=0` requires the entire input; `search=1` asks whether any substring, including an empty one, belongs to the language. Bytes outside a/b can separate search candidates but cannot satisfy BYTE states. Epsilon closure must terminate on `a**` and `(~|a)*`, marking a state before following its edges; a repeated state is not a new concurrent path.

`rx_determinize(nfa,capacity,out)` performs subset construction over a/b, capacity1..16. It includes reachable empty/dead subsets as needed. A table exhausting capacity returns RANGE unchanged, leaving the original NFA available for a caller-selected fallback. DFA states are created from start closure, then breadth-first by a followed by b; the exact numeric identity is a representation detail, language equivalence is the assessed property. `rx_dfa_match` performs whole-input matching only, with outside-alphabet bytes rejecting. Do not compare search-mode NFA timings with whole-input DFA timings.

Compile `(a|b)*abb`: aabb is a whole match, abbc is not, cabbc is a search match. At capacity1 determinization is rejected. `(~|a)*` accepts empty/aaa, and `a**` must terminate. Derive O(pattern-size) NFA storage, O(input-length × states) simulation with a deduplicating closure worklist, and potentially exponential subset count. The finite16-state table bounds resources by rejection, not by proving all regular languages need sixteen states.

## X-T15-011: SLR tables and derivation trees

`struct lr_grammar` contains1..12 productions; each right side has0..4 symbols. Terminals are0..6, EOF7 is never present on a right side, ordinary nonterminals are8..11. Production0 must be the sole augmented12->start rule, where start8..11 is defined. All other left sides and referenced nonterminals must be defined ordinary symbols. Epsilon is a zero-length right side. Unused array cells have no semantic role.

`lr_build` computes nullable, FIRST, FOLLOW, LR(0) closure/goto and the SLR ACTION/GOTO tables from these productions. At most60 item positions and32 states are admitted. State construction starts from closure of production0 at dot0, then visits states breadth-first and symbols in ascending order. FIRST/FOLLOW array index0 denotes nonterminal8. FOLLOW(start) includes EOF. Reduction actions are admitted only on FOLLOW(lhs). Two distinct actions in one cell return CONFLICT; never silently prefer shift, earlier production or a particular associativity. State exhaustion returns RANGE. All result tables remain unchanged on failure. Conflict diagnostics identify the state index and lookahead terminal; they do not assert that the grammar is ambiguous rather than merely outside SLR.

ACTION0 is error, positive j+1 shifts to state j, negative p reduces production p,99 accepts. GOTO=-1 is absent. `lr_parse` requires the exact successful table, retained without mutation. It consumes0..64 terminal IDs0..6 and an explicit action budget. Exhaustion is FUEL, including on a cycle of zero-length reductions; no indefinite recovery search is performed. Rejection reports the first blocked token index. Build a typed derivation tree with at most128 nodes and child indices smaller than the parent. A terminal node has production255, no children and span[i,i+1); a reduction carries production ID and children in grammar order; epsilon spans[p,p). Publish the tree only after complete EOF acceptance.

`grammars.h` supplies expression grammar E->E+T|T, T->T*F|F, F->(E)|n with12 LR states; token n=0,+=1,*=2,(=3,)=4. Input n+n*n must derive multiplication inside the right T. Ambiguous E->E+E|n must report a conflict. The delayed grammar S->A '+', A->n A|epsilon requires nullable/FOLLOW propagation; '+' alone and n n '+' succeed, empty input fails. A valid derivation is not yet semantic evaluation: source spans and production tree must remain available to a separate consumer.

## X-T15-012: Pratt binding and checked semantics

`pd_lex` accepts up to256 bytes and emits at most64 tokens plus explicit EOF. It recognizes nonnegative decimal int32 literals, +,*,-,^,(,), and ignores only ASCII space/tab/newline. Each token records byte offset/length and one-based line/column; a tab advances one column. Minus is a separate token, so spelling2147483648 is rejected even if preceded by minus. Literals exceeding INT32_MAX return RANGE. Unknown bytes and malformed token arrangement are distinct lexical/syntax failures.

`pd_pratt` accepts an immutable admitted token sequence ending in EOF and builds an at-most64-node postorder tree. Binding powers are +/binary-minus10, multiplication20, unary-minus30, exponent40. `right_power`0 selects left-associative exponent;1 selects right-associative exponent. A nud handles integer, unary minus and parenthesis; a led handles binary operators. Stop when the next left binding power is no greater than the caller's right binding power. Every token must be consumed before EOF. Tree kinds are integer0,add1,multiply2,unary-minus5,power6,subtract8. Children precede parents; positions identify source operators/literals. Parsing must succeed even when later arithmetic overflows.

`pd_evaluate` is a separate checked int32 interpreter over that tree. Widen before addition/subtraction/multiplication/negation. Exponents must be integers0..31 (DOMAIN otherwise);0^0 is defined1 for this teaching language. Overflow returns RANGE without changing output. No undefined C signed overflow is used to emulate language arithmetic. Thus2^3^2 is512 in right mode and64 in left mode, -2^2 is-4,1+2*3 is7;2147483647+1 has valid syntax but fails evaluation.

## X-T15-013: scannerless ordered recognition

`struct ps_node` is an expression DAG of1..64 nodes; root0, all child indices strictly greater than their parent. This explicitly excludes recursive/nonterminal references and left recursion; it is sufficient for the bounded lexical-and-record grammars in this exercise, not a universal PEG interpreter. BYTE, inclusive RANGE, ANY and EMPTY are primitives. SEQ combines two expressions. CHOICE retries the right expression only after definite NO_MATCH; PENDING cannot be treated as failure. STAR is greedy, returns on a definite body failure and rejects a successful zero-length body with EMPTY_LOOP. NOT consumes nothing, succeeds only on definite failure, fails on success, and propagates PENDING/FUEL/RANGE. CAPTURE attaches tag `low` and byte span to its child's successful result; up to32 captures are admitted.

`ps_parse` accepts up to256 immutable input bytes, an EOF flag and a node-invocation budget. Every node visit consumes one unit; no unit returns FUEL. Primitive exhaustion at a nonfinal boundary is PENDING, at EOF is NO_MATCH. A successful root publishes its end position and captures; it need not consume the entire input unless the grammar ends with NOT ANY. All captures created by failed alternatives or lookahead must be rolled back. Captures are postorder; repeated tags are allowed. Diagnostics report the furthest primitive mismatch/boundary and the last tied expected lower byte, including speculative attempts; they are not claimed as a complete expected-token set.

Construct a scannerless assignment grammar that distinguishes keyword `let` from identifiers by negative lookahead, consumes whitespace explicitly, and captures identifier/value spans. `let x=12` is a declaration, `letx=2` an assignment, and reserved `let=2` is rejected. Decimal validation can be a separate consumer; recognition must not silently evaluate or mutate an external symbol table. Demonstrate that `(a / ab) EOF` rejects ab while `(ab / a) EOF` accepts it. This is prioritized choice, not regular-expression alternation. Every prefix of a nonfinal input is retried on the retained full byte prefix; the API does not retain an incremental parser state and makes no linear-total-work claim across repeated prefix calls.

## Proof, resource and security obligations

For each mechanism derive representation/lifetime invariants, admission/postconditions, failure atomicity and actual complexity. NFA worklist deduplication and parser budget/forward DAG bound adversarial work differently; neither is a universal parser-security guarantee. Keep syntax trees/captures separate from semantic validation and side effects. Test empty/singleton, exact-capacity, malformed and changed-assumption inputs, and independently minimize two distinct semantic mutations per anchor.

All attack-oriented inputs are synthetic and run only against these original local parsers. Attacker capabilities are selecting pattern/grammar/input bytes within the supplied harness, not corrupting trusted tables or arbitrary pointers. Harmless success conditions are a wrong recognition, leaked speculative capture, unjustified conflict resolution, exceeded declared budget or lost output preservation. Repair the mechanism and retain regressions. A syntax error, sanitizer finding or timeout is not a demonstrated arbitrary-code-execution exploit. No network target or host security change is needed.

Record compiler identities, input generators, raw outcomes, allocation/stack/table size and generated helper calls. Compare NFA and DFA only on identical whole-match contracts and separate compilation cost from reuse. The supplied model oracles use different representations: language sets, Earley recognition/derivation certificates, operator stacks and immutable capture lists. These are finite falsification evidence; independent derivation and delayed transfer remain separate gates.

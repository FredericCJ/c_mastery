# Longest-prefix scanning and repeated failed work

This required refinement of T15.14 follows X-T15-010. Retain its actual `RxDfa` and NFA/subset-construction artifacts. The implementation baseline is ISO C17 with eight-bit bytes, enforced by a translation-time assertion. No C23 facility is needed. Hosted CTest/Python/stdio/clock are verification tools, not scanner dependencies. The strict Cortex-M4 audit covers the scanner and adapter, with only explicitly identified original byte helpers; it does not execute the earlier regex compiler on a board.

## Mechanism and worked derivation

A scanner recognizes a sequence of tokens, whereas a whole-input recognizer only answers whether the complete string belongs to one language. At each token start, select the longest nonempty matching prefix; only equal lengths use rule priority. Consider ordered rules `abc`, `(abc)*d`, `abc`. On `abcabcd`, the first rule accepts after three bytes, but the second accepts all seven: selecting the first acceptance is wrong. On `abcabc`, the machine can pursue the second rule until EOF, then must return to its last acceptance at position3 and scan the second token. On `abc`, rules0 and2 tie, so rule0 wins. These are byte offsets, with exclusive ends.

Reps's author-hosted 1998 manuscript, selected pages1–7 and Figure1, distinguishes longest-prefix semantics, earliest-rule ties and potentially quadratic rescanning; the source register identifies the exact bytes and reading scope. Its `abc`/`(abc)*d` example motivates this original bounded implementation. On `(abc)^k`, a baseline scanner follows 3k transitions, then 3(k-1), down to3: total `3k(k+1)/2`, even though the returned k tokens have total length3k. A deterministic automaton alone does not make the complete scanner linear.

The changed-condition implementation records failed configurations `(state,input-position)` within one scan call. Such a record means that the fixed remaining suffix cannot reach an accepting state from that state. It is not a record that the state is universally dead. A known failure can stop a later fruitless search, without changing the saved last acceptance. Never carry these records into another input, modified transition table or changed accepting labels without a separate valid identity argument.

## Representation and operations

`MmDfa` contains1–16 states, a start index, 256 byte-to-class entries, four transitions per state and eight acceptance-rule bits per state. Map values0–3 select a class;4 means no transition. A transition is a valid state index or `MM_DEAD` (255). Zero acceptance mask is nonaccepting; the smallest set bit is the earliest rule. The start must be nonaccepting: nullable tokens are rejected to preserve progress. Validate every admitted map entry and state transition before scanning, including unused classes. Labels on unreachable states are permitted. This representation is a union automaton supplied by the caller; constructing arbitrary multi-rule DFAs is a separate exercise.

`mm_from_rx(source,out)` imports the actual prior binary-alphabet `RxDfa`. Its start is0, acceptance values must be0/1, and all a/b transitions must name an existing state. The adapter maps only `a` and `b`; every other byte is a dead class. A nullable source is refused. A valid empty language is allowed. Failure returns `PD_INVALID` and leaves the output unchanged. The function does not compile a regex or invent a substitute provider.

`mm_scan(dfa,input,length,mode,token_capacity,scratch,out,cost,error_offset)` admits lengths0–256 and capacities0–256. `input` may be null only for zero length; `out` and `cost` are required; mode0 is last-accept rollback and mode1 additionally uses memoization. Mode1 requires caller-owned `MmWorkspace`. Null/invalid metadata, out-of-range bounds and unsupported modes yield `PD_INVALID` before input access. Otherwise scanning either returns `PD_OK`, `PD_NO_MATCH` at the first token start with no accepting prefix, or `PD_RANGE` when a recognized token cannot fit the output capacity. Thus a nonmatching suffix takes precedence over output capacity at that position. Empty input succeeds with zero tokens even at zero capacity.

On complete success, `out` contains a contiguous partition `[0,length)` with strictly increasing nonempty spans and the selected rule per span; `cost` is published. On any failure these two objects remain byte-for-byte unchanged. If supplied, `error_offset` receives the failed token start only for `PD_NO_MATCH`/`PD_RANGE`; it is unchanged on `PD_OK`/`PD_INVALID`. Scratch may change on any call, contains no retained input pointers and is never an output token store. Inputs, output objects, scratch and diagnostic storage must be valid, correctly aligned, sufficiently large and mutually disjoint for their lifetimes; arbitrary pointers and overlap cannot be certified by this C API. Calls sharing mutable scratch require external exclusion. No heap allocation, library matching, hidden fallback or callback occurs.

`MmTokens` has256 span slots; `MmCost` counts successful transitions, bytes traversed beyond the eventual last acceptance, stops at a known failed configuration, and newly marked failed pairs. Invalid-transition probes, validation loops and table clearing are additional work and must be included in a full resource argument. `MmWorkspace` has a257-by16 byte table and two257-entry stacks. The input is not copied. Table entries are cleared for all admitted positions and states on each mode1 call. The local staged token result gives whole-call output rollback, not incremental token publication.

## Required construction and reasoning

First implement longest-prefix scanning with explicit `(begin,pos,state,last,mask)` invariants and a separate rule-priority operation. Trace all supplied strings, including the position at which a longer candidate fails. Then implement complete-output rollback and capacity diagnostics. Finally implement mode1 while preserving exactly the same token, error and publication contracts. Prove why a nonaccepting suffix of the current exploration stack may be marked, why marking stops at an acceptance, and why an accepting configuration cannot be declared failed. Prove token progress independently of the finite table bounds.

Derive the quadratic witness above. For the tabulation scheme, give the fixed-automaton linear-input argument from the failed-pair charging proof: distinct failed `(q,i)` configurations are charged at most once, and nonfailed exploratory stretches have a state-count-dependent bound. Keep the conservative `O(Q² n)` parameterized bound distinct from `O(n)` for fixed Q; initialization/storage is `O(Qn)`. This bounded implementation always stages a256-slot result and admits at most16 states/256 input bytes, so constant representation costs remain visible. Report actual `sizeof`, compiler stack reports, map/code sizes and counters separately from host clock ticks. Do not infer a universal speedup from one input or ignore table-clear costs on short strings.

ISO C enforces the declared representation and explicit checks only; it has no built-in maximal-munch, regex semantics, immutable borrow or array-index proof. Rust ownership or a lexer generator may enforce other properties, but neither ownership alone nor using a DFA proves this selection or complexity contract. Give a counterexample to each overstated claim.

## Local security and limits

Use only these original scanner programs and synthetic byte strings. The adversary controls admitted input and valid-but-costly DFA/lexicon choices; it cannot replace valid objects with forged pointers. The property is token correctness, bounded storage, output rollback and avoiding the demonstrated repeated-work amplification. A harmless success witness is a wrong local token or an excessive transition counter in an intentionally defective variant. Repair last-accept/priority/table lifetime, retain the regression and measure mitigation cost. A crash, undefined behavior or sanitizer report would not establish code execution, and this exercise makes no claim about a deployed lexer. True streaming/refill storage, Unicode, arbitrary regex syntax and unbounded lexicons require their own contracts.

# Finite streaming summaries

This original C17 component has three separate mechanisms. Read sketch.h with the relevant section before implementing src/*.c. All pointer arguments designate live, properly aligned, complete objects; output objects are disjoint from inputs. Exact self-merge is admitted; partial overlap is a caller violation. Configuration pointers do not alias destinations. The caller serializes operations and preserves initialized state. Runtime return codes check the specified numeric/configuration restrictions, not pointer validity, object lifetime or races. No function allocates, retains a caller pointer or invokes a callback. Public struct fields permit observation and the explicitly labelled synthetic estimator experiments; arbitrary state corruption is outside the normal update contract.

SK_OK publishes a complete result. SK_INVALID and SK_OVERFLOW preserve all destination/output bytes. Initialization accepts uninitialized destination storage and publishes only after configuration checks. Configuration identity compares the meaningful members, never struct padding or inactive slots. Ordinary structure assignment does not define a portable serialized representation. Copying an initialized value to separate live storage is allowed. Hash definitions and input-domain interpretations must travel with stored summaries; a matching integer identity label cannot certify those interpretations by itself.

## Count-Min ordinary mechanism and partition transfer

SkCmConfig specifies width 2^p for p=1..5 and depth 1..4. Each row's p masks and p-bit bias define h(key): bit b is parity(key & mask[row][b]) XOR bias bit b. Masks may be zero; a deliberately bad hash remains a valid configuration. Initialization clears every counter and total. sk_cm_add accepts uint32 keys and nonnegative uint64 weights, including zero; it increases exactly one counter per row and total. All affected sums are checked before any write. sk_cm_query takes the minimum of the selected counters. An empty summary returns zero. No negative-weight or deletion operation exists.

The ordinary invariant is that every active cell is the exact sum of admitted weights whose keys map to it, with total the sum of all admitted weights. Thus a point estimate cannot underestimate its true count. This assertion assumes no overflow and the nonnegative stream; it does not require randomness. Overflow is refusal, not saturation or modulo arithmetic. Obtain the actual byte footprint with sizeof rather than assuming an ABI's padding.

The required delayed change is merging independently processed partitions. sk_cm_merge requires equal active masks, biases, p and depth. It preflights total and every cell, then adds corresponding cells. Empty, self, mismatched and overflowing merges are required cases. Self-merge doubles represented weights, when representable. A failed merge preserves the old destination and source. Prove that the result represents the concatenated weighted stream; the same proof would not justify merging different hash maps.

Randomness is a separate premise. Uniform independent masks and biases give pairwise independent outputs within each row; choosing rows independently permits multiplying row failure probabilities for a fixed nonadaptive query/stream. With width w, expected collision mass is at most total/w. Markov with threshold 3*total/w gives failure at most 1/3 per row and at most 3^-depth overall. This component supplies parameters, not an entropy source. Its deterministic test configurations do not establish those probabilistic premises. A zero-matrix example returns another key's entire count. Discuss adaptive keys and adversarial hash choice explicitly.

## HyperLogLog ordinary mechanism and precision transfer

SkHll uses 32-bit prehashed inputs and p=4..8, hence 16..256 registers. identity is the caller's stable hash-domain/version label. Index uses the high p bits; rank is one plus the number of leading zeroes in the remaining 32-p bits, including rank 33-p for an all-zero suffix. Update is register maximum. Repeated hashes and insertion order do not change state. The API does not turn raw keys into high-quality hashes; that upstream obligation must be stated and tested separately.

The estimator uses the paper's practical alpha constants, harmonic indicator and small/large range corrections. Zero registers enable the small-range linear-counting correction. Above 2^32/30 the finite-hash correction applies; raw estimates at or above 2^32 return SK_OVERFLOW with output untouched because the real logarithm's argument is nonpositive. Empty state yields zero. Synthetic legal register vectors, including rank 28 and 29 at p=4, deliberately exercise finite-domain correction/refusal. Their cardinalities are not measured populations.

Double must have at least 53 significand bits and sufficient exponent range, enforced at compilation. The logarithm is original bounded range reduction plus 24 terms of an atanh series; its truncation bound and floating rounding are different error sources. The hosted oracle compares it with Python's independent math.log/log1p, including correction thresholds. No libm call is used in the component. Hosted compiler floating support is explicit; no cross-target runtime dependency or physical execution is asserted by this exercise.

Ordinary merge requires equal precision and identity and takes register maxima. The delayed sk_hll_fold admits a finer source into an equal/coarser destination with equal identity. Extra source-index bits become the prefix of the lower-precision suffix. If that prefix contains a one, its leading-zero position determines rank; otherwise add its length to the source rank. Skip empty source registers. Never average estimates or invent evidence from untouched registers. Compare folded state byte-for-byte over active registers with a direct coarse run over the same hashes; refuse attempted precision increase.

The commonly cited asymptotic relative standard error approaches 1.04/sqrt(m) under the paper's idealized independent uniform hash model. Small m has different constants, and this is not a worst-case bound. A fixed colliding stream can violate any proposed deterministic relative-error guarantee. Do not report an empirical fit or a successful merge as a proof of hash quality.

## MinHash ordinary mechanism and banded transfer

SkMhConfig explicitly stores 1..120 permutations of a universe of 1..16 elements. Each active rank row must contain every integer 0..universe-1 exactly once; initialization refuses duplicate or out-of-range ranks. Permutations may repeat across rows; this is legal but does not provide independent samples. The order of rows is part of configuration identity. This finite design makes the minwise premise inspectable instead of silently substituting an arbitrary hash.

Each signature holds a minimum rank per row, initialized to the universe sentinel. sk_mh_add updates minima, admitting only elements in the universe. Duplicates have no effect. sk_mh_similarity returns matching positions/count as an exact unreduced fraction. Two empty sets return 1; exactly one empty set returns 0. For a uniformly chosen permutation, the least-ranked member of A union B is equally likely to be any union member, so matching minima occur with Jaccard probability. The tests enumerate all 120 permutations on five elements and every subset pair; this exact finite identity is distinct from a confidence interval for sampled permutations.

sk_mh_merge takes minimum per position under equal full configurations, representing set union. It cannot generally reconstruct intersection or multiplicities. The delayed sk_mh_bands groups consecutive rows, requires a positive group size dividing count, and returns the number of complete equal bands. Empty signatures yield zero candidates even when both sets are empty. It is a candidate filter, not an unbiased similarity estimator. Under independent uniform rows, b bands of r rows produce candidate probability 1-(1-J^r)^b; reused or correlated permutations invalidate that derivation. Demonstrate both a candidate below J=.5 and a missed pair at or above J=.5 using the supplied ordered ten-permutation case.

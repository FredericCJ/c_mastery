## Derivation and representation — T28.06.a

TIM3 has a 16-bit prescaler, counter/reload and compare values. Let `P=PSC+1`.
An edge-aligned upcounter visits `0..ARR`, so `f=timer_hz/(P*(ARR+1))`.
Center-aligned counting visits `0..ARR-1,ARR..1`, so its period is `2*ARR` ticks.
For PWM1, edge duty is `CCR/(ARR+1)`; center duty is `CCR/ARR`. The hardware
direction changes the comparison at equality. Derive the waveform for ARR8,
CCR4,7,8,0 before coding; do not invent an extra tick at either reversal.
ARR0 blocks the selected timer and is rejected, not modeled as a one-tick PWM.

Implement `pt_choose` from a `struct pu_clock`, explicit PSC, requested positive integer
Hz, two duty requests in permille, mode and maximum frequency error in ppm.
It uses the actual APB1 timer clock from `pu_rates`. Round the ideal reload span
to nearest integer, ties to the larger period; this is a **period rounding**
policy, not a search for minimum frequency error. Reject if the unrounded span
is below one, if the selected edge span is below two or any span exceeds65535,
or if exact rational frequency error exceeds the allowance. Duty rounding is
nearest, ties upward, with its separate quantization error recorded. A desired
frequency of1001Hz at1MHz counter clock fails zero-ppm tolerance but can pass a
nonzero allowance. Do not silently clamp invalid requests into a different
waveform. Explain why the edge profile reserves ARR65535: full-duty CCR65536
does not fit the register. A forced-active output mode is a distinct extension.

`struct pt_config` owns clock identity, nonzero generation, PSC, ARR, two CCRs and mode.
`pt_ratios` returns unreduced numerator/denominator pairs for frequency, tick
seconds and both duties; outputs are distinct live objects and must not alias
the input. All failures preserve outputs. Configurations have clock1..180MHz,
PSC0..65535, edge ARR1..65534 or center ARR1..65535, and CCR in0..period-span.
Check arithmetic bounds before narrowing: after admission, base×span is at most
270MHz and error/ppm products fit64bits. Division in the constructor is only
32-bit after a validated narrowing. No target floating point is necessary.

Required artifacts: derivation, `timer.c`, annotated valid/rejected request table,
zero/full-duty traces, error budget, generated-code/import and resource ledger.
The fixed16MHz,PSC15,ARR999,CCR250 example must be explained, not memorized.
Compare the later `fw_timer` component under equivalent contracts: it accepts an
already prescaled clock and truncates duty. Identify a nonintegral-duty case in
which its result and this nearest-rounding policy differ legitimately.

## Active/shadow state and composition — T28.06.b

`struct pt_model` represents active and written shadow configurations separately.
`pt_init` installs a valid configuration at counter0/up, divider phase0, running,
UDIS=URS=UIF=0 and zero update count. `pt_stage` atomically copies the full shadow
configuration; clock/generation mismatch is STALE and a mode change is BUSY.
The API is serialized. Its atomic publication is a caller exclusion contract,
not an ISO C guarantee for concurrent struct assignment.

`pt_tick` advances one counter tick; `pt_input` advances one timer input clock
and divides by active PSC+1. Stopped advancement returns BUSY unchanged. An
edge overflow or either center reversal is an update boundary. With UDIS=0,
PSC/ARR/both CCRs latch together, the saturating diagnostic update count grows,
and UIF is set. With UDIS=1, counters continue but shadows do not latch.
`pt_ug` resets counter/direction/divider phase even with UDIS=1; otherwise it
latches shadows, and sets UIF only if URS=0. Clearing UIF is an explicit model
action. The model intentionally abstracts clocks and bus timing; it is not a
cycle-accurate STM32 simulator. Invalid externally corrupted model state is
outside the API contract; model objects must originate from `pt_init`.

Change ARR999→499 and CCR250/750→125/375 after tick250. Show unchanged active
state until overflow, then simultaneous publication. Add UG, UDIS and URS
interleavings; distinguish “no interrupt request” from “no update.” Provide a
counterexample to separately writing two unprotected preload registers: an
update between the writes can latch a mixed pair. `pt_f439_stage` temporarily
sets UDIS while all four values are written, then restores the running control.
This can defer a natural update; it promises a coherent pair, not a particular
first update deadline. Other thread/ISR writers must be excluded. Never set UG
midcycle merely to force a new duty without accounting for the shortened cycle.

Target code owns TIM3 exclusively from successful start to stop; clock-manager
generation must stay stable. RCC gate/readback/reset precede configuration.
ARPE and both OCxPE bits are enabled, initialization UG precedes output enable,
and both channels share TIM3's update event. Stale requests do not touch MMIO.
Changing clock or count mode requires stopping, recomputing and restarting.
`pt_f439_stop` disables counter and channel outputs; it does not guarantee an
external actuator's safe level. This lab connects only passive instruments.

Two channels on the same timer share the counter; two separate timers do not
become aligned because software writes CEN consecutively. Analyze trigger routing,
slave-clock admission and master/slave synchronization using RM0090 pp634–635;
identify common-clock/divider-phase and output-route limits. Do not claim a
zero-skew physical edge from a common logical event.

## Capture and measurement — T28.06.c

TIM4_CH1 on PB6 is a separate free-running16-bit capture timer. The adapter uses
no input prescaler or digital filter; it captures rising edges. It reads CCR1
before checking CC1OF, preserving the manual's overcapture ordering. Reading
CCR clears CC1IF; overcapture clearing uses **write-zero-to-clear**, unlike the
earlier W1C teaching device. BUSY/LOST leave output untouched. A LOST capture
invalidates the previous interval; establish a fresh baseline. The adapter is
bounded polling, not an ISR or a complete acquisition queue.

`pt_interval` admits counter values0..65535 and an independently established
maximum gap1..32767. With no overcapture it accepts a positive modular difference
no larger than that bound; otherwise it preserves output. It cannot detect an
unobserved whole wrap from the two timestamps alone. Supply an acquisition-rate
argument or independent elapsed-time bound; do not infer it from the returned
small difference. Capture time is distinct from interrupt-service time.

Use `BOARD_CAPTURE.md` for dedicated-board setup, safe routing, stimuli, raw
capture identity, limits and rejection criteria. `analyze_capture.py` computes
exact interval bounds from declared timer tolerance, instrument timebase,
resolution, edge jitter, probe skew and capture uncertainty. Its physical mode
requires raw-file identity and instrument metadata; neither that check nor
interval overlap authenticates calibration. Zero/full duty use a separate DC
level protocol because their missing edges cannot yield period/duty intervals.

## Verification, progression and assessment

1. Predict arithmetic and shadow traces, then implement and run public tests:
   `python labs/peripheral_depth/timer/run.py --source YOUR_TIMER.c
   --clock-source YOUR_UART.c --serial-source YOUR_SERIAL.c --build build/timer`.
2. Diagnose off-by-one edge/center formulas, immediate shadow activation, split
   channel latching, ignored overcapture and out-of-window wrap acceptance.
   Explain each repair; disabling an assertion or increasing a timeout fails.
3. Implement the actual adapter and use `run.py --target --source YOUR_TARGET.c
   --type-headers /path/to/type/headers --build build/timer-target`. Inspect its
   disassembly and imports. This public structural check complements the private
   register-effect suite and is not semantic or physical proof.
4. Submit criterion-indexed derivations, minimized counterexamples, results,
   costs and limitations. Assessor-private cases compare rational selection,
   triangular waveforms, finite event histories and modular capture boundaries,
   and reject compiled semantic mutants and unfinished stubs.

Rubric for each objective: level0 is incorrect/missing evidence or an invented
physical/language guarantee; level1 reproduces the supplied case; level2 derives
the invariant, implements its boundary and diagnoses a discriminating control;
level3 independently handles the original delayed change after at least seven
days. For .a the changed mode is center-aligned, for .b it is coherent two-channel
synchronization with inter-timer limits, and for .c it is a changed source or
instrument with a recomputed uncertainty budget. Executing an assessor solution
does not establish any learner level. Graduated hints: count states; separate
shadow publication from event generation; then track each source of interval
uncertainty independently. No network target, real secret, actuator or host
security change is involved. Physical/reviewer/learner dimensions remain open.

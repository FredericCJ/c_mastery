# I2C address sequencing, bus recovery and uncertain effects

This successor implements AX-PR-T28-04-T28.08.a/.b/.c and their original seven-day variants. It complements the SPI successor under the same project without rewriting accepted tasks, hours or receipts. Use C17, strict freestanding profileE on Cortex-M4, and host-only Python/native oracles. No HAL, libc, compiler runtime or existing bus library may implement the target mechanism. C23 does not add hardware-acknowledgement, retry or exclusive-bus guarantees.

## Explain before construction

Read R-PI-RM21: RM0090 Rev21 pp849–855 and863–874. A seven-bit address is not a wire byte: address0x52 becomes0xa4 for write and0xa5 for read. The ordinary exchange is START,address/write,register0x10,repeated START,address/read,byte0x5a,NACK,STOP. ACK is low on the wire; the last received byte is deliberately not acknowledged. A successful bus exchange does not establish an application's idempotence.

The selected STM32 controller exposes side-effect status sequences. Reading SR1 then writing address DR clears SB. Reading SR1 then SR2 clears ADDR, including an ADDR that becomes set between reads. Therefore a generic status-dump function can destroy the receive sequence. Do not read SR2 as a routine diagnostic during an address wait. For one byte, clear ACK before clearing ADDR and request STOP afterward. For two bytes, wait ADDR, clear ACK/set POS, clear ADDR, wait BTF, set STOP, then read DR twice. RXNE alone does not justify the two reads. These complete procedures were inspected, rather than extrapolated from the one-byte example. More than two bytes requires the separate N>2 end sequence on p854; it is explicitly outside this API, not silently accepted.

ES0206 Rev24 §2.10 describes spurious master BERR: clear it and continue the transaction. NACK and ARLO are distinct. Hardware releases the bus on arbitration loss; issuing STOP would interfere with the winning master. A stretched clock may keep a software wait pending. A timeout supplies no proof that the lines are free or a command did not execute.

## Representation and API contracts

Prerequisites are the T27 startup/clock artifact, T28 MMIO side-effect model, completed `pu_rates`, and the serial_depth/firmware_io interfaces. Ps/Sd/Fw references used by author tests are assessor components, not learner artifacts. Supply your own prerequisites to the public runner.

Zero-initialize PiI2c. One owner serializes all calls, including cancellation and diagnostics. PiIo read/write callbacks are bounded; they must implement the documented register effects and cannot re-enter the driver. PiI2c holds phase, clock generation, monotonically increasing nonzero token, deadline, command-submitted flag, received prefix and two internal bytes. Output is borrowed until terminal status; only a successful STOP completion publishes the complete reply. Errors leave the caller's output unchanged, while diagnostic partial bytes/counts remain available. A caller must retain the descriptor through cleanup; ISO C does not enforce this lifetime.

`pi_open` uses actual PuClock/APB1 rates, restricted to integral MHz2..42. This deliberate range avoids the contradictory upper-limit wording on RM0090 p866. It configures CCR=ceil(PCLK1/160000), standard mode, TRISE=MHz+1, analog filter enabled/digital filter off, no own-address/general-call acknowledgement, no DMA/interrupt requests. Nominal SCL is at most80kHz;16MHz gives CCR100 and TRISE17. This avoids the erratum's88–100kHz repeated-START corner; analog delay/rise time still affect real timing. The selected peripheral's register access is16/32-bit; the adapter uses32-bit volatile accesses.

`pi_begin` accepts ordinary nonreserved addresses8..119, one command octet, count1 or2, a matching clock generation and fresh token. It refuses BUSY or a pending CR1 command before any START. Token exhaustion requires retirement, not wrap. Budget1..2^31-1 ticks and monotonic modulo32 observations with deltas below2^31 make deadlines unambiguous. Each `pi_step` performs fixed bounded work; receive cleanup can read at most two bytes. It never spins waiting for hardware. Changing a clock epoch requires quiescence and reopening.

A pending START/STOP/PEC forbids another CR1 write (RM p865). This applies to cleanup as well as the normal path. A START may complete after timeout before the normal SB branch runs; cleanup must recognize the resulting master ownership and request STOP when permitted. If a command never clears, remain PI_BUSY with the recorded timeout and retained controller state. Do not equate bounded step execution with bounded hardware recovery. `pi_cancel` enters that timeout/cleanup policy. ARLO returns PI_ARBITRATION without STOP and preserves output; future admission waits for BUSY0. Address and data NACK have separate results. BERR is counted saturatingly and cleared according to the selected erratum. Unexpected OVR/SMBus errors produce PI_IO.

The concrete F439 adapter uses I2C1 at0x40005400 and PB8/PB9 AF4 open-drain. External pullups and the measured electrical contract are mandatory. It wraps every protocol call in saved/restored PRIMASK exclusion so an interrupt cannot split the timing-critical ADDR/STOP/DR sequence; it does not mask interrupts across waiting calls. Compiler inline assembly and CPU interrupt behavior are outside ISO C. This single-core exclusion is not a multicore mutex. Original target objects and final image must be inspected for helpers/imports and retained functions.

## Exclusive recovery and changed participants

PiRecovery is a separate bounded-step open-drain state machine. `pi_recover_begin` requires an externally established exclusive single-master lease and no other masters; a boolean assertion alone does not prove that physical condition. It releases SDA/SCL, waits for observed SCL high, holds each high/low phase for `half` ticks, and sends at most nine clock-release requests while SDA remains low. It then generates a STOP with SDA rising while observed SCL is high. It checks stretching on recovery clocks and STOP, returns PI_IO if SDA remains low after nine clocks, and returns timeout with both outputs released if SCL never rises. `pulses` counts requested recovery rising phases; a line held low may prevent a physical edge.

When another master is possible, recovery returns PI_FORBIDDEN before changing a line. Redesign admission as passive BUSY/line observation plus arbitration and an externally coordinated recovery lease. A mere longer timeout cannot create exclusivity. `pi_f439_recovery_prepare` may reset this controller and select GPIO only while idle or in quarantined cleanup and after the exclusive lease is established. It invalidates readiness; reopen and restore AF4 after recovery. Never reset another owner's controller or drive push-pull high into a wired-AND bus.

## Application effect and retry

The original teaching partner has an8-bit register. Command0x10 reads it;0x11 increments unless already255. `pi_device` can apply the command then lose its acknowledgement. Lost read can be retried under the immutable-register premise. Lost increment changes42 to43 but leaves the caller's old reply; replay changes43 to44. `pi_retry_policy` returns PI_UNCERTAIN for a possibly applied increment, and PI_BUSY only as eligibility for a separately admitted retry. Invalid/caller/busy/stale statuses are not bus-retry instructions. It performs no retry itself. Production solutions may require operation IDs, deduplication, reconciliation or a stronger device contract; none is implied by I2C ACK.

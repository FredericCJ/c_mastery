## Representation, operations and failure

The original B2_IDENTITY supports exactly int/unsigned int and calls the corresponding typed provider. Six compile-time `_Static_assert` checks preserve int/unsigned identity results, int/unsigned binary results, and mutable/const record-pointer results. Double, pointer and record values passed to the original identity facade receive separate semantic diagnostics. Do not replace the required type-directed interface with `(x)` just because it evaluates once.

`struct bf_record` holds one int value. `bf_mutable`, `bf_const` and `BF_BORROW` return their supplied pointer unchanged, including null. No object is copied, owned, retained or freed. A nonnull pointer designates a live, properly typed caller object; any dereference requires its continued lifetime. Const access prevents writes through that expression, not mutation through another authorized mutable alias. The demonstration changes a live record through the mutable borrow and observes the change through its const alias. A lifetime-invalid pointer is analyzed only; no dangling-pointer execution is used as a test oracle.

`BF_BINARY(a,b)` admits exactly a pair of int expressions or a pair of unsigned expressions; mixed types are diagnosed. It selects the typed function designator and calls it once with each operand evaluated once. The direct functions require each value0..99 and compute100*a+b, fitting even the minimum16-bit int. They do not dynamically validate arbitrary caller values. The unevaluated type/sizeof gates do not produce operand side effects. Result type remains int or unsigned, respectively. Single evaluation does not impose left-to-right call-argument order.

`bf_sequence(left,lc,right,rc,out)` preflights nonnull callbacks/output, invokes left, validates0..99, then invokes right and validates0..99. Only then does it publish100*a+b and return0. Invalid admission/value returns-1 with output unchanged; a failed left value prevents calling right. Callback effects already performed are retained, not rolled back. Callback contexts and output remain live; no callback reenters, mutates the other's control state, destroys these objects or transfers control out of the call. They may append to a bounded shared log. In the unsequenced direct-call experiment the two callback function-body executions are not interleaved under the C17 call rules; their relative order may be either LR or RL. The explicit wrapper's separate full expressions impose LR. No `i++ + i++` execution is used.

All components acquire no resources and have constant bounded work/storage. Borrowed pointer values and function arguments are passed under their typed contracts; C does not automatically enforce lifetime or the direct binary value domain. Compile diagnostics enforce selected type restrictions, runtime checks enforce wrapper value/admission restrictions, and caller discipline supplies callback/lifetime premises. Report actual code/stack/link measurements rather than claiming every facade is cost-free.

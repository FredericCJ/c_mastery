## Representation, ownership and failure

`schema.json` is the only input authority. Its exact keys are version, features, internal_fast, fields and constraints. Version is integer1 or2; features has exactly Boolean raw, framed, crc, datagram; internal_fast is Boolean. At most one transport among raw/framed/datagram is selected; crc requires framed. The baseline eight combinations of raw/framed/crc admit none, raw, framed, framed+crc. Adding datagram produces a graph with one exclusive transport group and a crc→framed requirement; the sixteen combinations additionally admit datagram alone. The generator derives both admission and a rules header from that declared graph. The rules-only header is for isolated feature checking. A compiled configuration header refuses command-line overrides that would change its recorded identity.

The public record model has a uint32_t value and, when framed, sequence; crc adds checksum. These selected fields determine the public-layout identity. Transport, crc policy and active field positions determine the wire identity. An internal multiplication-versus-shift rendering policy changes build provenance and generated implementation bytes, while preserving layout/wire identity and behavior. These identities are complete SHA-256 digests of canonical declared records, not authentication or a proof that an undeclared flag is irrelevant. `ls_require` compares the required wire/layout identities before a consumer uses the service. It never claims that hashing can dynamically make incompatible C structure definitions safe; consumers do not pass foreign-layout structures in this experiment.

Fields are three required active fields tag,length,flags plus zero to five named reserved fields. Names are lowercase ASCII letter followed by up to23 lowercase letters/digits/underscores, globally unique. Offsets are exact integers0..15 and widths1..16-offset; Boolean values are not accepted as integers. Intervals must be disjoint. Only version2 permits reserved fields; these bits must encode zero. At most eight semantic constraints of the form `{kind: width_at_least, field: length, other: tag}` are admitted; both names must exist and the first width must be at least the second. All checks precede shifts or output creation. Unknown keys, absent active fields and invalid names/counts/versions refuse.

The generator sorts canonical input fields and constraints, fixes ASCII serialization/newlines and emits config.h, rules.h, fields.h, codec.h and manifest.json. The manifest includes full canonical input, sorted enabled features, graph, three identities and hashes of the four emitted headers. `--check` detects missing/stale bytes. Invalid input preserves an existing output directory unchanged. Successful output assumes an exclusive writable directory; interruption or partial filesystem write failure is outside this multi-file publication model. Do not claim atomic filesystem installation. Paths, working directory and time are not inputs to public generated bytes. CMake declares the exact generator and schema prerequisites and uses build-local generated headers.

`LsFields` contains uint32_t tag,length,flags. `ls_pack`/`ls_unpack` return0 on success, -1 on null required pointer or out-of-domain input. The generated baseline masks are7,248,768. Packing is `tag + 8*length + 256*flags`, with tag≤7,length≤31,flags≤3. All unallocated/reserved bits must be zero on decode. Inputs and outputs are live, correctly typed, distinct objects for each call; strings supplied to `ls_require` are live and terminated. Failure preserves supplied outputs. Operations stage results before publication, retain no caller pointers, acquire no ownership and allocate nothing. Returned identity strings have static const lifetime. A bounded number of integer operations and comparisons is independent of field values; identity comparison is bounded by the full digest string length. Resource evidence must report actual code/data sizes under equivalent contracts, not equate a macro with free computation.

Version2 adds reserved bits[10,16), retaining the three active positions. Its canonical input/build identity changes; normalized wire/layout identities remain compatible because version1 already required those unused bits to be zero. The actual separately compiled old decoder must accept newly encoded records. This compatibility is only the declared zero-reserved migration; assigning meaning to a reserved bit requires a new policy/identity and may break old consumers.

## Deliverables, verification and rubric

D1 is the twelve precise configuration/type/interval/identity derivations, including plausible incorrect claims: “same round trip proves correct layout”, “hash means ABI compatibility”, “constant expressions make invalid shifts safe”, and “same interpreter name means same version”. D2 is learner-owned generator, generated headers, allocation-free C component, independent oracle and X-macro comparison. D3 is source-bound commands, manifests, all matrix outcomes, refusal controls, changed implementation bytes, dependency traces and strict link audit. D4 is the independently performed delayed variants under the retained minimum delay; author demonstrations are preparation, not learner completion.

Passing each criterion requires its exact expected result, a valid invariant/range/authority argument, the independently chosen falsification case and its changed-condition reasoning. Score0 is missing/wrong,1 reproduces output without cause,2 derives the mechanism and failure boundary,3 independently transfers it and explains evidence limits. Each rubric is assessed per original ID, never inferred from a family pass. Graduated hints: (1) separate feature graph, field intervals and public identity; (2) validate before rendering and use independent positional arithmetic; (3) inspect codec bytes and real dependency edges when round trips or rebuilds look suspicious. Technical answers are in the separate assessor analysis, not learner exports.

Security scope is original local generators and synthetic records only. Malicious names/offsets are rejected as data; no shell text is generated. There is no third-party target, credential, hardware flashing or host security change. Finite compile/run/negative controls support bounded author readiness; source access, physical evidence, independent human review and delayed learner mastery remain explicitly separate. No finite set of passing checks proves absolute mastery.

## Representation, operations and failure

Implement `declarations.c` from `declarations.h` using only integer arithmetic, comparisons and caller storage. `ld_encode` accepts -4096..4095, emits two octets in big-endian order with the high three bits zero and a signed thirteen-bit two's-complement mathematical encoding. `ld_decode` rejects any high reserved bit; map 4096..8191 to -4096..-1 arithmetically, never cast an out-of-range unsigned value to signed. This is a wire format, not permission to serialize `_BitInt` object representation. CHAR_BIT=8 and the declared exact-width types are explicit selected-profile premises.

All pointers designate live correctly typed storage. Non-null input/output spans are disjoint; controls do not retain them. Null required pointers reject. Invalid values/encodings preserve every output byte. Preflight all checks before publication. Each operation costs O(1) time/storage, allocates nothing and has no callback or runtime dependency. Explain the range proof for each intermediate and why a successful round trip alone cannot detect noncanonical acceptance.

`ld_triangle` accepts n=0..65535 and returns n(n+1)/2 as uint32_t. Divide the even factor before multiplying. The maximum result is 2147450880; n=65536 and UINT32_MAX reject unchanged. The generated 32-entry table uses independent Python arbitrary-precision summation. The C function remains an ordinary runtime function: matching a table does not make its calls integer constant expressions.

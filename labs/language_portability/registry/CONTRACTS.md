## Representation, ownership and failure

registry.json is the one authoritative row input. Each canonical row has a unique ID0..2147483647, unique lowercase ASCII name1..31 characters, one registered handler and up to32 aliases. Names begin with a letter and then use letters,digits,underscore. There are1..32 commands and at most64 total names. Aliases live inside one canonical row; a repeated canonical ID is rejected rather than silently interpreted as an alias. All canonical/alias names are globally distinct. The permitted handler set is start,stop,status,reset, with result input+1,+4,+7,+9 respectively for admitted input0..100.

The host generator validates everything before creating output, sorts canonical rows by ID and aliases by name, and produces ids.h,names.inc,dispatch.inc,aliases.inc,validation.json and a complete content-hash manifest. Invalid input preserves an existing output directory's contents. Successful writes assume an exclusive writable directory; partial filesystem I/O failure is not an atomic multi-file publication guarantee. `--check` compares every expected byte and reports stale/missing outputs. The CMake command declares both generator and registry dependencies and generates build-local views; it does not rewrite canonical source outputs during compilation.

The target tables are immutable static storage. lr_at enumerates ascending canonical IDs. lr_name returns only the canonical borrowed static name. lr_id accepts a live terminated string and resolves either canonical or alias name to its shared ID. lr_dispatch uses bounded binary search rather than ID indexing, validates input0..100 and publishes result only on success. Unknown ID/name, bad index/input or null required output returns-1; supplied live outputs remain unchanged. Multiple output pointers must designate distinct valid objects. Returned name pointers have static lifetime, remain const and carry no ownership. No concurrent mutation of generated tables or independent descriptor forgery is admitted.

ID lookup costs O(log n) comparisons and no allocation. Name lookup is linear in total name bytes. lr_probes reports only the actual ID-search comparisons, not elapsed time. Direct indexing at maximum ID2147483647 requires2147483648 pointer slots even with three commands; the search table stores three entries. Use actual selected pointer/entry sizes and object measurements rather than allocating the huge table or asserting a universal speed advantage. Generator host parsing/sorting costs are distinct from target lookup costs.

The numeric functions select typed int/double operations through function designators. Their admitted arithmetic domain is finite values[-100,100], so +1 fits the selected representations. LG_VALUE uses unary plus in its controlling expression: integer promotions/conversions are explicit, typedef aliases match compatible types, and arrays are rejected unless the caller explicitly selects an element. The control is not evaluated; the actual call argument is evaluated once. LG_OBJECT uses &(x) instead and accepts live int/const-int objects or exactly three-element int/const-int arrays. It retains object/array and qualifier distinctions and excludes temporaries, bit-fields and unsupported array bounds. LG_EXTENDED adds long as a distinct accepted type. These private helpers are teaching implementations; lr_generic exposes nine fixed admitted scenarios with a staged LrGeneric result and unchanged output on invalid scenario/null refusal. C does not enforce the stated numeric domain for arbitrary direct helper calls.

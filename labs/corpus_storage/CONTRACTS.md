# Ordered storage contract 1

This required extension is additive to retained descriptive-hour records. It teaches three original bounded mechanisms, not a production database. Implement the public `storage.h` API in `src/storage.c` from typed caller storage. No container, random-generator or storage-engine library implements the mechanism for you. Host Python dictionaries and models are verification tools only.

## Environment, ownership and common errors

The baseline is C17, profile C: no allocator, file, thread or operating-system calls in the component. Tests use a hosted runtime. Exact-width uint32_t/int32_t and 32-bit unsigned counters are required. Structure assignment can lower to compiler byte helpers; this contract permits those helpers and does not claim a strict freestanding linked image. Account for them when changing target. The selected passages are C-independent mechanisms; published C17 text access remains a separately recorded source gap. Unsigned arithmetic is modulo its type width; ISO C does not provide probabilistic independence, atomic publication, durable ordering or thread safety.

Initialize each live, properly aligned owner exactly once before use. Owners remain at a stable address until all version handles are released. All operations are serialized and nonreentrant. No arbitrary corrupt owner or forged pointer is admitted. Public fields expose inspection, not permission to violate invariants. Required control/output pointers are nonnull except where explicitly allowed; all outputs and input/control objects are disjoint. Constructors require nonnull storage and return void. `SS_INVALID` covers explicitly checked nulls and scalar admission errors; it cannot validate arbitrary addresses. Caller buffers have the stated live capacity.

All mutating failures preserve the entire owner; output arguments also remain unchanged except the documented query probe counter on a valid missing-key result. The bounded reference uses complete private staging where necessary. This has a measurable stack/copy cost. Snapshot output is a fresh nonowning destination. Releasing a copied token consumes the one ownership right; copying bits does not create another right. No shared ownership or C language lifetime checking is implied.

## Skip list and deterministic generator

`SsSkip` holds at most 32 distinct uint32_t keys, int32_t values and six ordered forward levels. Index32 is the end sentinel, never a key restriction. Every live node appears at all levels below its height; level zero contains every key once. `ss_skip_put` inserts or replaces, with replacement preserving height even at capacity. `ss_skip_erase` removes every level or returns `SS_MISSING`. `ss_skip_get` returns a value or `SS_MISSING`; `cost` records key comparisons on both outcomes. No pointer/iterator escapes.

`ss_height(bits,quarter)` consumes low bits: start at height1, promote while the next bit is zero (quarter0) or next two bits are zero (quarter1), capped at6. Its `quarter` input is 0 or1; put checks that domain. Supplied bits are explicit experimental input, not a secret randomness source. `ss_skip_scan(lo,hi,keys,values,capacity,count)` returns increasing entries in [lo,hi); equal endpoints are empty, lo>hi invalid. Both arrays may be null only at capacity0. Insufficient capacity preserves both arrays/count. Because hi is uint32_t, this range operation cannot include UINT32_MAX; exact lookup can. Derive a separate inclusive-bound API before changing this fact.

`ss_random(state,bound,budget,out)` advances the 32-bit recurrence x'=1664525*x+1013904223 modulo2^32. Bound is1..UINT32_MAX. Reject x'<(2^32 mod bound); publish the first accepted x' modulo bound and its state. At most budget transitions are attempted. No accepted sample returns `SS_EXHAUSTED` with state/output unchanged; retrying the same insufficient budget can make no progress. This removes residue-count bias from a uniform/full-cycle population, not serial correlation or finite-budget selection bias. The raw generator is predictable and its lowest bit alternates. It is not PCG and is not suitable for keys, credentials or adversarial height secrecy.

`ss_random_advance(state,steps)` computes exactly steps recurrence transitions by affine composition, including0 and UINT32_MAX, without iteration proportional to steps. Derive the full-period conditions (odd increment and multiplier1 modulo4), prove the 32-bit period separately from finite experiments, and compare period with statistical quality. Use actual bounded selection for a Fisher-Yates insertion permutation and recurrence states for promotion words. Repeat with promotion probability1/4, replay a seed, and jump to a later state. Expected logarithmic search arguments require a random-height model; this deterministic implementation alone supplies only bounded worst-case traversal. Include all-height-one and height-aware adversarial workloads.

## Path-copy B-tree and retained roots

`SsTree` has256 typed pages, three records/four children per page, current root slot0 and seven retained-root slots. Keys and values live in both internal and leaf pages: this is a B-tree, not a B+tree. Nonroot pages have1..3 sorted keys, strict child ranges and equal leaf depth. On a four-key split promote key index1, leaving1 key left and2 right. A published page is immutable until unreachable from every live root.

`ss_tree_put` replaces/inserts with path copies and splits; it atomically publishes a new current root at the C function boundary. `ss_tree_snapshot` acquires the current root in a free slot and returns owner/slot/generation. `ss_tree_get` takes null version for current or a live matching retained token. Wrong owner, released/reused generation or invalid slot returns `SS_STALE` without touching the output. The owner must still be alive. `ss_tree_release` frees the root right, not pages. Generation never wraps: a slot at UINT32_MAX retires after release. Exhausted root slots return `SS_FULL`.

Deletion is explicitly lazy: `ss_tree_erase` copies the path and marks the found record absent. Tombstones remain ordered occupants. Missing/previously deleted keys return `SS_MISSING`. This policy is not structural deletion with sibling borrowing/merging. `ss_tree_vacuum` rebuilds the current tree from present records, preserving retained versions; it can refuse because retained pages constrain workspace. `ss_tree_collect` marks all live roots and frees only unreachable pages, reporting count. No interior page borrow survives an operation; this is serialized reachability collection, not concurrent hazard-pointer reclamation.

Put, erase and vacuum take a failure ordinal:0 disables injection, N rejects the Nth attempted page allocation with `SS_FAILED`; an ordinal beyond actual allocations has no effect. Full page storage returns `SS_FULL`; a copies counter at UINT32_MAX refuses further page allocation with `SS_EXHAUSTED`. No failure publishes partial work, frees a retained version or changes output. Allocation counts are cumulative instrumentation, not live-page counts.

The reference stages the whole owner (16,484 bytes on the selected tested ABI), in addition to logical path copying; vacuum adds768 key and value slots. State actual sizeof/alignment/compiler stack observations for your build. Logical O(height) fresh pages does not make this reference O(height) total copied bytes. Linear page scans and full marking are also real costs. Recursion follows the bounded valid-tree height, not arbitrary untrusted pointers. Compare a simpler complete-version copy under equal version/failure semantics.

## Ordered memtable and immutable runs

`SsLsm` represents keys0..31 with a four-entry sorted memtable and three immutable runs of up to32 sorted records. Each successful write assigns a strictly increasing uint32_t sequence. A tombstone is a versioned deletion record, including for an absent key. Replacement in a full memtable is allowed; a new key at capacity returns `SS_FULL`. Sequence exhaustion returns `SS_EXHAUSTED`, never wraparound. No automatic flush, compaction, durability or background thread is hidden in write.

`ss_lsm_get` selects the highest sequence for the key across memory and all active runs; a winning tombstone means missing. It reports actual record probes even for a missing key, leaving value unchanged. `ss_lsm_flush` copies a nonempty memtable into the first free run then clears memory. No free run means unchanged `SS_FULL`; empty flush is a no-op. Written counts emitted records, not device writes. Counter overflow is refused.

`ss_lsm_compact(mask,drop,fail)` requires a nonzero three-bit mask selecting at least two live runs, and drop0/1. Merge selected sorted streams, choosing the largest sequence for equal keys; publish the replacement in the lowest selected slot, clear other selected slots, preserve unselected runs. Partial compaction retains tombstones. Drop1 is admitted only when every active run is selected and memory is empty. This conservative bottommost rule prevents resurrection of older values outside the merge. An empty resulting run remains an active empty run.

Flush/compaction fail ordinalN refers to the Nth emitted record copy and then one final publication event;0 disables injection. Every such failure preserves the entire owner. Distinguish write amplification (emitted records per accepted logical write), lookup probes, retained versions and explicit capacity backpressure. Compare partial/full compaction and overwrite-heavy/distinct-key workloads under the same logical map contract.

## Changed conditions, security and evidence

Required delayed changes are promotion1/4 plus jump-ahead replay; retained-root lazy deletion plus vacuum and all allocation cuts; and partial compaction followed by bottommost tombstone dropping. They change invariants and admission, not constants alone. Obtain predictions before the run after the exercise's minimum seven-day learner delay.

The C owners above model RAM publication. The independent oracle also explores eight explicitly hypothetical page-write/flush/root-publication cuts, including a root becoming durable before its page. This is a counterexample to inferring crash consistency from path copying, not an implemented disk protocol. Actual filesystem, torn-sector, flush-barrier and recovery mechanisms remain their retained storage exercises and would require a separately specified adapter. No experiment targets external data or changes host storage settings.

Security work is confined to original local owners, synthetic keys and deliberately flawed compiled variants. An attacker can choose keys, operation order and promotion words, retain snapshots or cause injected admission failures. Demonstrate harmless comparison growth, a changed retained value, premature collected pages detected by an invariant, or deleted-value resurrection. Repair the exact defect and show regressions plus two causal controls per mechanism. Do not equate wrong results, undefined behavior or sanitizer reports with arbitrary code execution. Resource caps and serialization are real residual limits.

Supply representations, operation pre/postconditions, ownership and failure tables, invariants, worst-case/expected-work separation, independent models, raw commands and source hashes. GCC/Clang debug, optimized and address/undefined sanitizer profiles are author evidence. Learner scaffold compilation followed by the intended `SS_ASSERT:` rejection is required. No finite campaign establishes absolute mastery, cryptographic randomness, device durability, external review or physical observation.

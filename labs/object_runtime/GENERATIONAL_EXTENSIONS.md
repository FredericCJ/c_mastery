## Admission and preflight evacuation

Retain the original two eight-cell young semispaces, eight old cells and four relocated roots. References0/1..8/9..16 mean null/current-young/old. Populated cells have age0 or1 and valid references; physical references and native pointers into movable cells cannot survive collection unless rewritten. All controls are live initialized objects, required pointers are nonnull and output/control storage is distinct. The API is serialized and does not accept arbitrary corrupted structs. Young/old capacities0..8 and old_capacity at least old_used are required. Invalid inputs return INVALID; insufficient survivor capacity returns FULL. Both failures preserve heap, card state and every output. No output becomes partially relocated.

or_minor_preflight computes a unique young discovery queue from external roots and old-to-young roots, follows young edges, assigns all destination references and checks young/promotion capacity before writing either space. Age0 survivors enter the inactive young space with age1; age1 survivors append to old. The commit copies each survivor once from unchanged from-space, rewrites all edges/roots, then switches active space. Appended old cells cannot overwrite an original old cell. No fallible operation remains after the first destination write. Queue/seen/forwarding arrays contain eight entries each, rather than a copy of the entire ORNursery. A local card snapshot is permitted; account for it separately.

With root3, young3-to2 and old9-to2, the first collection copies two distinct young cells and preserves sharing. A second collection promotes both. With one existing old cell and old_capacity2, that second collection returns FULL unchanged because two promotions need three old slots. Preflight capacity counts survivors, not all originally allocated cells. The original whole-state-copy or_minor remains the independently coded full-scan reference; compare logical payload/edge/root identity, not unspecified padding or unused from-space bytes after success.

## Card adapter and major collection

or_nursery_cards_init constructs the actual ORCards mirror of old fields. After initialization, every old field change uses or_nursery_old_store; the adapter updates the heap and calls the original or_card_store. Do not mutate a mirrored field or dirty bit directly. Mirror equality is checked, but dirty completeness is established by this API discipline: a missing barrier must not be repaired by silently scanning all old roots. Minor collection with a null card argument scans all old roots. With a card argument it calls actual or_card_scan on a local snapshot, uses that young-root set to seed evacuation, and reconstructs cards after relocation/promotion. False positives are legal; false negatives are not.

root_fields_scanned counts only root discovery: two fields per existing old object in full mode, four fields per dirty two-object card in card mode. It excludes admission validation, mirror comparison, output rewriting and card reconstruction, which still touch old metadata. Therefore fewer root scans are not proof of lower total memory traffic or runtime. The bounded adapter intentionally retains these correctness checks; do not subtract them from timing.

or_major_preflight constructs the actual sixteen-node ORGraph and uses its begin/step marker with only explicit roots. Minor collection retains every old cell, whereas major collection may reclaim unreachable old and young cells. After complete marking, it computes a total forwarding map before mutation. Young survivors copy into the other semispace; old survivors compact left in source order, so a destination never overwrites an unread later source. Rewrite all edges/roots and rebuild cards. Forwarding0 means reclaimed or originally absent; retained entries map old physical references to new ones. Ages do not advance during major collection. Output reclaimed counts both generations. No raw large-object payload is part of these movable descriptors.

The second-survival promotion policy is explicit and bounded: eight reachable old cells plus an age1 young root cannot fit another promotion. FULL preserves the heap; repeatedly retrying cannot create space. Drop the old chain's external root and run a major collection: eight old cells disappear, the young root survives, and a subsequent minor collection can promote it. This demonstrates the difference between a long-lived workload and reclaimable old garbage. It is not evidence for a universal generational lifetime distribution.

## Dedicated nonmovable payload region

ORLargeHeap embeds this nursery/card composition, eight uint32 words, four block descriptors and four central lease records. A large allocation requests1..4 contiguous words, fills each with a synthetic pattern, creates an old descriptor and one of the four external roots, and returns a slot1..4/generation1..3 handle. First fit examines contiguous free runs. Handle generation4 retires a block descriptor; it never wraps. No dynamic allocation is used. FULL may mean root/descriptor/old capacity, retired identity or fragmentation. Failure leaves all state and output unchanged. Large payloads never move, even when unpinned; movable old descriptor positions are internal. Values1000..1003 in old descriptors are reserved associations and must not be forged or duplicated by an adapter.

or_large_release removes the allocation's external root, returning STATE if already absent and INVALID for a stale handle. Copied handle bits are borrowed identity, not another ownership count. Collection retains any block reached through strong graph edges or roots. A pin additionally contributes a root to the composed major collector. or_large_pin publishes a const uint32 span and a central lease; the owner must not move/reinitialize the ORLargeHeap, write borrowed words, or end a lease before all readers stop. Pinning is synchronous lifetime protection here, not an asynchronous cancellation API. or_large_unpin validates the active central ticket and generation, drops exactly one pin and retires the ticket on its fourth generation. A copied ticket cannot be finished twice. All ordinary calls remain serialized; this does not authorize concurrent raw reads during arbitrary caller mutation.

Collection uses the actual major marker/forwarding implementation with pinned descriptors as additional roots, then clears words and retires block identities whose descriptor disappeared. Pinning protects lifetime, while the nonmovable region policy protects address stability. Four length2 blocks fill the eight-word region. After blocks1 and3 become collectible, two holes of length2 leave four free words but cannot admit length3. Releasing block2 creates a contiguous run and admits a larger allocation. Explain internal/external fragmentation separately. A pin on block1 keeps its words and native address valid across descriptor compaction; after unpin and collection, the old handle must reject. There is no claim that compaction of movable descriptors repairs fragmentation in a nonmovable payload region.

## Verification and assessment

D1 derives forwarding uniqueness, atomic admission, survivor identity and separate minor/major root sets. D2 implements preflight rather than whole-heap staging, the actual card adapter, major collection and large-region lifetime adapter. D3 independently enumerates64 young graphs,16 root sets, four old-to-young targets and eight age patterns:32,768 inputs and65,536 minor/major result rows, including copied counts, young/old membership, root identities and edges. Also compare the original or_minor result on every input. The independent Python model uses sets/reachability, not the C forwarding algorithm. Large-region verification compares20,736 allocation/root/pin scenarios against independent occupied-word sets. Separate tests cover two successive collections, promotion exhaustion/recovery, invalid field atomicity, finite handle/ticket retirement and unchanged outputs on fragmentation failure.

Each of the preflight, composition and large-object anchors has two compiled semantic controls: missing old roots; writing a root before capacity admission; adapter stores without card marking; major collection treating all old cells as permanent roots; ignoring pin roots; and admitting by total free space despite fragmentation. The harmless success condition is a wrong survivor/identity map, failed atomicity assertion or overwritten synthetic region. Require passing corrected implementations plus intended assertion failures. Do not classify a process failure alone as successful falsification.

R2 level2 requires the preflight proof and actual composed implementation. R3 level2 requires independent normalized graphs and capacity failures, including old-only reachability. R4 level2 requires the long-lived promotion boundary and actual nonmovable/pin/fragmentation behavior; a statement that large objects can be allocated elsewhere is insufficient. Level3 independently changes promotion age or region size class, provides a counterexample to the old capacity argument, and revises the proof/cost comparison. Hints: discover identities before destinations; do not confuse old retention during minor collection with major roots; moving a descriptor need not move its payload; total free words do not guarantee a contiguous run. Separate assessor analyses contain worked traces. X-T74-006-DELAYED supplies new block lengths/root removals and requires the learner to derive admission and lifetime without the worked implementation.

## Security and evidence limits

Only the original local synthetic heap and payload words are targets. The adversary controls admitted roots, edge changes, allocation lengths and collection timing. Missing card/pin roots can drop a logically live identity; an incorrect fragmented admission can overwrite another block's harmless pattern. Prerequisites are the relevant old-to-young edge or retained lease and the specific collection interval. Repairs preserve root completeness, preflight and contiguous-run checks, with positive and negative regressions. No native freed-pointer dereference, external service, deployed board or real data is used. These property failures do not establish code execution. The control state, reserved descriptor associations and cooperative lease lifecycle remain trusted.

The core and large-region adapter are serialized. X-T74-007's concurrent card snapshot/clear protocol is specified separately in CARD_EPOCH_EXTENSIONS.md; a sequence of independently committed card snapshots is not a global concurrent collection snapshot. Source-bound host evidence is separate from external review, independent learner performance, exact published C17 access and physical validation. Supply all thirteen cost dimensions; explicitly include validation/reconstruction traffic and the observed whole-state-copy versus preflight stack distinction.

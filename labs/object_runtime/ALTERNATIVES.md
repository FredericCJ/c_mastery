## Four-entry dictionary contract

Zero-initialize ORDictionary. It owns up to four unique nonzero octet keys and copied int32 values, in insertion order. Set replaces an existing value even when count4, otherwise appends or returns FULL unchanged. Delete removes an own key and shifts both key and value arrays; absent key returns MISS unchanged. Get returns a copied value, or MISS with output unchanged. Zero key or null required pointer returns INVALID without mutation. Inputs and outputs are distinct storage and callers must not fabricate dictionary state. No dynamic storage or retained borrowed payload exists. Empty/singleton and delete-first/middle/last must preserve key/value pairing.

Dictionary mode stores keys per object rather than sharing an immutable shape. Its four-field capacity equals the original receiver's field capacity, but it does not have the shared16-transition capacity failure. Compare only the common admitted operation traces for semantic equivalence; explain this different metadata/capacity contract instead of claiming identical resource behavior. Deletion is native dictionary behavior, while the original immutable-shape kernel has no deletion operation. Repeated dictionary churn therefore does not consume shape slots. A dictionary has no cache, so no offset can survive a mutation; a proposed cached dictionary variant requires explicit mutation/version admission before reuse.

## Direct generic contract

or_property_generic reads the original ORShapes/ORObject representation and returns the same payload/status as or_property_get on an admitted query. It scans the receiver's actual descriptor and owns no cache state. Missing output stays unchanged. It does not construct or reset an ORCache internally. Original cached lookup may change its diagnostics and become sticky generic after the third distinct guarded pair; these observer effects are intentionally absent from the direct path. Restrict performance runs below unsigned counter wrap and state that counters are part of measured cache overhead, not payload semantics.

Concrete cases: layout[1,2] has fields[10,20], layout[2,1] has fields[30,40]. Direct and cached key1 must return10 and40 respectively. A missing key3 preserves sentinel777. A value update keeps its layout and must be observed immediately by both paths.

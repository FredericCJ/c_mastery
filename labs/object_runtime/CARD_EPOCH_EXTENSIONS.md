# Concurrent card snapshots, clearing and placement

This is required X-T74-007-R4 and X-T74-007-DELAYED implementation support. Prerequisites are the original card/root invariants, the actual nursery/card adapter, and X-T74-005's mutex publication and finite-revision proof. Use object_runtime_card_epoch.h, the compiling src stub, tests/card_epoch.c and the independent card model in verify_object_runtime_completion.py. C17 plus POSIX threads, GCC/Clang host profiles and the declared64-byte alignment support are required. The unchanged original two-object ORCards kernel remains the width2 serialized comparison; this wrapper implements changed widths1/2/4/8 and a genuinely concurrent snapshot interval. A mutex library supplies exclusion, not the card algorithm.

## State and operations

ORCCards has eight old objects with two octet references each, target0=null,1..8=young and9..16=old. Objects per card is1,2,4 or8, fixed at initialization. Metadata is selected from either packed ORCCMeta entries or64-byte-aligned ORCCPadded slots. A union reserves the larger storage in both cases: the experiment changes touched metadata placement, not the total control allocation size. Initialization clears all fields, sets each revision1 and clears dirtiness. The control must be correctly aligned, live, initialized, stationary and not copied. It may be published only after init. Reinitialization/close require joined workers, no calls or future users and discarded snapshots. No recursive use, asynchronous cancellation or robust owner-death recovery is supported.

Store validates object0..7, field0..1 and target0..16, acquires the same mutex used for metadata, writes the field, marks its card when the new target is young and increments the card's revision. Overwriting one young field does not clear the card. Even a same-value store increments revision. A card's revision never exceeds65535; at the limit store returns FULL without writing. Close after quiescence retires the entire embedded state instead of wrapping identities. Invalid arguments return INVALID; a lock failure returns STATE. An unexpected unlock failure aborts the local teaching process because the admitted environment contract failed.

Prepare locks one dirty card, copies its revision and all2*width fields into a private ORCCSnapshot, publishes that snapshot, then unlocks. A clean card returns DONE without changing output. The snapshot owns no live heap pointer except an opaque owner identity; its copied fields may be scanned outside the mutex. scan_commit first computes the young-root union from the immutable snapshot, then locks and compares the current card revision with the snapshot revision. A mismatch returns STATE with both output values unchanged and leaves current dirtiness intact. The caller discards the computed roots and prepares again. On success it publishes the root bitmap and exactly2*width scanned fields, retaining dirty if any young edge remains and clearing it otherwise.

Snapshot fields are trusted copies from prepare and cannot be fabricated or modified. Inputs/outputs are distinct storage. The same successful snapshot may be rechecked while revision remains unchanged; it represents the same card contents. Neither a snapshot nor a pointer to this control can survive its lifetime/address reuse. Global initialization fields remain immutable while threads run; every mutable field/metadata access uses the mutex. The native C type system does not enforce these lifetime and protocol obligations.

## Late-writer trace and proof

Store young1 into object0, overwrite it with null, then prepare the still-dirty card. Its copied contents contain no young reference. A separate pthread stores young7 into the last object sharing that card and returns. Join the worker, then try to commit the old snapshot: STATE must preserve roots777 and scanned888. Preparing again discovers root7, publishes bitmap64 and keeps dirty. Removing that final young edge and rescanning clears the card. Repeat for all four widths and both layouts. The critical defect is clearing based on an old snapshot after a writer has published new young reachability; merely making dirty atomic would not make the snapshot current.

Store and successful commit linearize under the same mutex. A successful equal-revision check proves no field store occurred since prepare because revisions cannot wrap. Therefore copied fields describe that card at commit, and clearing is safe exactly when their young union is empty. A stale snapshot never clears or publishes roots. Per-card validation is not a proof of a global collection snapshot across different cards: integrating an actual concurrent minor collection additionally needs a root/epoch/quiescence protocol covering all cards and young mutations. This exercise supplies the requested card-clearing mechanism, not an undeclared concurrent copying collector. No lock-free, fairness, bounded scheduling or wait-free claim applies.

## Work, costs and evidence

D1 derives card completeness, finite-revision admission and the late-clear counterexample. D2 implements copying under exclusion, scanning private data and checked clearing under exclusion. D3 executes the real late-writer schedule, unchanged-output rejection and revision exhaustion; two compiled mutants ignore the revision check or omit store marking. The independent Python model checks2,176 width/layout/object/field/target rows. Corrected code must pass while both mutants hit their intended assertions after worker join. ThreadSanitizer observations do not prove all schedules.

D4 changes card width and metadata placement with the same stores, roots and clear policy. Record exactly how many fields are scanned, useful young references and false-positive fields; count touched metadata addresses under an explicit64-byte line model before interpreting elapsed time. The probe repeats actual accesses to packed and separated slots and retains complete lifecycle checks. A line-address trace is not a hardware cache-miss or coherence-transfer count. Record any available hardware-counter result separately; unsupported/permission-denied counters stay an observation gap without changing host settings. Global mutex contention, initialization, padding and union storage can dominate, so do not attribute every timing difference to false sharing. Supply representation, retention, lifetime, aliasing, allocation, movement, destruction, dispatch, concurrency, failure, compilation, binary/stack and boundary rows under the shared cost contract.

Level1 reproduces one dirty-bit example. Level2 independently explains revision invalidation, rejects both controls and implements the actual thread schedule with honest traffic/timing models. Level3 implements a different epoch/double-buffer scheme and demonstrates why a writer cannot disappear across a buffer exchange, including wrap and shutdown. Graduated hints: a dirty bit records more than the last field; a snapshot can become stale while its scanner runs; clearing needs a validity check within the writer's publication boundary. The delayed variant withholds the split implementation, changes card width/layout and requires a new trace/proof and revised work measurements without copying the solution.

## Laboratory containment and limitations

The target is only this original local synthetic card table. The adversary chooses admitted reference stores and the prepare/clear interval, without forging internal snapshots or corrupting memory. In the revision-omission mutant, a young edge exists while its card becomes clean; in the missing-mark mutant, prepare incorrectly reports DONE. The harmless success condition is this wrong remembered-root result, not a native pointer dereference. Repair store marking and locked revision validation; retain exact late-writer and shared-card regressions. Residual limits are trusted initialization/state, finite revisions, caller quiescence and the absence of a global concurrent collection protocol. No external service, production board, real data or host security setting is involved. Actual host execution remains separate from independent learner assessment, external review and physical validation.

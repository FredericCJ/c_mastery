# Active allocation, explicit marking work and synchronized termination

This required X-T74-005 extension assesses R2 and R4 and supplies the changed-condition implementation for X-T74-005-DELAYED. Complete the original graph/barrier exercise first. The public interfaces are object_runtime_marking.h and object_runtime_concurrent.h; learner implementations remain under src/. Use the original ORGraph and its begin/root/store operations through an explicit adapter; do not call a collector library. The host harness, Python oracle and pthread runtime are distinct from the allocation-free core. C17 with 8-bit octets and the declared exact-width integers is required; the concurrent adapter additionally requires POSIX threads. No Cortex-M4 execution or physical measurement is claimed for this extension.

## Representation, admission and ownership

ORCHeap embeds sixteen objects, each with two strong outgoing handles. A handle has slot1..16 and generation1..3; {0,0} is null. A collected slot increments its generation; generation4 retires it permanently. No integer-to-pointer conversion occurs. Each live object has an external root count0..255. Allocation creates one root. Copying handle bits does not retain a root; storing an edge does not create an external root. A copied read result is a borrowed identity and must be retained before its protecting root/edge can disappear. Concurrent clients must call retain while another known owner protects it, or accept a stale rejection after the protecting edge is removed. No API exposes mutable payload pointers.

Initialize fresh storage with a valid ORCPolicy. All core calls use a live, initialized heap; argument/output storage is distinct from the control and from other written outputs. Do not fabricate internal state, generations or finish tokens. The core requires serialized calls. The concurrent control is stationary, initialized once before publication, and never copied, moved, recursively entered, asynchronously cancelled, destroyed or reinitialized while a call can be active. A handle or finish token cannot outlive its control instance, even if the same address is reused. These are caller obligations, not properties enforced by ISO C's type system.

Revision starts at1 and never exceeds65535. Every successful state-changing operation increments it, even an identical store. Full root count, finite revision exhaustion, a full pool, or all retired slots returns FULL without changing the heap or output. Invalid/null required inputs and stale handles return INVALID; wrong phase, root underflow and an invalidated finish return STATE. Read/prepare/inspect are read-only. Step with budget0 publishes scanned0 and performs no work; an empty queue returns DONE while keeping the cycle active. Validated mutation is staged or preflighted before output publication. The public invariant checker is diagnostic, not a universal validator for arbitrary corrupted structs.

## Worklist and allocation policies

The explicit LIFO worklist contains each gray object exactly once. White-to-gray admission enqueues; scanning pops gray, shades both white children and blackens the node. At most sixteen nodes are gray, so a sixteen-entry worklist suffices even with cycles, duplicate edges and active allocation. A step scans at most budget objects. Allocation during an active cycle has three separately implemented policies:

1. BLACK: create a black node and shade both initial children before publishing it.
2. GRAY: create a gray node on the worklist; scanning it later discovers children.
3. RESTART: install the new rooted node, whiten the heap, discard prior work, and shade every current external root.

All policies preserve roots nonwhite and no black-to-white edge. Root insertion shades a white target; a store from a black source shades a white target. Root deletion need not unmark an object, so floating garbage can remain until a later cycle. Restart may repeatedly redo work and cannot guarantee completion under an unbounded allocator. It is a deliberate alternative, not a claim that all three policies have equal work or latency.

Concrete trace: allocate rootA and nodeB; release B's root; begin and scan A; allocate rooted N with its first edge to B. Finish the cycle. A, B and N survive for all policies. Total scans are BLACK2, GRAY3 and RESTART4, with exactly one restart only in the last policy. Release A and N, then start another cycle: all three are reclaimed. Reusing any old handle rejects. After48 single-object allocate/release/collect cycles, all sixteen slots have consumed three generations and the next allocation rejects unchanged.

## Prepare, commit and concurrent publication

An empty worklist is only a candidate termination point. Prepare returns the owner address, current revision and current white bitmap without ending the active cycle. Commit requires this same live control, active cycle, exact revision, empty worklist and available next revision. It then reclaims the white set and publishes the dead bitmap in one serialized operation. Any root/store/allocation/scan/release between prepare and commit changes revision and rejects the candidate. A caller must retry from current work; it must not force an old candidate through. A valid token is copied from prepare and never modified. This is an internal cooperative token, not an authentication capability against arbitrary memory writes.

ORCConcurrent serializes each operation with one default non-robust pthread mutex. Root counts, graph fields, colors, worklist, revision and finish validation all use that same lock. Initialization happens before thread creation/publication. A request returns copied results only after its operation; unlock publishes writes to a later successful lock. Prepare deliberately releases the mutex before commit, so a real mutator can intervene. Commit's revision/worklist recheck under the lock closes that window. No relaxed-atomic payload access, volatile-based synchronization, lock-free progress, fairness or real-time bound is promised. This is a concurrent mutator/collector with serialized critical sections, distinct from a parallel tracing engine with atomically updated fields and work stealing.

Normal close requires no live nodes and no active cycle. At revision65535, further state mutation is intentionally refused; the owner may instead retire the entire embedded pool. In either case close additionally requires all workers joined, no possible future calls, and all handles/tokens discarded. The terminal exception permits destruction of a full or active exhausted pool only under that stronger lifetime boundary. It does not authorize forced destruction of clients' live references. A failed lock returns STATE; unexpected unlock failure aborts the original teaching process because the admitted synchronization environment has been violated. Robust owner-death repair and asynchronous cancellation are outside this adapter contract.

## Deliverables, verification and assessment

D1 gives the reachable-set proof, worklist capacity argument, operation linearization points, finite-counter exhaustion policy and a counterexample to finishing after an old empty-queue observation. D2 implements the core, three allocation policies and concurrent wrapper; it reuses the original ORGraph barriers instead of silently replacing their contract. D3 compares all64 three-node one-edge graphs, eight root masks and three policies with independent Python reachability after adding a fourth rooted node during marking:1536 rows. Also test root-count saturation, invalid fields, unchanged outputs, zero budget, dead cycles, generation retirement and revision exhaustion. D4 runs the actual pthread late-store and late-root schedules, then100 collector cycles against1000 mutator iterations, and supplies a thirteen-dimension cost review with scan counts separate from elapsed time.

The allocation and concurrent anchors each reject two separately compiled semantic controls: missing black-allocation child shading; gray allocation silently blackening; committing an invalidated sweep; and root publication without shading. Require positive controls and the intended assertion, not a timeout, compile error or arbitrary process failure. The late-mutator tests join workers before assertions; negative controls therefore do not manufacture sanitizer failures by destroying thread-owned stack storage early. GCC/Clang debug, optimized, AddressSanitizer/UndefinedBehaviorSanitizer and declared ThreadSanitizer runs are evidence about those executions only.

R1 level2 requires the root and edge invariants and floating-garbage distinction. R2 level2 requires explicit bounded work, correct collection/retirement and failed-operation atomicity. R3 level2 requires independent graph expectations and meaningful mutant rejection. R4 level2 requires all three allocation strategies and an actual thread schedule invalidating a finish candidate; merely calling a serialized loop concurrently is insufficient. Level3 independently changes publication or work ownership and defends a revised termination protocol. A missing retained root or an overstated lock-free/safety claim fails the relevant criterion. Passing tests cannot establish independent learner mastery.

Graduated hints: first keep the active flag set after an empty queue; next identify every state change that can invalidate a candidate; finally put mutation and candidate validation under the same synchronization boundary. Delayed assessment removes the offered split prepare/commit implementation and requires rebuilding it from a recorded late-store trace, then changes allocation policy mid-design and explains the new work/progress argument. Do not change policy in a live initialized control: the learner must define a legal transition or new-instance migration. The separate assessor analysis contains the worked proof and traces.

## Security and limits

The only target is this original local synthetic heap. The attacker controls admitted graph edges, roots and the scheduled late mutation, without arbitrary memory writes or control-token forgery. A stale candidate can reclaim B after a new A-to-B edge or external root makes it reachable. Harmless success is an incorrect dead bitmap or a live edge into a reclaimed teaching slot; do not dereference freed native memory. Preconditions are an active cycle, a candidate white B and a mutation in the prepare/commit interval. Repair candidate invalidation plus root/store barriers, preserve both schedule regressions and disclose finite identities, trusted control integrity and caller lifecycle restrictions. This demonstrates premature logical reclamation, not arbitrary code execution. No service, deployed firmware, real credentials or other people's data is touched.

The primary V8 comparison concerns worklists, barriers, layout changes and finalization; this original locked collector is not a V8 implementation or performance reproduction. The POSIX source specifies synchronization, while ISO C supplies ordinary typed operations within that protocol. Exact published C17 access, independent review, delayed learner performance and physical target validation remain separate evidence obligations. Concurrent card clearing and generational composition belong to X-T74-007 and are not established by this marking adapter.

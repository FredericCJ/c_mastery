## Common state and ownership rules

All public controls and referenced backing owners remain live and at stable addresses throughout their operations and borrowed handles. Initialize controls before use. Unless specifically admitted below, inputs, outputs, control objects and backing arrays are distinct, correctly aligned live objects; arrays contain the stated count of elements. Invalid logical indices and admitted exhaustion are returned statuses. Forged pointers, cyclic corrupted control objects and violated lifetimes are precondition violations to analyze, never execute. Runtime checks cannot validate arbitrary C pointer provenance or a lying allocator.

Operations are externally serialized. Callbacks may observe published state but may not mutate or reenter the component, terminate nonlocally, retain temporary scratch, or access released storage. A successful backing allocation supplies the entire requested extent. Deallocation cannot fail. Failure preserves logical values, ownership and promised output values; explicit exceptions are diagnostic probe counts and traversal partial-output counts. A failed initializer must clean its own partially acquired subresources. No asynchronous cancellation is admitted inside the short commit region. Ownership transfers exactly at successful publication; failed operations retain the caller's input ownership.

Destroyed dynamic controls release storage once and invalidate all borrows. Plain byte copies of owning controls create neither a second owner nor transferable lifetime. The supplied fixed and intrusive controls do not destroy payloads automatically. Compare identity, value equality and live-resource accounting separately.

## Sequence, view, ring and growth operations

`struct cd_array` borrows actual `int[capacity]`; valid length is `0..capacity`. Insertion accepts `index==length`, reads the scalar value before movement (including when it aliases a moved element), and shifts from the end. Erase/get require `index<length`; erase shifts toward the front. Destroy clears metadata; re-destroy and use after logical destruction return `CD_INVALID`. Zero capacity with null backing is a valid empty owner. An erase-current loop keeps the same index to visit its successor.

`struct cd_view` borrows an actual array extent and uses `first + i*stride` as an integer index model, not speculative pointer arithmetic. Nonzero positive and negative strides are supported. Endpoint admission uses division before multiplication. Empty views form no pointer and accept `first<=extent`; an empty subview need not manufacture an unrepresentable one-past strided pointer. Subview output may equal its source. Growth or destruction of the backing owner invalidates every view.

`struct cd_ring` uses `head,count`, with all `capacity` slots usable. Full and empty can share equal head/tail positions; count distinguishes them. Reads expose at most two borrowed spans, invalidated by mutation. Reserve exposes free spans and blocks other reads/mutations until commit; the caller must initialize the committed prefix. Overcommit fails without discarding the reservation. Commit zero cancels it. The strong push admits the entire batch before mutation; the separately selected partial mode reports exactly the copied prefix. Pop is all-or-none and preserves output on insufficient items. No input/output overlap is admitted. `struct cd_deque` adds front/back ends to three typed slots; back/back is a bounded stack, back/front a queue.

`struct cd_vector` starts empty with zero storage, takes capacity one on first append, then doubles. Reserve never shrinks; shrink-to-fit explicitly relocates or frees an empty backing block. Check `capacity*sizeof(int)`, doubling and copy-counter admission. Allocate and copy before publishing new pointer/capacity, then release the old block. Old borrows survive failed growth but end on successful relocation; do not compare or dereference a freed pointer. The host oracle compares logical values, capacity, length and live backing blocks after every operation, including failed acquisitions.

`struct cd_payload_vector` separately acquires replacement backing, retains old resources while cloning the new suffix, destroys only the successful new prefix on failure, and releases the staged backing. It caps total payloads at eight and publishes only a fully constructed replacement. `cd_clone_batch` admits at most eight payloads into empty destination objects. It constructs a scratch prefix; failure destroys that prefix in reverse and leaves destination unchanged. Success transfers resources into destination and does not destroy the transferred scratch copies. `struct cd_owned` separately models move-only resource tokens: equal values can have distinct resources, duplicate resource ownership is rejected, and success clears the moved-from token. Cancellation is allowed before staging or after staging but before publication; no cancellation is allowed between publication and clearing the input. These small tokens model ownership, not an ISO C type-system guarantee.

`struct cd_segmented` is a bounded four-by-four typed layout. Quotient/remainder lookup is constant time and earlier addresses remain valid while the owner stays live and unmoved; all sixteen slots are reserved up front. This is a concrete stable-address design, not an unbounded segmented allocator or iterator-stability claim across owner movement.

## Lists, heap and ordered trees

Singly, null-ended doubly and circular sentinel lists have distinct controls. A live intrusive link has one owner at most; initialize detached links to zero. Removing a link clears its edges/owner but does not destroy its enclosing payload. A containing task with two links must detach both before destruction. An allocated wrapper has its own release, distinct from the borrowed task's destructor. Erase iteration saves a successor while both objects are live, detaches the current wrapper, then releases it. It never reads the freed wrapper to find the next element.

`struct cd_queue` has three initially admitted typed nodes and a second three-node pool segment. A refill request can fail before publishing availability or any link; the synthetic failure parameter selects that acquisition boundary. The six actual node objects remain allocated in the owner throughout. This models a bounded pool refill, not heap growth or a physical allocator timing observation. Compare the identical three-element FIFO trace with `struct cd_ring` and the separately allocated wrapper design.

`struct cd_heap` stores at most sixteen entries. Ties preserve insertion order in both min and max modes. A handle includes the live owner address, slot and generation; every swap updates the slot-to-index map. Taking an item advances its slot generation, retiring the slot after generation three. Sequence exhaustion refuses new insertions. Reinitialization is legal only after all prior handles are retired by the caller's protocol. Update-key repairs in either direction. Check child existence before evaluating `2*i+1`. Bottom-up build and repeated insertion have equivalent contents, not necessarily equal comparisons or layouts.

`struct cd_tree` has thirty-two actual typed nodes, parent links, stored heights, and optional AVL repair. The ordinary policy rejects duplicates unchanged; the transfer policy counts multiplicities and deletes one occurrence at a time. Acquisition failure occurs before any link/height change. Node slots retire before generation wrap. Two-child deletion physically transplants the successor slot; its node identity and attached resources survive, while the victim slot is invalidated. Payloads with self-pointers therefore stay at their own addresses. A value-copy alternative has different identity obligations and must not blindly duplicate unique resources.

Traversal with a caller stack returns `CD_FULL` and an explicit emitted count if stack/output capacity is insufficient. Parent-link traversal uses constant auxiliary storage and also reports its emitted prefix. Neither permits concurrent mutation. Recursive traversal exists only as the independent host oracle with the bounded thirty-two-node limit; it is not the target's stack discipline. AVL tests reconstruct heights from children, detect repeated reachability and check parent/order/balance independently after every mutation. Rotation/ancestor counters are diagnostic, not amortized or timing proofs.

## Hash, prefix, sets and graph operations

`struct cd_chain` has four bucket heads and sixteen typed nodes. `struct cd_hash` owns `1..16` buckets with empty/live/tombstone states. Search stops at an empty slot or after exactly capacity probes, but not at a tombstone. `live` differs from `occupied` (live plus tombstones). Existing-key updates do not change counts. Manual rebuild is the stated maintenance rule: acquire a new table, insert every live key, publish, then release old storage. Failed acquisition preserves the old table. Deliberately clustered hashing supplies worst-case probe evidence; expected-time claims require an actual distribution assumption.

`struct cd_byte_map` copies up to eight length-delimited bytes into four slots, including embedded zeros and an empty key. Mutating the source afterward is admitted. Mutating a borrowed key after bucket placement instead breaks the hash/equality precondition; the test uses live bytes to show the changed bucket without invalid memory access. Copying cannot repair inconsistent equality/hash callbacks. For equality that folds ASCII case, a case-sensitive modulo-three hash maps equivalent `A` and `a` differently.

`struct cd_trie` stores copied edge bytes in sixty-four typed nodes and keys of at most eight bytes. Root can be terminal for the empty key. Insertion plans every required free node before publication, so failure at any staged acquisition preserves the original. Deletion of a terminal with descendants clears the terminal without discarding descendants. Prefix enumeration order is node-slot order, not lexicographic; the cursor borrows its owner and records a mutation generation. Any mutation makes its next operation return `CD_BUSY`, with no output publication. Generation saturation refuses mutation. Radix-label splitting is a separately specified finite descriptor/ownership derivation, not a claimed compiled compressed-trie implementation.

Bitset algebra masks a universe of zero through thirty-two bits. Exactly full words use `UINT32_MAX`, avoiding a width-sized shift. Sparse-set membership checks generation, range and reciprocal dense equality. Its universe is thirty-two and maximum count sixteen. Clear advances a two-bit model's generations one through three; wrap clears every tag before reusing one. External handles require a separate identity scheme; membership epochs do not supply it. A universe1024 storage analysis explicitly declares four-byte keys/indices/tags and distinguishes ordinary constant clear from worst-case reset. A requirement forbidding that reset is rejected at wrap until a maintenance phase completes.

`struct cd_sets` supports at most sixteen items, union by size and path compression. Every changed parent/size is logged. Operations stage candidate arrays, preflight the128-entry undo capacity and publish only if all changes fit. Rollback marks must be previously recorded operation boundaries from this live history; arbitrary middle-of-operation marks are not admitted. Repeated unions do not double a root's size. Parent links encode partitions, not graph edges.

`struct cd_csr` accepts at most eight vertices and thirty-two directed weighted edges. Endpoints are validated; self-edges are admitted. Parallel edges are either rejected or explicitly retained by a mode flag. Counting offsets and scatter preserve input order within each source. A rejected build preserves the old snapshot. Lists and a Boolean matrix are checked as host representations; the Boolean projection deliberately loses parallel weights. The separate `graph_consumer.c` BFS imports the actual immutable CSR snapshot by const reference and must finish before its live owner is modified or destroyed. It ignores weights to compute edge-count distances, returns `UINT32_MAX` for unreachable vertices, and validates every offset before reading edges. Its implementation is a path-algorithm consumer, separate from CSR construction.

## Filter, evidence and transfer

The required advanced implementation is the original eight-bit filter over keys0..15 with exactly the two stated hashes. It promises no false negatives only while inserted bits are retained and uncorrupted; positives need not prove membership. No deletion is admitted. A counting transfer has eight cells capped at three plus an explicit sixteen-key multiplicity ledger. Check both cells before increment, reject overflow unchanged, and reject deletion not justified by the ledger. This exact ledger has a real space cost; it is not a claim that an approximate filter alone can authorize arbitrary deletions.

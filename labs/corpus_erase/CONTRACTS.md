# Stable compaction and owning-tail contract 1

This required Profile C exercise separates a logical range boundary from container size and resource destruction. Implement the C operations locally; no container, sorting, filtering, allocator or external memory primitive may implement them. Compiler byte-copy helpers from typed aggregate assignments are permitted and must be reported. The C core uses real typed objects and no heap. Hosted C++17 standard-library experiments and Python models are comparison tools, not C target dependencies. The baseline is C17; no newly inspected published C17 text or strict freestanding final-image closure is claimed.

## Representation and premises

`erase.h` defines all public types. An `struct er_owner` holds at most twelve `struct er_item` records, each with a distinct nonzero synthetic resource ID and an integer value. Exactly one logical ownership right exists per ID. Copying a record while staging does not clone that right. The owner is live, aligned, at a stable address, and used serially without callback reentry. An initialized owner must not be reconstructed or bit-copied as a second owner while it owns rights. `er_clear` ends rights but not the C object's lifetime. After its lifetime ends, no token may even use its old owner pointer.

Except for the explicitly permitted read-only predicate-context borrow, distinct arguments denote disjoint storage. Output objects are live and do not overlap inputs or control state. A tail output initially owns no resource; it is a nonowning description, not a capability. Callers must not forge owner fields or violate `count <= 12`, valid IDs, pending-state or generation invariants. Runtime checks do not make arbitrary corrupted C objects safe. ISO C does not enforce uniqueness, moves, callback effects or linear token use; those are explicit caller obligations supported by tests and reasoning.

## Scalar logical compaction

`er_compact(a,n,value,new_end,moves)` accepts a live `int[n]`, or `a == NULL` only when `n == 0`. Both outputs are required. `value` is passed by value, so a caller expression such as `a[0]` is captured before the operation. Preserve the order of all elements unequal to `value` in `[0,*new_end)`. Array extent and caller length do not change; values in the remaining tail are unspecified by this contract. Report the actual number of element assignments needed to move retained elements to earlier indexes, excluding self assignments. The supplied case `[1,2,1,3]`, value 1, produces prefix `[2,3]`, end 2 and two assignments. Empty input produces zero outputs. Invalid null controls return `ER_INVALID` before writes. Complexity is exactly `n` value comparisons, at most `n` assignments and constant auxiliary space; this does not shrink storage or destroy resources.

## Owning two-stage operation

`er_init(owner,items,n)` admits `n <= 12`, a nonnull owner, and nonzero distinct IDs; `items == NULL` is admitted only for zero length. On success it transfers the caller's logical rights into a new owner, sets `count=n`, `keep=0`, `pending=0`, `epoch=1`; caller records are no longer owning aliases. On rejection the destination is unchanged. Initialization checks IDs in quadratic time within the stated capacity.

`er_remove_if(owner,predicate,context,tail)` requires no pending tail, a required callback and output, and two remaining epoch increments. Predicate return 0 keeps, 1 removes; any other value returns `ER_FAILED`. Evaluate in original order, exactly once per original element on success, stopping at the first failure. Evaluate every decision before changing owner storage. A predicate may read a value through `context` that points into the original owner; it must not mutate that owner, reenter operations, acquire/release its resources, retain element pointers beyond publication or exit nonlocally. On failure all owner fields and the tail output are unchanged; callback side effects such as a diagnostic count are not rolled back.

On success arrange retained records in original order in `[0,keep)`, followed by removed records in original order in `[keep,count)`. Preserve all rights and the original `count`; set `pending=1`, increment epoch, and publish a matching `{owner,epoch,new_end=keep}` token. Unlike ordinary C++ `remove_if`'s unspecified tail, this bounded owning adaptation deliberately preserves each removed right in a defined tail. It uses twelve decision cells plus a staged owner, with linear filtering/copy cost and fixed-capacity auxiliary storage. No destruction occurs in this phase.

`er_erase(owner,tail,drop,context)` requires a drop callback. A nonmatching owner/epoch/end or absent pending phase returns `ER_STALE` unchanged. A matching token calls `drop` once for each removed ID in tail order, zeroes those slots, sets `count=keep`, clears pending and increments epoch. The callback cannot fail, reenter, mutate the owner, retain storage or exit nonlocally; its context must maintain a valid resource ledger. Earlier admission reserved the epoch increment, so successful erase cannot wrap. Copied tokens do not duplicate a right; reuse after success is stale. A fabricated token with matching public fields is not cryptographically prevented.

`er_clear` with a required drop callback releases each of the current `count` rights, including a pending tail, then clears count/keep/pending. It increments epoch unless already at `UINT32_MAX`; terminal cleanup remains possible at exhaustion. Any outstanding token becomes unusable. At epochs above `UINT32_MAX-2`, filtering returns `ER_EXHAUSTED` before callbacks, preserving owner/output. These bounded generation rules do not solve owner-address reuse after object lifetime.

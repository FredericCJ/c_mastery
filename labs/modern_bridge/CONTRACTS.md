# modern_bridge contract, version 1

This contract is an additive bridge to PR-T16-01, PR-T51-11, PR-T55-05 and PR-T55-07. It does not replace accepted project identities, profile E/F machine obligations, historical receipts or earlier laboratory contracts. C17 remains the implementation baseline; the inspected N1570 text elsewhere is a C11 draft. The byte arena is profile C; the once/hazard anchor is a hosted C17 memory-model experiment; the epoch anchor is an explicitly serialized transition model. Hosted pthread tests are verification dependencies, never implicit freestanding target dependencies.

## Common ownership and failures

Preserve `include/bridge.h`. Control objects have stable addresses, are initialized exactly once before use, and remain alive until every borrower/worker is quiescent. Reinitialization in tests occurs only after all operations and old handles have ended. Do not copy initialized atomic control objects, forge handles, modify public representation fields except admitted region byte writes, or race initialization/destruction. Distinct control, output and input objects do not overlap. Required pointer arguments must point to live objects; null required controls/outputs return INVALID, except void initialization/clear functions accept null as a no-op. Non-null invalid addresses are outside the contract. Null hazard observe/collect and epoch collect return zero. Region generation, cursor, count and other exposed metadata are not untrusted serialized input.

All failed status-returning operations preserve output arguments and ordinary object state unless explicitly stated: unsuccessful hazard revalidation clears that reader's just-published hazard, and `mb_once_enter` may observe a competing CAS and return RETRY. Successful `enter` may acquire an initialization claim. MB_BUSY means ownership prevents progress now; MB_FULL means this bounded policy cannot admit; neither promises eventual completion. Returns do not allocate or log. Record stack, object size, atomic operations, callback work and generated helpers separately. C does not verify no-copy, borrow, callback or participant discipline.

## Region API

`struct mb_region` owns 32 declared character bytes and four cleanup entries. It is a byte arena, not generic typed allocated storage. `_Alignas(max_align_t)` does not change its declared type. `mb_region_alloc(r,n,a,out)` accepts positive n and power-of-two a in 1..8 and at most `_Alignof(max_align_t)`; zero size/unsupported alignment is INVALID. Compute padding relative to the aligned base, then admit padding and n against remaining capacity before addition. On success return `(owner,generation,offset,length)`, advance cursor, add n to payload, and retain peak cursor in high. Initial generation is1; generations1..3 admit,4 permanently refuses allocation and cleanup registration. Arithmetic rejection is FULL without consuming padding.

Only bytes within an admitted current span may be initialized by the caller. Reading requires prior initialization. `mb_region_read` checks owner/generation before extent/index; stale/foreign handles return STALE, invalid extent/index INVALID, otherwise copies one byte. It cannot validate a lying live owner, revoke raw pointers or enforce no escape. Never demonstrate a language lifetime violation by dereferencing an invalid pointer.

`mb_region_cleanup` appends a borrowed context and nonnull callback; ownership transfers to the region only on success. Registration does not allocate bytes. Context and externally owned resource survive until that callback returns. `reset` invokes callbacks in reverse order exactly once, then discards byte allocations/payload, advances generation without wrap, preserves high and clears busy. Bytes need not be erased. During cleanup, reading an initialized current span is allowed; allocation, registration and reset return BUSY. Callbacks must return normally, must not mutate region metadata, recursively call cleanup functions, escape through longjmp, retain/access an expired span, or destroy another pending context. Callback work can be unbounded even though byte reset is constant-time; reset with k callbacks is O(k). Callbacks cannot report failure in this API: a fallible cleanup requires a redesigned contract. Reset of a retired empty region is harmless; no generation resurrection.

## Once API

State encodes EMPTY0, RUNNING(owner0..2) as1..3, READY4 and permanent FAILED5. retry is immutable. `mb_once_enter(o,id,out2)` uses an acquire observation; READY copies two ordinary unsigned values; FAILED returns FAILED; RUNNING by the same participant returns RECURSIVE and by another BUSY. EMPTY claims a single initializer with CAS; success returns INIT, contention RETRY. IDs identify participants, not arbitrary caller-provided authentication. A participant cannot have simultaneous overlapping operations under the same ID.

Only the owner may `finish`: wrong or stale ownership returns STALE. Successful finish initializes both ordinary values before release publication. Failure publishes EMPTY under retry policy or stable FAILED under permanent policy. Failure arguments are ignored; no partially initialized values are exposed. This is a nonblocking protocol core, not a blocking wait primitive. Owner cancellation must run the owner's cleanup/finish-failure path; asynchronous thread cancellation, abandonment and process crashes are excluded. A stuck owner causes indefinite BUSY and must be reported. No reset/retry generation while readers remain live is supported. Integrating blocked waiters requires the existing execution wait enrollment/recheck/wakeup contract and a proof against lost wakeup.

## Hazard API

Three typed cells and two fixed reader hazard slots use logical identity tokens, not forged/dangling C pointers. A single writer serializes publish, retire and collect. Each reader owns one slot and must clear protection before publishing another. Initial generation1 advances after collection to permanent retirement4; a token encodes generation and index and never reappears during this domain lifetime. Publication initializes the selected free cell before a sequentially consistent source store. A nonempty source gives BUSY; absence of a usable free cell gives FULL.

Reader steps are observe source, protect that actual observed candidate, then use the copied value only after OK. Candidate0 gives EMPTY. Protect publishes the candidate in its slot, rechecks source using sequential consistency and, on mismatch, clears its slot and returns RETRY without reading payload. All nonzero candidates must have been returned by observe on this live domain. `clear` releases the protected interval only after its last hazardous access. Payload is immutable while published or retired/protected. `retire` atomically removes source, marks the cell retired and returns EMPTY if source was empty. `collect` scans every participant and reuses only unprotected retired cells; all source/hazard operations are sequentially consistent in this conservative baseline. State/generation metadata are writer-owned; readers touch payload only after revalidation. Storage and reader registrations remain fixed and live.

This finite adapter checks identity, protection and reuse ordering. It is not the general Michael algorithm, a proof of lock freedom on every C implementation, an allocator, or a solution to every ABA problem. The actual anchor schedules are controlled, not an exhaustive weak-memory execution search. A target mapping must inspect atomic lock freedom and helpers; hardware fences cannot be chosen by copying an x86 trace. Scan is O(cells*participants), protection uses two atomic observations and one store, and bounded generation retirement deliberately sacrifices eventual capacity. A stalled reader pins its hazard cells; it does not justify ignoring that slot.

## Epoch API

`struct mb_epoch` is a serialized specification model, with two registered participants, three one-use node identities, epoch1..3 and no wrap. `enter` of an active participant returns BUSY; `leave` of an inactive participant STALE. Retirement is once per node and records the current epoch; repeated retirement/reclaimed identity returns STALE. Advance is FULL at3; otherwise BUSY if any active participant entered before the current epoch, or increments by1. Thus an active current cohort permits one advance and prevents the next. Collect reclaims retired nodes only after distance>=2 and no active participant whose entry epoch is <= retirement epoch. It returns a count and never reuses a node identity.

A reader may access a node only after entry and before leave. A real append/read/remove structure must publish membership and implement entry/removal ordering; this tracker alone does neither. Concurrent unsynchronized access to this non-atomic structure is a C data race. Required target work must introduce a documented synchronized representation and independently test participant registration/deregistration. No active reader may be administratively forgotten. Stalled readers retain memory; epoch counter retirement is explicit exhaustion, not a reason to wrap. Entry/leave O(1), advance O(participants), collect O(nodes*participants).

## Verification boundary and security

Default learner sources compile and deliberately fail semantic checks. Assessor sources are supplied only through an explicit assessor path; learner packaging excludes them. Each anchor has two semantic mutations whose rejection requires MB_CHECK, not a crash or timeout. The once anchor includes100 rounds of three real pthread workers after deterministic failure/recursion checks; all are joined before storage is reused. Region/hazard/epoch anchor histories are controlled local models. Host sanitizers cannot prove the memory model, identify all stale logical tokens, prove progress or validate an OS/board port.

Use only original teaching programs, synthetic integers/bytes and local unprivileged processes. For the flawed hazard identity demonstration the harmless violation is wrong-generation data returned from a still-live typed cell; no actual use-after-free or arbitrary-code-execution claim is needed. Kernel integration remains inside disposable emulators/VMs. No host security changes, firmware flashing, deployed systems or third-party targets are authorized.

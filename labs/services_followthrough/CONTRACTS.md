# T56 exact service followthrough

This is an additive teaching ABI and a set of original, disposable guest experiments. The retained CMK1/CMK2/SDK provider files, original exercises and historical results remain unchanged. Choose every implementation source explicitly. The files in this public package deliberately leave mechanisms unfinished; assessor implementations are separate. C17 is the language baseline, with declared x86-64/Arm assembly at target boundaries. An emulator result establishes that selected executable and environment, not a physical board or an independent learner result.

## Process, thread and page authority

The kernel has eight process slots, four live threads per process and 32 global thread slots. The historical `cmk_handle` encodes only sixteen slots: using it for a 32-entry table can allocate a thread and return zero. SF encodes its own explicitly bounded tables and tags process/thread/channel/shared handles above the low32-bit slot/generation. Generations refuse wrap. Old numerical identities and old entry points retain their historical behavior. Tags diagnose table confusion; they do not authorize operations without owner, incarnation, state and rights checks.

Thread exit retires its execution frame and wakes its unique joiner. Process exit closes publication for every thread; a remotely current address space cannot be reaped until every CPU leaves it. Wait consumption, CPU quiescence, page reaping and pending-I/O process-slot retention are separate facts. A dead read owner receives no copyout. The DMA bounce storage is static provider storage, not the user page; freeing user pages after CPU quiescence does not authorize reusing the still-pending process incarnation.

Zero reservation initially owns no frame. A successful first touch zeros all4096 bytes even when an allocation was seeded with nonzero bytes. A copied private page must obtain a fresh frame before replacing its PTE; an allocation failure leaves the original shared frame intact and terminates only the offending process. A sole remaining COW owner can regain write permission without allocating. Refcount saturation is an admission failure before any clone mutation. Private clone refuses multiple live threads and explicit shared mappings; the separate inherited-shared profile has its own rights/refcount contract.

The saved x86 page-fault cause and current PTE are both needed. A second, already-resolved read/write fault may be admissible; an NX instruction fetch, read-only write, supervisor access or reserved-bit fault must not become writable/executable merely because a present mapping exists. The case15 test gate holds both real user page faults before either shared-lock acquisition. It is explicitly staged instrumentation, enabled only by that test; it is not a production fault-handler requirement or a native-model substitute.

## Copies, channels and mappings

Eight messages of up to512 bytes belong to each of eight queues. There are64 process-incarnation capability entries. A successful send copies the complete payload before publication; a blocked sender retains a kernel copy. A blocked receiver retains no caller pointer and retries whole validation after waking. Nonblocking full rejects before service ownership. Receive validates the actual message length, whole destination and descriptor before consuming or publishing any bytes. Page materialization can succeed for the first page and fail for the second; that changes mapping ownership, but leaves destination bytes and queued message unchanged. Closing refuses new/blocked sends while accepted messages remain drainable by surviving receivers. Owner death closes publication; a surviving grantee can destroy a closed, drained orphan.

Delegation grants a nonempty subset of the grantor's SEND/RECEIVE rights. It cannot grant CLOSE. Every token also binds queue generation and recipient process generation. A numeric token in a message supplies no authority to an unrelated process. Shared objects own one creator reference and every PTE owns another. Closing a creator handle retains live mappings. Unmap clears the PTE, obtains remote TLB acknowledgment and then drops the reference. New mappings are exactly one aligned4096-byte page within the admitted heap region, offset0, with read or read/write authority and no execute right. Checked admission rejects wrap and protected overlap.

The coherent x86 guest SPSC protocol separates head and tail cache lines and uses release/acquire in both directions. A plain counter has no synchronization contract; two reads of10 followed by two writes of11 lose an increment, and a C thread data race is undefined rather than a reliable measured outcome. On H745, C atomics alone do not establish cache visibility or DMA ownership: the selected target images use declared shared, noncacheable SRAM3 and explicit architectural barriers. Physical cache and interconnect behavior remains unobserved.

## Files, VM and store

The file probe uses the exact ten-byte `abcdefghij` object. Independent opens have separate descriptions; dup shares one description and offset. Whole copy admission precedes offset publication. Existing SDK seeks retain their admitted `[0,length]` contract. `SF_SEEK_EXTENDED` separately admits positions0..1048576; a position beyond EOF reads zero without moving. Flat-name admission rejects slash/traversal, duplicate names and malformed extents before lookup publication.

The VM service accepts copied containers up to256 bytes, verified with definite initialization before execution, at most100000 instruction and GC budget units, two independent client slots and no host capability. Each slot owns its Vs instance and arena. A result contains tagged byte encoding up to64 bytes; oversized serialization produces a capacity status and no partial response. Too-small caller storage leaves the retained response and outputs unchanged. Instance/session/request wrappers reject numerically colliding raw heap references from another instance. No raw Cvm reference crosses the service wire. Sessions and request IDs are nonzero and nonwrapping. New session admission requires a larger session and no running work. A running or retained result prevents replacing it; cancellation explicitly suppresses publication and permits subsequent work because this profile has no external host operation to abandon. A completed reply consumes its retained result; a duplicate ID does not resurrect it.

The store is owned by one actual user process, which alone holds the cache and delegated block capability. Its two authenticated senders use bounded copied requests. PUT is a durable idempotent assignment; its success follows `store_commit` and flush. A batch reads `left` then `right` in one serialized owner turn, with no intervening write. INCREMENT uses the retained SDR transaction committing effect, operation identity, payload and result together. Two provisioned client epochs are1, IDs are strictly increasing32-bit values and each client retains three receipts. Exact retained duplicates return their recorded result; same ID/different payload conflicts; an evicted older ID is stale and cannot be applied again. This bounds retry availability: it is not indefinite duplicate-result retention.

The restart experiments terminate the real owner process, reopen the same synthetic virtio disk in a fresh process, replace endpoint generations and bind a new session. A received request is not a durable success; no reply after durable commit is uncertain to the caller. The disk-reboot experiment additionally reboots QEMU against the recorded same disk and contrasts a freshly formatted-zero control. Corrupt/truncated uncommitted WAL payloads are tested while the commit marker is durably inactive. A damaged committed marker or active committed payload is a different fault class and must not silently recover as an incomplete tail.

## Reproducible evidence and physical work

Guest cases1..27 have separate mechanism names and assertions. `guest.py` records exact compiler/QEMU commands, source bytes, staged imports, images, maps, disassembly, unresolved-symbol audits and raw traces. Test-only fault allocation, before-lock arrival and completion-observer controls are declared parts of this original teaching guest. They do not change host policy, use host block devices or claim hardware cancellation acknowledgment.

The identical128-item workload has burst1 and burst4 admission policies, one compute quantum per offer round, and a quiescent final boundary that leaves at most two accepted items uncertain. Host time is `CLOCK_MONOTONIC` nanoseconds; the x86 guest reports emulator TSC counts. The H745 image pairs exchange logical acquisition and compute roles while RCC/boot/MPU authority stays with M7. Their input is synthetic, phases use release/acquire, interrupts remain disabled and no ADC/DMA operation is claimed. See `BOARD_CAPTURE.md` before any separately authorized physical experiment. Timing samples, image audits and a physical WCET proof are distinct claims.

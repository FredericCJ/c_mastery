# Owned mutex composition, recursion and transactional records

This is required successor support for all three PR-T51-03 criteria and their exact `-DELAYED` variants. Retain the original project, its T51.03 teaching, source passages, rubric and fourteen-field shared assessment contract. Prerequisites are PR-T51-01's wait-state contract, PR-T51-02's distinction between permit credits and ownership, the original CMX learner kernel, and a predicted original mutex fixture. The files `mutex.h`, `mutex.c`, `mutex_tests.c`, `mutex_m4.c` and `run_mutex.py` supply concrete interfaces, unsolved scaffold and observations. The completed CMX source is an explicit learner import; no reference implementation is copied into the learner package.

## Execution and representation

Use ISO C17 with exact-width `int32_t`, `uint32_t` and `int64_t`, the original sixteen-task/sixteen-mutex CMX kernel and caller-owned stationary storage. All operations run under one external exclusion boundary. This extension does not implement a lock that makes simultaneous native C accesses safe. Hosted tests drive logical tasks serially; the target experiment executes the same C state transitions on an owned Cortex-M4 emulator. Compiler helpers, linker inputs and generated code are audited separately. No allocator, mutex library or runtime may replace the studied CMX mechanism. Host Python orchestration is not a target dependency.

CMX task numbers are borrowed slots, not generation-safe public handles. A caller must not retain a slot across task reap/reuse. Mutex addresses remain live and registered until successful close; recursive controls and their embedded mutex may not move. Required pointers refer to valid initialized objects with distinct input/output/control storage, except the explicitly in-place record update. Call only after successful initialization. Arbitrarily corrupted control state is outside this contract. Fresh initialization may fail without publishing a control; it is not an operation on an already active object.

## Original owned-mutex mechanism

Implement CMX acquisition, nonrecursive self-lock refusal, wrong-owner unlock refusal, FIFO handoff, cancellation and destruction refusal first. On `CMX_BLOCKED`, resume by observing `task.result` after completion; repeating the lock call is a new erroneous request. Immediate acquisition may succeed at a due deadline; a contended `cmx_at(kernel.now)` is a nonblocking try and must leave the caller ready. Enqueue can fail at the original finite sequence limit. Priority donation changes urgency and does not remove a circular ownership dependency.

Drive A holding X, B holding Y, A waiting for Y, then B requesting X. The closing request returns `CMX_DEADLOCK` before changing ownership, queue sequence or the existing waiter. Cancel A's wait and release both resources. Owner exit must refuse, and close must refuse while owned or while a condition waiter retains an indirect reference through `task.aux`. In the latter case, cancel chooses the terminal result but reacquisition still precedes completion: destroying the temporarily unowned mutex would invalidate the pending return contract.

## Recursive changed condition

`CDRecursive` owns one original registered `cmx_mutex`, a borrowed kernel pointer, a depth and a positive maximum. The base CMX mutex remains nonrecursive. `cdm_recursive_lock` uses it for the first acquisition and ordinary blocked contenders. A live current owner can increment the wrapper depth without re-enrolling; at maximum it returns `CMX_FULL` unchanged. Unlock by another task returns `CMX_NOT_OWNER`. An intermediate unlock decrements depth without waking a contender. Only the final unlock calls the original handoff, setting depth to one for the newly published owner or zero if unowned. Task values outside 0..15 reject before conversion to an owner integer. Close delegates to the original lifetime checks.

All acquisition and unlock operations on this embedded mutex must use the wrapper; direct condition waits on it are forbidden because they would bypass recursive-depth bookkeeping. Condition interaction is tested separately with the nonrecursive mutex. Deadline and cancellation semantics remain those of the original wait protocol. Cancellation of a blocked contender does not alter the current owner's depth. There is no forced owner-death recovery or implicit rollback of protected application data.

Enumerate all 4,096 six-operation words over `{lock A, unlock A, lock B, unlock B}` at maximum depth two. Compare each of 24,576 transitions with a separately coded owner/depth/one-waiter state machine. Include final handoff to a contender and invalid operations. Construct a valid near-limit fixture at depth `UINT_MAX-1`, acquire once, reject the next increment unchanged, reject wrong-owner release, and verify that a valid release still decrements. This directly initialized boundary is not a claim that billions of acquisitions were executed.

## Callback lock ordering

`cdm_ordered_lock` receives the complete immutable registry of this kernel's mutexes, one distinct rank per object, the requested index, logical task and deadline. Count equals `kernel.mutex_count`; duplicates, foreign objects, duplicate ranks and invalid indices reject without changing kernel state. For every mutex already owned by the caller, the requested rank must be strictly larger. Otherwise return `CMX_DEADLOCK` before the base acquisition. This is a coarse, explicit global-order discipline, including calls made through callbacks; it is not a dynamically discovered whole-program call graph.

Hold rank20 and invoke a callback requesting rank10: refusal must preserve the first owner and leave the lower mutex free. Release, acquire rank10 and invoke the same callback for rank20: both acquisitions succeed. Verify the complete-registry requirement, duplicate-rank rejection and a contended nonblocking try. The proof assumes every potentially blocking acquisition in this lock group follows this API, including indirect calls. A callback obtaining an undeclared lock breaks that premise. An acyclic order excludes this class of mutex cycle; it does not exclude a semaphore, I/O, join or condition-predicate deadlock.

## Publication and overflow transaction

`CDRecord` contains signed balance and checksum `(uint32_t)balance XOR 0x9e3779b9`. Initialize it before publication. `cdm_record_read` requires ownership and validates the checksum before copying output. A refusal leaves output unchanged. `cdm_record_apply` also requires ownership, computes the proposed balance in `int64_t`, rejects values outside the `int32_t` range with `CMX_FULL`, then publishes both fields. Failure preserves both fields and ownership. Conversion of a negative balance to `uint32_t` is the ISO C modulo conversion; signed overflow is avoided before narrowing.

The optional observer is a teaching hook called while the mutex is still owned and both fields are consistent. Its context remains live; it must return normally, cannot mutate or retire the protected record/control, and may only attempt the declared nonblocking read through another logical task. It cannot block, reenter apply, cancel the owner or acquire another lock. The normal observer fails to acquire. A faulty implementation releases after changing balance but before checksum; the same observer then acquires and detects `CMX_BROKEN`. This witness is an entirely serialized logical schedule, so no native data race or undefined behavior is needed. The failed invariant is not a demonstration of arbitrary code execution.

Execute 64 updates with an observer and then a real blocked reader handed ownership after each complete publication. Retain all 192 owner transitions. Separately test `INT32_MAX+1`, `INT32_MIN-1`, a crossing-zero update, wrong-owner attempts and unchanged output. The overflow control corrupts only the checksum on failure; it must fail the exact unchanged-state assertion, not a later crash.

## Deliverables, falsification and costs

D1 derives ownership, recursion, complete-order and record invariants with the smallest counterexamples to semaphore/mutex equivalence, priority-inheritance-as-deadlock-cure and sanitizer-clean-as-publication-proof. D2 implements the actual base import and these adapters under the explicit contracts. D3 supplies the finite oracle, complete owner traces, exact boundary refusals, source/compiler/image hashes and positive/negative observations. Five semantic controls respectively omit depth capacity, release on intermediate recursion, ignore ordering, release before checksum and modify the failed-overflow record. The compiling learner and producer stubs must fail an intended semantic assertion after successful compilation. Compiler errors, sanitizer failures, abnormal signals and harness timeouts do not establish a correct negative result.

D4 performs the original seven-day changed conditions: recursive bounded depth; acquisition through a callback; and arithmetic rollback with the same ownership discipline. Author reference execution supplies a reproducible assessment opportunity, not the learner's delayed independent evidence. Level1 only reproduces one acquire/release trace. Level2 explains and implements every named refusal and the first divergent ownership/publication edge, with independent expectations. Level3 derives the changed contracts without the worked solution after the recorded delay and revises the whole argument when a callback or lifetime assumption changes.

Count wrapper storage, registry validation and critical work. Recursive entry/partial release and record arithmetic are constant work; final CMX handoff scans the fixed task table and invokes its existing priority propagation. Ordering validation uses O(M²) pointer/rank comparisons plus the underlying acquisition, with O(1) extra storage. The reference's bounded sixteen-task loops are not a certified latency or scheduling bound. A recursive wrapper increases state and can prolong exclusion; it does not make callback use safe automatically. Compile on GCC/Clang at debug/release and with address/undefined sanitizers, then execute the freestanding target and inspect all actual link dependencies. No ISO C edition supplies automatic mutex ownership, linear types, callback effect checking or transactional application updates: this contract relies on runtime checks and programmer discipline. A hosted language lock wrapper would likewise need a separate record invariant and callback policy.

Hints: label the owner before considering urgency; split recursion depth from wait membership; include indirect calls in the rank graph; preserve the old record before reasoning about failure. Assessor analyses and implementations remain separate. The laboratory target is the original local logical kernel and synthetic balances only. No external service, host security policy or deployed firmware is involved. The target ABI observation, finite oracle and sanitizer runs do not prove all schedules, native context switching, multicore correctness, physical timing, independent review or absolute mastery.

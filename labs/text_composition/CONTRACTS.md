## Recovery protocol

`tc_recover` admits at most512 bytes. A batch is a sequence of expression statements, each terminated by `;`. With newline_sync1, a newline is also a terminator; mode0 treats newlines as expression whitespace. A segment is trimmed of space/tab/newline. Empty terminated segments are errors. Whitespace-only final input is ignored; a nonempty unterminated final segment is one error with diagnostic status105 and error_offset at its trimmed end. No implicit terminator is inserted. Each complete segment is lexed, parsed with right-associative power and separately evaluated using the actual Pd producer. Lexical, syntax, capacity and arithmetic errors discard that statement's temporary tokens/tree. A successful statement contributes its int32 value and absolute trimmed start offset. A failed statement contributes begin/end delimiter offset, absolute blocked offset and the exact Pd status, or105 for missing delimiter. No external effect occurs while recognizing a statement.

There are at most16 successful statements and16 diagnostics; exceeding either capacity rejects the whole staged batch unchanged. The scan consumes one budget unit for each of length+1 examined positions, including final EOF; insufficient budget returns FUEL unchanged. Imported parser work is separately bounded by its256-byte/64-token/64-node contract; the scan budget is **not** a bound on individual lexer/interpreter instructions. A segment exceeding256 bytes becomes a RANGE diagnostic. A batch with errors but within capacities publishes surviving statements and all diagnostics with RECOVERED. For `1+;22;3*4;`, only22 and12 are published, with one error. `2147483647+1;9;` publishes9 and reports arithmetic failure for the first statement.

Synchronization consumes the selected delimiter exactly once, resets the failed statement's syntactic state and resumes at its successor. Parenthesis depth does not prevent semicolon recovery in this language; a spurious delimiter can produce multiple errors. This is an explicit statement-boundary strategy, not generic context-preserving compiler recovery. The delayed newline policy changes the admitted language: `1\n2;` fails as one expression in mode0 and yields1,2 in mode1. Show why quoted delimiters or multiline statements would require a different lexical/grammar contract.

## Document algebra and layout

A TcDoc contains1..128 nodes, a root and at most512 copied printable ASCII text bytes. Nodes are NIL, TEXT(span), LINE, CAT(left,right), NEST(amount,child), GROUP(child). Children must have smaller indices, so the structure is an acyclic shared DAG. TEXT contains bytes32..126, never newline; LINE alone denotes a break, or one space when flat. NEST adds0..120 indentation at subsequent breaks, never before an initial text. Reject cumulative indentation above120. CAT preserves order, NIL is its unit; flattening converts LINE to one space and removes indentation effects. Each GROUP chooses its flat child if a probe fits the remaining width, otherwise its broken child. A flat outer group forces every nested group flat.

The explicit probe includes the pending continuation after the group. It counts text and flat spaces until the next broken LINE or the end; unchosen groups encountered in that continuation retain the inherited broken mode. This is the specified deterministic greedy choice, not a claim of globally minimal line count or every optimality theorem for lazy Wadler/Oppen implementations. Width0..120 is a preference: an unbreakable TEXT can exceed it. `group(nest(2, "a" LINE "b")) CAT "zzz"` at width4 is `a\n  bzzz`; width6 is `a bzzz`. Ignoring the continuation or indenting initial text is incorrect. Every render/probe node visit consumes a shared fuel unit. The explicit frame/probe arrays each hold256 entries; repeated DAG references can produce much larger unfolded work, terminated by fuel/output bounds. Analyze expanded visits and repeated lookahead, not just unique-node count.

`tc_expression_doc` adapts an actual successful immutable PdTree of at most14 nodes into this algebra. It preserves the whole syntactic tree by fully parenthesizing binary and prefix operators, not merely its current numeric value. Number literals are nonnegative int32 values, prefix negation is a separate node, operator kinds are the producer's exact kinds. Larger trees return RANGE. For each width, reparsing rendered text must reproduce node kinds, literal values, children and root while allowing different source offsets. Parsing may succeed even if evaluation overflows; formatting must retain that syntax rather than silently fold it. Delayed assessment introduces an unbreakable continuation and compares width changes, nested groups, flat outer groups and DAG sharing under a small fuel limit.

## Restricted templates and synthetic injection target

`tc_template_compile` admits0..256 ASCII template bytes and emits at most128 typed operations; maximum block nesting64. Ordinary printable bytes, tab and newline are literal output. `{{` and `}}` emit literal braces. `{a}`..`{d}` emit the first value of a model field, or nothing if absent. `{.}` emits the current loop item, or nothing outside a loop. `{?a}body{/}` includes body iff field a is present (count>0). `{*a}body{/}` applies body to each field value in order. These block forms support all four names a..d and may nest. `{>0}`..`{>3}` include a statically named bank entry. Unknown directives, computation such as `{a*2}`, unmatched closing/opening blocks and solitary braces reject compilation unchanged. Empty body blocks are valid. The compiler pairs block jumps; the interpreter independently validates operation kind, ranges and properly nested start/end relations before execution.

A model is four fields, each0..4 copied byte strings of length0..256. Values contain printable ASCII/tab/newline only. Presence differs from nonempty string. A bank has1..4 compiled immutable programs; entry must exist. An executed missing include returns INVALID; an executed include cycle returns CYCLE via the active-template set. An unexecuted conditional cycle does not fail. Includes retain the current loop item, while nested loops shadow and restore it. No files, network, dynamic name resolution, expression evaluation, callbacks, casts into model functions, or model writes exist. The interpreter recursion limit128 is explicit; excessive nesting returns RANGE unchanged. Each executed operation, loop iteration and emitted byte consumes budget; expansion can be exponential in nested loops, so budget and output admission are essential.

Rendering has two explicit modes. html_text1 replaces model `& < > " '` with `&amp; &lt; &gt; &quot; &#39;`. It does not rescan produced entities or evaluate braces from values. Literal template text is trusted structure. html_text0 emits model bytes literally for plain-text output. This is HTML **text-node** encoding only, not a sanitizer for attributes, URLs, JavaScript, CSS or untrusted template structure. The first-principles mechanism is the explicit bounded encoder and evaluator; no server/browser is started. The original flawed mutant omits model escaping. Feed synthetic `<tag>&` and observe literal markup-shaped bytes in its output versus `&lt;tag&gt;&amp;` in the correction. That observable string violation is the success condition; it is not evidence of script execution, credential theft or arbitrary code execution. Inputs/outputs stay in local tests. Compare both modes under equal declared contracts, check model byte identity, reject include cycles, and kill a second mutant that repeats the first loop item instead of advancing.

The C API prevents model mutation through its declared operations, but `const` alone does not prevent another alias from changing the model, and a caller can supply layout-shaped model text. Compare the restrictions with Parr's formal separation rules and identify which properties require model construction discipline. The delayed variant combines nested list application and static includes, changes plain-text to HTML-text encoding and forces cycle/fuel/output refusal. No universal model-view or injection-safety claim follows.

# Higher-order construction and interpretation contract

## Common scope

C17 hosted Linux, exact int32_t/int64_t/uint64_t types. Initial objects are zeroed or constructed by this API; all pointers and callback contexts remain live, correctly typed and disjoint from mutable outputs. Null required control/output pointers reject with HO_INVALID. Void operations have no hidden destructor. Inputs remain stable throughout calls. No concurrency or callback reentry is admitted. Caller-forged internal nodes/carriers, invalid pointers, nonlocal callback exits and arbitrary struct copying after external ownership transfer are not checked generally by ISO C. The implementations use no free-monad, interpreter or closure library; Python/stdio/sanitizers belong to host verification. No physical or freestanding execution is claimed.

## Free effect representation

HOA owns65 HONode entries; index0 is invalid, entries1..used (at most64) are live. Pure stores an int32 result. Emit stores one int32 output and one continuation root. Choose stores the roots for answer0 and answer1. Every constructor points only to already existing nodes in this same arena, so edges strictly decrease indices and cycles cannot be constructed. Roots borrow the arena; roots, interpreters and bind traversals must all be quiescent before the arena is reset. Child references may share nodes, but own no separate deallocation obligation. The finite functor is Emit(int,next) plus Choose(next0,next1); its free structure adds Pure results. This is a specific first-principles effect language, not a generic C type constructor.

Constructors allocate one typed node. attempts increments before capacity/injected-failure decisions; SIZE_MAX rejects without wrap. fail_at0 disables injection, otherwise equality with the incremented counter fails. Failure leaves output and used unchanged. Capacity exhaustion returns HO_FULL. ho_bind traverses terminal Pure values and substitutes each with the root produced by HOBind. The callback borrows context only during construction, may append through the same arena API, returns HOStatus and a valid same-arena root on success, and must not mutate old nodes, reset used, change failure configuration or retain borrowed construction storage. On any failure the outer bind restores used to its entry mark and preserves output; attempt counters remain consumed. No newly created root may escape a failed bind. All preexisting roots remain valid. Callback effects outside the arena would not roll back and are excluded from the algebraic laws. This explicit tree construction replaces captured continuations with two possible branch roots; it does not capture the C stack.

ho_run stages a complete HOResult. Choose consumes one supplied0/1 byte; Emit appends to at most32 trace values; Pure returns its value. Missing answers return HO_INPUT, invalid answer bytes HO_INVALID, trace exhaustion HO_FULL. Every rejection preserves the complete caller output. Extra unused answer bytes are permitted and consumed reports the actual prefix. There is no externally committed I/O or resumption state in this whole-run interpreter. ho_summarize is a different interpreter: paths counts all answer paths, emissions sums their emitted-value counts and sum adds final values. Shared children count once per path, not once per physical node. Memoize per node to avoid traversing exponentially many shared paths; check unsigned and signed accumulation overflow before output publication. The64-node DAG can represent2^63 paths. Construction, bind and the summary interpreter are distinct mechanisms and costs.

Monad left/right identity and associativity apply to observable result/trace when callbacks are pure constructors and all constructions succeed. Root indices, allocation counts and failures are not equated by those laws. For example, binding a full arena through a reconstructing identity can fail while running the original root succeeds. A capacity or callback side-effect counterexample refutes unconditional operational equality without refuting the mathematical law. Bind copies effect paths without memoization; DAG sharing can duplicate substitution work and allocations. Its node limit bounds successful allocations but is not a claim of constant work. Interpreter path length and recursion depth are at most64; the summary uses O(65) memo storage plus O(depth) recursion.

## Typed final interpretation

HEInt is int32_t; HEFun is a compatible callback plus borrowed context. HPInt and HPFun are distinct concrete structs with a127-character payload and terminator, carrying rendered integer and function expressions. HEOps and HPOps contain genuinely different C function-pointer signatures for literal, addition, integer-function abstraction and application. The same program definition in tests/program.inc is specialized twice. Its higher-order term accepts an integer-to-integer function, applies it to1, then adds2. Function bodies add a captured integer. This is a closed, explicitly typed fragment with integer expressions and integer-to-integer functions; it does not implement arbitrary kinds, type inference, generic higher-order type constructors or a general lambda calculus. ISO C diagnoses the supplied incompatible carrier/function arguments. A callback with a correct signature but false semantics still compiles.

The evaluation interpreter's lambda constructor borrows its HEBody/context without invoking it; application invokes exactly once, stages the output and retains external callback effects on failure. The context and operation table captured by a body remain stable/live for every use. No automatic ownership or lifetime checker follows from HEFun. The rendering interpreter invokes its builder once during lambda construction with the symbolic variable x and stores a completed textual value; later rendering of application does not invoke that builder. Builders must be semantically pure for an equal-denotation comparison. Call-count instrumentation is permitted but its differing schedule must be reported. This fragment has one binder and does not admit nested same-name binders; a generalization needs fresh names and explicit capture rules.

Evaluation addition stages an int64 calculation and rejects outside int32 range; literal is exact. Rendering composes parentheses/text and rejects above127 characters, preserving output. Builder failure also preserves output. Rendered text is a denotation for inspection, not an accepted untrusted serialization protocol or executable command. Cross-interpreter equality compares the represented program's meaning on jointly admitted inputs, not equal callbacks, representation sizes, failure capacities or construction schedule. Negative and INT32_MIN literal rendering must avoid negating INT32_MIN in its own signed type.

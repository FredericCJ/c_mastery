# T09 inspected primary passages

Sources below were read only within the named bounds. Glibc2.42 source is not the observed Ubuntu glibc2.43 binary source.

- **R-LELF-HEADER**: [ELF header](https://gabi.xinuos.com/elf/02-eheader.html), ELF Object File Format4.3 DRAFT. 2.1–2.2, lines4–207: header fields/class/order/ordinary and extended counts. Header interpretation; unsupported extended counts must remain explicit.
- **R-LELF-SECTION**: [ELF sections](https://gabi.xinuos.com/elf/03-sheader.html), ELF Object File Format4.3 DRAFT. 3.1–3.3, lines1–214: header fields, alignment, extent, NOBITS and section types. Section metadata differs from runtime mapping; only this bounded passage was inspected.
- **R-LELF-STRING**: [ELF string table](https://gabi.xinuos.com/elf/04-strtab.html), ELF Object File Format4.3 DRAFT. Complete27-line string table chapter: index, terminating NUL, empty table and suffix references. Bounded names and byte indexes rather than native pointers.
- **R-LELF-SYMBOL**: [ELF symbols](https://gabi.xinuos.com/elf/05-symtab.html), ELF Object File Format4.3 DRAFT. 5.1–5.3, lines4–163: fields, bindings, weak/archive/local ordering and TLS symbols. Symbol interpretation and resolution obligations; not full platform symbol semantics.
- **R-LELF-RELOCATION**: [ELF relocation](https://gabi.xinuos.com/elf/06-reloc.html), ELF Object File Format4.3 DRAFT. 6.1, lines3–66: REL/RELA, field versus virtual offset, explicit/implicit addends and composition. Processor relocation formulas still require the named psABI; RELR implementation is not claimed.
- **R-LELF-SEGMENT**: [ELF program headers](https://gabi.xinuos.com/elf/07-pheader.html), ELF Object File Format4.3 DRAFT. 7.1–7.3, lines3–135: fields, PT_LOAD, filesz/memsz, order/alignment and PT_TLS. Segment file/memory intervals; no general safe-loader claim.
- **R-LELF-AMD64**: [AMD64 relocation table](https://refspecs.linuxfoundation.org/elf/x86_64-abi-0.99.pdf), Draft0.99.6 July2,2012. 4.4, printed70–72: RELA, notation, Table4.10,32/32S extension checks. Actual absolute32/PC32 formulas; historical draft retained as such.
- **R-LELF-OPTIONS**: [GNU ld options](https://sourceware.org/binutils/docs/ld/Options.html), Moving manual inspected2026-10-17. Archive one-pass search lines169–178; Group search lines712–717; Whole archive lines1348–1352. Extraction policy and link order; actual installed version is captured by the campaign.
- **R-LELF-KEEP**: [GNU ld section retention](https://sourceware.org/binutils/docs/ld/Input-Section-Keep.html), Moving manual inspected2026-10-17. Complete KEEP input-section example. Section retention does not imply extracting an archive member.
- **R-LELF-MEMORY**: [GNU ld memory regions](https://sourceware.org/binutils/docs/ld/MEMORY.html), Moving manual inspected2026-10-17. 3.7, lines5–68. Region bounds and non-shuffling section placement; synthetic maps are not board authority.
- **R-LELF-LMA**: [GNU ld output LMA](https://sourceware.org/binutils/docs/ld/Output-Section-LMA.html), Moving manual inspected2026-10-17. 3.6.8.2, lines5–35. VMA/LMA distinction, AT/AT> and copy/zero startup responsibilities.
- **R-LELF-ASSERT**: [GNU ld script commands](https://sourceware.org/binutils/docs/ld/Miscellaneous-Commands.html), Moving manual inspected2026-10-17. 3.4.5, lines7–32: ASSERT timing and EXTERN; lines45–58: INSERT augmentation. Named budget failures, explicit extraction and retained default-script layout.
- **R-LELF-SYMBOL-ADDRESS**: [GNU ld source symbol references](https://sourceware.org/binutils/docs/ld/Source-Code-Reference.html), Moving manual inspected2026-10-17. 3.5.5, lines5–51. Linker address symbols allocate no C object; source conventions remain implementation-bound.
- **R-LELF-VERSION**: [GNU ld symbol versions](https://sourceware.org/binutils/docs/ld/VERSION.html), Moving manual inspected2026-10-17. 3.9, lines5–62: version trees, visibility, .symver and default/multiple versions. Named version availability differs from semantic compatibility.
- **R-LELF-DLOPEN**: [Linux dynamic loading interface](https://man7.org/linux/man-pages/man3/dlopen.3.html), Moving Linux man-pages inspected2026-10-17. lines41–84: recursive search and lazy function resolution; lines144–158: reference counts and reopen flags; lines365–367: POSIX function-pointer lookup convention. Original child-local loading, function versus data timing and module lifetime.
- **R-LELF-TLS**: [glibc TLS allocation and initialization](https://raw.githubusercontent.com/bminor/glibc/glibc-2.42/elf/dl-tls.c), glibc2.42 tagged source. _dl_allocate_tls_storage lines468–495; _dl_resize_dtv lines501–543; _dl_allocate_tls_init lines546–650; _dl_deallocate_tls lines663–679; allocate_dtv_entry/allocate_and_init lines682–727. Allocation, deferred entries, copy/zero and deallocation; observed host2.43 is explicitly a different build.
- **R-LELF-DSO-INIT**: [glibc DSO initialization consumer](https://raw.githubusercontent.com/bminor/glibc/glibc-2.42/elf/dl-init.c), glibc2.42 tagged source. call_init lines22–70: once flag, relocation precondition, DT_INIT and DT_INIT_ARRAY calls. Identified runtime consumer; no whole-loader source inspection claimed.
- **R-LELF-START**: [glibc program startup](https://raw.githubusercontent.com/bminor/glibc/glibc-2.42/csu/libc-start.c), glibc2.42 tagged source. lines153–185: static init/fini traversal; lines222–329: auxiliary vector, static-PIE relocation call, TLS setup, fini registration and call_init/main handoff. Metadata producer versus consumer and self-relocation ownership; exact host source body remains separate.
- **R-LELF-OBJCOPY**: [GNU objcopy transformations](https://www.sourceware.org/binutils/docs/binutils/objcopy.html), Moving manual inspected2026-10-17. lines97–103: raw output starts at lowest copied LMA; lines170–184: stripping modes; lines300–308: gap fill and padding; lines353–360: dump/update sections. File-format conversion loses or changes information independently of RAM costs.
- **R-LELF-DEBUGLINK**: [GDB separate debug files](https://www.sourceware.org/gdb/current/onlinedocs/gdb.html/Separate-Debug-Files.html), Moving manual inspected2026-10-17. 18.3, lines5–64: lookup, build ID, filename/padding/CRC, correlation and split commands; lines125–130: CRC iteration. Companion identity and address correlation; no security signature equivalence.
- **R-LELF-HEX**: [Keil Intel HEX format](https://www.keil.com/support/docs/1584/_hlp_hexfile.htm), Article1584 reviewed2021-02-25. Record/data/checksum lines47–90; Extended linear/segment/start addresses lines91–143; EOF lines144–156. Tool-vendor primary description of byte-oriented records; MDK-specific entry interpretation is not universal.

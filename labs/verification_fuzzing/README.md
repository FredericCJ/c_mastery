# Formal verification, falsification and fuzzing laboratory

C17 target implementation; Python mathematical oracle, CBMC and Clang fuzz/sanitizer runtimes are host-side verification dependencies only. Use local original programs and synthetic data.

Portable core controls are independent of required guest/board observations. Ordinary init copies compiling learner stubs, tests and contracts. Explicit `-DCMASTERY_ASSESSOR_ROOT=/absolute/repository/assessor` selects reference sources; never use that flag for learner evidence.

Actual solver version/commands/results, reachable assumption witnesses, complete-unwinding evidence and bounded fuzz campaign logs remain distinct requirements; missing tools do not become successful proof.

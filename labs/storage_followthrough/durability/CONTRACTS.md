## Stable and pending model

Implement `medium.c` from the public stub. A successful write copies one complete page to pending state and marks it dirty; it does not promise persistence. Reads observe pending bytes when dirty, otherwise stable bytes. A successful nonlying flush copies every dirty page to stable in reverse page order and clears dirty flags. A selected boundary returns an error after applying its specified persistence transition, marks the medium dead and disallows further I/O until reboot. Reboot discards pending authority and trace state but retains stable bytes and lifetime counters.

The seven full-protocol modes are: no pending persistence; reverse even-page subset; first 2048 bytes of the current write; last 2048 bytes; all pending writes persisted despite an error; reverse odd-page subset; and a 512-byte tear at offset 512. Tear modes act only on the selected write boundary; a selected flush boundary in those modes persists no additional bytes. The eighth mode accepts a caller-selected subset bit mask. Enumerate all four subsets of two pending toy pages. These are declared model transitions, not measured device reorder or tear behavior.

Read-failure injection is a separate absolute read number. It may write the first 17 bytes of the output and then report failure. The store must not interpret failed callback bytes as a complete page. A deliberately lying flush returns success without persisting pending data. Label its outcomes as a violated persistence premise; never silently expand the successful-flush contract after seeing a failure.

## Finite model and security scope

Derive a reduced six-page transition system: two homes, an alternate checkpoint, two after-images and a marker; the older checkpoint is implicit. Each page is old, new or invalid-CRC. Enumerate unchanged/full/torn outcomes of every pending page at every cut and repeatedly restart recovery. Use visited-state exploration with no selected number of reboots. Explain the correspondence between actual 32-page event traces and the reduced homogeneous batch, including the premise that each physical page is written at most once per flush epoch. The model omits CRC collisions, byte-level structure, concurrency and hardware behavior; those require separate evidence. Produce shortest counterexample traces for missing data flush, missing commit flush and early reclamation. Do not equate model termination with a proof of arbitrary C executions.

The CRC exercise targets only this original local teaching decoder and synthetic pages in process memory. The attacker may change page bytes and compute CRC values; no file outside the disposable laboratory image, external service or real data is involved. Flip the one-byte value in a valid leaf and solve the 32-bit linear CRC correction using four reserved bytes. The harmless success condition is two accepted pages with the same stored CRC and different decoded values. This demonstrates failure of authentication, not code execution or privilege gain. CRC still detects many accidental corruptions. Structural checks, trusted generation authority and byte-preserving regression tests address their respective properties; adversarial authenticity needs an independently keyed authentication design with key ownership, replay policy and domain separation. Merely choosing a different unkeyed checksum does not repair this property. Retain collision and structural regressions, and state residual availability, rollback and key-compromise limits of any proposed authentication design.

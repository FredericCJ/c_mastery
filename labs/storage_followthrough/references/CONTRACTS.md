# Allocation incarnations in a versioned tree format

This required successor implements `AX-PR-T47-05-T47.05.b-DELAYED`: add generation-tagged page references under a versioned format. It extends the ordinary merge/reuse ownership exercise with a distinct persistent allocation identity. Families A, B, C, D, F, G, H and J apply. The original CST2 provider and accepted evidence remain unchanged; CST5 is a separately compiled teaching fork, not an in-place upgrade.

## Three different identities

The transaction generation orders complete committed images; it does not identify an allocation of a logical page. Each of32 logical positions therefore has a persistent64-bit allocation incarnation. Position0 is metadata and has incarnation0. A live node1..31 has a nonzero incarnation. Freeing keeps its last incarnation in the metadata table. Allocation chooses the first free position below `UINT64_MAX`, increments its incarnation before publishing links, and records it in the node. A slot may issue MAX once; after it is freed, future allocation skips it and searches later positions. No wrap or reset-to-one is allowed.

Every authoritative reference is a pair: root ID/incarnation, child ID/incarnation, or leaf-next ID/incarnation. A node also records its own incarnation. Moving a child or next link must move both fields, including internal split, borrow, merge, parent compaction and root contraction. Null next is exactly0/0. The tree checker still requires one owner per reachable allocated page, exact separators, occupancy, equal leaf depth and leaf-chain agreement; tags supplement those conditions rather than replace them.

`struct store_ref` is an observational reference `(live owner,id,incarnation)`, not an owner or pin. `store_ref_make` can mint it only outside a transaction on a valid live node; `store_ref_read` similarly refuses active/poisoned state and copies a validated node to a disjoint destination. Freed or mismatched identities return `STORE_STALE` unchanged. A caller may copy these observations, but all stop being usable before owner destruction, constructor reuse or switching the owner's image. Equal pointer bits after a new C lifetime do not restore authority. Cross-process or durable external capability identity is not supplied.

## CST5 byte contract and persistence

All pages use magic `0x43535435`, with the parent kind at byte4, transaction generation at8, logical ID at16 and CRC at4092. The retained fixed key/value/child offsets and seven-key occupancy rules are unchanged. In a node, own incarnation is little-endian64 at768, next incarnation at776, and nine child-incarnation slots start at784. A canonical leaf emits all child tags zero; an internal node emits only n+1 active tags and has next0/0. Decode rejects zero live tags, nonzero unused child tags, invalid next pairs and the wrong format. Existing native padding is never serialized.

Metadata page0 stores root ID at20, bitmap at24, root incarnation at32 and32 little-endian64 allocation counters at64. Counters of free and retired positions are included in full-image redo and checkpoint; omitting them would make a stale identity reusable after reopen. The complete canonical leaf and metadata pages are independently constructed in Python. An otherwise valid CST2 node is rejected with unchanged output; there is no implicit migration. CRC and generation consistency are not authentication against an actor able to rewrite the complete trusted image consistently.

Every traversed node validates its own incarnation against the table and all its outgoing live references against current allocated identities; root access also validates the root pair. A resealed page with a stale child tag must fail open/check/traversal, even though its checksum and logical page ID are valid. Native active scratch is an engine-owned valid representation, not an untrusted arbitrary byte buffer; public callers cannot mutate it during operations.

## Aborts, publication and finite resources

An active transaction owns provisional incarnations and reference pairs. Begin saves the root pair and entire incarnation table; whole-transaction abort restores them with the original root/bitmap. This rollback is valid only because references cannot be minted or dereferenced while active, provisional references do not escape, and no dirty page has been published. A commit's IO or indeterminate failure still poisons the owner according to the parent contract; never restore an undo copy over potentially durable effects or relabel an uncertain commit as an abort.

A successful committed allocation remains counted after deletion, checkpoint and reopen. Reclaiming a node removes its authoritative links and bitmap bit but preserves the last incarnation. A live MAX-incarnation node remains usable and can be deleted; cleanup is not blocked by admission exhaustion. Full capacity or all eligible free slots retired returns the original full/whole-transaction-abort result. Explain how the new32-counter save area and88-byte node tag extension change resident space, copying and disk bytes; derive costs separately from the parent O(B*H^2) separator repair and full-image commit.

## Concrete implementation and falsification

Implement `refs.c` from the public stub. Retain all split/borrow/merge/root and prefix-map checks from the tree fixture. Run `exercise`, `persistence`, `reuse`, `retirement`, `stale` and `rollback`. `reuse` commits eight records, observes page2 incarnation1, deletes all, reinserts and observes the same page at incarnation2 while the old reference rejects unchanged. `retirement` seeds a valid free counter at MAX-1, issues MAX, frees it, then proves allocation skips page2 and uses page3 with its next incarnation; reopen preserves retirement. These boundary fixtures are explicit trusted component states, not claims to have performed2^64 operations.

`stale` changes root, child, next and node-own tags separately, restores each valid fixture, and checks rejection. It then changes an actual stored root-child tag and recomputes its CRC; fresh open still rejects. `rollback` refuses the second cascading allocation, proves unpublished counters restore, forbids active reference minting, then commits/deletes/checkpoints/reopens and proves the freed counter survives. Three compiled controls ignore incarnation equality, reuse a retired MAX slot at1, or omit free counters from the persistent metadata.

Hosted C17 is the implementation baseline. The four builds are capacity 7/path, capacity 7/full, capacity 3/path and capacity 3/full. No freestanding, foreign-ABI or physical drive claim follows from this packet.

The fixed representation remains 32 logical pages, seven persisted/eight scratch key slots in the original capacity 7 profile, eight native key slots and nine child slots, 16-byte keys and 64-byte values. Capacity3 deliberately retains the same large arrays and disk offsets to isolate occupancy and algorithm changes. It is not a space-optimized format. Native structs are never serialized directly. Pages have explicit little-endian fields and the original IEEE CRC. Capacity7 uses the original magic `0x43535432`; capacity 3 uses new magic `0x43535434` for every page kind, including superblocks and commit records. These are disjoint format profiles, not an automatic migration. The full 4096-byte canonical oracle and cross-profile decode rejection are required; a CRC is not authentication.

All objects are live, initialized by their constructor, exclusively owned and externally serialized, including reads and test hooks. IO callbacks may perform partial effects on failure; a successful flush has the parent durability contract. Callbacks do not reenter/mutate the store or retain borrowed buffers. Fresh format authority remains required. `tree_page_admit` is an explicit verification port before allocation publication; false refuses that allocation. `tree_event` records entry into the named mutation branch or repair visit. It must not inspect a temporarily inconsistent tree, change state, fail, retain a pointer or reenter; its counts do not themselves establish completed publication. They are not hidden storage dependencies.

## Derive the split and deletion rules

For maximum `B` in {7,3}, define `h=(B+1)/2`. A leaf overflow contains B+1 actual records and splits h/h. The parent copies the right leaf minimum; that record remains in the leaf. An internal overflow contains B+1 separators and B+2 children: promote separator h, keep h separators/h+1 children on the left, and h-1 separators/h children on the right. Nonroot minima are h leaf records and h-1 internal separators. The root can be an empty leaf, or must have at least one separator. All leaves have equal depth; separator i equals the minimum of child i+1 and equality descends right.

Before coding, draw keys 0..7 and the first cascading capacity 7 internal split, then keys 0..3 and the corresponding capacity 3 split. Label each child interval and every authoritative reference. Derive left/right borrow, merge and root contraction separately for leaves and internal nodes. Check that a non-underflow deletion of a subtree minimum still changes an ancestor separator. Explain why clearing an allocation bit before repairing all authoritative tree/leaf references is not sufficient ownership transfer.

Implement both capacities in `tree.c`. Maintain ordered unique leaves, exact minima, occupancy, equal depth, one owner per allocated node and a leaf-next chain matching tree traversal. A released node must be absent from every authoritative link before any later public operation can allocate it. Temporary states inside a serialized operation are not externally observable; hooks cannot reenter. Whole-transaction abort on insertion allocation failure remains the parent policy. This packet does not silently adopt the separate operation-undo facade, nor does it make stale external page IDs safe.

## Changed separator repair and its costs

Keep the full recursive refresh as a measured comparison (`TREE_FULL_REFRESH=1`). Implement the changed repair using an operation-local set of affected nodes inside each store. Before mutation, clear a bit set and explicit ID list; append each page at most once. Mark the original ancestor path, split outputs/new root, and both participants in every borrow/merge. Freed nodes are skipped; live leaf records are already canonical. For each live affected internal node, derive child minima by following child0 to a leaf without consulting potentially stale separators, then publish each separator. Sibling modifications are part of the affected region, not merely the original search path.

Explain why repair order does not depend on other repaired separators. An unmarked node has neither changed children nor a changed descendant minimum; changed descendants lie on a marked ancestor path, and moved siblings are explicitly marked. With height H, fanout at most B+1 and M affected nodes, this implementation has O(M*B*H) repair work, with M=O(H) for one operation, hence an O(B*H^2) bound. The explicit list avoids scanning all P bitmap positions. It is not an O(H) proof or a claim of universally faster code. Full refresh visits O(P) allocated nodes. Both share the fixed O(P) resident workspace and the parent allocation search/whole-image transaction costs; those costs do not disappear when separator maintenance improves.

Required diagnosis controls omit sibling marking, omit all repair, preserve a retired leaf-next link, route equality left, and propagate an incorrect subtree minimum. Identify the first violated invariant and a minimal public sequence; do not suppress the checker. The wrong-minimum control fails on the first leaf split (eight inserts at capacity 7, four at capacity 3), while its shorter prefixes have no parent separator to corrupt. Explain why a correct final map alone cannot excuse invalid intermediate links.

## Concrete workloads and independent verification

Run six named cases for each capacity/policy: `shape`, `exercise`, `minimum`, `separator`, `mixed`, `persistence`. The exercise inserts 92 keys at capacity 7 or 32 at capacity 3, with ascending, descending and alternating-end orders; deletes by `(37*i)%count` and nine deterministic shuffled orders; checks every key/value, ordered scan and complete tree after every operation; empties to the single original root leaf; then reinserts. Event assertions require left/right borrow and merge at both leaf and internal levels, root growth and contraction. The seeded mixed workload performs 4096 replacement/new-insertion/present-deletion/missing-deletion operations over 20 keys and checks each prefix. `minimum` deletes 20 from 0..26 or 8 from 0..10 without underflow. `separator` queries every actual internal separator. `persistence` commits/reopens, deletes/commits/reopens and reinserts/commits/reopens in the selected RAM model.

The independent Python map enumerates 3375 three-operation histories from 15 operations plus 120 five-key insertion permutations: 3495 histories, 10725 transitions per executable. Its full canonical page construction uses integer packing and `zlib.crc32`, independent of the C codec, and sends each profile's page to the other profile's decoder to verify unchanged output on refusal. The same larger workloads compare logical full-refresh visits against local-minimum visits and affected internal-node counts. Record native object size, compiler stack output, object disassembly and actual include/link closure. Logical visits are not nanoseconds, disk measurements or a universal speedup. No finite enumeration proves arbitrary tree correctness.

Use `cmake -S labs/storage_followthrough/tree -B build/tree -G Ninja` for the unfinished public implementation. Add an explicit `CMASTERY_ASSESSOR_ROOT` only for assessor verification. Public stubs must compile and fail semantic assertions; a compiler failure or sanitizer abort is not a valid mutant kill. An assessor run executes all 34 cases (24 positive and 10 compiled control rejections); the source-bound runner repeats all six compiler profiles and the independent oracle. Exported learner workspaces contain these public files, never the private implementation.

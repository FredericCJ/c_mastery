# Abandonment is not completion of an asynchronous block read

## Exact obligation and prerequisites

This required changed-condition assessment implements `AX-PR-T47-12-T47.12.b-DELAYED` from `PR-T47-12`: replace a synchronous page service with actual queued I/O and preserve borrowed storage through completion. Core prerequisites are T03 object lifetimes and PR-T47-01/02 page/backend contracts. The actual guest stage additionally requires PR-T48-09 block I/O and the retained T53 CMK2 async ABI in `labs/kernel_smp/include/cmk2_abi.h`, plus a completed `SaRead`. The supplied public CMK2 workload and build producer are copied into an isolated workspace; the kernel implementation remains an explicit external completed provider. This is a changed adapter, not a claim that the original synchronous store API became asynchronous.

## Representation, operations and authority

The ISO C17 core holds one backend ticket, one borrowed writable 4096-byte buffer, a live callback/context pair, a state and an abandonment bit. Start requires zero-initialized EMPTY control. Control, output pointer storage, buffer and context are live, appropriately aligned, exclusively owned and mutually disjoint; callbacks cannot reenter or mutate control. Do not copy a live control or independently change the submitted buffer. Initializing over a live or quarantined control would discard ownership and is forbidden.

`submit_read` returns a positive ticket only when accepted; a nonpositive return promises that no request retained the buffer. `wait` returning zero is the backend's completion and memory-quiescence certificate. A nonzero result is not such a certificate. Callback exceptions/nonlocal exits and asynchronous control destruction are outside the profile. ISO C enforces none of these ownership promises.

Start publishes OWNED only after acceptance and preserves control on rejection. A second start refuses before calling the backend. Abandon records that the result is unwanted; it does not cancel the device, release the borrow or clear the ticket. Finish on OWNED waits once: zero changes to COMPLETED and returns READY or DRAINED according to abandonment; nonzero changes to QUARANTINED and returns UNKNOWN. Further finish calls are idempotent and make no backend call. Abandon may also mark a completed or quarantined operation. Release publishes the original pointer and returns the control to EMPTY only from COMPLETED. Refused release preserves its output. Quarantine is deliberately irreversible in this API: retain storage until a separately proved external reset/quiescence mechanism or termination of this disposable guest. There is no invented cancellation acknowledgement.

## Actual CMK2 boundary and local containment

Read `assessor/kernel_smp/async.inc`: submit retains the user's READ destination while the original kernel uses its own bounce storage; a later completion copies into that destination. A WRITE copies on submission and is not a substitute for this lifetime experiment. The actual wait syscall blocks until terminal completion; it has no caller deadline. Its device-timeout error poisons the device and does not authorize buffer reuse in this adapter. The selected release path is an actual successful wait. Host fake-backend error cases investigate the conservative quarantine branch separately.

Use only the original curriculum kernel in QEMU TCG with one, two or four virtual CPUs, `-net none`, no KVM, no host disk passthrough and a fresh private 4 MiB ordinary disk image. Synthetic page 8 contains `(13*i+7) mod 256`. Preserve the original CMK2 regression workload and insert the supplied guest function. The guest submits a READ, abandons it, verifies release refuses, waits successfully, checks all 4096 bytes, releases and reuses the buffer for a second actual read. This establishes authority before reuse; it does not force the device to still be active at the abandonment instruction or measure physical late writes. No production kernel, credential, user data or host setting is involved.

## Workload, falsification and resource argument

Derive the transition table and prove the borrow can escape only after positive completion. Explain why UNKNOWN is different from a failed operation whose storage is known quiet. Count callback invocations across duplicate finish, refused admission, repeated abandonment and release. The independent finite model enumerates every nonempty trace of length at most six over Start/Abandon/Finish/Release for accepted/refused submit and successful/failed wait. Native tests additionally inspect the complete payload and output preservation. This finite alphabet abstracts away arbitrary device behavior; it is not a refinement proof of the kernel.

Reject three compiled semantic controls: abandonment changes directly to completed, wait error permits release, and abandoned successful completion is exposed as READY. The first and third also run inside actual guest user space; the second is exercised through the explicit error backend. Compile the unsolved C scaffold and require semantic assertion failure, not a missing symbol or sanitizer failure. Run GCC/Clang C17 debug, optimized and ASan+UBSan profiles, then audit the actual guest C17 freestanding objects and linked images for unresolved symbols and dynamic dependencies. O(1) control storage and O(1) core work exclude backend wait duration and the backend's 4096-byte copy; no latency bound follows.

## Deliverables, hints and assessment

Deliver D1 transition/authority proof and an example where timeout does not imply quiescence; D2 completed core plus explicit CMK2 callbacks and unchanged original provider; D3 independent trace comparison, mutation results, whole-page checks and exact guest/link logs; D4 a changed backend design with a separate reset acknowledgement, explaining which component owns the quarantine until that acknowledgement. D4 is an independent learner design assessment, not a claim this API already implements reset.

Pass requires all ownership claims to follow from the declared certificate, exact callback counts, unchanged outputs on refusal, actual READ composition and the scoped evidence above. Superficial completion passes a happy read but frees on abandonment or confuses the fake backend with a device. Competent work preserves the state machine and explains failure ownership. Independent transfer adds a properly generation-bound reset/late-completion protocol and defends it against a stale acknowledgement without copying the worked adapter. Hints: (1) draw the borrow independently of the wanted-result bit; (2) a terminal status and memory quiescence are separate propositions; (3) retain ticket and storage on unknown outcomes, and do not give a second wait the authority of a reset. Separate assessor analysis and implementation remain private. Author execution is bounded evidence; human-independent assessment, learner mastery and physical observations are not inferred.

# Bounded operation rollback and savepoints

This required support supplies exact obligations `AX-PR-T47-04-T47.04.b` and its
delayed variant, plus ordinary `AX-PR-T47-06-T47.06.a/.b/.c` and `.b-DELAYED`.
Other T47.04/05/06 variants remain separate: this is not path-local refresh,
changed node capacity, versioned page references, concurrent snapshot readers
or a shared multi-handle cache. Prerequisites are the learner's actual
`PR-T47-01..06` mechanisms and, for publication/refusal integration, `PR-T47-07/09`.
The original store and its transaction-wide abort policy remain unchanged.

## Original mechanism and an explicit verification port

Use C17 on the hosted teaching profile. `store` owns fixed typed node scratch,
four clean cache pages and metadata; its IO callbacks/context are borrowed.
`store_begin` loads live nodes, records prior root/allocation state and admits one
externally serialized caller including readers. Active put/delete operate on
private nodes. Input rejection preserves prior staged work; allocation exhaustion
aborts the entire original transaction. Commit and recovery are separate IO
protocols with possible indeterminate outcomes.

The assessor campaign generates a copy of the exact source-hashed retained store
in its build directory. It inserts only the declared `fault_port.h` hooks:
`st_page_admit` immediately before allocating an available node, and observation
`st_refresh_visit` at each actual full separator-refresh visit. Generated bytes,
recipe and original source are archived and checked. The original source is not
edited. This is an explicit verification adapter, not evidence that the old
public API already exposed allocation injection. Learner implementations supply
the same admission/observation port at their equivalent mechanism boundaries;
the recipe intentionally only accepts the known assessor source shape/hash.
The port is synchronous, nonreentrant and acquires no external resources.
Its counters are host verification tools, not target runtime dependencies.

The concrete three-allocation case starts with committed keys0..34, one-octet
values equal to keys. Begin, replace key0 with99, then insert35. With the actual
seven-key engine, this overflows a leaf, then an internal node, then allocates a
new root. Inject refusal at allocations1,2,3 independently. The original engine
must return FULL, end the transaction and recover committed key0=0. A replacement
of an existing key consumes no page allocation. Also fill the real node pool
until natural exhaustion; do not substitute only a simulated admission failure.

## Changed contract: operation rollback

`struct st_txn` is a stable-address, noncopied borrowed facade over one valid inactive
`store`. `st_init` initializes fresh/unowned wrapper storage, checking the actual
store invariant before publishing the wrapper. The check may populate clean cache
and instrumentation; only wrapper output preservation is promised on failure.
Engine, IO context and backing image remain live outside the wrapper. All public
controls, key/value inputs and saved-point outputs are disjoint live objects.
No escaped pointers into engine scratch are permitted. While bound, raw engine
mutation/begin/abort/commit bypasses the facade contract; ISO C cannot prevent it.

`st_put/delete` require an active, unpoisoned engine. Copy the complete typed
workspace before calling the actual operation. If it refuses, restore that copy
and return the original error, leaving the transaction active and its previous
staged work intact. For a successful operation, keep the actual resulting state.
The undo set includes root, allocation bitmap, every private node, original
transaction bookkeeping, cache/flags/counters and the unchanged borrowed IO
descriptor. Copying the whole workspace is deliberately bounded and simple;
derive which subsets a more compact undo log would need before claiming one.

This is legal only because the admitted active mutation has no backend IO,
external allocation or escaping owner. The verification hook may record an
attempt/refusal externally; those observation counters are not rolled back.
Restoring native memory cannot undo writes, callbacks or consumed external
resources in a different dependency profile. Measure this premise directly by
snapshotting all image bytes and IO callback counts around active updates.
After a separate successful commit, keep both physical representations present:
logical leaf1 has generation1 at home page3 and generation2 at redo page35. The
actual current handle must read generation2 through WAL and return the changed
value, while the older home bytes remain until checkpoint. This distinguishes
numeric logical identity from the authoritative generation and physical view.

## One savepoint with finite identity

`st_savepoint` admits one active savepoint, copies the complete current engine
workspace into `struct st_txn.undo`, increments its nonwrapping serial, and returns
`{owner address, serial}`. An existing saved point or inactive/poisoned transaction
returns STATE with output unchanged. At `UINT64_MAX`, a new point returns FULL;
the final identity may be issued once. The wrapper must not be copied, relocated,
reinitialized while tokens survive, or accessed after lifetime ends.

Rollback and release require the exact live owner and current serial. Rollback
restores the saved active workspace and consumes the point. Release consumes it
without changing staged work. Reusing a consumed/old point returns STATE. Neither
cleanup operation increments the serial, so the final point remains releasable.
A new transaction may begin after cleanup even when no more savepoints can be
issued. Nested savepoints are not silently simulated.

`st_begin` delegates to actual begin and rejects nesting. `st_abort` delegates to
actual abort and discards a current point. `st_commit` delegates to actual commit
and invalidates any savepoint on **every admitted commit outcome**, including IO
and INDETERMINATE. It never restores native undo over a potentially durable
commit. Poisoned handles reject further facade operations; end the facade's
borrow/lifetime and reopen through the original recovery protocol. No destructor
has an external resource to release: undo contains inline values and borrowed IO
identity, not a second independently owned file handle.

In the selected local RAM IO model, inject the first commit write failure and
the final commit-flush failure. The first reopens the old map; the final case has
the new bytes visible and reopens the new map. Savepoints cannot override either
result. These are precise model outcomes, not proof of a physical drive's flush
behavior or every possible failed-flush persistence outcome.

identity finite and cleanup independent of new identity allocation; discard undo
authority once a commit has begun. Keep separate assessor analysis private.

## Verification and limitations

Eight anchors exercise original abort, operation rollback, savepoints, lifecycle,
no-steal, natural capacity, workspace cost and uncertain commit. Four compiled
controls omit operation restore, ignore token serial, retain a savepoint after
commit, or leak a dirty leaf write. They must compile and fail named assertions;
build/setup failures and sanitizer reports are not semantic rejection. Learner
stubs compile but fail every anchor. The independent Python map/savepoint model
enumerates729 three-operation histories and2187 transitions over nine operations;
all allocation cuts, token extrema and physical-effect refusals are separate
anchors, not inferred from that small model.

Operation rollback costs O(sizeof(store)) copy plus the original operation. One
saved point permanently reserves one additional store workspace; an operation
also has a temporary store copy on the stack. Report both and native padding
separately from the4096-byte format. The observation port verifies that replacing
one key still refreshes every allocated tree node in the original implementation;
this packet does not claim path-local repair. No heap allocator implements undo.
Local synthetic RAM images and original compiled controls are the entire scope;
no device, production data or host security setting is changed. Current evidence
is `research/v5/expansion/legacy_storage_followthrough/transactions_validation.json`.
Finite author runs do not establish delayed learner mastery, human independence,
arbitrary concurrency, strict freestanding suitability or physical durability.
Exact published C17 remains an access gap; the active compile mode is C17.

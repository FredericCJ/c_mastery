## Problem and concrete inputs

Implement `queues.c`, the guest task/scheduler in `queues_guest.c`, and a suitable BSP entry in `queues_frames.S`. Inputs: 1–4 logical CPU indices, capacity1–4 per queue, 16 task slots, generation-bearing handles, explicit actor/home IDs, and either per-queue or coarse locking. Invalid arguments refuse without changing caller output. The initial unit fixture has capacity2, task0 on CPU0 and tasks1/2 on CPU1. A transfer into full CPU1 must leave task0 dispatchable on CPU0. Dispatching task1 does not yet free its reserved return position; exiting it does. Begin, abort, duplicate completion, commit, block/wake, duplicate wake, stale generation and terminal revision cases are supplied in `tests.c`.

The guest creates two stable 8192-byte task stacks per observed CPU. Each task performs seven checked actions: its third action blocks and its seventh exits. When every task is blocked, all CPUs observe an empty queue. CPU0 wakes the tasks and, when another CPU exists, transfers task0's saved context to CPU1. The final invariant requires every task EXITED and every queue/current/reservation empty. Expected total actual switches are `28 * CPU_count`; task0 must have executed on both CPUs0/1 for the multi-CPU case. Four-CPU topology has APIC IDs0,1,2,4: dense array indices are not APIC identities.

## Why this exercise is necessary

A task is not safely transferable merely because a field says READY. Its old CPU may still be using the stack. Equally, a full destination cannot justify removing the source entry first; a later rollback needs reserved space. The retained early CMK cooperative scheduler selects a CPU's two-task subset under a coarse lock. Its later ring-3 scheduler scans a global thread array with affinity. Neither is evidence that this explicit bounded per-CPU queue has been implemented. Changing lock granularity does not turn per-CPU queues into a global run queue.

## Representation, invariants and ownership

READY has exactly one queue entry and no executing owner. RUNNING has exactly one CPU `current`, no queue entry, and one reserved return position on that CPU. BLOCKED/EXITED/EMPTY have neither. TRANSFER has no runnable entry or executing owner; it reserves one source rollback position and one destination commit position. For every queue, `count + reserved <= capacity`. Generations are immutable while workers operate. Initialization creates an externally distinct world lifetime; the caller must invalidate every old handle, ticket and context pointer, even a currently unused handle. It is not a same-world reset: `sq_init` resets generation fields and cannot distinguish surviving old values. Slot creation/reuse instead preserves and increments generation history. Both initialization and creation/reuse require whole-world quiescence, no outstanding tickets or live task context; they are not concurrent APIs. Handle generation exhaustion refuses reuse permanently unless a new, externally distinct world lifetime is established.

One caller owns each actor CPU. Queue operations are excluded from interrupt handlers and may not recursively acquire these locks. Task/queue/control storage stays stable. Handles, tickets, events and stats are nonaliasing live caller objects. `sq_finish` is called by the owner scheduler only after the actual task stack has been saved and execution has returned to the scheduler. A request field written by a task is not state publication. A transfer ticket belongs to its initiating actor until commit/abort; no third party may destroy or force-clear it. Slot revisions reserve the completion increment before dispatch or transfer admission; those completions remain possible at the finite limit. Rejected admission is not permission to recycle a live terminal-revision task.

Per-queue mode acquires both transfer locks in increasing CPU index, releases in reverse, and validates before removing the entry. Coarse mode uses the same representation/invariants under one lock. State/home are atomic because a wrong-home caller may inspect them under another queue's lock. Revision and transfer fields may only be read after validating the home under its queue lock; migration holds both old and new queue locks. Explain the acquire/release chain for saved stack-pointer publication. `sq_invariant` is a whole-world-quiescent diagnostic, not a safe concurrent scan.

## Operations, failures and resource costs

Dispatch rejects an occupied current slot; an empty queue returns IDLE without touching outputs. It reserves the returning task's capacity until finish chooses READY, BLOCKED or EXITED. A blocked task's wake returns FULL if no slot exists; a READY wake is DUPLICATE and does not enqueue again. Wrong generation/home returns STALE. Begin-transfer verifies READY, source membership, destination capacity and revision reserve. Commit/abort validates the exact ticket revision, actor, generation and endpoints before releasing both reservations and publishing one READY entry. Errors preserve caller outputs and previously admitted ownership. There is no allocation failure or partial I/O in this fixed-storage core; introducing either requires a new contract, not a decorative failure case.

With maximum capacity `K`, FIFO head removal/search cost O(K), with O(1) state and at most two lock acquisitions otherwise. World storage is O(C*K+T), events O(recorded transitions), and each guest stack is8192 bytes. The supplied TAS lock may spin without a fairness or bounded-latency guarantee. Queue-lock wait time and scheduler work are separate from task execution; do not call algorithm counters cache-miss or bus-transaction measurements.

## Verification and acceptance

Require unit/refusal tests and snapshot differential equality, successful intended native executions without sanitizer diagnostics, and real guest exit33 with checked task/stack/owner state. A compilation failure, crash, timeout or unrelated marker is not a killed semantic mutant. Purpose-built controls allow duplicate enqueue, remove-before-capacity-check, stale generation or duplicate dispatch; each must fail a stated invariant. The target control publishes READY before saving the context; it is detected before executing an unsafely exposed stack, with a specific harmless diagnostic and guest exit35. Default learner stubs must compile and fail the intended contract checks.

Every full trace contains actor-local sequence numbers and task generation/revision edges. Check both edge sets for cycles; require each task's complete revision sequence, legal state transitions, owner CPU, final EXITED state and seven dispatches. Printed serial order and cross-CPU TSC values are not a total execution order. Full trace consistency is evidence about recorded transitions, not proof that instrumentation cannot omit an event. The independent model checks queue snapshots/FIFO separately; the trace checker does not reconstruct every possible interleaving of different tasks.

Measure each CPU's active task interval around the two actual context switches, polling-idle ticks and total interval with local virtual TSC readings. Active time includes switch-boundary costs; remainder includes scheduler/coordination. Require active+reported idle <= total and exact switch counts. Do not interpret these virtual observations as physical utilization, fairness, WCET, calibrated nanoseconds or IRQ latency. This polling guest does not establish correct idle wakeup notification; T53.07 owns that mechanism.

## Security containment and evidence status

The attacker model is an invalid/stale teaching API caller, not arbitrary kernel memory write; memory safety still requires valid live pointers and actor ownership.

# Messaging laboratory contract

This is an original hosted C17 laboratory. `messaging.h` is the public representation and operation contract. POSIX threads, mutexes and condition variables are backend dependencies; Python, CMake and sanitizers are host verification tools. No ready-made channel, actor, STM or scheduler implementation is permitted. Use actual initialized objects, correctly sized output arrays and live callbacks; uninitialized storage, arbitrary forged pointers and unsynchronized writes to public fields are outside admitted calls. No library call or runtime secretly enforces the discipline merely because a type has a descriptive name.

All structures are caller-owned and have stable addresses while registered or used concurrently. Do not copy a mutex, atomic-containing active object, nursery, snapshot store or live operation state. Copying an unsigned message is allowed. User callbacks must return normally: no `longjmp`, thread cancellation, process exit or hidden destruction of borrowed state. Every destroy requires quiescence. Handle rare POSIX failures explicitly in production adapters; this original harness treats initialized mutex/condition operations under their valid-use preconditions as successful and tests thread creation failure separately. A real backend error is not permission to free an unjoined task's context.

## Nursery

One parent thread owns spawn/join and the eight child slots. `MsgTask` receives a borrowed context and an atomic cancellation flag. A child returns an integer result; nonzero requests cancellation of siblings. Cancellation is cooperative and does not bound join time for an uncooperative child. Spawn fails without admitting a child if full, invalid, exhausted, explicitly injected at its one-based attempt or rejected by pthread_create. Creation failure requests cancellation of existing children. Join closes admission and joins every admitted child before reporting the first nonzero result in creation order; retry after a join error retains storage. Initialization is only legal after prior quiescence. Parent and child contexts outlive join. No detached children.

## Channel hub

Two channels share one mutex and one condition variable so selection and readiness registration have one atomic exclusion boundary. Each channel has capacity0..4. A positive capacity stores unsigned values by copy in FIFO order. Nonblocking send reports FULL with no effect when full. Blocking send loops on the predicate. Capacity zero implements a rendezvous: nonblocking send reports FULL; a blocking sender publishes one offer and returns OK only after a receiver acknowledges that ticket. Close aborts an unaccepted offer; already accepted delivery remains OK. Tickets retire at UINT64_MAX. Buffers drain after close, then selection returns CLOSED when all selected channels are closed and empty. A zero or out-of-range mask is invalid; bit0/1 selects channel0/1. Successful selection uses deterministic alternating preference among ready channels, not Go's random policy. Outputs change only on OK.

Hub cancellation is terminal, wakes all waiters and takes precedence over further receives; values still buffered are dropped logically at destruction after all users join. A rendezvous already acknowledged succeeds even if cancellation arrives before the sender resumes. Spurious wakeups are normal. Close and cancellation require neither allocation nor an external signal. Do not use pthread_cancel on blocked operations. Fair scheduling and eventual mutex acquisition are assumptions, not guarantees. Quiescent destruction requires no waiters, no producer and no consumer. Locking is O(1) local work with unbounded scheduling/wait latency; queue storage is bounded. Changing payloads to owned handles requires explicit failed-send and discarded-buffer ownership rules.

## Operation states and actors

`MsgOperation` is serialized and transitions NEW → STARTED → DONE. Connect borrows receiver/context; start validates receiver and occurs once. Stop requests cancellation but leaves STARTED. Complete accepts only OK/FAILED/CANCELLED, transitions to DONE before exactly one receiver call, then never accesses the operation again. The receiver may reclaim the operation on that completion; repeated completion tests must therefore use a still-live state. A cancelled request may still complete with a value. Real asynchronous adapters retain the state until terminal completion and synchronize competing completions.

`MsgActor` is a serialized single-executor runtime with a four-message copy mailbox, generation identity and a handler. Enqueue validates incarnation before capacity. One step removes one message and runs its handler to completion; recursive step returns BUSY. Failure makes the actor dead and discards queued unsigned messages; it cannot undo external effects already performed by the handler. Restart requires dead/quiescent state, increments generation without wrap and clears the mailbox. Old incarnation messages are STALE. Mailbox storage and actor metadata remain caller-owned; a concurrent producer adapter must add synchronization.

## Supervisor

Four child positions have creation order0..3. A restart plan reports negative one-based positions to stop in reverse order, then positive positions to start forward. ONE affects the failed child, ALL every child, REST the failed child and later siblings. Caller supplies eight action slots. Times are monotonic uint64 ticks; reject backwards time before changing state. Keep at most four failure times strictly inside the sliding window (`now-old < window`). If an additional failure would exceed the configured1..4 restart limit, stop all children and permanently escalate. No implicit actor restart or native thread termination occurs: execute each stop to quiescence before applying the next phase. Callback failure during restart requires escalation/rollback in the consumer adapter.

## Work stealing and transactions

The bounded Chase–Lev-style deque has one owner for push/pop and multiple thieves. Eight slots hold atomic unsigned values; all metadata and payload accesses are sequentially consistent in this baseline. Pop is LIFO, steal FIFO. The final item is contested through a top CAS. A losing operation returns CONFLICT without changing output. No resize or pointer reclamation is hidden. Indices begin at1; empty-pop subtraction is restored; push retires at SIZE_MAX-1 before either index wraps. Quiescent reinitialization is the only reset. Full reports no mutation. The SC total-order argument does not establish the paper's weaker-order algorithm or make arbitrary non-atomic payloads safe. Lock-free progress depends on the implementation's atomics, finite capacity and scheduling; report actual `atomic_is_lock_free` observations.

The original TL2-style store has four atomic unsigned values with per-cell version/lock words and one global version clock. A transaction is private to its thread and buffers a four-bit read/write set. Begin records a snapshot clock. Read checks its own write set first; otherwise it validates the atomic cell stamp before/after loading and rejects a lock or a version newer than its snapshot. Every admitted read is validated before user computation; abort means no writes are published. Commit acquires write locks in index order without waiting, reserves a nonwrapping timestamp, validates its reads against its snapshot (using saved versions for locks it owns), publishes all values, then releases all locks with the new version. Failed commit restores acquired lock versions; timestamp gaps are allowed. Maximum timestamp is UINT_MAX/2. All shared accesses are SC. Abort forbids external irreversible side effects from speculative code. This fixed-object model does not implement arbitrary malloc/free, privatization, nesting, durable transactions or fairness. A read-only transaction is also validated at commit here; that is a deliberate conservative difference from the paper's optimized read-only path.

## Versioned snapshots and sequence validation

`MsgVersions` stores eight complete two-unsigned versions and four reader pins under one mutex. The first version is[0,0] at timestamp0. Snapshot captures current time in a generation-tagged pin. Read selects the newest stored version at or before that pin. Publish writes both fields as one new version. Collection retains current version and the visible version of every active pin; all other versions can be reused. There are at most five distinct retained versions under this contract, so eight slots suffice for the next publication. A fifth pin fails FULL; a pin with an exhausted generation is retired. Dropping an old handle cannot drop a reused slot. Publish retires at UINT64_MAX. Copying whole snapshots under a mutex is intentionally simpler than a lock-free database; it does not establish serializable multi-object transactions, predicate consistency or durable recovery.

`MsgSequence` admits one externally serialized writer and any readers. Both payload words and sequence are atomic and SC. A writer makes sequence odd, stores both words, then makes it even; at UINT_MAX-1 it reports OVERFLOW without change. A reader makes at most the requested attempts and publishes outputs only after seeing the same even sequence around payload reads. A zero budget returns BUSY. The SC order gives a simple coherence proof; an ordinary racy payload copy remains undefined even if a later validation discards it. Multiple writers, pointer payload lifetime, weakening orders and wraparound each require new arguments. No starvation or real-time deadline guarantee follows from a finite retry budget.

## Demand stream

The stream is serialized on one executor. Request adds unsigned demand, saturating to UINT64_MAX as the explicit unbounded sentinel. Request0 signals a terminal INVALID error. If called inside next, queue that error until the current callback returns so signals do not overlap; further requests are CLOSED. Cancellation inside that same callback suppresses the queued notification and remains terminal for delivery. Emit requires positive demand, decrements finite demand before calling next and forbids recursive emission. A next callback may request more without synchronous recursive delivery or cancel; caller retains stream storage through callback return. Cancellation prevents future delivery but is not a cross-thread quiescence mechanism. End accepts OK/FAILED/INVALID, signals once, and prevents later delivery. Terminal callbacks and request/emit/cancel all run under the caller's serialized protocol. This subset compares selected Reactive Streams rules; it is not a JVM interface or certification. Adaptation to multiple threads requires serialized signal delivery and retained callback lifetime.

## Composition and evidence

Use the existing `work.pool`, `sync.condition_queue`, `sync.spsc`, `io.async`, `io.deadline`, `testing.faults` and `coro.frame` learner artifacts through explicit adapters. In a coroutine-channel adapter, arm captures a generation and retains the frame; disarm returns only when all notifications for that generation are quiescent. Channel cancellation never implies that event. The original public anchors test the standalone mechanisms; an adapter is not claimed executed merely because an artifact appears in metadata.

All demonstrations are local original programs with synthetic unsigned values. No privileged target, third-party service or real data. Race diagnostics, lost messages and violated counters are distinct observations; none establishes arbitrary code execution. Independently assess each exercise's changed assumptions and all thirteen dimensions in the modern cost contract. TSan is a separate campaign from ASan/UBSan and neither is a memory-model proof.

# HTTP depth contracts, revision 1

Use ISO C17 with eight-bit octets, ASCII execution characters, exact uint32_t and valid nonoverlapping caller objects. Core operations use only arithmetic, arrays and type/limit headers; no allocator, socket, string parser, time library or calendar library implements them. Host verifiers and imported baseline integration tests are distinct. Calls are serialized. Pointers refer to live, correctly aligned objects of the declared type and sufficient extent; C cannot validate that premise. All rejection leaves output arguments unchanged. Pool controls must be zero initialized once, then mutated only through their operations; generation-exhaustion tests may seed a valid near-exhaustion state before use. No reinitialization while stale tokens might exist.

## length

`hd_length` consumes an explicitly sized, nonempty, already OWS-trimmed field value. Every octet must be an ASCII decimal digit. Leading zeros are legal and input has no required NUL. The numeric ceiling is **4294967295**, independent of `size_t` or pointer width. Overflow or syntax failure is400. Only after complete syntax/range validation apply caller cap0..1024: excess is413. Otherwise publish the exact uint32 value and return0. Invalid pointers/cap are400 under this API. Thus `1025x` is400, `4294967295` is413 for cap1024, and `4294967296` is400. Rejecting at the first prefix above the resource cap would misclassify later syntax/overflow. Work O(n), constant storage. Input/output must not overlap.

The retained HTTP field parser uses SIZE_MAX and has an observed64-bit discrepancy. The source-bound integration procedure compiles an adapted COPY in build, replacing only the checked CL field branch by this operation. It maps valid-over-cap to a1025 sentinel, because later header finalization first rejects TE+CL and then rejects excess body size. That sentinel is never an accepted body size. All original accepted files and receipts remain unchanged. Learner integration must document this information-loss proof and supply its own accepted parser revision; the assessor adapter is not a learner dependency.

## date

`hd_date` receives availability0/1, Gregorian days since1970-01-01 and ordinary seconds within the day. With availability0 it returns0 and writes length0, leaving output untouched regardless of its capacity or time values. With availability1 require days0..2932896 inclusive, seconds0..86399, capacity>=30 and live output/length. Produce29 ASCII IMF-fixdate octets plus a NUL, length29. Other values reject HD_INVALID unchanged. Epoch0 is Thursday; leap years are divisible by4 except centuries not divisible by400. Last admitted date is9999-12-31. This explicit input model has no leap seconds; RFC9110 permits a leap second in the wire grammar, so the exercise is an ordinary-time sender subset, not a full timestamp receiver. UTC accuracy belongs to the clock supplier. Unavailable clock means omit Date; fabricating an epoch or old fixture instant is not a repair. Wall-time changes never reset monotonic request deadlines. Show bounded year/month iteration cost, then derive a400-year-cycle alternative as transfer. The serializer integration demonstrates available-clock injection; unavailable-clock omission requires a serializer path explicitly supporting absence.

## lifecycle

Four slots own admitted descriptors and finite (index,generation) identities. Admit requires fd>=0, flags_ready exactly1 (adapter actually checked nonblocking and close-on-exec), no duplicate live fd, a free unretired slot and a live handle output. Choose lowest eligible index, increment its generation without wrap, publish fd/interestREAD and handle. Failure retains caller descriptor ownership and all state/output. HD_FULL means no eligible slot. The caller closes a failed accepted descriptor exactly once; the core never calls close.

`hd_interest` accepts mask0..3: READ1, WRITE2. `hd_event` accepts ready0..15: READ1, WRITE2, HUP4, ERROR8. It requires matching live index/generation **and fd**. On success dispatch `ready & (interest | HUP | ERROR)`. A readable+HUP event can therefore require reading buffered bytes before observing EOF; a dispatch mask is not an I/O result. Writable dispatch is disabled when no output remains. `hd_close` returns the owned fd once, clears live/interest, and retires at generation UINT32_MAX. A stale close/event cannot affect a new connection reusing the same integer fd. The adapter must close the returned fd before admitting its reuse and prevent outstanding I/O callbacks from retaining the released record; generation alone does not revoke raw pointers. Null controls/output or invalid mask/fd reject INVALID; an otherwise malformed/nonlive handle or fd mismatch is STALE. Slots at max generation cannot be admitted. O(4) admit, O(1) other operations, fixed storage.

## Evidence and containment

Only original local C programs, local socketpairs and synthetic values/events are used. Attacker capability is control of original teaching input values and queued-event ordering within live storage. Harmless success is a wrong local framing status or dispatch to the wrong synthetic incarnation; no external endpoint, deployed service or other data is used. A parser disagreement alone is not demonstrated request smuggling; that requires an actual two-interpreter composition and extra framing premises. No arbitrary-code-execution claim follows from a crash. Diagnose each compiled mutation, repair it and retain a regression, including caller-lifetime and clock-trust limits.

Six host profiles, independent Python arithmetic/calendar/state oracles, compiled mutants and failing learner stubs are separate from the freestanding Cortex-M4 compile/link audit. No target execution, board capture, independent human assessment or absolute mastery is claimed. The complete legacy server and delayed assessment obligations remain required.

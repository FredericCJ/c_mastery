# Allocation policy, upstream resize and hidden diagnostic work

Required X-T66-009/R1-R4 and X-T66-009-DELAYED support. Implement the public `allocator_audit.h` in the two unfinished sources. The baseline is ISO C17, GCC and Clang, debug/optimized/ASan+UBSan. This single-owner module requires external serialization, genuine typed storage and callbacks that return normally. It makes no thread-safety, ISR, freestanding or operating-system allocation-failure guarantee.

## Representation, contracts and operations

Initialize `struct oaa_audit` only in fresh nonowning storage. It borrows stable upstream callbacks/context, owns eight tracking slots, and returns ordinary V4Allocator callbacks. All admitted extents are1..16 int32 elements. Each successful upstream allocation is disjoint from other live allocations and suitable for actual int32 objects; each release is infallible under its valid-pointer premise. Upstream callbacks cannot reenter the same audit. A successful resize may return the same numerical address or another one; it preserves min(old,new) values and ends the old allocation/borrow. Failure returns NULL and preserves the old owner and contents. The wrapper does not read or compare the old pointer after successful upstream resize.

Every admitted take/resize attempt consumes one1-based injection index, including invalid sizes, full capacity and upstream failure. Refuse at exactly fail_at. Attempts at SIZE_MAX refuse without wrapping and set a sticky flag. Other instrumentation counters saturate and set the flag; they do not prevent necessary release. Live blocks never exceed8; live cells never exceed128. Peak cells is the wrapper's logical simultaneous live-cell maximum, distinct from the upstream's temporary overlap during copy-resize. Success, resize-success, caller-release, upstream-call and upstream-attempt counters measure different events. Release operations do not consume the injection index.

Take finds a free tracking slot, then calls upstream. Only after success does it publish the slot and initialize its requested prefix to INT32_MAX. Resize locates the exact currently live base and validates a nonzero size before invoking upstream. Same-size resize still consumes an attempt and can be injected to fail; otherwise it returns the same owner without an upstream call or a success counter increment. On growth initialize the new suffix to INT32_MAX; shrink preserves the shorter prefix. Update size/counters/output only after upstream success. A failed operation may change attempt/failure instrumentation and diagnostic effects, but never silently transfers the old allocation.

Release fills the requested live prefix with INT32_MIN, detaches the tracking slot, updates bounded ownership and calls the matching upstream release once. Invalid/duplicate releases increment a diagnostic counter. This is not a dangling-pointer validator: test such diagnostics only with NULL or pointers to actual still-live backing objects, such as the baseline typed arrays. Do not evaluate indeterminate pointers after real deallocation. Poison observations of the underlying still-live arrays are assessor diagnostics, not permission for a client to use a released handle. Poisoning and numerical address equality cannot enforce lifetime safety.

## Reentrant diagnostic boundary and actual formatting

An optional failure reporter runs only after the wrapper has reached a consistent failed-operation state and is no longer inside an upstream callback. It may call the same wrapper's take/resize/release on new or independently owned allocations; these are counted normally and increase `nested_attempts`. It must not mutate or release the failed resize's old owner, nor any object borrowed by the invoking call. While reporting, further failures do not invoke another reporter. This prevents an endless failure-report-allocation cycle without hiding the nested attempts. Changing the reporter while it is active returns BUSY. Reporter/context and all referenced owners remain live; no nonlocal exit, destruction of the audit or concurrent entry is allowed. The reporter may have ordinary retained effects, so a failed caller operation does not imply that the complete callback graph did nothing.

The required T65 consumer calls actual `er_parse_pair`, then an optional formatter only on error. `oaa_format_result` renders a bounded nested error record from first principles: depth1..3, non-success er_code and offset0..999. Each recursive frame obtains16typed cells, forms its decimal fragment without printf/malloc, calls its child and releases on unwind. At depth3, error2/offset3 renders `E2@3[E2@3[E2@3]]`. Stage the complete output in64characters and publish text/length only after success; failure preserves the prior text while attempts/failures remain observable. Preflight the formatter call counter for its maximum recursive depth. The recursive frames have bounded stack/resource use; the callback contract does not generalize this into unrestricted recursion safety.

Concrete counterexample: parsing `12:x` without a formatter returns INVALID/offset3, preserves sum91 and makes zero allocator calls. The same parser through the allocating formatter returns that same semantic error but performs three actual allocations and releases, reaching48live cells. Fail each recursive allocation in turn and retain old text. Separately inject the outer wrapper failure, let its reporter format the error through this same allocator, and observe four total attempts, three nested attempts, one report and zero remaining live blocks. If the first nested upstream call fails, observe only two total attempts and still one report. A source scan of the parser or wrapper alone cannot justify the whole-call-graph resource claim.

Hints: (1) draw old and staged owners before touching counters; (2) write an event ledger distinguishing wrapper attempt, upstream call, successful replacement and release; (3) invoke diagnostics only after the state is consistent; (4) count nested work while suppressing nested reporting; (5) never treat poison as inaccessible memory.

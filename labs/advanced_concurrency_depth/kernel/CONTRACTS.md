## Copied input and operation contracts

`ak_copy` accepts1–32 bytes and a copy-provider callback. The provider writes only the supplied destination extent, returns the number of bytes **not** copied, and may leave its remaining destination bytes unchanged. A nonzero residual is failure even if a zero-padding wrapper happened to write zeros. The adapter stages all data before publishing an `AKPacket`, zeroes unused bytes, preserves the previous packet on any failed copy, and rejects residuals greater than the request. Invalid shape invokes no copy callback. The callback's input/address validation belongs to its environment: the native harness is a residual model; actual kernel `copy_from_user` must execute in a permitted process address-space context. A worker cannot retain a raw user pointer and assume the originating task's address space, mapping or lifetime survives.

For the delayed deferred-worker variant, copy/validate in the initiating file-operation context, then enqueue only owned kernel bytes. The original T57 module does this before scheduling its worker. The worker may acquire its mutex and allocate with `GFP_KERNEL` because it is an ordinary sleepable worker, not a BH workqueue or hard-interrupt handler. The separate original IRQ module demonstrates primary hard-interrupt versus threaded handler contexts. A raw spinlock region forbids sleeping; `spinlock_t` differs under PREEMPT_RT, so never infer its rules merely from the type's spelling. `GFP_ATOMIC` has failure semantics and is not a promise of success. This exercise's hard-interrupt path allocates nothing.

`AKService` contains the actual capacity4 `ASQueue`, one held value, a backend table, cookie and state. `ak_enqueue` returns BUSY at queue capacity. A popped value is held across map failure and submit failure; retry must not drop or duplicate it. A successful map owns exactly one mapping. `sync_device` publishes payload to the device's declared view before `submit`. A failed submit guarantees that no device access began, so unmap is allowed and the value remains held. A successful submit transfers access authority to the backend; another start is BUSY. `ak_complete` cannot expose output, synchronize for CPU, unmap or reuse while `quiesce` reports that device access remains possible. After positive completion/quiescence, synchronize for CPU, unmap exactly once and publish the held value to the caller. Output is preserved on BUSY. Initialization requires quiescent live storage; all pointers/control/output objects are distinct and callbacks cannot reenter, retain service control or violate their stated access extents.

The DMA-shaped backend is an executable **synthetic device contract**, with distinct CPU/device ownership and observable synchronization/doorbell stages. Its callbacks are where a selected real adapter must supply DMA mapping, cache maintenance, descriptor ordering, MMIO accessors, completion and stop acknowledgement. A C release store or successful queue test supplies none of those board guarantees. Coherent DMA still requires ordering. DMA barriers alone do not order MMIO. Posted-write completion and readback rules are device/interconnect contracts. Actual board execution remains a separate physical observation, not replaced by these tests.

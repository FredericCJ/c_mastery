## Environment, representation and ownership

The native component uses active ISO C17 with explicit uint32_t/unsigned bounds. It implements no allocator and imports the actual learner CMX epoch tracker and `struct api_registry`; those producers supply the mechanisms already taught. All AG metadata operations execute in one external serialization domain. The hosted two-writer adapter supplies a POSIX mutex; C atomics inside a different CMX object do not make AG's ordinary fields concurrently safe. Host tests and Python models are verification dependencies. Kernel code is a separately compiled Linux module using its pinned kernel dialect, API and configuration, not ISO freestanding C.

For the strict target dependency experiment, first link the selected AG/epoch/registry closure without a runtime provider and retain any implicit byte-helper failure. Then explicitly compose the existing first-principles byte support component defined in `labs/execution/targets/README.md` and scaffolded in `labs/execution/src/support.c`. This named prerequisite may provide compiler-emitted memset/copy and AEABI aliases; libc, libgcc, libatomic and compiler-rt remain forbidden. Inspect the exact final symbols and map. Symbol closure of the component does not audit arbitrary client callbacks or authorize interrupt use.

`struct ag_domain` has four registered participants with nonwrapping registration identities, read-section identities, depths and the retained `cmx_epoch` state. Initial epoch is0. Enter at depth0 announces the current epoch and advances the section identity. In the baseline profile a nested enter is INVALID; the delayed profile admits nesting until unsigned saturation. Only the outermost leave clears participation. Depart requires depth0, invalidates the registration identity and eventually retires saturated registrations. A section identity that cannot advance returns EXHAUSTED. Old tokens never authorize a new registration's access.

Advance uses the retained policy: an active participant must have announced the current epoch; otherwise advance returns PENDING. At the maximum epoch it returns EXHAUSTED without wrapping. A retired stamp is eligible only if it is not in the future and no active announcement is at or before that stamp. This predicate is one lifetime obligation, not a complete allocation authority. A published object must first be removed, old readers must drain, retained callback references must reach zero, and the allocator must exclusively own reuse. No barrier or checksum substitutes for those conditions.

`struct ag_store` contains17 typed version slots, each with32 immutable payload bytes, a nonwrapping generation, retirement epoch and explicit retained-reference count. There is one current root; published values are repeated byte values0–255. A writer lease excludes a second writer in the serialized state machine. Publishing requires that lease, finds an unused nonsaturated slot, initializes all32 bytes, publishes the new root and marks the former root retired at the current epoch. It then attempts epoch advance; an old reader can prevent advancement while later updates still retire at that same epoch. FULL preserves the old root and all ownership. At terminal epoch, publication returns EXHAUSTED. Writer exclusion is ordinary state, so callers must still supply the external serialization domain.

Read enters a section and returns a generation-bearing `struct ag_borrow`; copying its bits creates no additional enter/leave obligation. A valid borrow permits copying32 bytes while its registration and outermost section remain live. Ending the outermost section invalidates its borrows. Nested borrows share that outer section's lifetime. Outputs are separate live objects; rejected copies preserve them. A dangling store pointer cannot be validated. Initialization and boundary injection require fresh or fully quiescent storage; no callback, writer, read token or retained reference may survive reinitialization.

`ag_capture` registers a callback through the actual four-slot `struct api_registry`. Before leaving the read section, it obtains one reference to that exact version for each successful registration. A failed add rolls back the reference and leaves the output handle/caller ownership unchanged. The registry owns that capture until its drop hook; an invocation is protected by this reference even after read-side quiescence. Pending removal keeps the captured version alive through its already-snapshotted invocation. Destruction inside a callback suppresses later callbacks and releases captures after the active callback returns. Registry drop releases the version reference; only a later eligible collection may reuse its slot. Callbacks return normally, preserve immutable bytes, do not free store/registry control storage and obey the registry's reentry restrictions. Refcounts and generation fields are checked runtime metadata, not language-enforced ownership types.

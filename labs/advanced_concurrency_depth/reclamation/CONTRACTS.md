## Environment and limits

Use the active C17 baseline, 32-bit unsigned integers, exact-width uint32_t and C atomics. N1570 supplies inspected C11 draft passages; it is not final C17 or C23. The core has no allocator, OS call, thread creation, library container or hidden permitted runtime provider. POSIX threads, condition variables, history enumeration, Python and sanitizers are host verification tools. Separate compiler/CPU object and strict final-link audits determine whether the selected implementation uses atomic or other helpers; do not infer lock freedom from the atomic type spelling. No core API is authorized for an interrupt merely because one target link closes.

The Michael–Scott pseudocode's allocator assumption is not ordinary free. The inspected hazard-pointer paper describes an asynchronous shared-memory algorithm; its publication and reclamation proof must be mapped to this C representation. This exercise uses permanent typed storage and integer indices, no dangling native pointers. A safety failure in an integer lifetime model is not an executable use-after-free exploit.

## Representation, ownership and operations

`struct ap_queue` contains 32 typed nodes, one dummy node, atomic Head/Tail and next indices, two hazard slots for each of at most eight participants, and a bounded registration table. A payload has two ordinary words: sequence and its complement. Node state includes a nonwrapping incarnation and FREE/LIVE/RETIRED state. Initialization admits participant counts 1–8 and generation limits 1–UINT_MAX/4. A maximum-generation retired node remains retired permanently. The generation bound limits total successful incarnations, not just currently queued elements.

The owner initializes a live, disjoint queue before publication and keeps it at a stable address until every operation/collector and hook has finished. Initialization and direct fixture inspection are quiescent. `ap_register` claims an exclusive generation-bearing lease. One execution agent owns each lease; copying its bits does not authorize concurrent use. A lease remains exclusive across its complete call. Register scans may return FULL conservatively under contention. Null required controls/outputs and invalid leases return INVALID without publishing a value; other invalid object lifetimes cannot be checked in ISO C. `ap_collect` requires a live initialized queue. Nonempty outputs are separate live objects and never alias the queue.

`ap_push` claims a FREE slot by compare-and-exchange, initializes its payload and next link, then protects/validates Tail before linking. A successful link publishes the item; Tail advancement is helpable. A failed bounded allocation scan returns FULL, preserving the abstract queue. This is neither an exact concurrent pool-full snapshot nor a logical queue-capacity observation. Do not report FULL as a successful enqueue. `ap_pop` protects/validates Head and its successor, rereads Head before payload access, helps a lagging Tail, and advances Head. It returns OK plus a copied value, or RETRY for the empty observation, preserving the output. A successful removal retires the old dummy; retirement is not reuse permission.

`ap_collect` scans retired slots and both hazards of each admitted participant. Only an unprotected retirement may become FREE. Its final compare-and-exchange includes the complete retirement generation; a collector paused across reuse must not free a later incarnation. Successful claims order the next private payload writer after the previous lifetime. No node can be reclaimed while continuous protection of that incarnation remains valid.

`ap_leave` is called by the quiescent owner, or a successor with external proof that the owner has terminated and cannot resume. It clears hazards then advances the registration generation. A stale lease must not clear the replacement owner's hazards. Registration saturation retires the participant slot. A timeout, canceled flag, stopped polling or a temporarily paused thread is not proof of termination. Asynchronous cancellation within an operation is outside this contract. The dedicated departure fixture joins the actual thread before transferring cleanup authority.

Hooks are test instrumentation at load, validation, link and retirement snapshot. They must return normally, neither mutate queue state nor retain storage, and cannot reenter queue operations, cancel a thread or jump out. Host fixtures deliberately block in a hook to expose partial progress. Progress claims for the target algorithm require no hook or a separately bounded hook; the POSIX gate itself is not lock-free.

## Reservation cancellation is a separate contract

`struct ar_queue` is a four-cell FIFO ordered by reservation ticket. Tickets monotonically advance and stop at AR_LIMIT; no wrap is permitted. The atomic cell state includes the ticket identity. States distinguish not-yet-initialized reservation, RESERVED, CANCEL_REQUESTED, PUBLISHED, CANCELLED and CONSUMING. Each successful reserve transfers exactly one completion obligation to one producer. Multiple producers and consumers may call the API, but only that producer calls `ar_finish` once. The control plane may call `ar_cancel` concurrently; it receives OK only for a recorded request, TOO_LATE after publication/acknowledgement, INVALID for a stale or unrelated ticket. No output ticket is published on FULL/EXHAUSTED.

The producer writes its private payload, then either publishes it or acknowledges cancellation after its last possible write. A request alone never permits reuse. A consumer reports PENDING while the FIFO head remains unfinished, even if a later producer has published; EMPTY means no reservation exists. After acknowledgement it returns CANCELLED while leaving the value output unchanged and advances past the tombstone. For PUBLISHED it claims CONSUMING, copies the payload, frees the cell and only then advances Tail. A paused consumer in CONSUMING can also stall the prefix. This design deliberately does not claim lock-free service or successful progress when a reservation owner stops. Forced reclamation requires a different externally proved termination protocol.

2. **T26.04.b:** Execute the frozen CMX reservation producer, then implement `reservation.h`. Producer A reserves, B publishes, and the consumer meets unfinished A. ## Verification and assessment

Compile the public scaffolds first and show that they build but fail the intended semantic assertions. Required tests include every named `tests.c` case, the reservation fixture, real-history test and independent permutation oracle, finite protection models and both SPSC participant countermodels. Execute debug, optimized, AddressSanitizer/UndefinedBehaviorSanitizer and ThreadSanitizer profiles with GCC and Clang where supported; retain unsupported environments explicitly. The separate original data-race sensitivity process validates the chosen race detector, not the safety of unexecuted schedules. Disable no warning or contract to obtain a pass.

Run each intentionally flawed control independently: skipped validation, ignored hazard, untagged collector release, reused participant generation, generation wrap, cancellation request treated as acknowledgement, and pending prefix treated as empty. Identify the exact assertion and violated property. Those integer-state controls are not arbitrary-code-execution demonstrations. Require generated-code and final-link audits of both queue cores for the selected M4/M0 profiles, retaining helper-dependent failures. Never load a module on the host or flash a board for this packet.

The original rubric levels apply with these objective-specific obligations. Level 0 includes a missing state, native invalid lifetime, invented result or overclaimed progress. Level 1 reproduces a normal trace only. Level 2 supplies each leaf's concrete protocol, boundary and falsification witness with the correct ownership, C-order and resource argument. Level 3 independently transfers the original delayed condition, preserves prior regressions and explains which guarantees require external verification or programmer discipline. The queue has no language-enforced affine lease, lifetime or unique-owner type: diagnostics and tests do not enforce those properties for arbitrary callers.

Hints, in order: first separate reachability, protection and storage eligibility; next mark the one transition publishing each ordinary payload; then ask whether a delayed observer can mistake a later incarnation for the earlier one. For cancellation, identify the last possible write before choosing the acknowledgement event. For more participants, count both protected nodes and outstanding private allocations before changing memory orders. The separate assessor analysis contains solutions and variant outcomes.

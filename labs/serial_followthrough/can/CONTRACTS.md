# Classic CAN current-source and controller successor

This required additive laboratory implements all six original criterion/changed-condition pairs in PR-T38-09, retaining their identifiers, rubric, seven-day delay and baseline prerequisites. Families A, B, C, D, F, G, H, I and J apply. Read the parent project, its legacy assessment supplement and `curriculum/v5/expansion/legacy_assessments/shared-contract.md` together with this contract. The separate assessor analysis and reference implementation are excluded from learner exports. A passing finite campaign supports only the stated observations, not absolute mastery or physical conformance.

## Prerequisites and environment

Use the actual `serial_depth.h` artifact and the learner's `sd_can_arbitration`, encoder and timing implementation; no CAN library may implement the assessed mechanism. `can.h`, `tests.c`, `controller_tests.c`, `native.c`, `guest.c`, `target_build.py`, the declaration-only freestanding shim and unsolved `learner.c` are supplied. The codec/timing/fault model uses ISO C17 fixed storage, 8-bit bytes and exact-width integers. C11/C17 do not supply device register semantics. The selected Armv7-M target uses STM32F439 CAN1, RM0090 Rev21, aligned volatile 32-bit accesses, and the selected compiler's Arm ABI. The host tools are verification dependencies only.

Build the public tests with strict C17 warnings and your implementation plus the actual prerequisite implementation. The target builder requires explicit `--source` inputs, `--serial`, `--serial-include`, `--boot`, `--link` and `--runtime`; it does not discover assessor sources. Link without libc/compiler archives, inspect undefined symbols, compiler-generated memory helpers, disassembly, stack frames and the map. Supply and audit any necessary original byte helpers. The supplied model executes on a host or Cortex-M4 emulator; it does not emulate electrical CAN or claim physical F439 execution.

Before touching actual CAN1, the board owner must establish selected package/pins, external transceiver power/enable, reference/termination, CAN1 APB clock, exclusive CAN1/filter ownership and a reset peripheral with no pending request. A frozen software producer and these explicit board prerequisites are different evidence classes.

## Problems and necessary distinctions

1. **T38.10.a:** Derive and execute the 11-/29-bit arbitration prefix for standard data, standard remote and extended data frames sharing base `0x123`. Then find numeric-ID ordering counterexamples for every standard base1..2047 using an extended base one smaller. Equal arbitration fields with different payload are not a successful multi-transmitter protocol. Submit the competing bit positions and explain dominant/recessive sampling versus bit-error detection.
2. **T38.10.b:** Implement `cn_feed` as an incremental decoder for the deliberately strict standard-data, DLC0..8 subset. Produce separate fixed-form and CRC counterexamples. Preserve the run-of-five state across every split, including a split immediately before a mandatory stuffed bit. Publish a copied frame only after CRC and tail admission; record ACK separately. A dominant ACK establishes neither destination authorization nor application delivery. The changed task uses every ordered three-chunk split of the zero-filled8-byte frame and single-bit input.
3. **T38.10.c:** Implement `cn_fault` from the actually inspected ISO11898-1:2024 clauses8.1.1–8.1.5. Classify events before applying them; encode every counter rule, both transmit-error exceptions, threshold transitions and restart observations. Explain why an isolated sender receiving only missing-ACK errors can become passive without reaching bus-off through that particular history. Compare the ISO-permitted REC reset range with the selected RM0090 implementation description. The reference model chooses127; it is not a claim that bxCAN chooses127.
4. **T38.11.a:** Derive encoded BTR `0x001A0005` from 42MHz, prescaler6, BS1=11, BS2=2, SJW=1. Search exact legal bitrates after changing to48MHz and sample target3/4. Include a minimum BS1 propagation allowance and reject an unattainable allowance. A rounded bitrate calculation or a matching register value is not a physical timing margin.
5. **T38.11.b:** Implement one 32-bit mask filter for standard data `0x120/0x7F0`, FIFO0 copying and exactly-once release. Inject10,20,30,40 without a release: locked mode retains10,20,30; unlocked hardware retains10,20,40. The changed software queue deliberately retains20,30,40. Explain why those are different policies and why the sticky overrun flag cannot count every loss.
6. **T38.11.c:** Implement one TX mailbox with monotonic software tokens, pending/ready/consumed states, abort request and later completion. Ordinary automatic retransmission keeps arbitration loss pending. Changed NART mode reports the first attempt terminal. Demonstrate bus-off while a request remains leased, refusal of premature recovery/reuse, bounded unavailable recovery, and a later observed successful recovery. Successful transmission may win a cancellation race; expose that result honestly.

## API contracts and reasoning

All objects and output storage are live, suitably aligned and mutually disjoint unless explicitly allowed. One foreground owner serializes calls; no callback may reenter, mutate the controller or fail. Model inputs may be hostile bytes or invalid parameters, but arbitrary fabricated internal C object states are outside the initialized-object contract. No heap allocation, recursion or unbounded wait is permitted. No ISO C assertion makes an MMIO read atomic with another read; register-specific stability and single-owner assumptions supply that argument.

`cn_feed` starts from a zeroed `CnStream`. Inputs0..160 are raw bit values0/1; null is allowed only for a zero-length chunk. Invalid raw input rejects before state/consumed/output mutation. `CN_MORE` consumes the supplied prefix, `CN_FRAME` publishes a copied frame and reports the exact prefix consumed, `CN_ERROR` consumes the offending prefix, preserves output and enters terminal error, and terminal states return `CN_BUSY` until the owner explicitly abandons/resets them. Storage holds at most98 unstuffed bits and160 total wire bits. Work is linear in consumed input, fixed storage. The local decoder requires recessive reserved/fixed bits and all seven EOF bits; ISO current receivers have wider permitted behavior, including the final-EOF exception. Do not market this subset decoder as a complete conforming CAN receiver.

`cn_fault` accepts one classified MAC event at a time. Each complete dominant-run episode is submitted once, not repeatedly as a cumulative length. The caller proves the event's flag/role/exception premises; this is not a physical error detector. TEC saturates at256 for the bus-off sentinel, REC at255; a successful receive above127 chooses127 from the allowed119..127 interval. Error signalling disabled keeps both counters zero. Counter-changing rules may apply more than once to an error history; use separate applicable events. Restart requires an explicit request followed by128 nonoverlapping occurrences of11 consecutive recessive bits. A dominant bit interrupts the current run; completed idle occurrences persist. This model says nothing about a bus's recovered health.

`cn_search` bounds clock to180MHz, bitrate to1MHz, sample denominator to1000 and requested BS1 allowance to1ms. It admits only exact integer rates, all legal prescaler/BS1/BS2 tuples, SJW1, and integer cross-product comparisons of rational sample errors. First encountered candidate wins ties. Failure preserves output. Complexity is bounded by1024×16 candidate work; 64-bit multiplication is used for the propagation inequality and must be checked for target helpers.

`cn_begin` requires a fresh zeroed controller, valid timing fields and a poll budget1..1,000,000. The supplied timing's rate is descriptive; the board clock must match its derivation. It disables interrupts and requests initialization with manual bus-off management. `cn_control` waits for INAK before BTR/filter writes, establishes bank0 with standard/data match bits, requests normal operation, and requires INAK/SLAK clear, BOFF clear and mailbox0 empty before running. A phase has at most the configured number of status observations. Expiry returns `CN_UNAVAILABLE` and never pretends that time or hardware state is known. `cn_recover` is explicit, requires no pending/unconsumed TX lease, and repeats enter/leave initialization; software never clears BOFF by assigning a counter. CAN2 must be unused; bank0 must belong to CAN1. Configuration intentionally disables other filters.

`cn_send` validates the whole standard/extended data/remote frame, copies its register payload, clears only mailbox0's stale completion and publishes TXRQ last. Tokens increase without wrap; at `UINT32_MAX` admission fails unchanged. No new send is admitted while pending or ready. `cn_tx_poll` accepts only the live token; terminal publication requires both RQCP0 and TME0. Raw hardware does not contain a software token: exclusive mailbox ownership and no reuse before acknowledged completion prevent an old completion being reassigned. `cn_cancel` writes ABRQ0 once and retains the lease. `cn_take` consumes a copied result once; success outranks an abort request if TXOK is observed. BUSY/unavailable never permits mailbox reuse. Each call does bounded constant work apart from at most8 payload bytes.

`cn_receive` snapshots FIFO0 status, copies four output registers, and writes RFOM0 exactly once. It does not read-modify-write the mixed write-one-to-clear register. A DLC outside this local0..8 contract is released once and rejected without changing the output. The copied `overrun` is a snapshot, not an exact lost-frame count. `cn_ack_overrun` is a separate explicit acknowledgement; events arriving before its write can coalesce. `cn_queue_put` is a separate copied3-slot oldest-drop queue, with an exact local drop count that saturates by rejecting before mutation at `UINT_MAX`; hardware loss and local queue loss remain separate.

## Deliverables, verification and assessment

Deliver your implementation, state/ownership diagrams, arithmetic derivations, hand-calculated independent traces, public positive/negative test results, generated-code/link/stack audit, source passage ledger, raw experiment commands/results and a limits statement. Preserve failed attempts and distinguish a test-oracle repair from a component repair. Supply at least one counterexample to each overstated claim: numeric-ID order, ACK-as-delivery, CRC-as-authentication, cancellation-as-completion, recovered-state-as-health and model-as-silicon.

The objective-specific original rubrics remain authoritative. For every objective, level0 lacks the mechanism or violates admission/ownership; level1 reproduces supplied outputs but cannot justify the critical transition; level2 explains each transition and passes ordinary and boundary experiments with honest limits; level3 independently derives and executes the original changed-condition task after the required seven-day interval, including a new falsifying trace and revised resource/portability argument. The author campaign is not that learner assessment. Reject a submission that erases sticky error evidence, frees/reuses a pending mailbox, polls without a bound, treats a crash as exploitability or claims physical evidence from RAM callbacks.

Graduated hints: first separate the arbitration, data, CRC and fixed-tail regions; then annotate ownership before every register write; finally write a hand trace where hardware completes successfully after the abort request. For the fault rules, tabulate event premises separately from numerical updates before coding. ## Security, variants and evidence limits

Use only original synthetic frames and the dedicated two-node teaching bus or emulator. No production vehicle/network, third-party service or real credentials are targets. IDs, filtering, CRC and ACK do not authenticate a peer. A harmless demonstration is a synthetic unauthorized payload accepted by an original receiver that mistakes these properties for authorization; repair it at the application trust boundary and test the same input. Electrical experiments require the explicit board-capture protocol; curriculum authoring does not authorize flashing or rewiring deployed equipment.

All six original `AX-PR-T38-09-…-V1` variants remain required with their unchanged minimum delay. Additional transfer: add an explicit declared widened receiver subset for final EOF/reserved-bit behavior; change the physical clock and propagation premise; separate asynchronous ISR ownership; or replace the controller's newest-overwrite FIFO with an oldest-overwrite controller while preserving the client contract. Each changes an assumption and requires new reasoning and evidence. Author native/Thumb campaigns establish only their recorded conditions. Board captures, independent learner work and external review remain separate outstanding evidence dimensions.

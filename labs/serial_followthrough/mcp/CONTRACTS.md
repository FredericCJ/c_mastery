# MCP2518FD selected-controller successor, revision 1

This required extension retains PR-T38-11 and PR-T38-12 and their six original objective-specific criteria and seven-day variants. It supplies author implementation, executable faults, and a physical protocol. The physical milestones remain required and not-run. No historical hours, accepted task, source inspection or receipt is rewritten.

## Prerequisites and environment

Use ISO C17, exact-width unsigned integers, original byte operations and the actual prerequisite SPI component at `labs/peripheral_depth/spi/spi.h`. `spi_adapter.h` composes `struct ps_spi`, `ps_begin`, `ps_step`, cancellation/reset and `pu_rates`. Target closure permits only supplied original byte helpers; it must not link a vendor controller driver, HAL, libc, libgcc or compiler-rt. Host Python and sanitizers verify the target mechanism and are not target dependencies. Compiler, Arm instruction set, MMIO, SPI electrical signaling, controller registers and ISO CAN rules are distinct contracts; a C23 compiler does not enforce these device leases.

Read the exact MCP datasheet, family manual and current errata locators in `research/v5/expansion/legacy_serial_mcp/resources.json`. Retained communications helpers remain a comparison: their plain READ is insufficient for the selected current erratum. No claim that every SPI CRC error means malicious input or that CRC authenticates a device is permitted.

## Problem, representation and concrete inputs

Implement `mcp.h`, `spi_adapter.h` and the selected target wrapper from their learner stubs. Use one foreground owner, no reentry or concurrent interrupt invocation, no dynamic allocation, one pending copied TX and an RX FIFO of1..16 entries. Input, output, control and adapter objects must be distinct nonoverlapping live objects; callbacks may not retain passed byte spans or reenter the owner. The ISR may only record a pending service request; foreground calls `mc_interrupt` and drains bounded frames. Callback context and driver remain live while any quarantined adapter staging exists.

The selected route uses an awake/cold-start MCP2518FD with40MHz external clock, no PLL/divider/sleep operation, SPI mode0 at no more than1MHz through the retained primitive, nominal500kbit/s, data1 or2Mbit/s, standard11-bit FD data frames, FIFO1 TX depth1, FIFO2 RX depth1..16, one exact-ID standard filter, no TEF/TXQ/timestamps, ISO CRC and gateway ESI, and no automatic retransmission. The SPI primitive maximum16 bytes is real: split READ_CRC into at most8 payload bytes and WRITE into at most12, each with its own CS interval and command/address. RAM chunks remain word aligned. Ordinary MC transport may admit up to17MHz per inspected silicon ratio; the composed PsSpi route is deliberately stricter.

`struct mc_driver` starts entirely zero. `mc_init` rejects invalid arguments without bus activity, then immediately enters POISONED until the complete bounded configuration/readback succeeds. A failed init requires explicit board/quiescence recovery and a new externally distinguished zero driver; memset of a live owner is not recovery. Identity is an expected selected DEVID byte plus Configuration/reset/readback/challenge sequence, never authentication. All-ones link data is rejected. Read ID/revision and errata for the actual board before setting expected_devid; do not assume the source fixture value0 describes every device.

`mc_layout` allocates one8+payload TX object, depth×(8+payload) RX bytes and conservatively reserves29×16 bytes for unused default FIFO entries. Supported payload codes map8,12,16,20,24,32,48,64. A64-byte/depth16 configuration consumes1688 bytes, within2048. The controller itself does not check a software RAM allocation proof. FIFO user addresses are offsets; add0x400 only after range/stride validation, and read them only after leaving Configuration and FRESET clear. Code and proof must change together when timestamping, TEF, TXQ, FIFO count or element size changes.

## Initialization and errata obligations

Request Configuration, observe OPMOD4 under elapsed and transaction-count bounds, then RESET. Select clock, observe ready twice, configure IOCON with single-byte writes, enable ECC with SEC/DED interrupts, write/read every RAM word, configure CAN/bit timing/TDC/FIFOs/filter and interrupt sources, leave Configuration and verify mode/reset/UA. No ready publication occurs before all operations return successfully with CS released. The selected data sample point is75%; automatic TDC offsets15 or30 SYSCLK periods correspond to the selected2M/1M rate, and require actual physical measurement before board acceptance.

All reads use READ_CRC, polynomial0x8005 initialized0xffff, MSB first over command/address/count/data, received CRC high byte first. Retry a CRC mismatch at most twice; never retry a side-effect write blindly. An incomplete write can commit a prefix. A failed UINC/TXREQ write is indeterminate and poisons the driver while retaining the token. Readback detects sampled data mismatch but is not an atomicity guarantee. Erratum1 requires CRC reads; erratum6 allows a valid CRC with a wrong RX FIFO index, so the implementation does not use FIFOCI. Both SEC and DED mean corruption, because single-error correction is not reliable under the selected erratum. RX RAM is read only after a nonempty flag. No sleep/wake support is claimed; adding it must implement erratum7 timing and repeated-ready workaround.

## Ownership, failure and publication

`mc_send` validates metadata/length before I/O, checks room and UA, copies and reads back the object, reserves a strictly increasing nonzero token, then writes UINC and TXREQ together. Zero-byte FD is valid. Caller payload may be reused when the function returns: only controller RAM and the copied adapter staging remain. Success here means admission, not acknowledged transmission or peer application delivery. A second pending send returns BUSY unchanged. UINT32_MAX is the last token; retire the instance afterward.

`mc_poll` requires TXREQ clear and compatible FIFO terminal status. A loss/error may exhaust the selected one attempt; cancellation is only a request and successful transmission may win it. Do not reset a FIFO while TXREQ is live. `mc_take` resets/drains the terminal FIFO under a bounded acknowledgement, publishes the result once, then releases pending ownership. A failed reset remains poisoned and no result is published. Bus-off, system error and corrupt RAM require explicit recovery, not silent retries.

RX copies a full admitted object into a temporary, validates standard FD metadata and configured size, then increments the FIFO exactly once and only afterward publishes the application frame. Failed reads/UINC preserve application output and poison state. Overflow is a separately observed coalesced flag, cleared at the source using the documented write-zero status semantics; it is not an exact lost-frame count. Interrupt summaries do not clear every source automatically.

The SPI adapter owns16-byte staging. Success requires wire completion, hold time and CS release. On timeout it attempts the retained PIO cancellation/reset; a stuck peripheral quarantines staging and CS. It returns an error without retaining the passed controller stack buffers. Further transfer rejects until actual recovery. The adapter itself must remain alive. No completion event or ready result may precede CS release. Finite iteration bounds prevent a stopped clock from hanging software; they do not prove that broken hardware quiesced.

## Required deliverables and verification

D1: derive RAM offsets, NBTCFG/DBTCFG/TDC words, CS chunks, retry bound, state/token table and equal-correctness cost ledger. D2: implement the actual selected controller and compose the prerequisite learner SPI; record native/sanitizer/Arm commands, final symbols, stack and emitted calls. D3: inject every initialization transfer failure before and after its possible side effect; show no ready publication, CRC-corruption retries, stuck mode/clock, all payload sizes and DLCs, malformed UA, pending cancellation, stale token, partial publication and ECC corruption. D4: construct PR12 frames0/8/12/16/20/64 bytes, BRS0 and1, independent content/sequence oracle and missing-peer/filter/overflow scenarios. D5: complete the actual board and independent-peer dossier in BOARD_CAPTURE.md, raw SPI and physical CAN captures, with a changed oscillator/board/rate repeat. A synthetic transcript is a test fixture, never D5 evidence.

Run each named public test, independent oracle and deliberately faulty implementation. Compare complete output/state and first divergent transaction, not exit status alone. Native and MPS2 execution demonstrate tested software/ISA paths. A model that imitates a wrong specification can pass; justify registers against inspected passages and submit actual captures separately. The selected ordinary write transport does not claim cryptographic integrity or fault tolerance to arbitrary undetected line errors. Compare these limits with WRITE_SAFE and a CRC-protected write extension.

## Criterion rubric and changed conditions

PR11.a: reject a zero-length policy mismatch and prove every admitted DLC fits each changed element size. PR11.b: distinguish all-ones/valid CRC from initialized identity; inject every SPI phase failure and prove ready is last. PR11.c: classify cold/reset/clock/pin/errata assumptions for a different board revision and require physical readback/loopback. PR12.a: independently verify sequence/content/BRS and redo rate/peer assumptions for BRS1. PR12.b: reject link-ACK-as-application-delivery, demonstrate missing-peer bounded attempts/cancellation and preserve error/recovery evidence. PR12.c: retain mandatory physical gates despite historical optional wording; audit a source-bound capture dossier after seven days.

For each criterion: level0 is a false property/evidence claim; level1 reproduces a fixture without the ownership/source argument; level2 supplies the relevant implementation, counterexample and bounded verification; level3 independently solves the exact unchanged delayed task with new evidence and limitations. The original criterion/variant IDs remain canonical in the attached assessments. Author tests never award learner level3.

## Graduated hints and assessor separation

First mark which operations can publish externally. Next separate a device write request from observed acknowledgement and a transport error from rollback. Finally audit each command's byte count/address/CRC against a separate trace representation and locate the first uncertain side effect. Technical analysis and corrected implementations live only under assessor/serial_followthrough/mcp and are excluded from learner exports.

## Security and validation limits

Use original fixtures, synthetic frames, dedicated unconnected development boards and a local compatible peer only. No deployed vehicle, service, real credentials or external network. CRC corruption, malformed frame and missing-ACK demonstrations stay within that setup. A failed frame, sanitizer finding or injected device error does not demonstrate arbitrary code execution. Physical measurements, independent review and delayed learner assessment are separate required dimensions and remain not-run until their own evidence exists.

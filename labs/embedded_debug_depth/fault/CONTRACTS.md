# T31 fixed fault capture, exact image attribution and stack evidence

## Identity and purpose

This required successor supplies the six original `AX-PR-T31-02-T31.03.a` through
`.04.c` criteria and their unchanged `-DELAYED` variants. It preserves original
project/unit IDs, historical eight-hour metadata and accepted evidence. There is
no study-time ceiling. Families A/B/C/D/F/G/I/J are assessed where the particular
mechanism needs them; one successful target fault is not every objective.

The essential distinctions are valid versus merely present bytes, first versus
secondary fault, precise versus imprecise attribution, a machine instruction
versus a source filename, and observed writes versus a bound on live stack use.

## Representation, ownership and lifetime

`DfCapture` owns atomic state0(empty),1(capturing),2(published), a monotonic
secondary-attempt flag, and one fixed `DfRecord`. Fresh initialization requires a
live nonnull owner and whole-owner quiescence; it cannot erase an active capture.
Input/status/image/frame spans and outputs are live, correctly typed, disjoint
and stable through each call. The input record is caller-proven acquisition data,
not an unforgeable certificate. A copied record retains its old meaning; it is
not permission to reset a live owner. No allocation, formatting, device I/O or
unbounded retry occurs in the capture core.

A strong atomic claim chooses the first admitted capture. Subsequent submissions
only set the atomic secondary flag and return AGAIN; they cannot replace the
first record, whether it is still being written or already published. A reader
returns BUSY without changing outputs before release publication, then acquires
the immutable record. The secondary flag may become true after a reader observes
it; it is a monotonic diagnostic, not an atomic snapshot of all future faults.
The optional synchronous test hook may submit another capture but cannot destroy
or reset the owner/input. It is not a general callback or asynchronous recovery
facility. Target interrupt integration additionally needs ISA/compiler guarantees.

## Capture validity and failure contract

Version1 contains a valid bitmap, CFSR/HFSR, EXC_RETURN, optional fault addresses,
eight basic-frame words, frame-decode status and optional32-byte acquisition image
identity. Capture always retains admitted status. BFAR/MMFAR are copied only when
their corresponding validity bits are set; absent fields remain zero. A stale
nonzero raw address with its validity bit clear is never published as valid.

`readable=0` forbids dereferencing the supplied frame pointer. A readable claim
requires an actual live extent; an exaggerated length cannot be made safe by the
decoder. Stacking/unstacking/lazy-save error bits reject frame interpretation.
The selected capture supports only basic Armv7-M frames through `xf_frame` with
FPU capability false. Extended frames, malformed EXC_RETURN, bad Thumb/IPSR/PC,
misalignment, short extent, padding without the ninth word and address overflow
are explicitly incomplete/rejected in `frame_status`. Status capture can still
succeed with no valid frame. Failure before claiming the owner preserves it.

All basic words are captured before the target's controlled continuation changes
the live saved PC. A richer formatting handler could fault through the same
failed peripheral or consume the remaining stack. The fixed-memory path avoids
those dependencies, but cannot promise a record if its own storage, stack or
execution context is inaccessible. A secondary architectural lockup can stop
software before any secondary flag is written.

## Exact image and instruction attribution

`df_access` borrows a complete record and exactly identified code extent. It
compares all32 image-identity bytes before attribution and rejects version2.
The pure selected decoder accepts only Thumb16 word STR/LDR immediate T1. Base
register r0..r3 and a store's value register r0..r3 must be captured; other forms
are unsupported/incomplete. Address arithmetic is checked; this contract refuses
a wrap instead of claiming to emulate all architectural modular addressing.
No captured address is dereferenced. Reads report no inferred destination value.

The computed effective address is separate from a hardware-valid fault-address
register. Precise confidence requires exactly the selected data-access cause
after ignoring address-valid bits; combined, imprecise or unrelated status does
not identify a unique causal instruction. The target clears prior status before
its one owned instruction. Arbitrary additive fault histories need a richer
causality argument even when individual bits are valid.

The target's fixed32-byte token is **not an embedded ELF hash**. The host
acquisition envelope records the actual image SHA256 and raw record. `decode.py`
checks that digest before locating the saved PC in one executable ELF32/Arm
segment and independently decoding its actual bytes/operands. A changed image
with the same source filename is refused. Preserve the actual ELF, map, assembly,
source lines and raw acquisition record together. Debug symbols alone do not
authenticate an arbitrary submitted record.

## Controlled original target experiment

The dedicated `mps2-an386` image initializes every implemented MPU region to
disabled, reads region capability/alignment and configures one32-byte aligned
no-access region at the beginning of an owned288-byte array. The remaining256
bytes model stack storage. Background privileged access permits the surrounding
image and actual MSP. A neighboring word is successfully written before the
controlled store to the guard. The guard's sentinel must remain unchanged.

The entry shim captures MSP/PSP and EXC_RETURN before the C prologue. The handler
checks the selected MSP reserve, captures status/frame into fixed memory without
output, then permits return only from the exact labelled original STR to its
exact labelled continuation. It disables the test MPU region and clears its own
fault bits. This is a bounded teaching continuation for one synthetic instruction,
not a general policy of skipping faulting instructions. No corrupted native
return or attacker-chosen control transfer is executed.

Post-return reporting must show valid basic frame, CFSR82, MMFAR equal to the
owned guard, saved r0=12345678 hexadecimal, saved r1 equal to MMFAR and saved PC
at the actual STR. Independent ELF decoding must reconstruct that same access.
The control with protection omitted must fail because no fault occurred; the
control with a changed captured base must fail the effective-address check.
The public target stub compiles and fails its intended assertion.

## Secondary faults and lockup model

`df_refault` is a pure selected priority-less-than-zero model, not a fault
injector. Kind0 precise data BusFault locks up when BFHFNMIGN=0 and is ignored
when1; kind1 imprecise BusFault becomes pending; kind2 MPU data fault depends on
HFNMIENA; kind3 non-INVPC UsageFault locks up. Inputs are Boolean/configuration
claims and the output is unchanged on invalid input. This deliberately excludes
vector errors, fetch/XN cases, INVPC/NMI-return and all other lockup details; cite
their different manual cases instead of generalizing this table.

The HardFault-refault variant applies the exact selected rule and explains why
another C handler call may never happen. An original synchronous nested-capture
test preserves first-fault identity and marks secondary attempts, but is not an
execution of architectural lockup. Physical reset/watchdog recovery remains a
separate continuation with its own evidence.

## Stack diagnostics and changed bounds

Canary checks inspect only chosen live sentinel bytes and detect their changes
when sampled; they do not validate a return address, alignment or an untouched
interior region. The watermark scans a declared byte extent from its low end for
the first byte unlike the fill pattern. With allocation256 and96 visibly changed
bytes it reports96 used/160 free. That is a byte observation, not liveness.
An actual live160-byte C object whose lower64 bytes still equal the fill value
demonstrates underestimation: its watermark remains96.

`df_budget` sums at most eight simultaneously live declared software frames plus
basic32-byte or extended104-byte hardware frames and optional4-byte padding.
Counts, flags and additions are checked transactionally. `[32,64,32+32]` gives
160, so an untested path can exceed the observed96 while fitting256. Adding two
extended+padded nested exceptions to160 gives376, which does not fit256. This is
conditional on the declared call/nesting graph. Recursion or an opaque callback
without an independent bound returns UNKNOWN and leaves the output unchanged;
it is not silently treated as zero. Compiler `.su` records also need complete
reachable-call/nesting evidence and do not measure physical WCET.

The MPU guard detects only accesses whose actual addresses match its region.
It is coarse-grained, cannot catch every interior write and can be jumped over
by an unrelated bad address. The actual target checks region support and uses
32-byte granularity; another target must derive its own supported size/access
rules. No test result permits reclaiming all observed free bytes.

## Security, validation and remaining evidence

All executable faults target only this original owned QEMU image with synthetic
sentinels, no networking, external target, credentials, host-security changes or
board flashing. The harmless success condition is rejected guard access plus
an unchanged sentinel and correctly captured diagnostic. The correction is safe
bounded capture/validity and declared protection; regress all controls. A fault
or sanitizer finding is not code execution or privilege escalation.

Current exact author-validation status is in the source-bound support record.
Physical MPU/bus timing, silicon imprecise delivery, physical damaged-stack
capture, external reviewer and independent delayed learner evidence remain
separate. Models do not execute every hardware failure; no software capture is
guaranteed after arbitrary corruption. These are limits, not optional exclusions.

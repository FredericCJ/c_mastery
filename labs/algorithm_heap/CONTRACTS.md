## Environment and representation

Execute on Linux x86-64 SysV and the dedicated Cortex-M4 MPS2 emulator. GNU assembly is an ISA/ABI-specific component, not ISO C. Build native GCC/Clang debug, optimized and Address/Undefined sanitizer profiles; target uses `-ffreestanding -fno-builtin -nostdlib`, explicit startup/link layout and provided byte helpers. Audit the final target's unresolved symbols and ELF segments; host Python certificate checks and sanitizers are not target dependencies. Emulator functionality does not provide board timing.

There are two intentionally distinct representations. Scalar `uint32_t[n]`, n<=1024, has no identity fields: a max heap chooses the lower child index on equal values, and stops when parent equals the best child. The actual imported `struct cd_heap` stores at most16 `struct cd_heap_item` records: signed32 priority, unsigned identity/slot and uint32 sequence. Its public max/min selector changes priority order; equal priority always prefers the older (smaller) sequence. Its generation, retirement and index-map rules remain unchanged. Compile-time assertions specify the selected offsets, 16-byte record stride and 64-bit comparison-counter offset. A different ABI/layout requires a new adapter, never an unchecked cast of records to scalar keys.

## Problem and failure semantics

1. Preserve the checked scalar facade. For nonempty input require p<n, all edges other than those leaving p already ordered, and, when p>0, the parent of p dominates each child that might be promoted. All child subtrees must be heaps. Investigate p1 in `[10,1,9,20,0]`: its storage is valid but its strengthened order premise fails. Contrast checked no-change rejection with the harmless original unchecked kernel's broken ancestor edge. Empty input is a no-op; p is ignored. Reject n>capacity, n>1024 and invalid nonempty/null positions before any access or mutation.
2. Preserve the full prior heap's build/insert/get/change/take contracts and capacity16. Replace only downward repair with original assembly for complete `struct cd_heap_item` swaps and index updates. Maintain the same comparison accounting and stable sequence preference. Compare every live record, index, generation, slot state, count and result with the prior implementation. Reuse unchanged upward repair for arbitrary increase/decrease-key: a raised max priority may move up, a lowered one down (reverse priority relation for min heap). Retiring a slot after its third generation and sequence exhaustion remain required.
3. Add `ah_trace(a,n,capacity,p,arity,minimum,stats,trace)`: arity2 or3, minimum0 or1, n<=1024. Return1 for admission/premise failure, preserving input, stats and trace; return0 after successful repair, publishing comparison/swap counters and every full array **after a complete swap**. Nonnull separate stats/trace are mandatory. The output holds12 snapshots of1024 values; the caller owns that bounded storage. Unused snapshot entries are unspecified. Empty success publishes zero counters/used snapshots. No fallible operation occurs after admission. Host and target test harnesses use static trace storage rather than putting ~49KiB on the target stack.

## Reasoning and resource obligations

Derive the moving violation invariant: all edges outside the current node's outgoing edges remain ordered; every complete state is a permutation of the input; the retained key descends to a proper child; remaining subtree height strictly decreases. Explain the ancestor condition needed for internal p and why build's bottom-up subtree repair has a different whole-heap premise. No proof may treat the first store of a swap as a complete permutation. For arity d, test existence with `n>=2 && p<=(n-2)/d` before computing d*p+1; scan the existing children left-to-right, retaining the first equal extremum. Each visited nonleaf level performs one comparison per existing child (children−1 selection plus one parent comparison); a leaf performs none. The checked scan is O(n), trusted binary repair O(log n), and the deliberately emitted full snapshots O(n log n) space/time under this fixed cap. They are different cost contracts. The structured kernel performs constant-size record transfers and two handle-index writes per swap; its unsigned64 counter wraps as the original C provider does. Do not count observer calls/copies as kernel instructions or infer speedup from semantic counts.

Handwritten assembly is not automatically instrumented by C sanitizers.

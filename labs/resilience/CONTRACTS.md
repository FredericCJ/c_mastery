# Resilience laboratory contract

Original hosted C17 mechanisms operate on synthetic values under an injected monotonic uint64 tick clock. Exact-width types are required. `resilience.h` defines representations; this document defines admitted operations. All control objects and outputs are actual live objects, initialized as specified, and outputs are disjoint from inputs/control state. Private representation corruption and arbitrary forged pointers are outside admitted calls. NULL required pointers return INVALID where checked; void initializers accept NULL as no-op. Init is only legal on fresh/quiescent storage with no retained identities. Except `rz_cancel` and reads of atomic cancellation flags, operations on a model are externally serialized. Parent, scope, wheel, gate and imported channel owners stay at stable live addresses through every dependent operation. No callbacks or allocator are hidden in the finite models. They implement mechanisms with typed objects, loops and checked arithmetic. Host CMake/Python/sanitizers are verification tools; T73 messaging imports POSIX threads and its own backend contract. These are not freestanding or real-time scheduling guarantees.

## Deadline and cancellation

RZScope forms a construction-ordered parent chain of depth1..8. Parent metadata is immutable; only its atomic cancelled flag can change. No reinitialization while children live. Init chooses the earlier of parent deadline and requested now+budget, rejecting unrepresentable standalone addition. Zero budget expires at now. `rz_check` gives cancellation of any ancestor precedence over expiry; expiry includes equality now==deadline. `rz_remaining` publishes only on OK. Cancellation is idempotent, cooperative and not an acknowledgement of stopped work. Scope storage remains until borrowers finish. A relative budget crossing hosts must deduct elapsed work and state transport-delay uncertainty; copying an absolute monotonic timestamp across unrelated clocks is invalid. Scalar now arguments must obey the operation's stated time model; no OS clock or sleep is read implicitly.

## Five overload policies and channel composition

RZQueue stores at most four unsigned copies FIFO. Its public closed flag may be set by the serialized owner to close admission; existing items still pop before CLOSED. Each RZOffer borrows a live scope and starts pending=true; a terminal result consumes that operation state, not an owned resource. BLOCK on full returns PENDING, preserving pending and value for explicit retry; it does not block a native thread. REJECT returns FULL, DROP returns DROPPED and leaves old queue values intact, OVERWRITE removes oldest then appends new, and DEGRADE replaces newest by max(old,new), returning DEGRADED so reduced information is observable. They act only when full; all admit ordinary FIFO enqueue when space exists. Deadline/cancellation/close terminates a pending offer before admission without queue mutation. Reusing a terminal offer is INVALID. The caller must bound the number and storage of pending producers separately. No implicit fairness or ownership of pointer payloads is promised.

`rz_forward` peeks and calls the actual imported `msg_send(hub,channel,value,false)`. Only MSG_OK consumes the queue head; FULL/CLOSED/CANCELLED preserve it. Channel0/1 and live initialized hub are required. The adapter never calls a nonexistent timed T73 operation. Actual waiting, readiness registration and cancellation acknowledgement belong in the explicitly required reactor adapter. Hub destruction requires all users quiescent, as in `labs/messaging/CONTRACTS.md`.

## Timer wheel

RZWheel has four buckets and four typed timer slots. Delays1..16 become nonwrapping absolute due times. Each bucket is a doubly linked slot-index list; collisions retain distinct due times. Schedule finds a free slot and inserts at head. A timer ID includes owner, slot and generation. Cancel unlinks exactly that active generation. Tick advances exactly one time unit and returns a bitmask of slots due at that instant, including all simultaneous expiries; it never invokes callbacks. Fired/cancelled slots advance generation1..3 and retire at4. Stale IDs cannot cancel reused slots. Scheduling/ticking at the numeric horizon rejects without change. Due checks prevent a multi-revolution timer firing on its first bucket visit. Fixed-capacity search is bounded; generalized search is O(capacity), insertion/unlink O(1), tick O(bucket population), plus output processing. No claim of constant worst-case total expiry work. Jumped-clock catch-up, hierarchical wheels and callback reentrancy require separate variants.

## Token bucket and retry budget

RZBucket capacity and integral rate are1..16, initially full. Consume costs1..capacity and admits monotonic now>=last. Refill is min(capacity,tokens+(now-last)*rate), computed without overflowing intermediate multiplication; last advances and refill persists even when insufficient tokens returns FULL. Successful admission subtracts exactly cost; equality is sufficient. Invalid arguments/backward time preserve state. Burst capacity, average replenishment and a per-call cost are distinct constraints; this is a policer returning status, not a scheduler or a complete tc TBF implementation.

RZRetry borrows a scope, schedules at most1..4 retries, base1..8 and cap in base..32. It requires an explicit idempotent-operation assertion. The kth scheduled retry window is min(cap,base*2^k). Caller supplies a draw uniformly selected in [0,window] for full jitter; this function checks its range but supplies no PRNG or entropy claim. A scheduled start must be strictly before the shared deadline. Failed scheduling preserves attempt count/output. The caller rechecks cancellation before dispatch and accounts for each actual attempt in a shared limiter. Zero jitter is permitted; an attempt limit prevents unbounded immediate retries. Whether a prior request committed is not inferred from timeout. Concurrent layers and retryable error classification are consumer obligations.

## Circuit breaker and bulkhead

RZGate combines separate state and capacity: CLOSED0 admits up to limit1..2 active permits; two consecutive classified backend failures open it for four ticks. Successful classified completion resets failure count. Neutral outcome -1 releases capacity without health evidence. OPEN1 rejects until cooldown, then HALF_OPEN2 admits only one current-epoch probe. Probe success closes; failure reopens. A permit binds owner, slot, generation and admission epoch. Late old-epoch completions release their slot but cannot heal or reopen a newer health decision. Duplicate completion is STALE. Each permit slot retires after generations1..3; no wrap. Breaker epochs1..7 retire terminally when another transition cannot be represented. A cooldown beyond UINT64_MAX also retires. Valid now values never go backwards; a valid denied admit may advance last and transition OPEN to HALF_OPEN even without an available slot. No admission output changes on failure. Completion does not cancel other in-flight effects. Health sample policy is deliberately consecutive failures, not the comparison library's sliding-window implementation. The fixed small generation spaces expose exhaustion; a service deployment needs a separately justified wider identity/lifetime policy.

## Hedged requests

RZHedge starts original attempt0; attempt1 may be started once at hedge_at while scope is live and no winner exists. A completion must refer to an actually started, unfinished attempt. It always records that attempt as completed, even if cancelled/expired. Only an acceptable completion before scope expiry can publish the first winner/value. It requests cancellation of outstanding attempts, but does not mark them completed. Later acceptable responses never replace the winner. `rz_hedge_result` reports the chosen value while `rz_hedge_quiescent` separately reports completion of all started attempts. After a rejected first response, the second may still start at its threshold. A fully rejected pair has no winner; caller reports its explicit aggregate failure policy. Storage and resources survive until quiescence. The model cannot interrupt remote work; concurrent completion requires synchronization of the single-winner transition. Operations with side effects require deduplication or a documented compensating policy.

## Idempotence and fencing

RZReceiver holds four request records and a checked int synthetic total. Client IDs0..1 are trusted authenticated identities for this original model, request IDs1..15, delta -8..8, positive fence, retention window1..16. Monotonic now cannot go backwards. The storage authority rejects any token lower than its highest successfully admitted fence, including cached replies. Within the window, identical (client,id,delta) replays return the original result without repeating the effect; changed delta returns CONFLICT. Records expire at age>=window and an expired ID may apply again. Never evict a live record merely to admit a fifth request. New effect, record, fence and reply publish as one serialized transition; failures preserve them and outputs. Duplicate success may advance fence and last but does not refresh retention. Exhaustion, restart, persistence, authentication and issuance of globally monotonic fencing tokens are separate problems. The in-memory model neither survives crashes nor promises indefinite exactly-once behavior. A token is checked at the actual protected resource; a lease timeout alone is insufficient.

## Telemetry admission and drain

RZService borrows scope and MsgHub. Init selects token capacity4/rate1, breaker bulkhead2, and dedup retention8; these descriptive constants are not deployment tuning evidence. Submit first checks scope and reserves available pending-notification capacity, then spends one limiter token, obtains a breaker permit, and calls the idempotent receiver. A token may remain spent when later admission fails. Receiver errors release a neutral permit; success releases a healthy permit. A new effect queues its request ID exactly once; replay returns its stored result without another notification. The reservation check precedes the effect, including for duplicate requests, so a full pending queue rejects duplicates too under this explicit policy. Outputs publish only on successful submit, but earlier limiter/health bookkeeping is not rolled back. Cancellation observed after admission cannot undo the committed effect or suppress its reserved notification. Flush moves one queued ID to the real T73 channel only after accepted send. Delivery to a consumer and durable persistence are separate from successful submit. Close/cancel of the hub retains pending notifications for a chosen explicit recovery/discard policy; never destroy borrowed channel state before quiescence. Small finite permit identities deliberately bound this anchor's total lifetime. The required service extension must replace that bound honestly, integrate retries/hedges/timers and real local I/O, and prove bounded outstanding ownership.

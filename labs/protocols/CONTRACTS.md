# Protocol mechanisms: shared execution and assessment contract

The baseline is ISO C17. The inspected public ISO text is the C11 committee draft N1570; it is identified as a draft, not the published C17 text. None of these mechanisms requires a C23 language feature. Struct type compatibility and switch-label constraints receive compiler diagnostics; ownership, exclusivity, quiescence, protocol progress and resource release are library contracts. Copying a wrapper is valid C. A copied stale wrapper is rejected only while its referenced device object remains live; a dangling pointer is outside the API contract and cannot be made safe by a generation comparison.

All objects must be initialized as specified, properly aligned and live, with exclusive serialized mutation. Inputs and outputs are distinct live objects unless a particular operation explicitly consumes and replaces one. Callbacks may not reenter, mutate control objects, perform a nonlocal jump, or retain a borrowed pointer beyond its declared ownership interval. Public control fields are inspectable for teaching; callers must not forge them except in a named invalid-state test. A null required pointer returns PT_INVALID except the fresh-object initializer, whose nonnull live-pointer precondition is explicit. Error codes are in protocols.h. Every unmentioned rejected call leaves state and outputs unchanged. No library supplying the studied mechanism is permitted.

## Typestate

Initialize a fresh device and PTClosed token with pt_device_init. The device begins generation1, CLOSED, control0, cleanup0. Configure consumes the matching closed token after validating fail_stage0..2 and generation exhaustion. It increments generation and writes control1, then control3. Injected failure at either write leaves RecoveryRequired, consumes the old token and leaves the ready output unchanged; rollback is not claimed. Success produces a matching PTReady. Close consumes a ready token, clears control and increments cleanup and generation. Recovery requires state RecoveryRequired and trusted external quiescence; quiet0 returns PENDING. Quiet1 clears control and produces CLOSED. Generation UINT32_MAX is retired: a new token is never issued by wrapping. Cleanup count is descriptive unsigned accounting; its potential wrap is not an ownership identity. Device storage remains caller-owned and cannot be reinitialized while tokens survive. Prove why a distinct PTReady struct catches some misuse yet does not implement Rust move semantics or forbid aliasing.

## Builder

A zero-initialized builder admits exactly three one-shot setters: field0 address0..255 divisible by4; field1 length1..64; field2 timeout1..1000. Repeating a field returns STATE; invalid values return RANGE. Finish requires presence mask7 and address+length<=256, and then publishes PTConfig atomically. Finish does not consume the builder; it may be repeated. Direct field fabrication is outside the construction invariant. A staged wrapper alternative must identify its extra types and the escape through a raw struct copy; it cannot claim arbitrary data validity from a presence bit alone.

## Binary session

Initialize role0 client or role1 server, phase0 and remaining0..8. The client sends HELLO, receives ACCEPT, sends DATA then receives ACK exactly remaining times, and sends BYE. The server uses the dual directions. Phases0..4 name the next message HELLO/ACCEPT/DATA/ACK/BYE; phase5 is closed. Each successful step consumes exactly one message. Wrong direction, tag or a step after closure returns STATE unchanged. DATA/ACK with zero remaining is an invalid fabricated state. This finite runtime automaton has no transport, liveness, deadlock-freedom, peer authentication or failure notification guarantee. Those require additional assumptions and adapters.

## Hierarchical dispatch and active object

Tree: ROOT has OFFLINE, ONLINE, FAULT; ONLINE has IDLE and BUSY. Initial leaf OFFLINE. CONNECT goes OFFLINE→IDLE. START goes IDLE→BUSY and is an external self transition from BUSY. FINISH goes BUSY→IDLE. FAIL at either online leaf is handled by the online region and goes to FAULT. RESET goes FAULT→OFFLINE. PING is internal, increments pings, emits no entry/exit. Reject pings exhaustion at UINT32_MAX. Other events reject unchanged. Exit traces encode 0x80|state, inner first; entry traces encode state, outer first. A transition exits/enters through its least common ancestor; an external self transition exits and reenters its leaf. A trace that cannot fit returns RANGE without changing machine, buffer or used. A dispatching flag rejects attempted reentry. This is a declared bounded HSM subset, not all UML/QP semantics; no action callbacks run in this kernel.

The active object adds a four-element copied-event ring, initial head/count0. Post appends or rejects full without overwrite. A step dispatches the oldest event and removes it only after success. A malformed/unhandled event remains at the front: the caller must choose an explicit administrative discard or repair policy in the transfer exercise; silently popping failures is forbidden. Producers and the consumer are serialized in the supplied MCU model. ISR or threaded producers require the actual copied-queue/scheduler adapter and synchronization evidence, never volatile alone.

## Stackless continuation

PTThread starts all-zero. pt_thread_sum accepts three available uint32 values, preserving sum/count across calls. Unavailable input moves pc to the waiting label and returns PENDING without consuming value. Checked sum overflow returns RANGE unchanged. The third accepted value publishes the sum and marks pc UINT32_MAX; subsequent calls return DONE without changing output. The PT_BEGIN/WAIT/END macros express the same switch-based suspension mechanism with explicitly unique constant labels. Label0 and UINT32_MAX are reserved. A completed macro function must not be called again. Locals do not survive an ordinary function return; persistent state belongs in the frame. No VLA, jumping into an uninitialized local's use, nested switch around waits, or blocking child stack is admitted. Inspect such invalid proposals without treating an undefined execution as an oracle.

## Memory behavior tree

The immutable node array has1..8 nodes, root0, and forward child indices. Sequence/selector children are contiguous, nonempty, in range and have exactly one parent; leaves have zero children. Each leaf callback returns SUCCESS, FAILURE or RUNNING. A memory sequence skips already successful children until its running child completes; a memory selector skips failed children. Terminal nodes reset their cursor. A running leaf's bit remains in active_mask; cancel clears state and calls abort exactly once for each active leaf, never for completed leaves. Tick/cancel reject reentry. Callback failure has only a basic guarantee: previously executed callback effects are not rolled back, and a malformed callback result returns INVALID with output unchanged. Tree structure must not change while cursors are live. Recursive depth is bounded by8, so stack usage is finite but must be measured. A reactive tree that rechecks earlier guards is a changed contract, not an optimization of this memory tree.

## Driver and imported components

PTDriver couples the device lifecycle to an original local register/DMA adapter. Start admits READY, no existing DMA loan, buffer length1..64, and all callbacks. It borrows the caller's immutable buffer before start_dma. Start failure may mean partial hardware progress, so it retains the loan and enters RecoveryRequired. Stop-and-quiesce returning nonzero retains the loan and returns PENDING; returning zero certifies that the teaching device cannot access it again and permits release and lifecycle recovery. Complete requires trusted_quiescence1 before releasing a loan; device error enters recovery. A successful completion in READY invokes watchdog once. Completion after a failed start can release a quiescent loan but still requires recovery. No timeout or cancellation intent substitutes for quiescence. Callback success/failure meanings are adapter obligations, not facts inferred from an integer return alone.

The final project must connect learner-owned firmware_io.gpio, uart, timer, dma and watchdog, execution.tasks, sync.copied_queue, containers.ring and adt.brand through an explicit ADAPTERS.md: identify producer revision, imported operations, representation conversion, lifetime, serialization and mismatch policy. The executable public port is a synthetic model, not evidence those real component integrations have run. Preserve the baseline component implementations. No target library may implement these protocol mechanisms. Host Python, stdio and sanitizers are verification dependencies only. The separate Cortex-M4 object/link campaign proves only the declared build and helper audit, never peripheral behavior or physical timing.

## Assessment and containment

Every exercise submits D1 mechanism derivation, D2 implementation, D3 independent falsification, and D4 changed-condition transfer plus COST_REVIEW.md covering all13dimensions. Supply operation counts, storage, callbacks and allocation counts before performance conclusions. The public tests and two mutants per mechanism establish bounded sensitivity; an assessor evaluates each leaf rubric separately and holds a delayed changed-contract case at least seven days. No finite suite establishes absolute mastery.

Security experiments use only these original in-process devices, synthetic events and byte buffers. An attacker may submit invalid tags, reorder/replay tokens or cause scripted device failure; may not change trusted quiescence facts, forge arbitrary live pointers or access external hardware. Observable success is an illegal transition, overwritten queued event or premature buffer release recorded by a synthetic counter. Each demonstration records prerequisites, exact state transitions, corrected behavior, regression tests and residual liveness/trust limits. No crash is described as arbitrary code execution. No hardware is flashed and no deployed equipment is used.

## Target runtime boundary

The Cortex-M4 link audit explicitly includes labs/protocols/targets/runtime.c: original byte-loop __aeabi_memcpy, __aeabi_memclr and __aeabi_memset helpers with aligned aliases. These are declared target dependencies, not an implicit hosted library. Inspect their compiled call graph and the complete undefined-symbol list. The entry point only spins; it is not executed and does not initialize a board. Callback imports are unresolved semantic obligations even though indirect calls require no external link symbols.

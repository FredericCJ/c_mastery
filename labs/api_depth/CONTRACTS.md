# Exact API depth contracts

These are required construction/diagnosis/boundary/verification/failure/transfer laboratories attached to existing leaf criteria. C17 is the active implementation baseline. Profile C applies to the component; hosted test instrumentation is separate. No malloc, library copying/container/dispatch implementation, compiler extension or hidden runtime is allowed in the component. A freestanding claim additionally requires generated-code and link audits, including callbacks and implicit compiler helpers. No physical or concurrent execution is inferred from hosted tests.

## api_depth.append — PR-T18-01

Prerequisites: learner `bytes.checked` and `bytes.cursor` reasoning, the parent's bounded append contract, and AX-PR-T18-01-T18.02.a/b/c. Implement `api_append` from the public header. An `ApiBuffer` is a live, exclusively accessed typed object containing32 unsigned-char elements, a logical length and a capacity. Valid state requires length<=capacity<=32. A nonempty source is a live readable extent of n unsigned-char elements; the caller must establish its lifetime and extent. Zero length permits a null source and performs no source arithmetic/access. Output is a status and the updated buffer.

Admission order: reject null buffer, invalid length/capacity or null nonempty source as API_INVALID. Reject n>capacity-length as API_FULL. Then reject any source byte sharing an address with any byte of the complete ApiBuffer object's representation as API_OVERLAP. This deliberately conservative policy includes descriptor metadata. Use only defined byte-address equality or a justified equivalent; do not order/subtract unrelated pointers. The equality-scan reference model takes O(n*sizeof(ApiBuffer)) comparisons and O(n) copy work with O(1) auxiliary storage. A caller-supplied owner/offset variant may change this cost only with an explicit revised contract.

All rejected calls preserve every logical field and every data-array element. Success preserves the old prefix, appends source bytes and sets length to old length+n. Bytes outside the newly written suffix remain unchanged. The caller must not modify the source during the call. Do not compare padding bytes as logical state. The former foundations.owner test accepts overlap as a transfer variant; it does not certify this rejecting contract.

Inputs include initial[1,2], source[3,4], capacities3/4, empty-null, aliasing the data array, aliasing the length representation, invalid scalar states and maximal n rejected before access. Expected capacity outcomes are unchanged[1,2] and committed[1,2,3,4]. The visible suite enumerates all561 valid length/capacity pairs and33 admitted source extents (18,513 cases), with a separately computed field/byte expectation. Supply an independently written overlap case generator, proof of admission order, object-code/helper audit and a changed owner/offset design after at least seven days.

## api_depth.registry — PR-T19-01

Prerequisites: exact function pointer types, owner/borrow ledgers, finite generation identity, and AX-PR-T19-01-T19.03.a/b/c. Implement a serialized four-slot registry with callback/context/drop triples. Context ownership transfers only on successful add when a drop function is supplied; otherwise context is borrowed. Every context and the registry storage remain alive until their promised final use. Initialize only fresh storage or a fully destroyed registry after no old handles/callbacks remain. Direct field mutation is forbidden except the explicit exhaustion setup in the visible test harness.

Add requires a callback and output handle. A full/closed/releasing registry leaves output and ownership unchanged. Handles consist of slot index and a nonzero generation. Increment generation on allocation; never wrap. A freed slot at UINT32_MAX is retired permanently. Invalid index/zero generation is API_INVALID; an inactive/mismatched live slot is API_STALE. This identity model cannot validate a dangling registry pointer or synchronize concurrent access.

Dispatch snapshots all active handles in ascending slot order, with at most four invocations. Additions during dispatch become eligible only for the next dispatch. Removal during dispatch marks the slot and returns API_PENDING; it remains eligible in the current snapshot and its context is released only after dispatch completes. Pending slots cannot be reused. Self-removal of A from[A,B] therefore calls A,B and leaves B. Removing B from A also calls A,B once and then retires B. Outside dispatch, removal releases immediately and returns API_OK.

Recursive dispatch returns API_BUSY. Destruction requested inside a callback marks closing, returns API_PENDING and suppresses remaining snapshot callbacks; after the active callback returns, every owned active context is released once in slot order, the registry becomes closed, and dispatch returns API_CLOSED. Outside dispatch destruction is immediate. Repeated destruction of live closed storage returns API_OK without releases. Add/dispatch on closed state reject. Drop hooks may inspect their own context, but may not free or directly mutate registry storage; attempts to call registry operations while a drop is running receive API_BUSY. The registry must remain live through all enclosing API returns. These rules deliberately exclude terminal receivers freeing the registry; that distinct contract is taught in modern_composition.

Deliver traces for self-removal, removal of another callback, add-during-dispatch, destruction during A, capacity rejection, stale generation, repeated destroy, reentry and exhaustion. Visible tests assert callback and drop counts at intermediate points, not merely final state. Supply a hand-derived state machine and an independent bounded event-history test; analyze a changed immediate-suppression policy and a truly concurrent registry as separate delayed variants. Generation checks do not replace quiescence.

## Assessment and limitations

Submit implementation, invariants/ownership proof, exact commands and outputs, minimized mutant failures, resource ledger and the parent AX criterion's delayed transfer. Level0 violates a contract; level1 reproduces nominal traces; level2 derives boundaries and supplies independent evidence; level3 independently rederives the changed policy and its counterexamples. Each named AX objective must meet its own rubric. Two compiled mutants per anchor target overlap admission/failed mutation and premature removal/missed destruction cleanup. Rejecting those mutants is bounded evidence, not proof of all faulty implementations or learner mastery.

Graduated hints: first write admission/publication and eligibility/retirement as separate transitions. Then mark the last legal use of each context and the first externally visible write. Keep expected callback identities separate from registry membership after dispatch.

Only original local programs and synthetic contexts are used. No external targets, credentials, host security changes or hardware actions are part of this lab. Undefined dangling-pointer cases are reasoning tasks, not expected-output tests. Current actual execution comes only from the source-pinned campaign receipt; authored variants, independent assessment and physical validation are separate.

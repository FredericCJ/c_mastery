# B03 depth contract, version1

Original local teaching models and a C17 atomic mailbox; no devices, sockets or production targets are contacted. Profile C components use their own state transitions; the hosted harness uses standard library tooling. Assume 8-bit bytes and exact-width integers. Control/output/input objects are live, correctly typed and disjoint. Lengths describe actual accessible arrays. Null required control/output pointers return INVALID. Objects are initialized as specified and are not arbitrarily corrupted. Concurrent access to models requires external synchronization; only the explicitly declared SPSC mailbox permits concurrent roles. C17 is the baseline; N1570 supporting passages are C11 draft evidence. C23/implementation/ISA claims require separate source evidence.

`B3Writer` starts {bytes,length,0,0}. Buffer is borrowed immutable until terminal. Callback takes the unconsumed span and returns positive bytes transferred, -1 interruption with zero transfer, -2 would-block with zero transfer, 0 no progress, or any other negative value fatal. This is a synthetic adapter protocol, not errno values. Positive value must not exceed requested remaining bytes. Each `b3_pump` permits at most budget callbacks; budget0 yields, budget>64 INVALID. Interruption consumes quota and retries only within this turn. Would-block/zero returns WAIT without spinning; a positive short write advances only that prefix. Exhausted budget returns YIELD. Completion returns OK and terminal1; fatal or impossible oversized transfer returns FAILED and terminal2. Terminal calls do not invoke backend. Empty buffer completes without forming null-pointer arithmetic. Failed calls retain confirmed partial progress; no rollback or durability is promised. A lying backend makes external effects uncertain even if cursor remains bounded. Synchronous callbacks cannot reenter/mutate state or retain passed spans beyond their borrowed lifetime.

`B3Operation` starts all-zero. `start` requires no owned operation; creates ACTIVE and increments generation, at most3 starts in the owner's lifetime. IDs never recycle; fourth start FAILED unchanged. Owner remains live at stable identity until all callbacks quiesce. `event` with mismatched generation or no owned operation is STALE unchanged. TIMEOUT changes ACTIVE/CANCELLING to CANCELLING and returns WAIT while retaining ownership, with no report. COMPLETE in either owned phase wins: COMPLETED, owned0, reports+1. CANCEL_ACK is valid only CANCELLING and produces CANCELLED, owned0, reports+1. Other ACK is STALE. Every later event for that terminated request is STALE. Start leaves cumulative reports unchanged. Terminal event is a teaching-model guarantee of backend quiescence; real APIs may have different callback/ack semantics. This code does not reclaim memory or implement an OS cancel primitive.

`B3Device` is a synthetic host model, status bits0..3, data arbitrary unsigned, read/write counters. Init with values selected by test, upper status bits zero. `ack(mask)` accepts masks0..15 and performs one W1C write: status clears exactly selected bits and writes increments even for mask0. It performs no status read. Invalid mask changes nothing. `read_data` returns WAIT unchanged when status bit0 clear; otherwise returns data, clears bit0, increments reads exactly once. The model's hardware event injection is an explicit test transition setting status bits; no actual volatile pointer/address is used. No real board register behavior, bus width, barriers or lost-event guarantees follow from this model. Repeated identical events while a bit is already set coalesce: no software can reconstruct event count without additional device information.

`b3_due(now,start,delay,out)` uses an 8-bit monotonic tick representation modulo256. Delay must be0..127. Caller must separately establish the sampling/history assumption: true elapsed time since start is less than128 ticks. The function computes modular elapsed; values128..255 return AMBIGUOUS unchanged, but cannot detect a hidden full wrap. Admitted values set out to elapsed>=delay, including equality and zero delay. Invalid delay returns INVALID unchanged. The model says nothing about physical frequency, torn reads, drift or WCET. No unsigned-to-signed out-of-range conversion is permitted in the proof.

`B3Mailbox` is one-slot SPSC, exactly one producer and one consumer, stable live object, initialized before publication. `ready` is atomic 0 empty/1 full and payload is ordinary int. Producer loads ready with acquire (or seq_cst), returns WAIT if full, otherwise writes payload then release-stores1. Consumer acquire-loads ready, returns WAIT if empty preserving output, otherwise copies payload then release-stores0. Producer may overwrite only after observing empty through the reverse handoff. The public order functions are used by both operations and must return at least acquire/release respectively. No additional producer/consumer, reentrant call, concurrent init, payload escape or owner destruction is admitted. Init requires nonnull pointer and quiescence. Operations are bounded but no general lock-free claim is made until actual atomic support/helpers are audited. Host sequential tests and explicit order-policy checks are smoke/contract evidence, not exhaustive C memory-model or weak-hardware verification.

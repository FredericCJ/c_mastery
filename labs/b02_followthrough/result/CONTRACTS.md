# Counted result and compatibility follow-through

## Objectives, prerequisites and environment

This required companion covers X-T19-002, R1-R3, its owning-byte immediate variant and named delayed version/old-consumer variant. Complete PR-T19-02 and the actual B02 result API first. Bring its source, tag/member invariant, borrowed-lifetime diagram and failure tests. C17 with 8-bit bytes, exact-width integers and int capable of [-9999,9999] is the implementation baseline. Host verification uses libc formatting, Python integers and real allocation. The component uses only loops, arithmetic, actual B02 rendering and explicit allocation callbacks; no conversion or sum-type library supplies the mechanism. Strict M4 checks use a separate caller-backed allocation provider; a target execution is not a physical board observation.

The original B02 contract remains authoritative for its functions. Controls, output spans, counts and input spans are live, correctly typed and disjoint. All lengths describe accessible arrays; pointers cannot be validated portably. Controls are externally serialized, never copied while owning, and remain at stable addresses. Initialization requires fresh or fully reset nonowning storage. Callback code/context remains live, cannot reenter/mutate/destroy the component, retain temporary controls, or perform a nonlocal exit. Allocators return fresh disjoint suitably aligned storage of at least the requested length or NULL with no ownership; release is nonfailing and matches that allocation.

## Constructors and counted rendering

`bf_number(x,tag,out)` admits only tags0 integer and2 error and values [-9999,9999], returning INVALID for bad tag/output before RANGE. It writes the corresponding active union member and tag together. `bf_text` admits NULL only at zero length and copies a borrowed span descriptor. Every refusal preserves output. Neither constructor extends a borrow's lifetime. Feed these results to actual `b2_render`: capacity admission precedes writes, output has no terminator, and embedded zero/all256 octets remain bytes. The same numeric text is used for integer and error, with semantic meaning retained in the tag. Rendering is O(number of emitted digits/bytes), O(1) temporary storage for the bounded decimal domain. Zero-capacity empty text admits NULL output.

Exhaust both numeric tags, every integer [-9999,9999], capacities0..6 and eight-byte sentinel tails against independent formatting. Include unknown tags before payload access, both numeric range boundaries, empty/null/nonempty text, all octets and embedded zero. A live result with only tag9 assigned is legal to reject without inspecting its uninitialized union. Never execute a dangling borrow or mismatched active-member interpretation as a golden output.

## Owning bytes, move and take

`BfValue` has integer0, borrowed1, error2, owning3 and empty4 alternatives. The owning operations admit only their stated tags; `bf_value_render` adapts a valid active alternative to actual B02 rendering. `bf_clone` requires an empty destination, both callbacks and a valid source. It admits at most256 bytes, allocates/copies before publishing OWNED and returns FAILED on allocation failure with the destination unchanged. At zero length it publishes an empty owning byte value without invoking the allocator or release. Refusing a nonempty destination does not discard its owner.

`bf_move(dest,src)` requires distinct controls, empty destination and owning source; transfer publishes the destination and leaves source EMPTY. `bf_take` requires an owning source and an all-zero, nonowning `BfBytes` destination; it transfers the same allocation then empties the source. `bf_bytes_drop` first empties the descriptor and then calls the cached matching release once if a block exists. `bf_reset` first empties an owning control then drops its block; resetting other valid alternatives simply empties them. Repeated reset/drop is harmless. Move/take are O(1), cloning O(n) time/one allocation, reset/drop one callback. No hidden refcount exists. Shallow C assignment of an owning value duplicates authority and violates the API: ISO C does not insert move checks, destructors or lifetime tracking.

Use the static recording allocator to observe every transition and the hosted malloc/free provider to demonstrate actual allocation, copied bytes and exactly one release across clone/move/take/reset. Inject allocation failure before publication. Check original source mutation does not change cloned bytes. Count empty allocations separately. Compare borrowed and owning resource costs under equal output contracts. No allocator mutation, destructor failure or concurrent access is claimed by this version.

## Delayed wire version and old consumer

The wire representation is independent of C struct layout: `[version,tag,length-high,length-low,payload...]`, version1 or2, big-endian unsigned length<=256, exact total length4+length. Integer0/error2 payload is exactly four octets encoding signed32 two's-complement mathematics, admitted value [-9999,9999]; decoder computes the negative value without an out-of-range unsigned-to-signed cast. Text1 is counted bytes. New boolean3 exists only in version2, length1 and value0/1. Version2 also accepts old tags. `BfWire` is an in-process decoded record, not serialized by copying its object representation; only the selected fields are semantically relevant. `bf_encode` validates all semantics and capacity before output/count publication. `bf_decode` stages the whole decoded record and preserves output on malformed/version/tag/range refusal. Unknown fields are rejected, not silently reinterpreted. Length admission precedes payload access.

`old_api.h` and `old_consumer.c` form the prior version1 consumer. Compile that source once as a separate object without the new producer header, then link the new producer and the old object. The old consumer accepts version1 tags0..2, rejects version2 and version1 tag3 before payload use, and preserves output/count on rejection. Actual builds record this separate translation unit. The test is source-independent wire compatibility on the recorded ABI, not a promise that changing a C struct/enum preserves binary layout. Changing field order, ABI/data model, or old function signatures requires new analysis. A version1 unknown tag is not rescued by having a version2-aware producer.

## Diagnostics and enforcement

Compile the supplied enum-switch omission with `-Wswitch-enum -Werror` under GCC and Clang; it must be rejected, while the complete branch set compiles. With a default branch and ordinary `-Wswitch`, the same omitted enumerator may compile: record actual diagnostics. An unsigned-tag switch has no enumerator set for that warning to enforce. These diagnostic comparisons are implementation behavior, not an ISO C requirement for exhaustive switches. C enforces member types and expression constraints; constructor tag agreement, borrowed lifetime and unique ownership require API discipline/runtime checks. An algebraic datatype can make alternatives and pattern exhaustiveness language-level checks, but its exact ownership/FFI guarantees depend on the language and boundary. Do not claim an arbitrary ADT prevents all invalid external wire values.

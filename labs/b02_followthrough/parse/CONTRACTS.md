# Counted integer parsing: radix, streaming and hosted adaptation

## Original obligations and representation

This required successor supplies `X-T12-002`, R1-R3, its immediate separately supplied base variant and `X-T12-002-DELAYED`. It imports the actual unchanged `b2_parse` for the decimal comparison. Prerequisites remain X-T04-001 checked arithmetic and the original B02 counted-span contract. The existing exercise and historical campaign identities are preserved.

`struct bf_parse` owns only scalar tentative state: radix2..36, OPEN/FINISHED/CANCELLED phase, sign/digit/leading-zero flags, sticky invalid/range flags and bounded unsigned magnitude. No input pointer or string is retained. Live control, counted input and output storage are disjoint; lengths describe actual accessible bytes. Control is exclusively accessed and arises from reset/legal transitions. Null input is allowed only at length zero. Reset may initialize fresh storage or discard tentative/final state; there are no external resources to destroy. Arbitrary forged control, concurrent mutation and dangling pointers are outside this API.

## Grammar, operations and failures

Radix is a separate argument, never inferred from a prefix. The ASCII wire grammar is `0` or an optional minus followed by a nonzero uppercase digit and zero or more admitted uppercase digits. Digits are `0`..`9`, `A`..`Z` with numeric values below radix. Lowercase, plus, whitespace, prefixes, negative zero, leading zeroes, embedded NUL and suffixes are invalid. Range is exactly signed32. The complete grammar takes precedence over range: 1000 valid digits followed by `!` is INVALID even when its numeric prefix overflowed.

Reset with unsupported radix refuses unchanged. Feed on OPEN consumes the complete supplied chunk, returns OK and retains any syntax/range error for finish; it does not publish a number. Its pointer-argument failure preserves state. Feed after finish/cancel returns CLOSED, including an empty feed. Finish with null output preserves phase; otherwise it seals the parser, returns INVALID before RANGE and publishes only on success. Repeated finish returns the same result under the unchanged-output premise. Cancel is allowed in every initialized phase, discards magnitude and makes finish return CANCELLED without publication. Reset revokes that cancellation and starts a new independent token. No finite length counter is required, so arbitrary many chunks do not silently wrap such a counter.

The magnitude update proves `m <= (limit-digit)/base` before multiply/add, with limit2147483647 or2147483648. Once overflow is known, further valid digits need no arithmetic but must still be examined for syntax. The negative endpoint is assigned directly. Total work is O(total input bytes), state O(1); the original decimal implementation has separate syntax/range passes. Empty input and a lone minus remain invalid at finish. These are runtime checks and caller ownership premises, not ISO C borrow checking.

## Hosted comparison and exact source boundary

`bf_parse_libc` is verification-only. It independently admits the strict grammar, copies and NUL-terminates the counted span, clears errno, calls actual `strtol`, checks full consumption and signed32 range, then publishes. Allocation failure is FULL and preserves output. Its temporary storage is O(n); it is forbidden as the target mechanism. The harness selects C and C.UTF-8 locales in a single-threaded process and records LONG width. Canonical admitted ASCII inputs have no locale-dependent spelling. The target core uses octet values independently of execution character spelling; the hosted comparison explicitly asserts ASCII execution characters.

Inspected [N1570 7.22.1.4 paragraphs1-8](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf) describes prefix conversion, end-pointer, radix, locale and range behavior. A zero return alone cannot distinguish conversion from no conversion. The strict counted grammar is an additional application contract. N1570 is a C11 draft; the exact published C17 and C23 texts remain unavailable. No C23 binary-prefix extension is assumed: target baseline is C17 and grammar never admits prefixes.

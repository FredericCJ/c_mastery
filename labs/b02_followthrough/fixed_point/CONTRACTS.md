## Q7 and signal units

The unchanged b2_q7 admits n<=1024 int8 pairs, forms exact widened products, sums them, divides once by128 with nearest ties away from zero, then clamps once to[-128,127]. Empty produces0. Maximum absolute product is16384; every prefix magnitude is at most16777216, and adding rounding bias64 still fits int32. Cast each operand before multiplication so integer promotions on a narrower int do not choose the product width accidentally. Taking absolute magnitude is safe here because the proven domain excludes INT32_MIN; that is not a generic abs implementation.

bf_q7_even keeps the same exact accumulation and final clipping, but uses quotient parity to choose the even retained integer on a half tie. For raw totals64,192,320 and their negatives, even outputs0,2,2 and0,-2,-2. The parity applies to the retained quotient, not the original input. Two products1*64 sum to128: round-once returns1, per-term ties-away returns2. A large positive prefix followed by cancellation must not saturate early. Correct order is exact products, exact sum, one rounding decision, one final clipping decision.

BfSignal supplies a concrete synthetic sensor/control workload. Samples represent stored_integer/128 volts; gains represent stored_integer/128 dimensionless ratios. Therefore product_sum/16384 is the exact voltage computed from these quantized inputs, while output/128 is the represented output voltage. rounded_raw is the unbounded rounded output integer; clipped identifies endpoint clipping; error_numerator=(output*128-product_sum) gives actual voltage error over denominator16384. The adapter invokes actual b2_q7 for output, then records this independent units ledger. It publishes the entire result only on success.

For an unclipped result, arithmetic rounding error is at most1/256 volt, half an output quantum. For sample=-128 and gain=-128, exact voltage1 clips to127/128; error is-1/128 volt, so the half-quantum bound no longer applies. Physical sensor/input quantization errors are separate: with input errors e_x and e_g, one product adds x*e_g+g*e_x+e_x*e_g to the error relative to the unquantized product. Sum those bounds before adding arithmetic rounding; clipping requires its own endpoint-distance term. No physical sensor error is measured here.

## Exact scale16 legacy tasks

PR-T04-03 uses q/16 with signed stored q in[-128,127]: range[-8,127/16], quantum1/16. Scale32 changes the range to[-4,127/32] and quantum1/32; improving resolution reduces range. These conventions must accompany each input. bf_mul16 represents the product by rounding a*b/16 once and clipping to the same stored range. BF_AWAY and BF_EVEN select the specified tie policy; any other mode or null output is INVALID and preserves output. Inputs are passed by value. All integer products lie in[-16256,16384]. The required examples(3,8),(-3,8),(64,64),(0,127) give2,-2,127,0 with ties-away; only the third clips. Both-sign ties with even/odd retained integers discriminate the changed policy.

BfSmall stores the exact ideal output raw integer as raw_numerator/raw_denominator, the rounded_raw integer, clipped output and error_numerator=(output*raw_denominator-raw_numerator). Divide that error by16*raw_denominator for real output units. For multiplication the raw denominator is16. Unclipped real error is at most1/32; after clipping, use exact endpoint distance instead. No unsafe absolute minimum or negative shift is needed because the admitted numerator bounds are known.

bf_mix16_32 takes two voltage channels a/16 and b/32, converts before addition, and emits scale16: ideal raw output is(2*a+b)/2. The exact numerator is in[-384,381], and rounding/clipping follow the same selected policy. Inputs16 and32 both mean1 volt; output raw32 means2 volts. Adding the raw integers without scale conversion produces the wrong physical quantity. Scale32's narrower representable input range is retained; no storage widening is silently assumed.

bf_two16 computes two actual rounded/clipped scale16 multiplies: first a*b, then its represented result times c. The exact unquantized composition of these stored inputs is a*b*c/4096. error_numerator=(final_output*256-a*b*c) uses denominator4096. Products remain in int32. If neither stage clips, the first rounding error is magnified by |c|/16, so the real error bound is |c|/512+1/32, represented as bound_numerator=(8*|c|+128) over4096. bounded is false if either stage clips. The witness(3,8,127) gives first raw2, final raw16, error1048/4096 and bound1144/4096; merely adding a second half quantum would understate the error. This is arithmetic error relative to already quantized operands, not a bound on unknown physical input errors.

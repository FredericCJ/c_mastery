## Probe and rehash contracts

Every original get/put/remove visits at most seven slots. A first tombstone is a possible insertion location, not proof that a later equal key is absent. Replacing an existing key in a full table succeeds without increasing count; a new key fails unchanged. Deleting leaves a tombstone; a fully tombstoned table still terminates. Count measures live entries, while nonempty occupancy also includes deleted entries. No randomized constant-time guarantee follows from key modulo seven.

`bf_map_rehash(map,scratch,capacity,fail_after)` clears tombstones at the existing capacity seven. This is explicit maintenance, not a resizing API. It requires scratch capacity at least seven and a failure selector0..7; invalid admission changes neither object. Zero disables injected failure. A positive selector returns FAILED immediately after that many live entries have been staged; if fewer live entries exist, that failure point is not reached. Failure leaves every original field unchanged but may modify the first seven scratch entries. Success publishes all seven replacement entries only after all live entries were staged. The live count and key/value relation remain unchanged; scratch entries beyond seven are untouched. The caller owns scratch before and after the call, and may reuse it afterward. No borrowed pointer into scratch escapes.

Derive the invariant that, before staging entry k, exactly k original live entries are reachable in scratch and at most k slots are live. Therefore insertion of the next entry has an empty location. The commit is an externally serialized, nonfailing field-copy phase; this is not machine-atomic publication to concurrent observers. Work for capacity C and n live entries is O(C+nC), scratch C typed entries, auxiliary stack O(1). Here C=7. Compare that same-capacity cleanup with the existing CDHash manual resizing contract; this packet does not silently claim a new resize algorithm.

## Changed key ownership

`struct bf_borrow_map` is an original four-slot teaching target that stores a pointer, length and value, using the same bounded hash/equality algorithm as the copied provider. Byte keys have length0..8, including embedded zero; null input is admitted only with zero length. An admitted borrowed key is immutable for its entire table membership. No deletion is exposed; quiescent owner destruction ends all borrows. Put replaces an equal key's pointer/value, so the newly supplied backing must satisfy the same lifetime. Get preserves output on missing or invalid admission.

The local counterexample inserts live bytes `{65,0}`, then changes the first byte to66. Both original-key and mutated-key queries fail because equality and original bucket placement no longer agree. All backing remains live, so the demonstration exposes a logical ownership-contract violation without executing invalid memory access. The repair calls actual `cd_bytemap_put` while original bytes are still available; later buffer mutation leaves the copied key reachable. A second repair uses genuinely immutable live backing. Include colliding `{69,0}`, empty and embedded-zero keys. Copying cannot repair inconsistent hash/equality relations, and `const` alone cannot prevent mutation through another alias.

# Service depth contract, revision 1

These are four original, inspectable C17 mechanisms used to close specific gaps in the retained T56 contracts. They are required additions, not replacements for the kernel projects. The public header is the exact ABI. Status values are enumerated there. All calls are serialized by one owner. Inputs, outputs, controls and callbacks refer to live, suitably aligned, disjoint objects unless an operation explicitly shares an internal representation. No concurrent mutation, callback reentry, forged control structure, or retained borrowed pointer is permitted. C does not enforce these conditions. No operation allocates from a host heap. Target code may use only type/limit headers and original byte loops; Python, sanitizers and test C library calls are host verification dependencies.

Zero initialization creates SDMemory and SDJournal. Other controls must be initialized before use. Reinitializing a live control while references remain is prohibited: doing so could resurrect stale capabilities. Null required controls/outputs return SD_INVALID except where the documented precedence first rejects a capability. Failure leaves outputs and logical ownership unchanged except SD_UNCERTAIN journal progress and terminal channel retirement described below. Padding bytes are not a portable state comparator; tests may compare unchanged copies of the same object representation.

All exact-width types in this profile must exist, CHAR_BIT is 8, and file names use ASCII execution characters. C17 unsigned arithmetic is modular; signed overflow is forbidden. Endian conversions are arithmetic, never packed-structure casts. C11 introduced the exact concurrency facilities required by the retained SMP kernel but this core deliberately has no atomic/thread claim. C23's representation changes do not grant pointer lifetime, copyout validity or durable ordering. A C2x syntax run is only a compiler probe. Cortex-M4 compilation/link inspection is not execution, an MMU implementation, or a persistence experiment.

## Memory: X-T56-002

SDMemory owns 16 actual 64-octet backing arrays, each with a reference count. An SDImage owns one reference to each of at most four distinct frame indices; active images have length 1..256 and count ceil(length/64). Callers may inspect frames/bytes but may not forge ownership. Unowned frame contents have no preservation contract. Last release clears all 64 octets before the frame becomes available. Counts are bounded at 65535. PTEs, TLBs, remote CPUs and hardware permissions are outside this model and require the explicit kernel adapter deliverable.

`sd_load(m, data, n, fail_after, out)` accepts n=1..256. The output is live descriptor storage that owns no previous image; its fields need not be initialized because this constructor does not read them. Release any owned image before reusing its descriptor. This is construction, not checked replacement. It selects lowest free frames, initializes every byte (zero tail), copies input, and publishes out only after all frames succeed. fail_after=-1 disables injection; nonnegative k rejects allocation number k (zero based), if reached. On exhaustion/injection return SD_FULL, release only allocations made by this invocation, preserve existing owners and output. Released temporary frame bytes may be cleared. n=0, n>256, null inputs, or fail_after<-1 return SD_INVALID. The input must not alias backing memory or output. Construction costs O(n + 16*ceil(n/64)), with one bounded temporary descriptor.

`sd_clone(m,parent,live_threads,out)` admits exactly one live thread and only kind=0 private ordinary frames. kind=1 shared or kind=2 device mappings return SD_DENIED; other nonzero kinds are denied too. Invalid thread count/image shape returns SD_INVALID. Invalid frame indices or absent/saturated references return SD_FULL. Check the complete image before modifying any parent COW bit or reference. Successful clone increments each reference and marks parent and child COW. Parent and out are distinct; out owns no previous image. This is the deliberately restricted project profile: the retained kernel currently inherits PTE_SHARED, so the adapter must explicitly reconcile that behavior instead of claiming the profiles match.

`sd_write(m,image,offset,value,allocation_allowed)` requires offset<length and allocation_allowed in {0,1}. A shared frame needs a fresh complete copy before decrementing its old reference and publishing the new index. Failure is SD_FULL and changes nothing. A sole owner writes in place even when allocation_allowed=0, then clears its COW flag. `sd_release` validates its whole ownership list before releasing, makes the descriptor inactive, and rejects a repeated release. The contract assumes unique frame indices within each valid image and globally consistent counts; arbitrary memory corruption is not repaired by this API. Clone/release are O(number of frames); write copies at most64 octets and scans at most16 frame slots.

## Byte channel: X-T56-003

SDChannel owns two messages, each up to32 octets. `sd_channel_init` on fresh quiescent storage establishes epoch1, open, empty. SDCap is trusted owner-side metadata, not an unforgeable userspace token. A real syscall adapter must resolve an opaque handle against a protected rights table. Rights are SEND=1, RECEIVE=2, CLOSE=4. `sd_grant` only attenuates an existing current-epoch capability to a nonempty subset; output changes only on success. Invalid requested rights return SD_INVALID; an insufficient source right returns SD_DENIED. Retired or mismatched epoch is SD_STALE before rights checks.

`sd_send` copies the complete span into the tail before making it visible. n=0 permits NULL; n>32 is SD_INVALID. Closed returns SD_CLOSED, two queued messages SD_FULL. Input ownership remains with caller and its lifetime need only cover the call. `sd_receive` requires RECEIVE and a size output/validator. Empty returns SD_EMPTY, or SD_CLOSED after close. Insufficient capacity/null nonempty output returns SD_FULL. SDValidate(ctx,destination,exact_length) returns zero only when the whole extent can be written without fault for the duration of the following copy. It performs no writes, cannot reenter/mutate any participating object, and retains no pointer after return. Nonzero yields SD_COPY, preserving destination, length output, head and message. A successful validation is followed by the complete copy, length publication, and exactly one dequeue. Zero-length messages still invoke validation once with length0. Validation is a model of a stable pinned copyout extent; a real pageable kernel must establish that premise or implement a different partial-progress contract.

Close is idempotent and preserves queued messages for draining. Reopen is a trusted lifecycle operation, allowed only closed+empty. It increments epoch without wrapping; at UINT32_MAX it sets retired and returns SD_FULL. That terminal retirement is the documented state-changing failure; subsequent reopen is SD_STALE. Old capabilities cannot act on the new incarnation. Queue operations have fixed bounded costs; copy costs O(message length), no allocation or blocking. Wake queues, cancellation and SMP locking remain kernel adapter obligations.

## Read-only files: X-T56-004

SDFiles contains1..4 borrowed immutable entries,4 open descriptions and8 handles. An empty namespace (n=0) returns SD_INVALID without changing the output control; empty files within an admitted namespace are supported. Entry names are NUL-terminated ASCII strings of1..11 characters drawn from [a-z0-9_.-], excluding `.` and `..`; every supplied name pointer must be readable until its NUL or12 bytes. Data length is0..256; NULL data is allowed only for empty files. Names/data remain live and unchanged until all associated handles close and the filesystem is discarded. `sd_files_init` validates the complete namespace, including duplicates, before publication; fresh/quiescent-only initialization cannot invalidate existing references.

`sd_open` performs exact-name lookup and allocates the lowest free handle and description. Unknown/invalid names return SD_INVALID. Each open creates offset0 independently. `sd_dup` allocates a new handle referring to the same description and offset. Lack of either resource is SD_FULL. A handle is index+generation; generation increments on each admission and never wraps. An inactive handle at UINT32_MAX is permanently unavailable. `sd_close` removes exactly that reference, frees the description on its last handle, and returns SD_STALE for stale/double-close handles. The exposed structures are diagnostic state, not a secure userspace ABI.

`sd_seek` origins0/1/2 are beginning/current/end. Compute in a wide signed temporary and admit only [0,file length]; this profile rejects seeks beyond EOF. `sd_read` requires requested<=capacity, a length output and SDValidate with the same nonreentrant stable-extent contract as channel receive. Copy min(requested, length-offset) bytes; at EOF or request0, NULL output is legal and validation still occurs with length0. No null-pointer arithmetic occurs. On validation failure return SD_COPY with offset, output length and output bytes unchanged. On success publish copied length and advance the shared description once. Partial writes, mutable files, pathname resolution, mount namespaces and OS descriptor conventions are excluded from this original contract. Lookup/admission scans fixed4/8 slots; reads cost O(bytes copied).

## Durable receipt: X-T56-005

SDJournal owns two 32-octet durable slots and two volatile pending buffers. This is an explicit **atomic32-octet flush** fault model: copying a whole pending record to its durable slot is indivisible and persists; interruption may occur only at the four declared points. It is not a model of arbitrary sector tears, DMA, real filesystem fsync, Byzantine storage or concurrent writers. Actual disk experiments must state and implement their own persistence contract. Reset discards pending, never durable. Tests may mutate durable bytes for bounded corruption demonstrations, but the checksum is not authentication.

Record fields are little-endian u32: magic0=0x53445231, nonzero operation ID4, signed32 delta8, signed32 resulting value12, FNV1a checksum16 over bytes0..15 (initial2166136261, multiplier16777619, unsigned32 wrap), commit20=0xc017c017, zero padding24..31. Decode signed values arithmetically. Recover ignores slots without the exact commit marker; committed invalid magic/zero ID/checksum or duplicate IDs return SD_CORRUPT without publishing output. Otherwise select greatest ID, or receipt {0,0,0} if neither committed. No hash authenticity, arbitrary corruption detection, adjacent-ID proof or full historical replay is claimed; corrupting a commit marker can make a record appear uncommitted.

`sd_apply(j,id,delta,fault_stage,out)` admits id>0 and fault0..4. Retry of the current committed ID and same delta returns its recorded value; same ID with another delta is SD_CONFLICT. Older IDs are SD_STALE because only the latest receipt is retained. A fresh ID must equal last+1 without wrap. Signed result overflow returns SD_FULL before journal/output changes. Prepare in slot id&1 with commit0; flush the prepared record; write commit; flush the committed record; then publish result. Fault1 interrupts after volatile prepare,2 after first flush,3 after volatile commit,4 after committed flush before result publication. All return SD_UNCERTAIN with caller output unchanged. Recover sees the previous receipt for1..3 and the new receipt for4. Retry after4 must not apply the delta twice. A reported SD_OK requires a committed durable receipt. SD_UNCERTAIN permits durable progress, so it cannot be treated as rollback. Costs are two bounded record writes/flushes and fixed recovery work. ID exhaustion requires an explicit external epoch migration, never wrap.

## Composition and evidence

The supplied composition reads a synthetic request from an immutable entry, copies it through the byte channel, applies its delta through the journal, discards volatile state at an injected interruption, and retries the same ID. Failed copyout must preserve the message/offset and cannot create an effect; a durable retry cannot create a second effect. The program owns every byte and never opens external files, sockets or devices. It demonstrates cooperation among these cores, not full user/kernel boundary integration.

Each exercise requires D1 contract/representation derivation, D2 implementation plus a source-identified adapter into the corresponding retained learner kernel component, D3 independent expected results, two mutant diagnoses, failure/resource/portability evidence, and D4 delayed changed-condition assessment. The portable anchor and composition are executed by the author campaign; the real kernel adapter remains a learner deliverable and may not be claimed from these logs. The separate assessor sources are excluded from learner publication.

## Local security scope

Targets are only these original controls and deliberately mutated teaching implementations, run as a local unprivileged process or in a disposable teaching VM. The attacker chooses synthetic requests, capabilities provided by the harness, names and injected scheduling/failure points; it cannot write arbitrary protected metadata in the corrected profile. Harmless success conditions are a leaked frame count, a byte received without RECEIVE permission, a changed offset after rejected copy, or a falsely acknowledged/doubled local integer effect. Mutants exhibit those specific violations, not arbitrary execution or privilege escalation. Preconditions, exact transition and residual limits must accompany every claim. Repairs restore preflight, ownership and durable publication; regression tests preserve successful behavior and reject both semantic mutations. Kernel transfer must use a disposable VM, no production targets, real secrets, host security changes or hardware flashing.

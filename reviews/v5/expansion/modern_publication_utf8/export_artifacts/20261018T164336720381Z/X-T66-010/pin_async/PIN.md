## Representation and admitted calls

`OpaMachine` owns no storage. It combines one actual `OwPin`, one actual `FAsync`, a completion-executor identity, notification/recovery flags and a result. Initialize only a fresh or quiescent nonowning control. Keep the control, backing object and callback contexts live and at stable addresses until terminal cleanup; do not copy controls with pending work. The core is externally serialized. Logical owner7/executor9 are ordinary untrusted integers, not native thread identity or a security boundary. A valid live address comparison is not proof of a whole allocation's extent or lifetime. Inputs, controls and output objects are disjoint; callers do not corrupt public representations.

Submit preflights both the operation-generation and terminal-release counters. UINT32_MAX is a legal final issued generation and a legal final release count. When no terminal capacity remains, refuse before publication and preserve output. A successful submit publishes one pending pin and one `FAsync` operation together. Cancellation records a request; repeated cancellation is idempotent in this adapter. Timeout additionally enters RecoveryRequired. Neither transition permits reuse, movement, destruction or a second operation.

An exact current ticket from the completion executor may notify once. Notification stores the result but does not complete `FAsync`, clear pending or release the address. Wrong executor is INVALID; stale ticket is STALE. `opa_finish` requires a separate **trusted backend quiescence fact**. It checks the current pending notified operation, invokes actual `f_complete` once, completes the pin and publishes the result last. The core cannot establish the trust premise. A client that calls finish after notification alone violates the contract even if checks pass.

## Real host executor

`OpaPort` is initially zeroed, fresh nonowning storage. It owns a noncopyable pthread mutex/condition and at most one joinable worker; it borrows 1-16 int32 elements. Initialize on the owner thread. Public port operations check `pthread_equal(pthread_self(), owner)`. All core/control transitions use the same mutex. Value input is -1000000..1000000, ensuring the bounded worker's sum is representable.

Start reserves the pending operation before creating the thread; creation refusal restores the old core and leaves the output ticket unchanged. The worker waits on a supplied laboratory gate, then writes `value+i` to every element even if cancellation or timeout has already been requested. This deliberately models a backend that cannot be stopped by a request. It notifies under the mutex and invokes the receiver on the worker outside that mutex. Receiver, context and backing remain live; the receiver must return normally, must not destroy/move the port or backing, and must not reenter lifetime-changing operations. It may demonstrate that an owner-only port operation rejects the foreign executor. No asynchronous thread cancellation, nonlocal callback exit or owner-thread death is supported.

Only after the receiver returns does the worker publish its `done` flag. Even that flag is insufficient: the owner must successfully call `pthread_join` before finishing the core. `join(wait=0)` refuses while done is false, but can still wait briefly for thread exit after observing done; it is not a nonblocking join API. `join(wait=1)` also waits for done. A failed join retains the operation and all borrows; no timer establishes a retry bound. A successful join is retained so an unexpected protocol refusal cannot cause a second join. Rebind/destroy refuse while an operation is started. Destroy requires the owner and no other active caller; synchronization-error recovery outside these valid-object premises is not promised.

Required trace: start with three allocated elements; timeout before opening the backend gate; refuse rebind/destroy/join. Open the gate and hold the foreign receiver on a separate condition. Observe notified=true, pending=true, recovery=true, done=false and releases=0. Rebind and another start still refuse. Return from the receiver, join, observe values40,41,42/result123, exactly one terminal release, then rebind and release the old typed allocation. Run a second operation to expose stale-generation mistakes. All allocation owners and synchronization objects must be drained after actual joins.

## Device stage: actual Pd provider, explicit model boundary

`OpaDma` combines the same owner protocol with the exact retained `PdTransfer` and `PdIo`. The stable `scope` address identifies a live lease owner covering **all source and destination payloads** admitted by Pd. It is not a fabricated native pointer corresponding to an integer bus address. Preserve Pd's board, width, capacity, overlap, cache-line exclusivity and callback rules from its contract. In particular configure refusal leaves the stream disabled; configure cannot publish, and enable/stop/snapshot/visibility are bounded nonreentrant operations under the specified target premises.

Publish the owner pending state before `pd_submit` can enable a transfer. On configure refusal no hardware operation has begun: restore the old owner and preserve the ticket. Timeout asks actual `pd_cancel` to stop but retains the owner. Poll cannot release on a stale snapshot, enabled stream, nonempty FIFO or absent transfer-complete flag. Only actual `pd_poll` success followed by actual `pd_finalize` authorizes the owner notification/terminal transition. Preserve a finalized result for retry if an unexpected later protocol refusal occurs, without finalizing twice. Publish the caller's `PdResult` only at the successful terminal transition.

The supplied native model uses two actual live 16-byte arrays and separately validated F439-shaped numeric bus ranges. It writes four bytes after timeout while enabled, then four more after EN=0 while the FIFO is still nonempty. The observer must remain BUSY through both, through an absent TC flag, and through a wrong snapshot token. Matching disabled/FIFO-empty/TC state finalizes CANCELLED with8completed/8possibly-written bytes. A separate error state after four writes returns IO with0completed/16possibly-written bytes. A possible-write bound is not evidence that all those bytes were written, nor permission to retry a side-effecting peripheral. No model operation accesses actual MMIO.

For a dedicated physical extension, retain the exact board/revision, memory map, cacheability, peripheral direction, DMA stream/FIFO mode and manual clauses. Instrument stop request, observed EN, FIFO-drained evidence, flags, barriers/cache maintenance and the final buffer-reuse event. Capture independent bus/peripheral evidence capable of detecting a late write; merely observing the same C flags is not independent confirmation. Include a delayed completion/error run and show that the old buffer is retained until the documented condition. Never flash deployed equipment or change host security settings. Until such a controlled run exists, physical quiescence remains **not run**, including for the already compiled target provider.

## Verification and falsification

Seven anchors separate retained pin semantics, timeout, notification, identities, finite counters, actual pthread execution and actual Pd composition. Eight independently compiled controls remove timeout retention, notification retention, executor checking, cleanup headroom, retained pin pending/thread checks, adapter pending retention or Pd's quiescence gate. Require an intended OW_CHECK assertion with exit1; a compile failure, signal, sanitizer diagnosis or timeout is not a killed semantic control.

The Python oracle enumerates all37449words of length0..5 over eight core events and compares complete state/output traces. Its finish event supplies abstract quiescence; it is not a device or C memory-model oracle. Boundary tests independently exercise MAX counters, because the finite histories do not reach them. Six GCC/Clang C17 debug/optimized/ASan+UBSan profiles and separate GCC/Clang TSan host runs retain exact source/command/runtime identities. The actual C tests compare a copied self-referential record's pointer against two live objects without dereferencing a dangling pointer. Do not manufacture invalid pointers as an execution oracle.

Preserve source-level predictions, output canaries, typed allocation counts, real thread identity observations and failure histories. Report which callback outcomes or platform errors were injected and which were not. A clean sanitizer execution does not prove all schedules, correct physical DMA behavior, memory allocation lifetimes outside the API or caller compliance.

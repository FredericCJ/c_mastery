# Original network and HTTP variants

This required companion retains X-T41-001 and X-T42-001 through X-T42-004 and their original rubrics and variants. It adds missing implementations; it does not replace the earlier gates or retroactively change accepted evidence. Use C17, exact uint16_t/uint32_t, eight-bit octets and ASCII wire characters. Core functions use live, aligned, valid caller objects and bounded borrowed spans; no pointer is retained. Refusal preserves all outputs except the specified successful Date omission. Partial overlap of byte inputs and outputs is forbidden; summary values are passed by value and may be combined back into either original summary object. Caller objects and ordinary controls are serialized unless the owned-descriptor contract below explicitly supplies synchronization.

## Independent checksum segments — X-T41-001 R1/V1/V2

Implement `nv_sum` by explicitly importing the learner's `SChecksum` add/finish component. Represent each independently computed span by its uncomplemented numeric network-order sum and length parity. Empty is `{0,0}`; keep the distinction between raw positive zero and all-ones negative zero. `nv_combine(a,b)` denotes concatenation, not unordered addition: when a has odd length, byte-swap b's folded sum before end-around addition. Combine parity with exclusive-or. No hidden padding enters the concatenated message. Derive associativity with this parity action and explain why swapping segment order generally changes the checksum despite commutative word addition. Include a counterexample where forgetting the odd-offset swap passes even splits.

Construct three independently stored segments: IPv4 TCP pseudoheader, 20-byte synthetic TCP header and five-byte payload. The supplied 37 octets are local fixtures only; the TCP checksum field is zero. Compare every partition of the fixture, the existing streaming implementation, independent mathematical expected words, and both association orders. Finish must not mutate the streaming provider. Explain why checksum agreement is neither authentication nor a collision-free integrity proof. No raw sockets or external traffic are required or authorized.

## Declared wire maxima — X-T42-002 R1–R3/V1/V2

Implement `nv_length(bytes,n,maximum,cap,out)` for any uint32 maximum, including 0 through 9. Cap is 0 through 1024. Nonempty decimal syntax is required; leading zeroes are legal. Malformed syntax or a value exceeding the declared wire maximum returns 400. A valid wire value exceeding cap returns 413. Success publishes the value; all refusals preserve it. Derive quotient/remainder admission (`value < maximum/10`, or equal with `digit <= maximum%10`); explain the underflow in `(maximum-digit)/10` when digit exceeds maximum. The malformed suffix of `1025x` dominates the storage cap. Neither a 64-bit host nor 16-bit size_t changes the declared wire domain. Use the actual earlier AVR profile for the original fixed maximum, and keep that emulator observation distinct from this native generalized implementation until its target campaign runs.

## Calendar cycles and source authority — X-T42-003 R1–R3/V1/V2

Replace year iteration with decomposition into 146097-day Gregorian eras, capped century and four-year components, followed by at most eleven month steps. Derive 719162 days before 1970. The domain remains days 0..2932896 and ordinary seconds 0..86399, producing exactly 29 bytes plus NUL. Available=0 publishes length0 and touches no output bytes, even if the other time/capacity arguments would be unusable. Invalid available values and missing length pointers reject. Compare the complete 2000–2399 cycle with the actual previous implementation, independently sample the full 1970–9999 domain with Python datetime, and record iteration counts separately from measured elapsed time.

`NVStamp` separates availability, trust and scale. Unavailable or untrusted readings omit Date. Trusted ordinary UTC uses the original subset. TAI and smeared time reject; no implicit offset or unsmearing is invented. A positive-leap reading has second86400 and an externally attested exact UTC day, then emits 23:59:60 on that same calendar day. The adapter rejects a missing/mismatched attestation. Gregorian leap-year rules cannot predict leap seconds. The synthetic attested 2016-12-31 case tests representation, not current clock accuracy, a verified historical bulletin, or future scheduling. Negative leap scheduling and attestation retrieval remain explicit external-source extensions; they are not silently inferred. Clock values never drive the transport's monotonic deadlines.

## Concurrent descriptor ownership — X-T42-004 R1–R3/V1/V2

Implement the Linux pthread adapter over the actual `HFPool` provider. NVOwned has one mutex and four records. Initialize fresh control storage once; never copy a mutex, live control or active lease. A candidate descriptor belongs exclusively to the submitting caller; its flags and lifetime must remain stable through admission. Verify actual O_NONBLOCK and FD_CLOEXEC. Success transfers ownership to the pool; any refusal leaves it with the caller and preserves the handle output. Raw `HFPool` access is forbidden during use; test-only near-exhaustion seeds are set while quiescent before publication.

Borrow validates incarnation and the nonclosing state under the mutex, increments a pending pin, and publishes a unique, noncopied NVLease containing the descriptor. The lease gives its exclusive owner permission to perform bounded I/O until release. No second thread may manipulate that same lease object. Close linearizes by marking closing under the mutex and rejects later borrows immediately. If pins remain, it retains the actual descriptor, slot and generation; it does not close or recycle them. Final release consumes its lease, drains the final pin and, if closing, closes the descriptor and retires that incarnation before unlocking. Admission cannot overlap the final OS close. No user callback runs in a critical section.

All API callers disable pthread cancellation around calls; cancellation of a borrower requires an external cleanup path that releases its lease after its I/O stops. This is a stated limitation, not automatic cancellation safety. Linux close on a valid exclusively owned descriptor releases that descriptor even when a late error is reported; do not retry the numeric descriptor. This adapter discards such errors and makes no data-delivery/durability claim. A portability variant must change this policy where EINTR can leave a descriptor open. Destroy is allowed only after all caller threads have joined and all descriptors/leases have drained; BUSY preserves the control. Joining is an external lifetime precondition that a mutex cannot prove.

Use only owned local pipes/socketpairs. Hold a borrower on an explicit condition-variable gate, close concurrently, observe the descriptor still usable and the fifth admission refused, then release and prove exactly one reclamation. Run competing close/admit threads at full capacity, accepting only the two legal serial outcomes. Test stale generations, duplicate close, failed admission ownership and permanent generation retirement. A passing ThreadSanitizer run is an observation about these schedules, not proof of all C executions or arbitrary callback safety.

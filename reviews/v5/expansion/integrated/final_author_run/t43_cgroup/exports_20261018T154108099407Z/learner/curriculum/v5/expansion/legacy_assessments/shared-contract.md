# Additive legacy assessment contract, version 1

These assessments deepen an existing project without replacing its implementation, accepted identity, historical hours or receipts. The JSON supplement binds the exact project text inspected. Each criterion is a substantive assessment task with its own stable AX identifier and an existing leaf objective; several criteria may use the same learner artifact only when each has a distinct rubric and observable obligation. A supplied exercise title, census row or test name is not evidence of its mechanism.

## Environment and dependencies

Use the active C17 baseline and the parent project's dependency profile, target, storage and error contracts. Each supplement records these explicitly. ISO C semantics, compiler extensions, ABI/OS/library and board contracts remain separate. C11 draft passages are identified as C11 and cannot substitute for exact C17 text. A freestanding target must audit generated instructions, linker maps and undefined symbols, including implicit compiler helpers; host verification tools are not target dependencies. Preserve permitted-primitive restrictions: a learner may not call a library implementation of the mechanism being assessed.

## Learner workflow and deliverables

Read the bound project and teaching passages, then the criterion's exact task before consulting its hints. Record a prediction, preconditions, postconditions, representation and invariants. Explain ownership, lifetime, failure preservation, complexity and resource assumptions where relevant; mark genuine non-applicability with reasons. Retain an incorrect explanation and counterexample. Use the existing learner project implementation as an explicitly named prerequisite artifact; a supplement never imports assessor implementations.

Every criterion produces four evidence classes, concretized by its deliverables field: D1 reasoning/source comparison; D2 implementation or analysis artifact; D3 independent verification, boundary/adversarial observations and minimized failures; D4 changed-condition transfer. Analysis-only tasks need an inspectable derivation or trace, not an irrelevant executable. Distinguish authored, executable, actually executed, independently assessed and physically validated evidence. A supplemental check cannot retroactively upgrade historical acceptance.

## Assessment and transfer

The local rubric supplies objective-specific expectations for levels0–3. Level0 is missing/incorrect, level1 superficial or example-only, level2 demonstrated bounded understanding with independent evidence, level3 independent transfer under the stated changed condition. Each criterion requires level2; its delayed variant requires level3 at least seven days after a recorded source-bound study event. This local-clock/self-study evidence is not independent reviewer identity. Save the changed problem before implementing it; parameter substitutions alone are insufficient. Separate assessor files contain technical analyses and withheld discriminators and must not enter learner packages.

Passing finite tests does not prove absolute mastery. Predictions, derivations, diagnostic traces and independent evidence must agree. A correct output accompanied by a false language, ownership or ordering explanation fails the affected criterion. A crash, timeout, warning suppression or sanitizer finding is not a repair or an exploitability proof. Report unavailable targets/tools honestly.

## Security and containment

Use original curriculum programs or learner code, synthetic data and local bounded processes. Kernel experiments use disposable VMs/emulators; firmware uses dedicated teaching boards/emulators. Authoring does not authorize host security changes, flashing or external targets. Undefined-expression cases are analysis/compile-only unless a separately specified original laboratory safely demonstrates the actual property. A security-specific criterion must additionally name target, attacker capabilities, defect/property, exposing transition, exploitability prerequisites, harmless observation, repair/regression and residual limits. Ordinary reasoning tasks may state security non-applicability.

## Evidence bindings

The supplement's source_records list only actual inspected passages; inaccessible sources appear in reference_gaps. The baseline_binding lists actual files/passages read and hashes where recorded, plus explicit uninspected limits. Teaching anchors and retained laboratory names denote authored support, not fresh execution. Facet_scope describes which original leaf claims are retained, supplemented or still open. Validation status remains authored until a separate source-bound campaign or learner assessment establishes more.

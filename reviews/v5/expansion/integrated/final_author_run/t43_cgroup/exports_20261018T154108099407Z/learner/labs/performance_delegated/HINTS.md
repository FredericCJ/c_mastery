# T43.11.a delayed transfer: hints and evidence

Use the original `AX-PR-T43-10-T43.11.a-DELAYED` task and rubric. This companion supplies the prepared guest and executable boundary; it does not replace the original minimum delay or supply an assessed learner result. The required previous artifact is the working default T43 observation workload, available unchanged as `labs/performance_followthrough/observations.c`. Read `CONTRACTS.md` and `fixtures.json` before editing `learner.c`.

1. Draw three groups: an empty delegation boundary, a control sibling for the observer, and a work sibling. Predict which UID can write each group membership and resource interface. Keep the boundary's own resource-policy files under the preparer's authority.
2. Have a new child enter the work group before exec, threads, allocations or I/O. Let it acknowledge entry, then have the observer read the exact child PID from the work group's membership file before sending a start token. A printed path alone is insufficient.
3. Run the unchanged default workload twice. Compare raw keyed CPU accounting and ancestor policy in the unlimited and quota trials. Require actual throttled-period/time increases for the quota observation; do not require a timing ratio.
4. Keep absent fields explicitly unknown. A historical peak does not reset at your first read, a live-object byte count is not group memory, and tmpfs completion does not reveal physical device traffic.
5. Save and restore the exact prior quota, reap the owner and remove the groups. Test missing placement and missing restoration. Explain why the observer must remain outside the work budget even when the workload fails.

The fixture lists exact required boundaries and negative cases. Successful exit plus counter printing earns no placement evidence without identity and ordering. A valid author run still does not establish independent learner competence, physical PMU availability, or a latency guarantee.

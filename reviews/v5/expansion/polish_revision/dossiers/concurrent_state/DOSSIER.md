# Does moving an atomic counter off the line explain the whole cost?

With two threads on distinct Zen 3 cores, moving one counter from the adjacent slot to a separately aligned slot reduced the measured thread's median cost by 22.638 ns/increment. With two SMT siblings the reduction was 11.549 ns/increment. The second result challenges the narrower explanation that every nanosecond saved came from a line transfer between private caches.

Both threads execute the same relaxed C17 atomic fetch-add loop. Each final counter must equal the number of increments addressed to it, including warm-up and separately counted tail work. All variants pass the same accounting contract before measurement. Shared uses one address, adjacent uses two addresses on one measured 64-byte cache line, and separate puts the addresses 128 bytes apart. Solo retains the measured thread and excludes peer contention. Per-thread affinity uses CPUs 2 and 4 for distinct cores and CPUs 2 and 3 for siblings on this host. Each opens its own user-mode counter group. Worker creation, placement, warm-up and the start barrier are outside the measured loop. A peer that finishes first continues incrementing until the measured window closes. Use both per-thread intervals, tail timestamps and context switches when assessing overlap. GCC 15.2 emitted `lock addq $0x1,(%rdi)` at 0x2d61 and twice in the unrolled body at 0x2d80 in every layout. At the C level relaxed atomic operations guarantee indivisible increments. The instruction and its relative cost belong to this x86-64 build and placement. [Measured disassembly](disassembly.txt)

Both coherence-group comparisons passed all five gates, with separate faster in 31/31 pairs. The restricted subsets give −22.973 and −11.877 ns/increment. Event 0x43, mask 0x02 counts demand fills from the shared L3 or a different L2 in the same CCX. It cannot separate those sources. Under SMT the large timing difference persisted while that event changed little. Possible contributors include serialization of same-line locked operations inside the core and competition for shared resources. The measured counters cannot isolate either. Per-thread retired lock events are descriptive; the available definitions do not give the latency of an individual lock. [Event definitions](events.json)

Shared versus adjacent differed by +0.011 ns/increment for cross-core coherence and changed sign across pairs. Spacing to separate tested a larger effect than switching between two locations in one line here. SMT separate versus solo added 0.309 ns/increment, which leaves evidence of peer cost even with separate lines. A processor with another core topology or cache-line size requires new placements and fresh events. The ordered-pair interval assumes independent pairs; interference and history can survive a process boundary.

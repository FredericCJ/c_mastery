# Assessor reasoning and negative controls

This document and the completed C providers are private. Public tests and contracts contain the problem, not a completed learner answer. All three original exercises require their own derivation and delayed changed-condition work; passing one mechanism does not validate another.

For Count-Min, induction on admitted updates gives the exact cell-sum invariant. Each selected cell includes the queried key's complete mass and only additional nonnegative mass. Componentwise addition proves partition merge. Preflight matters because a later refusal cannot undo already published earlier rows. For valid ordinary state, each cell is at most total; total overflow checking is already sufficient for this invariant, while explicit cell checks defensively preserve arithmetic safety. The API does not purport to validate arbitrary serialized state. Weight-zero updates and self-merge are separately exercised. Mutant1 decrements a nonzero point estimate; mutant2 publishes total while dropping merged cells. Both compile and fail intended assertions rather than memory safety instrumentation.

For a random Boolean affine row, take distinct keys x,y. Their difference has at least one set bit. Each independently chosen mask gives a fair parity on x XOR y; the independent bias makes the first output bit fair without changing the difference. Repeat for p independent rows of the matrix to obtain uniform independent p-bit outputs. This proof includes singular matrices in the family, even though an individual singular choice can be poor. The finite oracle enumerates all 64 two-bit affine maps and checks all six distinct key pairs against every output pair; it illustrates the algebra without proving a production random generator. Row independence, fixed input and no overflow must be named in the Markov argument. Negative counts can destroy the no-underestimate premise: another colliding key with mass -10 and queried key with mass 7 gives -3 in that cell. Such input is excluded by the unsigned API, not repaired by selecting a minimum.

For HLL, write each 32-bit input as coarse-index || extra-index || old-suffix. Folding observes the first one in extra-index if it exists; otherwise it observes the old suffix at an offset equal to extra-index width. A nonempty fine register summarizes enough information for precisely that rank. An empty fine register summarizes no observation and must be skipped. Max distributes over union and over this monotone rank transformation, establishing direct/fold equivalence. Equal precision gives ordinary merge, including idempotent self-merge. Mutant1 discards rank information; mutant2 forgets index-to-rank transfer. The oracle computes direct coarse registers from the original hash stream, rather than reproducing the fold algorithm.

The logarithm's range-reduced z=(x-1)/(x+1) lies in [0,1/3); the omitted positive series tail after 24 terms is below 2*(1/3)^49/(49*(1-1/9)). This is a real-arithmetic truncation bound, not a proof that all floating evaluations meet a particular ULP bound. The actual C17 profiles compare observed results with math.log/log1p at relative tolerance 3e-14 and absolute tolerance 1e-10. Integer-to-double m and powers used here are exact on the declared platform; alpha decimals are rounded. Synthetic registers force finite-hash correction and refusal. No result claims a confidence interval from adversarial hashes, and no direct/fold equivalence removes finite-hash collisions.

For MinHash, the minimum of two minima is the minimum of the union. Under a uniform random permutation, the earliest union element belongs to the intersection with probability |intersection|/|union|; that is exactly the event that two nonempty minima match. Empty policy is defined separately. Enumerating all permutations is an exact proof experiment for the five-element domain; selecting the first ten lexicographic permutations is correlated and deliberately yields candidate errors. Mutant1 forces observed minima to zero, making disjoint sets falsely match. Mutant2 counts every band rather than every completely matching band. The oracle checks all 1024 set pairs with the complete 120-row family and then the ordered ten-row family, and compares union signatures independently from sets.

A signature cannot recover arbitrary intersection: with the sole identity permutation, A={0,1} and A'={0,2} have the same minimum; choose B={1}. A intersect B is nonempty while A' intersect B is empty. The signatures presented to an intersection algorithm are identical, so no exact general answer follows. Repeated insertions also leave the signature unchanged; a multiset similarity claim would therefore be false. Banded candidate probability needs independent rows; the explicit repeated-row configuration accepted by the API is a counterexample to treating legal configuration as probabilistic certification.

Resource costs are bounded and visible: Count-Min stores at most128 counters and20 masks, with update/query O(depth*p*32) bit work and merge O(depth*width). HLL stores256 registers; this validation-heavy teaching API scans active registers before each operation, so update is O(m+32), unlike a trusted-state implementation's constant update. Estimation is O(m*rank_bound), folding O(source_m*precision_difference) plus validation. MinHash stores at most120*16 ranks and120 minima; update/query/merge are O(k), configuration validation O(k*universe), and banding O(k). State validation and upstream hash costs must not be omitted from comparisons. These are implementation bounds, not empirical speed claims.

Only original local specimens and bounded synthetic inputs are tested. No live-service probing, secret extraction or external system attack is involved.

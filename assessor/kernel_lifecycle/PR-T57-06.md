# Assessor analysis: PR-T57-06

Read-copy-update separates removal from reclamation. A reader that began before removal may still hold the old pointer. A grace period concerns the relevant readers, not elapsed wall time.

Show removal prevents new lookup while preexisting readers retain storage lifetime. Identify how refcount acquisition extends ownership beyond a read-side section and why the section alone does not do so.

The reference implementation is in `core.c`; inspect it together with the public test. The named fault is: Repair immediate reclamation on unlink; delayed arbitrary sleeps are not grace-period proofs. Host bitmask traces cannot validate actual RCU memory ordering.

Require the learner to derive 0 from the fixture inputs independently. Wait for the appropriate grace condition, not an assumed duration.

Transfer answer obligations: Permit readers of a replacement object after retirement; tag reader epochs and show waiting for all new readers can cause unnecessary starvation.

Actual guest module build/load/unload, concurrent open/remove traces, allocation-fault injection and lockdep/KASAN observations remain mandatory target evidence; host model tests do not satisfy them.

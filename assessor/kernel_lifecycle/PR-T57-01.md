# Assessor analysis: PR-T57-01

A successful acquisition creates a cleanup obligation even when registration has not reached its final step. Encode ownership independently from the control-flow label so that every acquired resource is released once in reverse dependency order. Returning an error does not undo allocations.

Show each owned bit has exactly one release and no release precedes its dependents. Relate O(3) model work to the number of real acquisitions, including a failure before endpoint publication.

The reference implementation is in `core.c`; inspect it together with the public test. The named fault is: Repair forward-order cleanup and double release on a second failure label; a module that returns ENOMEM after leaking work is incorrect even if loading fails.

Require the learner to derive 21 from the fixture inputs independently. Walk set ownership bits in reverse dependency order; clear after actual release.

Transfer answer obligations: Replace one acquisition by a managed device allocation and demonstrate which cleanup obligations migrate to the device lifecycle, including failure after publication.

Actual guest module build/load/unload, concurrent open/remove traces, allocation-fault injection and lockdep/KASAN observations remain mandatory target evidence; host model tests do not satisfy them.

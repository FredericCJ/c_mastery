# Assessor analysis: PR-T57-08

Object references, callback references and references to module text can have different owners. Unloading a driver requires closing all ways to acquire them and waiting for outstanding users; empty work queues alone do not prove that open handles disappeared.

Construct a global ownership graph and identify the linearization point of shutdown. Give separate evidence for module pinning, object release, callback quiescence and bounded wait policy.

The reference implementation is in `core.c`; inspect it together with the public test. The named fault is: A module unloads after the last open handle while a callback still retains its function pointer. Demonstrate rejection in the model; any guest fault stays inside the disposable VM.

Require the learner to derive 0 from the fixture inputs independently. Unload requires both closed admission and exhaustion of every relevant owner, not one counter.

Transfer answer obligations: Add hot-unplug while two open handles remain: choose revoked operations versus retained detached objects, and justify error propagation and final cleanup under both close orders.

Actual guest module build/load/unload, concurrent open/remove traces, allocation-fault injection and lockdep/KASAN observations remain mandatory target evidence; host model tests do not satisfy them.

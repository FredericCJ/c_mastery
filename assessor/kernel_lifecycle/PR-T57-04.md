# Assessor analysis: PR-T57-04

Lock selection includes who can preempt whom and whether the operation may sleep. CPU-local interrupt exclusion does not serialize another processor. PREEMPT_RT changes ordinary spinlock behavior; a successful non-RT test is not proof for RT.

Derive preemption, migration, interrupt and inter-CPU exclusion separately. A lockdep trace is evidence for exercised lock-order paths, not a proof of all schedules.

The reference implementation is in `core.c`; inspect it together with the public test. The named fault is: Repair an RT hardirq path that uses ordinary spinlock_t and a second-core race hidden by local interrupt disabling. The host truth table assesses policy only.

Require the learner to derive 0 from the fixture inputs independently. For the lab policy validate fields before choosing context-sensitive admission.

Transfer answer obligations: Move a callback from task context to threaded IRQ and then hardirq; revise allocation and lock choices and retain the failed and corrected guest traces.

Actual guest module build/load/unload, concurrent open/remove traces, allocation-fault injection and lockdep/KASAN observations remain mandatory target evidence; host model tests do not satisfy them.

# Assessor analysis: PR-T58-08

A freestanding compilation can still emit runtime helpers for division, atomics, copies or stack protection. A successful object build does not establish that a reset image links or that the dependencies obey target constraints.

Distinguish declarations, emitted references, linked providers and actually exercised target paths. Explain why hosted test libraries cannot be treated as target dependencies.

The reference implementation is in `core.c`; inspect it together with the public test. The named fault is: A port links only because the developer machine supplies libgcc or libc; removing the runtime reveals a hidden helper. Report this as missing target support, not a compiler bug.

Require the learner to derive 0 from the fixture inputs independently. Link with an explicit script and allowed providers; retain the final map and target disassembly.

Transfer answer obligations: Change optimization, atomics width and ISA extensions; regenerate closure and code-size/stack evidence and explain every new helper or inline expansion.

Actual cross-linked image runs, hostile-register context tests, trap return and two-address-space translation observations in both dedicated guests are mandatory; model tests are not a complete OS port.

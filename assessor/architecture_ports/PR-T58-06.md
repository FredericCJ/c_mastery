# Assessor analysis: PR-T58-06

Supervisor trap entry saves prior interrupt enable and disables interrupts; trap return restores it. C function-call preservation does not capture these privilege transitions. Nesting without saving the prior trap frame overwrites the interrupted state.

Draw status before entry, after entry and after return. Explain which processor state is automatic, which is software saved and why a call-return instruction cannot replace a trap return.

The reference implementation is in `core.c`; inspect it together with the public test. The named fault is: Repair stale prior-privilege state after return and a nested handler that overwrites the first saved PC. The model cannot establish interrupt controller acknowledgement behavior.

Require the learner to derive [0, 1, 1] from the fixture inputs independently. Preserve a separate frame for each permitted nesting level and validate the privilege-return target.

Transfer answer obligations: Port the same logical event to an AArch64 exception level and identify every register/return difference from an inspected architecture manual before implementing.

Actual cross-linked image runs, hostile-register context tests, trap return and two-address-space translation observations in both dedicated guests are mandatory; model tests are not a complete OS port.

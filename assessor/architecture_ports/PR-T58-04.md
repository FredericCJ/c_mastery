# Assessor analysis: PR-T58-04

A context image is an owned snapshot of a defined machine-state set. Copying arbitrary register bytes is not sufficient if the architecture tag, stack lifetime or asynchronous state differs. Its representation must reject cross-architecture restoration.

Prove a save/restore preserves exactly the declared set and leaves nonowned registers untouched. State stack ownership, resume-address validity and exclusion of asynchronous FP/trap state.

The reference implementation is in `core.c`; inspect it together with the public test. The named fault is: Repair restoration of an RV image as Arm by rejecting mismatched tags before any register mutation. A C struct size match does not establish semantic compatibility.

Require the learner to derive [108, 999] from the fixture inputs independently. Use the same offset definitions in C and assembly and inspect generated relocation/disassembly.

Transfer answer obligations: Add two task stacks and a yield-return continuation; inject stack exhaustion and duplicate resume, and compare cooperative with asynchronous preemption save sets.

Actual cross-linked image runs, hostile-register context tests, trap return and two-address-space translation observations in both dedicated guests are mandatory; model tests are not a complete OS port.

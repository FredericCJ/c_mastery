# Assessor analysis: PR-T58-01

Rounding a stack address down consumes bytes. Subtracting first and checking later can wrap the address. Public-call alignment belongs to the selected ABI; it is not an ISO C stack guarantee.

Prove result<=top-bytes, alignment and nonwrap; account for consumed padding and live stack bounds.

The reference implementation is in `core.c`; inspect it together with the public test. The named fault is: A port aligns to8 because pointers are8 bytes, violating the16-byte call boundary. A linker-defined top is not proof that subtraction stays in the reserved stack.

Require the learner to derive 4080 from the fixture inputs independently. Round the resulting integer downward and account for padding before mapping to target storage.

Transfer answer obligations: Change to RV32E or Thumb and derive the appropriate ABI alignment from its specification rather than inheriting16. Add a guard region and test exact exhaustion.

Actual cross-linked image runs, hostile-register context tests, trap return and two-address-space translation observations in both dedicated guests are mandatory; model tests are not a complete OS port.

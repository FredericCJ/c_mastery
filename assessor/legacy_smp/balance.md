# T53.08 assessor analysis

The policy lock is a deliberately simple composition boundary. It serializes mask/lease changes against actual queue operations; it does not replace the queue's reservation or saved-context invariant. The nested lock order is fixed. A running mask request changes only pending state, so the old CPU remains permitted until finish publishes a saved frame. Disallowed READY tasks may remain queued but cannot dispatch; selection repairs them before ordinary load balancing.

Migration begin reserves rollback and destination capacity in the actual queue. Failure injection2 must call actual abort, not only clear a ticket. Its revisions change even though ownership/output rollback succeeds. A committed transfer may return SIGNAL; the transfer is already terminal, so retry is notification-only. Counter exhaustion may stop new moves but cannot block required finish/exit/cancel.

Timer serial and task generation identify authority. The stored old CPU is specifically not authority. A callback during TRANSFER returns MOVING without consuming the lease; after commit it resolves the new home. A duplicate callback is stale after the first accepted/duplicate wake consumes the lease. Exit with a live timer prevents slot reuse until cancel, while a stale token after reuse fails generation validation. There is no force-cancel of executing foreign code or timer-ISR claim.

Mutants discriminate four different errors: immediate effective-mask replacement for a running context; missing rollback after reservation; callback routing through its old CPU; and balancing a pinned task. Actual guest controls separately publish a context before its stack is saved or omit a required durable wake. Neither is accepted as an arbitrary crash. Full trace analysis connects actor sequence with per-task revisions, rather than treating serial output order as a global clock.

Expected guest results: each of four contexts executes seven actions, exits once, and has its private stack canary preserved. Pinned mode has64 events and zero migrations; movable mode has68 events and two migrations, with tasks1/2 seen on CPUs0/1 and task0 onlyCPU0. Both have56 context switches. The timer exercises TRANSFER refusal and postcommit duplicate recognition at its new home.

The native benchmark uses real Linux allowed-CPU selection and per-thread affinity with equal work. First/repeated sweep times are observations with multiple causes, not isolated cache miss measurements. A finite cost model demonstrates that equal-length queues may lose performance with unequal work and movement cost. Neither native timing nor virtual TSC proves physical WCET, cache topology, fairness, or all C executions. External human review, physical observations and delayed learner assessment remain separate.

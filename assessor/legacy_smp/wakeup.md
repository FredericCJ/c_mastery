# T53.07 technical analysis

The additional control lock establishes one publication transaction around the actual per-CPU queue operations and the doorbell. This sacrifices scalability deliberately; the exercise does not claim a production scheduler. A consistent lock order is control before the queue locks. The ISR never takes those locks. Hosted predicate mutex callbacks also never call back into the wrapper, avoiding the reverse order.

Queue READY count is mirrored with a release atomic store before the selected port rings. The fence and x86 port operation are distinct from ISO C acquire/release synchronization. An ISR observation of the mirror is useful instrumentation, not queue ownership. A failed ring leaves READY and the bell retained; retry is safe even if the first ring partly delivered. Transfer completion has already consumed its ticket before SIGNAL, so retrying the transfer instead of the notification is a real error.

For a level source, deassert then recheck durable state while producers are excluded. If work remains, reassert. If a producer follows unlock, it raises the level again. The bad alternative checks empty, permits publication, then clears the new level. The independent schedule model contains that three-step witness. Its level Boolean model and the pthread predicate adapter are explicitly different from physical level-triggered I/O APIC behavior.

For the fixed IPI target, IF=0 spans the empty check and release. Adjacent STI/HLT closes the instruction-boundary gap under the selected Intel footnote premise; starting with IF=1 would not provide that deferral. EOI does not remove READY work. The actual negative waits until the first IPI has been handled, executes a separate HLT with work still queued and requires a later rescue IPI whose saved RIP is after that HLT. This is a controlled lost-wakeup witness, not just a timeout.

The early-notification mutant has a different conclusion. Its notification can arrive while the mirror is empty. The wrapper's control lock still forces the consumer's later queue access to follow publication, so actual work may all complete. Reject the violated publication-before-notify contract, but do not claim this exact locked path necessarily stranded an item. The separate finite model demonstrates stranding when that compensating exclusion/recheck is absent. Learners should identify this difference rather than repeating a generic warning.

Every eight-round block dispatches23 items: mode0/1/2 single plus mode3 four, followed by four batches of four. Three blocks give69. Modes1/2 produce12 total halt-resume conditions; an interrupt frame's RIP after HLT is the actual instruction witness. In four-CPU runs, CPUs2/3 execute explicit background loops; their progress is checked. Counts of ring requests and delivered IRQs may differ because software and APIC notifications coalesce. Never require a one-to-one relationship with task count.

Only local-clock intervals are subtracted. Sender publication→observed batch completion is wider than first dispatch and includes polling/task work; receiver IRQ→first dispatch begins on the receiving CPU. Negative or absent intervals must be reported rather than normalized away. A low average for these selected samples proves neither absence of lost wakeups nor physical performance.

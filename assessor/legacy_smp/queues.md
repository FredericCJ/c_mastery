# T53.06 assessor reasoning

The key capacity invariant includes reservations. A RUNNING task occupies no FIFO entry but owns a guaranteed return slot. A TRANSFER simultaneously reserves source rollback and destination commit capacity. This is deliberately conservative: two-sided reservation can refuse a move even when final destination counts alone look acceptable, but it never needs an unbounded rollback allocation. Mutation2 removes the source first and exposes the lost task on a full destination immediately.

Acquire the old/new queue locks in numeric order; only inspect non-atomic task revision/transfer fields after home validation. A move publishes its new home under both locks, so an old-home reader cannot concurrently read those fields once validation succeeds; a wrong-home reader uses only atomic home/state and immutable generation. Generation creation/reuse is separately quiescent. This reasoning does not authorize `sq_invariant` during worker execution.

The saved-context adapter keeps the logical task RUNNING throughout the task-to-idle switch. The scheduler clears the executing guard and then finishes under the queue lock. A later dispatcher acquires the lock before using the saved stack. Moving task0 after the common blocked phase exercises an actual continuation with live automatic variables on CPU1. It does not prove arbitrary architecture migration: general-register-only, common address space, no TLS/preemption and no held task lock are premises. Initial creation sets the stack frame to match the imported six-callee-save-register switch, including ABI stack alignment.

The finite revision reserve is an admission property: dispatch/begin require room for both their event and their mandatory resolution. At MAX-2, dispatch followed by EXITED reaches MAX safely. At MAX-1 dispatch refuses before taking execution ownership. The quiescent owner may later retire/replace the world under the specified identity contract; silently resetting a revision or generation with live handles is not a repair.

Other tasks have16 revisions; task0 has18 when moved. Per-CPU traces are printed after completion, so output ordering is deliberately unrelated to the interleaving. The validator joins actor order and per-task protected revisions, verifies acyclicity and legal state/owner transitions. It does not infer ordering for independent tasks from TSC. Revision gaps reject completeness; a malicious logger that rewrites all counters is outside this instrumentation premise.

For sampled logs, construct two executions with identical retained observations: one ordinary READY→RUNNING→READY interval, and another with an omitted duplicate dispatch; similarly omit an enqueue and its repair before the next retained checkpoint. Even a correct final snapshot cannot exclude the intervening violation. The changed-condition validator returns inconclusive rather than treating missing records as legal state jumps. The complete-log negative fixtures must independently catch duplicate transition, missing revision, wrong owner and causal cycle.

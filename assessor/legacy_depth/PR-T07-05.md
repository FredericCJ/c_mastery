# PR-T07-05 supplemental assessor analysis

Assessor only. The accepted project remains the implementation contract. These arguments are authored technical expectations, not fresh experiment or learner evidence.

<a id="t0710a"></a>
## T07.10.a — Pin source versions and record integrity identifiers.

Content verification rejects corruption and missing files; a label alone is insufficient and hashes without trusted provenance do not prove authenticity.

Reject superficial reasoning: A version string establishes source identity and integrity.

Discriminator: Require the causal argument above and an independent artifact or trace that discriminates it from: A version string establishes source identity and integrity.

Delayed assessor check: Introduce a generated file whose generator and configuration must also be pinned.

<a id="t0710b"></a>
## T07.10.b — Compare system packages, vendored source, and fetched dependencies.

Behavior may agree while provenance and rebuild inputs differ; source selection must be explicit and mismatch fails visibly.

Reject superficial reasoning: Three dependency acquisition methods imply equivalent supply-chain and update behavior.

Discriminator: Require the causal argument above and an independent artifact or trace that discriminates it from: Three dependency acquisition methods imply equivalent supply-chain and update behavior.

Delayed assessor check: Choose a patched vendored version with identical version text and detect it through source identity.

<a id="t0710c"></a>
## T07.10.c — Define offline and clean-room build prerequisites.

Success must use the enumerated cache; missing data is not recovered silently from the network. A clean output directory alone does not imply clean dependencies.

Reject superficial reasoning: A build that succeeds once is demonstrably reproducible offline.

Discriminator: Require the causal argument above and an independent artifact or trace that discriminates it from: A build that succeeds once is demonstrably reproducible offline.

Delayed assessor check: Change a transitive dependency and show the offline manifest either closes that dependency or rejects it.

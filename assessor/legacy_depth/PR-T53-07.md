## T53.07.a — Derive and defend the state, ownership and ordering contract for remote wakeup and reschedule delivery.

Notification prompts checking durable work state; coalescing is safe only if the consumer drains/rechecks that state. A lost idle transition can strand published work even with correct queue storage. The protocol must close the check/sleep interval.

Reject: One IPI corresponds to exactly one work item.

Assessor discriminator: require the first state, result, ownership edge or schedule event that differs under the rejected explanation. A generic stress checksum or missing sanitizer finding is not a substitute for that witness. Confirm the claim stays inside the declared execution and source scope.

Delayed assessor check: Use a level-triggered doorbell and derive the acknowledgement/recheck sequence that prevents clearing new work.

## T53.07.b — Implement remote wakeup with a generation-checked task handle and destination notification. Inject wakeups before idle check, between check and sleep, and during existing execution.

Task identity, queue ownership and ordering must be established separately. A stale handle cannot wake a reused task; a duplicate wake cannot add a second queue node. Polling progress does not validate a halt transition that was never executed.

Reject: An IPI alone provides lifetime validation and all C memory ordering.

Assessor discriminator: require the first state, result, ownership edge or schedule event that differs under the rejected explanation. A generic stress checksum or missing sanitizer finding is not a substitute for that witness. Confirm the claim stays inside the declared execution and source scope.

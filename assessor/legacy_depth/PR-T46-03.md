# PR-T46-03 supplemental assessor analysis

Assessor-only; author reasoning, not independent or learner evidence.

<a id="t4603a"></a>
## T46.03.a

Changing erroring arithmetic to wrapping is a language change, not a repair. The host implementation must realize the chosen semantics without its own UB.

Expected relation: The defined guest result is representable or RANGE; -7/2 is-3; no invalid C arithmetic is evaluated.

Withheld transfer discriminator: Define a separately versioned wrapping-int32 guest and rederive conversions and tests.

<a id="t4603b"></a>
## T46.03.b

Multiple simultaneous faults make error precedence ambiguous. State any intended precedence explicitly rather than relying on incidental implementation order.

Expected relation: Each failure reaches its intended layer; runtime total stack pressure can exceed per-function relative heights; result remains unchanged.

Withheld transfer discriminator: Add a host-service error after valid arithmetic and preserve the distinction.

<a id="t4603c"></a>
## T46.03.c

Rollback and resumability are stronger contracts than unchanged result output. They require explicit ownership and instruction-commit boundaries.

Expected relation: Output stays unchanged; consumed fuel and diagnostic state may differ; independent replay starts from initialized state.

Withheld transfer discriminator: Design a resumable VM API and specify the additional continuation/state invariants.

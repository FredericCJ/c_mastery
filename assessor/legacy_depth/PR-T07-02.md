# PR-T07-02 supplemental assessor analysis

Assessor only. The accepted project remains the implementation contract. These arguments are authored technical expectations, not fresh experiment or learner evidence.

<a id="t0704a"></a>
## T07.04.a — Compare optimization levels through behavior and generated code.

All profiles meet the same defined result; generated instructions and size may differ. The oracle reduces after mathematical addition and avoids signed overflow.

Reject superficial reasoning: Optimizations must preserve instruction shape or measured timing.

Discriminator: Require the causal argument above and an independent artifact or trace that discriminates it from: Optimizations must preserve instruction shape or measured timing.

Delayed assessor check: Introduce restrict on a second buffer; state the new nonaliasing precondition and analyze a violating caller without running it as a valid case.

<a id="t0704b"></a>
## T07.04.b — Configure separate debug, sanitizer, release, and size-oriented builds.

Effective compile and link commands, binary identity and runtime requirements substantiate the profile. A test built with NDEBUG must not silently lose its assertions.

Reject superficial reasoning: A preset name proves the binary was compiled with its advertised flags.

Discriminator: Require the causal argument above and an independent artifact or trace that discriminates it from: A preset name proves the binary was compiled with its advertised flags.

Delayed assessor check: Add a coverage preset whose runtime is forbidden in the target component; keep host measurement separate.

<a id="t0704c"></a>
## T07.04.c — Avoid assuming debug and release profiles have identical dependencies.

Every configuration has its own closure; final linking can resolve helpers that were visible in objects. Lack of a symbol in one profile is not a universal guarantee.

Reject superficial reasoning: The debug nm report proves the release or LTO closure.

Discriminator: Require the causal argument above and an independent artifact or trace that discriminates it from: The debug nm report proves the release or LTO closure.

Delayed assessor check: Enable stack protection on a custom-entry build and diagnose the new initialization and support requirements.

## T07.05.a — Model explicit targets, prerequisites, recipes, and generated dependencies.

The generated header has one producer and consumers wait for it; deletion regenerates it before step.o. main.o is rebuilt only if its real inputs change.

Reject superficial reasoning: Order in the Makefile text establishes all dependencies.

Discriminator: Require the causal argument above and an independent artifact or trace that discriminates it from: Order in the Makefile text establishes all dependencies.

Delayed assessor check: Generate two outputs from one invocation and prevent parallel recipes from publishing mismatched generations.

<a id="t0705b"></a>
## T07.05.b — Distinguish ordinary files, phony targets, and order-only prerequisites.

Directory timestamp changes need not rebuild objects; cfg.h changes invalidate consumers; phony targets express actions, not persistent output freshness.

Reject superficial reasoning: An output directory must be an ordinary prerequisite of every object.

Discriminator: Require the causal argument above and an independent artifact or trace that discriminates it from: An output directory must be an ordinary prerequisite of every object.

Delayed assessor check: Replace cfg.h's ordinary edge with an order-only edge and provide the smallest stale-binary counterexample.

<a id="t0705c"></a>
## T07.05.c — Diagnose stale, missing, and unnecessarily rebuilt outputs.

A failed generation must not publish a partial header; the old output must not be mistaken for success. Rebuild sets follow the declared graph, not an arbitrary full rebuild.

Reject superficial reasoning: A successful clean build proves incremental correctness.

Discriminator: Require the causal argument above and an independent artifact or trace that discriminates it from: A successful clean build proves incremental correctness.

Delayed assessor check: Use coarse filesystem timestamps and derive a content-digest alternative with its own cache-invalidation costs.

<a id="t0707a"></a>
## T07.07.a — Sequence code generation and configuration checks correctly.

Configuration and build dependencies have distinct owners; failure blocks consumers and preserves coherent outputs. No stale generated bytes are reported as newly generated.

Reject superficial reasoning: A configure-time generated file can never become stale.

Discriminator: Require the causal argument above and an independent artifact or trace that discriminates it from: A configure-time generated file can never become stale.

Delayed assessor check: Move generation from configure time to build time and justify how repeated configuration avoids destroying a valid prior output.

<a id="t0707b"></a>
## T07.07.b — Validate generated headers and embedded resource dependencies.

Both generator and resource bytes are dependencies. Empty input needs a defined C representation without a zero-length array extension.

Reject superficial reasoning: A generated header depends only on its generator executable.

Discriminator: Require the causal argument above and an independent artifact or trace that discriminates it from: A generated header depends only on its generator executable.

Delayed assessor check: Split the resource into ordered fragments and detect reordering or missing fragments through a manifest.

## T07.07.c — Avoid target-code execution during unsupported cross-configuration checks.

Target feature answers are evidence-tagged assumptions or compile observations, never accidental host execution. Unsupported execution remains unavailable.

Reject superficial reasoning: A successful host try_run establishes a target ABI fact.

Discriminator: Require the causal argument above and an independent artifact or trace that discriminates it from: A successful host try_run establishes a target ABI fact.

Delayed assessor check: Provide a named emulator explicitly and separate emulator evidence from physical-board behavior.

# PR-T56-06 independent technical assessment

Same-author technical analysis, excluded from learner package. Historical accepted evidence remains unchanged.

<a id="t56-06-a"></a>
## t56-06-a

Creation owns one reference and each mapping another; closing the object drops its reference but does not revoke existing mappings. The final mapping/reference releases the frame.

Required remaining mechanism/evidence: Explicit unmap, read-only rights, independent grants and synchronized protocol extensions remain required.

Transfer discriminator: Unmap one process while another accesses it and prove frame lifetime through exit and TLB invalidation.

A repeated output without derivation and scope is at most level1. A source/model check never substitutes for required guest or physical execution.

## t56-06-b

Retained SHM_MAP always publishes user writable NX mappings; it has no caller-selected read-only or unmap operation. Those parent obligations need explicit interfaces and checks.

Required remaining mechanism/evidence: Explicit unmap, read-only rights, independent grants and synchronized protocol extensions remain required.

Transfer discriminator: Implement rights attenuation and reject overlap with protected virtual regions using checked extent arithmetic.

A repeated output without derivation and scope is at most level1. A source/model check never substitutes for required guest or physical execution.

<a id="t56-06-c"></a>
## t56-06-c

Common physical storage is not synchronization and volatile is not an atomic protocol. Use selected interprocess atomic/ISA guarantees and prove publication; process exit alone does not sanitize a data race.

Required remaining mechanism/evidence: Explicit unmap, read-only rights, independent grants and synchronized protocol extensions remain required.

Transfer discriminator: Use an SPSC protocol with separate cache lines and compare the coherent guest with noncoherent H745 assumptions.

A repeated output without derivation and scope is at most level1. A source/model check never substitutes for required guest or physical execution.

# PR-T21-01 supplemental assessor analysis

Assessor-only; author reasoning, not independent or learner evidence.

<a id="t2101a"></a>
## T21.01.a

Classification depends on boundary and application policy. Resource failure may be recoverable elsewhere even when this operation cannot recover locally.

Expected relation: Each category retains a distinguishable cause and legal post-failure state; invalid input is rejected before use and an internal invariant defect is not silently called timeout.

Withheld transfer discriminator: Make the parser input trusted after a verified boundary and identify which checks may become internal assertions without changing external guarantees.

<a id="t2101b"></a>
## T21.01.b

Exactly-once effect claims require more than retry loops. State retention windows and recovery assumptions explicitly; no external service is contacted.

Expected relation: A lost acknowledgment is ambiguous; retry requires an idempotency/deduplication contract or exposes possible duplication.

Withheld transfer discriminator: Add bounded request IDs and show what happens when deduplication history expires.

<a id="t2101c"></a>
## T21.01.c

Preserving context does not require exposing unstable backend codes as a public ABI. Overflow of diagnostic storage needs an explicit observable policy.

Expected relation: Construction failure remains primary; cleanup failure adds bounded secondary context without allocation or recursive logging.

Withheld transfer discriminator: Allow more secondary failures than record capacity and define truncation/loss accounting.

<a id="t2102a"></a>
## T21.02.a

A many-to-one mapping can be appropriate if callers need only the public action. Do not discard information required for diagnosis or recovery.

Expected relation: Known cases map deliberately; unknown remains identifiable with bounded detail; public success never aliases a failure.

Withheld transfer discriminator: Merge two backend failures into one public category while preserving an optional diagnostic discriminator.

<a id="t2102b"></a>
## T21.02.b

A pointer to a temporary backend message is not stable context. Text formatting and ownership are separate from the public error taxonomy.

Expected relation: The consumer keeps the same public result contract; internal detail has explicit lifetime/access rules and no dangling borrowed message.

Withheld transfer discriminator: Permit deferred diagnostic retrieval after the operation object is destroyed and choose copying or a stable owner.

<a id="t2102c"></a>
## T21.02.c

A tagged result may need a progress field in both success and failure alternatives. A language-level Result comparison must not erase the underlying operation's partial effects.

Expected relation: The three outcomes remain distinguishable; callers can resume only the unaccepted prefix and never treat partial failure as full success.

Withheld transfer discriminator: Support error accumulation across independent fields and preserve their individual locations.

<a id="t2103a"></a>
## T21.03.a

Reverse sequence works for this dependency chain. More general resource graphs require an order justified by actual dependencies.

Expected relation: Failure index2 releases channel then memory; every other failure releases exactly its completed prefix in reverse dependency order.

Withheld transfer discriminator: Acquire two independent resources in either order and derive a dependency graph rather than assuming one universal cleanup order.

<a id="t2103b"></a>
## T21.03.b

SQLite finalize is a concrete consumed-resource comparison, not a rule for every close function. A strong cleanup-success guarantee may be impossible under a fallible-release model.

Expected relation: The ledger contains no unrecorded live resource; consumed-on-error cleanup is not retried blindly and retained-on-error cleanup remains owned.

Withheld transfer discriminator: Add a fourth resource whose cleanup must run before two earlier resources and revise ordering.

<a id="t2103c"></a>
## T21.03.c

Zeroing a still-owning object loses obligations. Idempotence belongs to specified logical states, not to arbitrary memory contents.

Expected relation: No resource is leaked or released twice; active reinitialization rejects without overwriting owned state.

Withheld transfer discriminator: Allow restart after stop while preserving a stable handle identity policy.

<a id="t2104a"></a>
## T21.04.a

Control-flow style organizes a proof but does not supply it. Publication after acquisition is essential to the original unchanged-output guarantee.

Expected relation: Both versions have the same successful and failed ownership traces; the review names a concrete advantage and counterexample for each structure.

Withheld transfer discriminator: Insert a fallible operation after publication and determine whether either cleanup pattern can still promise rollback.

<a id="t2104b"></a>
## T21.04.b

A net-zero counter can hide duplicate release and missing release. Generational identity avoids conflating recycled handles in the evidence.

Expected relation: Identity-level event counts establish the specified release property; final counts alone are insufficient.

Withheld transfer discriminator: Reuse resource numeric IDs with generations and distinguish separate lifetimes.

<a id="t2104c"></a>
## T21.04.c

A simpler-looking common cleanup block may release resources that were never acquired. The state proof must survive the refactor.

Expected relation: The mutation is detected and all old observable contracts remain; the rationale identifies how each ownership obligation is visible.

Withheld transfer discriminator: Make one cleanup conditional on a committed side effect and revise the review argument.

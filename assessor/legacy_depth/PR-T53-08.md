## T53.08.a — Derive and defend the state, ownership and ordering contract for affinity, migration and load balance.

The source must stop using the context before destination publication. One authoritative saved frame and one CPU owner remain. Affinity constrains destination but does not itself stop a running thread or deliver pending work.

Reject: Migration copies a live context and lets the destination start immediately.

Assessor discriminator: require the first state, result, ownership edge or schedule event that differs under the rejected explanation. A generic stress checksum or missing sanitizer finding is not a substitute for that witness. Confirm the claim stays inside the declared execution and source scope.

Delayed assessor check: Restrict a currently running task's affinity to exclude its CPU and define the safe rescheduling boundary.

## T53.08.b — Add explicit affinity masks and migration of ready tasks, followed by a bounded work-balancing policy. Measure migration count, queue imbalance and cache-warmup cost.

Opposite migrations create an AB/BA cycle unless lock order is total. Failure before commit must preserve source ownership; after commit, wakeups route to the new owner. Intermediate states and reserved slots must be visible to the protocol, not ordinary dispatch.

Reject: Taking source lock then destination lock is globally deadlock-free.

## T53.08.c — Show every migration has one source release and one destination acquisition, with no lost service or simultaneous execution. Explain why balancing overhead can reduce throughput.

Task costs, affinity, migration and cache costs can outweigh queue balance. The correctness gate remains one execution owner and no lost service; performance needs equal work and repeated controlled measurements. A global ready queue has a different migration mechanism.

Reject: Balanced queue lengths imply reduced completion time.

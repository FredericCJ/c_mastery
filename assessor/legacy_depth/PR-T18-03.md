# PR-T18-03 supplemental assessor analysis

Assessor-only; author reasoning, not independent or learner evidence.

<a id="t1805a"></a>
## T18.05.a

The fixture models only four transitions. The added failure states must not silently inherit active operations or permit reinitializing a still-owned resource.

Expected relation: init,stop,stop,destroy yields active,stopped,stopped,destroyed; failed initialization has a separate cleanup-safe representation.

Withheld transfer discriminator: Add a restart transition from stopped and state whether old views or registrations remain valid.

<a id="t1805b"></a>
## T18.05.b

Idempotence is a specified operation property. Calling through destroyed storage is not made valid by an idempotent logical stop protocol.

Expected relation: Failure after the first acquisition releases only that resource; repeated stop adds no release; failed construction never publishes active state.

Withheld transfer discriminator: Make the second resource optional and preserve the same active-state invariant without pretending absence is failure.

<a id="t1805c"></a>
## T18.05.c

A state machine residing in live caller storage can reject operations. Once that storage lifetime ends, the caller must not inspect it to discover that fact.

Expected relation: Invalid logical operations reject before resource use; no test calls an API through dead storage and expects defined rejection.

Withheld transfer discriminator: Move the state tag outside the object into a stable handle table and identify the additional lifetime protocol required.

<a id="t1806a"></a>
## T18.06.a

Choose a public typed storage wrapper or byte-oriented representation with justified access. Hiding a struct by casting an unrelated declared byte array needs a language argument, not only an alignment assertion.

Expected relation: Each representation has a defined C object type/lifetime and explicit storage owner; a guessed aligned char array is not accepted as a universal typed-object construction trick.

Withheld transfer discriminator: Use a byte-serialized opaque representation whose operations load/store fields explicitly and compare its costs.

<a id="t1806b"></a>
## T18.06.b

A same-sized pointer does not guarantee unchanged behavior, ownership or calling convention. Report exact consumer/toolchain evidence and reject universal ABI portability claims.

Expected relation: Exposed/caller-sized layouts require revised compatibility analysis; an opaque pointer can keep handle layout stable while factory/allocation obligations remain.

Withheld transfer discriminator: Require heap-free embedding and choose a versioned typed storage contract with explicit size queries or generated headers.

<a id="t1806c"></a>
## T18.06.c

Overalignment alone does not establish effective type. Never dereference the intentionally invalid representation as a diagnostic demonstration.

Expected relation: A mismatch is detected at compile/configuration time; accepted storage satisfies both actual size/alignment and the chosen object-type contract.

Withheld transfer discriminator: Hide the complete type and design a generated contract header with version identity; show how stale headers are rejected.

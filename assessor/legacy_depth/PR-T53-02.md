## T53.02.a — Derive and defend the state, ownership and ordering contract for secondary-cpu trampoline and startup.

The startup vector identifies a low4KiB page and the AP must establish the required machine state before C. The original mailbox provides page tables, stack, entry and CPU index; each has a lifetime and visibility requirement. ISA rules are not ISO C semantics.

Reject: Sending a SIPI to the C function address is sufficient startup.

Assessor discriminator: require the first state, result, ownership edge or schedule event that differs under the rejected explanation. A generic stress checksum or missing sanitizer finding is not a substitute for that witness. Confirm the claim stays inside the declared execution and source scope.

Delayed assessor check: Move the trampoline to another valid low page and regenerate relocation/disassembly evidence instead of patching one literal only.

## T53.02.b — Implement original AP startup using the selected local-APIC INIT/SIPI sequence and a bounded acknowledgment timeout. Keep trampoline storage reserved until no AP can still execute it.

Timeout means acknowledgement was not observed, not that the AP stopped. Reuse can make a delayed AP consume another CPU's mailbox or stack. Failure must retain/contain affected resources or establish quiescence before retry; a busy ICR bit is not software initialization completion.

Reject: Timeout proves the AP will never execute the startup code.

Assessor discriminator: require the first state, result, ownership edge or schedule event that differs under the rejected explanation. A generic stress checksum or missing sanitizer finding is not a substitute for that witness. Confirm the claim stays inside the declared execution and source scope.

Delayed assessor check: Support parallel AP startup with per-AP mailboxes and derive the extra allocation and acknowledgement invariants.

## T53.02.c — Boot1,2,4 CPUs and retain distinct per-CPU entry markers and stack addresses. An intentionally missing acknowledgment must fail within the declared bound.

Each CPU must publish its own verified state before the BSP accepts completion. A print marker alone can be stale or early. QEMU execution and generated-code closure support that bounded guest, not physical startup timing or current CPU errata.

Reject: A printed AP count proves every CPU has initialized usable private state.

Assessor discriminator: require the first state, result, ownership edge or schedule event that differs under the rejected explanation. A generic stress checksum or missing sanitizer finding is not a substitute for that witness. Confirm the claim stays inside the declared execution and source scope.

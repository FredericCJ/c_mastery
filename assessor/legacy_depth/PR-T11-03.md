# PR-T11-03 supplemental assessor analysis

Assessor only. The accepted project remains the implementation contract. These arguments are authored technical expectations, not fresh experiment or learner evidence.

<a id="t1106a"></a>
## T11.06.a — Implement byte-copy, overlap-safe move, set, and comparison operations.

Backward overlap requires a direction or staging argument; comparison uses unsigned bytes and promises ordering, not a particular difference magnitude. No target libc delegation.

Reject superficial reasoning: memmove can always use the same forward loop as memcpy.

Discriminator: Require the causal argument above and an independent artifact or trace that discriminates it from: memmove can always use the same forward loop as memcpy.

Delayed assessor check: Replace pointer-order assumptions with an explicit same-arena offset API and derive a portable interval-overlap test.

<a id="t1106b"></a>
## T11.06.b — Test boundaries, overlap contracts, alignment, and zero-length conditions.

Every access stays inside the declared live arena; zero count is governed by the local API and is not automatically a standard-library null-pointer guarantee.

Reject superficial reasoning: Passing two overlap examples establishes every alignment and lifetime case.

Discriminator: The existing assessor uses uintptr_t ordering, which is appropriate only under its declared flat-address implementation assumptions. Within a single arena, offsets provide an alternative derivation; across unrelated objects an ISO relational pointer comparison is not a portable replacement.

Delayed assessor check: Use disjoint separately allocated objects and explain why relational pointer comparison needs a different portability argument.

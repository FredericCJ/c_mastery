# PR-T08-03 supplemental assessor analysis

Assessor only. The accepted project remains the implementation contract. These arguments are authored technical expectations, not fresh experiment or learner evidence.

<a id="t0806a"></a>
## T08.06.a — Distinguish arithmetic instruction availability from calling convention.

Instruction selection and call convention can vary independently; the declared AAPCS variant controls argument placement.

Reject superficial reasoning: Hardware floating-point instructions necessarily imply hard-float argument passing.

Discriminator: Require the causal argument above and an independent artifact or trace that discriminates it from: Hardware floating-point instructions necessarily imply hard-float argument passing.

Delayed assessor check: Compare hard-float with softfp and identify an interface that becomes incompatible although both can emit VFP instructions.

<a id="t0806b"></a>
## T08.06.b — Compare soft, softfp, and hard-float configurations where applicable.

The matrix records ABI compatibility independently of arithmetic; a missing linker is not an expected ABI rejection.

Reject superficial reasoning: A rejected mixed link means the arithmetic algorithm is wrong.

Discriminator: Require the causal argument above and an independent artifact or trace that discriminates it from: A rejected mixed link means the arithmetic algorithm is wrong.

Delayed assessor check: Introduce a variadic function and derive why its argument marshaling differs from a fixed-prototype VFP candidate.

<a id="t0806c"></a>
## T08.06.c — Audit library compatibility and floating-point register preservation.

The d8-d15 preservation obligation differs from scratch VFP registers; a correct numeric result can hide corrupted persistent state.

Reject superficial reasoning: An FPU register is always caller-saved.

Discriminator: Require the causal argument above and an independent artifact or trace that discriminates it from: An FPU register is always caller-saved.

Delayed assessor check: Change to a target with fewer VFP registers and distinguish absent registers from changed calling-convention rules.

## T08.07.a — Write callable routines with explicit symbol and section declarations.

The supplied arithmetic and hostile gates assess distinct obligations; symbol/section metadata and permitted memory extent must also be justified.

Discriminator: Require the causal argument above and an independent artifact or trace that discriminates it from: A global label alone fully describes a portable callable function.

Delayed assessor check: Export the same algorithm from a shared object with hidden internal labels and inspect the dynamic symbol boundary.

## T08.07.b — Generate useful unwind/debug annotations where supported.

CFA and saved-register descriptions must match each instruction interval; return-value tests cannot assess unwinding.

Discriminator: Require the causal argument above and an independent artifact or trace that discriminates it from: A frame pointer or correct execution automatically makes unwind metadata correct.

Delayed assessor check: Remove the frame pointer and derive CFI directly from rsp changes, including an early-return path.

## T08.07.c — Test register preservation and stack alignment mechanically.

Arithmetic, preservation and stack alignment have separate observations; diagnose the earliest wrong state rather than treating any crash as proof of the intended defect.

Reject superficial reasoning: Testing many input arrays substitutes for testing call-state invariants.

Discriminator: Require the causal argument above and an independent artifact or trace that discriminates it from: Testing many input arrays substitutes for testing call-state invariants.

Delayed assessor check: Call the routine from a separately compiled optimized C consumer with different surrounding register pressure.

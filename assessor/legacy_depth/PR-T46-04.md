# PR-T46-04 supplemental assessor analysis

Assessor-only; author reasoning, not independent or learner evidence.

<a id="t4604a"></a>
## T46.04.a

Static function metadata and dynamic invocation state have different lifetimes. Reusing one local array across calls corrupts recursive state.

Expected relation: Each invocation has independent locals/IP/base; return restores the caller's operand boundary and preserves its live temporary.

Withheld transfer discriminator: Use mutual recursion with two functions sharing the same local slot numbers.

<a id="t4604b"></a>
## T46.04.b

Tail calls can reuse a frame only when caller continuation and ownership obligations permit it. The language-level result and debugging model must remain explicit.

Expected relation: The explicit VM frame limit is enforced; the interpreter dispatch loop does not recursively call itself; argument movement preserves order.

Withheld transfer discriminator: Add tail-call elimination under a new opcode contract and compare resource behavior.

<a id="t4604c"></a>
## T46.04.c

Avoiding recursive interpreter calls does not eliminate the storage cost of the VM state. Caller placement and concurrent instances matter.

Expected relation: The failure categories differ; larger fixed frame arrays consume explicit memory and can change placement/stack requirements.

Withheld transfer discriminator: Move VM storage from an automatic object to caller-owned static storage and reassess lifetime/reentrancy.

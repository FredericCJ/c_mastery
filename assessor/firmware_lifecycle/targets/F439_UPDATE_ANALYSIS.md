# F439 assessor analysis

Keep this analysis and corrected sources out of learner packaging. The mechanism is single-core: no invented FWPeer success can authorize a record. `newer` requires actual prior admission, strictly increased generation and another fixed slot; the public struct is caller discipline, not an unforgeable handle. `f4_install_result` rechecks current policy and actual stored signature after all programming.

The record CRC covers its first64bytes; sequence/complement and final marker are separately checked. Both candidate image and metadata must match. The final marker has1bits at high positions, so a partial prefix write can already create exactly the intended record. The independent fixture compares bytes; it deliberately does not label all interrupted writes invalid. At reset, ignores trial even if fully written; only the uninterrupted launch consumes it. Incomplete health stops before any journal command. An interrupted next-journal erase preserves the selected record. No old-record erase is needed after confirmation; the next update reuses that inactive journal.

Controller writes only sectors7–11; x32 programming requires the documented voltage qualification. Erase completion restores the previous lock/parallelism, verifies all128KiB in32word batches, and fresh-programs each word once. Readback and controller errors stop rather than advance state. Poll budget exhaustion has no cancellation or unlock promise. Caches are disabled at entry, reset while disabled after mutation, and never silently enabled. F4 USART requires SR then DR clearing; PE without RXNE is reported immediately without pretending the flag was cleared. Wait for TC after ACK, not just TXE.

Mutant1 overwrites the active slot; mutant2 ignores corrupted readback; mutant3 ignores application generation/result. Port mutant1 accepts remapped banks; port mutant2 omits the required error-clearing read. Require each to compile and fail a named semantic assertion; a build error is not a killed mutant. The stub also compiles and fails semantic acceptance.

The linked bank2 service can read/write bank1 while executing out of the other bank; map/disassembly/symbol/stack checks bind the complete selected build. The bank2 report veneer runs on the original application stack; the supplied app uses a tiny bounded frame and an upper64KiB reserved region. The service static objects remain in lower64KiB. Privileged code can violate this discipline; the MPU profile is not a hostile-code sandbox. Actual MPS2 execution checks original application recurrence plus admission to the single-core commit state, not F439 controller behavior. No hardware-specific result is fabricated.

Delayed assessor: supply two records, corrupt the higher record digest, then revoke the key used by the remaining image. Expected cold selection is none, not automatic trial retry. Require the learner to justify current-policy refusal, preserve outputs and identify the need for authenticated recovery/provisioning. Under x16 changed voltage, require two halfword writes per former word and a new tear oracle, alignment and CR configuration; constant substitution alone is insufficient.

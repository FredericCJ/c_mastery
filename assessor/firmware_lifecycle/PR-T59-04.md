# Assessor analysis: PR-T59-04

A new image that starts once may fail before it can provide a service. Trial boot retains the old confirmed image until the new application explicitly confirms health. Reversion after a failed trial and rejection of security downgrades serve different goals.

Prove repeated unconfirmed resets eventually return to a known confirmed slot. Identify the exact persistence point before transferring control and the risk if it occurs afterward.

The reference implementation is in `core.c`; inspect it together with the public test. The named fault is: The faulty state machine retries the unconfirmed image forever, causing a boot loop. A watchdog reset alone cannot repair an incorrect persistent selection policy.

Require the learner to derive 0 from the fixture inputs independently. Persist the attempt before jumping, and keep the confirmed image independently recoverable.

Transfer answer obligations: Require two-core health confirmation on H745 and inject one core failing after the other confirms; define a joint image-generation commit and recovery protocol.

Real erase/program granularity, torn writes, cache maintenance, boot ROM interaction, watchdog reset and physical power-interruption evidence remain required on dedicated boards. Model success is not secure-boot certification.

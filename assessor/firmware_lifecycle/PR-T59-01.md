# Assessor analysis: PR-T59-01

Programming flash generally clears selected bits; restoring bits requires an erase operation. A RAM assignment hides this restriction. Validate the entire requested update before modeling a transaction, then split it explicitly to investigate interruption.

Prove admission catches every forbidden bit transition and prevents a partially modified prefix. Derive physical program-unit alignment and erase-sector dependencies separately.

The reference implementation is in `core.c`; inspect it together with the public test. The named fault is: Repair a model that silently ANDs an illegal request and reports success. Its resulting bytes differ from the requested image even without a crash.

Require the learner to derive 15 from the fixture inputs independently. A legal requested byte is a subset of the currently set bits.

Transfer answer obligations: Replace whole-span admission by per-program-unit persistence and cut power after each unit; derive which metadata must stay uncommitted until image completion.

Real erase/program granularity, torn writes, cache maintenance, boot ROM interaction, watchdog reset and physical power-interruption evidence remain required on dedicated boards. Model success is not secure-boot certification.

# Assessor analysis: PR-T59-03

Image length validation must happen before checksum/signature operations consume bytes. A signature over one extent cannot authorize another. Separate parsing from the trusted verifier and do not let a malformed header select arbitrary memory.

Specify exactly which bytes and metadata the trusted verifier authenticates; derive bounded extent arithmetic and the immutable authority for the rollback floor.

The reference implementation is in `core.c`; inspect it together with the public test. The named fault is: The intentionally faulty admission ignores a failed verifier verdict. Harmless success is selection of a synthetic unauthorized image; no real key or deployed bootloader is targeted.

Require the learner to derive 1 from the fixture inputs independently. The verifier and security floor are trusted inputs, unlike fields inside the image.

Transfer answer obligations: Introduce key rotation and a revoked signing key; show why a numerically newer version with a valid old-key signature may still be inadmissible.

Real erase/program granularity, torn writes, cache maintenance, boot ROM interaction, watchdog reset and physical power-interruption evidence remain required on dedicated boards. Model success is not secure-boot certification.

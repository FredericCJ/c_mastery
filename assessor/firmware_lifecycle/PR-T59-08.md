# Assessor analysis: PR-T59-08

Crash records must survive a subsequent reset without being mistaken for fresh normal data. A partially written record cannot be trusted merely because a magic field was stored first. Capture itself must use bounded operations safe in the failure context.

Define record validity, persistence assumptions, reset-reason interpretation and ownership of storage during recovery; corrupted PC values must never become executable addresses.

The reference implementation is in `core.c`; inspect it together with the public test. The named fault is: Repair a record reader that accepts a committed but corrupted payload. A synthetic check detects only its modeled faults; physical retention and fault-entry register capture remain separate.

Require the learner to derive 2654431674 from the fixture inputs independently. Treat captured addresses as data to inspect, never as trusted control flow.

Transfer answer obligations: Add nested faults and a full crash log; choose preserve-first versus preserve-latest policy, prove bounded writes and assess what diagnostic information is lost.

Real erase/program granularity, torn writes, cache maintenance, boot ROM interaction, watchdog reset and physical power-interruption evidence remain required on dedicated boards. Model success is not secure-boot certification.

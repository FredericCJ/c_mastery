# Assessor analysis: PR-T63-01

An attacker can exploit a mismatch between physical allocation and logical object extent even when every C access lies inside one large array. This model makes the security property observable without relying on a crash or undefined execution.

Derive subtraction-form bounds without overflow and distinguish logical isolation from ISO C allocated-object bounds. State why a sentinel violation proves integrity failure only within the teaching model.

The reference implementation is in `core.c`; inspect it together with the public test. The named fault is: Repair capacity confusion and post-write checks. A canary that detects corruption afterward does not restore overwritten data or authorize the write.

Require the learner to derive 0 from the fixture inputs independently. Check n<=capacity-offset only after establishing offset<=capacity.

Transfer answer obligations: Split the logical object into a real heap allocation and run the isolated faulty path under ASan; compare deterministic model evidence with environment-dependent undefined execution and mitigation effects.

Each security dossier must retain attacker input, violated property, necessary exploitability assumptions, harmless target-local success, repaired result and residual mitigation limits. Model violations do not imply arbitrary code execution or privilege escalation.

# Assessor analysis: PR-T63-06

A format interpreter treats certain bytes as instructions rather than data. Passing untrusted text as the format transfers authority over conversions. A bounded destination does not by itself remove this semantic confusion.

Identify which argument is interpreted as a format and prove the repaired path treats attacker bytes as data. Discuss embedded NUL, truncation policy and logging integrity separately.

The reference implementation is in `core.c`; inspect it together with the public test. The named fault is: Blindly replacing percent with a question mark suppresses the witness but corrupts the required logged bytes. The real repair separates interpreter control from untrusted data.

Require the learner to derive [37, 110, 0] from the fixture inputs independently. Use a constant format or a byte-oriented sink; do not sanitize away data as a substitute for correct interpretation boundaries.

Transfer answer obligations: Add structured binary logging with explicit length and escaping at display time; test embedded NUL and terminal-control bytes without confusing storage fidelity with safe rendering.

Each security dossier must retain attacker input, violated property, necessary exploitability assumptions, harmless target-local success, repaired result and residual mitigation limits. Model violations do not imply arbitrary code execution or privilege escalation.

# Assessor analysis: PR-T63-04

Memory bounds and access authority are separate properties. A valid pointer or generation does not prove that the caller is permitted to read the object. C structs do not make capability tokens unforgeable.

Specify representation, operations, ownership and failure semantics of a checked view. Identify exactly what runtime checks enforce and what trusted-caller discipline or external verification must guarantee.

The reference implementation is in `core.c`; inspect it together with the public test. The named fault is: The mutant validates generation and bounds but ignores principal ownership. The attacker can read another synthetic principal’s object without any memory error or sanitizer report.

Require the learner to derive 0 from the fixture inputs independently. Never claim an ordinary C struct is an unforgeable capability.

Transfer answer obligations: Compare the C view with a language-enforced borrow or capability mechanism; provide a concrete C counterexample showing forged structs or escaped pointers defeat an overstated equivalence claim.

Each security dossier must retain attacker input, violated property, necessary exploitability assumptions, harmless target-local success, repaired result and residual mitigation limits. Model violations do not imply arbitrary code execution or privilege escalation.

# Assessor analysis: PR-T63-07

Double release is often created by composing individually plausible cleanup paths. A successful transfer of ownership must change which path may destroy the resource; an error label cannot infer ownership from a nonnull address alone.

Prove ownership conservation and exactly-one destructor call under every failure prefix. Explain why nulling one alias cannot revoke another copied raw pointer.

The reference implementation is in `core.c`; inspect it together with the public test. The named fault is: The faulty cleanup path releases twice after ownership moved to a callback. Demonstrate the duplicate counter first, then separately observe an actual original double-free target under ASan.

Require the learner to derive [0, 1] from the fixture inputs independently. Model release as a terminal transition and reject every repeated transition.

Transfer answer obligations: Introduce reentrant destruction and partial object construction; define callback restrictions or use detached cleanup state so recursive calls cannot double release.

Each security dossier must retain attacker input, violated property, necessary exploitability assumptions, harmless target-local success, repaired result and residual mitigation limits. Model violations do not imply arbitrary code execution or privilege escalation.

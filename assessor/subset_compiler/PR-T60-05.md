A compiler verifier checks properties the backend otherwise assumes. Rejecting malformed IR is not optional merely because the current parser behaves correctly. Resource bounds belong to the contract and must be measured before emission.

Derive prefix-height and terminal-height conditions and peak stack bytes separately for the two backends. Explain the verifier assumptions that remain outside its scope.

The reference implementation is in `core.c`; inspect it together with the public test. The named fault is: The faulty verifier accepts executable instructions after RET. That can conceal malformed data and causes consumers to disagree about the authoritative program extent.

Require the learner to derive 2 from the fixture inputs independently. Reject malformed instructions before publishing a successful verification result.

Transfer answer obligations: Serialize IR to a bytecode file; add version, checked count arithmetic and canonical endianness, then fuzz parser and verifier independently.

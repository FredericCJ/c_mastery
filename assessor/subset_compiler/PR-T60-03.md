# Assessor analysis: PR-T60-03

A small compiler must state a precise language rather than accidentally accept a poorly implemented large one. This subset uses a32-bit unsigned value type; wraparound is deliberate. Host int width must not silently change the evaluator semantics.

Derive modulo behavior independently of host signed overflow; identify absent signed conversions, floating-point rules and pointer semantics rather than pretending they are covered.

The reference implementation is in `core.c`; inspect it together with the public test. The named fault is: A backend replaces multiplication by addition or performs signed overflow in its evaluator. Passing small positive constants is insufficient evidence.

Require the learner to derive 4294836225 from the fixture inputs independently. Conversion to the specified unsigned width happens after the defined wide operation.

Transfer answer obligations: Add a signed32 type with explicit overflow diagnostics, usual arithmetic conversions and casts; construct a case where the unsigned and signed programs must differ.

Execute emitted x86-64 code against an independently compiled C oracle, execute Thumb output in a dedicated emulator, and complete changed-condition extensions. Public IR anchors do not certify a general C compiler.

# Assessor analysis: PR-T60-08

Agreement between two implementations is evidence only when they do not share the same fault and the source has defined semantics. Random source generation must track grammar, type and resource constraints; arbitrary C text is a poor differential oracle.

Separate front-end correctness, IR semantics, backend correctness and target environment. Define the supported source subset before interpreting an oracle disagreement.

The reference implementation is in `core.c`; inspect it together with the public test. The named fault is: An integrated path perturbs an otherwise correct result; a shared parser-based expected value would reproduce some parser faults and miss them. Use independently generated trees.

Require the learner to derive 18 from the fixture inputs independently. Retain source, input, tree denotation, IR, assembly, machine result and tool versions for the smallest disagreement.

Transfer answer obligations: Add variables, conditionals, loops and function calls in separate increments with revised grammar, IR verifier and both backends; retain counterexamples at each boundary and state any still-unimplemented C construct.

Execute emitted x86-64 code against an independently compiled C oracle, execute Thumb output in a dedicated emulator, and complete changed-condition extensions. Public IR anchors do not certify a general C compiler.

# Assessor analysis: PR-T60-07

Thumb integer calls use r0 for the first argument and result. Reusing r0 for constants destroys the argument unless it has another live location. Return addresses and stack alignment are ABI state, not IR values.

Prove the private operand stack remains word-aligned and returns to its public8-byte boundary. Identify the Thumb-state return and why r3 would not survive a newly added call.

The reference implementation is in `core.c`; inspect it together with the public test. The named fault is: The backend omits argument preservation, so expressions that load x after a constant compute from the constant instead. A constant-only test cannot detect this.

Require the learner to derive 24 from the fixture inputs independently. The backend is a leaf; adding calls invalidates its current r3 lifetime argument.

Transfer answer obligations: Retarget Thumb-1 without movw or the same instruction set assumptions; synthesize constants, inspect helper dependencies and execute on the corresponding emulator CPU.

Execute emitted x86-64 code against an independently compiled C oracle, execute Thumb output in a dedicated emulator, and complete changed-condition extensions. Public IR anchors do not certify a general C compiler.

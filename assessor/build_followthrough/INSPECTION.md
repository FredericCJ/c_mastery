# Observed generated-code interpretation

These findings follow the exact GCC15.2/Clang21.1.8 reports and object/final-code logs produced by `run_build_followthrough.py`. Recheck them when the bound sources/flags change. Code evidence does not establish universal speed, cache causality or physical board behavior.

GCC O3 emits two conditional moves for both clamp forms, in a different dependency order. Each function occupies22 bytes including the recorded entry instruction. Clang emits identical19-byte comparison/conditional-move instruction sequences for `bf_clamp_branch` and `bf_clamp_select`. This directly rejects the hypothesis that removing the source `if` necessarily removes a machine branch or improves speed. The constant/alternating/mixed paired measurements must still retain noise and call-site context.

GCC `bf_recurrence` carries its accumulator through shift-by5, add-old-accumulator, and add-next-input before the backedge. The arithmetic dependency remains. Strict `bf_reduce` uses serial `addss` instructions even when its loop is unrolled; unrolling is not floating reassociation. The selected relaxed profiles deliberately relax association, signed-zero and contraction obligations but retain finite/NaN handling; the small cancellation probe returning3 under both is only a selected observation, not proof the relaxed contract is identical. A prior `-ffast-math` Clang attempt explicitly rejected the NaN test under its no-NaN assumptions; that failed build is retained.

GCC constant-unroll wrappers1/2/4/8 occupy264/568/504/616 bytes; Clang occupies274/565/405/469 bytes in the recorded O3 object. The sequence is not monotonic in the source unroll factor. Use `.su` and disassembly for stack and spill interpretation; larger byte count alone does not demonstrate an instruction-cache miss. Loop versioning/tail and vectorization messages are mapped to these exact generated objects, and plain/LTO/archive linked images are retained because a later stage can supersede an object-level inference.

The ordinary hosted core may acquire compiler-generated memory helpers for record compaction. The separate freestanding `-fno-builtin` audit admits only the explicitly linked `bf_sse2` specialization. Cortex-M4 images use section garbage collection and retain only the scalar path; their final undefined-symbol set must be empty, with no gcov collector. Volatile board input snapshots preserve runtime arithmetic under LTO. The images are unflashed and supply no physical timing, stack-watermark or energy evidence.

Hardware PMU `cycles` is unsupported in this WSL environment; no security setting is changed. The software `cpu-clock` sampler is attempted independently, with raw samples, symbol report, sampled addresses and matching saved ELF. A hosted `gprof` histogram is a second instrumented sampling view, not a substitute for unavailable cache/TLB events. Linux `getrusage` minor-page-fault deltas are real process counters but describe faults resolved without I/O, not cache misses. Their measured interval includes the documented process work and does not isolate an instruction.

CBMC's original `--cover cover` attempt hit an internal invariant failure. It was not valid reachability evidence, despite an early runner treating that optional command as observational. `attempt6_witness_invalidation.json` preserves that finding without rewriting the historical receipt. The current guard rejects internal tool failures and requires actual n=0/n=4 counterexamples to negated reachability assertions, plus a separate vacuous-domain success. No solver crash is a negative semantic control.

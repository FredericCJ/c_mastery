# Assessor: split, merge and affected-minimum repair

The parent implementation's full refresh is retained in the fork as an explicit comparison; the historical provider is unchanged. The new store structure has a touched mask plus up to 31 unique IDs. Do not link or copy it through the old C ABI. Capacity3 changes page magic as well as occupancy rules, so an old decoder cannot accidentally accept a smaller-tree profile merely because the current node happens to contain few keys.

For capacity 7, eight leaf records 0..7 become `[0,1,2,3]` and `[4,5,6,7]`, with copied parent separator 4. After an eight-separator internal overflow, separator index 4 is promoted, leaving four separators/five children left and three separators/four children right. For capacity 3, the corresponding quantities are 2/2 leaf records; separator index 2 promoted; two separators/three children left and one separator/two children right. Promotion removes a separator from the children, not a leaf record. Both satisfy leaf minimum h and internal minimum h-1. A root with one remaining child contracts to it; the empty map retains the original leaf 1 and exact used bitmap 3.

Deletion can change the first key without underflow. The selected capacity 7 key 20 is the first key of the final seven-record leaf in 0..26; removing it leaves six records, but its parent minimum changes to 21. Capacity3 key 8 in 0..10 likewise leaves a valid two-record leaf with minimum 9. An implementation repairing only underflow paths fails here. Tests must distinguish the return value from the structural checker and complete map/scan behavior.

Every insertion/deletion marks its initial ancestor path. New split siblings and the new root are marked; each borrowing or merging sibling is marked. The recipient may be outside the original path, especially a merge into the left sibling. A freed mark is ignored. Each marked internal node's child array is already final before repair. Descending child0 needs neither its own nor a descendant's separator cache, so arbitrary touched-list order is safe. Any unmarked internal node retained the same child membership and every descendant's minimum: otherwise the change propagated on the original ancestor path or through a marked moved sibling. This is the bounded affected-region argument; omitting sibling marks breaks it during internal redistribution/merge.

At most 31 distinct bits can enter the list, and each is recorded once; no write beyond the list is reachable under a valid owned store. A single operation marks O(H) nodes. Finding each of at most B separators follows at most H links, giving O(B*H^2), not O(H). Full refresh is O(P). The list avoids an O(P) scan for touched bits, but allocation search remains O(P), resident workspace remains O(P), and commit still writes the complete image. Raw work counters are source-derived algorithm observations, not hardware performance. The native cap3 objects intentionally retain the original large arrays, so reduced logical capacity does not reduce `sizeof(store)`.

Control 1 omits the off-path sibling marks; the shuffled deletion workloads expose a stale internal separator. Control 2 suppresses repair and fails the non-underflow minimum deletion. Control 3 leaves a stale leaf-next link when merging, so traversal and bitmap ownership disagree before reuse. Control 4 routes equality to the left child, failing actual separator lookups. Control 5 changes the computed child minimum before publishing the parent separator, failing exactly the first leaf split: shorter prefixes contain no internal separator and cannot expose that defect. The harness requires an ordinary `TREE_CHECK` refusal, never a signal or undefined-behavior sanitizer finding.

The twelve schedules at both capacities assert both directions of leaf and internal borrow/merge. They verify every observable record after every prefix and reinsert after complete deletion. The 4096-step mixed workload separately covers replacement and missing delete; the Python model has no tree representation and checks 3495 histories / 10725 transitions for all four executables. Four canonical 4096-byte pages are independently encoded; cross-profile decoder rejection must preserve its destination. Persistence is exercised through the selected synthetic RAM backend, and must not be labeled a failed-flush or physical drive theorem.

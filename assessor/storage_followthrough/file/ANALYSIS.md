# File-adapter technical assessment

The selected support closes only T47.11.a/b/c ordinary and .a/.b delayed. Dirty-page redo remains a distinct changed protocol. Keep original criterion and baseline identities.

The retained original transfer loop is adequate for successful short positioned I/O under the selected64-bit off_t profile, and retries EINTR. Its failed read can leave a prefix in the caller buffer. The new operation stages reads and publishes only at4096; do not retrofit that guarantee onto the raw original callback. The link wrappers cover40954 histories and check suffix pointer contents, exact offset and remaining count. Real operations bypass the synthetic descriptor hook and use the unchanged actual adapter.

SfiOp admits ownership before callbacks, stages a write copy or read result, and never advances beyond an accepted positive count. AGAIN changes the admission state so a later no-readiness call cannot spin on the callback. EINTR consumes the current step budget. Terminal IO includes malformed callback reports: their actual side effects are outside the callback contract, so `done` remains only the known accepted prefix. A successful read publishes once; cancel/error never copies its staging bytes. State and exact-owner generation reject stale tickets, and MAX retires after cleanup. Per-step budgets bound each invocation; a global deadline/retry cap belongs to the caller and cannot be inferred from repeated steps.

The actual pipe experiment demonstrates EAGAIN, no callback without readiness,13-byte progress, a second wait, then remaining bytes with hangup. It is an ordered single-page transport, not a substitute for random-access block I/O or synchronous fsync. A real network block service additionally needs address framing, request identity, remote flush authority and asynchronous quiescence; none is invented by this adapter.

Original-file execution uses a preallocated disposable image and actual pread/pwrite/fsync. The final sync wrapper can call the real fsync and then return EIO, so STORE_INDETERMINATE plus a recovered new value is an observed lost-response case. One earlier EINTR is retried. Device power loss remains outside the observed environment.

The new-name constructor opens exclusively, allocates, formats, syncs the file and then syncs the directory. The normal trace has four file fsync calls (three in actual store_format plus one final call) followed by one directory fsync. Injecting failure at the fifth leaves a complete currently readable image but uncertain name durability; the output retains its old nonowning sentinel and exactly one descriptor close occurs. The no-directory-sync mutant violates the trace, while the premature-output mutant leaks a consumed descriptor number into caller authority. The explicit private-namespace premise prevents other callers from mistaking the incomplete construction for a published service.

Linux close consumes the descriptor even on the deliberately injected post-close EINTR. Clear ownership before the call and never retry its integer. This is a Linux-specific contract, not the POSIX.1-2024 EINTR behavior. The new helper reports uncertainty; the old void close interface cannot communicate it. No cleanup may delete a preexisting name: O_EXCL refusal is before creation, and failed newly created names are retained for inspection.

The one-byte hot-root update has no provider read during begin/put/commit: the root was cached by open, mutation works on transaction scratch, and commit emits a fixed full32-page batch.34writes include two marker writes;3flushes separate invalidation, batch and publication. Checkpoint reads one marker plus32preflight and32installation pages, writes32homes plus metadata and marker, and flushes three times. Syscall accepted byte counters corroborate139264write bytes at commit and266240read/139264write bytes at checkpoint. They do not measure physical sectors, filesystem journaling or latency.

Reject any argument that partial progress means whole-page success, treats zero as retryable forever, infers directory durability from file fsync, treats a failed close as a reusable ownership token, calls the pipe a full block protocol, or compares a weaker dirty-page protocol against this one solely by byte counts. Strong delayed work changes an assumption and states exactly which ownership/persistence proof must be replaced. Source-bound author reports do not establish learner mastery or human-independent review.

# Assessor: persistent page incarnations

The critical new state is the allocation table in metadata, including free positions. A transaction generation changes every commit; it cannot distinguish two allocations of page2 within the history of that image. Conversely, an allocation incarnation remains stable while a node survives unrelated commits. Both appear on disk for different reasons. Root, child and leaf-next references carry the allocation incarnation and the loaded node checks its own incarnation against the same trusted table.

The source derivation moves every pair together: insertion shifts existing child pairs; leaf split transfers old next and publishes the new sibling's incarnation; internal split copies each child tag; new root binds both children; left/right internal borrow rotates matching tags; merges append child pairs; parent compaction shifts pairs; root contraction takes the surviving child's tag. Freeing clears node storage/bitmap only. The next allocation increments the retained counter, except MAX is skipped. The full checker still rejects dangling, shared or unreachable ownership even if all supplied tag numbers agree.

The exact ABA witness commits page2/incarnation1, releases it through complete deletion, commits the free state, and reuses page2/incarnation2. An old observational reference rejects both while free and after reuse. The MAX boundary issues MAX once, frees it and chooses a later eligible slot. Mutation2 deliberately resets to1; the test checks the allocator's actual selected IDs and persistent counters rather than assuming stale rejection alone detects every wrap defect.

Begin saves root identity and all counters. An allocation refusal before commit may restore this state only under the explicit nonescape rule for active identities. Both mint/read APIs refuse active state. A committed old reference remains valid after a clean abort because its old allocation remains authoritative. A poisoned/uncertain owner cannot issue usable references, and constructor reuse requires retiring all prior references. These rules are programmer/API discipline; a C struct with matching bits does not enforce them by itself.

Node fields are encoded at768/776/784, separate from existing keys/values/child IDs; metadata root tag is at32 and the32 counters begin at64. Decode checks active/unused tag structure, then world validation checks tags against allocated current identities. The resealed-child test distinguishes consistency from checksum coverage. It does not authenticate an image against a writer able to change metadata and all references consistently. CST5 cannot be read as CST2; native ABI changes are also explicit.

Mutation1 ignores equality and admits the crafted stale pair. Mutation3 persists zero for free counters; after delete/checkpoint/reopen, reuse can return an old incarnation and the boundary check rejects it. The complete derived-tree schedules and independent map guard against damage to ordinary split/delete behavior. The Python page oracle uses integer packing and a separate CRC provider, not the C encoder as its expected result. No physical failed-write theorem or arbitrary history proof is claimed by these author runs.

# X-T66-009: accounting survives callbacks and replacement

R1: genuine int32 arrays establish the baseline storage representation. Poison only changes values; it does not revoke C pointers or prevent stale reads. The upstream contract supplies typed storage and non-reentry, while the wrapper checks a bounded slot protocol. Its counters themselves require a saturation/refusal policy. The Rust allocator comparison is limited to the inspected primary passages, not an identical C semantic rule.

R2: keep V4Allocator byte-for-byte compatible. Wrap take/release and add a separate resize operation. Track wrapper-live cells independently from transient upstream allocation overlap. Increment the injection index before invalid-size or upstream-failure outcomes; zero size is rejected, not an implicit free. At attempt MAX refuse new work, but saturation of release counters cannot strand an existing owner.

R3: successful resize has already ended the old allocation. Do not inspect that pointer afterward, even just to compare numerical addresses in a generic upstream implementation. Cache slot/index/old size before the call and publish the new pointer/accounting after success. On NULL the old pointer, size, prefix and output remain usable/unchanged, while instrumentation records the attempt. A poison observer must run before the upstream's own poison, otherwise omitted wrapper poison is invisible. Actual frontier/COW/array consumers expose real callback boundaries; the independent two-owner model catches ledger mismatches, not every lifetime bug.

R4: a diagnostic invoked from an inconsistent partially modified allocator can recurse into that inconsistency. This implementation invokes its reporter only at a stable failure boundary and prohibits reentry from upstream callbacks. Nested allocations are permitted at the reporting boundary, counted, and prevented from recursively reporting their own failure. The first-principles three-frame error formatter allocates16cells per frame, stages text, cleans in reverse recursion order and preserves prior text on failure. The same T65 parse result can therefore have either zero or three downstream allocation attempts. Correct the resource claim to describe the complete callback graph, exact configuration and measured execution.

Distinct controls target failed/successful resize accounting, wrapper poison, hidden nested attempts and the retained baseline's poison/failure injection. Require actual semantic failures. Describe costs of eight-slot search, prefix work and resize temporary backing rather than claiming O(1) in an unspecified block size. All thirteen cost dimensions and seven sample timings remain bounded by the learner contract. No independent human review or unaided mastery is implied by these author implementations.

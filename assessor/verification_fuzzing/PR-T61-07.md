# Assessor analysis: PR-T61-07

Fuzzing a stateful component in one process can make an input fail only after a prior input. Such history dependence is a real target property only when it is intentional; accidental global state corrupts reproducibility.

Derive the required isolation between fuzz invocations, including allocator cleanup and thread joining. Distinguish deterministic input-derived randomness from wall-clock seeding.

The reference implementation is in `core.c`; inspect it together with the public test. The named fault is: The mutant retains the prior hash globally, creating a history-dependent mismatch. A single fresh-process run passes and therefore misses the defect.

Require the learner to derive 104 from the fixture inputs independently. Encode intentional history in the test input so the failure remains reproducible.

Transfer answer obligations: Deliberately fuzz a multi-command protocol where history is meaningful; encode the entire session in one input and reset only between sessions.

Actual solver version/commands/results, reachable assumption witnesses, complete-unwinding evidence and bounded fuzz campaign logs remain distinct requirements; missing tools do not become successful proof.

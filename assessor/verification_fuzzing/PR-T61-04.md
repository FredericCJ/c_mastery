# Assessor analysis: PR-T61-04

Coverage guidance steers execution toward new paths, but it does not define correctness. A fuzz target must reset state and check semantic properties rather than merely call a parser and wait for a crash.

Separate memory-safety, grammar, integrity and canonicalization properties; bound fuzz input processing without excluding empty, malformed or huge harness inputs.

The reference implementation is in `core.c`; inspect it together with the public test. The named fault is: The parser ignores checksum mismatch yet never crashes, so sanitizer-only fuzzing misses the defect. The semantic oracle must reject the corrupted frame.

Require the learner to derive 6 from the fixture inputs independently. A fuzz callback returns normally for all malformed inputs and restores per-input state.

Transfer answer obligations: Introduce streaming segmentation and state reset between repeated calls; compare every split with the single-shot decoder and minimize a split-sensitive mismatch.

Actual solver version/commands/results, reachable assumption witnesses, complete-unwinding evidence and bounded fuzz campaign logs remain distinct requirements; missing tools do not become successful proof.

# X-T69-007: assessor technical analysis

Do not include this file in learner packages.

Because link is the initial non-bitfield member, the inspected C draft rule permits recovery of its actual enclosing DSItem; it says nothing about converting the standalone sentinel. Each insertion uses a null owner as the unlinked predicate, and removal clears all link fields. Payload movement while linked leaves neighboring pointers stale. Withheld transfer gives one object two lists: each hook needs its own owner, and recovery must identify which hook and actual enclosing type are involved. External behavior dictionaries must preserve the link lifetime contract.

Independent expected example: Appending values1,2,3 produces sum6. Removing2 repairs both neighboring links, clears its membership and produces sum4. Duplicate insertion and repeated removal reject. Removing all items restores both sentinel links to itself.

Assessment boundaries: Check count and both link directions after every admitted trace of up to7 operations over four items. Test empty/singleton/head/tail/middle removal and checked-sum overflow. Retain removed objects live so rejection tests do not use ended storage. A separate diagnostic/assembly report must distinguish standard initial-member conversion from compiler-supported arbitrary-offset recovery.

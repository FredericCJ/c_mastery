## Actual asynchronous retirement solution

Keep two DSLoaded controls inside DSReload permanently stationary. The older
integer-only DSHost transfer cannot be reused by struct assignment once registry
entries hold owner pointers. Each registration owns one borrow and each queued
worker another. Only the serialized controller changes borrow counts; workers
read the API while their queue lease lives. The mutex protects go/cancel/result/
done fields; pthread_join closes the thread-lifetime boundary before queue release.
Cancellation acknowledges an intent, not quiescence. Removal while job==1 must
retain the registration even when done==1. This distinction catches mutant1.
A completed canceled callback's scalar result is discarded, catching mutant2.

Candidate preparation uses actual DSmall plus the T66 byte adapter. Two dormant
registrations can fit beside the current two in the four-entry registry. There
is no externally callable preparation window because controller calls are
serialized. On second-registration failure, release the first exactly once and
reset candidate state before closing. Mutant3 leaves the prefix owned. Commit
publishes only the slot index, then cancels the old two entries. Old copied scalar
arguments need no state pointer, but the owned serialized old snapshot remains
available for explicit retained cleanup, independently of code liveness.

The collection gate is a deterministic pre-close failure boundary. Previous
removal acknowledgements remain committed; an injected failure retains both the
module and full snapshot, so retry is safe and bounded. Mutant4 resets that
snapshot on failure. A successful real dlclose logically releases ownership;
no mapping probe or stale call establishes physical unloading.

The oracle covers all9 lengths across7 concrete failure schedules. The running
case owns two registration and two queue leases for the old module while the new
one owns two registrations. Queued cancellation executes no plugin code; the
running call returns from the host barrier back into the old DSO before setting
done. Joining/draining and then removal are essential even if the call appears
to be paused in host code. The observed implementation is serialized control with
real pthread workers, not arbitrary concurrent reload or forced interruption.

A nonreturning callback retains the old slot indefinitely and blocks further
reload; this is a documented liveness limitation, not permission to unload code.
Generation3 and registry-slot generation4 are permanent exhaustion states. An
unexpected genuine dlclose error during rollback retains the candidate in retired;
its staged state is already reset, current remains unchanged, and collection is
required. The test gate models retained cleanup without fabricating such an OS
error. Assess reasoning and changed-condition evidence separately from passing

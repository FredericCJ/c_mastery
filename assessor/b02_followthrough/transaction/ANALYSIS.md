# Withheld transaction analysis

The original four implementations should have exactly the same traces: failure0 is [0]; failure1 [0,1,10]; failure2 [0,1,2,11,10]; success with explicit caller cleanup [0,1,2,12,11,10]. No form releases the failed acquisition. Successful output3 transfers an obligation, not a cleanup action. The early-return mutant forgetting resource0 is caught by both mask and exact trace. Source shape is not a substitute for an acquired-prefix invariant.

In the extension, the mask remains a contiguous low prefix because cleanup runs downward and stops on failure. Primary cause/stage are written once at acquisition or commit failure. Cleanup writes only its separate code and accumulated failing bits. A pending failure at sloti retains bits0..i, not only i: lower resources may be borrowed by the retained owner. A complete cleanup leaves historical errors while returning FAILED for the original construction failure; treating completed reclamation as successful construction would lose information.

The registered malloc-backed pair proves the distinction directly. Sequence acquire0,acquire1,register2,commit-fail,remove2-fail leaves three live obligations and unchanged output. Retrying close adds remove2-success,release1,release0: eight total callbacks. Source-state rollback cannot erase the registry's earlier visibility or the recorded failed removal. A release result with unknown external effect is outside the specified retain-on-failure callback; require a new reconciliation protocol rather than promote this model to arbitrary distributed compensation.

The list-based oracle independently computes the stack, error history and traces for216 failure schedules and1944 snapshots. Eight close calls cover at most six injected failures plus eventual ordered releases; repeated terminal calls establish no repeated successful release. Controls use static recording state before the actual heap path, so the intentional continued-release defect fails an ownership assertion before any dangling dereference. Tests do not claim human-independent assessment, physical execution or exhaustive arbitrary callback behavior.

# Arena authority and retained cleanup analysis

The original B2 provider supplies checked64-byte offset admission and exact nonreused top marks. The wrapper's allocation records add byte authority without manufacturing typed objects in declared character storage. Its successful reserve publishes only after capacity and extent admission, with a fresh ID; rollback deletes suffix records so an old borrow cannot name a later allocation at the same offset. A live unmodified owner is a required premise. A stale raw pointer or copied control is not repaired by an integer generation check.

The cleanup failure discriminator must be stronger than observing a failure return. In the first reverse pass, successful callbacks may already have external effects. Keeping their done bits prevents double close, while retaining the whole scope allows failed callbacks to inspect still-live backing and retry. Reentrant mutation is BUSY; read-only checked access is permitted. Once every resource is closed, the top mark is still exact and the retained original rollback cannot fail under the valid-control premise. Only then remove allocation records and cleanup metadata. A success callback may destroy its context because later attempts never load it. Caller destruction of a still-failed context violates the contract.

Inner commit pops a token, not its saved byte range. The parent's saved record counts remain unchanged, so inherited children remain in the parent's reclamation suffix, with reverse registration order preserved across scopes. A root commit is refused because this API provides no outer cleanup owner to receive it. New same-depth marks have new IDs. Allocation/mark exhaustion never prevents cleanup; no counter wraps or resets while stale tickets may exist.

The independent stack model covers both legal and illegal transitions, and the arbitrary-precision rounding oracle checks concrete extent statuses rather than mirroring the C subtraction. Explicit cleanup callbacks distinguish external partial success, retry, registration failure ownership and forbidden reentry. Compiled controls isolate out-of-order rollback, premature reclaim, repeated successful close and inner-commit reclaim. No invalid-pointer execution is used as a golden result. Host and emulator reports are bounded author evidence, not arbitrary-history proof, published-edition access, independent human assessment or physical measurement.

# X-T04-001 assessor analysis

Assessor-only, same-author reference analysis. Public fixtures and private solution agreement do not create reviewer independence.

## Technical solution

Check out first; reject offset>limit. If width is zero, the admitted result is offset regardless of count. Otherwise require count <= (limit-offset)/width. That subtraction is safe after offset admission; the division has a positive divisor. The bound proves the subsequent product and sum representable and no larger than limit<=SIZE_MAX. Publish exactly once. Zero count obeys the same logic and must not bypass offset admission.

For signed conversion, reject value<0, then compare its uintmax_t representation with (uintmax_t)SIZE_MAX. uintmax_t can represent any unsigned integer type's value; therefore the nonnegative intmax_t input and size_t limit compare without lossy conversion. Only then cast/write size_t. A hypothetical positive intmax_t larger than size_t is a genuine boundary, even if unavailable on the current host.

Manual checks have an unchanged-output contract. GCC overflow builtins and N3096 checked macros write results, including overflow cases; use local temporaries and separately enforce the application limit. The infinite-range mathematical operation is an oracle model, not a hidden target dependency.

## Expected discriminators

For limit 255, offset 16/count 3/width 4 succeeds with 28; count 60 rejects. Offset8/countSIZE_MAX/width0/limit8 succeeds with8, while offset9/count0/width0/limit8 rejects. At actual machine width, count=SIZE_MAX,width=2 can wrap to an apparently bounded result if admission is performed after multiplication; use an unbounded model to distinguish intended extent from machine residue.

The 16^4 campaign enumerates 65,536 reduced-domain tuples; do not call it an exhaustive machine-width proof. Each rejection must preserve a nontrivial sentinel. Compile mutants and require the semantic assertion to fire; compilation failure or a sanitizer crash is not adequate mutation evidence.

R3 needs a proof for every check and final operation, not just a helper call. R4 must compare the actual output side effect and availability of all three approaches. ## Withheld delayed variant: X-T04-001-DELAYED

Supply a two-segment arena request: header=12, first count=7,width=9, second count=10,width=11, ceiling=180. Each individual segment with the header fits, but the combined mathematical total185 rejects. Require a new all-or-nothing result struct containing both offsets and final extent, preserving it on any failure. Then supply negative signed second count and a source type wider than the modeled size type. The solution must not cast first or accidentally test each segment against the full original remainder.

Accept staged checked arithmetic with temporary state, or a derived single predicate with proof; reject sequential publication. Ask which generated helper costs change on a 32-bit target. This is composition and changed representation, not arithmetic trivia.

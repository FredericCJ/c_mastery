# X-T02-001 assessor analysis

Keep this file, reference code and exact verdict tests out of learner packages. This is same-author technical analysis; it is not an independent learner assessment.

## Technical solution

The C17 verdicts in FDCase order are: DEFINED (mixed comparison false), DEFINED (unsigned sum zero), UNDEFINED (unsequenced modifications), UNSPECIFIED (AB or BA call-output order, assuming successful writes), IMPLEMENTATION_DEFINED (negative signed right shift), UNDEFINED (unrepresentable signed addition), UNDEFINED (excessive shift count), CONSTRAINT (non-null integer implicit pointer initialization), UNDEFINED (access outside the automatic object's lifetime), DEFINED (false without evaluating the division).

For the mixed comparison, int -1 converts to unsigned int; comparison with 1u is false. A constant unsigned wrap is different from signed arithmetic overflow. Each emit function executes without interleaving with the other call's execution, but the order is not fixed; the sum of their returns is 2 regardless. An operator's grouping is not a sequencing guarantee.

The shift-width case explicitly makes sizeof(unsigned)*CHAR_BIT representable; padding cannot rescue it because the count is at least the value width. The pointer initializer violates assignment/initialization constraints; an explicit implementation-defined integer conversion would be a different source. Short-circuiting prevents evaluation of the right operand; a compiler may still warn. A warning does not make the evaluated path undefined.

The repair checks required pointers and distinctness, checks INT_MAX before incrementing, then publishes the old value and new value. An output alias cannot simultaneously contain old and new values, so rejection is a contract decision. Any other initialized int can be incremented safely once.

## Assessment and falsification

Require D1 to explain each verdict independently; enum matching cannot earn mechanism level 2. Check that the learner distinguishes the normative classification from actual diagnostic output, and does not execute the undefined cases to establish expected results. The supplied public gate tests completion and repair; exact assessor classification checks add finite coverage but cannot grade the explanation.

Rebut these wrong explanations explicitly: “unsigned means all intermediate operations are unsigned”; “two's complement makes overflow defined”; “a compiler warning is required for every undefined execution”; “the old stack bytes remain available, so the pointer is valid.” Corrections must identify the precise premise, not merely name undefined behavior.

## Withheld delayed variant: X-T02-001-DELAYED

Supply a header taking unsigned short, and the expression `unsigned short a=USHRT_MAX; a+1` under two stated models: USHRT_MAX=65535/INT_MAX=2147483647, and USHRT_MAX=UINT_MAX=65535/INT_MAX=32767. In the first model promotion yields int and 65536; in the second it yields unsigned int and zero. Ask the learner to explain why storing the first result back in unsigned short also yields zero but via a different conversion.

Then change repair to a single returned struct containing old/new/status. A valid solution removes the two-output alias problem and retains pre-admission arithmetic. Seal the attempt before revealing results. This assesses transfer of types, conversion and interface reasoning; it is not another constant substitution.

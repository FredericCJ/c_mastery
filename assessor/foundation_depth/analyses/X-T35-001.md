# X-T35-001 assessor analysis

Assessor-only. The original local teaching target and synthetic counter are the entire executable security scope. This is a defined state-integrity defect, not code execution or privilege escalation.

## Technical solution and witness

Decode the exact eight-byte record with the prerequisite extent/cursor/codec path. Evaluate proposed = (int64_t)old + (int64_t)count * value, prove it fits int64_t from the field bounds, then require int32_t range. Authorization is trusted nonzero, never a record flag. Validation errors take precedence over range, then denial. Commit the counter once after all gates.

The concrete input0100000200000003 means count2/value3. With old10 and trusted authorization false, the intended proposed16 must not publish. The flawed teaching program returns denial but leaves16; this directly violates the property “non-success leaves state unchanged.” The corrected program returns denial and leaves10 for the same input/state. Neither a crash nor a sanitizer report is needed.

Range example: oldINT32_MAX/count1/value1 rejects unchanged. Zero count does not waive authority. An invalid version cannot be laundered by an authorized caller. A valid flag0x01 has no authority meaning; accepting it as a permission bit is a distinct mutant.

## Assessment protocol

Seal D1 before disclosing the planted mechanism. Ask the learner for target, asset, attacker controls, trusted inputs, write sites and a predicted harmless witness. A learner who has seen the exact mutant receives guided-diagnosis credit; the withheld variant restores an independent opportunity, not retrospectively independent evidence.

Check all failure classes against state, not just status. A repair that rolls back only the demonstrated input or checks authorization after a persistent side effect fails. Sanitizers may remain clean for the logic defect. A repaired actual counter test proves its bounded observation; future external systems require a different threat model and authorization.

R4's variable-payload arithmetic analysis supports a connection to memory safety but does not claim an executed memory exploit. The fixed format's constant work cannot justify unbounded parser workloads.

## Withheld delayed variant: X-T35-001-DELAYED

Supply events: feed first3 bytes of the witness, cancel, feed its remaining5 bytes, then feed a complete authorized record. The interface must define empty/partial/complete/failed states with an eight-byte fixed buffer. Choose the following assessment contract: cancel discards all staging; each feed supplies bytes for at most one record; bytes exceeding the remaining frame capacity reject the entire feed unchanged; no implicit concatenation or second commit is allowed. A completed frame commits once, then the parser returns to empty. Authorization is a trusted per-frame value captured at the first accepted byte; later fragments cannot change it.

After cancel, the remaining5 bytes are a new partial frame, not a continuation. Feed a further4-byte fragment to that partial state: it exceeds remaining3 and must reject without commit or staged-state mutation. Reset, then feed the authorized complete record to commit16 exactly once. Inject an independent defect that retains the old authorization across cancel, and require a denied fresh frame to preserve10. The assessor may change schedules but must keep these semantics fixed.

Require explicit destruction/reset of staged state, bounded work per feed and ownership of copied versus borrowed bytes. The learner supplies new tests and a transition proof without the previous implementation.

## Limits

No host security changes, network interaction, kernel execution or hardware flashing are part of this lab. Concurrency, durable external effects and authenticated identity are outside the proven contract and remain future curriculum work.

# X-T03-003 assessor analysis

Assessor-only same-author technical analysis. The FDSlot API contract in the family uses zero for successful initialization and a nonzero result for failure.

## Technical solution

Acquisition establishes an allocation, not an initialized FDValue. Save its exact allocator/context for release. Typed initializer stores establish the concrete effective-type/value story; source character copying from a live FDValue is a separate valid route under the selected rules. An aligned declared byte array does not become arbitrary typeless allocated storage by cast.

Successful initialization installs optional destroy/context and enters INITIALIZED. Failure means the initializer already undid its own partial acquisitions; the slot must deallocate backing storage once, clear its ownership state and return EMPTY. Calling a full destructor on failed initialization assumes facts never established. Publish accepts INITIALIZED or PUBLISHED and returns the existing borrow. Reset from ACQUIRED frees without a destructor; reset from initialized/published calls a supplied destructor then releases. Empty reset has no effects.

All callbacks return normally, do not reenter or retain ownership, and their contexts outlive use. The allocator must honor shape/alignment; this API cannot authenticate a malicious native pointer. The wrapper cannot be copied while it owns storage. It does not enforce a language-level move, and pointer qualification does not prolong its borrow.

## Expected event histories

Allocation failure: request, allocation-null, EMPTY; no deallocation/destruction. Initialization failure: request, acquire, initialize-fail, deallocate, EMPTY. Initialized reset: acquire, initialize-ok, destroy-if-supplied, deallocate. Repeated publish returns the same live object, and repeated reset adds no events. Check callback order, not only totals.

The value's two scalar fields own no resources; partial-resource failure is still analyzed with synthetic tokens in the changed variant. Neither zeroed bytes nor allocation capacity is a generic constructor. Distinguish C17 zero-size realloc correction analysis from this slot's nonzero request.

## Rubric and language comparison

Require the access timeline, state transitions and callback closure. Correct status codes with a destructor called too early fail correctness/ownership. C accepts an ordinary struct copy of the owner unless the interface hides or prohibits it; the resulting double ownership is a protocol violation. Rust's inspected move example statically rejects later use of the moved String, while its reference explicitly documents ways destructors do not run. Reject claims that either mechanism proves arbitrary program correctness or guarantees cleanup after every termination.

## Withheld delayed variant: X-T03-003-DELAYED

Give a two-resource initializer: acquire synthetic token A, then B; inject failure at B. It must release A before returning failure. The slot then releases backing storage and must not invoke the full-value destructor. On full success, the destructor releases B and A exactly once before backing release. Give a typed-array storage adapter whose acquire reserves one actual FDValue element; its release returns a slot rather than calling free. Require a revised declared-type proof and a unique ownership transfer between wrappers.

Observe wrong-order cleanup, repeated reset and publication attempted during partial initialization. Accept explicit transfer that invalidates the source; a shallow copy without ownership revocation fails.

## Limits

The supplied API excludes callback exceptions, nonlocal jumps and concurrency. Those require a different recovery contract. Source and test review do not establish callback correctness for arbitrary external allocators.

# Assessor analysis: PR-T64-08

A numerical comparison needs a declared error model before results are measured. Relative error alone fails near zero; an absolute threshold alone does not scale, and NaNs must not accidentally pass a negated comparison.

Derive the asymmetric expected-relative policy, near-zero behavior and exceptional-value handling. Explain rounding at the acceptance boundary and why a tolerance must come from a prior requirement or error analysis.

The reference implementation is in `core.c`; inspect it together with the public test. The named fault is: The mutant removes the absolute component, rejecting a permitted near-zero error. Conversely a loose tolerance selected after seeing failures can hide a wrong algorithm.

Require the learner to derive 1 from the fixture inputs independently. Keep the acceptance requirement separate from the algorithm and from a measured discrepancy.

Transfer answer obligations: Construct condition-sensitive and metamorphic tests whose predictions do not use the implementation output as the oracle. Compare ulp-based and absolute/relative policies around subnormals, signed zero and an ill-conditioned problem.

Required extension evidence includes scalar versus explicit-vector differential tests, emitted assembly and target feature checks, fast-math counterexamples, reproducible resource/timing experiments and changed-size/data-layout transfer. Portable core tests alone do not establish SIMD execution or a performance advantage.

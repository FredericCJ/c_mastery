# Assessor analysis: PR-T64-07

A SIMD vector is a collection of fixed-width lanes governed by compiler and ISA rules. Scalar promotions, overflow behavior, alignment and tail handling cannot be assumed to carry over unchanged.

Specify lane width, widening, alignment and disjointness. Prove the vector body and scalar tail partition [0,n), and distinguish GCC vector operators from ISO C scalar promotions.

The reference implementation is in `core.c`; inspect it together with the public test. The named fault is: The mutant rounds n down to a four-lane boundary and leaves the tail unchanged. A benchmark using only multiples of the lane count can conceal this correctness failure.

Require the learner to derive [32767, -32768, 3, 5, 7] from the fixture inputs independently. Make the tail begin exactly where the complete-vector loop stops.

Transfer answer obligations: Change lane width and input alignment; implement a runtime-dispatched path with a scalar fallback. Inspect ISA/OS feature checks, emitted instructions and equal-contract performance distributions.

Required extension evidence includes scalar versus explicit-vector differential tests, emitted assembly and target feature checks, fast-math counterexamples, reproducible resource/timing experiments and changed-size/data-layout transfer. Portable core tests alone do not establish SIMD execution or a performance advantage.

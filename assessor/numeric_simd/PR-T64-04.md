# Assessor analysis: PR-T64-04

Small terms can disappear when added to a much larger partial sum. Neumaier compensation retains an estimate of that lost contribution, but depends on a particular arithmetic model and does not solve ill-conditioned data in general.

Derive the correction for each magnitude ordering and identify every rounding point. Compare naive, compensated and exact-rational reference results without claiming a universal relative-error bound near a zero sum.

The reference implementation is in `core.c`; inspect it together with the public test. The named fault is: The mutant drops compensation and returns0 for [1e16,1,-1e16]. Reassociation permitted by fast-math can invalidate the correction identity even when the source text is unchanged.

Require the learner to derive 1 from the fixture inputs independently. Keep a separate correction and compare with an exact integer/rational oracle on constructed data.

Transfer answer obligations: Implement pairwise summation and a fixed reduction tree for parallel execution. Compare accuracy, stack use, reproducibility and throughput under an equivalent exceptional-value contract.

Required extension evidence includes scalar versus explicit-vector differential tests, emitted assembly and target feature checks, fast-math counterexamples, reproducible resource/timing experiments and changed-size/data-layout transfer. Portable core tests alone do not establish SIMD execution or a performance advantage.

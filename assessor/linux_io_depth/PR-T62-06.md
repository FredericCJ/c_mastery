# Assessor analysis: PR-T62-06

Progress can refresh an idle deadline without extending an overall operation deadline. Timer notification may be delayed or coalesced, so the state machine compares current monotonic time with its recorded start instead of counting callbacks.

State the half-range observation assumption and prove equality is expiration. Distinguish wall-clock corrections, monotonic elapsed time and deadline policy.

The reference implementation is in `core.c`; inspect it together with the public test. The named fault is: The faulty start+duration comparison wraps the deadline and expires an operation prematurely. Resetting the total deadline after each byte also permits indefinite slow progress.

Require the learner to derive 1 from the fixture inputs independently. The finite-width argument needs a bound on the unobserved elapsed interval.

Transfer answer obligations: Combine idle and total deadlines with eventfd shutdown and signalfd notifications; measure cancellation latency without claiming observed maxima are universal bounds.

Actual epoll, eventfd/timerfd/signalfd, io_uring feature/error paths, splice/sendfile and fsync/rename observations are required; unavailable kernel features are explicit gaps and never simulated passes.

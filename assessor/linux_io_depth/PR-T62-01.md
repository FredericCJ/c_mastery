# Assessor analysis: PR-T62-01

A short write can stop inside an iovec element. Retrying the original vector duplicates already accepted bytes; advancing by elements instead of bytes skips data. Validation must also reject a backend reporting more progress than remained.

Prove accepted progress plus remaining extent equals the original stream length, including zero spans and overflow. Distinguish kernel acceptance from remote delivery or persistence.

The reference implementation is in `core.c`; inspect it together with the public test. The named fault is: The faulty cursor resets the within-element offset after a short write, duplicating the first byte of the next span on retry.

Require the learner to derive [3, 1] from the fixture inputs independently. Validate total remaining bytes before mutating the public cursor.

Transfer answer obligations: Add EINTR, EAGAIN and an error after a nonzero prefix; define whether the API returns progress plus deferred error or an immediate terminal error and test consumers.

Actual epoll, eventfd/timerfd/signalfd, io_uring feature/error paths, splice/sendfile and fsync/rename observations are required; unavailable kernel features are explicit gaps and never simulated passes.

# Assessor analysis: PR-T62-02

Edge-triggered notification reports a readiness transition, not one unit of work. If a consumer processes only one item and sleeps again, remaining data can wait indefinitely. Fairness requires remembering ready work when a per-dispatch budget expires.

Distinguish kernel notification, locally remembered readiness and actual EAGAIN. Derive a fairness budget that does not lose readiness or spin forever after EOF.

The reference implementation is in `core.c`; inspect it together with the public test. The named fault is: The mutant clears readiness at budget exhaustion while unread data remains. The pipe receives no new edge, exposing a liveness failure without a crash.

Require the learner to derive 1 from the fixture inputs independently. Budget exhaustion moves work to a ready queue rather than forgetting it.

Transfer answer obligations: Add two continuously active peers and timerfd deadlines; prove bounded dispatch work and measure fairness under equivalent correctness contracts.

Actual epoll, eventfd/timerfd/signalfd, io_uring feature/error paths, splice/sendfile and fsync/rename observations are required; unavailable kernel features are explicit gaps and never simulated passes.

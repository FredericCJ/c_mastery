# Assessor analysis: PR-T62-08

Avoiding one userspace copy does not remove all data movement or lifetime obligations. A page can remain referenced by a kernel operation after local submission; mutation or release before quiescence changes the data being transmitted.

Distinguish copy avoidance, kernel retention, DMA mapping and application borrowing. Derive memory-pressure/backpressure costs and what the selected syscall actually promises.

The reference implementation is in `core.c`; inspect it together with the public test. The named fault is: The mutant releases after terminal I/O while an application borrower still uses the buffer. Kernel completion does not revoke independent application ownership.

Require the learner to derive 0 from the fixture inputs independently. Compare equivalent bytes and durability before comparing throughput.

Transfer answer obligations: Introduce direct I/O alignment constraints and unsupported-filesystem errors; preserve a semantically equivalent fallback and measure overhead without silently changing durability.

Actual epoll, eventfd/timerfd/signalfd, io_uring feature/error paths, splice/sendfile and fsync/rename observations are required; unavailable kernel features are explicit gaps and never simulated passes.

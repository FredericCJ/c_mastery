# T65.08 assessor: separate policies and one report owner

The retained counter's OFF effect is total over its admitted domain because it
clamps a representable candidate. That premise does not transfer to an unchecked
memory primitive. Every mode must guard the address. Report overflow is checked
before the increment; valid writes do not need report capacity. Empty views must
reject without evaluating a NULL-based address. The deliberately flawed control
uses a shorter advertised view inside an actual8byte object, so its unauthorized
sentinel change is defined and harmless; never replace it with an arbitrary unsafe
out-of-object execution and call a crash an exploit.

The default C11 mutex and explicit POSIX variant protect bytes, counter and reports
with one lock. A snapshot publishes a local staged copy after unlock. Counter and
byte paths must share the actual count, not per-thread/private discarded increments.
At reportMAX, the counter remains90 after the final byte refusal. Thread start/join
handles and the byte object remain live through quiescent destruction. C11 TSan
runtime failure is reproduced by a separate minimal protected-write control;
POSIX passing TSan does not silently change that result.

R1-R4 require both model tables and execution: all legal counter inputs plus report
edges, all byte modes, NDEBUG's omitted essential increment, actual4worker counts,
and the changed synchronization contract. A lock-free report-only counter would
not by itself serialize the byte/counter effects. Assert is not an admission API.
Unexpected unlock failure deliberately terminates this local process; no rollback
or injected recoverability claim exists. Independent delayed work remains unassessed.

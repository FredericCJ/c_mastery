# Assessor analysis: six byte/string criteria and transfers

The 23409 cases enumerate size0..16, both offsets0..size, and count0..size.
Expected destination bytes come from an immutable snapshot, so the oracle is
independent of copy direction. A forward-only mutant fails overlap; the cursor
mutant commits before output admission; the record mutant omits padding. Each
must compile and exit1 at BYTES-CHECK. The learner stub is a separate rejection.
The accepted foundation.c is linked unchanged for f_take; the actual previously
authored format.c supplies the two publication policies. This is assessor
reference composition, never evidence that learner artifacts were integrated.

T12.03a requires the loop invariant, integer offset proof and extent obligations;
an unrelated-object pointer comparison is not a repair. T12.03b starts with a
valid int representation and restores into a declared int, while wire admission
constructs values. T12.03c's wrapper deliberately strengthens empty-span behavior;
it must not call memcpy(NULL,NULL,0) and infer permission from a successful run.
T12.04a assesses both view/string length and the binary-field adapter's atomic
cursor/output commit. T12.04b must cite the formatter's exact result fields and
two-pass assumptions, not just see a NUL. T12.04c's record semantics intentionally
permit a full-width nonterminated field while requiring zero padding when shorter.

Withhold the six existing DELAYED tasks and this analysis until the ordinary
attempt is submitted. Supply disjoint arrays; padding-bearing structs; one-past
empty spans; a network field with embedded zeros; no-truncation output; and a
fixed-width record, respectively. Require an independent derivation, a changed
implementation when applicable, and a counterexample to the old contract.
Alternative valid representations can pass if they preserve the specified
observable behavior and cost bounds. A crash or an optimized-away invalid call
cannot substitute for the missing semantic argument. All7-day evidence is pending.

The struct experiment reports its real layout. It initializes all known padding
bytes after member writes so a difference is intentional rather than a claim
about unspecified compiler padding. Source code using raw memcmp as logical
equality remains wrong even if an ABI happens to have no padding in one struct.

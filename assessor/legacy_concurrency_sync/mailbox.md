# PR-T51-07 worked boundary analysis

Assessor only. The reference composes original CMX queues/semaphores and original CLAck receipts; neither producer is silently replaced by a synthetic implementation. Public files remain unsolved scaffolds.

T51.07.a distinguishes three boundaries. A mailbox owns copied request bytes before the server processes them. A rendezvous's raw CMX word match is not yet the wrapper's byte-copy acknowledgement when the server was already blocked. In that receiver-first schedule the client can execute again before the server wrapper is resumed, so delivery must remain BLOCKED and the borrowed input must remain live. Once copying completes, the server's `struct cdmb_request` owns independent bytes and progress can be signaled. Neither boundary is an application reply. The exact delayed variant adds a reply while retaining that distinction.

T51.07.b uses session plus checked generation plus client. Slot0,g1 can time out after transfer; g2 then occupies the same slot. A g1 reply must fail before changing `has_reply`, semaphore state or g2 output. A short reply buffer similarly leaves the existing reply and operation available. Request generation65535 is usable once; the next request rejects. Restart advances session and refuses at exhaustion. It preserves the synthetic counter but drops old volatile receipt metadata; this is not crash consistency or authentication. Old copied requests remain valid byte objects but their prior identity cannot publish into the new session.

T51.07.c compares sender result with receiver bytes rather than treating a timeout as evidence of nontransfer. Before rendezvous copy, cancellation can prevent access and yields CLOSED; after copy or mailbox admission, it yields UNKNOWN unless a reply already won. The local effect example reaches counter1, loses the reply, and demonstrates stable-ID replay remains1 while a fresh-ID retry reaches2. The latter is deliberately an unsafe application policy, not a hidden retry in the repaired transport. It motivates preserving logical identity or refusing automatic retry.

The shared settle transition observes actual CMX send/progress completion before delivery, receive, reply, cancellation and polling interpret client state. A selected timeout is terminal even when the client has not polled; accepting a late reply then dropping it at poll would violate the reply admission contract. The reciprocal schedule, reply then tick, retains success. Receiver-first raw matching can also precede a progress timeout: the server must settle before dereferencing the borrow, reject STALE and leave output unchanged. A clock value alone does not override a reply when no wait selected a timeout. The eighth control restores the missing reply-side settlement and is rejected on the precise late-admission assertion.

Receipt eviction has a precise scope: four terminal unacknowledged entries per client can replay their results. Acknowledging ID1 removes its cached result but retains a high-water fence; retry then returns STALE without reapplying. Forgetting that fence causes the exact old identity to apply again. A restart session rejects old-epoch effects; it does not recover their result or forbid an application from inventing a fresh ID and duplicating its intent. Exclude any exactly-once/durable claim beyond these admitted in-memory transitions.

The controls isolate generation, reply retention, unknown-outcome classification, finite identity, session fencing, eviction fencing and borrowed-byte lifetime.

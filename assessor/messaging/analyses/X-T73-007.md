# X-T73-007 assessor technical analysis

Snapshot-relative version checks prevent a transaction from consuming a value committed after its start. Commit validates reads while holding its own write locks, using saved unlocked versions for those cells. Atomic SC payloads avoid importing the paper pseudocode as racy C. All data remains live for the store lifetime, deliberately leaving arbitrary reclamation outside this proof. An abort can consume a timestamp but cannot publish buffered values.

## Executable effect and privatization successor

The separately packaged `followthrough/transactions.c` implements the required
`TRANSACTIONS.md` support. Its phase engine makes the unchanged core's algorithm
observable without changing the imported base API. All four write locks have
rollback receipts before any abortable hook. Seven prepublication refusals leave
payload unchanged; after the first payload store the hook is observational and
the commit completes. Clock gaps are harmless identities, unlike omitted lock
rollback. A reader of a locked payload must reject before publishing its output.
The test checks this during every payload step, then runs2,000 committed paired
increments from actual threads. These observations do not prove all atomic
histories. The3,360-history Python model works at operation boundaries only.

The owned adapter protects reference acquisition with an outer mutex, preserving
the payload before releasing that mutex. A later transaction can remove the node
from shared reachability without freeing a reader's retained owner. The reader's
old transaction may still fail validation; memory lifetime and commit validity
are separate. A read-your-writes borrow is invalidated by replacement of its
staged owner. Retained read references and staged write references are distinct
ownership edges and both must be released on abort. Reference counting cannot
collect arbitrary cycles or prevent indefinite retention by a stalled client.

Retry support deliberately compares an immediate synthetic counter with a staged
log. Two attempts occur, but only event111 from the successful attempt enters
the store log. Counter2 is the harmless demonstration of blindly repeated effects;
it is not a general compensation algorithm. Preflight log capacity before core
commit, then ordinary infallible metadata transfer under the same mutex. This
ordering does not make a real file or network send transactional. An external
service would require its own idempotency/durable protocol and separate proof.

Controls71/72 test effect timing/omission;73 tests reference acquisition before
reclamation;75 tests cleanup of abandoned writes;74 tests lock rollback;76 tests
honoring the explicit abortable phase hook. Lifetime controls fail an owner count
before stale storage is evaluated. Keep stage allocation failure distinct from
commit failure: the former preserves the supplied unique owner, while closing a
failed transaction destroys owners already transferred to it.

The newly inspected TL2 section2.3 discusses mixed transactional/non-transactional
memory and quiescence, with different lock placement assumptions. This adapter
uses immutable payloads and protected retained-owner acquisition, not speculative
access to freed C objects. No whole-paper proof, performance equivalence,
independent-human assessment or durable effect claim is imported. Require the
original R1–R4 evidence and unseen delayed work separately; public execution alone
does not establish the thirteen cost/enforcement dimensions or learner mastery.

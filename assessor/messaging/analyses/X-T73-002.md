# X-T73-002 assessor technical analysis

The shared lock makes readiness inspection and condition wait atomic with respect to publication. Predicate loops handle spurious wakes. Received offers update their ticket acknowledgment before waking the sender. Cancel is terminal for the hub, so no later offer can be mistaken for an earlier cancelled one. A frame adapter has a separate registration lifetime; it must disarm before releasing the borrowed state.

Delayed assessment splits the hub into separately locked channels; derive a registration/recheck protocol that prevents a wakeup lost between observing empty and going to sleep, or justify retaining the common lock.

Require the revised contract, minimal counterexample, implementation/trace and cost evidence before feedback. Assess the invariant under the new assumptions, not just output similarity. Schedule publication between the separate-lock implementation’s final empty check and wait registration. A timeout that merely retries hides the missed-notification defect and does not prove latency.

## Implemented owned-buffer successor

`followthrough/owned.c` retains the actual common-lock MsgHub and carries record
indices. A record has two independent completion obligations: the sender's return
bookkeeping and receiver delivery. Clearing `used` on delivery alone can let a new
send reuse the index before the old sender returns and clears its new state.
The test deliberately holds the accepted sender at the post-submit hook, consumes
and destroys its payload, verifies the metadata is still reserved, submits another
owner and cancels before releasing the old sender. The old accepted send still
returns OK; the second undelivered owner is destroyed only after users quiesce.

No mutex is held across the underlying blocking operation. Failed send leaves
the caller's owner intact; accepted send consumes it even if receiver destruction
precedes return. Cancellation prevents new receive but does not prematurely drop
buffered ownership. Destruction has an external admission-closure precondition
and checks active calls; its BUSY result is not an admission barrier by itself.

The sealed changed-condition decision retains the common readiness lock. The
split-lock counterexample publishes and signals after checking empty but before
wait registration; a predicate recheck/registration protocol is necessary if
scaling beyond this bounded hub. The actual common-lock wait establishes the
registration boundary; a separate payload-record mutex cannot replace it.
The native two-producer test covers 1,000 owned values, and the independent Python
model checks 9,334 finite send/close/select/cancel histories and final destructors.
Neither proves arbitrary fairness. Coroutine-frame quiescence is separately
provided by the source-bound T72 ticket/channel adapter, not by these destructors.

This analysis records the technical solution and expected reasoning, not learner performance or a non-author review. Public-source comparisons are restricted to the registered inspected passages. Tests, sanitizers and bounded models do not prove arbitrary lifetimes, interleavings or environments correct.

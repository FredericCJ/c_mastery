# X-T73-001 assessor technical analysis

The parent owns slot allocation; successful pthread_create admits exactly one child. Join creates the lifetime boundary before parent context release, and pthread_join makes the child result observable. Failure order is deliberately independent of scheduling. The work.pool adapter must not retain a second ambiguous owner. A nested scope can propagate cancellation safely but cannot promise prompt return if a descendant ignores checkpoints.

## Implemented nested adapter solution

`followthrough/nursery.c` uses the actual `MsgNursery` at both tree levels.
Initialize all three cancellation flags before spawning: a leaf can fail before
the creator returns from pthread_create. Cancellation may write any initialized
atomic flag; ownership of each join remains with one thread. A group alone joins
its descendants until it has returned. The root joins groups and only then retries
any incomplete inner join. A failed join keeps the caller-owned control and every
context alive; no stack-owned tree escapes into live child references.

The completion pipe carries group acknowledgments, not task ownership. Two bytes
cannot fill it, and the root owns both descriptors until joins finish. The actual
deadline reader starts cancellation when its timeout/cancel rule selects it, then
the root still waits for descendants. A cooperative checkpoint assumption is
necessary for eventual completion. The worker reducer is imported synchronously
inside a leaf: its actual worker joins precede leaf return and final context drop.

Error aggregation scans all four slots after joins, independently of temporal
order. The admitted bitmap distinguishes an unrun zero from successful zero;
spawn failure is separate from task failure. The Python oracle uses set admission
and creation-order selection for 2,187 cases. Native tests force both error orders,
all admission cuts, descendant cancellation and exactly-once drops. Four distinct
compiled controls break those properties. No general-purpose work-pool API or
actual join-failure injection is claimed. Require a learner explanation of why
releasing after the completion pipe alone would be wrong after a failed join.

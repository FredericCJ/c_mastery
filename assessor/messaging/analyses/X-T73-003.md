# X-T73-003 assessor technical analysis

## Concurrent retained winner

The separate `followthrough/completion.c` implements `COMPLETION.md` using the
actual serialized MsgOperation. The flags' compare/exchange claims completion
before any ordinary receiver or pending-value access. Cancellation and claim
share one atomic modification order, so a cancellation observed before the
successful claim fixes the stopped result; a later request cannot undo delivery.
Only the winner accesses the serialized operation. Losing callers inspect only
the atomic flags in storage protected by their own references, then retain their
payload. Independent control allocation prevents receiver destruction of its
application context from invalidating those flags.

The count increment is relaxed because the source owner already protects the
control; this is not a lock-free weak-pointer promotion algorithm. A token must
be published through a thread-start or another synchronization edge. The last
acquire/release decrement destroys the control after all token users finish.
The count mutant is caught before dropping any falsely retained token; the
winner mutant is rejected on repeated completion of a still-live control.
Native three-way competitions and3,279 model words are bounded evidence.
Neither establishes arbitrary-scheduler progress or extends the serialized
original API to concurrent callers without this adapter.

Copy receiver/context to local variables, publish DONE, call once and return without reading the operation again. The inline-completion path invalidates the common assumption that start can inspect its object after dispatching the backend. The serialized core does not solve concurrent duplicate completion; the backend must retain storage and arbitrate a winner before terminal release.

## Delayed case X-T73-003-DELAYED

Allow an operation to complete inline during start and let the receiver destroy its enclosing object. Delayed assessment connects a chain of two operations; ensure the successor starts only after ownership transfers and no predecessor field is accessed after its receiver may have destroyed it.

Require the revised contract, minimal counterexample, implementation/trace and cost evidence before feedback. Assess the invariant under the new assumptions, not just output similarity. Have the successor complete inline as well and free the entire chain. The final source inspection must show no access through either old operation pointer after the terminal callback. A callback-count assertion alone misses that lifetime violation.

## Implemented owning inline chain

`followthrough/operation.c` wraps the real producer. `mfo_start` copies backend
and context, commits STARTED through `msg_start`, then invokes the backend and
returns a constant without inspecting the operation. `mfo_finish` validates both
state and terminal status before consuming the external descriptor. Its receiver
bridge copies receiver/context/value, clears the pending owner and calls the user
receiver without any post-call object access. The descriptor passed to finish must
survive the receiver; the test uses an automatic descriptor outside the heap owner.

The first inline receiver transfers the value into the successor, frees its own
heap operation, then starts the successor. The successor completes and frees itself
inline. The outer start call returns after both objects are gone; this is safe only
because neither wrapper nor base completion accesses the old objects afterward.
The deferred case distinguishes stop request from chosen terminal status. Invalid
status must leave ownership unchanged; cancellation delivery still transfers an
owned value for receiver cleanup. Mutants omit STARTED or lose the owner. Actual
sanitizer execution checks this finite chain, not all reentrant callback programs
or unbounded recursive chains. C supplies no linear-owner type enforcement.

This analysis records the technical solution and expected reasoning, not learner performance or a non-author review. Public-source comparisons are restricted to the registered inspected passages. Tests, sanitizers and bounded models do not prove arbitrary lifetimes, interleavings or environments correct.

# Zipper, owned leaves and budgeted reclamation

Crumbs retain original ancestors and directions; reconstruct from leaf upward
so every new parent points to the new child and the old untouched sibling. A
failure resets the unpublished arena suffix but never an old node. The census
visits each node once while counting all incoming references, so sharing is
different from repeated logical expansion. Tests compare all eight positions
for all eight foci and each of four allocation cuts.

The reference-count alternative counts parent edges and retained root owners.
Each new parent adopts its newly constructed child reference and retains its
unchanged sibling. If parent allocation fails, both must be released. Forgetting
the sibling release is a rollback leak even though all strings in the new
version look correct. Successful leaf cloning creates one external string
obligation; failure at any of four node allocations must eventually discharge
it. The other control omits right-child release and leaks an entire branch.

A release queue holds owning references, not unprotected borrowed node IDs.
Budgeting one pending reference per step can free at most one node and add two
child obligations. A second retained root prevents reclamation when the first
reference is drained. The four-node single-path example takes four later steps
after its last root ownership transfers. Delayed work raises retained memory;
the caller must finish or transfer the queue, never simply discard it. None of
this establishes thread-safe reclamation, arbitrary-depth stack bounds or a
cycle collector. Actual delayed unaided performance remains separate.

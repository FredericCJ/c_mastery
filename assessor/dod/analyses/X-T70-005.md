# Query-cache extension analysis

A query is keyed by owner identity, version, required mask and excluded mask.
The match equation is live AND contains(required) AND disjoint(excluded).
Disjointness of required/excluded is an admission rule, not an implicit empty
result. Cached misses need the same invalidation as nonempty results. Every
successful mutation bumps the version, including nonstructural changes; this
conservative policy simplifies validity at the cost of extra misses.

The trace queries position without velocity, migrates its only matching entity
to both components, then expects an empty cached result. A missing epoch bump
preserves the obsolete ID. Ignoring excluded bits incorrectly admits both-
component entities. Exhaustion rejects before calling the underlying mutation;
wrapping would allow an old cache to appear current. Direct writes through the
public C struct can bypass the protocol, which is a programmer precondition,
not a language-enforced encapsulation guarantee. This does not yet implement
arbitrary deletion/reuse or supply comparative workload measurements.

## Recycled entities and deferred command solution

The adapter embeds actual DSparse and DQueryWorld components. Its world copy
contains index arrays and scalar values, so it can stage mutations safely; the
handle owner must be checked against the real world before substituting the
staged pool address. Blindly rebinding a foreign handle would erase a necessary
ownership check. On successful create, rebind the newly published handle to
the real pool. No raw pointer into the temporary copy escapes.

Delete performs archetype swap-row repair and then generation advancement in
the staged pool. A command after that deletion is stale even if its slot is
still in range. Generation exhaustion retires the slot; version exhaustion
rejects the batch before publication. An intermediate destination-full result
is a failure even if later commands might make room. This preserves a precise
sequential command semantics without solving a global migration scheduling
problem. A different all-at-once capacity policy would require a new contract.

The prefix-publication control fails the test where command1 migrates into an
available table and command2 targets a full table. The generation-ignoring
control fails when a deleted slot is reused and an old command reaches the new
occupant. Neither failure needs invalid memory access. Require explanations of
both invariants and the changed-condition command ordering, not only a passing
final snapshot. A successful batch invalidates row borrows regardless of which
slots moved. Failed batches leave the original rows and cache version intact.
The finite oracle independently models logical live/generation/mask triples;
it is not derived from table row layout and cannot validate arbitrary foreign
memory or concurrent clients.

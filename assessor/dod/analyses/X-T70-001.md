# Layout extension analysis

The same field-list expands into row members, column arrays and both conversion
visitors. That is token generation, not semantic reflection: a new field may
still require overflow, ownership or cold-column policies that macros cannot
derive. Three-lane tiles map row i to tile i/3 and lane i%3. With at most8 rows,
the last tile has at most2 valid lanes. Decode only counted rows. Cold absence
has the explicit value0; it is not lossless preservation of an absent field.

Each position update is computed in int64_t, whose range contains every
int32_t position plus an int32_t velocity times ticks0..10. Admit all results
before writing any row. The premature-commit mutant fails with overflow after
an earlier accepted row. The partial-tile mutant aliases the eighth row with
the seventh; the oracle compares complete ordered row triples.

The column extension currently converts to local typed rows before its staged
update. Its correctness contract matches AoS, but it deliberately makes no
claim to be an optimized SoA kernel. A performance investigation must measure
that conversion cost and supply a direct equivalent-contract kernel before
claiming vectorization benefits. Small public sizes are not a substitute for
warm/cold large populations or a whole-record counterexample.

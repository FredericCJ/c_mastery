# Deletion and normalization analysis

is represented by0, removed from its parent's packed array, and cleared in the

# Caller dictionary solution and bounded adversary

`dod_dictionary.c` uses16 low-to-high two-bit chunks of a caller hash, then a
linear equality-checked bucket. Keys are copied two-byte values, not pointers
into caller backing storage. Canonical ASCII equality makes A/0 and a/0 one
logical key while A/0 and B/0 remain distinct under the valid constant hash.
The inspected im HashMap description requires Hash/Eq and permits an explicit
hasher; that comparison motivates a contract, not a claim that C enforces the
laws or that this fixed-capacity representation has im's performance.

Each recursive edit copies a node into a local value. It creates the new child
before its parent and publishes the root only after the final allocation. The
saved region watermark rolls back all newly reachable candidates on failure.
Metrics intentionally retain attempted work, so cloning cut k reports k-1
completed clones and k attempts. A semantic control writes the old leaf before
allocation and is rejected by retained-root checks even though the root
publication itself is delayed. The second control replaces equality with
full-hash equivalence and loses one synthetic key under constant hashing.

Deletion must propagate an empty child upward, shift packed child entries and
clear the matching bitmap bit. It does not promote an internal child across a
hash level, which would misinterpret later hash chunks. A missing key returns
the same root without cloning. The exhausted-region check can therefore still
allow deletion that removes the only branch. Genuine map roots and unchanged
dictionary semantics are preconditions; a numeric index bound alone does not
validate every internal structural invariant.

threat model; it does not erase the equality, lifetime or capacity obligations.

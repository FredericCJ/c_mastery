# Sixteen-bit lane derivation

Masking off each lane's high bit prevents low-part addition from carrying out
of the lane. The high result bit is the XOR of both original high bits and the
low-part carry. Saturation occurs if both original high bits were set, or one
was set and the low-part addition carries into the high bit. The overflow mask
contains only bits15 and31; shifting by15 and multiplying by65535 expands each
set bit into its whole lane without overflow between lanes. OR restores a
saturated result. The ordinary-add mutant allows cross-lane carry; the missing
saturation mutant loses the required maximum. The Python oracle uses unlimited
integers and per-lane min, independent of this mask construction.

The endpoint Cartesian product and65536 correlated lane values provide useful
falsification but not an exhaustive2^64 enumeration. Derivation plus measured
compiler output is still needed. Neither C source branchlessness nor a host
instruction listing proves constant-time behavior on another ISA.


Required variant implementation is now in dod_buffers.c. The quota is requested-live bytes, not physical backing. Strong staging deliberately retains old allocations until both candidates exist, so quota rejection can occur although a final footprint would fit. Attempts/peak survive rollback; owned staged rows do not. Signed lanes use low15-bit addition and sign parity, then same-sign/different-result-sign overflow masks. The scalar oracle uses a wider representable mathematical sum. Both mechanisms have separate compiled controls and independent host models.

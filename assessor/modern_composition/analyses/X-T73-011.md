# X-T73-011 assessor analysis

COAsync owns partial bytes and handles registration/recheck. Its terminal paths disarm before returning; the adapter then copies complete output if applicable, marks itself terminal, drains OwScope and calls msg_complete. The receiver is the last permitted access boundary. Returning a local status after that call is safe; reading r->terminal is not. Cancellation calls co_async_cancel before cleanup. The backend model asserts that no borrow remains at cleanup; it does not prove a real operating-system cancellation API quiesces callbacks. Mutant3 omits disarm and fails the borrow assertion; mutant4 omits cleanup and fails the receiver precondition. The hidden changed-condition trace sends cancel, queues a callback, then acknowledges cancellation: hold a callback reference until acknowledgement and let exactly one terminal path transfer completion ownership. Concurrency needs synchronization and a retained reference for losers, not just a CAS on already freed storage.

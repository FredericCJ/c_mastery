# X-T73-011 assessor analysis

COAsync owns partial bytes and handles registration/recheck. Its terminal paths disarm before returning; the adapter then copies complete output if applicable, marks itself terminal, drains OwScope and calls msg_complete. The receiver is the last permitted access boundary. Returning a local status after that call is safe; reading r->terminal is not. Cancellation calls co_async_cancel before cleanup. The backend model asserts that no borrow remains at cleanup; it does not prove a real operating-system cancellation API quiesces callbacks. Mutant3 omits disarm and fails the borrow assertion; mutant4 omits cleanup and fails the receiver precondition. The hidden changed-condition trace sends cancel, queues a callback, then acknowledges cancellation: hold a callback reference until acknowledgement and let exactly one terminal path transfer completion ownership. Concurrency needs synchronization and a retained reference for losers, not just a CAS on already freed storage.

# Real readiness-worker cancellation analysis

`struct mc_linux_port` separates the owner thread from a polling worker. The worker
publishes a notification under a mutex and retains a queued reference. It
never writes COAsync. Owner dispatch consumes the notice and then calls the
serialized coroutine API. A readiness event is not a successful read: another
poll can observe EAGAIN, partial data or EOF. POLLHUP does not erase data already
buffered in the socket.

Cancel request sets stopping and signals both wait mechanisms. It cannot
authorize reclamation because the worker and queued notice may still reference
the port. Finish joins the worker, drops its reference, removes any queued
notice and drops that reference, then enters the existing cancellation path.
The happens-before argument uses POSIX mutex/join operations, not volatile or
a generation check. Successful join is necessary before destroying mutex/cond.
The output remains private until a complete read; cancellation reports partial
progress but leaves the caller's bytes unchanged.

The terminal callback may free the enclosing object. Copy any needed result
before delivery and make the delivery call the final operation that accesses
the object. The test's observer lives separately and records cleanup-before-
receiver, quiescent-before-cleanup and exact notice/reference accounting for
both retained and immediately freed owner storage.

Five schedules are repeated16 times for both destruction choices: no-data
cancel, queued-notice cancel, fragmented completion, partial EOF and input
already ready before initial poll. Thus160 local histories execute in each
profile. The worker and owner genuinely run as separate POSIX threads; these
finite schedules do not prove arbitrary interleavings. TSan instrumentation
checks only executed accesses. The compiled controls equate cancellation intent
with quiescence or lose a queued borrow after joining; both fail a named
reference invariant rather than relying on an accidental memory fault.

This port cancels readiness work, not an arbitrary blocked syscall or io_uring
request. Owner operations remain serialized. The current COAsync disarm still
returns synchronously after the outer asynchronous request has been acknowledged
by join; changing that interface to return a future acknowledgement requires
another explicit operation-state reference and is not silently equivalent.
Unexpected join errors are fail-stop in the void-disarm teaching API. A richer
recoverable backend needs a fallible quiescence interface and must retain the
operation on failure. Independent learners must derive that changed contract.

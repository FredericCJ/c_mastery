# Private T31 connection and optimized-state analysis

Read the public exact contract and the original six criterion records. The core
is a typed fixed-state protocol, not a hardware detector: caller-owned evidence
handles are checked for consistent knownness, and phases certify only admitted
observations. The author implementation does not infer a Flash algorithm from a
Cortex identifier. Removing the target equality, separate Flash gate or identity
revocation is each independently rejected. Reconfiguration compares fields, not
padding with memcmp. Wrong-shape input and false observation preserve state.

The numeric vector test has a representable exclusive end and checks extent
membership before subtraction; at least two bytes remain after clearing Thumb
bit0. No pointer is constructed or dereferenced. A syntactically valid entry
cannot prove a live stack, correct vector placement or electrical power.

For T31.01.b accept the reset-loop changed condition as its original requested
experiment plan, not a claimed physical experiment. Verify exact SRST/debug
gating, driver support, reset timing and abort prerequisites against the source.
Unknown wiring is a reason the plan cannot yet execute, not a default setting.
The manifest's real software commands and hashes cannot fill physical unknowns.
For .01.c the UNIX relay is an actual remote-protocol transport with synthetic
delay, not a remote physical probe. Require that distinction in every conclusion.

For T31.02.a the checksum fixture is 3*(1+2+3+4)=30 and after replacement
3*(1+7+3+4)=45. Mutant1 omits the last term, mutant2 uses factor4. Both remain
defined; their wrong outputs are meaningful counterexamples, while a target
timeout or compile failure is not. The actual repaired default must pass again
under the same four target configurations. The unsolved learner stub stays in
the public package and is rejected for the wrong observed value.

For .02.b same-value writes are absent from value-change semantics. The access
stop must have counter7 and be at the actual store boundary, distinct from the
next checkpoint; the change-watch run reaches that checkpoint without a second
change stop. Read actual PC/disassembly before naming the corrupting instruction.
The two-region/four-byte limits are intentionally configured GDB policy because
QEMU's emulated target is not a finite physical debug-comparator implementation.
Do not award a silicon-capacity claim from those error messages. Refusal is not
evidence that software fallback occurred.

For .02.c a volatile read used only for a dead local remains an observable read,
but retaining that side effect does not require a recoverable local value. O0
and O3 can produce different debug locations without different abstract checksum
semantics. In the selected GCC O3 build dc_tail branches to dc_leaf; LR retains
the return into reset code. GDB may synthesize the absent tail frame from DWARF.
Actual LTO may instead emit a call/return sequence while inlining the checksum;
the assessment must follow the retained machine code rather than demand a canned
optimization. `info locals` at function entry can precede initialization even in
O0; a displayed stack word is not a valid argument for the local's source value.

The independent Python transition model exhausts only four actions over eight
selected operations, 4096 histories. Six compiler/instrumentation profiles and
four target profiles add falsification power but prove neither all executions
nor learner competence. Per-objective and changed-condition support is recorded
without upgrading external review, physical results or delayed learner evidence.

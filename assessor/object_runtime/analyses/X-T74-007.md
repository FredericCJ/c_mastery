# X-T74-007: assessor analysis

A conservative card may remain dirty longer than necessary without losing objects. Premature clearing creates a false negative that ordinary C memory sanitizers cannot detect until much later, if at all. The serialized scan is a deliberate contract; racing writers need a new protocol. Delayed case: a store dirties a card between scan and clear, so the collector overwrites the only record of the new reference; require a concrete interleaving and repair.

## Actual nursery adapter and concurrent clear solution

The preflight adapter calls actual ORCards store/scan operations and compares surviving payload/edge/root graphs with the independently coded full-old-scan or_minor. Dirty completeness follows initialization plus every mirrored store. Mirror comparison alone does not establish it: equal field bytes with a missing dirty bit still lose an old-to-young root. Card reconstruction after relocation keeps future scans consistent, but its validation/rewrite traffic must remain in measured total cost.

The concurrent extension takes a private card snapshot under a mutex, scans those copied fields outside exclusion, then validates the same card revision under the writer's mutex before publishing roots or clearing. Revisions increment for every store and refuse to wrap. In the decisive schedule the snapshot contains only nulls, a joined worker installs young7 in the same card, and commit of the old snapshot returns STATE unchanged. Ignoring revision would clear a now-nonempty card; missing marking would incorrectly report DONE. Both errors are witnessed without dereferencing reclaimed native memory. The worker is joined before assertions and teardown, so a negative result is not an unrelated thread-lifetime failure.

One card has2*width fields. Width1/2/4/8 changes false-positive scan work; packed versus64-byte-aligned metadata changes the actual addresses touched. The reserved union size remains the padded size in both layouts, so the comparison cannot claim a control-storage saving. Software address-line counts use an explicit64-byte model; they are not measured hardware misses or coherence transfers. Global mutex and snapshot overhead remain included in elapsed time. Any unavailable hardware event is recorded separately, and no host security setting is modified.

Per-card successful revision validation is a linearizable local result, not a consistent snapshot of all cards/roots/young mutations for a global concurrent copying collector. An assessor should reject that stronger claim even if every local test passes. A different epoch/double-buffer answer must show who owns writes during exchange, when the previous buffer is quiescent, and how revision exhaustion/close preserve pending observations. The delayed learner variant changes width and placement and requires new work and lifetime arguments; the author reference does not establish independent performance.

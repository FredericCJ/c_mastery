# Required weak hash-intern follow-through analysis

The bucket encoding identifies the handle generation, not the physical cell.
Lookup probes collisions and compares all bytes; strings `{0,97}` and `{97,0}`
collide under the defined low-bit hash yet remain distinct. A hit increases the
existing root count without consulting the allocator. A resize privately builds
the new probing array; pool admission follows, so a full independent pool must
release that private allocation. The omitted-release mutant is detected through
the actual T66 allocator's live-row accounting, not a simulated failure flag.

Table entries are weak. Only external roots, foreign pins or reachability
through actual strong handle edges retain a symbol. Collection increments an
epoch; before rebuilding stale chains, lookup rejects rather than following a
retired identity. Sweep copies at most eight surviving handles to a typed local
array, clears buckets and reinserts in the same allocation. This handles holes
in probing without an incorrect early stop. A retained symbol follows its
identity entry through packing; dead/reinterned content gets a new generation.

R2 needs both the existing linear table and the genuinely allocated hash table.
R3's independent Python dictionary tracks each of2,500 input/failure scenarios,
including when an attempted growth fails and later succeeds. R4 additionally
requires collection/sweep ordering, retained-symbol movement, rehash rollback and
the inability to reuse a retired generation. Epoch exhaustion is a deliberate
finite-resource failure, not an excuse to reset while external identities live.
One successful table run cannot establish bounds for arbitrary hash adversaries.

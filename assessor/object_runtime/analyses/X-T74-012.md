# Assessor: X-T74-012 weak interning and moving identity

This is a later integration of T74.02, after the actual T74.08 pool and T66 typed allocator. Original X002 still teaches the linear model. Assess each metadata criterion explicitly; neither its test count nor this worked implementation is learner acceptance.

## R1: identity and ownership

Bucket encodings name generation and logical slot, not cell position. A live caller handle has a separately counted external root. A table hit performs retain; the table itself adds no roots. Thus collecting after the final caller release must make the bucket stale, even if its bytes remain in allocated bucket storage. Reinterning equal bytes after sweep gets the allocator's next generation. A copied integer neither extends lifetime nor revives old authority.

## R2: publication boundary

The reference implementation folds counted bytes, probes at most capacity slots and compares full payload length/bytes. It derives prospective capacity before modifying the table. Replacement storage is an actual V4Allocator int32 allocation. Rehash writes only this private array. Pool admission happens next; if it fails, release the private allocation, preserve old table and output, and leave allocator diagnostic attempts as the only permitted changed observations. A successful pool allocation is followed only by infallible bucket insertion/publication and old-array release. The peak is two arrays during growth. Hit-with-pending-failure must never consume an allocation attempt.

## R3: independent falsification

The Python dictionary model has no C hash implementation and compares10000 observations from625 four-key sequences and four actual failure schedules. The collision pair {0,97}/{97,0} maps to the same hash but not the same key. The first mutant conflates equal-length keys; the second omits release of private rehash storage when later pool admission fails. Demand the semantic assertion, positive control and actual allocator live count, not merely a process failure. Also inspect unchanged output and heap/table state on allocation and capacity failures. The bounded dictionary model does not exercise arbitrary memory corruption or every possible table history.

## R4: transfer and delayed assessment

A moving collection updates physical positions behind stable entries. Retain a non-first symbol, drop unrelated roots, collect, pack and sweep. The surviving table handle must still name the original bytes. Force reserve/growth allocation failure and verify that retained identity remains accessible and no private array is live. Sweep rebuilding is necessary: simply clearing a dead slot in a collision chain can make a later live key unreachable. If the changed assessment adds a foreign pin, prove the pinned cell cannot move or even be rewritten until backend join; weak-table sweep still uses handle identity.

Use allocator observations and object_runtime_storage_probe for measured scope, while deriving worst-case bounded probes and transient storage independently. Do not award an equivalent-contract speedup from comparing strong linear retention against weak retention. A sealed choice must disclose the changed lifetime semantics. External delayed learner assessment remains unperformed.

## Failure of overstated equivalence

Language-level managed strings may provide automatic reachability and thread-safe interning. This C table provides neither without the stated roots, serialized controller and callback contract. ISO C permits typed operations here but does not enforce ownership. A valid generation is cooperative state validation, not an unforgeable security capability.

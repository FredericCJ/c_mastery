## Worklist and active-allocation solution

The implementation under object_runtime_marking.c reuses ORGraph begin/root/store operations, adding a unique gray stack. The proof is by transition: initial roots are gray; shade enqueues only a white object; popping a gray object before shading children cannot admit a duplicate of itself; every outgoing target is gray/black when the source becomes black. Allocation either makes the new object black after shading its children, queues it gray, or restarts from every root. The 16-entry stack cannot overflow because each admitted slot is live and gray exactly once. Mutation adds work but never exceeds the number of live slots. The original color-array scanner and the explicit stack have different search costs; staging a full ORCHeap also incurs O(capacity) copies per allocating or scanning operation, so do not credit an unconditional O(V+E) machine-cost claim merely because edge scans are linear without restarts.

For A rooted, B white/unrooted and N allocated during the cycle with N-to-B, the exact total scans are 2/3/4 for black/gray/restart. A and N are external roots; B is reachable through N. The black mutant leaves a black-to-white edge and the gray mutant never schedules N's children. Root deletion leaves already black nodes floating, so reclaiming them immediately would require a different proof. Starting the next cycle with no roots reclaims all three. Generations retire after 3 uses and never wrap to a former identity.

## Concurrent termination and delayed solution

The actual pthread wrapper protects every graph, root, color, work and revision access with the same mutex. An empty stack keeps active true. Prepare copies white B and revision r, then unlocks. The worker installs A-to-B or retains B and increments revision while executing the relevant barrier. After join, commit(r) must return STATE unchanged. Finish current gray work, prepare a new candidate and commit: B survives. The two schedules distinguish missing candidate validation from missing root shading. Merely checking queue emptiness without revision fails when a new rooted black allocation or another mutation changes the candidate even if no gray work remains.

Mutex lock/unlock provide the publication boundary; ISO C alone does not make unsynchronized shared struct access valid. At a successful commit's locked validation point, no gray work exists, every external root is nonwhite and no black edge reaches white. Therefore no path from a root reaches a white object. Sweep is safe within that invariant and the cooperative token contract. A thread that retains a stale borrowed handle after its protector has vanished may get INVALID; the API does not make arbitrary borrowed identities live. The collector is concurrent at call boundaries but has serialized critical sections. It is not lock-free, fair, parallel tracing or a moving collector.

After revision65535, no mutation may wrap the sequence. Ordinary root releases also refuse. The only remaining destruction route for a nonempty instance is whole-pool retirement after all worker joins, all clients gone and every token/handle discarded. The test explicitly drives that bound, checks a failed release leaves response unchanged, closes under the lifetime precondition, then rejects an attempted post-close call. Address reuse cannot preserve old tokens. A proposal that drops the join requirement or resets revision in place fails the lifetime criterion.

For the delayed assessment, disclose only the graph and interval in which the worker runs. Require the learner to identify a publication point, define retry behavior and reconstruct a safe finish protocol. An alternate stop-the-world handshake may pass if every participant and root is accounted for. Adding volatile, checking an unlocked root bitmap or retaining only the work count fails. An independent learner attempt and external review remain unperformed; the available source and schedules are author support.

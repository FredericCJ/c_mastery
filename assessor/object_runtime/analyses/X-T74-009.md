# X-T74-009: assessor analysis

The ordinary closure and temporary finalizer retention are distinct sets. The kernel clears weak references before retaining objects for finalization, then marks the dequeued identity finalized before user code can resurrect it. This chosen one-time policy differs from Lua re-marking semantics and must not be advertised as equivalent. Delayed case: finalizer A resurrects B after B’s weak reference has been cleared; derive the exact legal observations from the declared phase order.

## Callback and value-graph solution

The driver commits the finalized bit before invocation. A returned callback error is not rollback: a new root or resurrection remains observable. Every still-open resource is enqueued for deterministic cleanup even on failure; collections are refused while cleanup remains. An explicit whole-owner close releases resources even if no callback ever ran. Test self resurrection and A resurrecting already queued B: B's weak reference stays cleared, its queued callback still runs once, and its root protects it at the later collection.

The driver must reject nested collection, drain, cleanup and close while allowing its documented root/edge/allocation/resource operations. Removing this exclusion is falsified without native pointer exploitation: the nested operation returns the wrong status and may retire the active logical identity. The cleanup mutant loses an obligation after a failed callback. Generation 4 retires a slot, so the owner admits at most 48 lifetimes and counters cannot wrap. Full-queue and injected admission failure preserve all state and the output sentinel.

For delayed value graphs, pairs 3=>4 and 1=>2 plus strong edge 2->3 require another conditional pass. Root1 reaches all four. Remove it and add 4->1: the resulting cycle has no external path and all four die. The independent Python set model enumerates 25,600 root/edge/pair combinations. Its fixed point is structural, rather than a copy of the C bitmap implementation.

Lua can re-register an identity for finalization; this model cannot. PEP442 cyclic disposal performs its own isolation recheck after callbacks, whereas this model forbids another collection until pending callbacks and cleanup are drained, then uses a later explicit collection. Neither comparison grants ISO C a memory-safety or deterministic-finalization mechanism. Require each student to defend the callback termination and borrowed-context preconditions.

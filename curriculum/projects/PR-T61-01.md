# PR-T61-01: Bitvector arithmetic and complete bounds

## Contract

Implement vf_add(a,b,out) for uint32_t: return1 and sum when representable, else0 with unchanged output. Write a C Bounded Model Checker harness for every input and a sentinel output, with overflow checks enabled; separately exhaust a reduced8-bit domain and explain why that enumeration is not a proof for32-bit implementation code.

Shared requirements: [B06 exercise contract](../v5/contracts/b06.md). Stable
unit IDs are `LAB-VF-01A` and `LAB-VF-01B`. Families: A, B, C, D, F, G, I, J;
source records: R-B06-CBMC, R-B06-FUZZ, R-B06-ASAN, R-B06-KUNIT in
`research/v5/b06_resources.json`, using only its inspected locators.

Prerequisite knowledge: State a loop invariant and a decreasing variant for a bounded array search. Show a counterexample to the assertion that branch coverage proves correctness and explain signed overflow before enabling a solver.
Prerequisite learner artifacts: the source, contract argument and recorded
assessment of PR-T32-02. Keep these artifacts and
their evidence identities in D1; reading or copying their assessor solution
does not satisfy the prerequisite. Use the already accepted artifact interface
where integration is assigned; do not substitute a library for this mechanism.
Target-specific supplied materials are in `labs/verification_fuzzing/targets/` and remain
subject to the named outstanding evidence requirements.

## Steps

- **T61.01:** A checked operation needs both a successful arithmetic result and a failure contract. Proving only the success branch can hide output corruption on rejection. Solver bitvectors and mathematical integers must be related explicitly.
- **T61.01:** Implement vf_add(a,b,out) for uint32_t: return1 and sum when representable, else0 with unchanged output. Write a C Bounded Model Checker harness for every input and a sentinel output, with overflow checks enabled; separately exhaust a reduced8-bit domain and explain why that enumeration is not a proof for32-bit implementation code.
- **T61.01:** Derive the pre-add inequality without executing overflowing signed arithmetic. Prove unchanged output on failure as a separate postcondition and identify pointer validity assumptions.

## Failure cases

Retain the first divergent transition and distinguish the cause from a symptom.

## Contract

Write component and whole-image contracts for allowed headers, startup, libraries, helper symbols, storage and OS services. Experimentally distinguish freestanding/no-builtin compilation from startup/default-library exclusion and header search restrictions. An intentionally forbidden external call must be detected.

## Inputs and expected results

Load [`fixtures/systems/PR-T11-01.json`](../../fixtures/systems/PR-T11-01.json). Its `input` and `expected` define an exact synthetic case, not an observation from a real compiler, filesystem, board or concurrent run. Run `python tools/verify_systems_fixtures.py` from the curriculum root to recompute all declared fields. Keep input immutable for the reference comparison; store observed outputs separately. The fixture is one anchor, not exhaustive acceptance coverage.

## Steps

1. Write the operation/state/effects contract and predict the fixture result by hand.
2. Establish the smallest supported positive case and record environment/provenance.

- **T11.01:** Write an allowlist for headers, symbols, callbacks, storage and OS services at two boundaries.
- **T11.02:** Build a controlled option matrix and compare unresolved symbols, selected startup inputs and final dependencies.

3. Add boundary and deliberate-failure cases before broadening the implementation.
4. Minimize each disagreement and retain the earliest broken invariant.

## Failure cases

- Challenge the mistaken claim: Omitting stdlib.h removes runtime dependencies. Preserve a minimal failing trace or explain the valid precondition that excludes it.
- Challenge the mistaken claim: -ffreestanding is equivalent to -nostdlib. Preserve a minimal failing trace or explain the valid precondition that excludes it.

Exercise empty/singleton or zero-progress states where the operation admits them, exact capacity, one beyond capacity, repeated completion/cleanup and a deliberately invalid precondition. For storage-owning work, inject acquisition failures and verify unchanged old ownership. For build/binary/source studies, inject a wrong edge, symbol, width, target assumption or unsupported environment and require a visible failure verdict. Never execute malformed pointers or privileged instructions just to demonstrate a negative case. Apply these cases to the declared operation; document any inapplicable case and its reason.

## Hints and recovery

Use one deliberate forbidden external symbol as a negative control. A command-line option is an input to the experiment; the object and final image decide whether the declared dependency boundary was achieved.

Before changing the target, determine whether the disagreement is its semantics, an invalid test precondition, a boundary mismatch or an environment limitation. If the fixture oracle fails, stop and repair the fixture/oracle independently; do not change expected data to fit the target. Return to the named prerequisite module when ownership, width or ordering assumptions are missing.

# PR-T02-01: Declarator and separate-unit interface catalog

## Contract

Create a small matrix-processing interface and callback dispatcher split across two implementation sources and two consumers. Build a declaration catalog that records identifier grouping, type category, scope, namespace, linkage and storage duration. The component must have complete prototypes and callbacks with exact signatures; pointer casts may not serve as signature adapters.

The declared profile **A** applies to the boundary named here; specify harness versus component dependencies in {ref}`guide-profiles`. Budget 8 h for implementation and verification together. Start from your own sources and the listed fixtures, with prior modules as prerequisites; no starter repository or solved program is required.

## Inputs and expected results

The synthetic fixture is an object declaration manifest: internal state, external state, block-local temporary and static-duration local cache. Expected categories follow explicitly declared properties. Functions have a separate call/linkage analysis and are not assigned object storage duration. Actual compiler symbol output is collected separately because optimization can remove unused symbols.

The canonical fixture is `fixtures/language/PR-T02-01.json`. Preserve its supplied fields and add independent cases in your dossier. Run `python tools/verify_language_fixtures.py` from the curriculum root to verify the fixture oracle; then test your C component separately.

## Steps

Start with pointer-to-row and function-pointer declarations. Compile the public header alone, create two consumers, and inspect each object. Add tag/member/ordinary-name examples and prototype-scope names. Introduce one inconsistent declaration, capture the diagnostic or link limitation, then replace it with a compatible contract.

- **T02.01:** Make a catalog of pointer-to-array, array-of-pointers and function-pointer declarations; annotate declarations versus definitions and rewrite one nested declaration using two typedefs. Retain expression-based explanations, compilable examples and intermediate typedefs that preserve the original type. For its three original objectives, record separate evidence references: T02.01.a (Parse pointer, array, and function declarators systematically.); T02.01.b (Distinguish declarations, definitions, typedef names, and type specifiers.); T02.01.c (Rewrite intricate declarations using readable intermediate typedefs.).

- **T02.02:** Build a matrix of complete/incomplete, object/function, scalar/aggregate examples and compare two declarations of the same external function. Retain a compatibility table and a wrapper-struct experiment that demonstrates stronger semantic separation. For its three original objectives, record separate evidence references: T02.02.a (Distinguish object, function, incomplete, scalar, and aggregate types.); T02.02.b (Identify compatible types across separate declarations.); T02.02.c (Explain the limits of typedef-based semantic type separation.).

- **T02.03:** Trace an identifier through nested blocks, a prototype, a structure tag/member and a label; repair a collision by naming the role. Retain an annotated scope map and negative examples for actual collisions, distinguished from legal but confusing shadowing. For its three original objectives, record separate evidence references: T02.03.a (Trace block, file, function, and prototype scopes.); T02.03.b (Distinguish tag, label, member, and ordinary identifier namespaces.); T02.03.c (Diagnose shadowing and accidental name collisions.).

- **T02.04:** Inspect symbols from two objects and deliberately mismatch a public declaration; record extern, static, register and thread-storage examples under their selected edition. Retain a declaration/linkage/storage-duration table, symbol evidence and a repaired cross-unit mismatch. For its three original objectives, record separate evidence references: T02.04.a (Compare internal linkage, external linkage, and no linkage.); T02.04.b (Analyze extern, static, register, and thread-storage declarations by edition.); T02.04.c (Diagnose inconsistent declarations across translation units.).

- **T02.05:** Pass a row pointer to a matrix function and a context-bearing callback to a dispatcher; state signatures before writing bodies. Retain header compilation, compatible callback calls and a rejected cast-based adaptation with a real wrapper alternative. For its three original objectives, record separate evidence references: T02.05.a (Specify parameter and return types with complete prototypes.); T02.05.b (Compare array-parameter adjustment with actual array objects.); T02.05.c (Audit callback signatures, function-pointer conversions, and call compatibility.).

## Failure cases

Reject a null callback according to the public policy. Do not assume the linker diagnoses every type mismatch. Do not index a matrix through int ** when the representation is an array of rows. Keep deliberate erroneous sources separate from the valid build.

## Acceptance and evidence

Supply the catalog, a namespace/scope map, a symbol comparison and a caller test for each public function. Explain why typedef aliases do not enforce units and show one wrapper-struct alternative. Each of the five linked subtopics needs its own evidence entry.

Record contract, build/dependency evidence, independent cases, minimized failures and the specific evidence file for every linked objective. A passing synthetic oracle does not establish a passing implementation. Use {ref}`guide-assessment` for the review gate.

## Hints and recovery

Translate each declarator into an expression involving its identifier; introduce typedefs only after that explanation. Use a wrapper function when adapting behavior rather than changing a function pointer’s type.

If stuck, separate the violated contract from the observed symptom and reduce the input before changing the implementation. Revisit the linked teaching section and retain the minimized case after repair.

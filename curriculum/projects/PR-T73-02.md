# PR-T73-02: Bounded CSP channels, rendezvous and atomic select

## Contract

Implement the two-channel MsgHub exactly as CONTRACTS specifies: capacity0..4, copied unsigned values, FIFO buffers, zero-capacity blocking rendezvous, per-offer acknowledgment, close/drain and terminal hub cancellation. Selection uses one shared mutex/condition boundary, a bit mask and alternating ready preference. Outputs remain unchanged on failure. Build a coro.frame adapter whose notification generation and synchronous disarm preserve frame lifetime; neither timeout nor cancellation alone releases it.

The full required exercise {ref}`X-T73-002`, its shared contracts and objective rubric are part of this project. Eight hours is descriptive author accounting, not a learner-time or scope ceiling.

## Inputs and expected results

Capacity2: send7,close,send8 gives OK,OK,`CLOSED`; the first receive returns7 and the next `CLOSED`. Two ready channels alternate preference. A capacity0 sender of42 returns OK only after select consumes42. Close before acknowledgment returns `CLOSED` to sender; an acknowledged send remains successful if cancellation arrives before sender resumes.

## Steps

- **T73.02:** Implement buffered/rendezvous operations and select with a single predicate-registration boundary, explicit spurious-wakeup loops, finite tickets and quiescent destruction; retain coroutine frames until generation-specific disarm. Submit the exercise D1–D4 and retain prerequisite interfaces.

## Failure cases

Test full/empty, both ready, one closed, all closed, close with buffered values, cancellation with blocked sender/receiver and accepted-versus-unaccepted rendezvous. Repeatedly inject spurious broadcasts. Capture event histories and verify no lost/duplicated accepted values. Reject send-after-close and skipped-buffer mutants; independently model sequential traces and use TSan for actual threads.

## Acceptance and evidence

- **T73.02:** Derive readiness, linearization, close/drain and cancellation semantics; compare deterministic selection with Go ready-case randomness and distinguish rendezvous acknowledgment from merely enqueuing an offer. Every leaf has a separate rubric criterion in X-T73-002. Public test passage alone does not assess independent understanding.

## Hints and recovery

Checking readiness and registering a waiter cannot leave an unprotected gap. Then A rendezvous offer is not yet a completed send. Record the failed hypothesis before using further hints.

## Transfer challenge

Change unsigned copies to owned buffers with a destructor: define ownership on failed send, close/drain and cancellation. Delayed assessment splits the hub into separately locked channels; derive a registration/recheck protocol that prevents a wakeup lost between observing empty and going to sleep, or justify retaining the common lock.

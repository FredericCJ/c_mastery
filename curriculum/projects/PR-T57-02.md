# PR-T57-02: User-copy progress and ABI admission

## Contract

Implement kl_copy into a live disjoint destination with capacity cap. Reject n>cap with -1 before writes; otherwise copy min(n,fault_after) bytes and return the completed count. The model input is ordinary accessible memory; a separate guest adapter must use copy_from_user and preserve its actual return convention.

## Steps

- **T57.02:** A user copy may stop before transferring the requested span. Its result is a count of bytes not copied in kernel APIs, while a read/write method typically reports completed bytes or an error. Translate between these contracts without treating a user address as a trusted C pointer.
- **T57.02:** Implement kl_copy into a live disjoint destination with capacity cap. Reject n>cap with -1 before writes; otherwise copy min(n,fault_after) bytes and return the completed count. The model input is ordinary accessible memory; a separate guest adapter must use copy_from_user and preserve its actual return convention.
- **T57.02:** State ownership of unread input, modified prefix and untouched suffix. Explain why a partial-copy return cannot be reused as a negative errno and why cap admission precedes copying.

## Failure cases

A faulty wrapper returns the requested count after a partial copy and exposes stale bytes. Demonstrate the stale sentinel in the original local teaching endpoint without touching other processes.

Retain the first divergent transition and distinguish the cause from a symptom.

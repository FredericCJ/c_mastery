# PR-T73-09: Sequence validation without racing ordinary C payloads

## Contract

Implement a one-writer sequence lock over two atomic unsigned payload words. All operations begin sequentially consistent. Writer publishes odd sequence, both payloads, then even sequence; refuse exhaustion before wrap. Reader performs at most its supplied retry budget and publishes outputs only after equal even sequence observations. Analyze the plausible repair “copy ordinary payload then discard if changed” and explain its C data-race defect. Do not execute a racy program as a portable value oracle.

The full required exercise {ref}`X-T73-009`, its shared contracts and objective rubric are part of this project. Eight hours is descriptive author accounting, not a learner-time or scope ceiling.

## Inputs and expected results

With sequence1, three attempts return `BUSY` and outputs stay[99,99]. Writing[7,14] then reading succeeds. Zero attempts is `BUSY`. SequenceUINT_MAX-1 rejects a new write without modification. The threaded anchor writes10000 pairs[i,2*i] and rejects any successfully returned incoherent pair.

## Steps

- **T73.09:** Derive the atomic representation and sequentially consistent ordering argument, implement bounded retry and nonwrapping writer publication, and account for every output and failure effect. Submit the exercise D1–D4 and retain prerequisite interfaces.

## Failure cases

Test odd/even transitions, zero retry, interrupted writer state, output canaries and counter exhaustion. Reject odd-sequence acceptance and omitted-payload-write mutants. Run actual concurrent stress and TSan while explaining that clean runs do not prove weak-order correctness. Inspect disassembly and compare lock-free status and fences with an equivalent mutex snapshot.

## Acceptance and evidence

- **T73.09:** Separate storage race freedom, coherent snapshot validation, writer serialization, retry bounds and counter lifetime; identify what sequential consistency proves and what a later weakened implementation must re-establish. Every leaf has a separate rubric criterion in X-T73-009. Public test passage alone does not assess independent understanding.

## Hints and recovery

Discarding a value does not erase an earlier language-level data race. Then An odd sequence is a state, not merely a changed numeric value. Record the failed hypothesis before using further hints.

## Transfer challenge

Derive a weaker-order version from explicit synchronization/fence reasoning and check it with a C memory-model tool before comparing costs. Delayed assessment uses pointer payloads and a reader that pauses after loading one pointer; add lifetime protection or reject the design, since sequence validation does not retain pointees.

## Contract

Extend the accepted [cache reference worksheet](PR-T37-05.md) with a separate single-disk external-memory certificate. Implement only a tiny bounded two-block LRU/write-back traffic adapter in original C, keeping its results separate from the prior direct-mapped CPU cache. No library cache/container routine may perform the educational policy. The harness may parse JSON and compare output externally.

Use 5 hours implementation and 3 verification. Fixed four-byte items, B=2 items and M=4 items give two eight-byte buffer blocks; D=P=1. This is a declared model with write allocation, dirty eviction and a final dirty flush. It makes no prediction of actual disk service time.

## Inputs and expected results

[The fixture](../../fixtures/performance/PR-T43-05.json) sequentially reads items 0..7: four block reads, 32 bytes transferred/useful and amplification 1. The mixed references read 0, write 1, read 4, write 0, read 2, write 4, read 5 read four blocks and write two: 32+16=48 transferred bytes for 28 useful bytes, amplification 12/7. The dirty block 0 is evicted; dirty block 2 remains for final flush.

For no references, useful and transferred bytes are both zero. Amplification is undefined, represented by null; 0/0 is not zero or one. A cyclic three-block read stream thrashes the two-block buffer: six reads/48 bytes for 24 useful bytes.

## Steps

1. Declare N as the backing sequence length in items, M and B in the same item units. Name the buffer layer and show each block number, resident order and dirty flag.
2. Extend the C adapter with counts of fetched/flushed blocks; verify final-flush handling and exact byte conversion against all original fixture cases.
3. Observe a bounded file read through the existing file adapter, preserving syscall accepted-byte counts and any permitted device-byte evidence. Compare a repeat/warm run without claiming a system cache flush.
4. Explain a discrepancy between useful bytes, userspace requests and device accounting. Buffering, readahead, writeback or a different layer are hypotheses to test, not invisible zero-cost transfers.

## Failure cases

Reject invalid indices, unknown read/write modes and geometry that violates the stated buffer contract. The empty stream must not divide by zero. A dirty hit does not write back immediately in this policy. A bus transaction, disk I/O and CPU cache fill can have different sizes; replacing one with another invalidates the unit label.

## Acceptance and evidence

For .a submit an original hand-traced stream and the N/M/B/D/P model contract. For .b submit all read/write/useful byte totals, ratios and null denominator case. For .c supply actual existing-adapter observations or a clearly labeled denied device-accounting boundary, plus a warm-state explanation and follow-up. The independent Python model checks the bounded policy, not C correctness on every stream or a physical device model.

## Hints and recovery

Use an ordered resident list oldest first; on a hit update recency without incrementing fetch count. Keep dirty identity independent of recency. Count final dirty writes exactly once. If your sequential ratio is below one, inspect whether useful-byte totals are counting repeated bytes while transfer counts refer to an already warm cache.

## Transfer challenge

Increase M to six items and predict the cyclic-stream counts before running. Compare the gain in traffic with additional retained storage; do not infer the same speedup for every device or asynchronous backend.

## Contract

Specify the exact F439-LAN8742 same-link profile before implementing its stack. Board IP is 192.0.2.2/24, fixture MAC 02:00:00:00:00:02, peer 192.0.2.1/24, passive TCP 8080. The actual peer MAC is recorded during the cable lab. There is no default route, DHCP, DNS, bridge to the Internet, VLAN or fragmentation/options support. State explicitly that a cooperative-client exchange is not full RFC/IEEE conformance.

Define frame/datagram/segment/stream boundaries and ownership for receive, submit, tick, link change, DMA completion and TCP ACK. Reuse T39's frame-channel design; the new work is the upper packet/stream handoff and finite stack resource plan. A borrowed receive span expires on callback return; queued data needs private owned storage.

## Inputs and expected results

The fixture gives an application TCP payload length 3, fixed headers 20/20, Ethernet header 14, minimum pre-FCS frame 60 and FCS 4. Expected IP 43, unpadded frame 57, pad 3 and MAC frame 64 exclude preamble/SFD/interpacket gap. It also budgets six 2048-byte DMA buffers and six 16-byte descriptors.

Output interface/result/lifetime table, nested length diagram, static resource inventory and omitted-requirements matrix. The independent fixture derives arithmetic; actual build map and capacity tests validate placement/bounds.

## Steps

1. Draw MAC/PHY/magnetics/cable and Internet layer ownership without forcing seven one-to-one protocol labels.
2. Define immutable packet spans, complete validation before publication and BUSY without consuming caller bytes.
3. Separate TX DMA buffer reuse from retention of unacknowledged TCP bytes. Design a bounded retransmission copy and 512-byte receive storage.
4. Derive padding and nested length trimming independently, including ARP which has no IP wrapper.
5. Prepare isolated host adapter settings and select independent capture/client tools. Attach actual source revision and board identity to the ledger.

## Failure cases

Do not count Ethernet padding as IP/TCP payload, cast an incomplete header, free retransmission bytes at DMA completion, or call an emulator physical evidence. A second simultaneous connection is refused by the one-connection resource contract. Queue-full/BUSY preserves ownership, and protocol omissions remain visible even after successful HTTP.

## Acceptance and evidence

Submit subset/exclusion table, exact boundary lengths and API/resource/ownership ledger. For the objectives demonstrate declared interoperability limits, nested bytes/lifetimes and packet-to-stream semantics. Show at least one rejected borrowed-reference test and a build-map storage plan. No physical claim closes in this design milestone.

## Hints and recovery

Name every length by its starting byte and excluded trailer. If ownership is unclear, compare DMA complete and TCP ACK as two separate events. If an excluded requirement seems optional, consult the actual host/RFC scope before labeling it that way.

## Transfer challenge

Increase HTTP response length beyond MSS 256 and predict segmentation, retained output and padding per packet while preserving the exact response byte stream.

For this milestone, retain three separately labeled evidence items:

- **T41.01.a:** Declare the controlled same-link interoperability profile and excluded full-host requirements.
- **T41.01.b:** Trace nested Ethernet/ARP or Ethernet/IPv4/TCP/HTTP lengths and buffer ownership.
- **T41.01.c:** Define byte-span APIs that preserve packet boundaries below TCP and byte-stream continuity above it.

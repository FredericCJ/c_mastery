# PR-T47-04: Insertion, splits and root growth

## Contract

Implement insert-or-replace, leaf splitting, internal propagation and new-root allocation. Retain an adversarial ascending insertion trace that builds multiple internal levels. Check the entire allocation/reachability/occupancy invariant after every insert and compare actual values with an independent map. Treat duplicate keys as value replacement, not duplicate records.

Budget 6 implementation and 4 verification hours. Reuse the same engine throughout; previous milestones are not charged again. The public API and original disk format are in the storage laboratory.

## Inputs and expected results

Use [the contract fixture](../../fixtures/storage/PR-T47-04.json) and the actual C tests `storage.insertion`. The image has 67 pages of 4096 bytes; the tree owns 32 logical data pages. The reference transaction changes the complete map from {1:10,2:20} to {1:11,3:30}. Compare whole maps. No fixture asserts physical power-cut durability.

## Failure cases

An unavailable compiler, sanitizer runtime, syscall or device produces unavailable evidence; it never counts as a clean run. A wrong implementation must fail a semantic assertion after successful setup.

## Hints and recovery

Insertion maintains sorted keys within a leaf and increases height only when a root splits. With maximum seven keys, the eighth exists only in private split scratch. A leaf split yields four records on each side and copies the right minimum upward; an internal split promotes a separator and partitions child intervals. These are different operations. Reserve or recover capacity for propagation: a failed allocation cannot leave a half-published tree. This first implementation aborts the entire transaction on page exhaustion and refreshes separator minima over allocated nodes, explicitly adding O(P) work.

The staged laboratory hints separate invariant, observation and repair direction. Keep the original failing image or key sequence and compare it with a clean control.

## Contract

Implement linear search, lower/upper bounds, partition, insertion sort, stable merge sort and heap sort under explicit caller-workspace contracts. Reuse the binary-heap build/sift-down kernel already accepted in PR-T14-05; this milestone adds the shrinking active-region/sorted-suffix policy and its evidence rather than another heap implementation. No bsearch/qsort or external sorting/searching routines may perform the target operations. Labeled equal keys test stability; counters support, but do not replace, loop and complexity arguments.

The reusable target is Profile C: implement each studied algorithm/container/allocator/byte operation locally. A hosted test oracle may call mature libraries, but the target may not delegate its mechanism to qsort, bsearch, malloc/realloc/free, strto*, printf-style conversion, external memory primitives or equivalent library substitutes. Allocator callbacks/backing storage and compiler helpers must be explicitly scoped and audited.

Worked stable merge: sorted left [1A,3A] and right [1B,2B] have labeled equal keys. Taking the left element on equality produces [1A,1B,2B,3A], preserving the earlier 1A; taking the right equal key would violate stability. A four-element caller workspace receives one element per transition, and the two input cursors never pass their lengths. For heap sort, reuse PR-T14-05 build/sift-down: max-heap [4,3,2,1] has active length 4. Swap root with the final active element to obtain [1,3,2 | 4], shrink to 3, then sift to [3,1,2 | 4]. Next extraction gives [2,1 | 3,4]; the active root already dominates its child. The last exchange gives [1 | 2,3,4]. Each step preserves the active max-heap and increasing final suffix; heap sort has no stable-tie promise.

# PR-T74-03: Immutable hidden classes and reusable property transitions

## Contract

Implement immutable four-field shapes in a16-shape arena, transition reuse by parent-plus-key and atomic capacity failure. Add a dictionary-mode alternative for deletion and compare its explicit lookup/invalidation contract. The full required specification is {ref}`X-T74-003` and its explicit shared contract. Twelve hours is descriptive author accounting, never a ceiling.

## Inputs and expected results

Objects built with keys1 then2 share shape; keys2 then1 have different offsets and a different shape. Updating an existing key changes only its value; adding a fifth distinct key returns FULL unchanged.

## Steps

- **T74.03:** Complete D1–D4, the named public anchor, independent falsification and changed-contract implementation.

## Failure cases

Construct same-order and permuted-order receivers, update existing properties at full capacity, exhaust transition storage and test rollback. Reject parent-omission and omitted-receiver-transition mutants; independently compare every lookup with a property dictionary.

## Acceptance and evidence

- **T74.03:** Satisfy all four leaf rubrics and source-bound verification; passing supplied tests alone is insufficient.

## Hints and recovery

A transition is keyed by its starting layout as well as the added name. Do not modify a shape shared by other receivers. Equal key sets can have different offsets.

## Transfer challenge

Add property deletion, attributes and a prototype chain. Derive which operations preserve shape identity and which invalidate caches. Delayed assessment permits shape ID reuse and requires a generation or epoch policy that rejects stale references to shape records.

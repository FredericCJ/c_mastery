# PR-T59-01: Flash programming as a constrained state change

## Contract

Implement lc_program(dst,src,n) on live disjoint octet spans: reject if any new byte requests a0-to-1 transition, leaving all bytes unchanged; otherwise program with bitwise AND. n0 succeeds. This is an atomic admission model, not a claim that physical multi-byte programming is atomic.

Shared requirements: [B06 exercise contract](../v5/contracts/b06.md). Stable
unit IDs are `LAB-LC-01A` and `LAB-LC-01B`. Families: A, B, C, D, F, G, I, J;
source records: R-B06-BOOT, R-B06-STBOOT, R-B06-STIPC in
`research/v5/b06_resources.json`, using only its inspected locators.

Prerequisite knowledge: Explain flash erase/program asymmetry and reconstruct a recoverable page-store commit. Distinguish reset, power loss, brownout and interrupted CPU execution before proposing an update protocol.

Target-specific supplied materials are in `labs/firmware_lifecycle/targets/` and remain
subject to the named outstanding evidence requirements.

## Steps

## Failure cases

Repair a model that silently ANDs an illegal request and reports success. Its resulting bytes differ from the requested image even without a reset or power interruption.

Retain the first divergent transition and distinguish the cause from a symptom.
The named mutation control must fail for its intended reason; compilation
failure is not a successful mutation kill.

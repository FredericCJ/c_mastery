# PR-T72-03: Allocated coroutine frames and generator ownership

## Contract

Implement allocator-backed Fibonacci generators with one owned frame, stable `DONE`, cancellation through destroy and exactly-once release, plus a caller-provided-frame alternative under an equal value contract. The full required specification is {ref}`X-T72-003` and its explicit shared contract. Twelve hours is descriptive author accounting, never a ceiling.

## Inputs and expected results

count3 emits0,1,1 then stable `DONE`. count47 ends at1836311903. Allocation failure leaves the caller output unchanged and performs no release.

## Steps

- **T72.03:** Complete D1–D4, the named public anchor, independent falsification and changed-contract implementation.

## Failure cases

Inject allocation failure, count0/1/47, suspension then destroy, repeated destroy through the cleared owner and interleaved generators. Compare every value with an independent integer recurrence and record allocation counts; reject extra-yield and omitted-release mutants.

## Acceptance and evidence

- **T72.03:** Satisfy all four leaf rubrics and source-bound verification; passing supplied tests alone is insufficient.

## Hints and recovery

List state that survives next returning. Destroy the frame through the sole owning pointer. C++ allocation elision is conditional; the C frame location is an explicit design choice.

## Transfer challenge

Make yielded values own heap buffers and retain one across suspension. Define borrow/transfer/clone explicitly and compare cleanup after partial construction; delayed assessment introduces an address-sensitive self-reference that forbids moving the frame.

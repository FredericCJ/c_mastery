# PR-T76-04: Join-semilattice counters and deterministic registers

## Contract

Implement RPPN with3 positive and3 negative uint32 components, checked local increments and int64 query sum(P)-sum(N). Merge by componentwise maximum, allowing self-merge. Implement RPRegister merge by lexicographic(timestamp,replica0..2); identical identity with different payload is RP_CONFLICT. A canonical initial register is(0,0,0), and generated writes use positive timestamps. Inputs must derive from one writer per replica identity; public fields are not Byzantine proofs.

The full required exercise {ref}`X-T76-004`, its shared contracts and objective rubric are part of this project. Eight hours is descriptive author accounting, not a learner-time or scope ceiling.

## Inputs and expected results

Replica0 adds5; replica1 subtracts3. Merge yields2 and repeating the same merge remains2. Register(7,0,1) joined with(7,2,9) chooses9; another payload at(7,2) is a conflict. Adding UINT32_MAX to component5 fails unchanged.

## Steps

- **T76.04:** Prove idempotence, commutativity and associativity on admitted compatible states, plus inflation of each grow-only component. Explain why sum of received states double-counts retransmission, why finite overflow must reject, and why a reused writer identity with forked state violates the ownership model. For registers identify conflict cases outside the unique-event assumption and the total-order tie rule. Submit the exercise D1–D4 and retain prerequisite interfaces.

## Failure cases

Run replicated.counters; enumerate small component states and three-way merge permutations, including duplicate, reordered and dropped-then-retransmitted messages. Kill additive-state-merge and missing replica tie-break mutants. Show a counterexample for unchecked uint32 wrap and for independent writers sharing one replica slot.

## Acceptance and evidence

- **T76.04:** Derive convergence from explicit componentwise joins and globally unique writer identities, and distinguish state merge from replaying operations. A last-writer register resolves an order chosen by the protocol, not necessarily real-time recency. Every leaf has a separate rubric criterion in X-T76-004. Public test passage alone does not assess independent understanding.

## Hints and recovery

Write the partial order before the merge routine. Then Try receiving exactly the same state twice. Record the failed hypothesis before using further hints.

## Transfer challenge

Add membership replacement, serialized snapshots and state corruption detection. Distinguish fail-stop tolerance, where a replica stops sending, from Byzantine tolerance, where it may send arbitrary state: demonstrate a synthetic forged high component monopolizing the merge and specify an authenticated admission/identity policy without claiming signatures solve semantic authorization. Compare state size with operation-log retention under the same delivery assumptions.

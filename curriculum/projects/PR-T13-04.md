## Contract

Audit the same qsort API in inspected glibc 2.41 stdlib/qsort.c and musl 1.2.5 src/stdlib/qsort.c. Map allocation, temporary storage, callback and transitive-helper boundaries; distinguish glibc stack/heap selection and allocation-failure heapsort from musl smoothsort. Do not infer stable tie ordering or a complete effect bound from the API name. Locally implement a replacement restricted to at most sixteen int elements using insertion sort and caller-owned actual int storage, with visible over-capacity rejection preserving input. No qsort, external sorting or byte-library call performs the replacement. A separately hosted qsort run and mathematical sorted-multiset oracle check ordering only; comparator effects, stack, latency, size and maintenance have separately scoped evidence. Compare the two library source paths without claiming their uninspected transitive helpers are effect-free.

Worked source branch: the inspected glibc 2.41 source reserves a 1024-byte temporary stack buffer. Sorting 64 four-byte elements needs 256 temporary bytes and selects it; 300 four-byte elements need 1200 and reach the acquisition branch, which falls back to heapsort if acquisition fails. For ten 64-byte elements and eight-byte pointers, indirect storage is 2*10*8+64=224 bytes. These are source-selected temporary requirements, not total-stack bounds; helper and comparator frames/effects remain separate. The restricted local replacement accepts at most sixteen ints, so its workload and API exclusions are explicit.

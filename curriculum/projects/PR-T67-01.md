# PR-T67-01: Products, tagged sums and checked elimination

## Contract

Implement ad_measure and ad_number over ADValue: `EMPTY` maps to0, `NUMBER` to its uint32 payload, `PAIR` to the exact uint64 sum. Invalid enum values fail; ad_number accepts only `NUMBER`. Every failure preserves the output. No union payload may be read before validating the tag. Supply constructor/accessor conventions and a deliberately incomplete switch translation unit.

The full required exercise {ref}`X-T67-001`, its shared contracts and objective rubric are part of this project. Eight hours is descriptive author accounting, not a learner-time or scope ceiling.

## Inputs and expected results

`PAIR`(UINT32_MAX,5) measures4294967300; `NUMBER`(0) is distinct from `EMPTY` despite equal measurement. Invalid tag99 leaves prior result unchanged. A `PAIR` requested as `NUMBER` leaves its output sentinel untouched.

## Steps

- **T67.01:** Draw all admitted tag/payload states, establish uint64 sufficiency for two uint32 values, and explain which inactive-member operations are avoided. Derive a counterexample to the claim that adding a default branch makes future variants exhaustively handled. Compare Rust enum constructors and binding behavior with C aggregate initialization and private-header discipline. Submit the exercise D1–D4 and retain prerequisite interfaces.

## Failure cases

Run adt.sums and compile the missing-enumerator probe with -Wswitch-enum -Werror. Both semantic mutants must fail: omitted second product member and silently accepted invalid tag. Add every variant and invalid boundary, inspect enum size without assuming it is the wire tag size, and compare debug/release generated branches.

## Acceptance and evidence

- **T67.01:** Derive product versus sum cardinality and distinguish a C union representation from an automatically checked discriminated union; show why -Wswitch-enum is a diagnostic policy, not an ISO C exhaustiveness theorem. Every leaf has a separate rubric criterion in X-T67-001. Public test passage alone does not assess independent understanding.

## Hints and recovery

List the admissible states before writing a switch. Then Promote before addition, not after it. Record the failed hypothesis before using further hints.

## Transfer challenge

Add an owning text variant with a failing clone callback. Derive copy/drop/rollback and exhaustiveness obligations for every old eliminator; demonstrate which clients fail compilation and which silently preserve a default path.

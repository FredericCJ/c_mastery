# PR-T58-06: Trap status versus call state

## Contract

Implement po_trap(status,from_supervisor) and po_return(status): trap records spp, copies sie to spie and clears sie; return restores sie from spie, sets spie1 and clears spp. Inputs are boolean fields; invalid input rejects without mutation. Compare the explicit model to supervisor CSR traces in a dedicated RISC-V guest.

Shared requirements: [B06 exercise contract](../v5/contracts/b06.md). Stable

source records: R-B06-RVPRIV in
`research/v5/b06_resources.json`, using only its inspected locators.

## Steps

- **T58.06:** Supervisor trap entry saves prior interrupt enable and disables interrupts; trap return restores it. C function-call preservation does not capture these privilege transitions. Nesting without saving the prior trap frame overwrites the interrupted state.
- **T58.06:** Implement po_trap(status,from_supervisor) and po_return(status): trap records spp, copies sie to spie and clears sie; return restores sie from spie, sets spie1 and clears spp. Inputs are boolean fields; invalid input rejects without mutation. Compare the explicit model to supervisor CSR traces in a dedicated RISC-V guest.
- **T58.06:** Draw status before entry, after entry and after return. Explain which processor state is automatic, which is software saved and why a call-return instruction cannot replace a trap return.

## Failure cases

Repair stale prior-privilege state after return and a nested handler that overwrites the first saved PC. The model cannot establish interrupt controller acknowledgement behavior.

Retain the first divergent transition and distinguish the cause from a symptom.
The named mutation control must fail for its intended reason; compilation
failure is not a successful mutation kill.

# PR-T48-07: Static ELF64 and a read-only boot archive

## Contract

The loader consumes program headers, not section names. File bytes are copied into a checked virtual span and the remaining memory bytes start at zero. CMKA1 maps bounded unique names to non-overlapping image spans; it is a boot container, not a general filesystem.

This 12-hour milestone includes implementation and verification. Reading, assessment and delayed retrieval are in the module budget. Reuse accepted prerequisites; implement the studied mechanism in the learner workspace.

## Inputs and expected results

Use `fixtures/kernel/PR-T48-07.json` for the declared finite calculation and `labs/kernel` for actual C/guest controls. Static arithmetic does not close the executable gate. The relevant CTest names are `kernel_elf`, `kernel_archive`. Cross-family projects explicitly enable the original runtime/store source paths; a standalone kernel pass is insufficient.

## Steps

Decode ELF64 little-endian x86-64 ET_EXEC images with at most eight load segments, fixed 4096-byte alignment and no interpreter, dynamic linking or TLS. Validate all segments before mapping. Package init, workers, fault control and shell.

Keep the contract, pre-run prediction, exact image/build identity, raw observation and first invalid transition. Reveal hints in `labs/kernel/HINTS.md` in stages. The default stubs compile but fail; selecting an assessor solution changes the evidence category.

## Failure cases

Truncated header or payload, filesz greater than memsz, overlapping page mappings, entry outside executable storage, writable executable segment, duplicate archive names and payload/table overlap.

## Acceptance and evidence

Pass hosted truncation/extent cases and boot real independently linked ELF programs. Preserve zero-fill and rejected-image evidence separately.

- **T48.07.a**: Validate the bounded ELF program-header contract before committing mappings.
- **T48.07.b**: Implement a checked named-span boot archive and zero-filled static image loader.
- **T48.07.c**: Distinguish the educational executable profile from general ELF and filesystem support.

Map each objective to a concrete file/observation, retain negative controls and state unresolved claims. Refer to {ref}`guide-assessment` for rubric and causal repair.

## Hints and recovery

Start with a hosted checked boundary whenever possible, then cross the actual machine boundary. A publication or model verifier is not a substitute for the named boot, privilege, queue or reboot observation. Reduce one failed boundary before editing unrelated mechanisms.

# PR-T69-09: Authority attenuation, revocation and the limits of C tokens

## Contract

Implement the original DSAuthority/DSCapability model over a synthetic int counter. Rights bits1(read) and2(add), owner identity and finite epochs enforce checked API requests. Issue and attenuation must never add rights; add requires both root and capability permission; revoke invalidates old epochs and retires after3. Attack only this cooperative local model by requesting a stronger mask, reusing a revoked capability and crossing owners. Then analyze a C client that directly forges exposed fields: explain why this violates the model and refutes a broader security claim. Design an opaque broker/process boundary that can enforce the stronger threat model.

The full required exercise is {ref}`X-T69-009`; its shared contracts, D1–D4, objective-specific rubric and delayed variant are part of this project. Eight hours is descriptive accounting, not a ceiling on required work.

## Inputs and expected results

A full-rights capability can add5. Its attenuated read-only capability cannot change the counter. Attempting to attenuate read-only rights to full rights rejects with output unchanged. After revocation, the former full capability returns stale and the counter remains5.

## Steps

- **T69.09:** Implement subset admission, owner/epoch validation, bounded revocation and checked effect publication without global ambient authority. Complete every exercise deliverable, including separately specified extensions.

## Failure cases

The attacker perspective reveals whether a token is actually authoritative or simply trusted data. A subset check is meaningful only under a threat model that prevents the caller from changing the checked authority metadata. Enumerate rights0–3 and all subset/non-subset requests. Retain capabilities through each revoke and retirement, comparing the counter and status to an independent set/epoch model. Mutation1 permits amplification; mutation2 accepts a stale epoch. Success is an observable synthetic counter change contrary to the declared policy, not abnormal termination or privilege escalation. Repairs require both rejection and preserved state.

## Hints and recovery

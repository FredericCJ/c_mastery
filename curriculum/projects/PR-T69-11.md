# PR-T69-11: Quiescent hot reload with staged state handoff and retirement

## Contract

Implement DSHost reload/collect with current and one retired DSLoaded owner, integer state and non-wrapping generation0–3. Stage candidate migration from old schema/state, then atomically transfer ownership and publish state only on success. The previous module remains owned in retired until explicit collection. Reject reload while current/candidate borrows exist, retired remains occupied or generation is exhausted. Plugin1 preserves state; plugin2 doubles admitted state0–500. Add a failure-injecting loader backend model for collection failure without passing invalid real loader handles.

The full required exercise is {ref}`X-T69-011`; its shared contracts, D1–D4, objective-specific rubric and delayed variant are part of this project. Eight hours is descriptive accounting, not a ceiling on required work.

## Inputs and expected results

Starting state7, load schema1 then schema2: state becomes14, generation2, candidate becomes empty and the former module is retired. Collect releases retired. With old state600, migration rejects and retains state600, generation2, current and candidate ownership unchanged.

## Steps

- **T69.11:** Implement staged migration, source ownership consumption, finite generations and explicit retired collection, preserving the old service on every precommit failure. Complete every exercise deliverable, including separately specified extensions.

## Failure cases

Hot reload is a lifetime and state-compatibility transaction. Swapping a function pointer is insufficient when old callbacks, data schemas or cleanup failures remain live. Use both actual original DSOs for the admitted synchronous protocol and a deterministic backend model for failure stages that cannot safely be induced through real invalid handles. Inject candidate load/migration/collection failure; enumerate all borrow counts0–4 and finite generations. Record exactly which steps commit and which require recovery. Never unload a running callback as an experiment.

## Hints and recovery

Keep the old service owned until the new state is fully admitted. Cleanup after commit can fail without undoing the published service. Every cache, thread-local object, queued callback and allocator callback is part of quiescence if the design permits it.

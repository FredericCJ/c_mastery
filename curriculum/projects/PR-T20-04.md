# PR-T20-04: Configuration identity and fault decision review

## Contract

Add versioned configuration validation and a fault-supervision policy to the portable architecture. Distinguish recoverable adapter errors, malformed contract results and terminal faults. Record logical containment limits and compare two architecture alternatives against latency, capacity, portability and recovery requirements.

The declared profile **C** applies to the boundary named here; specify harness versus component dependencies in {ref}`guide-profiles`. Budget 8 h for implementation and verification together. ## Inputs and expected results

The fixture adapter outcomes ok, timeout, timeout, ok, fault use a threshold of two consecutive timeouts. Expected modes are normal, normal, degraded, normal and stopped. A successful operation clears the timeout streak; a terminal fault stops. This is a declared supervision policy, not a hardware safety claim.

## Failure cases

Invalid configuration must fail before activation. Malformed adapter results are contract faults, not ordinary timeouts. A shared-address-space module cannot promise memory isolation; state what process or MPU boundary would additionally be required.

## Acceptance and evidence

Submit configuration/reproducibility evidence, fault/degradation traces and two evaluated alternatives. Show a changed assumption causing a reasoned decision revision. Keep recovery claims limited to the tested logical model.

Record contract, build/dependency evidence, independent cases, minimized failures and the specific evidence file for every linked objective. A passing synthetic oracle does not establish a passing implementation. Use {ref}`guide-assessment` for the review gate.

## Hints and recovery

Use a small explicit mode/streak state. Test supervision failures such as logging exhaustion separately from the primary adapter error.

If stuck, separate the violated contract from the observed symptom and reduce the input before changing the implementation. Revisit the linked teaching section and retain the minimized case after repair.

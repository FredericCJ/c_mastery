# PR-T76-06: Replicated sequence identities and contextual transformation

## Contract

Implement RPSequence with16 nodes{id,parent,byte,tombstone}. id is globally unique and positive, parent<id; parent0 is the root and every nonzero parent must already exist. Concurrent siblings render in descending ID order by depth-first traversal; tombstoned parents remain traversable. Duplicate identity with identical parent/value is idempotent; conflicting reuse fails. Missing dependencies return RP_GAP unchanged. Render stages output and fails transactionally if capacity is insufficient. Also implement two-concurrent-insert position transformation with distinct priority tie-breaks; no full network operational transformation control algorithm is supplied.

The full required exercise {ref}`X-T76-006`, its shared contracts and objective rubric are part of this project. Eight hours is descriptive author accounting, not a learner-time or scope ceiling.

## Inputs and expected results

Insert A(id1,parent0),B(id2,parent0),C(id3,parent1) in either admissible arrival order: render BAC. Delete id1: render BC, retaining descendant C. Two inserts at position0 with priorities1 and2 transform the higher-priority-number insertion to position1.

## Steps

- **T76.06:** Derive acyclicity from parent<id and closure from causal admission. Prove insertion-order-independent rendering for a fixed admitted node set, including descendants of deleted anchors. Explain that this original tree contract is RGA-inspired, not a claim to implement every detail of Specification19. For operational transformation derive the two-branch diamond under distinct priorities and identify the state-vector/log context needed beyond it. Submit the exercise D1–D4 and retain prerequisite interfaces.

## Failure cases

Run replicated.sequence; enumerate topological arrival orders and deletion subsets against a recursive tree oracle. Kill arrival-order sibling rendering and deleted-subtree omission mutants. Check full capacity, duplicate identity, missing dependency and output failure atomicity. Enumerate both paths of the two-insert operational transformation diamond, then provide a three-operation context counterexample to an unjustified generalization.

## Acceptance and evidence

- **T76.06:** Separate stable sequence identity from transient visible position, and compare a bounded parent-tree sequence with context-dependent operational transformation. Pairwise insertion agreement is a necessary local property, not a complete operational transformation correctness theorem. Every leaf has a separate rubric criterion in X-T76-006. Public test passage alone does not assess independent understanding.

## Hints and recovery

Do not delete the parent edge when hiding a character. Then Sort siblings by identity before recursively rendering descendants. Record the failed hypothesis before using further hints.

## Transfer challenge

Add delete operations delivered before insert, Unicode scalar payloads and snapshot compaction. Compare an explicit pending-dependency queue with tombstone admission. Implement an operational transformation context-control protocol with state vectors and retained transformations, identify assumptions about fixed membership and failures, and test more than pairwise transformation equations.

# PR-T48-02: Bounded boot information and memory reservations

## Contract

A boot tag carries a byte size; the following tag starts at its eight-byte-rounded end. Check the raw extent before rounding or reading fields. Preserve the module, boot structure and kernel physical ranges before giving any page to a process. Reserved overlapping map entries win over usable entries in this teaching allocator.

This 6-hour milestone includes implementation and verification. Reading, assessment and delayed retrieval are in the module budget. Reuse accepted prerequisites; implement the studied mechanism in the learner workspace.

## Inputs and expected results

Use `fixtures/kernel/PR-T48-02.json` for the declared finite calculation and `labs/kernel` for actual C/guest controls. Static arithmetic does not close the executable gate. The relevant CTest names are `kernel_boot`. For early projects 03–10, a full kernel_guest run is a later cumulative regression: the immediate component dossier must include the project-local trace specified below; the full run cannot be claimed until its later dependencies exist. Cross-family projects explicitly enable the original runtime/store source paths; a standalone kernel pass is insufficient.

## Steps

Decode tags by explicit field widths, accepting larger compatible memory-map entry strides. Require one bounded module and one map. Generate truncated headers, invalid strides and overflowing physical ranges before using actual GRUB input.

Keep the contract, pre-run prediction, exact image/build identity, raw observation and first invalid transition. Reveal hints in `labs/kernel/HINTS.md` in stages. The default stubs compile but fail; selecting an assessor solution changes the evidence category.

## Failure cases

Size below eight, rounded tag beyond total size, overflowing base plus length, missing terminator, duplicate required tag and reserving only kernel .text.

## Acceptance and evidence

Pass kernel_boot and retain an actual boot reservation ledger. A synthetic tag at offset 8 with size 21 must advance to offset 32.

- **T48.02.a**: Validate complete boot-tag and memory-map spans before interpreting fields.
- **T48.02.b**: Reserve boot-owned memory and give reserved overlaps precedence over available ranges.
- **T48.02.c**: Reject truncated or overflowing records while preserving the prior output contract.

Map each objective to a concrete file/observation, retain negative controls and state unresolved claims. Refer to {ref}`guide-assessment` for rubric and causal repair.

## Inputs and expected results

Tags A..E denote distinct numeric tags in the target harness. Fixture `(3,A),(1,B),(3,C),(2,D),(1,E)` gives B, E, D, A, C, six shift writes, four final placements and nine key comparisons. The merge checkpoint takes left ties before right ties. Sorted/reverse five-key inputs use four/ten comparisons with the declared final-placement convention. Heap-sort evidence is ordering/permutation only, since its prior policy is unstable.

## Failure cases

Test n 0/n 1/32, all equal, largest unsigned keys, capacity 31 for 32 records in the checked API, and a `≥` shift mutation. Whole-record moves must keep key/tag pairs intact. Failure returns before any writes; stable but corrupted multiplicities and sorted but reversed tags both fail acceptance.

## Hints and recovery

Preserve the pending whole record across shifts. A tie must stop insertion and choose the left head in merge for this policy. Count comparisons at the stopping predecessor, but not a nonexistent predecessor when insertion reaches index 0. If counts differ by one, replay that boundary before altering the algorithm.

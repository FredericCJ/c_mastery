# PR-T73-01: Scope-owned child tasks and cooperative cancellation

## Contract

Implement MsgNursery with eight stable child slots, one parent owning admission/join, borrowed contexts and atomic cooperative cancellation. Child failure requests sibling cancellation; join must wait for every admitted child and return the first nonzero result in creation order. Inject pthread creation failure at each one-based attempt, retaining previously admitted children. Closing rejects new tasks. Supply a work.pool adapter that transfers each accepted task into this lifetime scope and proves no child outlives its borrowed stack context.

The full required exercise {ref}`X-T73-001`, its shared contracts and objective rubric are part of this project. Eight hours is descriptive author accounting, not a learner-time or scope ceiling.

## Inputs and expected results

Spawn result5 then result0: after join, both slots are joined, cancellation is true and result is5. Fail admission at attempt2: exactly one child remains admitted, its context is retained until join and no second thread handle is joined. An uncooperative infinite child is a bounded external-timeout experiment, not silently declared cancelled.

## Steps

- **T73.01:** Derive admission/closing/quiescent states, implement spawn/join and deterministic error selection, then compose with the existing work.pool artifact without detached tasks or prematurely released contexts. Submit the exercise D1–D4 and retain prerequisite interfaces.

## Failure cases

Inject failure before every admission, record thread/context ownership, join zero/one/eight children, reject ninth admission and late spawn. Use a barrier-controlled failure with siblings acknowledging cancellation and compare accepted/completed counts. Reject both missing-cancellation and swallowed-result mutants. Run separate TSan and demonstrate that eventual cancellation needs child checkpoints.

## Acceptance and evidence

- **T73.01:** Explain scope-owned task lifetime, failure aggregation and cooperative cancellation, including why a cancellation flag does not establish completion or a bounded join latency. Every leaf has a separate rubric criterion in X-T73-001. Public test passage alone does not assess independent understanding.

## Hints and recovery

Admission and completion are different ownership events. Then A failed create has no thread to join, but earlier successful creates still do. Record the failed hypothesis before using further hints.

## Transfer challenge

Add nested nurseries with a parent deadline: propagate cancellation down while joining upward, retaining contexts until every descendant is quiescent. Delayed assessment supplies two failures racing in different orders; keep deterministic creation-order reporting while preserving both errors in a bounded aggregate.

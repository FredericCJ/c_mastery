# PR-T66-01: Owning handles and the partial-initialization frontier

## Contract

Implement ow_construct and ow_destroy for OwOwner, which owns exactly three separately acquired int32_t arrays after success. The input lengths array has three positive counts, each representable as count*sizeof(int32_t). Validate every count before any allocator call. The output must initially be empty. Acquire in index order using the imported V4Allocator; on the first null return, release the acquired prefix in reverse order and leave the output unchanged. Publish only after all three acquisitions. Destroy releases the live prefix in reverse order, clears each pointer and count, and succeeds on an empty owner. Callbacks cannot reenter, fail release or exit nonlocally.

The full required exercise {ref}`X-T66-001`, its shared contracts and objective rubric are part of this project. Eight hours is descriptive author accounting, not a learner-time or scope ceiling.

## Inputs and expected results

Lengths[1,2,3] with failure on take2 produce `NOMEM`, one release, zero live blocks and unchanged empty output. Failure on take1 releases nothing. Three successful takes publish count3; two destroy calls together perform exactly three releases. A zero middle count causes no allocator invocation.

## Steps

- **T66.01:** Implement transactional three-resource construction and idempotent destruction using the accepted typed allocator callback ABI, proving which prefix is owned at each failure point. Submit the exercise D1–D4 and retain prerequisite interfaces.

## Failure cases

Inject failure on each acquisition, reject zero and overflowing lengths before any callback, instrument release order and exactly-once counts, and test repeated destruction. Kill the omitted-rollback mutant. Extend the anchor with a callback trace that proves reverse order, not just equal release totals.

## Acceptance and evidence

- **T66.01:** Derive the construction frontier invariant and distinguish acquired storage, initialized object state and published ownership; compare explicit C cleanup with automatic language destruction. Every leaf has a separate rubric criterion in X-T66-001. Public test passage alone does not assess independent understanding.

## Hints and recovery

At iteration i, only blocks0 through i-1 are owned. Then Do not assign the public owner until every acquisition succeeds. Record the failed hypothesis before using further hints.

## Transfer challenge

Replace the prefix with a dependency graph: acquire A, then B and C independently, then D requiring B. Write an initialized-set representation and reverse dependency cleanup. Delayed assessment makes C initialization fail after its storage acquisition; distinguish storage release from destruction of a constructed value.

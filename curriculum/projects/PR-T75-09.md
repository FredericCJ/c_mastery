# PR-T75-09: Resilient telemetry admission, committed effects and draining

## Contract

Implement RZService by composing the accepted deadline, limiter, breaker, receiver, pending queue and actual T73 MsgHub. Reserve notification capacity before committing a new synthetic effect; flush only consumes a pending ID when channel send accepts it. Then build the full local telemetry service through the existing IPC/reactor/TCP-fault artifacts, using the wheel for retries and deadlines, limiter for all original/retry/hedge work, breaker permits until terminal completion, and deduplication for repeated requests. Keep the executable anchor and this required integration as distinct evidence obligations.

The full required exercise is {ref}`X-T75-009`; its shared contracts, D1–D4, objective-specific rubric and delayed variant are part of this project. Eight hours is descriptive accounting, not a ceiling on required work.

## Inputs and expected results

A new delta2 request applies once and queues its ID. Flush to channel0 allows msg_select to observe that exact ID. Filling the four pending slots rejects the next request before changing receiver.total. A full/cancelled imported channel retains pending notifications. Cancellation after an admitted effect cannot make its already-reserved notification disappear.

## Steps

- **T75.09:** Implement the bounded service anchor using actual conc.channel and all required local IPC/reactor/fault adapters; preserve exactly-once notification for a new retained request and explicit replay/expiry semantics. Complete every exercise deliverable, including separately specified extensions.

## Failure cases

Locally correct components can compose into lost committed notifications, duplicated effects, retry storms or premature cleanup. A service acceptance result needs a defined commit point and recovery policy, not a collection of successful unit tests. For the public anchor, fill/drain the real MsgHub, close/cancel it and compare pending IDs with receiver records. Mutation1 commits after notification capacity is exhausted; mutation2 discards an item without channel acceptance. For the full integration, enumerate each acquisition/failure prefix and replay randomized seeded event traces with an independent total/effect ledger. Retain exact compiler/link dependencies and actual measured traces. Do not record a simulated timer observation as hardware/network latency.

## Hints and recovery

Reserve the resource that makes a committed effect observable before committing it. Cancellation can stop new work without undoing work already accepted. A full queue requires a recovery decision; silently forgetting the head is not backpressure.

# PR-T47-06: Bounded no-steal transactions

## Contract

Implement begin, abort and the transaction state machine. Reject nested begin and commits without an active transaction. Demonstrate that staging updates and deleting records leaves the stable home image unchanged. Fill the node pool, force a split allocation failure and show that the old committed map survives without any partially applied operation.

Budget 5 implementation and 3 verification hours. Reuse the same engine throughout; previous milestones are not charged again. The public API and original disk format are in the storage laboratory.

## Inputs and expected results

Use [the contract fixture](../../fixtures/storage/PR-T47-06.json) and the actual C tests `storage.transaction`. The image has 67 pages of 4096 bytes; the tree owns 32 logical data pages. The reference transaction changes the complete map from {1:10,2:20} to {1:11,3:30}. Compare whole maps. No fixture asserts physical power-cut durability.

## Progressive execution

The immediate learner gate is `storage.transaction`. Early tests inject declared valid component states; they do not require a completed opener, recovery engine or later mutation API. Defer `storage.format`, `storage.capacity` until PR-T47-09/10 integrates opening, durable publication and recovery. Passes cover their finite mechanism only; retain the separate invariant, failure and transfer evidence.

## Failure cases

Attempt a second begin, access a poisoned handle and call commit after abort. None may silently begin a replacement transaction or report success.

An unavailable compiler, sanitizer runtime, syscall or device produces unavailable evidence; it never counts as a clean run. A wrong implementation must fail a semantic assertion after successful setup.

Include the exact source-reading locator and fault assumptions. A CTest family pass supports its executed cases, not automatic completion of every objective. Use `tools/verify_storage_fixtures.py` for contract-index consistency; it neither compiles your C nor awards runtime mastery.

## Hints and recovery

Atomicity begins before logging: uncommitted nodes must never reach their home pages. store_begin loads live nodes into bounded typed scratch, records the prior root/allocation map and admits one writer. Input rejection leaves staged earlier work intact; capacity failure aborts the complete transaction. This explicit difference belongs in the API contract. The caller serializes all access, including readers; there is no hidden locking or snapshot mechanism. Scratch, clean cache, I/O buffers and C call stack have separate memory bounds.

The staged laboratory hints separate invariant, observation and repair direction. Keep the original failing image or key sequence and compare it with a clean control.

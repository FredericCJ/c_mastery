# PR-T03-03: Raw-storage slot and alias contract audit

## Contract

Build a single-element raw-storage abstraction with explicit allocator callbacks, type size/alignment, initialization and destruction. Exercise one concrete type through a typed wrapper. Create an aliasing/provenance audit alongside it, comparing valid representation copying, invalid cast-based access, restricted disjoint transforms and stale address reuse. The portable component makes no direct library calls.

The declared profile **C** applies to the boundary named here; specify harness versus component dependencies in {ref}`guide-profiles`. Budget 10 h for implementation and verification together. Start from your own sources and the listed fixtures, with prior modules as prerequisites; no starter repository or solved program is required.

## Inputs and expected results

The fixture defines half-open ranges [0,4), [4,8), [2,6) and [8,8). Its pairwise overlap results establish that adjacent and empty ranges do not overlap, while partially intersecting ranges do. This arithmetic oracle supports contracts, not an implementation-dependent pointer-order test.

## Failure cases

Allocator failure leaves the slot empty; failed construction must not publish a live value. Reject insufficient alignment/capacity. Do not execute incompatible lvalue accesses or stale pointers as expected-output tests. Restrict promises must cover the accesses, not only distinct base addresses.

## Acceptance and evidence

Show a complete slot state/access timeline, release exactly once, and a reachable-callback dependency audit. Present optimized-code evidence only after proving the transform’s alias contract. Provide a handle alternative for the address-reuse scenario.

Record contract, build/dependency evidence, independent cases, minimized failures and the specific evidence file for every linked objective. A passing synthetic oracle does not establish a passing implementation. Use {ref}`guide-assessment` for the review gate.

## Hints and recovery

Start with one known type instead of a fully generic container. Treat allocation, initialization and publication as separate states. Compare addresses only inside the synthetic range model or under a documented target extension.

If stuck, separate the violated contract from the observed symptom and reduce the input before changing the implementation. Revisit the linked teaching section and retain the minimized case after repair.

## Contract

Calculate S+A−P for declared signed-width fields, reject overflow, and correlate one actual relocation with final bytes. Build non-PIE, PIE and shared variants of the same address-taking program. Attribute address formation and runtime relocation without claiming identical code or costs.

## Inputs and expected results

Load [`fixtures/systems/PR-T09-02.json`](../../fixtures/systems/PR-T09-02.json). Its `input` and `expected` define an exact synthetic case, not an observation from a real compiler, filesystem, board or concurrent run. Run `python tools/verify_systems_fixtures.py` from the curriculum root to recompute all declared fields. Keep input immutable for the reference comparison; store observed outputs separately. The fixture is one anchor, not exhaustive acceptance coverage.

## Steps

1. Write the operation/state/effects contract and predict the fixture result by hand.
2. Establish the smallest supported positive case and record environment/provenance.

- **T09.04:** Calculate a positive, negative and overflowing relocation, then locate one real relocation and its final bytes.
- **T09.05:** Build the same address-taking example as non-PIE, PIE and a shared object and identify its address-formation mechanisms.

3. Add boundary and deliberate-failure cases before broadening the implementation.
4. Minimize each disagreement and retain the earliest broken invariant.

## Failure cases

- Challenge the mistaken claim: A relocation contains only an absolute address. Preserve a minimal failing trace or explain the valid precondition that excludes it.
- Challenge the mistaken claim: PIC and dynamic linking mean the same thing. Preserve a minimal failing trace or explain the valid precondition that excludes it.

Exercise empty/singleton or zero-progress states where the operation admits them, exact capacity, one beyond capacity, repeated completion/cleanup and a deliberately invalid precondition. For storage-owning work, inject acquisition failures and verify unchanged old ownership. For build/binary/source studies, inject a wrong edge, symbol, width, target assumption or unsupported environment and require a visible failure verdict. Never execute malformed pointers or privileged instructions just to demonstrate a negative case. Apply these cases to the declared operation; document any inapplicable case and its reason.

## Hints and recovery

Compute the mathematical displacement before truncating to its field width. A matching low byte is insufficient when the signed displacement is outside the relocation’s permitted range.

If the fixture oracle fails, stop and repair the fixture/oracle independently; do not change expected data to fit the target.

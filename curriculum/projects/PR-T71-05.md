# PR-T71-05: Bounded active-object queue and failure-preserving dispatch

## Contract

Compose the HSM with a four-slot copied-event ring; reject overflow unchanged and retain an event whose dispatch fails. Integrate learner-owned execution.tasks and sync.copied_queue through an explicit adapter. The full required specification is {ref}`X-T71-005` and its explicit shared contract. Twelve hours is descriptive author accounting, never a ceiling.

## Inputs and expected results

The fifth post to a full ring rejects. If CONNECT cannot fit its trace, head/count remain0/4 and OFFLINE stays active. Four successful steps reach FAULT.

## Steps

- **T71.05:** Complete D1–D4, the named public anchor, independent falsification and changed-contract implementation.

## Failure cases

Test full/empty/wraparound, trace-capacity failure before removal and bursts CONNECT/START/FINISH/FAIL. Reject overwrite-on-full and consume-before-dispatch-success mutants. Model adversarial event floods using synthetic counters.

## Acceptance and evidence

- **T71.05:** Satisfy all four leaf rubrics and source-bound verification; passing supplied tests alone is insufficient.

## Hints and recovery

Separate enqueue from dispatch commits. Copying an event removes the borrow of the producer's event storage; it does not synchronize concurrent writes to queue indices or prevent competing consumers from removing the same event. Preserving a failed event forces a policy for poisoned queues.

## Transfer challenge

Change one producer to an interrupt source and two consumers to competing tasks. Identify the single-consumer assumption that fails, implement a bounded enqueue synchronization adapter, and choose a documented policy for an unhandled event that blocks the queue.

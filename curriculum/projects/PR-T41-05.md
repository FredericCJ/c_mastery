## Contract

Implement the selected IPv4 receive/emit and ICMP Echo subset above checked Ethernet. Receive version 4/IHL 5, bounded total 20..1500, positive TTL, correct header checksum, local destination/configured peer source and protocol 1/6. Reject options, MF or nonzero fragment offset and unknown protocol. Emit DF 1, MF 0, offset 0, ID 0, TTL 64. This intentionally omits full-host reassembly/options requirements; keep that limitation explicit.

ICMP Echo accepts type 8/code 0, valid checksum and 0..64 data octets; reply type 0 preserves id, sequence and payload. Implement reusable one's-complement checksum over byte spans, including odd final byte and TCP's IPv4 pseudo-header. Fold carries without overflowing the selected accumulator.

## Inputs and expected results

The supplied fixture uses five bytes hex 6162636465, Echo id 0x1234/seq 1 and peer/local 192.0.2.1/.2. Reply IP total is 33; Ethernet header+IP is 47, requiring 13 pad bytes before FCS for 64 minimum MAC frame. It recomputes exact emitted request/reply IP/ICMP bytes, checksums and padding, plus the odd final-byte checksum example. It does not execute the receive parser or establish fragment/options rejection.

Create mandatory learner receive cases with an invalid IP checksum, IHL other than 5, MF set and nonzero fragment offset, as well as the length/TTL/address/ICMP cases below. Assert the specific drop category and unchanged output sentinels. Include one valid packet with Ethernet padding and ensure only IPv4 total-length bytes reach ICMP.

Output verified/trimmed datagram spans, exact Echo reply bytes and drop categories. Do not checksum Ethernet padding as ICMP data; IPv4 total length bounds the nested message.

## Steps

1. Independently derive odd-span and end-around carry examples, then implement bounded checksum over one and split spans.
2. Parse fixed IPv4 fields and reject all length/flag/header mismatches before reading ICMP/TCP data.
3. Build the Echo reply from preserved fields and recomputed checksums; derive IP length/padding separately.
4. Inject each corruption, odd-length split, MF/nonzero offset and IHL 6. Keep all failed output sentinels unchanged.
5. Run actual default 56-byte ping on the isolated link and compare peer capture bytes with your target output; record host offload/capture settings.

## Failure cases

Truncated or inconsistent length, TTL 0, wrong destination/source, invalid checksum, fragmented/options packet, nonzero Echo code and payload over 64 drop without reply/publication. Receiving a checksummed IPv4 header never bypasses ICMP/TCP checksum validation. A checksum result from a host RAM fixture cannot establish hardware CRC or electrical integrity.

## Acceptance and evidence

Submit the independent checksum/length worksheet, exact reply wire bytes, odd/split-span tests, invalid-case counters and actual Echo capture. The three objectives require fixed-header validation, one's-complement/pseudo-header arithmetic and exact Echo plus omitted-requirement evidence. Show the same data is returned unchanged and that receive padding is trimmed exactly once. Successful ping remains lower-layer evidence, not TCP/HTTP acceptance.

## Hints and recovery

If only odd-length messages fail, inspect whether the final byte became 0xXX00 and whether carries were repeatedly folded. If ICMP checksum differs by the padding amount, audit nested total length. If a packet with options seems parseable, still enforce the declared IHL 5 subset and record the omitted host requirement.

## Transfer challenge

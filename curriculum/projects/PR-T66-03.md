# PR-T66-03: Move protocols, source poisoning and the limits of must-use diagnostics

## Contract

Implement ow_move(destination,source) for distinct valid OwOwners. Destination must be empty and source nonempty. Transfer every owned pointer and allocator, then clear source pointers and count; reject self-move, a nonempty destination and an empty source without side effects. ow_consume destroys a nonempty owner and returns `DEAD` for empty. The public header offers OW_MUST_USE as an explicitly GNU/Clang warn_unused_result diagnostic extension; baseline C17 permits ordinary struct copying and does not enforce linear use.

The full required exercise {ref}`X-T66-003`, its shared contracts and objective rubric are part of this project. Eight hours is descriptive author accounting, not a learner-time or scope ceiling.

## Inputs and expected results

After moving three blocks, destination.count=3 and source.count=0. Consuming the source returns `DEAD`; consuming the destination releases three blocks once; a second consume returns `DEAD`. A direct C assignment copying the original owner is a counterexample to an alleged static move-only guarantee.

## Steps

- **T66.03:** Implement checked move/consume operations and an isolated diagnostic probe that intentionally ignores OW_MUST_USE, with extension-enabled and portable builds reported separately. Submit the exercise D1–D4 and retain prerequisite interfaces.

## Failure cases

Test self-move, occupied destination, empty source, repeated consumption and allocator release counts. Reject the source-not-poisoned mutant. Compile a copied owner without consuming both copies: use it as a static counterexample, not an unbounded double-free experiment. Record whether GCC/Clang actually emit the ignored-result diagnostic.

## Acceptance and evidence

- **T66.03:** Separate ownership transfer, physical byte copying, source poisoning and diagnostic enforcement; explain why ISO C17 cannot prevent all implicit copies of this public struct. Every leaf has a separate rubric criterion in X-T66-003. Public test passage alone does not assess independent understanding.

## Hints and recovery

The postcondition needs both destination ownership and source invalidation. Then A debug bit cannot intercept an ordinary assignment elsewhere. Record the failed hypothesis before using further hints.

## Transfer challenge

Move a self-referential value or an inline-buffer owner: derive why copying its bytes may leave internal pointers referring to the former object. Delayed assessment hides the representation behind an opaque handle but allows duplicate handles; identify the remaining duplication attack and design checked generation/ownership tokens.

# PR-T73-06: Bounded work stealing with an explicit C memory-order proof

## Contract

Implement the eight-slot single-owner/multiple-thief deque with atomic unsigned payloads and sequentially consistent operations. Owner push/pop uses the bottom; thieves steal the top. Compete for the final item using CAS, return `CONFLICT` on loss without publishing output, and retire indices before wrap. Derive the sequentially consistent linearization argument before comparing the published weaker-order algorithm. Integrate with work.pool using integer task IDs whose external lifetime is retained until exactly-once completion.

The full required exercise {ref}`X-T73-006`, its shared contracts and objective rubric are part of this project. Eight hours is descriptive author accounting, not a learner-time or scope ceiling.

## Inputs and expected results

Push7,push8,pop,steal,steal returns OK,OK,8,7,`EMPTY`. Eight live entries fill capacity and a ninth push leaves state unchanged. Empty pop preserves its output canary. Starting quiescent top=bottom=SIZE_MAX-1 makes push return OVERFLOW. Two thieves plus owner process4000 distinct IDs exactly once in the supplied threaded anchor.

## Steps

- **T73.06:** Derive a circular representation with monotonic nonwrapping indices and atomic slots; implement push/pop/steal with a proof for empty, full, last-item and reused-slot states. Submit the exercise D1–D4 and retain prerequisite interfaces.

## Failure cases

Differentially compare1095 bounded sequential traces with Python deque, include repeated empty pops and capacity reuse, record concurrent invocation/response histories and check small histories for legal linearizations. Reject wrong-pop and omitted-steal-CAS mutants. Run TSan, inspect generated instructions and report atomic_is_lock_free; do not infer weak-memory correctness from x86 stress.

## Acceptance and evidence

- **T73.06:** Identify linearization and ownership in competing owner and thief operations, last-item arbitration, finite-index exhaustion and stale slot reads; distinguish correctness under sequential consistency from weak-order proof and actual lock-free progress. Every leaf has a separate rubric criterion in X-T73-006. Public test passage alone does not assess independent understanding.

## Hints and recovery

The last item has two potential consumers. Then A losing CAS must not publish its speculative payload. Record the failed hypothesis before using further hints.

## Transfer challenge

Replace sequentially consistent operations with acquire/release operations and fences one edge at a time, deriving a C memory-model argument and model-checker counterexamples before benchmarking. Delayed assessment changes payloads to pointers and permits array growth: add a reclamation scheme and prove a losing thief cannot dereference freed storage.

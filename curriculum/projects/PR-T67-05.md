# PR-T67-05: Branded pool handles with checked generations

## Contract

Implement the fixed4slot ADPool API. init requires a live fixed-address pool with no surviving handles. acquire takes first free nonretired slot and returns owner pointer/index/generation; full pool fails unchanged. get/release validate exact live pool identity, index and generation. Release increments generation, or permanently retires a UINT_MAX generation slot. Caller controls synchronization; no concurrent calls.

The full required exercise {ref}`X-T67-005`, its shared contracts and objective rubric are part of this project. Eight hours is descriptive author accounting, not a learner-time or scope ceiling.

## Inputs and expected results

A handle frompoolA is rejected bypoolB; release/reacquire invalidates the old generation; release atUINT_MAX retires its slot and reduces usable capacity to3.

## Steps

- **T67.05:** Derive FREE/LIVE/RETIRED transitions and count available slots. Explain why copying a handle is permitted by C yet does not duplicate ownership. Pool objects must remain live at fixed addresses and cannot be reinitialized or reused while handles survive: pointer identity does not prevent ABA across object lifetimes. Compare PhantomData nominal/lifetime roles without claiming equivalent static checks. Submit the exercise D1–D4 and retain prerequisite interfaces.

## Failure cases

Run adt.brands and enumerate short acquire/release/get traces against an independent occupancy/generation model. Kill owner-check omission and generation-check omission independently. Compile a wrong-category handle probe; show that copying or explicitly constructing a valid public representation bypasses any unforgeability claim.

## Acceptance and evidence

- **T67.05:** Separate nominal handle category, pool identity, slot generation and ownership; demonstrate why a C wrapper cannot create a compile-time fresh brand per runtime pool or enforce linear use. Every leaf has a separate rubric criterion in X-T67-005. Public test passage alone does not assess independent understanding.

## Hints and recovery

Write the state transitions before adding generations. Then Check owner and index before indexing storage. Record the failed hypothesis before using further hints.

## Transfer challenge

Replace the owner pointer with a nonreused externally assigned pool identity and implement relocation of the pool. Then introduce concurrent get/release: provide a reclamation/lifetime protocol, not just an atomic generation counter.

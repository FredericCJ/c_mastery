# PR-T01-01: Trace, invariant and finite-representation diagnostic

## Contract

Implement a caller-storage prefix-sum routine for at most 16 signed values. Each input and every intermediate prefix must fit the declared result bounds. Return a range failure before any unrepresentable addition, even when cancellation would make the final mathematical sum fit. On every failure leave output storage unchanged; use a fixed local staging array before committing results. Before implementation, give an invariant and termination argument. Independently trace a recursive version on paper; implementation of recursion is optional, but its live-call and space account is required. Include conversion and flag exercises under an explicitly synthetic eight-bit representation, rather than claiming the host has eight-bit bytes.

The declared profile **C** applies to the boundary named here; specify harness versus component dependencies in {ref}`guide-profiles`. Budget 6 h for implementation and verification together. Start from your own sources and the listed fixtures, with prior modules as prerequisites; no starter repository or solved program is required.

## Inputs and expected results

The fixture supplies [3, -1, 4], decimal 173, width 8 and flag mask 12. Expected prefix totals are [3, 2, 6]; the representation is binary 10101101 and hexadecimal ad. The flag table enumerates all four combinations of the two selected bits. Its signed-bound cases use a declared synthetic range -32768..32767: [32767, 1, -1] and [-32768, -1, 1] fail at zero-based index 1 although their final mathematical sums fit; [-32768, 32767, 1] succeeds with prefixes [-32768, -1, 0]. Also test the corresponding INT_MAX and INT_MIN cases for the actual C int type, using <limits.h> rather than assuming its width.

The canonical fixture is `fixtures/language/PR-T01-01.json`. Preserve its supplied fields and add independent cases in your dossier. Run `python tools/verify_language_fixtures.py` from the curriculum root to verify the fixture oracle; then test your C component separately.

## Steps

First fill in prediction tables without running code. Implement the iterative component with no external C-library calls; use a hosted harness for printing. Validate the input value and test the next addition against the declared bounds before evaluating it; do not rely on a wider integer type being available. Stage at most 16 prefix results locally and publish them only after complete validation. Add empty and capacity-limit inputs, count operations, and compare a recursive state trace with the iterative trace. Check representability before accepting the synthetic width.

- **T01.01:** Trace a loop and recursive sum on [3, -1, 4]; count additions, iterations and maximum live calls, then state the invariant and decreasing measure. Reject a cancellation case whose intermediate prefix exceeds the declared bounds. Retain a state table, an induction argument, checked-prefix rejection evidence, and separate O(n) work / O(1) iterative / O(n) recursive stack claims. For its three original objectives, record separate evidence references: T01.01.a (Trace loops and recursion using explicit state tables.); T01.01.b (Derive time and auxiliary-space costs for simple implementations.); T01.01.c (State loop invariants and termination conditions before coding.).

- **T01.02:** Convert decimal 173 to binary and hexadecimal, then build a truth table for two flags and compare any/all predicates. Retain conversions checked by reconstruction and a complete truth table including neither, each and both flags. For its three original objectives, record separate evidence references: T01.02.a (Convert between binary, hexadecimal, and decimal representations.); T01.02.b (Relate Boolean expressions to masks and truth tables.); T01.02.c (Distinguish mathematical integers from finite machine representations.).

## Failure cases

Reject a list longer than capacity, an out-of-range input, or an unrepresentable intermediate prefix without changing output storage. Do not dereference an empty range. Never compute an overflowing prefix first and inspect it afterward. A representable final mathematical sum is insufficient: retain the positive and negative cancellation failures as regressions.

## Acceptance and evidence

Submit traces, an initialization/preservation/exit proof including representability before every addition, the decreasing measure, complexity accounts and a dependency contract. Show unchanged output sentinels after each cancellation failure and the successful boundary trace. Account for the fixed staging capacity separately from the unbounded-recursion stack model. Each representation result must reconstruct the decimal input. Show any-bit and all-bit predicates differ on a one-bit case.

Record contract, build/dependency evidence, independent cases, minimized failures and the specific evidence file for every linked objective. A passing synthetic oracle does not establish a passing implementation. Use {ref}`guide-assessment` for the review gate.

## Hints and recovery

Use k as the number already processed, not the next valid index and last processed index interchangeably. Draw recursive activations until the base case; include the base activation in the stated counting convention.

If stuck, separate the violated contract from the observed symptom and reduce the input before changing the implementation. Revisit the linked teaching section and retain the minimized case after repair.

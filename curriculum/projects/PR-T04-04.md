# PR-T04-04: Floating contract and boundary laboratory

## Contract

Create a floating-point laboratory that records the chosen type characteristics, exception/rounding support and strict compiler configuration. Compare naive and compensated accumulation, fused versus separated operations where supported, and one explicitly relaxed build. The result is a numerical dossier, not a universal guarantee of IEEE behavior.

The declared profile **A** applies to the boundary named here; specify harness versus component dependencies in {ref}`guide-profiles`. Budget 10 h for implementation and verification together. Start from your own sources and the listed fixtures, with prior modules as prerequisites; no starter repository or solved program is required.

## Inputs and expected results

The fixture uses exact decimal strings 10000000000000000, 1 and -10000000000000000; its mathematical sum is 1. It also supplies reference 0 and observed 0.000001 with absolute tolerance 0.000002, so the declared near-zero test accepts it. Learner floating results are measured separately under a recorded format.

## Failure cases

Do not use a relative-only comparison at zero. Treat unsupported rounding/exception facilities as explicit limits. Never increase a tolerance solely to silence a failure; minimize the disagreement and revisit the analysis. Keep performance conclusions within identical semantic requirements.

## Acceptance and evidence

Submit format/environment evidence, error tables, boundary vectors and criterion derivations. Explain at least one cancellation case and one strict/relaxed disagreement. Save compiler flags, library version and reference precision so another reader can reproduce the experiment.

Record contract, build/dependency evidence, independent cases, minimized failures and the specific evidence file for every linked objective. A passing synthetic oracle does not establish a passing implementation. Use {ref}`guide-assessment` for the review gate.

## Hints and recovery

Begin with exact rational or decimal reference calculations, then distinguish conversion error from accumulation error. Record signed-zero behavior without assuming it survives fast-math.

If stuck, separate the violated contract from the observed symptom and reduce the input before changing the implementation. Revisit the linked teaching section and retain the minimized case after repair.

# PR-T68-04: Portable C17 variadic machinery and single evaluation

## Contract

Implement mp_variadic as an inspectable demonstration of a nonempty1..4argument macro selecting typed inline functions; arity0 uses a separate explicit empty operation. Each argument is evaluated exactly once and arithmetic is uint32 modulo. The supplied demo evaluates seed+i and reports the exact count. Use separate counters for distinct argument expressions so the test itself does not contain unsequenced writes to one scalar.

The full required exercise {ref}`X-T68-004`, its shared contracts and objective rubric are part of this project. Eight hours is descriptive author accounting, not a learner-time or scope ceiling.

## Inputs and expected results

seed7 andarity0..4 produce sums0,7,15,24,34 with evaluation counts0,1,2,3,4. Arity5fails preserving bothoutputs. No argument-order claim is made.

## Steps

- **T68.04:** Show token substitution, rescan, selector position and parentheses for each admitted arity. Explain why an empty token argument differs from omitted variadic arguments in C17, and why this lab deliberately has a distinct zero-argument entry. Compare N3033 proposal semantics without presenting a proposal as the inspected final C23 standard. Submit the exercise D1–D4 and retain prerequisite interfaces.

## Failure cases

Run metaprog.variadic, inspect -E output, and compile strict C17 probes. Kill duplicate-evaluation and incorrect-zero-identity mutants. Add arguments with commas protected by parentheses and demonstrate an unsafe unparenthesized form in a diagnostic-only target; retain a separate C2x __VA_OPT__ observation.

## Acceptance and evidence

- **T68.04:** Derive a bounded1..4argument dispatch macro without __VA_OPT__ or GNU comma deletion, and distinguish single evaluation from the unspecified order of function arguments. Every leaf has a separate rubric criterion in X-T68-004. Public test passage alone does not assess independent understanding.

## Hints and recovery

Expand the one-argument case completely before the four-argument case. Then Use separate counters for different function arguments. Record the failed hypothesis before using further hints.

## Transfer challenge

Build a bounded logging dispatcher that optionally attaches source metadata, with a distinct zero-field operation. Preserve single evaluation and type checking while making expansion limits explicit; diagnose unsupported arity without compiler-specific comma extensions.

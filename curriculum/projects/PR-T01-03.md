# PR-T01-03: Reproducible bounded list tool

## Contract

Build a two-translation-unit list-sum command-line tool with a documented maximum of four decimal integers and a deterministic text protocol. The reusable computation and the effectful parser must be identifiable. Preserve builds and regressions in version control. The tool is deliberately small so that compile, link, startup and runtime failures can be investigated without unrelated application complexity.

The declared profile **A** applies to the boundary named here; specify harness versus component dependencies in {ref}`guide-profiles`. Budget 6 h for implementation and verification together. Start from your own sources and the listed fixtures, with prior modules as prerequisites; no starter repository or solved program is required.

## Inputs and expected results

The fixture defines valid input tokens [2, -5, 9], capacity 4 and signed result bounds -32768..32767. Expected output is status ok, count 3, sum 6. Empty input produces count 0, sum 0. Invalid spelling and excess capacity have distinct errors and no partial result.

The canonical fixture is `fixtures/language/PR-T01-03.json`. Preserve its supplied fields and add independent cases in your dossier. Run `python tools/verify_language_fixtures.py` from the curriculum root to verify the fixture oracle; then test your C component separately.

## Failure cases

The parser must reject trailing junk, too many tokens, out-of-range values and an unrepresentable intermediate prefix. Check before every addition; a representable final sum after cancellation does not permit an overflowing prefix. Keep user input failures separate from internal invariants. Preserve the first causal error and avoid publishing an accumulated result after rejection.

## Hints and recovery

If the shell or compiler is unfamiliar, pause implementation to practice one compile-to-object and one link command. Use an explicit output directory and retain exact arguments rather than relying on shell history.

If stuck, separate the violated contract from the observed symptom and reduce the input before changing the implementation. Revisit the linked teaching section and retain the minimized case after repair.

# PR-T66-05: Interior-mutability cells and guard escape boundaries

## Contract

Build OwCell over the previous borrow book initialized with extent1. Read requires a live token whose range is exactly[0,1); write additionally requires a writer token. Replace admits no active guards and writes the old output only after all checks. Return `STALE` for a dead token, `INVALID` for a token range/mode that cannot authorize the operation, and `BUSY` for replacement while borrowed. All cell operations are single-threaded or externally excluded; do not return an unchecked persistent pointer into the value.

The full required exercise {ref}`X-T66-005`, its shared contracts and objective rubric are part of this project. Eight hours is descriptive author accounting, not a learner-time or scope ceiling.

## Inputs and expected results

Cell value9, old-output sentinel71 and one reader: replace(4) returns `BUSY`, leaves value9 and sentinel71. Read succeeds with9; write through that reader returns `INVALID`. After release, reading with the old token returns `STALE` and replace publishes4 while returning old9.

## Steps

- **T66.05:** Implement guarded read/write and transactional replacement, composing the range guard protocol without bypassing its identity or exclusivity checks. Submit the exercise D1–D4 and retain prerequisite interfaces.

## Failure cases

Test shared readers, exclusive writer, stale/released token, zero-length and partial-range tokens, failed replacement output canaries and every allowed guard-release order. Reject replacement that ignores an active guard. Analyze an escaped raw-pointer API as a contract counterexample rather than treating a clean sanitizer run as proof.

## Acceptance and evidence

- **T66.05:** Explain how dynamic borrow guards permit controlled mutation through a shared interface without making const a global immutability or thread-safety guarantee. Every leaf has a separate rubric criterion in X-T66-005. Public test passage alone does not assess independent understanding.

## Hints and recovery

A live token alone does not prove that it covers the whole cell. Then Validate exclusivity before writing either value or old output. Record the failed hypothesis before using further hints.

## Transfer challenge

Add reentrant callbacks that read the cell while an update is in progress: choose an explicit rejection or snapshot policy and test it. Delayed assessment moves to multiple threads; derive the synchronization and guard lifetime changes rather than merely making the value atomic.

## Contract

Create debug, sanitizer, release and size presets for a generated-header component. The generator is a host utility. Header edits, deletions and clean builds must rebuild exactly the declared dependent objects; configuration must not run target binaries. Deliberately introduce then repair a missing graph edge.

## Inputs and expected results

Load [`fixtures/systems/PR-T07-02.json`](../../fixtures/systems/PR-T07-02.json). Its `input` and `expected` define an exact synthetic case, not an observation from a real compiler, filesystem, board or concurrent run. Run `python tools/verify_systems_fixtures.py` from the curriculum root to recompute all declared fields. Keep input immutable for the reference comparison; store observed outputs separately. The fixture is one anchor, not exhaustive acceptance coverage.

## Steps

1. Write the operation/state/effects contract and predict the fixture result by hand.
2. Establish the smallest supported positive case and record environment/provenance.

- **T07.04:** Build debug, sanitizer, release and size configurations of the same defined program and compare symbols and disassembly.
- **T07.05:** Break a generated-header edge deliberately, then repair it with compiler-generated dependency files.
- **T07.07:** Generate a header from a small schema and provide explicit configuration answers for a non-runnable target.

3. Add boundary and deliberate-failure cases before broadening the implementation.
4. Minimize each disagreement and retain the earliest broken invariant.

## Failure cases

- Challenge the mistaken claim: Listing a directory as an ordinary prerequisite expresses only creation order. Preserve a minimal failing trace or explain the valid precondition that excludes it.
- Challenge the mistaken claim: A file produced once during configuration cannot become stale. Preserve a minimal failing trace or explain the valid precondition that excludes it.

Exercise empty/singleton or zero-progress states where the operation admits them, exact capacity, one beyond capacity, repeated completion/cleanup and a deliberately invalid precondition. For storage-owning work, inject acquisition failures and verify unchanged old ownership. For build/binary/source studies, inject a wrong edge, symbol, width, target assumption or unsupported environment and require a visible failure verdict. Never execute malformed pointers or privileged instructions just to demonstrate a negative case. Apply these cases to the declared operation; document any inapplicable case and its reason.

## Hints and recovery

Give the generated header a producer target and make each consumer depend on it. Touching a header is a useful probe, but deleting it exposes stale-output dependencies that timestamps alone can conceal.

Before changing the target, determine whether the disagreement is its semantics, an invalid test precondition, a boundary mismatch or an environment limitation. If the fixture oracle fails, stop and repair the fixture/oracle independently; do not change expected data to fit the target. Return to the named prerequisite module when ownership, width or ordering assumptions are missing.

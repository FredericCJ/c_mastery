# PR-T02-02: Typed expressions and a two-pass variadic protocol

## Contract

Implement a bounded variadic formatter using a count plus explicit tags. Limit the protocol to promoted int and double arguments; support a sizing pass and a writing pass through va_copy. Separately build a typed-expression and sequencing notebook, replacing ambiguous effectful call-site expressions with explicit steps before they reach the formatter.

The declared profile **A** applies to the boundary named here; specify harness versus component dependencies in {ref}`guide-profiles`. Budget 8 h for implementation and verification together. Start from your own sources and the listed fixtures, with prior modules as prerequisites; no starter repository or solved program is required.

## Inputs and expected results

The fixture supplies an abstract signed value -1 and unsigned comparison width 16. Its converted value is 65535 and its comparison against unsigned 1 is false. This is a synthetic arithmetic model, not a claim that the host unsigned int has 16 bits. Add formatter cases for zero arguments and a promoted float.

The canonical fixture is `fixtures/language/PR-T02-02.json`. Preserve its supplied fields and add independent cases in your dossier. Run `python tools/verify_language_fixtures.py` from the curriculum root to verify the fixture oracle; then test your C component separately.

## Steps

Document the tag/count convention, annotate promotions at every call and pair each va_list initialization/copy with va_end. Draw expression trees for arithmetic and conditional operators. Build sequencing graphs for safe and unsafe examples. Run only defined expressions and compare strict-build diagnostics for separate negative cases.

- **T02.06:** Design a tagged/count convention for a statistics formatter, perform two passes using va_copy, and audit every call-site argument after promotion. Retain a promotion ledger, empty-list case, two-pass output and explicit va_start/va_end ownership for each list. For its three original objectives, record separate evidence references: T02.06.a (Apply default argument promotions at variadic call sites.); T02.06.b (Use va_start, va_arg, va_copy, and va_end correctly.); T02.06.c (Specify a reliable argument-type and argument-count convention.).

- **T02.07:** Draw the tree and type each node for arithmetic, conditional and assignment examples; add a range-checked conversion boundary. Retain a typed expression tree and a table showing both accepted conversions and rejected out-of-range values. For its three original objectives, record separate evidence references: T02.07.a (Separate precedence, associativity, and evaluation order.); T02.07.b (Trace integer promotions and usual arithmetic conversions.); T02.07.c (Analyze conditional expressions, assignments, and explicit casts.).

- **T02.08:** List side effects for a nested-call example and replace a conflicting increment/read expression with explicit temporary values. Retain a sequencing graph, classification under the selected edition and a repair whose result no longer depends on argument order. For its three original objectives, record separate evidence references: T02.08.a (Distinguish sequenced, unsequenced, and indeterminately sequenced evaluations.); T02.08.b (Classify conflicting reads and writes under the selected edition.); T02.08.c (Refactor expressions into explicit, reviewable steps.).

## Failure cases

A tag/type mismatch is a caller contract violation that cannot generally be detected by the callee; do not execute it as an ordinary malformed-input case. Insufficient output capacity must report required size and preserve the chosen termination policy.

## Acceptance and evidence

Show identical semantic output from both traversals, exact capacity boundaries and a conversion ledger. Explain an unspecified argument order that remains defined and one unsequenced conflict that does not. Retain the explicit-step repair and a new test using negative and unsigned inputs.

Record contract, build/dependency evidence, independent cases, minimized failures and the specific evidence file for every linked objective. A passing synthetic oracle does not establish a passing implementation. Use {ref}`guide-assessment` for the review gate.

## Hints and recovery

Keep argument extraction in one switch with the protocol types visible. Separate precedence questions from conversion questions before considering sequencing.

If stuck, separate the violated contract from the observed symptom and reduce the input before changing the implementation. Revisit the linked teaching section and retain the minimized case after repair.

## Contract

Core awareness: compare portable C graphs with inspected LKMM relations and write an isolated version-matched kernel experiment dossier. Use the inspected Linux 6.12 ordinary-work cancel_work_sync contract to draw references from an external producer and queued/running work to module text and its device object. In the declared narrow model, stop and join all producers so racing enqueues are impossible, invoke synchronous cancellation from a permitted sleepable context without a lock needed by the worker, and release the object only after drain. An smp_mb event alone changes neither pending/running work nor reference ownership. Analyze user-pointer access and nonsleepable-context restrictions separately. No kernel module must be loaded to pass. The fixture certifies only this declared ordinary-work lifetime graph; timers, IRQ handlers, RCU callbacks, delayed work, registrations and other module references are excluded and require newly inspected complete contracts before any actual unload claim.

Worked kernel lifetime graph: external producer -> module_text; queued/running work -> module_text and device_object. With one queued and one running instance in the declared model, smp_mb preserves all these lifetime edges. An unload attempt therefore fails the model gate. Stop and wait for every producer first, then let cancel_work_sync return under its no-racing-enqueue and permitted-context preconditions. Only then are pending/running work zero; release the object and consider code removal eligible within this narrow graph. That eligibility is not a real-module verdict: any IRQ, timer, RCU, delayed work or other registration adds a distinct obligation outside this fixture.

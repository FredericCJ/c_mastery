## Contract

Define synthetic memory regions, execution/load addresses and section boundaries; implement a tiny matching linker-script experiment. Retain one indirect registration table with the smallest justified KEEP/extraction policy. Linker assertions reject one over-budget variant; report flash load bytes and runtime RAM separately.

Load [`fixtures/systems/PR-T09-04.json`](../../fixtures/systems/PR-T09-04.json). Run `python tools/verify_systems_fixtures.py` from the curriculum root to recompute all declared fields. Keep input immutable for the reference comparison; store observed outputs separately. ## Steps

1. Write the operation/state/effects contract and predict the fixture result by hand.
2. Establish the smallest supported positive case and record environment/provenance.

- **T09.08:** Describe a text/data/zero-fill layout with region capacities and exported boundaries, and calculate the copy interval.
- **T09.09:** Create a registration table and observe its disappearance, then justify the smallest retention rule.
- **T09.10:** Calculate budgets from a declared map and add linker assertions for one region limit.

3. Add boundary and deliberate-failure cases before broadening the implementation.
4. Minimize each disagreement and retain the earliest broken invariant.

## Failure cases

- Challenge the mistaken claim: Every object has one address meaningful at every stage. Preserve a minimal failing trace or explain the valid precondition that excludes it.
- Challenge the mistaken claim: KEEP automatically pulls every archive member into the image. Preserve a minimal failing trace or explain the valid precondition that excludes it.
- Challenge the mistaken claim: Small file size proves low runtime RAM use. Preserve a minimal failing trace or explain the valid precondition that excludes it.

Exercise empty/singleton or zero-progress states where the operation admits them, exact capacity, one beyond capacity, repeated completion/cleanup and a deliberately invalid precondition. For storage-owning work, inject acquisition failures and verify unchanged old ownership. For build/binary/source studies, inject a wrong edge, symbol, width, target assumption or unsupported environment and require a visible failure verdict. Never execute malformed pointers or privileged instructions just to demonstrate a negative case. Apply these cases to the declared operation; document any inapplicable case and its reason.

## Hints and recovery

Track load bytes and runtime bytes in different columns. A zero-filled section consumes runtime address space even when it contributes no stored payload to the image.

Before changing the target, determine whether the disagreement is its semantics, an invalid test precondition, a boundary mismatch or an environment limitation. If the fixture oracle fails, stop and repair the fixture/oracle independently; do not change expected data to fit the target. Return to the named prerequisite module when ownership, width or ordering assumptions are missing.

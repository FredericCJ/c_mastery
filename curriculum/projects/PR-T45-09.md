# PR-T45-09: Asynchronous lifetime and reentrant scratch repair

## Contract

Implement the original bounded request/generation ownership protocol over caller storage, reusing T21's operation model and T29's qualified adapter only after the selected embedded leaves. Submit transfers a bounded borrow; timeout stops waiting but retains the borrow; cancellation request retains it until matching completion or confirmed cancellation. Exactly one matching event ends the borrow. Reclaim is denied while active, then advances the generation before reuse. Old/duplicate completion cannot access the new generation. A callback's transient borrow expires when it returns. Reentrant operations must use disjoint scratch storage or a documented excluding policy. Host atomics/debugger stops do not establish independent DMA quiescence.

## Inputs and expected results

Request7/generation 1 is submitted, timed out and cancel-requested. Early reclaim is busy. Completion ends the borrow, reclaim produces generation 2 and a late generation 1 completion is stale. Request8/generation 2 confirms cancellation, reaches exactly two total completion outcomes, and reclaim produces generation 3. Another generation 2 completion is stale. The scratch pairs [1,1] and [1,2] produce conflict true and false. These events model the original adapter contract; they are not peripheral timestamps or execution logs.

## Steps

1. Draw ownership intervals for buffer, callback context and scratch, including submit, timeout, cancel request, matching completion and reclaim.
2. Implement the bounded hosted protocol with integer request/generation validation and unchanged state on denied early reclaim. The production caller-storage target owns this mechanism; the harness may allocate externally.
3. Test completion versus cancel acknowledgment ordering, duplicates, stale generations, expired callback borrows and reentrant scratch reuse.
4. Repair lifetime/publication and disjoint scratch policy; require exactly one result and zero retained borrows before reclaim.
5. For a physical extension, reuse a qualified driver whose completion/quiescence and memory-reachability contracts are already inspected. Identify SRAM/CCM placement, ordering and interrupt assumptions; do not invent a DMA-cancel register recipe from the generic event model.
6. Record which core, debugger, device and physical observations would close the remaining claim. A host race tool or paused core is insufficient. Actual device activity is reported only after measured adapter execution.

## Failure cases

Include completion just before/after timeout, early reclaim, duplicate acknowledgment, late completion after reuse, wrong request/generation and a callback retaining its borrowed pointer beyond return. Reject invalid external protocol states without corrupting current ownership. Physical arbitrary stale writes are unnecessary; use defined reserved storage and qualified instrumentation. Missing physical capability leaves the physical claim open.

## Acceptance and evidence

Provide per-event ownership and completion count, early-reclaim rejection, new-generation protection, reentrant scratch counterexample/repair and callback-borrow tests. Submit an explicit host/core/device evidence matrix and target reachability/order/quiescence obligations. Physical evidence is an optional extension, with no completion claimed from the finite fixture alone.

## Hints and recovery

Separate timeout from cancellation completion. A shared allocator lock protects its metadata, not buffers retained by a peripheral or callback. For callbacks, copying persistent data into owned storage can replace an expired borrow; copying does not establish device quiescence. Revisit selected T21 cancellation and T29 ownership/ordering leaves before using a target adapter.

## Transfer challenge

Reuse the same storage at a new generation and reorder cancel/complete events. Add a reentrant callback with separate scratch. Predict denied and stale events, then prove that the new request's data is unchanged.

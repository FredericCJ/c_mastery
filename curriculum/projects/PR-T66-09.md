# PR-T66-09: Adversarial allocation through the existing typed callback ABI

## Contract

Implement ow_allocator as a V4Allocator adapter over OwAllocator: eight actual int32_t[16] blocks, each admitting a positive requested prefix of1..16. Count every take attempt; fail exactly on a configured1-based attempt or when size/capacity is invalid. Successful take chooses a free block, initializes its requested prefix to INT32_MAX and updates live/peak counts. Release accepts an exact currently live base pointer, fills its requested prefix with INT32_MIN, frees its slot and increments release count. Invalid or duplicate release increments a diagnostic counter without touching storage. Counters never wrap: an exhausted attempt counter refuses allocation and sets a sticky flag; other counters saturate with the flag.

The full required exercise {ref}`X-T66-009`, its shared contracts and objective rubric are part of this project. Eight hours is descriptive author accounting, not a learner-time or scope ceiling.

## Inputs and expected results

Take16 succeeds; fail-at2 makes take1 return null. Live1,peak1,attempts2. Release poisons all16 requested elements, gives live0/releases1; a second release only records an invalid-release event. Starting attempts at SIZE_MAX refuses allocation and leaves it at SIZE_MAX.

## Steps

- **T66.09:** Implement fail-at-N, counting and poisoning as the accepted containers.array allocator callback adapter, preserving typed storage legality and explicit finite-capacity behavior. Submit the exercise D1–D4 and retain prerequisite interfaces.

## Failure cases

Sweep every allocation failure point of frontier and COW workloads, fill all eight slots, test sizes0/16/17 and counter extrema, and verify requested-prefix poison plus release accounting. Compare the imported header byte for byte with the accepted ABI and reject the no-poison mutant. Integrate with the learner dynamic array and T65 error paths, measuring actual calls rather than inferring zero allocation from source spelling.

## Acceptance and evidence

- **T66.09:** Distinguish allocator policy, backing storage, object initialization, protocol invalidation, poison diagnostics and actual memory-safety enforcement; explain instrumentation overflow and observer effects. Every leaf has a separate rubric criterion in X-T66-009. Public test passage alone does not assess independent understanding.

## Hints and recovery

Instrumentation state can overflow too. Then Use real typed backing arrays and compare exact base pointers without unrelated-pointer ordering. Record the failed hypothesis before using further hints.

## Transfer challenge

Wrap a separately supplied upstream allocator while retaining accounting through resize success/failure; specify whether failed upstream calls consume the injection index. Delayed assessment makes an error-formatting callback allocate recursively: detect the hidden allocation and revise the whole-call-graph resource claim.

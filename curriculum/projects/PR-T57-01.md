# PR-T57-01: Failure-safe module initialization

## Contract

Implement kl_unwind for an ownership mask whose bits0,1,2 mean buffer, workqueue and registered endpoint. Return the decimal release trace with resource numbers3,2,1 in reverse order; unknown bits return0. Derive the acquire/fail matrix, then apply it to the supplied teaching module init labels.

## Steps

- **T57.01:** A successful acquisition creates a cleanup obligation even when registration has not reached its final step. Encode ownership independently from the control-flow label so that every acquired resource is released once in reverse dependency order. Returning an error does not undo allocations.
- **T57.01:** Implement kl_unwind for an ownership mask whose bits0,1,2 mean buffer, workqueue and registered endpoint. Return the decimal release trace with resource numbers3,2,1 in reverse order; unknown bits return0. Derive the acquire/fail matrix, then apply it to the supplied teaching module init labels.
- **T57.01:** Show each owned bit has exactly one release and no release precedes its dependents. Relate O(3) model work to the number of real acquisitions, including a failure before endpoint publication.

## Failure cases

Repair forward-order cleanup and double release on a second failure label; a module that returns ENOMEM after leaking work is incorrect even if loading fails.

Retain the first divergent transition and distinguish the cause from a symptom.
The named mutation control must fail for its intended reason; compilation
failure is not a successful mutation kill.

## Contract

Implement a three-resource acquisition transaction with injected failure at every boundary. On failure release exactly acquired resources and leave output unpublished; success transfers all three resources to the declared owner.

Use dependency profile B under {ref}`guide-profiles`. Implement the studied mechanism yourself; a mature library may be a separately declared hosted oracle. This 6-hour milestone includes implementation and verification, with reading/assessment budgeted in the module.

The supplied fixture `fixtures/embedded/PR-T32-04.json` contains concrete inputs and exact expected fields; use the supplied-fixture download below in the local handbook. Failures before acquisitions 0,1,2 produce acquired counts 0,1,2 and zero live resources; successful acquisition retains three for the caller.

Compute each acquisition prefix and subtract declared cleanup; a separate adapter injects short/zero/invalid I/O progress.

## Steps

Label acquisition/ownership transitions, implement reverse cleanup and outcome publication, then inject every failure and partial-progress return. Include a maliciously oversized adapter count before pointer advancement.

First write the public interface, storage/effect limits and expected failure state. Derive at least one supplied value by hand before coding. ## Failure cases

Cleanup of unacquired resource, duplicate release, failed output publication, zero-progress loop and invalid count must be caught.

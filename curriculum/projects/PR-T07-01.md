## Contract

Build a two-translation-unit integer tool from explicit preprocessing, compilation, assembly and link stages. Each artifact has a provenance manifest. Positive, warning and prohibited-build cases have distinct expected outcomes; matching behavior is required, while byte identity is evaluated only under identical declared inputs.

## Steps

1. Write the operation/state/effects contract and predict the fixture result by hand.

2. Establish the smallest supported positive case and record environment/provenance.

- **T07.01:** Stop a two-file example at .i, .s and .o, then reconstruct the final link command.

- **T07.02:** Inventory driver include paths, sysroot, startup objects and target libraries; classify every discovered tool as host or target.

- **T07.03:** Create one positive, one expected-warning and one expected-failure translation unit; justify one narrow suppression.

3. Add boundary and deliberate-failure cases before broadening the implementation.

4. Minimize each disagreement and retain the earliest broken invariant.

## Failure cases

- Challenge the mistaken claim: Compilation success implies link success. Preserve a minimal failing trace or explain the valid precondition that excludes it.

- Challenge the mistaken claim: Changing -march alone creates a correct cross-toolchain. Preserve a minimal failing trace or explain the valid precondition that excludes it.

- Challenge the mistaken claim: Warning-free means defined behavior. Preserve a minimal failing trace or explain the valid precondition that excludes it.

Exercise empty/singleton or zero-progress states where the operation admits them, exact capacity, one beyond capacity, repeated completion/cleanup and a deliberately invalid precondition. For storage-owning work, inject acquisition failures and verify unchanged old ownership. For build/binary/source studies, inject a wrong edge, symbol, width, target assumption or unsupported environment and require a visible failure verdict. Never execute malformed pointers or privileged instructions just to demonstrate a negative case. Apply these cases to the declared operation; document any inapplicable case and its reason.

## Hints and recovery

Retain the preprocessed file before inspecting a missing symbol: if its declaration is absent, the linker cannot repair that earlier failure. Compare the driver’s printed subprocesses with your explicit four commands.

Before changing the target, determine whether the disagreement is its semantics, an invalid test precondition, a boundary mismatch or an environment limitation. If the fixture oracle fails, stop and repair the fixture/oracle independently; do not change expected data to fit the target. Return to the named prerequisite module when ownership, width or ordering assumptions are missing.

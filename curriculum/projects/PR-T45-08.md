# PR-T45-08: Initialization and publication repair

## Contract

Repair a partially initialized record and its consuming branch/output. Storage acquisition and addressability do not initialize the required semantic fields. Explicitly initialize length and mode before publishing the record; failed initialization leaves no published active object. Track field writes and consuming uses separately. Compare semantic fields rather than treating padding or raw whole-struct representation as equality. Use separate native/ASan/UBSan and supported unsanitized Memcheck controls; optional MSan requires supported OS and correctly instrumented dependencies. Detector propagation behavior does not license indeterminate C evaluation.

## Inputs and expected results

The supplied cases write only length, write both length/mode, or mark fully initialized storage inaccessible. Expected verdicts are uninitialized_consumption, ok, unaddressable; publication is permitted only in the middle case. The address contract reports only the inaccessible case. Synthetic representations 0701aaaa and 0701bbbb differ, while semantic fields length 7/mode 1 are equal. This is explicitly supplied byte data, not a real C padding layout or native uninitialized-byte oracle.

The supplied finite fixture is [fixtures/memory_lab/PR-T45-08.json](../../fixtures/memory_lab/PR-T45-08.json). Run `python tools/verify_memory_lab_fixtures.py` from the handbook source root for arithmetic/history/catalog checks. Actual C/tool/hardware evidence remains a separate learner obligation.

## Steps

1. List every required field, acquisition/initialization stage and consuming branch. State typed initialization and publication ownership.
2. Create one own-program uninitialized scalar/field negative under the hosted supervisor; record the earliest missing write and actual consuming-use diagnostic.
3. Repair complete initialization and failure cleanup. Test different initialized fill patterns and acquisition failures without predicting indeterminate values.
4. Compare supported Memcheck reporting with address-only coverage. If using MSan, record all relevant instrumentation/dependency coverage and origin settings; otherwise retain that experiment as unavailable supplemental evidence.
5. Add field-wise equality and explicit initialized serialization; never expose native padding as semantic payload.
6. Run an unseen partial field/failure path and prove no active record or output is published before its contract is met.

## Failure cases

Include a missing field, value propagation to a later branch, partially initialized failure cleanup, inaccessible initialized storage and nonsemantic representation differences. A silent ASan run does not close initialization. calloc zero bytes do not establish every typed object's valid representation. Avoid relying on the exact bit pattern or integer value produced by a faulty indeterminate read.

## Acceptance and evidence

Deliver a write/consume graph, original and repaired observations, exact publication/failure snapshots, field-wise and serialization tests, fill-pattern variation and tool coverage limits. Explain the difference between a detector delaying its report and the C program's legality. A claimed optional MSan result requires a supported actually configured environment.

## Hints and recovery

Initialize the actual typed object and its required members, then publish. Keep diagnostic data in a separately initialized record so reporting does not add another uninitialized use. Return to T03 indeterminate-state and T21 partial initialization when the first missing write is unclear.

## Transfer challenge

Add a pointer-valued field and a new initialization failure between fields. Prove valid typed initialization and cleanup without assuming all-zero bytes represent every pointer or treating padding as data.

# PR-T45-04: Stack capacity, high water and exhaustion experiment

## Contract

Compute a conditional stack bound for the declared single-stack call path, then compare actual compiler frame evidence, changed-pattern scanning and a controlled native exhaustion observation. Distinguish exhausted stack capacity from local-buffer corruption. The native negative runs only in a child with checked limits set/read back before executing the worker: a documented stack limit, core dump limit 0 and finite CPU/wall/input limits. The supervisor collects termination; it does not execute a recovery handler on the exhausted stack. Record the actual limit and environment. A setup failure or deadline kill is a separate verdict. The embedded extension uses the qualified T27/T29/T31 stack adapter after its selected preludes.

## Inputs and expected results

The synthetic frames 32, 48, 64 and two nested contexts 32+48 and 32+40 total 296; reserve 320 leaves 24. Substituting one saved frame 104 yields 368 and margin −48. unknown_dynamic=true makes whole_path_bound null even though these conditional sums are reported. The 64-byte pattern has 32 unchanged bytes; four-byte words give 8 reported free words. Recorded minimum SP offset 16 reserves 48 bytes, exceeding the 32 changed bytes. This is an explicit finite model, not a native or board stack dump.

The supplied finite fixture is [fixtures/memory_lab/PR-T45-04.json](../../fixtures/memory_lab/PR-T45-04.json). Run `python tools/verify_memory_lab_fixtures.py` from the handbook source root for arithmetic/history/catalog checks. Actual C/tool/hardware evidence remains a separate learner obligation.

## Steps

1. State stack direction/interval, ABI, permitted call edges, recursion bound, reentrant callbacks, interrupt nesting and stack selection. Separate MSP/PSP if the actual target uses them.
2. Produce GCC .su reports and inspect generated code. Interpret `static`, bounded dynamic, and unresolved dynamic entries under the actual compiler version; close unknown paths or leave the bound open.
3. Derive the supplied sums independently. Add alignment, helper/logging frames and permitted exception extensions to your actual conditional budget.
4. Run a bounded pattern/lowest-SP observation through the qualified adapter; state how unwritten storage and restored patterns can affect it.
5. In the Linux child compare a bounded native recursion/large-frame exhaustion trial with a separate local-buffer corruption trial. Verify that compilation retained the studied frames/call depth, and record termination without imposing a universal depth or signal fixture.
6. Repair by bounding depth, reducing/replacing excessive automatic storage or using an explicit bounded work structure; rerun the same limits and semantic cases.

## Failure cases

Include an unknown dynamic frame, indirect callee, depth one beyond the supported bound, nested reentrant reporting and extended-frame assumption change. Native recursion has a finite cap and supervisor deadline. Do not lower resource limits in the supervising process or infer stack capacity from an ASan-instrumented image. No corruption or exhaustion need be triggered physically on the board.

## Acceptance and evidence

Submit the conditional path bound with unresolved nodes, .su/compiler/object evidence, pattern versus SP comparison, verified child limit setup, native negative and repaired logs, and a separate corruption diagnosis. A watermark, canary or successful run must not be presented as a universal bound. Demonstrate an unseen permitted nesting path or explain the preserved exclusion.

## Hints and recovery

The Linux process-stack limit is not every thread's stack configuration. Tiny limits can prevent startup rather than exercise your worker; distinguish those cases using a verified entry marker. Optimized-away arrays and tail calls change the experiment. Target frame contributions include configuration-specific saved context, not only declared C locals.

## Transfer challenge

Increase permitted nesting or enable a declared extended frame. Recalculate before execution, reject an inadequate reserve and test the repaired bounded-depth algorithm under the new native limits.

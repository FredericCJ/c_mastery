# PR-T73-05: Supervision trees with restart budgets and ordered quiescence

## Contract

Implement the four-child MsgSupervisor plan generator with ONE/ALL/REST strategies, reverse stop order, forward start order and a sliding-window restart limit1..4. Times are monotonic ticks; reject backwards time. Failure exceeding the budget permanently escalates and stops all children. Execute plans over original MsgActors, waiting for each child to quiesce before restart; inject start failure at every action and specify containment.

The full required exercise {ref}`X-T73-005`, its shared contracts and objective rubric are part of this project. Eight hours is descriptive author accounting, not a learner-time or scope ceiling.

## Inputs and expected results

REST failure at child1 yields[-4,-3,-2,2,3,4]. With limit2/window10, failures at0 and1 restart; failure at2 escalates with[-4,-3,-2,-1]. With limit1/window10, failures at1 and11 are both admitted because the older event is outside the strict window.

## Steps

- **T73.05:** Implement ordered restart plans with bounded timestamp storage and an actor execution adapter that preserves quiescence and accounts for partial restart failure. Submit the exercise D1–D4 and retain prerequisite interfaces.

## Failure cases

Independently enumerate all12 strategy/failed-child selections, test exact window boundary, backwards time, maximum timestamps and escalation permanence. Reject forward-stop and omitted-start mutants. Inject handler and restart failures, compare emitted action order and prove no restarted child observes a dependency that is still stopped.

## Acceptance and evidence

- **T73.05:** Derive restart topology, intensity accounting and the error-kernel boundary; explain why restarting healthy siblings may be necessary and why unlimited restart can amplify faults. Every leaf has a separate rubric criterion in X-T73-005. Public test passage alone does not assess independent understanding.

## Hints and recovery

Stop dependencies in reverse order before starting them forward. Then Budget an event at the window boundary using the stated inequality. Record the failed hypothesis before using further hints.

## Transfer challenge

Replace the flat four-child group with a two-level tree and distinct parent/child budgets. Delayed assessment makes child2 depend on child1 initialization and fail during restart; derive whether to escalate, roll back already restarted children or retain a documented degraded state.

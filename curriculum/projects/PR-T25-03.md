## Contract

Implement a single-owner publication handoff using declared C atomic operations and valid conservative memory-order pairs. Draw sequenced-before/read-from/synchronizes-with edges and include a scripted weak-CAS failure with expected-value updates. Target atomic widths, alignment and helper dependencies are audited; no portable consume/fence shortcut is assumed.

## Failure cases

- Challenge the mistaken claim: No detected data race proves the algorithm is correct. Preserve a minimal failing trace or explain the valid precondition that excludes it.
- Challenge the mistaken claim: Every atomic type is lock-free on every target. Preserve a minimal failing trace or explain the valid precondition that excludes it.
- Challenge the mistaken claim: A larger observed counter automatically orders every associated payload write. Preserve a minimal failing trace or explain the valid precondition that excludes it.
- Challenge the mistaken claim: A failed CAS leaves expected unchanged or transfers the object anyway. Preserve a minimal failing trace or explain the valid precondition that excludes it.

Exercise empty/singleton or zero-progress states where the operation admits them, exact capacity, one beyond capacity, repeated completion/cleanup and a deliberately invalid precondition. For storage-owning work, inject acquisition failures and verify unchanged old ownership. For build/binary/source studies, inject a wrong edge, symbol, width, target assumption or unsupported environment and require a visible failure verdict. Never execute malformed pointers or privileged instructions just to demonstrate a negative case. Apply these cases to the declared operation; document any inapplicable case and its reason.

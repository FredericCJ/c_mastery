# PR-T71-07: Memory behavior trees, running-child ownership and abort

## Contract

Implement bounded validated node traversal, per-composite cursors, running-leaf ownership bits and exactly-once abort on cancellation, with a callback-reentry guard. The full required specification is {ref}`X-T71-007` and its explicit shared contract. Twelve hours is descriptive author accounting, never a ceiling.

## Inputs and expected results

A sequence with successful leaf1 and running leaf2 calls leaf1 once across two ticks, leaf2 twice, and aborts leaf2 exactly once on cancel.

## Steps

- **T71.07:** Complete D1–D4, the named public anchor, independent falsification and changed-contract implementation.

## Failure cases

Use a leaf trace where the first child succeeds and the second remains RUNNING over repeated ticks; verify the first effect is not repeated. Check invalid topology, nested sequence/selector, reentry and cancellation twice. Reject cursor-reset and omitted-abort mutants.

## Acceptance and evidence

- **T71.07:** Satisfy all four leaf rubrics and source-bound verification; passing supplied tests alone is insufficient.

## Hints and recovery

Store the continuation of each composite node. Running means an outstanding action, not failure. Repeated cancellation must not repeat a destructor-like abort.

## Transfer challenge

Introduce a reactive safety guard that can invalidate a running action. Specify which subtree is aborted before reevaluation, which completed effects cannot be undone, and whether callback failure provides strong or basic recovery; delayed assessment adds shared subtrees and forces a new ownership representation.

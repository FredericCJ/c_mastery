# PR-T71-04: Hierarchical run-to-completion transitions and observable entry order

## Contract

Implement pt_dispatch with inner-first exits, outer-first entries, a nonreentry guard, and transactional trace-capacity failure. Produce a table-driven independent transition oracle. The full required specification is {ref}`X-T71-004` and its explicit shared contract. Twelve hours is descriptive author accounting, never a ceiling.

## Inputs and expected results

OFFLINE CONNECT emits exit OFFLINE, entry ONLINE, entry IDLE. `BUSY` START emits exit `BUSY` then entry `BUSY`. `BUSY` FAIL exits `BUSY` and ONLINE before entering FAULT.

## Steps

- **T71.04:** Complete D1–D4, the named public anchor, independent falsification and changed-contract implementation.

## Failure cases

Check every active leaf/event pair, insufficient trace capacity, repeated `BUSY` START and PING exhaustion. Reject reversed-entry and omitted-exit mutants; compare exact action sequences rather than final states alone.

## Acceptance and evidence

- **T71.04:** Satisfy all four leaf rubrics and source-bound verification; passing supplied tests alone is insufficient.

## Hints and recovery

Draw the ancestor chain on both sides. Self transitions need a declared external/internal distinction. A correct final state can hide a wrong cleanup/action order.

## Transfer challenge

Add an entry action that posts another event and a guard on the parent transition. Queue the posted event until the current run-to-completion step ends and define guard fallback; the delayed variant introduces a local transition that intentionally preserves a composite state.

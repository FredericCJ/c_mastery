# PR-T06-03: Validated configuration and schema generator

## Contract

Write a small external generator for a protocol-field schema and a build configuration identity. Generated C constants belong to a no-library component; the generator itself may use Python. Reject overlapping fields, duplicate names and incompatible feature combinations. Deterministic output must depend only on declared inputs, not current working directory or wall-clock time.

The declared profile **C** applies to the boundary named here; specify harness versus component dependencies in {ref}`guide-profiles`. Budget 8 h for implementation and verification together. Start from your own sources and the listed fixtures, with prior modules as prerequisites; no starter repository or solved program is required.

## Inputs and expected results

The fixture schema has fields tag bits [0,3), length [3,8) and flags [8,10), with enabled features crc and framed. Its expected masks are 7, 248 and 768; the declared forbidden pair raw+framed is absent. Canonical configuration names are sorted as [crc,framed].

## Failure cases

Failure produces no partly valid public artifact. Reject field widths/counts before shifts. Make generated-input dependencies visible to the build; a changed schema must trigger regeneration. Do not put local acquisition paths into public artifacts.

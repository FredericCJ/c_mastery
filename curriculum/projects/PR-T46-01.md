# PR-T46-01: Values and a portable bytecode image

## Contract

The first deliverable is a portable program image and value contract. Write the magic, function descriptors and code bytes individually; a C structure dump would inherit host padding and byte order. Decode a negative int32 via its mathematical unsigned representation before converting a representable result. Implement `cvm_encode` and `cvm_decode` for the bounded container first: check count, region lengths, contiguous descriptors and arity/local bounds, then publish the complete output. These raw codec functions deliberately do not accept instructions for execution. An unknown opcode can round-trip as bytes; the next checkpoint rejects it through the instruction verifier. Keep every output byte and reported length unchanged on failure. Value tags belong to the educational language: Boolean true is not an integer accepted by addition. Object references carry a slot and generation rather than exposing a native address.

This 6-hour implementation/verification milestone starts the runtime sequence; reuse earlier C ownership, arithmetic, parser and testing components. Its CTest names are `runtime.wire`. These finite gates cover named anchors, not every objective. The Thumb command is separate where assigned. Deferred cumulative tests `runtime.portability`, `runtime.integration` require later mechanisms and are not prerequisites for this checkpoint.

## Steps

Hand-encode the bytes for a program returning 42, round-trip them without running the VM, then encode the INT32_MIN immediate as 00 00 00 80. Predict every truncation verdict. Keep a canary program as the destination and prove rejection does not publish a partially decoded image.

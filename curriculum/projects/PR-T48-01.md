# PR-T48-01: Boot contracts and the long-mode transition

## Contract

GRUB supplies a 32-bit protected-mode entry, not a ready C environment. Preserve EAX/EBX, make the initial stack and page tables, load a GDT, enable PAE and long mode, then enter the 64-bit code segment. Our four-GiB supervisor identity map uses 2048 two-MiB entries; it includes the fixed PC MMIO window without exposing it to user mode.

This 8-hour milestone includes implementation and verification. Reading, assessment and delayed retrieval are in the module budget. Reuse accepted prerequisites; implement the studied mechanism in the learner workspace.

## Inputs and expected results

Use `fixtures/kernel/PR-T48-01.json` for the declared finite calculation and `labs/kernel` for actual C/guest controls. Static arithmetic does not close the executable gate. The relevant CTest names are `kernel_boot_smoke`. For early projects 03–10, a full kernel_guest run is a later cumulative regression: the immediate component dossier must include the project-local trace specified below; the full run cannot be claimed until its later dependencies exist. The first project uses only kernel_boot_smoke and stops after the actual C-entry serial marker. Cross-family projects explicitly enable the original runtime/store source paths; a standalone kernel pass is insufficient.

## Steps

Write the Multiboot2 header, original transition assembly and link layout. Inspect entry address, header checksum and map before stepping the transition. Audit undefined symbols and distinguish bootloader service from learner-owned entry code.

Keep the contract, pre-run prediction, exact image/build identity, raw observation and first invalid transition. Reveal hints in `labs/kernel/HINTS.md` in stages. The default stubs compile but fail; selecting an assessor solution changes the evidence category.

## Failure cases

Wrong header checksum, lost EBX, malformed CR3 alignment, absent far jump, wrong C stack alignment and accidentally linked hosted startup.

## Acceptance and evidence

Boot the selected QEMU guest to the first serial marker and retain disassembly, register trace and ELF/map identities. Explain every supplied and owned operation.

- **T48.01.a**: Derive the machine-state and memory contract between GRUB, transition assembly and C.
- **T48.01.b**: Build and execute an original protected-to-long-mode transition with a correctly linked freestanding image.
- **T48.01.c**: Diagnose a deliberately broken entry/mapping assumption from the first supported machine-state divergence.

Map each objective to a concrete file/observation, retain negative controls and state unresolved claims. Refer to {ref}`guide-assessment` for rubric and causal repair.

## Hints and recovery

Start with a hosted checked boundary whenever possible, then cross the actual machine boundary. A publication or model verifier is not a substitute for the named boot, privilege, queue or reboot observation. Reduce one failed boundary before editing unrelated mechanisms.

## Transfer challenge

Move the kernel physical load address while preserving the boot/header and mapping relations. Attempt after at least seven days, with a reviewer-held variant when available.

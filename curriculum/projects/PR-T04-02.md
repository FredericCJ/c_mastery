# PR-T04-02: Bit operations and explicit wire layout

## Contract

Implement unsigned field extraction/insertion, rotation, population count and bit width for a declared 16-bit logical word, plus a network-order 32-bit codec. All access is through caller storage and explicit values. Compare one compiler bit-field layout as a target-specific observation; do not use it as the wire contract or as proof of hardware access semantics.

The declared profile **C** applies to the boundary named here; specify harness versus component dependencies in {ref}`guide-profiles`. Budget 8 h for implementation and verification together. Start from your own sources and the listed fixtures, with prior modules as prerequisites; no starter repository or solved program is required.

## Inputs and expected results

The fixture has word 0x1234, rotate count 4 and wire value 0x12345678. Expected rotation is 0x2341, population count 5, bit width 13 and wire octets [18,52,86,120]. The codec requires CHAR_BIT == 8 or a documented octet adaptation.

Validate widths and counts before shifts. Handle rotation by zero without shifting by the width. Test every input for a smaller width, then selected boundaries at 16/32 bits. Decode from deliberately unaligned byte positions without casts. Record actual bit-field sizeof and bytes under named ABI/compiler settings.

## Failure cases

## Acceptance and evidence

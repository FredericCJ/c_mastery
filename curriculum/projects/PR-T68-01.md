# PR-T68-01: Template-header monomorphization and associated types

## Contract

Implement one unguarded private ring template instantiated for uint32_t and MPPair. Public MPU32Ring/MPPairRing each hold4elements,head,count. Push fails unchanged when full; pop fails without modifying output when empty. FIFO order must survive wraparound. Prefix, element type and ring type are explicit template parameters; undefine all private macros after each inclusion. Reuse the containers.ring contract but implement the type-generation mechanism yourself.

The full required exercise {ref}`X-T68-001`, its shared contracts and objective rubric are part of this project. Eight hours is descriptive author accounting, not a learner-time or scope ceiling.

## Inputs and expected results

Push0..3, pop0, push4, then pop1..4. Both scalar and pair instances preserve every semantic field. Full/empty operations leave their designated output/control state unchanged.

## Steps

- **T68.01:** Derive head<capacity and count<=capacity invariants, occupied logical slots and output ownership. Compare generated specialization with Rust generic/associated-type obligations and show a mismatched ring/element instantiation diagnosed by C. Explain why a template include guard would silently suppress the second instantiation and why internal macro names can collide. Submit the exercise D1–D4 and retain prerequisite interfaces.

## Failure cases

Run metaprog.mono and inspect preprocessed two-instance source. Kill incorrect-tail-index and stationary-head mutants. Compile and link two translation units using declarations to detect accidental multiple definitions; record generated symbol count and text size separately from handwritten equivalents under the same capacity/failure contract.

## Acceptance and evidence

- **T68.01:** Explain how repeated template-header inclusion generates distinct typed functions, how associated element/ring types must agree, and why token substitution has no trait-implementation proof or automatic instantiation isolation. Every leaf has a separate rubric criterion in X-T68-001. Public test passage alone does not assess independent understanding.

## Hints and recovery

Start with the invariant of one handwritten ring. Then Expand both instances and inspect the resulting identifiers. Record the failed hypothesis before using further hints.

## Transfer challenge

Instantiate a ring of owning objects with fallible clone/drop callbacks. Derive rollback on failed push and destruction order on clear; compare monomorphized and erased implementations with equal semantics and measured code growth.

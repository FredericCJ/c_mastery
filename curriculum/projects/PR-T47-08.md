# PR-T47-08: Checkpoint generations and reclamation

## Contract

Implement alternating checksummed checkpoint generations and highest-valid selection, with no wraparound. Enumerate crash cuts in checkpoint I/O. Require the acknowledged new state after every recovery. Keep both generations visible in the evidence dossier and explain why an older valid generation can still be usable with the next committed WAL.

Budget 5 implementation and 3 verification hours. Reuse the same engine throughout; previous milestones are not charged again. The public API and original disk format are in the storage laboratory.

Use [the contract fixture](../../fixtures/storage/PR-T47-08.json) and the actual C tests `storage.checkpoint_order`. The image has 67 pages of 4096 bytes; the tree owns 32 logical data pages. The reference transaction changes the complete map from {1:10,2:20} to {1:11,3:30}. Compare whole maps. No fixture asserts physical power-cut durability.

## Hints and recovery

Checkpoint moves already committed state; it does not decide whether a transaction committed. Validate the complete redo batch before changing home pages, copy and flush all home images, write and flush the alternate generation record, then invalidate and flush the log marker. The old generation survives a torn replacement; retained WAL repairs incomplete home writes. Reclaiming the log earlier destroys the only complete explanation of a mixed home image. Two slots are sufficient for this serialized bounded design, not a general concurrent checkpoint algorithm.

The staged laboratory hints separate invariant, observation and repair direction. Keep the original failing image or key sequence and compare it with a clean control.

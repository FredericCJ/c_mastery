## Contract

Specify a minimal environment service table for output, storage and entry state. Implement caller-backed storage and a deterministic refusal of unsupported heap/stream services. Compare semihosted test transport with standalone execution requirements without claiming hardware completion from a simulated backend.

## Inputs and expected results

Load [`fixtures/systems/PR-T11-04.json`](../../fixtures/systems/PR-T11-04.json). Its `input` and `expected` define an exact synthetic case, not an observation from a real compiler, filesystem, board or concurrent run. Run `python tools/verify_systems_fixtures.py` from the curriculum root to recompute all declared fields. Keep input immutable for the reference comparison; store observed outputs separately. The fixture is one anchor, not exhaustive acceptance coverage.

## Steps

1. Write the operation/state/effects contract and predict the fixture result by hand.
2. Establish the smallest supported positive case and record environment/provenance.

- **T11.07:** Specify a small service adapter with a refusing heap policy and a transport stub; classify debugger-dependent paths.
- **T11.08:** Write a platform entry checklist and test the component with one intentionally uninitialized service excluded.

3. Add boundary and deliberate-failure cases before broadening the implementation.
4. Minimize each disagreement and retain the earliest broken invariant.

## Failure cases

- Challenge the mistaken claim: Successful output under a debugger proves the board can print independently. Preserve a minimal failing trace or explain the valid precondition that excludes it.
- Challenge the mistaken claim: Link success establishes a valid runtime entry state. Preserve a minimal failing trace or explain the valid precondition that excludes it.

Exercise empty/singleton or zero-progress states where the operation admits them, exact capacity, one beyond capacity, repeated completion/cleanup and a deliberately invalid precondition. For storage-owning work, inject acquisition failures and verify unchanged old ownership. For build/binary/source studies, inject a wrong edge, symbol, width, target assumption or unsupported environment and require a visible failure verdict. Never execute malformed pointers or privileged instructions just to demonstrate a negative case. Apply these cases to the declared operation; document any inapplicable case and its reason.

## Hints and recovery

Return a deterministic unsupported-service status through the adapter. A hosted transport that supplies storage/output is an explicit test environment, not evidence that the standalone target supplies it.

Before changing the target, determine whether the disagreement is its semantics, an invalid test precondition, a boundary mismatch or an environment limitation. If the fixture oracle fails, stop and repair the fixture/oracle independently; do not change expected data to fit the target. Return to the named prerequisite module when ownership, width or ordering assumptions are missing.

## Contract

Implement checked Ethernet II demultiplexing and the exact one-peer Ethernet/IPv4 ARP service. DA/SA are six octets, type is big-endian; allow local unicast and ARP broadcast, types 0x0800/0x0806. VLAN, foreign destination and unsupported type drop/counter. Hardware filtering does not remove software validation obligations.

ARP payload is 28 octets with htype 1, ptype 0x0800, hlen 6, plen 4, opcode 1/2. Require sender hardware address equals enclosing Ethernet SA and learn only configured peer 192.0.2.1. Cache expires after 30 s, holds one peer and at most one queued datagram. Requests occur at 0, 1000, 2000 ms; unresolved failure releases the pending datagram at 3000 ms.

## Inputs and expected results

The supplied fixture reconstructs exact ARP request/reply wire bytes, checks a sender-MAC mismatch, and derives cache validity at 29999 ms versus expiry at 30000 ms, request times and bounded failure cleanup. Its fixed peer/local MACs are 02:00:00:00:00:01 and 02:00:00:00:00:02. This finite serialization/cache oracle is not an Ethernet/ARP receive parser.

Create mandatory learner receive cases for wrong configured peer IP, htype/ptype/hlen/plen/opcode, truncated or inconsistent enclosing length, VLAN and foreign destination. Recompute each nested span before accessing it and assert no cache mutation or upper delivery on rejection.

Output parsed frame kind, cache publication/expiry, queued datagram outcome and exact reply bytes. Ethernet padding is ignored using ARP's declared fixed payload length; it is not extra ARP data.

## Steps

1. Parse enclosing 14-byte header before demultiplexing, then validate ARP field lengths before addresses.

2. Build exact broadcast request and local reply from field serialization, never native struct layout.

3. Implement one-entry cache, monotonic expiry and one queued datagram with BUSY on an additional submit.

4. Inject forged SA/sha, delayed reply, expiry and unresolved retry trace; check no invalid learn or silent queue overwrite.

5. Observe actual peer MAC on the isolated cable and capture request/reply; replace fixture-only peer identity in the lab record, not the supplied fixture.

## Failure cases

Foreign destination, unsupported type/VLAN, short frame, invalid ARP types/lengths/opcode, sender mismatch and nonpeer source cannot update cache. Expired association cannot send a queued packet without renewed resolution. A second queued datagram returns BUSY and remains caller-owned. ARP is unauthenticated; a valid association does not prove peer application identity.

## Acceptance and evidence

Submit exact request/reply wire bytes, validation/drop matrix, timed cache/retry/queue logs and independent actual ARP capture. The objectives require field validation, bounded neighbor state and spoof/foreign/stale/unresolved outcomes. Show queue release on failure and distinguish Ethernet DA from IPv4 destination. Keep the original controlled-subset limits visible.

## Hints and recovery

If a reply parses but the next TCP frame goes elsewhere, compare Ethernet SA with ARP sender before cache write. If expiry depends on traffic count, use the injected monotonic clock. Do not solve unresolved peer by adding a broadcast TCP send.

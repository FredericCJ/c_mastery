# PR-T48-13: VM, durable store and kernel reboot integration

## Contract

The store owns B+tree pages, WAL and recovery; the kernel owns the block transfer/flush service. An exclusive adapter maps the 67-page store image to raw pages starting at 16. VM bytecode may request named store services but cannot choose a device page or kernel pointer.

This 12-hour milestone includes implementation and verification. Reading, assessment and delayed retrieval are in the module budget. Reuse accepted prerequisites; implement the studied mechanism in the learner workspace.

Use `fixtures/kernel/PR-T48-13.json` for the declared finite calculation and `labs/kernel` for actual C/guest controls. Static arithmetic does not close the executable gate. ## Steps

Link T46/T47 cores in init with caller-owned static workspace. Execute bytecode that commits value 42, deliberately lose the callback success reply, restart the guest on the same disk, recover and read the value through bytecode.

Keep the contract, pre-run prediction, exact image/build identity, raw observation and first invalid transition. Reveal hints in `labs/kernel/HINTS.md` in stages. The default stubs compile but fail; selecting an assessor solution changes the evidence category.

## Failure cases

Double-charged copied implementation, write without flush, bytecode raw-device access, unknown transaction outcome treated as definitely absent, wrong store-slice arithmetic and stack exhaustion from nested workspace.

## Acceptance and evidence

Preserve first-boot CVM_HOST_ERROR after the known committed callback, second-boot VM GET42, WAL recovery/store-check evidence and actual syscall/virtio image identities. This is a lost-reply experiment, separate from the store simulator crash matrix.

- **T48.13.a**: Compose runtime, transaction and block interfaces without bypassing ownership layers.
- **T48.13.b**: Execute bytecode-to-durable-storage and reboot recovery on the original OS.
- **T48.13.c**: Explain lost-response ambiguity without equating a reported error to absence of commit.

Map each objective to a concrete file/observation, retain negative controls and state unresolved claims. Refer to {ref}`guide-assessment` for rubric and causal repair.

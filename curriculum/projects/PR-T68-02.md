# PR-T68-02: Constraint probes and constant storage parameters

## Contract

Implement mp_storage_bound(count,width,limit,out): positive count/width, multiplication representable in size_t, and product<=limit. Fail without output changes. Create positive/negative translation units using _Static_assert for compile-time capacity and type compatibility, with array extents derived from constant parameters. A runtime input must use the checked function rather than a false compile-time guarantee.

The full required exercise {ref}`X-T68-002`, its shared contracts and objective rubric are part of this project. Eight hours is descriptive author accounting, not a learner-time or scope ceiling.

## Inputs and expected results

count4,width8,limit32 yields32;limit31fails. SIZE_MAX*2 fails before overflow; count0 or width0 is outside this storage contract.

## Steps

- **T68.02:** Derive count<=SIZE_MAX/width before multiplication and the independent budget bound. Explain why C17 _Static_assert requires an integer constant expression, VLA support differs from fixed arrays, and syntactically valid macros do not impose an abstract trait. Compare the inspected Rust const-generic type/use restrictions without claiming arbitrary compile-time evaluation equivalence. Submit the exercise D1–D4 and retain prerequisite interfaces.

## Failure cases

Run metaprog.constraints and compile the negative constraint probes expecting a named diagnostic, not a link failure. Kill multiplication-overflow omission and storage-budget omission independently. Test size_t-width changes analytically and inspect whether published C23 wording is available before attributing a C2x compiler behavior to the standard.

## Acceptance and evidence

- **T68.02:** Separate a required C constraint diagnostic, a chosen -Werror rejection, and a runtime range guard; show which properties constant-size generic storage can check before execution. Every leaf has a separate rubric criterion in X-T68-002. Public test passage alone does not assess independent understanding.

## Hints and recovery

Write the arithmetic predicate without performing the product. Then A storage budget can fail even when arithmetic is representable. Record the failed hypothesis before using further hints.

## Transfer challenge

Support a compile-time power-of-two ring capacity and a runtime fallback. Derive which optimization can use masking, reject an invalid constant capacity, and ensure a nonconstant caller cannot bypass runtime validation.

# PR-T73-07: TL2-style software transactions over actual C17 atomics

## Contract

Implement the four-cell MsgStore/MsgTxn contract with atomic unsigned payload, version/lock stamps and global timestamp. Begin captures a snapshot; reads validate before returning; writes buffer locally. Commit tries write locks in index order, reserves a nonwrapping timestamp, validates reads, writes values and releases versions. Conflict or clock exhaustion restores acquired locks and publishes no buffered values. No speculative I/O or allocation side effect is admitted without a separate undo/commit mechanism.

The full required exercise {ref}`X-T73-007`, its shared contracts and objective rubric are part of this project. Eight hours is descriptive author accounting, not a learner-time or scope ceiling.

## Inputs and expected results

TransactionA starts, B writes cell0=7 and commits: A reading cell0 returns `CONFLICT` without changing output99. If A reads7 before B commits8, then stages cell1=9, A commit conflicts and cell1 remains0 with its lock clear. Two concurrent increment transactions over two equal cells produce2000 committed increments and never expose unequal admitted reads.

## Steps

- **T73.07:** Implement bounded read/write sets, read-your-writes, nonblocking lock acquisition and validated commit using the declared sequentially consistent baseline; prove failed commits leave payload unchanged while allowing timestamp gaps. Submit the exercise D1–D4 and retain prerequisite interfaces.

## Failure cases

Force conflict before a read, after a read and during partial lock acquisition; test repeated writes, empty/read-only transactions and timestamp exhaustion. Reject missing read validation and missing commit validation mutants. Use an independent serial-history model for small schedules, TSan for actual threads and fault hooks for every commit phase. Explain why atomic individual loads alone do not provide a coherent transaction.

## Acceptance and evidence

- **T73.07:** Derive snapshot validation, write-set locking, abort restoration and the distinction between transaction isolation, atomic C accesses and memory reclamation; explain inconsistent-read hazards before commit. Every leaf has a separate rubric criterion in X-T73-007. Public test passage alone does not assess independent understanding.

## Hints and recovery

Validation after commit is too late if an inconsistent read already caused an invalid operation. Then A failed lock acquisition must restore every earlier lock. Record the failed hypothesis before using further hints.

## Transfer challenge

Introduce a retryable callback with a synthetic log effect: stage it for commit or supply compensation rather than replaying it blindly. Delayed assessment allows dynamically allocated nodes and privatization; show why the fixed-cell proof says nothing about reclaimed node lifetime and design a compatible reclamation protocol.

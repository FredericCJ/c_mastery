# PR-T74-08: Handle-based compaction and forwarding aliases

## Contract

Implement stable physical packing of live payloads with old-slot forwarding and updating every handle alias, then add a pinned-object alternative with explicit fragmentation costs and a generation policy for reused handles. The full required specification is {ref}`X-T74-008` and its explicit shared contract. Twelve hours is descriptive author accounting, never a ceiling.

## Inputs and expected results

Live physical slots2 and4 compact to1 and2. Two handles to slot2 both become1; a handle to4 becomes2, while payload fields naming handle3 retain that identity. Any outstanding borrow rejects unchanged.

## Steps

- **T74.08:** Complete D1–D4, the named public anchor, independent falsification and changed-contract implementation.

## Failure cases

Enumerate all small live masks and compare payload identity through handles before and after movement. Test holes, aliases, cycles through handles, empty/full heaps, and borrow rejection; reject omitted-handle-rewrite and ignored-borrow mutants.

## Acceptance and evidence

- **T74.08:** Satisfy all four leaf rubrics and source-bound verification; passing supplied tests alone is insufficient.

## Hints and recovery

An internal link can name a handle instead of a physical address. Update every alias, not only the first handle found. A borrow remains dangerous even if the current test never dereferences it after moving.

## Transfer challenge

Integrate a pool allocator and a foreign-function API that temporarily exposes raw pointers. Design pin/unpin lifetime and cancellation cleanup, and measure the tradeoff against copying handles. Delayed assessment allows handle-slot reuse with a stale external reference.

# PR-T57-05: Work cancellation and terminal ownership

## Contract

Implement kl_work for serialized state {queued,running,closed,released}. Events0 submit,1 begin,2 complete,3 close,4 release. Admission fails when closed or occupied; begin transfers queued to running; complete requires running; close is idempotent; release succeeds only once when closed and neither queued nor running. Rejected events preserve state.

## Steps

- **T57.05:** Cancellation is a request to prevent or stop future work, not permission to free storage while a worker can still access it. Teardown closes admission first, then drains or cancels work and only then releases its owner.
- **T57.05:** Implement kl_work for serialized state {queued,running,closed,released}. Events0 submit,1 begin,2 complete,3 close,4 release. Admission fails when closed or occupied; begin transfers queued to running; complete requires running; close is idempotent; release succeeds only once when closed and neither queued nor running. Rejected events preserve state.
- **T57.05:** Prove release implies quiescence and closed admission. Compare cancellation return values with work ownership; do not hold a lock required by the worker while synchronously draining it.

## Failure cases

A faulty release ignores running work after close; the sentinel release flag demonstrates premature destruction. A deadlock also occurs if teardown waits while holding the worker lock.

Retain the first divergent transition and distinguish the cause from a symptom.
The named mutation control must fail for its intended reason; compilation
failure is not a successful mutation kill.

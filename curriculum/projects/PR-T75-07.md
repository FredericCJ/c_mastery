# PR-T75-07: Hedged responses and ownership of losing work

## Contract

Implement RZHedge for original attempt0 and one delayed attempt1. Choose the first acceptable response before the shared deadline, request cancellation of outstanding attempts, and track their actual terminal completions separately. Expose result availability independently from quiescence. Add a completion arbiter with two concurrent workers in the dedicated local harness, each retaining its own response storage, and integrate deduplicated effects when both attempts reach the receiver.

The full required exercise is {ref}`X-T75-007`; its shared contracts, D1–D4, objective-specific rubric and delayed variant are part of this project. Eight hours is descriptive accounting, not a ceiling on required work.

## Inputs and expected results

A rejected response7 at1 does not win. Start the hedge at2; acceptable8 at3 wins. If original0 remains outstanding, result8 is available but quiescent is false and cancel_requested includes0. Its later response7 cannot replace8; only its completion makes the operation reclaimable.

## Steps

- **T75.07:** Implement exactly one winner and separately owned attempt lifetimes, with expiry, late response, repeated completion and unstarted-attempt rejection. Complete every exercise deliverable, including separately specified extensions.

## Failure cases

Returning a fast answer does not reclaim the slow attempt. Treating cancellation as completion creates lifetime defects, while treating any response as a winner can return a quick error instead of a valid result. Enumerate started/completed masks, both acceptable bits, completion orders and deadline equality. Assert first acceptable value stability and that quiescence means every started attempt terminated. Count active permits until loser acknowledgement. The public model is serialized; concurrent correctness requires the submitted arbiter and its synchronization proof, not merely passing this model.

## Hints and recovery

Keep started, completed and cancellation-requested as different sets. A response can be complete yet unacceptable. A single-winner CAS does not automatically manage each losing buffer.

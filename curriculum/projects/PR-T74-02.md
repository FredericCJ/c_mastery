# PR-T74-02: Owned binary interning and collision-safe symbol identity

## Contract

Implement the eight-entry copied-string table with first-insertion IDs and atomic admission failure, then implement a hashed table with explicit collision chains or probing and transactional resizing; compare both on the same byte-string contract. The full required specification is {ref}`X-T74-002` and its explicit shared contract. Twelve hours is descriptive author accounting, never a ceiling.

## Inputs and expected results

Bytes00,01 intern asID1 and00,02 asID2; a repeat00,01 returnsID1 even with failure injected. A new string under failure leaves used and output unchanged. NULL with length0 interns the empty string.

## Steps

- **T74.02:** Complete D1–D4, the named public anchor, independent falsification and changed-contract implementation.

## Failure cases

Generate binary strings including empty, embedded NUL and equal-length different bytes. Inject failure on hits and misses, exhaust capacity and preserve output/state snapshots. Reject length-only equality and ignored-admission-failure mutants; use a Python dictionary as an independent identity oracle.

## Acceptance and evidence

- **T74.02:** Satisfy all four leaf rubrics and source-bound verification; passing supplied tests alone is insufficient.

## Hints and recovery

Length is part of equality, not all of equality. Check for a hit before allocating or rejecting capacity. An intern table owns retention unless a weak contract explicitly says otherwise.

## Transfer challenge

Replace strong retention with weak interning linked to collector epochs, defining when IDs retire and whether reinterned bytes regain the same identity. Delayed assessment retains a symbol across a moving collection and forces an allocation failure during rehash.

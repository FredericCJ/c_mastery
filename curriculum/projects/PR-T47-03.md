# PR-T47-03: B+tree lookup and ordered scan

## Contract

Implement lookup and lower-bound scan with a callback that may request a normal early stop. Empty, missing, exact separator, between-key and prefix-key probes are distinct cases. Return NOT_FOUND without changing the caller value or length; return FULL for insufficient capacity. Compare all 92 inserted records and the complete ordered scan.

Budget 5 implementation and 3 verification hours. Reuse the same engine throughout; previous milestones are not charged again. The public API and original disk format are in the storage laboratory.

## Inputs and expected results

Use [the contract fixture](../../fixtures/storage/PR-T47-03.json) and the actual C tests `storage.lookup`. The image has 67 pages of 4096 bytes; the tree owns 32 logical data pages. The reference transaction changes the complete map from {1:10,2:20} to {1:11,3:30}. Compare whole maps. No fixture asserts physical power-cut durability.

## Progressive execution

The immediate learner gate is `storage.lookup`. Early tests inject declared valid component states; they do not require a completed opener, recovery engine or later mutation API. Defer `storage.tree`, `storage.differential` until PR-T47-09/10 integrates opening, durable publication and recovery. Passes cover their finite mechanism only; retain the separate invariant, failure and transfer evidence.

## Steps

1. Predict the state transitions on paper, naming capacities, ownership and the earliest invalid state.
2. Implement this milestone in your external learner workspace; reveal only the next relevant stage of the hint table when blocked.
3. Run the named positive and negative C cases and preserve exact commands, source identity, seed/cut and return codes.
4. Explain one rejected result using the invariant, then repair and rerun the same trigger.
5. Revisit an unfamiliar variation without hints and record separate evidence for T47.03.a, .b and .c.

## Failure cases

Change equality to descend left; the supplied compiled mutation must fail. Introduce a leaf-link cycle in a disposable image and reject it without an unbounded traversal.

An unavailable compiler, sanitizer runtime, syscall or device produces unavailable evidence; it never counts as a clean run. A wrong implementation must fail a semantic assertion after successful setup.

## Acceptance and evidence

Deliver the invariant/cost argument for .a, actual C/build/test transcript for .b, and minimized failure plus repaired and delayed transfer results for .c. Include the exact source-reading locator and fault assumptions. A CTest family pass supports its executed cases, not automatic completion of every objective. Use `tools/verify_storage_fixtures.py` for contract-index consistency; it neither compiles your C nor awards runtime mastery.

## Hints and recovery

All values reside in leaves. Internal separator i duplicates the smallest key in child i+1, so equality descends to the right child. Keys are length-delimited unsigned bytes: embedded zeros are ordinary data and shorter equal prefixes sort first. Tree descent and linked-leaf traversal are two independently checkable descriptions of the same ordered records. A cycle, dangling page or unreachable allocated node violates the representation even when one lookup succeeds. Bound descent and scan steps by the finite page count before following disk references.

The staged laboratory hints separate invariant, observation and repair direction. Keep the original failing image or key sequence and compare it with a clean control.

## Transfer challenge

Add a lower-bound key that is an exact prefix of two stored binary keys and predict the first emitted record.

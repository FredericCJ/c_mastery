## Contract

Pin one tiny dependency by source revision and integrity identifier. Demonstrate a clean offline build from a declared input cache and a controlled missing-input failure. Register semantic, negative-build and target-only tests; preserve a deliberately failing binary and complete reproduction manifest.

## Inputs and expected results

Load [`fixtures/systems/PR-T07-05.json`](../../fixtures/systems/PR-T07-05.json). Its `input` and `expected` define an exact synthetic case, not an observation from a real compiler, filesystem, board or concurrent run. Run `python tools/verify_systems_fixtures.py` from the curriculum root to recompute all declared fields. Keep input immutable for the reference comparison; store observed outputs separately. The fixture is one anchor, not exhaustive acceptance coverage.

## Steps

1. Write the operation/state/effects contract and predict the fixture result by hand.
2. Establish the smallest supported positive case and record environment/provenance.

- **T07.10:** Compare system, vendored and fetched acquisition of one tiny dependency; demonstrate an offline build.
- **T07.11:** Register semantic, expected-failure and target-only tests with explicit skip reasons.

3. Add boundary and deliberate-failure cases before broadening the implementation.
4. Minimize each disagreement and retain the earliest broken invariant.

## Failure cases

- Challenge the mistaken claim: A branch name is an integrity identifier. Preserve a minimal failing trace or explain the valid precondition that excludes it.
- Challenge the mistaken claim: A skipped on-target test is a successful hardware result. Preserve a minimal failing trace or explain the valid precondition that excludes it.

Exercise empty/singleton or zero-progress states where the operation admits them, exact capacity, one beyond capacity, repeated completion/cleanup and a deliberately invalid precondition. For storage-owning work, inject acquisition failures and verify unchanged old ownership. For build/binary/source studies, inject a wrong edge, symbol, width, target assumption or unsupported environment and require a visible failure verdict. Never execute malformed pointers or privileged instructions just to demonstrate a negative case. Apply these cases to the declared operation; document any inapplicable case and its reason.

## Hints and recovery

Build with the network unavailable only after recording every input in the cache. A missing dependency should fail at acquisition with its identity, rather than silently falling back to another system installation.

Before changing the target, determine whether the disagreement is its semantics, an invalid test precondition, a boundary mismatch or an environment limitation. If the fixture oracle fails, stop and repair the fixture/oracle independently; do not change expected data to fit the target. Return to the named prerequisite module when ownership, width or ordering assumptions are missing.

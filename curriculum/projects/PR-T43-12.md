## Contract

Complete a scoped Cortex-M DWT arithmetic/access dossier. The core route analyzes captured/static data and checks the exact architecture plus selected-device prerequisites; it does not claim execution on silicon. Optional silicon work reuses the accepted Thumb kernel and [timer experiment](PR-T28-03.md) after the firmware-only project preludes. Do not build new startup, clock or board drivers. Use 6 hours implementation and 4 verification, including an explicit absent/inaccessible counter route.

The project owns its counter setup only in a prepared exclusive trace session. This is a project policy, not a claim that architecture forbids shared counter reads. If another debugger/user owns setup, do not reset or overwrite it; retain the unowned result and use the captured route.

## Inputs and expected results

[The fixture](../../fixtures/performance/PR-T43-12.json) starts at 4294967280 and ends at 48: the modulo-2³² delta is 64. A separately justified interval bound 1000<2³² identifies the delta; at 16 MHz it is 4000 ns. Empty-bracket 8 cycles gives sensitivity 56 cycles/3500 ns. If the interval could include a full wrap, endpoints alone are ambiguous even if the arithmetic result is small.

Other cases report unknown DWT reads while TRCENA is clear, optional-counter absence, disabled count, unowned setup and a debug-halted active-cycle result with no wall-time claim. A zero delta is an observed bounded value, not proof of no instructions.

## Steps

1. Read the exact DDI0403E.e DEMCR/DWT scopes and selected-device/core identity. DEMCR at 0xE000EDFC has TRCENA bit 24; DWT_CTRL at 0xE0001000 has NOCYCCNT bit 25/CYCCNTENA bit 0; CYCCNT is at 0xE0001004. Access through the already accepted implementation's MMIO contract. Presence/access/errata/clock are implementation checks, not assumptions from these addresses.
2. In the optional owned session preserve unrelated debug bits with the established read/modify/write discipline, enable trace before interpreting DWT presence fields, then configure only owned counter state. Record prior state/restoration and reset effects. TRCENA-clear reads are UNKNOWN; do not infer feature presence from them.
3. Bracket a reused kernel with bounded intervals, record interrupts/debug halt/clock source and empty-bracket observations. Check wrap arithmetic and dimensions independently. Do not claim emulator timing as silicon cycles.
4. Explain a timer/GPIO alternative using the prior timer contract, including timer frequency, capture resolution and external observer. Keep static, captured, emulator-correctness and actual silicon rows separate.

## Failure cases

Reject an out-of-width endpoint, nonboolean feature flag, unknown clock or bound admitting a full wrap. The core counter is optional and may be inaccessible; those results must not become zero cycles. Debug state stops CYCCNT, so a halted span cannot be converted into full wall elapsed time. An overhead subtraction at or below overhead is inconclusive. Interrupt cycles, clock changes and probe effects remain in scope unless independently controlled.

## Acceptance and evidence

For .a supply the manual/device/access/setup ownership checklist and absent/unknown route. For .b derive the 64-cycle case, units, ambiguous-wrap rejection and overhead sensitivity; give an independently justified interval bound for any actual trial. For .c submit the labeled core captured/static certificate and timer/GPIO comparison, or add silicon evidence with all firmware preludes satisfied. No core pass certifies a physical board, energy or WCET. The finite oracle verifies scope flags and arithmetic, not memory-mapped register behavior.

## Hints and recovery

Obtain the interval bound from an independent experiment/design limit rather than from the same ambiguous endpoint pair. Enable trace before trusting DWT fields. Do not overwrite DEMCR with a single literal bit mask that clears other users' debug settings. Retain a halted counter's active-cycle meaning while refusing to label it full wall time.

## Transfer challenge

Change the declared clock and predict converted time while holding the count fixed; then explain why the actual count can also change with memory wait states. A timer or GPIO observer supplies a different clock/traffic boundary, not an automatic equivalent measurement.

# PR-T71-01: Consuming typestate and explicit recovery after partial device writes

## Contract

Implement pt_device_init/configure/close/recover with consumed matching tokens, unchanged success-output on failure, and externally certified quiescence before cleanup. Fail after each of the two control writes. The full required specification is {ref}`X-T71-001` and its explicit shared contract. Twelve hours is descriptive author accounting, never a ceiling.

## Inputs and expected results

Failure after control3 consumes the old token, leaves ready output unchanged and returns RecoveryRequired. quiet0 retains control3; quiet1 clears it. Reusing the pre-failure token after recovery rejects.

## Steps

- **T71.01:** Complete D1–D4, the named public anchor, independent falsification and changed-contract implementation.

## Failure cases

Enumerate failure stage0/1/2, quiet0/1, copied stale tokens and UINT32_MAX retirement; compile the wrong-wrapper fixture and demonstrate that a copied correct wrapper still compiles. Reject false-CLOSED and ignored-generation mutants.

## Acceptance and evidence

- **T71.01:** Satisfy all four leaf rubrics and source-bound verification; passing supplied tests alone is insufficient.

## Hints and recovery

List externally visible writes before assigning a final state. Keep failure recovery separate from a nominal close. A generation check presupposes live device storage; it is not a borrow checker.

## Transfer challenge

Replace one synchronous control write with deferred DMA completion. Design an owning Recovery token that retains a buffer until quiescence, including reset while a stale alias survives; explain why generation checks cannot inspect a dangling pointer safely.

# PR-T71-08: Typestate firmware driver with uncertain DMA ownership

## Contract

Implement pt_driver_start/complete/recover over the supplied original register/DMA model, retaining buffers on partial start failure. Connect all specified firmware_io and task/queue imports in a source-bound adapter integration. The full required specification is {ref}`X-T71-008` and its explicit shared contract. Twelve hours is descriptive author accounting, never a ceiling.

## Inputs and expected results

A failed start leaves RecoveryRequired and keeps the exact borrowed pointer. quiet0 completion returns PENDING and cannot feed the watchdog. Successful quiescence permits one release and one normal completion watchdog event.

## Steps

- **T71.08:** Complete D1–D4, the named public anchor, independent falsification and changed-contract implementation.

## Failure cases

Inject start failure after the model retains a buffer, repeated failed quiescence, successful recovery, completion with quiet0 and duplicate completion. Count watchdog and release events; reject premature-release and quiet-check omission mutants.

## Acceptance and evidence

- **T71.08:** Satisfy all four leaf rubrics and source-bound verification; passing supplied tests alone is insufficient.

## Hints and recovery

Treat a failed start as potentially having reached hardware. Write the buffer-loan interval on the event trace. A timeout says how long the caller waited, not what the device stopped doing.

## Transfer challenge

Compose UART transmission, timer deadline and DMA completion across a reset. Preserve the loan until the new hardware epoch is proven quiescent, and redesign generation issuance when wrap or stale interrupts are possible; delayed assessment changes DMA to noncoherent cached memory.

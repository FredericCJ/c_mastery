# PR-T47-01: A byte-exact page codec

## Contract

Implement the CST2 codec and fresh-image initialization. Use a preallocated 67-page image with two generation pages, 32 data pages, 32 redo images and one commit page. Define the empty tree as logical root page 1 and allocation bitmap 3. Reject zero/oversized keys, oversized values and out-of-range references before copying. Preserve output buffers and returned lengths on rejection.

Budget 5 implementation and 3 verification hours. Reuse the same engine throughout; previous milestones are not charged again. The public API and original disk format are in the storage laboratory.

## Inputs and expected results

Use [the contract fixture](../../fixtures/storage/PR-T47-01.json) and the actual C tests `storage.codec, storage.initial_image`. The image has 67 pages of 4096 bytes; the tree owns 32 logical data pages. The reference transaction changes the complete map from {1:10,2:20} to {1:11,3:30}. Compare whole maps. No fixture asserts physical power-cut durability.

## Progressive execution

The immediate learner gate is `storage.codec`, `storage.initial_image`. Early tests inject declared valid component states; they do not require a completed opener, recovery engine or later mutation API. Defer `storage.format`, `storage.corruption` until PR-T47-09/10 integrates opening, durable publication and recovery. Passes cover their finite mechanism only; retain the separate invariant, failure and transfer evidence.

## Steps

1. Predict the state transitions on paper, naming capacities, ownership and the earliest invalid state.
2. Implement this milestone in your external learner workspace; reveal only the next relevant stage of the hint table when blocked.
3. Run the named positive and negative C cases and preserve exact commands, source identity, seed/cut and return codes.
4. Explain one rejected result using the invariant, then repair and rerun the same trigger.
5. Revisit an unfamiliar variation without hints and record separate evidence for T47.01.a, .b and .c.

## Failure cases

Flip a metadata byte and its checksum separately; swap a page identity, increase a count beyond seven and truncate a block response. Require explicit corruption or I/O failure rather than a fabricated empty tree.

An unavailable compiler, sanitizer runtime, syscall or device produces unavailable evidence; it never counts as a clean run. A wrong implementation must fail a semantic assertion after successful setup.

## Acceptance and evidence

Deliver the invariant/cost argument for .a, actual C/build/test transcript for .b, and minimized failure plus repaired and delayed transfer results for .c. Include the exact source-reading locator and fault assumptions. A CTest family pass supports its executed cases, not automatic completion of every objective. Use `tools/verify_storage_fixtures.py` for contract-index consistency; it neither compiles your C nor awards runtime mastery.

## Hints and recovery

Define the file before casting a pointer. Encode integer fields byte by byte into a 4096-byte page; a C struct is an in-memory representation whose padding and alignment are not a portable file format. Validate magic, kind, generation, page identity, count, key/value extents and CRC before interpreting references. CRC-32 detects the exercised tears but is not a cryptographic authenticity guarantee. The corruption model explicitly excludes checksum collisions. A fresh format and reopening an established image are separate operations: corrupted existing data must not silently become an empty database.

The staged laboratory hints separate invariant, observation and repair direction. Keep the original failing image or key sequence and compare it with a clean control.

## Transfer challenge

Change the host byte order in a hand calculation; the encoded file bytes must stay identical.

# PR-T68-05: Generic customization with cv-preserving receivers

## Contract

Implement a _Generic receiver dispatcher selecting functions for uint32_t* and const uint32_t*. The mutable receiver returnsvalue+100, const receiver returnsvalue+200, using modulo arithmetic; neither modifies the pointed value. mp_generic_receivers invokes both through pointer-producing expressions and reports exactlytwoevaluations. Unsupported receiver categories receive a compile-time diagnostic; there is no default erased fallback.

The full required exercise {ref}`X-T68-005`, its shared contracts and objective rubric are part of this project. Eight hours is descriptive author accounting, not a learner-time or scope ceiling.

## Inputs and expected results

Mutable7 and const9 produce316 with2evaluations and unchanged pointees. Selecting the mutable policy for the const receiver produces the wrong semantic marker even if a cast lets it compile.

## Steps

- **T68.05:** Distinguish top-level pointer qualifiers from pointed-to const and state the compatible-type association restrictions. The controlling expression is not evaluated; only the selected call argument is evaluated. Explain why the generic selection should choose valid function names rather than embed branch-specific invalid field operations. Submit the exercise D1–D4 and retain prerequisite interfaces.

## Failure cases

Run metaprog.generic and compile unsupported-type/const-write diagnostic probes. Kill const-receiver-policy substitution and extra controlling-expression evaluation mutants. Check GCC and Clang with C17, and record implementation differences involving top-level qualifiers as observations requiring precise source interpretation.

## Acceptance and evidence

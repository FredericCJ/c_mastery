# PR-T47-07: Full-page redo and commit outcomes

## Contract

Implement the three ordered commit stages and an explicit INDETERMINATE result. Bind the commit record to the generation and all 32 page checksums. In the model harness update key 1, delete key 2 and insert key 3 in one transaction. On reopen require the complete old or complete new map, and require new after acknowledged success.

Budget 6 implementation and 4 verification hours. Reuse the same engine throughout; previous milestones are not charged again. The public API and original disk format are in the storage laboratory.

## Failure cases

Compile the omitted-commit-flush variant. Its successful return followed by loss of pending writes must be rejected by the semantic oracle. Never count a compiler/setup failure as mutation detection.

An unavailable compiler, sanitizer runtime, syscall or device produces unavailable evidence; it never counts as a clean run. A wrong implementation must fail a semantic assertion after successful setup.

## Hints and recovery

A successful write callback reports transfer acceptance; only a successful flush establishes the declared persistence barrier. Invalidate and flush the prior marker before reusing redo space, write and flush every after-image, then write and flush the new commit marker. Before marker publication an error is a definite abort in this model; after attempting publication it is indeterminate. The caller may not infer absence from a lost acknowledgment. The live handle reads committed redo images until checkpoint. Full-image logging has a simple bounded recovery argument and deliberately high write amplification.

The staged laboratory hints separate invariant, observation and repair direction. Keep the original failing image or key sequence and compare it with a clean control.

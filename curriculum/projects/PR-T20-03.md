# PR-T20-03: Bounded execution and cooperating machines

## Contract

Implement a bounded single-thread event-loop core with acquisition and transport state machines, explicit event order, deferred-event capacity and cancellation identities. Compare its scheduling/resource assumptions with a superloop and a task/thread-pool design. The comparison requires models and evidence, not implementing all three execution systems in one project.

## Failure cases

Queue exhaustion returns the declared rejection without losing ownership. Deferred events cannot grow unboundedly. Cancellation must not create duplicate completion or depend on incidental callback ordering. Analytical latency claims state arrival/service assumptions.

## Acceptance and evidence

Submit queue/state traces, overload/cancellation tests, resource bounds and execution-choice rationale. Show a counterexample where a different event order would break an unstated assumption, then preserve correctness under the stated order.

Record contract, build/dependency evidence, independent cases, minimized failures and the specific evidence file for every linked objective. A passing synthetic oracle does not establish a passing implementation. Use {ref}`guide-assessment` for the review gate.

## Contract

Core awareness: classify operation histories, candidate linearization points and progress quantifiers; model SPSC publication/reuse and analyze an inspected multi-participant algorithm. Supply wrap and stalled-reservation traces. No concurrent algorithm implementation is required at this gate; the optional implementation project is separate.

## Steps

1. Write the operation/state/effects contract and predict the fixture result by hand.
2. Establish the smallest supported positive case and record environment/provenance.

- **T26.01:** Classify small queue histories and nominate a linearization point for each successful operation.
- **T26.02:** Compare blocking/obstruction-free/lock-free/wait-free claims against declared stalled-participant traces.
- **T26.03:** Analyze a bounded SPSC publication/reuse graph; optionally implement it after the core awareness gate.
- **T26.04:** Study the inspected Michael–Scott algorithm or a fully declared slot protocol and trace contention/cancellation.

3. Add boundary and deliberate-failure cases before broadening the implementation.
4. Minimize each disagreement and retain the earliest broken invariant.

## Failure cases

- Challenge the mistaken claim: Memory-model consistency implies FIFO linearizability. Preserve a minimal failing trace or explain the valid precondition that excludes it.
- Challenge the mistaken claim: Lock-free means every operation has a fixed completion bound. Preserve a minimal failing trace or explain the valid precondition that excludes it.
- Challenge the mistaken claim: Single producer/consumer removes all ordering requirements. Preserve a minimal failing trace or explain the valid precondition that excludes it.
- Challenge the mistaken claim: Adding CAS to an SPSC head creates a complete MPMC design. Preserve a minimal failing trace or explain the valid precondition that excludes it.

Exercise empty/singleton or zero-progress states where the operation admits them, exact capacity, one beyond capacity, repeated completion/cleanup and a deliberately invalid precondition. For storage-owning work, inject acquisition failures and verify unchanged old ownership. For build/binary/source studies, inject a wrong edge, symbol, width, target assumption or unsupported environment and require a visible failure verdict. Never execute malformed pointers or privileged instructions just to demonstrate a negative case. Apply these cases to the declared operation; document any inapplicable case and its reason.

# PR-T75-04: Overflow-safe token buckets and competing rate contracts

## Contract

Implement RZBucket with integral capacity/rate1..16 and costs1..capacity. Refill lazily under monotonic uint64 ticks, saturating before a potentially overflowing multiplication. A rejected spend retains elapsed-time refill but spends no tokens. Extend to fractional fixed-point replenishment without rounding away long-term credit, then compose a second peak bucket with rollback of admission when either bucket denies.

The full required exercise is {ref}`X-T75-004`; its shared contracts, D1–D4, objective-specific rubric and delayed variant are part of this project. Eight hours is descriptive accounting, not a ceiling on required work.

## Inputs and expected results

Capacity4/rate1 starts with4. Spending4 at0 succeeds; another1 at0 is `FULL`. At1 one token is available and exactly-cost admission succeeds. Advancing to UINT64_MAX fills only to4 without arithmetic overflow. Backward time is `INVALID` without mutation.

## Steps

- **T75.04:** Implement overflow-safe lazy refill and fixed-point fractional credit, specifying rounding, numeric horizon and which state changes persist on a rejected spend. Complete every exercise deliverable, including separately specified extensions.

## Failure cases

Multiplication can wrap before a clamp notices it, and repeatedly rounding refill can silently suppress credit. A rate limit also does not stop an unlimited number of slow admitted calls from remaining active. For capacity/rate1..16 and elapsed0..19, compare every single-step refill/spend with integer arithmetic; add UINT64_MAX gaps. Generate length0–6 cost/time sequences with same-time bursts, backward time and impossible costs. Preserve fractional remainder in the extension and verify splitting an idle interval does not change credit. Do not execute tc or modify host network policy.

## Hints and recovery

Compare elapsed with the time needed to fill the missing capacity. The maximum burst is a parameter, not the same quantity as rate. If two budgets are required, consuming the first before rejecting the second changes future admission.

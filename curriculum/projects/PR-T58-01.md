# PR-T58-01: Stack extent and ABI alignment

## Contract

Implement po_stack(top,bytes,out): require bytes<=top, subtract and round down to16-byte alignment; publish only on success. Treat integers as modeled addresses, not dereferenceable C pointers. Then build both assembly entry stubs with a private aligned stack and inspect the map.

Shared requirements: [B06 exercise contract](../v5/contracts/b06.md). Stable
unit IDs are `LAB-PO-01A` and `LAB-PO-01B`. Families: A, B, C, D, F, G, I, J;
source records: R-B06-RVABI, R-B06-AA64, R-B06-RVISA, R-B06-RVPRIV in
`research/v5/b06_resources.json`, using only its inspected locators.

Prerequisite knowledge: Reconstruct an x86 call frame and an original linker map. Derive aligned downward stack growth without unsigned underflow. Explain why a C function-call save set is insufficient for an asynchronous trap.

## Steps

- **T58.01:** Rounding a stack address down consumes bytes. Subtracting first and checking later can wrap the address. Public-call alignment belongs to the selected ABI; it is not an ISO C stack guarantee.
- **T58.01:** Implement po_stack(top,bytes,out): require bytes<=top, subtract and round down to16-byte alignment; publish only on success. Treat integers as modeled addresses, not dereferenceable C pointers. Then build both assembly entry stubs with a private aligned stack and inspect the map.
- **T58.01:** Prove result<=top-bytes, alignment and nonwrap; account for consumed padding and live stack bounds.

## Failure cases

A port aligns to8 because pointers are8 bytes, violating the16-byte call boundary. A linker-defined top is not proof that subtraction stays in the reserved stack.

Retain the first divergent transition and distinguish the cause from a symptom.
The named mutation control must fail for its intended reason; compilation
failure is not a successful mutation kill.

## Contract

Implement L3 forwarding at R and endpoint delivery at A/B. The six-octet header is version 1, network source, destination, hop limit, next protocol 4 and payload length 0..34. A begins hop 4; R forwards only known nonlocal routes with hop>1, preserving end-to-end source/destination/payload and decrementing hop. B locally consumes positive-hop packets addressed to 51. No dynamic routes, broadcast or L3 fragmentation are part of this contract.

Use the exact table: A→51 left/link 2; R→17 left/link 1; R→51 right/link 2; B→17 right/link 1. R owns a bounded private copy while its egress segment is BUSY; the input span is invalid immediately after return. Rebuild egress link header and CRC.

## Inputs and expected results

The fixture routes A 17→B 51 via R 34 with hop 4 and a fixed payload. Expected right output retains source 17/destination 51, hop 3, link source 1/destination 2 and identical upper bytes. Additional unknown-route, hop 1, own-origin-loop and bad length/protocol cases produce distinct counted drops with no forward/local delivery.

Output a route decision and changed/preserved field ledger, plus complete rebuilt link bytes from the already-tested L2 encoder. The fixture arithmetic/route oracle does not implement a target router for you.

## Steps

1. Decode the network header with enclosing link bounds before table lookup. Keep ports opaque.
2. Separate local consumption from forwarding; never decrement a hop solely for delivery at B.
3. Copy one accepted egress packet into private storage before returning input ownership. Reject BUSY enqueue without consuming caller state.
4. Poison input storage and delay the other segment's grant; verify egress bytes remain unchanged.
5. Capture the same end-to-end record on both segments and annotate only local addresses, hop and CRC as changed.

## Failure cases

Unknown destination, hop<=1 at a forwarding router, source claiming R in a looped packet, wrong next protocol, actual length mismatch and full egress slot are independent failures. A foreign link address must already have been rejected by L2. An own-origin loop cannot be repaired by merely decrementing hops until zero.

## Acceptance and evidence

Submit positive and negative route tables, output wire record, poisoned-input ownership test and measured two-segment relay if available. Explain three address namespaces and why copying a link destination into a network destination is wrong. Evidence for the objectives covers namespaces, exact static forwarding and hop/route/storage failures; every drop leaves session/transport state untouched.

## Hints and recovery

If only delayed egress fails, inspect who owns the input after callback return. If routing works in one direction only, rewrite the left/right local address table explicitly; R has two different link identities. Do not add a default route to make a failing fixture pass.

## Transfer challenge

Predict a hop 2 forward and hop 1 destination delivery, then contrast hop 1 at R. Explain which behavior belongs to the original forwarding contract, rather than assuming an IP router's entire policy was implemented.

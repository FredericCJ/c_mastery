# PR-T45-10: Unseen memory causal repair dossier

## Contract

Diagnose one independently selected memory/resource failure without a solved implementation. For the unseen assessment, an assessor, peer or external case selection withholds the defect identity and semantic oracle until the dossier is submitted. Build competing extent, initialization, lifetime and capacity hypotheses; reproduce and minimize the trigger; identify the earliest violated invariant; repair it; and test semantic regression plus delayed transfer. A crash site, matching symptom or quiet instrumented run cannot substitute for the invariant argument. Use only valid bounded watched objects and matching image evidence. Watchpoint width/count/scope, optimization, asynchronous target events and damaged fault frames limit interpretation. Separate prevention from mitigation and state all remaining claims.

## Inputs and expected results

Four supplied finite histories distinguish the first invalid state from later symptom: extent 2→symptom 5, lifetime 1→4, initialization 3→5 and stack-budget 2→3. Their delays are 3, 3, 2, 1. The histories are selected explicit invariant checks, not a native execution trace. The actual unseen case must change input/capacity/failure position or event order beyond these fixtures and have independently established semantic acceptance.

The supplied finite fixture is [fixtures/memory_lab/PR-T45-10.json](../../fixtures/memory_lab/PR-T45-10.json). Run `python tools/verify_memory_lab_fixtures.py` from the handbook source root for arithmetic/history/catalog checks. Actual C/tool/hardware evidence remains a separate learner obligation.

## Steps

1. Select one prior repaired component and obtain an independently selected variant or trigger, following {ref}`guide-assessment`'s withheld-variant process. Submit the causal dossier before opening its defect identity and semantic oracle, then compare and record discrepancies. A self-authored delayed variant is useful additional practice with weaker independence; label it as such and keep the independent unseen criterion open rather than calling it blind or unseen.

2. State competing hypotheses and a distinguishing observation for each. Record image/input/configuration and minimum reproducing prefix.

3. Locate the earliest invalid extent, field, owner transition or resource reservation. Use valid watch scope, allocation history, map or qualified fault evidence as appropriate; keep target PC timing/frame limits explicit.

4. Repair the violated contract with one focused change. Compare canary/guard/hardening consequences separately if used; mitigation is not the repaired invariant.

5. Run semantic regression, negative controls and the appropriate separate detector builds.

6. After a delay, vary capacity, signed width, partial-failure position, nesting or completion order and complete a new causal dossier without changing the original fixture.

## Failure cases

Challenge a delayed symptom, a silent faulty run, a moved allocation layout, a watch that expires with scope and a claimed frame/address that is invalid. If an observation cannot distinguish causes, add a defined semantic check or retain the ambiguity. No exploit or arbitrary third-party target is part of this task.

## Acceptance and evidence

Deliver prediction/hypothesis table, minimum trigger, first-invalid-state proof, matching build and bounded observations, focused repair, semantic regression, prevention-versus-mitigation analysis and delayed transfer. Record who or what independently selected the variant, when the dossier was sealed and when the withheld oracle was opened. Explain all four finite first-event/delay results. A self-authored variant supports delayed practice but does not close independent unseen assessment. The assessor checks mechanism correctness and remaining evidence limits, not a particular crash message or memorized fixture value.

## Hints and recovery

Debug one state transition earlier than the visible symptom. Reuse the original T32 debugger/harness and this module's ownership/extents ledgers. If the issue disappears only when printing or changing optimization, preserve that observation and inspect its effect on layout, timing and code before accepting the repair.

## Transfer challenge

Diagnose a different mechanism producing the same outward symptom, then the original mechanism under a different symptom. Demonstrate that the invariant-based reasoning transfers across both changes.

Use {ref}`guide-assessment` for criterion-specific remediation and {ref}`guide-laboratory` for environment evidence. Preserve the original fixture and minimum failing input; do not edit expected data to fit the target.

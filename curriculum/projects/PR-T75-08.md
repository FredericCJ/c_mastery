# PR-T75-08: Idempotent effects, finite deduplication and storage fencing

## Contract

Implement RZReceiver for a checked synthetic integer total, four retained requests, two authenticated-model client IDs and finite retention1..16 ticks. A request has client,id,fence,delta. Replays within retention return the original result; changed parameters conflict; stale fencing tokens reject at the protected receiver. Publish effect and dedup record together. Add an append-only local teaching journal with explicit process-termination points around record/effect publication, then replay recovery without claiming the in-memory anchor is durable.

The full required exercise is {ref}`X-T75-008`; its shared contracts, D1–D4, objective-specific rubric and delayed variant are part of this project. Eight hours is descriptive accounting, not a ceiling on required work.

## Inputs and expected results

Client0/id1/fence2/delta3 at0 applies total3. Its replay at1 returns3 without another effect; delta4 with that ID conflicts. Client1 at fence1 is stale. With retention4, the same id at4 is no longer retained and may apply again, producing6. This bounded window is not indefinite exactly-once execution.

## Steps

- **T75.08:** Implement atomic in-memory record/effect publication, original-response replay, parameter mismatch rejection, no live-record eviction and checked arithmetic. Complete every exercise deliverable, including separately specified extensions.

## Failure cases

Deduplication needs an identity contract and retention limit. A timed-out lease or a unique randomly generated identifier does not establish that an old writer is fenced off after a newer owner acts. Enumerate client0..1, id1..3, delta-1..1, same/different payload, fence1..3 and every expiry boundary. Use a map of original requests/results plus a scalar high-water fence as the oracle. Attacker capability is replay/reorder or changing admitted request fields in this isolated original receiver; success is a synthetic counter change forbidden by the stated fence policy, or acceptance of conflicting intent. Repair and verify both rejection and unchanged effect. No real credentials, storage service or deployment is targeted.

# PR-T66-08: Thread affinity, address pinning and asynchronous quiescence

## Contract

Implement OwPin as a checked protocol binding a live object address and logical thread identifier. Check rejects a changed address or wrong thread. Submit admits at most one pending operation. Cancel only records a request. Complete is the backend-supplied terminal quiescence event and clears pending/cancel. Rebind to another live address is legal only with no pending operation and the owning thread. No API moves bytes or proves native thread identity. Write an adapter for the learner io.async contract that permits rebinding only after its exactly-once terminal release, never after request cancellation.

The full required exercise {ref}`X-T66-008`, its shared contracts and objective rubric are part of this project. Eight hours is descriptive author accounting, not a learner-time or scope ceiling.

## Inputs and expected results

Bind addressA/thread7, submit, cancel, attempt rebindB: `BUSY` and addressA remains retained. Complete then rebindB succeeds. Thread8 fails, and an address comparison using a separately live B reports `STALE`. Completion before submission or repeated completion is rejected.

## Steps

- **T66.08:** Implement the address/thread/pending state machine and an explicit io.async adapter, identifying the actual event that permits storage reuse and the lifetime of every retained address. Submit the exercise D1–D4 and retain prerequisite interfaces.

## Failure cases

Enumerate submit/cancel/complete/rebind traces with output-state canaries, include duplicate events and wrong-thread calls, and reject rebinding after cancellation while pending. Use only pointers to actual live test objects. Inspect a copied self-referential record to explain why its old internal address is wrong without dereferencing a dangling pointer.

## Acceptance and evidence

- **T66.08:** Separate address-sensitive validity, thread affinity, guard permission and asynchronous reclamation; explain why checked assertions are weaker than a language pinning guarantee. Every leaf has a separate rubric criterion in X-T66-008. Public test passage alone does not assess independent understanding.

## Hints and recovery

Cancellation describes intent, not backend cessation. Then An unchanged numeric address is not a complete lifetime proof. Record the failed hypothesis before using further hints.

## Transfer challenge

Introduce completion callbacks on a different executor: separate ownership-thread policy from completion-notification permission and queue the terminal transition safely. Delayed assessment uses a device that may still DMA after a timeout; add a RecoveryRequired/quiescence protocol and identify the physical evidence needed before reuse.

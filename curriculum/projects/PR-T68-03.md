# PR-T68-03: Policy composition with explicit failure semantics

## Contract

Implement mp_reduce over uint32 inputs and MPPolicy{limit,saturate}. Starting from0, sum mathematical values up to limit. saturate0 rejects any exceeding prefix and leaves output unchanged; saturate1 clamps tolimit. Invalid policy values fail. Empty input returns0; NULL input is allowed only when empty. Then generate two named specialized wrappers whose policy is fixed and compare with the dynamic function.

The full required exercise {ref}`X-T68-003`, its shared contracts and objective rubric are part of this project. Eight hours is descriptive author accounting, not a learner-time or scope ceiling.

## Inputs and expected results

Inputs[7,5],limit10: rejecting policyfails unchanged; saturating policyreturns10. Empty inputreturns0 under eitherpolicy.

## Steps

- **T68.03:** Prove value<=limit before subtracting limit-value, and define how a single input greater thanlimit is handled. Inputs/outputs are disjoint. State no allocation, single-threaded execution and failure publication at the end. Compare a policy parameter with Rust const parameters/trait-associated behavior only at the documented boundary. Submit the exercise D1–D4 and retain prerequisite interfaces.

## Failure cases

Run metaprog.policies and inject every prefix crossing the limit. Kill accidental-saturation-for-rejection and wrong-empty-identity mutants. Inspect specialized and dynamic assembly and benchmark only comparisons preserving the same overflow and empty-input contracts.

## Acceptance and evidence

- **T68.03:** Explain how a policy changes the operation contract and therefore the permitted performance comparison; distinguish compile-time specialization from runtime policy dispatch. Every leaf has a separate rubric criterion in X-T68-003. Public test passage alone does not assess independent understanding.

## Hints and recovery

List the empty identity independently of overflow policy. Then Use limit-value only while value<=limit remains invariant. Record the failed hypothesis before using further hints.

## Transfer challenge

Compose reduction with a caller-defined projection and fallible element acquisition. Specify evaluation order, callback side effects, rollback limits and whether saturation may short-circuit without skipping required effects.

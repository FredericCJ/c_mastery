## Contract

Instrument the ownership boundaries of the accepted [span component](PR-T18-01.md) and reuse the [stack-budget dossier](PR-T13-02.md). Produce a timestamped allocation/liveness ledger and parse one actual GCC -fstack-usage build. This is an adapter and accounting task; do not write another allocator or move a typed object into a byte arena to simplify the report. Keep caller-owned, allocated and borrowed objects distinct.

Use 5 hours implementation and 3 verification. Each owned object appears once. Lifetimes are half-open intervals, so a release at time t removes the object before the state at t is counted.

## Inputs and expected results

[The fixture](../../fixtures/performance/PR-T43-04.json) has work capacity 128/live 64, scratch 80/80 and result 96/24. Live peak is 144 at time 3, whereas allocated capacity peaks at 224 at time 7. At time 10, work is retained with no live payload: retained peak 128. Active slack peaks at 136 at time 7. These maxima occur in different states and must not be added into a fabricated simultaneous footprint.

Declared sections are text 512, rodata 64, data 32, bss 256 bytes: the stated Flash layout uses 608 bytes, and RAM sections use 288. A main/work/leaf path sums to 96 bytes; main/other is 112. With a stipulated nonnested 24-byte interrupt allowance, the known-path bound is 136. Unknown calls and recurrence have no finite certified bound here.

## Steps

1. Record ownership identity, capacity, currently meaningful payload, acquisition/release and live interval. Recompute every event boundary, then maximum each category separately.
2. Generate actual .su records from the reused component with build flags/ABI identity. Interpret static, dynamic,bounded and dynamic qualifiers. Trace feasible simultaneous call paths rather than summing all function maxima.
3. Record actual section sizes and a sampled watermark if available. State which RAM sections, stack, heap/resident pages and allocator metadata overlap or remain unobserved.
4. Add one indirect unknown call or unbounded dynamic frame to the certificate and preserve the unknown result. A successful shallow test does not resolve it.

## Failure cases

Duplicate ownership, inverted intervals and live bytes beyond capacity fail the ledger. Unknown recursion depth cannot be bounded by the maximum observed depth. An interrupt allowance is valid only under its declared nesting/preemption contract. .bss size is static storage, not runtime retained heap. Process RSS/cgroup memory contain additional charged pages and cannot substitute for the object ledger.

## Acceptance and evidence

For .a submit the event table, distinct four peaks and a rejected double-counted example. For .b submit actual .su lines, a known path, an unresolved path and the watermark/section/accounting distinction. For .c report a symbolic space bound with separate target byte observations and unresolved allocator/callback/interrupt boundaries. The fixture oracle checks declared intervals and simple paths; it does not infer whole-program stack safety from compiler output.

## Hints and recovery

Sort the union of acquisition, liveness and release endpoints. At an endpoint count the state after events according to the half-open convention. Distinguish inactive retained capacity from unused slots in a still-live object. If .su changes under inlining/LTO, retain both build identities rather than merging incompatible frame numbers.

## Transfer challenge

Move scratch use so it overlaps result lifetime and predict the changed simultaneous peak. Demonstrate that a lower retained heap count can coexist with a larger stack frame; select the boundary relevant to the requirement.

# PR-T03-04: Checked flexible buffer and resize transitions

## Contract

Implement a flexible-payload buffer with checked size calculation, explicit initialization and a resize operation that preserves the old owner on failure. State the exact invalidation rules for pointer views and compare a bounded VLA workspace with a pointer/length fallback. Allocation may be used, but every owner and failure transition must be recorded.

The declared profile **A** applies to the boundary named here; specify harness versus component dependencies in {ref}`guide-profiles`. Budget 8 h for implementation and verification together. The synthetic size fixture has prefix 16, element size 4, counts 0, 3 and 100, and limit 255. Expected sizes are 16 and 28 for the first two; the third is rejected without producing a truncated size. Actual structure prefix/alignment values come from the selected target.

## Failure cases

Zero payload is handled by the chosen nonzero-prefix contract rather than relying on zero-size allocation behavior. Reject invalid VLA bounds before declaration. Do not read uninitialized members or treat unspecified padding as a defect. All successful relocation invalidates prior pointer views.

## Acceptance and evidence

Submit checked-size proofs, injected-failure ownership traces, leak checks and a view-invalidation table. Compare flexible layout with pointer/length storage on allocation count, locality and lifetime. Keep dynamic-tool findings separate from language guarantees.

Record contract, build/dependency evidence, independent cases, minimized failures and the specific evidence file for every linked objective. A passing synthetic oracle does not establish a passing implementation. Use {ref}`guide-assessment` for the review gate.

## Hints and recovery

Use count <= (limit-prefix)/element_size after checking prefix <= limit; this avoids forming the overflowing product. Separate old and proposed capacity until commit.

If stuck, separate the violated contract from the observed symptom and reduce the input before changing the implementation. Revisit the linked teaching section and retain the minimized case after repair.

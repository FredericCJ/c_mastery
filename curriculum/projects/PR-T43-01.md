## Contract

Extend the accepted [T15 sorting milestone](PR-T15-01.md) with a counter adapter and an analysis sheet. Reuse its insertion kernel; do not rebuild the sort family. Count only key comparisons, shifts of existing records and final placements in this contract. Loop predicates, loading the key, allocation and harness setup are separate work. Preserve the original stable ordering and error contracts. No qsort, bsearch or library routine may perform the educational mechanism.

Spend 5 hours implementing the adapter and 3 verifying traces/proofs. Define n as the number of valid records, state the represented key width, and distinguish an exact cost on a particular input from the maximum over inputs of size n. The adapter's counters must have a checked range; silent wrapping invalidates the experiment.

## Inputs and expected results

[The fixture](../../fixtures/performance/PR-T43-01.json) includes [4,2,5,2,1,4]. There are 8 inverted pairs, so exactly 8 shifts; 11 key comparisons and 5 final placements give 13 destination writes. The six reverse keys give 15 comparisons and 15 shifts, while equal keys give 5 comparisons and no shifts. Empty input performs neither placements nor reads.

For the separate exact function 3n²+5n+7, prove 3n²≤f(n)≤15n² for every integer n≥1. Finite anchors check the arithmetic; they do not prove the quantifier. A separate output-sensitive work contract is 3V+2E+Z with V=4,E=5,Z=3, giving 25 units.

## Steps

1. Record the accepted prior revision and label each counted event at its semantic point; show one handwritten record-by-record trace before running C.
2. Compare C counts with the independent inversion-pair certificate. Add one input with duplicates in a different order and one maximum permitted size.
3. Write the bound with constants c₁=3,c₂=15,n₀=1 and the inequalities that justify the upper bound. Give the multi-parameter O(V+E+Z) statement and account for output production.
4. Use f(n)=n for n≤128 and n² afterwards to defeat a linear slope claim from samples 2,4,8,16. Test 130; 16900 is outside the apparent linear trend.

## Failure cases

Reject invalid spans before touching records. Preserve the prior failure result and counter status. An overflowed counter is unavailable, not a plausible small measurement. A deliberately weakened shift predicate must fail the stability/count evidence. Do not call every O(n²) upper bound a tight bound on sorted input; the chosen kernel's best case is linear.

## Acceptance and evidence

Submit six separate items: .01.a input/case contract; .01.b independently traced count vector; .01.c a three-column work/instruction/static-CFG distinction; .02.a the quantified algebraic proof; .02.b the V/E/Z input-output bound; .02.c the finite-slope counterexample. Include the prior accepted binary/source identity and actual C count results. The Python oracle certifies the original finite counts only. It supplies neither an asymptotic proof nor timing evidence.

## Hints and recovery

A key comparison that stops the scan counts even though it causes no shift. Compare shifts with inverted pairs to find an off-by-one counter. If the count adapter changes output, restore the accepted kernel and isolate the instrumentation. For the upper inequality use n≤n² and 1≤n² once n≥1; no regression fit is needed.

## Transfer challenge

Apply the same contract discipline to an already accepted graph traversal: name V, stored edges and emitted output Z separately. Supply a tiny work ledger rather than writing a second graph implementation. Predict which counts would change if parallel edges were retained.

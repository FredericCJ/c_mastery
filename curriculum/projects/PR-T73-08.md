# PR-T73-08: Multiversion visibility, reader pins and bounded reclamation

## Contract

Implement MsgVersions with eight complete two-field versions, four generation-tagged reader pins and one mutex. A snapshot pins current time; reads return the newest version no later than that time. Publish adds one whole version. Reclamation retains current plus every active pin’s visible version. Reject fifth pin, stale generation and exhausted clock without changing caller outputs. Derive why at most five distinct versions are retained and the eight-slot representation can admit a next publication.

The full required exercise {ref}`X-T73-008`, its shared contracts and objective rubric are part of this project. Eight hours is descriptive author accounting, not a learner-time or scope ceiling.

## Inputs and expected results

PinA at[0,0], publish[1,2], publish[3,4]: A still reads[0,0]. DropA and reuse its pin slot forB: old handleA is STALE and B reads[3,4]. A clock at UINT64_MAX refuses publish. Snapshot visibility is repeatable for the two-field value; no multi-object serializability or durability is claimed.

## Steps

- **T73.08:** Implement timestamped publication, exact pin identity, visible-version selection and reclamation with a bounded-space proof under the four-reader assumption. Submit the exercise D1–D4 and retain prerequisite interfaces.

## Failure cases

Enumerate pin/publish/read/drop traces against an independent immutable-history model, test four pins at different versions and a fifth refusal, stale slot reuse and generation retirement. Reject pin-ignorant collection and missing-generation mutants. Track retained version counts before/after releases and compare the mutex cost with read-copy-update assumptions.

## Acceptance and evidence

- **T73.08:** Derive version visibility and retention from reader lifetimes, distinguish repeatable snapshot reads from stronger isolation, and identify how a forgotten pin creates resource retention. Every leaf has a separate rubric criterion in X-T73-008. Public test passage alone does not assess independent understanding.

## Hints and recovery

Retain the version visible to each pin, not every historical version. Then A reused reader slot needs an identity beyond its array index. Record the failed hypothesis before using further hints.

## Transfer challenge

Give each version separately owned payload storage whose clone can fail; publish only after full construction and preserve old readers on failure. Delayed assessment adds independent keys and predicate queries: construct write skew under snapshot isolation and explain what validation or locking would establish the stronger requested property.

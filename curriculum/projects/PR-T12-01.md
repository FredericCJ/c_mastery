# PR-T12-01: Header, type and bounded-format inventory

## Contract

Create a standard-library inventory and a bounded status formatter. Classify ISO facilities by edition and distinguish POSIX, optional annex and implementation interfaces. The formatter reports required length, written length, termination and truncation/error status, with an audited format-to-argument-type mapping.

The declared profile **A** applies to the boundary named here; specify harness versus component dependencies in {ref}`guide-profiles`. Budget 8 h for implementation and verification together. Start from your own sources and the listed fixtures, with prior modules as prerequisites; no starter repository or solved program is required.

## Inputs and expected results

The fixture formats an already determined byte string abcdef into capacities 0, 1, 4 and 7. Required length is 6; written lengths are 0, 0, 3 and 6, and termination is promised only for nonzero capacity. The zero-capacity path is a sizing operation, not a generic null-pointer exemption for unrelated calls.

The canonical fixture is `fixtures/language/PR-T12-01.json`. Preserve its supplied fields and add independent cases in your dossier. Run `python tools/verify_language_fixtures.py` from the curriculum root to verify the fixture oracle; then test your C component separately.

## Steps

Build a limit/type/format report using actual available typedefs. Write compile-only header probes separately from link/run probes. Implement formatting around checked snprintf results, testing negativity before size conversion. Compare integer length modifiers and inttypes macros. Add negative mismatches as diagnostic tests, not executable valid calls.

- **T12.01:** Create an edition-tagged header/family matrix and classify a deliberate mix of ISO, POSIX and extension interfaces. Retain a facility/authority/dependency inventory with compile-only versus linked evidence. For its three original objectives, record separate evidence references: T12.01.a (Separate the complete standard library from the single stdlib.h header.); T12.01.b (Inventory headers and function families by language edition.); T12.01.c (Distinguish ISO, POSIX, optional annex, and implementation-specific interfaces.).

- **T12.02:** Build a limit/format report and compile negative mismatched-format examples separately. Retain type/range/format mapping and compiler/header/library layer records. For its three original objectives, record separate evidence references: T12.02.a (Use standard limit, type, format, and feature macros correctly.); T12.02.b (Audit fixed-width integer formatting and size-dependent conversions.); T12.02.c (Separate compiler-provided headers from external linked facilities.).

- **T12.09:** Implement bounded diagnostic formatting with a required-size result and a declared truncation policy. Retain format/type audit, zero-capacity sizing, exact-fit/truncation and encoding-error policy. For its three original objectives, record separate evidence references: T12.09.a (Match variadic argument types to format specifications.); T12.09.b (Handle precision, width, length modifiers, and required output size.); T12.09.c (Design bounded formatting with explicit truncation and error reporting.).

## Failure cases

Handle encoding failure distinctly from truncation. Missing optional headers/types are explicit inventory entries. Do not assume declarations imply linked implementation. A fixed-width-looking typedef still needs its correct format type.

## Acceptance and evidence

Submit the facility matrix, exact format ledger and boundary outputs. Independently calculate lengths and retain an invalid-format diagnostic. Explain the difference between stdlib.h, the complete library and linked runtime support.

Record contract, build/dependency evidence, independent cases, minimized failures and the specific evidence file for every linked objective. A passing synthetic oracle does not establish a passing implementation. Use {ref}`guide-assessment` for the review gate.

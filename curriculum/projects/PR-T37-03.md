## Contract

Implement an original four-register eight-bit machine with 16 byte memory cells, at most 16 program instructions and operations LI, SUB, BNZ, ST, LD, HALT. PC indexes instructions; BNZ has an absolute target index; arithmetic wraps modulo 256. One clock commits one instruction from a complete old-state snapshot. Produce control signals and next-state certificates; it is a pedagogical machine, not a Cortex-M4/x86 emulator.

This 8-hour milestone includes implementation and verification. Reading, assessment and delayed consolidation belong to the module budget. The concrete original fixture is `fixtures/algorithms/PR-T37-03.json`; run `tools/verify_algorithms_fixtures.py` for its independent narrow oracle, then run your own component checks separately.

Declare the Profile C component boundary and Profile A hosted harness under {ref}`guide-profiles`; audit object and final symbols, generated code and callback effects. Implement the studied mechanism yourself. Existing base work is reused with its original acceptance evidence; this budget covers only the new work described here.

## Inputs and expected results

The supplied original seven-instruction program loads r1=3/r2=1, loops subtract/branch until r1=0, stores 0 at memory 5, reloads r3 and halts. It commits 11 instructions, with r1 trace 3, 3, 2, 2, 1, 1, 0, 0, 0, 0, 0 and final registers 0, 0, 1, 0. No external event arrives in this fixture; any extra event must be injected between commits under an explicit policy.

## Steps

Draw operand muxes, ALU function, register/memory write enables and PC selection. Implement next-state independently of commit, and annotate fetch/decode/operand/execute/update for each event. Preserve old state until all validation succeeds, then commit registers, memory, PC/halt together. Add a maximum-clock budget and output the last accepted state on budget exhaustion. Inspect source for accidental same-step read-after-update and test a source/destination alias case.

## Failure cases

Reject unknown operation, register>3, address>15, out-of-program target and truncated instruction before commit. Budget exhaustion is a nontermination diagnostic, not HALT. A failed decode must preserve all state. Include an intentionally sequentially updated-register mutation to show why simultaneous next-state matters.

## Acceptance and evidence

For .01a give full state/external-input relation and transitions; .01b compare its choices to ISA-visible versus physical implementation choices; .01c label certificate, ISA and physical observations. For .05a submit original model with explicit next/commit; .05b full control/event trace; .05c explain combinational outputs versus stored state and why this is not a faithful commercial datapath. Supplied certificates pass independently of your parser/interpreter.

Keep the evidence items separate for each linked topic's three objectives. Retain the actual input/output replay, build identity, dependency/storage ledger, first counterexample and limits. Deterministic synthetic expectations do not substitute for required executable or device observations.

## Hints and recovery

A computed ALU result is a wire value until commit. Branch decisions read old registers; the previous instruction’s committed result is available only on its next clock. Start with LI and one SUB before introducing the loop. If PCs disagree, check the declared absolute toy target before applying real-ISA PC rules.

## Transfer challenge

Add one external-input event between two commits and state its precedence. Avoid silently adding asynchronous changes inside a transition.

# PR-T48-14: Kernel diagnosis, negative controls and delayed transfer

## Contract

A green image is one experiment. Diagnose entry failures, bad page permissions, malformed images, lost context and queue ownership at their first violated boundary. Keep host and guest results separate so a correct model cannot conceal broken assembly or an unexecuted device path.

This 12-hour milestone includes implementation and verification. Reading, assessment and delayed retrieval are in the module budget. Reuse accepted prerequisites; implement the studied mechanism in the learner workspace.

## Inputs and expected results

Use `fixtures/kernel/PR-T48-14.json` for the declared finite calculation and `labs/kernel` for actual C/guest controls. Static arithmetic does not close the executable gate. The relevant CTest names are `kernel_guest`. For early projects 03–10, a full kernel_guest run is a later cumulative regression: the immediate component dossier must include the project-local trace specified below; the full run cannot be claimed until its later dependencies exist. The first project uses only kernel_boot_smoke and stops after the actual C-entry serial marker. Cross-family projects explicitly enable the original runtime/store source paths; a standalone kernel pass is insufficient.

## Steps

Run the dual-compiler hosted matrix and real guest campaign, then introduce one controlled mutation at a time in a separate learner copy. Use GDB saved state and serial evidence to minimize the first causal divergence. Rebuild from a new directory.

Keep the contract, pre-run prediction, exact image/build identity, raw observation and first invalid transition. Reveal hints in `labs/kernel/HINTS.md` in stages. The default stubs compile but fail; selecting an assessor solution changes the evidence category.

## Failure cases

Synthetic log substituted for guest output, source/image mismatch, timeout reported as pass, changed expected marker hiding a defect and a known fault reported as blind diagnosis.

## Acceptance and evidence

Reject learner stubs and corrupted ELF/handle variants; pass repaired host and guest gates. Complete a reviewer-held perturbation after seven days and annotate unresolved physical/SMP/general-OS claims.

- **T48.14.a**: Use independent host and machine-level evidence to diagnose an original kernel defect.
- **T48.14.b**: Preserve matching source/image/tool identities and reject inadequate negative controls.
- **T48.14.c**: Transfer the mechanism to a delayed changed-condition assessment with explicit limits.

Map each objective to a concrete file/observation, retain negative controls and state unresolved claims. Refer to {ref}`guide-assessment` for rubric and causal repair.

## Hints and recovery

Start with a hosted checked boundary whenever possible, then cross the actual machine boundary. A publication or model verifier is not a substitute for the named boot, privilege, queue or reboot observation. Reduce one failed boundary before editing unrelated mechanisms.

## Transfer challenge

Defend and implement one changed resource limit or fault policy without consulting the old solution. Attempt after at least seven days, with a reviewer-held variant when available.

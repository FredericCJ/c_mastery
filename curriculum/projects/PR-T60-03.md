# PR-T60-03: Subset type and arithmetic semantics

## Contract

Implement cc_binary(op,a,b,out) for op3 addition and4 multiplication modulo2^32, using uint64_t intermediates and explicit conversion. Reject other opcodes without changing output. Identify the host assumptions required by uint32_t/uint64_t and compare with the C unsigned-return wrapper.

Shared requirements: [B06 exercise contract](../v5/contracts/b06.md). Stable
unit IDs are `LAB-CC-03A` and `LAB-CC-03B`. Families: A, B, C, D, F, G, I, J;
source records: R-B06-C11 in
`research/v5/b06_resources.json`, using only its inspected locators.

Prerequisite knowledge: Predict integer promotions and unsigned modulo arithmetic, parse precedence by hand, and derive a calling convention stack diagram. Diagnose a parser accepting an invalid trailing token before writing the compiler.
Prerequisite learner artifacts: the source, contract argument and recorded
assessment of PR-T60-02. Keep these artifacts and
their evidence identities in D1; reading or copying their assessor solution
does not satisfy the prerequisite. Use the already accepted artifact interface
where integration is assigned; do not substitute a library for this mechanism.
Target-specific supplied materials are in `labs/subset_compiler/targets/` and remain
subject to the named outstanding evidence requirements.

## Steps

- **T60.03:** A small compiler must state a precise language rather than accidentally accept a poorly implemented large one. This subset uses a32-bit unsigned value type; wraparound is deliberate. Host int width must not silently change the evaluator semantics.
- **T60.03:** Implement cc_binary(op,a,b,out) for op3 addition and4 multiplication modulo2^32, using uint64_t intermediates and explicit conversion. Reject other opcodes without changing output. Identify the host assumptions required by uint32_t/uint64_t and compare with the C unsigned-return wrapper.
- **T60.03:** Derive modulo behavior independently of host signed overflow; identify absent signed conversions, floating-point rules and pointer semantics rather than pretending they are covered.

## Failure cases

A backend replaces multiplication by addition or performs signed overflow in its evaluator. Passing small positive constants is insufficient evidence.

Retain the first divergent transition and distinguish the cause from a symptom.
The named mutation control must fail for its intended reason; compilation
failure is not a successful mutation kill.

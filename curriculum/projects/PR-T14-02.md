## Contract

Implement reserve/growth/shrink/append/insertion with an explicit allocator callback, checked capacity arithmetic and a defined invalidation policy. Force each allocation point to fail. The original allocation and logical contents survive unsuccessful reserve; compare all mutation traces with a simple hosted list model. Storage legality is part of acceptance. Under the selected C17 baseline, an aligned declared unsigned-char array is still a declared character array; alignment alone does not license arbitrary T* lvalue access. The portable byte arena uses byte APIs and explicit copying into/out of actual typed objects. A typed pool uses a real array of the selected T. A hosted harness may separately supply genuine allocated storage through a backing callback, while the studied allocator/container policy stays local. Firmware casts or mapping-backed typed objects need an explicit, inspected implementation contract and are reported under that contract, not as a blanket ISO C guarantee. Check effective type, alignment, bounds and lifetime independently.
The reusable target is Profile C: implement each studied algorithm/container/allocator/byte operation locally. A hosted test oracle may call mature libraries, but the target may not delegate its mechanism to qsort, bsearch, malloc/realloc/free, strto*, printf-style conversion, external memory primitives or equivalent library substitutes. Allocator callbacks/backing storage and compiler helpers must be explicitly scoped and audited.

## Failure cases

- Challenge the mistaken claim: Amortized constant append means every append is constant time. Preserve a minimal failing trace or explain the valid precondition that excludes it.
- Challenge the mistaken claim: A final correct result excuses transient ownership corruption. Preserve a minimal failing trace or explain the valid precondition that excludes it.

Exercise empty/singleton or zero-progress states where the operation admits them, exact capacity, one beyond capacity, repeated completion/cleanup and a deliberately invalid precondition. For storage-owning work, inject acquisition failures and verify unchanged old ownership. For build/binary/source studies, inject a wrong edge, symbol, width, target assumption or unsupported environment and require a visible failure verdict. Never execute malformed pointers or privileged instructions just to demonstrate a negative case. Apply these cases to the declared operation; document any inapplicable case and its reason.

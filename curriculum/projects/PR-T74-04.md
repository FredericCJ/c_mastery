# PR-T74-04: Monomorphic and polymorphic inline-cache guards

## Contract

Implement a two-entry polymorphic cache with monomorphic first state, sticky generic fallback, owner reset and current-receiver field loads. Compare always-generic lookup with the same output and missing-key effects. The full required specification is {ref}`X-T74-004` and its explicit shared contract. Twelve hours is descriptive author accounting, never a ceiling.

## Inputs and expected results

After caching key1 at offset0 in layout[1,2], key1 in layout[2,1] must read offset1. Looking up key2 in the first layout must read20, not the cached key1 value10; the third distinct pair selects generic mode.

## Steps

- **T74.04:** Complete D1–D4, the named public anchor, independent falsification and changed-contract implementation.

## Failure cases

Alternate receivers with different insertion orders and property names at one cache, update field values, switch arenas and test missing outputs. Reject missing-shape and missing-key guards; count hits/misses before timing equivalent workloads.

## Acceptance and evidence

- **T74.04:** Satisfy all four leaf rubrics and source-bound verification; passing supplied tests alone is insufficient.

## Hints and recovery

Cache the operation needed to read the current object. List every input to the shape-record lookup, including the owning arena, shape identity and requested property key. A successful C bounds check does not prove the cached offset means the requested property.

## Transfer challenge

Add prototype-chain access or shape retirement with weak cache references, then design invalidation tokens and deoptimization fallback. Delayed assessment inserts an accessor whose callback mutates the receiver during lookup.

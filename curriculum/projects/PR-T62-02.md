# PR-T62-02: Edge readiness and fair draining

## Steps

- **T62.02:** Edge-triggered notification reports a readiness transition, not one unit of work. If a consumer processes only one item and sleeps again, remaining data can wait indefinitely. Fairness requires remembering ready work when a per-dispatch budget expires.
- **T62.02:** Implement li_ready_after(result,budget_exhausted) for a synthetic read result: positive progress retains readiness, -2 means EAGAIN and clears readiness,0 EOF clears readiness,-1 terminal error clears readiness. Return1 while progress remains, even when a dispatch budget was exhausted. Exercise the actual anonymous-pipe EPOLLET adapter and compare drain-to-EAGAIN with a local ready queue.
- **T62.02:** Distinguish kernel notification, locally remembered readiness and actual EAGAIN. Derive a fairness budget that does not lose readiness or spin forever after EOF.

## Failure cases

The mutant clears readiness at budget exhaustion while unread data remains. The pipe receives no new edge, exposing a liveness failure while the process continues running.

Retain the first divergent transition and distinguish the cause from a symptom.
The named mutation control must fail for its intended reason; compilation
failure is not a successful mutation kill.

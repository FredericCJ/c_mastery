## Contract

Use one single-threaded component from [T13](PR-T13-01.md). Preserve an uninstrumented baseline, add bounded GCC entry/exit hooks, and compare one matching -pg/gprof build where its runtime is supported. Inspect the existing [coverage evidence](PR-T32-06.md) or a tiny matching --coverage build to distinguish counted arcs/conditions from elapsed time. Do not rebuild a coverage framework or optimize a new algorithm.

Use 7 hours implementation and 3 verification. The original hook buffer is fixed capacity, records drops and excludes the hook implementation with no_instrument_function. Avoid allocation, formatted I/O and recursive instrumentation in hooks. Restrict the gprof comparison to one thread because the inspected glibc mcount limitation is retained.

## Inputs and expected results

[The fixture](../../fixtures/performance/PR-T43-11.json) has work [0,9], child [1,4] and [5,7]. Complete LIFO attribution gives work inclusive 9/exclusive 4 and child inclusive/exclusive 5 with two calls. A four-record buffer drops two records and leaves work/child open; durations are incomplete, not zero or extrapolated.

Ten self samples at a 1-ms period imply 4 ms work and 6 ms child sampling estimates. A 20-ms child's two A/eight B calls would be attributed 4/16 ms by caller-independent averaging; declared actual costs 16/4 ms make errors −12/+12 ms. Synthetic instrumented duration 1250 versus baseline 1000 has 25% overhead; code grows 96→144 bytes.

## Steps

1. Build matching baseline, hook and supported -pg variants with complete compile/link flags and binary identities. Preserve normal cleanup so a gmon.out absence is an explicit result, not a silent success.
2. Implement a bounded event recorder and post-run LIFO reducer for the reused component. Trace drops, recursion and nonlocal exit; exclude the hook functions themselves. Account for conceptual inline functions in GCC's instrumentation contract.
3. Compare actual call/arc counts, sampled self time and estimated child time. Use the original caller-dependent fixture to expose the propagation assumption; inspect coverage output without labeling it time.
4. Measure overhead and code/stack changes against a matched uninstrumented workload. Retain off-CPU elapsed evidence from the component ledger, because gprof CPU samples do not measure I/O waiting.

## Failure cases

Reject unmatched exit order and undeclared incomplete traces. A dropped record invalidates exact attribution for affected spans. Unsupported profiling runtimes or missing cleanup/output are explicit unavailable observations; the bounded hook comparison still runs. Never compare instrumented time with a different input/build baseline or treat a sample count as an exact nanosecond total.

## Acceptance and evidence

For .a provide the three build boundaries or supported/unavailable gprof result and matching coverage distinction. For .b provide actual bounded hook traces, drops/inline/exclusion limitations and the caller-cost counterexample. For .c provide measured overhead, code/.su changes and the sampled/count/estimated/off-CPU table. The fixture oracle checks a strict serial synthetic trace and estimates only; it does not establish that all compiler-generated calls or nonlocal exits were observed.

## Hints and recovery

Start with two named functions and ensure the recorder is not instrumented before adding timestamps. If a trace never stops growing, suspect recursive instrumentation. Attribute serial exclusive time only after complete LIFO pairing. Keep samples and calls separate: a function can have many calls but few sampled CPU ticks.

## Transfer challenge

Make one caller perform a slow input and another a cheap input to the same callee. Predict the propagated child-time bias, then compare with direct per-call observations without modifying the underlying algorithm.

# PR-T68-10: Declarative build graphs and deterministic table generation

## Contract

Implement mp_build for0..8nodes with dependency bitmasks, source bytes, tool identity and configuration identity. Reject out-of-range dependencies/cycles; choose the lowest ready index deterministically. Compute each64bit FNV-1a key from length, source bytes, tool, configuration and ordered(dependencyindex,dependencykey) words. Encode words little-endian8bytes; output order/keys only after full success. Implement mp_emit_table for1..8keys as a bounded generated C uint64 array and compile the generated file in a temporary directory.

The full required exercise {ref}`X-T68-010`, its shared contracts and objective rubric are part of this project. Eight hours is descriptive author accounting, not a learner-time or scope ceiling.

## Inputs and expected results

Two nodes0->1 executeorder[0,1]. Changingnode0configuration changes bothkeys. A cycle0<->1 fails with previous outputs unchanged. Generated source retains all64bits of eachkey and is reproducible byte-for-byte.

## Steps

- **T68.10:** Prove Kahn-style readiness and termination, show how dependency content propagates into consumers, and distinguish source identity from timestamp ordering. Compare Ninja explicit/implicit/order-only dependency semantics and command-line rebuild tracking. The educational FNV key is not collision-resistant; require full input equality or a suitable cryptographic digest before any untrusted shared cache use. Submit the exercise D1–D4 and retain prerequisite interfaces.

## Failure cases

Run metaprog.buildgraph and independent Python topological/hash reconstruction. Kill omitted-configuration and omitted-dependency-key mutants. Compile/run the generated C table consumer, permute input storage without changing logical IDs, and inject a missing implicit dependency to demonstrate stale generated metadata.

## Acceptance and evidence

- **T68.10:** Derive build ordering separately from action invalidation, identify hidden inputs, and explain why a content key is only as complete and collision-resistant as its declared input model. Every leaf has a separate rubric criterion in X-T68-010. Public test passage alone does not assess independent understanding.

## Hints and recovery

Write the declared action inputs before the scheduling algorithm. Then A dependency edge affects order and usually invalidation for different reasons. Record the failed hypothesis before using further hints.

## Transfer challenge

Introduce an incremental cache with toolchain, environment, include-file and schema dependencies. Inject process termination before and after artifact publication, and separately simulate hash collisions; define atomic replacement and full-input verification. Compare a parallel scheduler only after establishing dependency and output ownership.

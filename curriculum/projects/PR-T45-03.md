# PR-T45-03: Checked sizing and narrowing repair

## Contract

Implement a checked count-to-byte-size helper and repair a caller that converts an external signed count or wide length too early. The helper validates count>=0, count/header within the declared size limit, stride in 1..limit, then multiplication and addition; total zero is rejected. Publish size only on success and make no allocation or destination mutation on rejected size. The fixture uses an original 16-bit mathematical limit; native C uses the recorded actual SIZE_MAX and interface limit. The allocation policy remains outside this allocation-free helper.

## Inputs and expected results

With limit 65535, stride 7 and header 12, count 9360 yields 65532; 9361 fails addition; 9363 fails multiplication; count 0 yields 12. A separate stride 1/header 0 case at count 65535 succeeds. Negative count fails input validation, and count 0/header 0 gives the explicit zero_size verdict. Fixture expected size is null for every rejected case and allocation_allowed is an exact boolean.

The supplied finite fixture is [fixtures/memory_lab/PR-T45-03.json](../../fixtures/memory_lab/PR-T45-03.json). Run `python tools/verify_memory_lab_fixtures.py` from the handbook source root for arithmetic/history/catalog checks. Actual C/tool/hardware evidence remains a separate learner obligation.

## Steps

1. Derive safe count bounds using wide mathematical arithmetic and identify each checked intermediate.

2. Implement the allocation-free helper with unchanged output on failure.

3. Repair the narrowing caller so rejection precedes conversion or multiplication.

4. Test SIZE_MAX-derived boundary counts with stride/header combinations, zero count, invalid signed count and narrowing beyond the interface maximum.

5. Observe one signed-overflow negative and one unsigned-wrap contract defect in separate hosted trials. Enable and record the exact UBSan checks; do not infer unsigned-overflow coverage from the default group.

6. Run the repaired allocation caller through a counted adapter and prove zero calls after size rejection.

## Failure cases

Exercise multiplication-success/addition-failure, multiplication failure, representable maximum success, zero-total rejection, invalid stride and out-of-range inputs. Never evaluate signed overflowing expressions in the repaired path or build an oversized native object merely to simulate its boundary.

## Acceptance and evidence

Deliver a first-failure-stage table, independent wide calculations, strict size/output sentinel tests, native width/configuration and allocation-call ledger. Explain why unsigned wrapping is defined arithmetic yet an invalid size contract, and why a narrow conversion before validation can change the problem.

## Hints and recovery

Division inequalities avoid overflowing the expression being checked. Use separate result publication from intermediate calculation. Revisit selected T16 layout/checked arithmetic and T03 flexible-size reasoning; a sanitizer report does not replace the size proof.

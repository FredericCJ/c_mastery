# PR-T02-03: Initialization, lifetime and qualified views

## Contract

Implement a caller-owned record and two views: a read-only pointer/length view and a mutable destination. Use aggregate and designated initialization for records, then expose explicit reset and update operations. The component calls no external C-library routines; the hosted test harness can inspect member values. Include a compound-literal lifetime analysis and negative qualification tests.

The declared profile **C** applies to the boundary named here; specify harness versus component dependencies in {ref}`guide-profiles`. Budget 6 h for implementation and verification together. Start from your own sources and the listed fixtures, with prior modules as prerequisites; no starter repository or solved program is required.

## Inputs and expected results

The fixture initializes a four-element synthetic aggregate at indices 1 and 3 with 7 and 9. Expected member values are [0, 7, 0, 9]. This describes value initialization only; padding bytes and non-integer representations remain outside its oracle.

## Steps

Compare static implicit initialization, automatic explicit initialization and later assignment. Draw lifetimes for a file-scope and block-scope compound literal. Compile const-pointer and pointer-to-const examples, including an invalid qualifier-loss conversion. Write a view contract that says who can mutate the underlying storage and when.

Retain a member-value table and a lifetime diagram with a corrected owner for any escaped data. - **T02.10:** Design a read-only view and a mutable destination API, test qualifier-loss diagnostics, and document volatile/restrict claims separately. ## Failure cases

Reject destination capacity below the required length without writing. Never return a view into an expired local aggregate. Keep volatile and restrict experiments separate from any concurrency claim, and do not byte-compare structures to establish value equality.

## Acceptance and evidence

Provide member-value checks, a lifetime diagram and header tests for read-only access. Explain why omitted members are initialized while an unrelated uninitialized automatic object is not. The dependency audit applies to the reusable component, including compiler-emitted helpers.

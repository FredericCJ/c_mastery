## Contract

Implement a fixed two-descriptor TX publication model and bounded transmit side of `ethernet_frame_channel_v1`. Accept a caller frame beginning DA without preamble/FCS,14..1514 bytes and exact declared capacity; MAC supplies pad/FCS under the selected policy. Copy into fixed internal storage or retain an explicit borrow token until confirmed completion/stop. At most 2 queued slots, one publication at a time. Full ring returns backpressure; no hidden allocation or automatic unbounded retry.

This 10-hour milestone includes implementation and verification. The module budgets reading, assessment and delayed consolidation separately. Apply profile C under {ref}`guide-profiles`: fixed caller storage and explicit component/image dependencies. A hosted harness may print/use library oracles; that permission does not extend to the studied component or target image.

## Inputs and expected results

Successful events prepare tail/head, own tail/head, complete then reuse. Early own-head fails partial_publication; reuse while DMA-owned fails premature_reuse. Error completion and confirmed reset-stop return local ownership but not peer-delivery proof. Payload 3,46,100 requires 43,0,0 pad bytes. The fixture’s completion events imply ownership has actually returned, not merely that an IRQ fired.

## Steps

1. Define CPU-prepared, DMA-owned, complete, failed, abort-pending and stopped-generation states.

2. Prepare metadata/buffers and publish tail before first OWN with declared compiler/hardware order.

3. Implement bounded completion, failure/backpressure and stop/reset ownership handling; prevent late-generation completion from ending a new request.

4. Replay publication/reuse failures and add a full-ring plus unconfirmed-stop case.

5. Bind the mechanism to the prepared E adapter for one captured frame and preserve image/map/status evidence, retaining the C component’s separate undefined-symbol audit.

## Failure cases

Capacity/invalid length, partial descriptor publication, full ring, premature reuse, completion without publication, unconfirmed abort and stale completion. On unknown engine state report unavailable/retain ownership; confirmed error completion is not successful wire delivery. An interrupt by itself is insufficient.

## Hints and recovery

Make the first descriptor the final publication point. Keep “queued”, “in flight”, “local completion” and “peer application accepted” as distinct outcomes. On timeout preserve the outstanding token until stop is established.

If a check disagrees, minimize the first failing prefix and compare units, capture point, state and ownership. Use {ref}`guide-assessment` for targeted remediation; repair only the failed objective group.

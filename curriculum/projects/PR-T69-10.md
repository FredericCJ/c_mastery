# PR-T69-10: Versioned plugin objects and borrowed code lifetime

## Contract

Implement DSLoaded open/acquire/release/close using only original test DSOs. Load an explicit local path with RTLD_NOW|RTLD_LOCAL, resolve the exported complete DSPlugin object, validate ABI1/sizeof/callbacks and maintain a bounded borrow count. Close must reject while API/code pointers are borrowed. Add original fixtures for missing symbol and incompatible size metadata, still backed by actual complete objects. Analyze constructor execution before validation and why version checks cannot sandbox malicious same-process code.

The full required exercise is {ref}`X-T69-010`; its shared contracts, D1–D4, objective-specific rubric and delayed variant are part of this project. Eight hours is descriptive accounting, not a ceiling on required work.

## Inputs and expected results

The ABI9 original fixture rejects and leaves the module empty. ABI1 opens; acquire then close returns busy. Its apply(17,3) returns20. Clear the borrowed pointer, release, and close empties handle/API. Never call a pointer after release/close to infer whether the loader really unmapped it.

## Steps

- **T69.10:** Implement failure-clean loading, exact version/size admission and borrowed-code quiescence using a typed exported object; define trusted fixture extent rather than pretending a size field proves memory validity. Complete every exercise deliverable, including separately specified extensions.

## Failure cases

A symbol address supplies neither semantic compatibility nor lifetime. A successful dlclose need not remove mappings, and a surviving address is not permission to keep using a logically unloaded API. Build DSOs and host separately with recorded flags. Use dlerror around symbol resolution and inspect dynamic symbols/dependencies. Retain handles after failed close and classify initialization side effects. All executable targets are original local DSOs; no external plugin/service load is authorized. No destructor, stale callback or invalid ABI is invoked after rejection.

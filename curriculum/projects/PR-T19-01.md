# PR-T19-01: Stateful object with operation table and callbacks

## Contract

Implement a caller-owned session object with two backends sharing immutable operation tables. Pair each callback with explicit context and a bounded registration handle. Define optional operations, table versioning, reentry and removal/destruction behavior. Use exact function types throughout, without pointer casts as adapters.

The declared profile **C** applies to the boundary named here; specify harness versus component dependencies in {ref}`guide-profiles`. Budget 10 h for implementation and verification together. Start from your own sources and the listed fixtures, with prior modules as prerequisites; no starter repository or solved program is required.

## Inputs and expected results

The fixture registry starts with callbacks A and B. During dispatch A removes itself; removal is deferred until the current dispatch completes, so calls are A then B and the remaining registry is [B]. This synthetic policy is explicit; a different removal policy would need different expectations.

Implement deferred self-removal, draw in-flight context lifetimes and demonstrate destruction cannot reclaim active context prematurely.

## Failure cases

Reject invalid table versions and missing required operations before calls. Reentry must follow the chosen prohibition or safe protocol. Registration capacity exhaustion leaves existing entries unchanged. A callback may not retain context beyond the declared lifetime.

## Acceptance and evidence

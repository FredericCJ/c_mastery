# PR-T65-03: Partial progress is a product, not an error alternative

## Contract

Implement er_transfer(bytes,length,next,sink,context). It calls the borrowed sink at most once with bytes+next and length-next. The backend returns er_progress whose next field is a relative consumed count and whose code is OK, `AGAIN` or IO. Preserve progress even with `AGAIN` or IO. Return an absolute next offset. A complete input returns OK without a callback. Reject next>length, a missing sink, or a null nonempty input. A backend count beyond the offered extent, unsupported status, or zero progress with OK on nonempty input returns ER_CONTRACT and preserves the input next. External backend side effects cannot be rolled back.

The full required exercise is {ref}`X-T65-003`. Its explicit shared contract, four deliverables, objective rubric, source inspections and delayed variant are part of this project. Eight hours is descriptive author accounting, not a study deadline or scope ceiling.

## Inputs and expected results

With length4,next0 and backend (2,`AGAIN`), return (2,`AGAIN`). Retrying from2 with (1,IO) returns (3,IO). A backend count2 offered only one byte violates the contract and returns the original next. Empty input does not call the sink.

## Steps

- **T65.03:** Implement a one-call bounded adapter with overflow-free relative-to-absolute progress conversion and explicit borrowed-buffer lifetime. Complete the exercise D1–D4 and preserve prior artifact contracts.

## Failure cases

Derive a state table in which progress and terminal/error status are independent, and distinguish accepted bytes from durable bytes. Enumerate lengths0–5, valid and invalid next positions, backend counts0–6 and all status tags using a fake sink. Assert call counts, offered spans, no retry duplication and unchanged next on contract violations. Kill error-discards-progress and status-erasure mutants. Use a separate actual pipe adapter only as an additional OS experiment.

## Transfer challenge

Compose with io.stream and introduce a copied bounded staging buffer. Cancellation arrives after a short write: identify what can be retried, what stays owned and what cannot be rolled back. Delayed assessment changes the sink to commit bytes in separate durable epochs. Retain source-bound evidence and the delayed variant's assistance record.

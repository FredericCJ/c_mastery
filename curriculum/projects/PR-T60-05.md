# PR-T60-05: Intermediate representation verification and resource bounds

## Contract

Implement cc_validate for1..128 instructions, at most64 live stack values, constants<=65535, opcodes1..5, no underflow, and exactly one final `RET` with height1. Return peak depth only on success. Reject any operation after `RET` and any missing `RET`.

Shared requirements: [B06 exercise contract](../v5/contracts/b06.md). Stable
unit IDs are `LAB-CC-05A` and `LAB-CC-05B`. Families: A, B, C, D, F, G, I, J;
source records: R-B06-C11, R-B06-LLVMIR, R-B06-AA32, R-B06-QEMU in
`research/v5/b06_resources.json`, using only its inspected locators.

Prerequisite knowledge: Predict integer promotions and unsigned modulo arithmetic, parse precedence by hand, and derive a calling convention stack diagram. Diagnose a parser accepting an invalid trailing token before writing the compiler.

## Failure cases

The faulty verifier accepts executable instructions after `RET`. That can conceal malformed data and causes consumers to disagree about the authoritative program extent.

Retain the first divergent transition and distinguish the cause from a symptom.

failure is not a successful mutation kill.

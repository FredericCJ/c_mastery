## Problem

Implement RPSet for values0..3 and2 replica writers, each with8 never-reused add identities. adds[value] and removed[value] are16-bit tag sets; next[replica] reserves the next local identity. add returns a delta containing its new tag and counter frontier; remove returns tombstones only for tags actually observed. Merge ORs add/tombstone sets and takes frontier maxima. Empty removal succeeds. Exhausted identity space returns RP_FULL; no reset/reuse while any state/delta survives.

Concrete inputs and expected results: Replica0 adds value2; replica1 observes it. Replica0 removes while replica1 concurrently adds its own tag. Join retains value2. Removing after observing both tags and replaying either old add delta does not resurrect it. The ninth add by one replica fails without resetting its identity counter.

Supplied artifacts: labs/replicated/include/replicated.h, compiling unsolved src/replicated.c, CTest replicated.sets, fixtures/replicated/PR-T76-05.json, and the shared contracts. State every additional backend assumption before running it.

## Security

Target only RPSet in [labs/replicated](../../../labs/replicated), in a local process.

- **Adversary.** You control the order, duplication and omission of add and remove deltas from two writers, including remove-before-add and replay of an old add delta, and how many adds are attempted. You do not control tag allocation, code or memory. Worked trace (sets_test): replica 0 adds value 2 and removes it, so it no longer contains 2; replica 1 concurrently adds its own tag for 2. After the deltas cross, both replicas must still contain 2 (tests.c:150) because replica 1's tag was never observed by the remove.
- **Violated property.** Observed-remove integrity: a remove deletes only the tags it observed, a tombstoned tag is never resurrected by replaying its old add delta (tests.c:153-156), and an exhausted identity space returns RP_FULL without reusing a tag (the ninth add by replica 0 fails with next[0] still 8, tests.c:161).
- **Experimental boundary.** One hosted process, values 0..3, two replicas and eight identities each, with no transport, file or child process.
- **Evidence to capture.** Predict first: which replica contains 2 after each merge step of the trace above, and what the final state of replica 1 is after it merges the second removal and then the old add delta (absent). Run CTest replicated.sets and record the CHECKs at tests.c:146, 150, 152, 156 and 161. Build the two variants from the header, record the `RP_CHECK line N` each produces, and compare your set against a tagged-set oracle for all two-writer traces.
- **Impact class.** demonstrated-invariant-violation, once you have built and run a variant. Resurrection or loss of an element is a violated specified property in the model; no memory corruption or external impact is shown.
- **Remediation.** Remove only observed tags, OR the tombstones on merge, take frontier maxima and return RP_FULL without resetting. The regression that rejects the original defect is replicated.sets; run it against both of your variants.
- **Limitations.** Bounded tags are a resource limit, not a compaction design; delta authenticity and replica identity are assumed.

# X-T75-002: Five overload policies and bounded pending producers

## Prerequisites

Bring pinned contracts and fresh recall for containers.ring, conc.channel, io.reactor; prerequisite exercises: X-T75-001. Required knowledge includes C object lifetime, checked arithmetic, ownership, typed arrays and the selected source passages. The shared contract and modern-cost contract are explicit parts of this exercise. Existing project estimates describe author accounting; they impose no learner time ceiling.

## Environment

Use C17 hosted Linux with GCC and Clang, CMake and host Python. Record compiler/ABI versions, integer widths, sizeof/alignment and optimization. Mechanism code uses no library implementing the mechanism. The T73 channel backend supplies its declared POSIX synchronization; the virtual-time model itself supplies no OS clock, sleep or hidden scheduler. A strict freestanding port requires its own generated-code/link audit and is not established by the hosted run. Compare C11 draft/C17/C23 only where inspected normative evidence supports the claim; exact published C17 access remains a reference gap.

## Problem

Implement RZQueue/RZOffer with four copied unsigned messages and BLOCK, REJECT, DROP, OVERWRITE and DEGRADE policies exactly as CONTRACTS.md specifies. A blocked offer is a retained operation to retry, not a hidden sleeping thread. Degrade coalesces newest by max and reports reduced semantics. Implement rz_forward using your actual T73 nonblocking channel send and remove the head only on acceptance. Then add a bounded two-producer readiness adapter that registers before checking readiness, acknowledges cancellation and never creates an unbounded waiting-producer list.

Supplied artifacts: labs/resilience/include/resilience.h, deliberately incomplete labs/resilience/src/resilience.c, executable anchors, fixture PR-T75-02.json and the shared CONTRACTS.md. Expected example: Queue[1,2,3,4] plus DROP9 remains[1,2,3,4]; OVERWRITE9 becomes[2,3,4,9]; DEGRADE10 changes newest to10 and reports DEGRADED. BLOCK retains pending ownership. Expiry before a later retry terminates that offer without enqueuing it. A full imported channel leaves the local head in place.

## Necessity

A fixed queue does not bound memory if arbitrary producers wait while retaining payloads. Overload policy changes the service contract and cannot be compared using throughput alone.

## Reasoning

T75.02.a: Specify each policy in terms of observable loss, ordering, caller ownership and completion; distinguish application admission, transport buffering and receiver consumption.

T75.02.b: Implement all five policies, closed draining and the real channel adapter, including exactly-once transfer and explicit retained pending state.

T75.02.c: Implement a two-producer readiness/cancellation adapter and falsify missed-wakeup, double-transfer and unbounded-pending assumptions with controlled event traces; bound queue plus producer-held memory together. Add explicit credit messages: start with four credits, consume one on admission, return one only when receiver capacity is released, and reject duplicate/stale credit returns so granted minus consumed plus returned never exceeds actual capacity.

T75.02.d: Compare block/reject/drop/overwrite/degrade under an identical synthetic producer/consumer schedule, measuring accepted, lost, coalesced, queued and pending work separately. Transfer to owned payloads with a disposer and prove exactly-once cleanup on every rejected or discarded path.

State preconditions, postconditions, representation invariants, resource ownership, failure publication and complexity. For each guarantee identify ISO C rules, diagnostics, runtime checks, external verification and programmer discipline separately. Include a minimal counterexample to an overstated equivalence with the corresponding language/library abstraction. Apply all13 dimensions in modern-cost-contract.md, recording genuine non-applicability with reasons and unavailable measurements as gaps.

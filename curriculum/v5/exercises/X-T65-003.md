# X-T65-003: Partial progress is a product, not an error alternative

## Prerequisites

Use the existing bytes.checked, parser.integer, io.stream and codec.records contracts as comparison boundaries. Complete C17 tagged-union, pointer-lifetime and function-pointer reasoning first. Preserve the learner's earlier implementations; do not import an assessor solution. Complete X-T65-002 first.

## Environment

Original C mechanisms; hosted setjmp/longjmp only for the explicit jump boundary. Host harness may use stdio/Python. No strict freestanding claim. C17, Linux x86-64, GCC and Clang with -Wall -Wextra -Wpedantic -Werror and extensions disabled. The exact shared contract is [errors/CONTRACTS.md](../../../labs/errors/CONTRACTS.md). C editions, language-level guarantees and implementation observations must be labeled separately.

## Problem

Implement er_transfer(bytes,length,next,sink,context). It calls the borrowed sink at most once with bytes+next and length-next. The backend returns er_progress whose next field is a relative consumed count and whose code is OK, AGAIN or IO. Preserve progress even with AGAIN or IO. Return an absolute next offset. A complete input returns OK without a callback. Reject next>length, a missing sink, or a null nonempty input. A backend count beyond the offered extent, unsupported status, or zero progress with OK on nonempty input returns ER_CONTRACT and preserves the input next. External backend side effects cannot be rolled back.

Concrete expected cases: With length4,next0 and backend (2,AGAIN), return (2,AGAIN). Retrying from2 with (1,IO) returns (3,IO). A backend count2 offered only one byte violates the contract and returns the original next. Empty input does not call the sink.

Supplied artifacts: labs/errors/include/errors.h, compiling unsolved src/errors.c, the named CTest errors.progress, and fixtures/errors/PR-T65-03.json. No installed package may supply the mechanism under assessment.

## Necessity

Derive a state table in which progress and terminal/error status are independent, and distinguish accepted bytes from durable bytes. An ordinary nominal call does not assess this distinction. The two isolated mutants and the changed-condition case expose different incorrect explanations.

## Reasoning

Implement a one-call bounded adapter with overflow-free relative-to-absolute progress conversion and explicit borrowed-buffer lifetime. State the preconditions, postconditions, valid representation states, ownership and failure effects before implementation. Derive operation and storage bounds; distinguish caller misuse from a reported operational failure. Compare the C protocol with the exact inspected source scope: C type compatibility and diagnostics do not supply automatic ownership, exhaustive matching or proof of a runtime predicate.

## Deliverables

- D1: Derive a state table in which progress and terminal/error status are independent, and distinguish accepted bytes from durable bytes.
- D2: Implement a one-call bounded adapter with overflow-free relative-to-absolute progress conversion and explicit borrowed-buffer lifetime.
- D3: Enumerate lengths0–5, valid and invalid next positions, backend counts0–6 and all status tags using a fake sink. Assert call counts, offered spans, no retry duplication and unchanged next on contract violations. Kill error-discards-progress and status-erasure mutants. Use a separate actual pipe adapter only as an additional OS experiment.
- D4: Compose with io.stream and introduce a copied bounded staging buffer. Cancellation arrives after a short write: identify what can be retried, what stays owned and what cannot be rolled back. Delayed assessment changes the sink to commit bytes in separate durable epochs. Complete all dimensions of the shared modern-cost contract, with evidence or a justified non-applicability.

## Verification

Enumerate lengths0–5, valid and invalid next positions, backend counts0–6 and all status tags using a fake sink. Assert call counts, offered spans, no retry duplication and unchanged next on contract violations. Kill error-discards-progress and status-erasure mutants. Use a separate actual pipe adapter only as an additional OS experiment. Run the named anchor separately from the complete suite. Preserve exact commands and expected/observed results. Every specified failure output and callback count is a pass/fail gate. Public anchors and source-bound author campaigns do not discharge independent inputs, reasoning or delayed transfer. Explain sanitizer, model-size and compiler limitations.

## Rubric

The four objective-specific metadata criteria assess representation reasoning, implementation, falsification and transfer separately. A candidate must satisfy every criterion at level2 or higher and at least two at level3 under the shared six-dimension rubric. A forbidden side effect, lifetime violation, unsupported dependency or overstated language guarantee fails the gate. Nominal tests alone earn at most level1.

## Hints

1. Draw count and status as two axes.
2. Bound the relative count before adding it to next.
3. A rejected backend report cannot erase side effects already produced by that backend.

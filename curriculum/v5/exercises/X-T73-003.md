# X-T73-003: Senders, receivers and immovable operation-state lifetimes

## Prerequisites

Explain C17 atomic ordering, POSIX wait predicates, existing queue ownership, async terminal completion and stable coroutine-frame registration; retain the named imported learner artifacts. Required learner artifacts: work.pool, sync.condition_queue, sync.spsc, io.async, io.deadline, testing.faults, coro.frame. Do not import an assessor implementation.

## Environment

Implement mechanisms locally using declared typed storage/callbacks; hosted harness and diagnostic runtimes are separate. See laboratory contract for exact dependencies. Use C17 with extensions disabled and warnings treated as errors. A diagnostic extension is identified explicitly and does not become an ISO guarantee. The full platform, pointer, callback and concurrency preconditions are in [messaging/CONTRACTS.md](../../../labs/messaging/CONTRACTS.md).

## Problem

Implement MsgOperation transitions NEW→STARTED→DONE. Connect records receiver/context, start succeeds once, cancellation records intent only, and complete accepts exactly one value/error/stopped result. Set terminal state before invoking the receiver and never touch the operation after that call: a receiver may reclaim it. Add an io.async backend adapter whose terminal callback carries partial progress and releases retained ownership exactly once.

Concrete inputs and expected results: Complete before start is INVALID. Start then stop leaves STARTED with cancellation requested. Complete CANCELLED,3 invokes one receiver and reaches DONE. Duplicate complete on a still-live test state is INVALID and leaves callback count1. A separate heap-owned completion test frees the state inside its receiver without later access.

Supplied artifacts: labs/messaging/include/messaging.h, compiling unsolved src/messaging.c, CTest messaging.operations, fixtures/messaging/PR-T73-03.json, and the shared contracts. State every additional backend assumption before running it.

## Necessity

Separate sender recipe, connected operation storage, start permission and completion ownership; identify the dated C++ proposal guarantees that an exposed C struct does not enforce. The misconception and changed-condition case below are separately assessed; ordinary successful execution alone does not cover them.

## Reasoning

Implement the serialized state protocol and backend lifetime adapter, including synchronous completion, cancellation races, callback reentrancy policy and exactly-once terminal release. Give the abstraction function, admitted states, pre/postconditions, ownership graph, failure effects and complexity before implementation. Identify the enforcement boundary of every safety claim using the shared modern-cost contract. Distinguish an invalid caller object from an operational failure admitted by the API.

## Deliverables

- D1: Separate sender recipe, connected operation storage, start permission and completion ownership; identify the dated C++ proposal guarantees that an exposed C struct does not enforce.
- D2: Implement the serialized state protocol and backend lifetime adapter, including synchronous completion, cancellation races, callback reentrancy policy and exactly-once terminal release.
- D3: Enumerate invalid start/complete orders, value/error/stopped alternatives and cancellation-before-completion. Use a receiver that frees a heap state to detect post-callback access under ASan. Reject duplicate-completion and cancel-as-completion mutants. For a concurrent adapter, use one atomic winner and demonstrate that losers never inspect reclaimed storage without their own retained reference.
- D4: Allow an operation to complete inline during start and let the receiver destroy its enclosing object. Delayed assessment connects a chain of two operations; ensure the successor starts only after ownership transfers and no predecessor field is accessed after its receiver may have destroyed it. Complete all thirteen cost/enforcement dimensions with evidence or a mechanism-specific non-applicability.

## Verification

Enumerate invalid start/complete orders, value/error/stopped alternatives and cancellation-before-completion. Use a receiver that frees a heap state to detect post-callback access under ASan. Reject duplicate-completion and cancel-as-completion mutants. For a concurrent adapter, use one atomic winner and demonstrate that losers never inspect reclaimed storage without their own retained reference. Preserve predictions before execution, exact commands, source/input/toolchain identity and observed outputs. Explain independent-oracle assumptions and minimize disagreements. A supplied anchor or compiled mutant checks only its named property. Failure-side effects, ownership accounting and the required changed-condition result are pass/fail gates; finite tests cannot establish absolute mastery.

## Rubric

The metadata rubric maps each leaf to a distinct D1–D4 criterion. Require every criterion at level2 and at least two at level3 on independently attempted cases; record assistance. A violated ownership/failure contract, unsupported guarantee or incorrect exploitability claim fails regardless of performance. Passing only the public suite earns at most level1. Apply the shared six-dimension rubric as well.

## Hints

1. Completion may be the last permitted access to the state.
2. A stop request does not authorize storage reclamation.
3. A C typedef does not make a state noncopyable or immovable.

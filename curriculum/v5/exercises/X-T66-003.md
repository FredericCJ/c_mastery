# X-T66-003: Move protocols, source poisoning and the limits of must-use diagnostics

## Prerequisites

Complete the earlier domain projects and retain the named prerequisite artifacts with their contracts, ownership ledger and tests. Required learner artifacts: memory.pool, containers.array, testing.faults, bytes.checked, io.async, errors.result. Do not import an assessor implementation.

## Environment

Implement mechanisms locally using declared typed storage/callbacks; hosted harness and diagnostic runtimes are separate. See laboratory contract for exact dependencies. Use C17 with extensions disabled and warnings treated as errors. A diagnostic extension is identified explicitly and does not become an ISO guarantee. The full platform, pointer, callback and concurrency preconditions are in [ownership/CONTRACTS.md](../../../labs/ownership/CONTRACTS.md).

## Problem

Implement ow_move(destination,source) for distinct valid OwOwners. Destination must be empty and source nonempty. Transfer every owned pointer and allocator, then clear source pointers and count; reject self-move, a nonempty destination and an empty source without side effects. ow_consume destroys a nonempty owner and returns DEAD for empty. The public header offers OW_MUST_USE as an explicitly GNU/Clang warn_unused_result diagnostic extension; baseline C17 permits ordinary struct copying and does not enforce linear use.

Concrete inputs and expected results: After moving three blocks, destination.count=3 and source.count=0. Consuming the source returns DEAD; consuming the destination releases three blocks once; a second consume returns DEAD. A direct C assignment copying the original owner is a counterexample to an alleged static move-only guarantee.

Supplied artifacts: labs/ownership/include/ownership.h, compiling unsolved src/ownership.c, CTest ownership.move, fixtures/ownership/PR-T66-03.json, and the shared contracts. State every additional backend assumption before running it.

## Necessity

Separate ownership transfer, physical byte copying, source poisoning and diagnostic enforcement; explain why ISO C17 cannot prevent all implicit copies of this public struct. The misconception and changed-condition case below are separately assessed; ordinary successful execution alone does not cover them.

## Reasoning

Implement checked move/consume operations and an isolated diagnostic probe that intentionally ignores OW_MUST_USE, with extension-enabled and portable builds reported separately. Give the abstraction function, admitted states, pre/postconditions, ownership graph, failure effects and complexity before implementation. Identify the enforcement boundary of every safety claim using the shared modern-cost contract. Distinguish an invalid caller object from an operational failure admitted by the API.

## Deliverables

- D1: Separate ownership transfer, physical byte copying, source poisoning and diagnostic enforcement; explain why ISO C17 cannot prevent all implicit copies of this public struct.
- D2: Implement checked move/consume operations and an isolated diagnostic probe that intentionally ignores OW_MUST_USE, with extension-enabled and portable builds reported separately.
- D3: Test self-move, occupied destination, empty source, repeated consumption and allocator release counts. Reject the source-not-poisoned mutant. Compile a copied owner without consuming both copies: use it as a static counterexample, not an unbounded double-free experiment. Record whether GCC/Clang actually emit the ignored-result diagnostic.
- D4: Move a self-referential value or an inline-buffer owner: derive why copying its bytes may leave internal pointers referring to the former object. Delayed assessment hides the representation behind an opaque handle but allows duplicate handles; identify the remaining duplication attack and design checked generation/ownership tokens. Complete all thirteen cost/enforcement dimensions with evidence or a mechanism-specific non-applicability.

## Verification

Test self-move, occupied destination, empty source, repeated consumption and allocator release counts. Reject the source-not-poisoned mutant. Compile a copied owner without consuming both copies: use it as a static counterexample, not an unbounded double-free experiment. Record whether GCC/Clang actually emit the ignored-result diagnostic. Preserve predictions before execution, exact commands, source/input/toolchain identity and observed outputs. Explain independent-oracle assumptions and minimize disagreements. A supplied anchor or compiled mutant checks only its named property. Failure-side effects, ownership accounting and the required changed-condition result are pass/fail gates; finite tests cannot establish absolute mastery.

## Rubric

The metadata rubric maps each leaf to a distinct D1–D4 criterion. Require every criterion at level2 and at least two at level3 on independently attempted cases; record assistance. Apply the shared six-dimension rubric as well.

## Hints

1. The postcondition needs both destination ownership and source invalidation.
2. A debug bit cannot intercept an ordinary assignment elsewhere.
3. A warning attribute is neither an ISO C17 guarantee nor proof that a result was used correctly.

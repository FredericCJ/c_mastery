# X-T67-006: Read-only strided views and ownership boundaries

## Prerequisites

Complete the earlier domain projects and retain the named prerequisite artifacts with their contracts, ownership ledger and tests. Required learner artifacts: bytes.checked. Do not import an assessor implementation.

## Environment

Implement mechanisms locally using declared typed storage/callbacks; hosted harness and diagnostic runtimes are separate. See laboratory contract for exact dependencies. Use C17 with extensions disabled and warnings treated as errors. A diagnostic extension is identified explicitly and does not become an ISO guarantee. The full platform, pointer, callback and concurrency preconditions are in [adt/CONTRACTS.md](../../../labs/adt/CONTRACTS.md).

## Problem

Implement ad_view and ad_view_get for2D uint32 data. Nonempty views require positive strides and required_span=1+(rows-1)*row_stride+(columns-1)*column_stride<=capacity with checked arithmetic. Empty rows or columns permitNULL and zero strides; no access succeeds. Overlapping indices are allowed for this read-only view. Input storage must be live and stable; view fields are not freely forgeable.

Concrete inputs and expected results: Backing[1,2,99,3,4],shape2x2,strides3/1 yields4 at(1,1) and needs5elements; capacity4fails. Shape0x3 is empty. Strides1/1 admit read-only overlap.

Supplied artifacts: labs/adt/include/adt.h, compiling unsolved src/adt.c, CTest adt.views, fixtures/adt/PR-T67-06.json, and the shared contracts. State every additional backend assumption before running it.

## Necessity

Derive required backing extent from shape and strides, including empty shapes and overflow, and distinguish a read-only overlapping view from a mutable injective layout. The misconception and changed-condition case below are separately assessed; ordinary successful execution alone does not cover them.

## Reasoning

Prove multiplication and addition guards before computing the last element offset; explain why logical element count need not equal required span. Compare span contiguous access and mdspan layout_stride preconditions. Define when two logical indices alias and why a writable transfer needs stronger validation or an explicit alias contract. Give the abstraction function, admitted states, pre/postconditions, ownership graph, failure effects and complexity before implementation. Identify the enforcement boundary of every safety claim using the shared modern-cost contract. Distinguish an invalid caller object from an operational failure admitted by the API.

## Deliverables

- D1: Derive required backing extent from shape and strides, including empty shapes and overflow, and distinguish a read-only overlapping view from a mutable injective layout.
- D2: Prove multiplication and addition guards before computing the last element offset; explain why logical element count need not equal required span. Compare span contiguous access and mdspan layout_stride preconditions. Define when two logical indices alias and why a writable transfer needs stronger validation or an explicit alias contract.
- D3: Run adt.views; enumerate small shapes/strides/capacities against a Python coordinate-set oracle. Kill row-major-assumption and missing-capacity-admission mutants. Audit zero/SIZE_MAX boundaries and distinguish arithmetic acceptance from existence of a real caller object of that extent.
- D4: Implement mutable transpose/submatrix views and a SIMD reduction adapter. Establish injectivity or documented repeated-write semantics, equivalent overflow/alias contracts, and measure scalar/vector behavior only on admitted layouts. Complete all thirteen cost/enforcement dimensions with evidence or a mechanism-specific non-applicability.

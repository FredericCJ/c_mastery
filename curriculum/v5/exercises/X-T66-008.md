# X-T66-008: Thread affinity, address pinning and asynchronous quiescence

## Prerequisites

Complete the earlier domain projects and retain the named prerequisite artifacts with their contracts, ownership ledger and tests. Required learner artifacts: memory.pool, containers.array, testing.faults, bytes.checked, io.async, errors.result. Do not import an assessor implementation.

## Environment

Implement mechanisms locally using declared typed storage/callbacks; hosted harness and diagnostic runtimes are separate. See laboratory contract for exact dependencies. Use C17 with extensions disabled and warnings treated as errors. A diagnostic extension is identified explicitly and does not become an ISO guarantee. The full platform, pointer, callback and concurrency preconditions are in [ownership/CONTRACTS.md](../../../labs/ownership/CONTRACTS.md).

## Problem

Implement OwPin as a checked protocol binding a live object address and logical thread identifier. Check rejects a changed address or wrong thread. Submit admits at most one pending operation. Cancel only records a request. Complete is the backend-supplied terminal quiescence event and clears pending/cancel. Rebind to another live address is legal only with no pending operation and the owning thread. No API moves bytes or proves native thread identity. Write an adapter for the learner io.async contract that permits rebinding only after its exactly-once terminal release, never after request cancellation.

Concrete inputs and expected results: Bind addressA/thread7, submit, cancel, attempt rebindB: BUSY and addressA remains retained. Complete then rebindB succeeds. Thread8 fails, and an address comparison using a separately live B reports STALE. Completion before submission or repeated completion is rejected.

Supplied artifacts: labs/ownership/include/ownership.h, compiling unsolved src/ownership.c, CTest ownership.pin, fixtures/ownership/PR-T66-08.json, and the shared contracts. State every additional backend assumption before running it.

## Necessity

Separate address-sensitive validity, thread affinity, guard permission and asynchronous reclamation; explain why checked assertions are weaker than a language pinning guarantee. The misconception and changed-condition case below are separately assessed; ordinary successful execution alone does not cover them.

## Reasoning

Implement the address/thread/pending state machine and an explicit io.async adapter, identifying the actual event that permits storage reuse and the lifetime of every retained address. Give the abstraction function, admitted states, pre/postconditions, ownership graph, failure effects and complexity before implementation. Identify the enforcement boundary of every safety claim using the shared modern-cost contract. Distinguish an invalid caller object from an operational failure admitted by the API.

## Deliverables

- D1: Separate address-sensitive validity, thread affinity, guard permission and asynchronous reclamation; explain why checked assertions are weaker than a language pinning guarantee.
- D2: Implement the address/thread/pending state machine and an explicit io.async adapter, identifying the actual event that permits storage reuse and the lifetime of every retained address.
- D3: Enumerate submit/cancel/complete/rebind traces with output-state canaries, include duplicate events and wrong-thread calls, and reject rebinding after cancellation while pending. Use only pointers to actual live test objects. Inspect a copied self-referential record to explain why its old internal address is wrong without dereferencing a dangling pointer.
- D4: Introduce completion callbacks on a different executor: separate ownership-thread policy from completion-notification permission and queue the terminal transition safely. Delayed assessment uses a device that may still DMA after a timeout; add a RecoveryRequired/quiescence protocol and identify the physical evidence needed before reuse. Complete all thirteen cost/enforcement dimensions with evidence or a mechanism-specific non-applicability.

## Verification

Enumerate submit/cancel/complete/rebind traces with output-state canaries, include duplicate events and wrong-thread calls, and reject rebinding after cancellation while pending. Use only pointers to actual live test objects. Inspect a copied self-referential record to explain why its old internal address is wrong without dereferencing a dangling pointer. Preserve predictions before execution, exact commands, source/input/toolchain identity and observed outputs. Explain independent-oracle assumptions and minimize disagreements. A supplied anchor or compiled mutant checks only its named property. Failure-side effects, ownership accounting and the required changed-condition result are pass/fail gates; finite tests cannot establish absolute mastery.

## Rubric

The metadata rubric maps each leaf to a distinct D1–D4 criterion. Require every criterion at level2 and at least two at level3 on independently attempted cases; record assistance. A violated ownership/failure contract, unsupported guarantee or incorrect exploitability claim fails regardless of performance. Passing only the public suite earns at most level1. Apply the shared six-dimension rubric as well.

## Hints

1. Cancellation describes intent, not backend cessation.
2. An unchanged numeric address is not a complete lifetime proof.
3. A caller-supplied thread number is a model input, not an authentication mechanism.

## Variants

Delayed assessment uses a device that may still DMA after a timeout; add a RecoveryRequired/quiescence protocol and identify the physical evidence needed before reuse.

Delayed assessment X-T66-008-DELAYED: use the separately held assessor variation at least seven days after assisted work, without the previous implementation. Record the new invariant and a counterexample to the old proof before coding.

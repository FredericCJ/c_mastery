# X-T67-001: Products, tagged sums and checked elimination

## Prerequisites

For the owning successor complete X-T66-001, X-T66-003 and X-T66-004 and retain your constructor, rollback and move reasoning. Implement the original ADValue provider before its owning adapter. No prebuilt owner library or assessor implementation is a learner dependency.

## Environment

Implement mechanisms locally using declared typed storage/callbacks; hosted harness and diagnostic runtimes are separate. See laboratory contract for exact dependencies. Use C17 with extensions disabled and warnings treated as errors. A diagnostic extension is identified explicitly and does not become an ISO guarantee. The full platform, pointer, callback and concurrency preconditions are in [adt/CONTRACTS.md](../../../labs/adt/CONTRACTS.md).

## Problem

Implement ad_measure and ad_number over ADValue: EMPTY maps to0, NUMBER to its uint32 payload, PAIR to the exact uint64 sum. Invalid enum values fail; ad_number accepts only NUMBER. Every failure preserves the output. No union payload may be read before validating the tag. Supply constructor/accessor conventions and a deliberately incomplete switch translation unit.

Concrete inputs and expected results: PAIR(UINT32_MAX,5) measures4294967300; NUMBER(0) is distinct from EMPTY despite equal measurement. Invalid tag99 leaves prior result unchanged. A PAIR requested as NUMBER leaves its output sentinel untouched.

Supplied artifacts: labs/adt/include/adt.h, compiling unsolved src/adt.c, CTest adt.sums, fixtures/adt/PR-T67-01.json, and the shared contracts. State every additional backend assumption before running it.

## Necessity

Derive product versus sum cardinality and distinguish a C union representation from an automatically checked discriminated union; show why -Wswitch-enum is a diagnostic policy, not an ISO C exhaustiveness theorem. The misconception and changed-condition case below are separately assessed; ordinary successful execution alone does not cover them.

## Reasoning

Draw all admitted tag/payload states, establish uint64 sufficiency for two uint32 values, and explain which inactive-member operations are avoided. Derive a counterexample to the claim that adding a default branch makes future variants exhaustively handled. Compare Rust enum constructors and binding behavior with C aggregate initialization and private-header discipline. Give the abstraction function, admitted states, pre/postconditions, ownership graph, failure effects and complexity before implementation. Identify the enforcement boundary of every safety claim using the shared modern-cost contract. Distinguish an invalid caller object from an operational failure admitted by the API.

## Deliverables

- D1: Derive product versus sum cardinality and distinguish a C union representation from an automatically checked discriminated union; show why -Wswitch-enum is a diagnostic policy, not an ISO C exhaustiveness theorem.
- D2: Draw all admitted tag/payload states, establish uint64 sufficiency for two uint32 values, and explain which inactive-member operations are avoided. Derive a counterexample to the claim that adding a default branch makes future variants exhaustively handled. Compare Rust enum constructors and binding behavior with C aggregate initialization and private-header discipline.
- D3: Run adt.sums and compile the missing-enumerator probe with -Wswitch-enum -Werror. Both semantic mutants must fail: omitted second product member and silently accepted invalid tag. Add every variant and invalid boundary, inspect enum size without assuming it is the wire tag size, and compare debug/release generated branches.
- D4: Add an owning text variant with a failing clone callback. Derive copy/drop/rollback and exhaustiveness obligations for every old eliminator; demonstrate which clients fail compilation and which silently preserve a default path. Complete all thirteen cost/enforcement dimensions with evidence or a mechanism-specific non-applicability.

Failure-side effects, ownership accounting and the required changed-condition result are pass/fail gates; finite tests cannot establish absolute mastery.

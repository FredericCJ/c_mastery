# X-T03-001: Cursor and subview composition

## Prerequisites

Complete X-T04-001 and the T03.04–T03.06 reading. Bring its checked-extent implementation and test evidence. If `bytes.cursor` is already accepted, import its contract/source revision and document how `FCursor` becomes `FDCursor`; the parent `f_take` contract remains unchanged. Know arrays, one-past pointers and ownership of borrowed views.

## Environment

Apply [shared contract v1](shared-contract.md). The byte component is profile C; the host supplies actual live arrays. A null base is allowed only with length and position zero. Non-null base plus advertised length is a caller object/lifetime obligation, not something portable C can authenticate by inspecting address bits.

## Problem

Implement `fd_take(cursor,count,out)` and `fd_subview(parent,offset,count,out)` from `depth.h`. A valid cursor has `position <= length` over a single backing array. On take success, output points at the start of the admitted window and position advances by count; on failure both remain unchanged. Count zero at the end succeeds without dereferencing one-past. Null-plus-zero produces a null empty view without performing null pointer arithmetic.

Subview offset is relative to the parent's unconsumed window. A successful subview has length=count and position=0, and leaves a distinct parent unchanged. `out==parent` is deliberately permitted: snapshot the input before publication. A rejected subview preserves both. Null control/output pointers or malformed cursor state return `FD_INVALID`; an admitted cursor with an insufficient requested extent returns `FD_RANGE`.

Supplied inputs include a real six-byte array `{10,20,30,40,50,60}`: at position 1, subview offset 2/count 2 describes 40,50; taking 2 from that child consumes exactly those bytes. The parent remains at 1 unless it is explicitly the output object. Do not change the API by copying the backing data.

## Necessity

Checking `pointer + length` after forming it can already violate the object model. Successive subviews can silently change the base of a bound argument. Tests of ordinary nonempty input miss empty/null states, one-past formation and transactional aliasing.

## Reasoning

State the abstraction function as the remaining sequence and show containment through two nested subviews. Every address formation needs an already established same-array and index proof. Prove addition/subtraction checks safe; explain why integer offsets can avoid a `ptrdiff_t` representability assumption. Account for unchanged output and state at every reject point.

A returned view borrows storage; neither cursor owns or prolongs its lifetime. Give a counterexample to the claim that passing pointer/length checks establishes valid backing memory, without evaluating an invalid pointer. Complexity is O(1) work and storage; no scan, allocation, integer-to-pointer reconstruction or unrelated-pointer order is allowed.

## Deliverables

- **D1:** nested-array/borrow diagram, formation proof and complete success/failure transition table.
- **D2:** both functions, a `bytes.cursor` adapter/compatibility note and a composed consumer.
- **D3:** finite state enumeration, independently modeled windows, sentinel tests and one failure-before-formation diagnosis.
- **D4:** changed slicing representation plus lifetime and resource defense.

## Verification

Run `foundation_depth.cursor`. For actual arrays of lengths 0 through 8, enumerate valid positions and requests through length+1, including all nested subviews. Model windows as integer sequence slices independently of pointer arithmetic. Check partition equivalence: two successful takes of a and b identify the same concatenated bytes and final position as one take of a+b when that sum is admitted.

Test malformed position>length, null+nonzero state, zero count at every position, exhaustion, `SIZE_MAX` counts/offsets, output sentinels and `out==parent`. Do not manufacture a false object extent to see whether the implementation detects it. Run an isolated mutant that advances before final admission; reject it with state preservation. Diagnose a form-before-check variant statically; do not require observing undefined behavior.

## Rubric

Each objective has its own criterion in metadata. A correct returned byte sequence without a formation/lifetime proof earns at most 1 for memory/ownership. Passing finite tests cannot compensate for assuming valid memory solely from a non-null pointer. Level 3 requires independent nested composition after an interface change.

## Hints

1. Express the remaining extent using validated indices before thinking about addresses.
2. A zero-length view needs a representation policy; it does not need a dereference.
3. Preserve an input snapshot when the output cursor can be the parent object.

## Variants

Delayed assessment identifier: `X-T03-001-DELAYED`. Attempt it at least seven days after the recorded studied event; the recommended interval is one to two weeks.

Change subviews to retain an owner plus absolute offset instead of rebasing the pointer. Then integrate a consumer that parses a prefix and rolls back on later failure; specify whether rollback belongs to the consumer or cursor. Delayed assessment replaces a contiguous backing array with segmented storage: identify why the old pointer-view contract no longer works and implement a bounded copy-out iterator.

## Security

Only real local arrays and synthetic bounds are used. Invalid metadata may be rejected; a malicious forged address cannot be safely validated by this API. No arbitrary memory probe or external target is part of the exercise.

## Validation

Authored specification with a scaffolded execution contract. Public tests are guided checks. Independent diagnosis and delayed transfer remain separate gates. Cross-target compilation and execution require their own evidence.

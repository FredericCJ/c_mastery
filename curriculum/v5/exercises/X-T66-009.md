# X-T66-009: Adversarial allocation through the existing typed callback ABI

## Prerequisites

Complete the earlier domain projects and retain the named prerequisite artifacts with their contracts, ownership ledger and tests. Required learner artifacts: memory.pool, containers.array, testing.faults, bytes.checked, io.async, errors.result. Do not import an assessor implementation.

## Environment

Implement mechanisms locally using declared typed storage/callbacks; hosted harness and diagnostic runtimes are separate. See laboratory contract for exact dependencies. Use C17 with extensions disabled and warnings treated as errors. A diagnostic extension is identified explicitly and does not become an ISO guarantee. The full platform, pointer, callback and concurrency preconditions are in [ownership/CONTRACTS.md](../../../labs/ownership/CONTRACTS.md).

## Problem

Implement ow_allocator as a V4Allocator adapter over OwAllocator: eight actual int32_t[16] blocks, each admitting a positive requested prefix of1..16. Count every take attempt; fail exactly on a configured1-based attempt or when size/capacity is invalid. Successful take chooses a free block, initializes its requested prefix to INT32_MAX and updates live/peak counts. Release accepts an exact currently live base pointer, fills its requested prefix with INT32_MIN, frees its slot and increments release count. Invalid or duplicate release increments a diagnostic counter without touching storage. Counters never wrap: an exhausted attempt counter refuses allocation and sets a sticky flag; other counters saturate with the flag.

Concrete inputs and expected results: Take16 succeeds; fail-at2 makes take1 return null. Live1,peak1,attempts2. Release poisons all16 requested elements, gives live0/releases1; a second release only records an invalid-release event. Starting attempts at SIZE_MAX refuses allocation and leaves it at SIZE_MAX.

Supplied artifacts: labs/ownership/include/ownership.h, compiling unsolved src/ownership.c, CTest ownership.allocator, fixtures/ownership/PR-T66-09.json, and the shared contracts. State every additional backend assumption before running it.

## Necessity

The misconception and changed-condition case below are separately assessed; ordinary successful execution alone does not cover them.

Identify the enforcement boundary of every safety claim using the shared modern-cost contract. Distinguish an invalid caller object from an operational failure admitted by the API.

# X-T65-008: Contract off, observe and enforce modes with safe violation traces

## Prerequisites

Use the existing bytes.checked, parser.integer, io.stream and codec.records contracts as comparison boundaries. Complete C17 tagged-union, pointer-lifetime and function-pointer reasoning first. Preserve the learner's earlier implementations; do not import an assessor solution. Complete X-T65-007 first.

## Environment

Original C mechanisms; hosted setjmp/longjmp only for the explicit jump boundary. Host harness may use stdio/Python. No strict freestanding claim. C17, Linux x86-64, GCC and Clang with -Wall -Wextra -Wpedantic -Werror and extensions disabled. The exact shared contract is [errors/CONTRACTS.md](../../../labs/errors/CONTRACTS.md). C editions, language-level guarantees and implementation observations must be labeled separately.

## Problem

Implement er_contract_counter on a caller-owned counter in0–100 and amount in-100–100. The candidate counter+amount is safely representable on every supported C int. The contract predicate is that the candidate remains0–100. OFF clamps and commits without reporting; OBSERVE increments reports on a violation, then clamps and commits; ENFORCE increments reports and returns ER_CONTRACT with counter unchanged. On report-count exhaustion return ER_RANGE before changing either object. Invalid mode, null objects or out-of-domain initial inputs return ER_INVALID unchanged. This is an original local state-integrity experiment, not a general safe unchecked-call API.

Concrete expected cases: Starting counter90/reports0, adding20 in ENFORCE returns CONTRACT,90,1; OBSERVE then produces OK,100,2; OFF adds no report. With reports=SIZE_MAX an observed violation rejects without wraparound.

Supplied artifacts: labs/errors/include/errors.h, compiling unsolved src/errors.c, the named CTest errors.contracts, and fixtures/errors/PR-T65-08.json. No installed package may supply the mechanism under assessment.

## Necessity

Separate diagnostic observation, enforced rejection and C undefined behavior; explain why disabling assert can remove argument evaluation. An ordinary nominal call does not assess this distinction. The two isolated mutants and the changed-condition case expose different incorrect explanations.

## Reasoning

Implement explicit contract modes with bounded arithmetic, report-counter overflow handling and failure-side-effect accounting. State the preconditions, postconditions, valid representation states, ownership and failure effects before implementation. Derive operation and storage bounds; distinguish caller misuse from a reported operational failure. Compare the C protocol with the exact inspected source scope: C type compatibility and diagnostics do not supply automatic ownership, exhaustive matching or proof of a runtime predicate.

## Security

Only original local curriculum code in `labs/errors` and synthetic inputs; no network, real data, privilege changes or deployed target. 
Target: er_contract_counter in `labs/errors` in OFF, OBSERVE and ENFORCE modes and the two variants the Problem names.

Adversary: you choose the mode, counter (0..100), amount (-100..100) and starting report count (including SIZE_MAX), plus invalid modes and null objects. You do not control the predicate or the report counter except through the function.

Violated property: ENFORCE must leave the counter unchanged on a violation, each observed violation is counted once, and report exhaustion must neither wrap nor change either object.

Evidence to capture: run `errors.contracts` and `errors.modes_base` on the correct build and record the status, counter and report count after each call from counter 90 and reports 0: ENFORCE amount 20 gives ER_CONTRACT, 90, 1; OBSERVE gives ER_OK, 100, 2; OFF gives ER_OK, 100, 2; and with reports = SIZE_MAX the call returns ER_RANGE with both objects unchanged. Then build the two variants the Problem names, a missing-report OBSERVE and an ENFORCE that still commits, and quote the `ER_CHECK:<line>:...` or `ER_CHECK ECM line<N>: ...` text that rejects each; the counter reaching 100 under ENFORCE is the integrity violation.

Impact class: demonstrated-invariant-violation, shown only by the missing-report and enforce-still-commits variants you build; the supplied tests pass on a correct build and no supplied artifact demonstrates it. A state-integrity violation is not a claim of code execution; a crash or sanitizer finding would be a weaker class.

Remediation: evaluate the predicate per mode on a safely representable candidate and check report capacity before changing either object. The regression tests are the existing `errors.contracts` and `errors.modes_base`; they must fail on your two variants and pass on the repair.

Limitations: An original local state-integrity experiment on caller-owned integers, not a general safe unchecked-call API; the ER_INVALID rows and the all-inputs enumeration against an integer model are separate deliverables, and concurrent use needs the external serialization described in labs/errors/contract_modes/MODES.md.

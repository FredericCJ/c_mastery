# X-T14-016: Path-copy B-tree versions, retained roots and tombstone vacuum

## Prerequisites

Know sorted maps, typed arrays, half-open bounds, unsigned arithmetic and strong failure publication. Bring a small exact map oracle and invariant traces from the retained container/search work. Tree work additionally requires ordinary B-tree splits and ownership/reachability; runs require stable merge and version ordering. No library may implement the assessed mechanism. These new required exercises do not inherit historical elective exclusions.

## Environment

The explicit [ordered storage contract1](../../../labs/corpus_storage/CONTRACTS.md) supplies all representations, operations, input/output domains, ownership, statuses, capacity/work bounds and security scope. Implement `src/storage.c`. Distinguish compiler helpers from target dependencies and host oracles. Changing ABI, optimization or execution environment requires revisiting stack/copy measurements and helper closure; no strict linked-image claim is made.

## Problem

Implement immutable published pages, bottom-up splits and eight root slots over256 typed pages. Snapshot the empty map, insert32 permuted keys, retain a second version, replace a value and lazily erase even keys. Reclaim unreachable pages and vacuum the current version while both retained versions keep their original contents. Inject every actual allocation failure and prove unchanged publication.

## Necessity

A copied root pointer does not preserve a snapshot if a shared descendant is edited. Reclamation from only the current root can destroy an older reader. Logical path-copy costs differ from whole-owner staging, and memory publication does not establish disk crash consistency. Lazy deletion and structural B-tree deletion are distinct policies.

## Reasoning

Derive child-range/equal-depth invariants, the1/2 split occupancy and reachability from every root. State token ownership, generation retirement and live-owner preconditions. Prove staged rollback for insertion, lazy erase and vacuum, including retained-root pressure. Account for logical page copies, full staging, linear allocation scans and vacuum workspace. Derive the explicit durable-root-before-page counterexample under its hypothetical persistence model. Provide preconditions, postconditions, representation/loop invariants, ownership, failure and complexity arguments. Distinguish ISO C guarantees, diagnostic checks, runtime admission, external proof/model evidence and caller discipline. Include one plausible incorrect explanation and a minimal counterexample.

## Deliverables

- D1: Representation and source-claim derivation, precise contract and misconception counterexample.
- D2: Original C implementation, costs for logical operations and actual storage/copies, and operation/failure ownership ledger.
- D3: Independent model, concrete boundary/injected-failure inputs and outputs, invariant snapshots and two causal semantic mutants.
- D4: Named delayed implementation/predictions, changed-assumption comparison under equal correctness contracts, and validation limits.

## Verification

Use independent copied Python maps for current and retained versions; check every page invariant after every operation. Exhaust root slots and generation retirement, repeat stale release, inject all allocation cuts, and retain old values across update/collection/vacuum. Kill in-place shared update and current-root-only collection separately. Model page flush/root publication cuts without attributing them to a real device. Run GCC/Clang debug, optimized and address/undefined sanitizer profiles. Preserve exact commands, logs, source identities and compiler configuration. The compiling learner stub must fail `corpus_storage.tree` with `SS_ASSERT:`. A finite differential campaign supports the specified tested scope; it neither proves all histories nor replaces D1/D4.

## Security

Why this matters here. Path copying promises two things: a snapshot never sees a later write, and a page stays unchanged for as long as any live root reaches it. The pages live in a 256-entry arena inside the owner, addressed by index, so a page reclaimed too early is still perfectly valid memory. ASan and UBSan stay silent; the error shows up only as a wrong value read through an old snapshot or as an invariant failure. That is why this exercise is about modelled heap and lifetime integrity of an arena, not memory safety of real memory: a crash or sanitizer report from your variant would be a different, lesser finding and must be reported as such.

What to try. Trace by hand what ss_tree_put does to the root-to-leaf path when key 13 is overwritten while a snapshot holds the old root, and list which pages the snapshot, the current root and the garbage set each reach before and after ss_tree_collect. Then build two causal variants of your own: one in which a snapshot can observe a later write, and one in which collection frees a page that some live root still reaches. Add your own failure-injection loop for ss_tree_erase, because the public test injects allocation failures only into ss_tree_put and ss_tree_vacuum.

What to capture and how to read it. A failed check prints `SS_ASSERT:<line>:<expression>` on stderr; keep it for each variant. The pages-live check inside tree_invariant() (every page a live root reaches must be live and visited once, keys ordered within child ranges, all leaves at one depth) is what sees a collected-but-reachable page. The value checks on the key-13 snapshot and the empty-map snapshot (still SS_MISSING for key 1 after 32 inserts and collections) are what see a changed retained version. The owner-identical checks (memcmp after every injected put failure and every injected vacuum failure, with more than three vacuum failures observed) are what see a partial publication. A variant that passes is a gap in the public test, not a pass.

What this does and does not show. A changed retained value or an unreachable-yet-needed page in a serialized RAM model, on synthetic keys. No supplied artifact demonstrates it, so the impact class holds only once you build the variant. The assessor's mutation set also checks this invariant. Concurrent readers, torn writes, flush ordering, hazard-pointer reclamation, corrupt owners and forged pointers are outside this contract; the hypothetical page-write cuts in the contract are counterexamples about crash consistency, not an implemented disk protocol, and lazy tombstones are not structural deletion.

# X-T66-007: Copy-on-write values with transactional detach

## Prerequisites

Complete the earlier domain projects and retain the named prerequisite artifacts with their contracts, ownership ledger and tests. Required learner artifacts: memory.pool, containers.array, testing.faults, bytes.checked, io.async, errors.result. Do not import an assessor implementation.

## Environment

Implement mechanisms locally using declared typed storage/callbacks; hosted harness and diagnostic runtimes are separate. See laboratory contract for exact dependencies. Use C17 with extensions disabled and warnings treated as errors. A diagnostic extension is identified explicitly and does not become an ISO guarantee. The full platform, pointer, callback and concurrency preconditions are in [ownership/CONTRACTS.md](../../../labs/ownership/CONTRACTS.md).

## Problem

Implement OwCow over caller-owned live controls and int32_t arrays acquired through V4Allocator. Clone increments a nonzero reference count with overflow refusal. A write to a unique owner changes its element in place without allocation. A shared write requires a distinct empty fresh control: allocate the same length, copy all elements locally, apply the update, initialize the fresh control, decrement old references and publish the caller owner pointer. A failed allocation or invalid index/control leaves all old owners, counts, values and fresh output unchanged. Drop releases backing storage only on the last reference; the caller controls metadata lifetime.

Concrete inputs and expected results: Two references to[1,2,3], write index1=9, fail-at2: NOMEM and both logical values remain[1,2,3]. Retry succeeds with old[1,2,3], new[1,9,3], one reference each and two buffers. Dropping both releases both buffers. A unique write must leave allocator attempts unchanged.

Supplied artifacts: labs/ownership/include/ownership.h, compiling unsolved src/ownership.c, CTest ownership.cow, fixtures/ownership/PR-T66-07.json, and the shared contracts. State every additional backend assumption before running it.

## Necessity

Explain logical value independence, shared representation and detach cost; distinguish copy-on-write from a deep copy guarantee or automatically synchronized shared mutation. The misconception and changed-condition case below are separately assessed; ordinary successful execution alone does not cover them.

## Reasoning

Implement reference sharing, failure-preserving detach, unique mutation and last-owner release with explicit control-block and mutable-borrow lifetimes. Give the abstraction function, admitted states, pre/postconditions, ownership graph, failure effects and complexity before implementation. Identify the enforcement boundary of every safety claim using the shared modern-cost contract. Distinguish an invalid caller object from an operational failure admitted by the API.

## Deliverables

- D1: Explain logical value independence, shared representation and detach cost; distinguish copy-on-write from a deep copy guarantee or automatically synchronized shared mutation.
- D2: Implement reference sharing, failure-preserving detach, unique mutation and last-owner release with explicit control-block and mutable-borrow lifetimes.
- D3: Compare every owner value to independently copied Python lists across clone/write/drop traces, inject allocation failure at each detach, test index bounds and reference overflow, and count allocations/copies for unique versus shared mutation. Reject a mutant that writes shared backing in place. Check that a borrowed mutable alias cannot legally survive cloning.
- D4: Change the backing value to contain owned resource handles whose copies can fail: derive a partial-clone frontier and rollback. Delayed assessment permits concurrent readers and one writer; define snapshot publication, reference acquisition and reclamation rather than relying on the non-atomic COW counter. Complete all thirteen cost/enforcement dimensions with evidence or a mechanism-specific non-applicability.

## Verification

Compare every owner value to independently copied Python lists across clone/write/drop traces, inject allocation failure at each detach, test index bounds and reference overflow, and count allocations/copies for unique versus shared mutation. Reject a mutant that writes shared backing in place. Check that a borrowed mutable alias cannot legally survive cloning. Preserve predictions before execution, exact commands, source/input/toolchain identity and observed outputs. Explain independent-oracle assumptions and minimize disagreements. A supplied anchor or compiled mutant checks only its named property. Failure-side effects, ownership accounting and the required changed-condition result are pass/fail gates; finite tests cannot establish absolute mastery.

## Rubric

The metadata rubric maps each leaf to a distinct D1–D4 criterion. Require every criterion at level2 and at least two at level3 on independently attempted cases; record assistance. A violated ownership/failure contract, unsupported guarantee or incorrect exploitability claim fails regardless of performance. Passing only the public suite earns at most level1. Apply the shared six-dimension rubric as well.

## Hints

1. Allocate and populate the replacement before decrementing the old count.
2. Logical independence depends on forbidding mutations through stale private aliases.
3. A shared buffer plus reference count is not enough if clients can write its elements directly.

## Variants

Delayed assessment permits concurrent readers and one writer; define snapshot publication, reference acquisition and reclamation rather than relying on the non-atomic COW counter.

## Security

Why this matters here. A byte channel is where a lower-privilege caller meets a message it must not necessarily read, and where a failed copy-out can lose it. Two properties carry that: receive needs the RECEIVE right (a SEND-only capability must get SD_DENIED and leave the message queued), and a receive that fails after the checks (a destination that is too small, or a validator that refuses the span) must not consume the message. The third is lifetime: after close and reopen the epoch changes, so a capability from the old epoch must stop working. None of these produces a crash when it is wrong; the evidence is a status, a queue count and a canary byte.

What to try. Trace the test's first receives by hand. Message {1,0,255} is queued; receive through the SEND-only capability must return SD_DENIED with `q.count == 1` and `n == 99`; receive through the RECEIVE capability with a validator that refuses must return SD_COPY with the count unchanged and `out[0]` still the canary 77; a 2-byte destination must return SD_FULL, count unchanged. Then follow the lifecycle: close, drain exactly three bytes, SD_CLOSED, reopen, and the old SEND capability returning SD_STALE. Note also that sd_grant from the RECEIVE-only capability asking for rights 3 is refused, so a capability cannot gain rights by being passed on. Then build two variants of your own: one where a capability lacking RECEIVE can still take a message, and one where a refused receive leaves the queue shorter.

What to capture and how to read it. Run `service_depth-tests channel` and keep the `SD_CHECK:<line>:<expression>` each variant reaches, mapped to the check in labs/service_depth/tests/tests.c: the SEND-only receive, the validator refusal with the canary, the small destination, the grant refusal, the close/drain/closed sequence, the stale capability after reopen, the zero-length NULL send and receive (including a refusal by the validator on a zero-length span), and retirement at epoch UINT32_MAX. A variant that survives is a gap in the public test, not a pass.

What this does and does not show. A byte delivered without permission or a lost message, in a two-slot model, on synthetic bytes. No supplied artifact demonstrates it, so the impact class holds only once you build a variant. The assessor's mutation set also checks this invariant. A callback that checks a transient page table does not give the stable copy-out proof the Problem asks you to derive, real user-copy races, page faults and concurrency are not exercised, and a crash from your variant would be a lesser finding, not privilege escalation.

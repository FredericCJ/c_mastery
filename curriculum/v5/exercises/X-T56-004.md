## Problem

Implement sd_files_init/open/dup/seek/read/close over entries alpha="0123456789" and empty={NULL,0}. Two opens start independently: reads3 and4 yield012 and0123. Duplicate the first handle; reading2 through its duplicate yields34 and reading1 through the original yields5. Denied read2 must leave that shared offset6 and output unchanged; the next read1 yields6. Seek end-1 then read3 returns9 only, and EOF permits NULL with length0. Reject negative/out-of-range seeks, ../alpha, duplicate names, stale closes, exhausted handles and generation wrap. Borrowed archive bytes must remain live until the last description closes.

## Security

Target: sd_files_init/open/dup/seek/read/close in `labs/service_depth` over alpha="0123456789" and an empty entry, and the early-advance and private-offset variants you build. Local unprivileged process over the original service_depth teaching code with synthetic objects only; no arbitrary writes to protected controls, no real syscalls, hardware or production targets (kernel transfer uses a disposable VM). 
Adversary: you choose names (../alpha, duplicates), seek offsets (negative, out of range), read lengths, the denied-read injection, stale closes and handle exhaustion. You cannot alter the borrowed archive bytes.

Violated property: duplicated handles share one offset, a denied read leaves it unchanged, reads stay inside the entry, and the archive stays live until the last description closes.

Evidence to capture: run `service_depth-tests files` (CTest `service_depth.files`) on the correct build and record the bytes, `n` and status at each step: independent reads "012" and "0123"; duplicate read "34" then original read '5'; the denied-copy read returning SD_COPY with `n == 99` and the following read yielding '6'; seek end-1 then a 3-byte read yielding only '9'; SD_INVALID for the negative seek and for "../alpha"; SD_STALE on a repeated close; and SD_FULL on handle exhaustion. Then build a variant that advances the offset before the copy and one with per-handle offsets, and quote each `SD_CHECK:<line>:...` failure.

Remediation: share one description among duplicates and commit the offset only after a successful copy. The regression test is the existing `service_depth.files`; it must fail on your early-advance and private-offset variants and pass on the repair.

Limitations: Only an in-memory table of two synthetic entries: no real filesystem, path resolution, concurrent offset race or kernel file table is exercised, and liveness of the borrowed archive bytes is a caller discipline the test does not enforce.

## Problem

Implement RPState{tick0..8,position0..15,score0..65535,random:uint32}. rp_step consumes movement-1/0/1, wraps position on a16cell ring, advances LCG random=random*1664525+1013904223 modulo2^32, adds(random&3) with checked score limit and returns RPEffect{tick,score} as data. No clocks,I/O,allocation or callbacks occur in the reducer. rp_replay stages at most8 steps and effects, preserving outputs on failure. Restore the state before a changed input and replay the suffix; compare with a fresh fold of corrected inputs. rp_checkpoint composes two actual HAMT updates for position/score under one root publication and injects failure at each of6allocation ordinals; it is a projection checkpoint, not the full replay snapshot (tick/random remain in the explicit RPState snapshot).

Concrete inputs and expected results: Initial(0,0,0,1),movement-1 gives position15,random1015568748,score0; next movement1 gives position0,score3. Eight inputs[1,1,0,-1,1,0,1,-1] produce score12. Replacing input4 with1 and replaying from the prior snapshot equals a fresh corrected fold. All six checkpoint failure cuts preserve the published root and used count.

Supplied artifacts: labs/replicated/include/replicated.h, compiling unsolved src/replicated.c, CTest replicated.replay, fixtures/replicated/PR-T76-09.json, and the shared contracts. State every additional backend assumption before running it.

## Security

Target only the reducer, replay and checkpoint in [labs/replicated](../../../labs/replicated), the synthetic effect adapter, and the supplied hidden-random reducer in `replay_depth/oracle_driver.c`.

- **Adversary.** You control the movement history (-1, 0 or 1, length 0..8), a changed input to replay, the allocation-failure ordinal 1..6 during rp_checkpoint (tests.c:258-263), and whether a replay re-invokes the effect adapter. You do not control the LCG constants, code, pointers or any real effect target. Worked trace: from state (tick 0, position 0, score 0, random 1) movement -1 gives position 15, score 0 and random 1015568748; movement +1 then gives position 0, score 3 and an effect at tick 2 (tests.c:241-245).
- **Violated property.** Deterministic replay and atomic checkpoint. Replaying the first three inputs and then the corrected suffix must equal a fresh fold of the corrected inputs in position, score and random (tests.c:250-255); this holds only if the snapshot carries every piece of state the reducer reads. The supplied hidden-random reducer breaks exactly that: its LCG state is a global left out of the snapshot, so the replay of inputs {1,2,3} yields a different sum than the first run. An effect must also apply at most once per (timeline, tick), and a failed checkpoint leaves the published root and used count unchanged.
- **Experimental boundary.** replicated.replay is in-process. replicated.replay_native forks two children over an AF_UNIX socketpair and uses two unlinked mkstemp files under /tmp (native.c:142-181, 228-230). The counterexample program and effect_adapter.c count in process memory. No network and no real side effects.
- **Evidence to capture.** Predict first, then run CTest replicated.replay and record the CHECKs (position 15 and random 1015568748, score 3, score 12 after eight inputs, suffix replay equal to the fresh fold, RP_FAILED with candidate 99 and unchanged arena.used for ordinals 1..6). Run replicated.replay_counterexamples and record first, replay and the external-effect count 2, noting that the 2 comes from two inline increments and is by construction; explain why a first/replay mismatch is evidence of nondeterminism only and not of its cause (the source comment says the same, oracle_driver.c:118-119). Compile and run effect_adapter.c yourself and read its counters critically: deduplicated_effects=8 and failure_prefix=3 follow from the receiver code, while unsafe_replay_effects=16 is a hand-written loop. Build the two variants from the header and record the `RP_CHECK line N` each produces. Then extend the adapter with a (timeline, tick) idempotency key and keep your own duplicate-effect counterexample.
- **Impact class.** demonstrated-invariant-violation. The divergent hidden-random replay is demonstrated by a supplied artifact (replicated.replay_counterexamples computes both folds, oracle_driver.c:118-140); the external-effect count of 2 from the same program is a scripted illustration of the hazard (two inline increments on a struct and its copy, :141-153), not a callback delivering an effect twice, so it demonstrates nothing about a real adapter; a leaking checkpoint or a score disagreement is demonstrated only when you build and run your variant. The target is synthetic, so this is not proved impact.
- **Remediation.** Pure reducer, effects as data, single-root publication with rollback, and adapter idempotency by (timeline, tick). The regression that rejects the original defect is replicated.replay; run it against both of your variants and extend effect_adapter.c.
- **Limitations.** Shows the duplicate-effect hazard only; no real side effects, durable snapshot recovery or concurrent adapter is demonstrated.

Inspect undefined symbols to confirm the core has no time, random or I/O dependency.

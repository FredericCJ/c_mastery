# X-T14-015: Skip-list ordering, deterministic state and probabilistic limits

## Prerequisites

Know sorted maps, typed arrays, half-open bounds, unsigned arithmetic and strong failure publication. Bring a small exact map oracle and invariant traces from the retained container/search work. Tree work additionally requires ordinary B-tree splits and ownership/reachability; runs require stable merge and version ordering. No library may implement the assessed mechanism. These new required exercises do not inherit historical elective exclusions.

## Environment

The explicit [ordered storage contract1](../../../labs/corpus_storage/CONTRACTS.md) supplies all representations, operations, input/output domains, ownership, statuses, capacity/work bounds and security scope. Implement `src/storage.c`. Distinguish compiler helpers from target dependencies and host oracles. Changing ABI, optimization or execution environment requires revisiting stack/copy measurements and helper closure; no strict linked-image claim is made.

## Problem

Implement the six-level,32-node typed ordered map and explicit deterministic generator. Insert keys2,0,1 with promotion words0,1,3, scan[0,3), replace a key at capacity and erase every level. Use actual unbiased bounded selection to shuffle a32-key insertion history, then replay promotion states using affine jump-ahead. Produce the all-height-one counterexample to an unconditional logarithmic claim.

## Necessity

A sorted level-zero list can appear correct while upper links are absent or dangling. A generator with full state period can still have predictable low bits and correlated heights. Modulo reduction can bias bounded choices; rejection and finite fuel introduce separate progress semantics.

## Reasoning

Derive predecessor-path invariants and geometric-height expectations under stated independent-bit assumptions. Prove the chosen recurrence period from odd increment/multiplier1 modulo4 and derive affine composition without division. Explain low-bit alternation, rejection threshold, unchanged state on exhaustion and why deterministic replay is not independent sampling. State exact scan endpoint limitations and worst-case key comparisons. Provide preconditions, postconditions, representation/loop invariants, ownership, failure and complexity arguments. Distinguish ISO C guarantees, diagnostic checks, runtime admission, external proof/model evidence and caller discipline. Include one plausible incorrect explanation and a minimal counterexample.

## Deliverables

- D1: Representation and source-claim derivation, precise contract and misconception counterexample.
- D2: Original C implementation, costs for logical operations and actual storage/copies, and operation/failure ownership ledger.
- D3: Independent model, concrete boundary/injected-failure inputs and outputs, invariant snapshots and two causal semantic mutants.
- D4: Named delayed implementation/predictions, changed-assumption comparison under equal correctness contracts, and validation limits.

## Verification

Check all levels after insert/replace/erase and every failed capacity admission. Compare generated operations to an exact dictionary, all1024 height prefixes and replay/jump histories. Exhaust small-state periods and compare naive versus accepted residue counts. Force a generator state whose next value is rejected and show budget1 rollback then budget2 success. Kill missing upper insertion and missing upper deletion independently. Run GCC/Clang debug, optimized and address/undefined sanitizer profiles. Preserve exact commands, logs, source identities and compiler configuration. The compiling learner stub must fail `corpus_storage.skip` with `SS_ASSERT:`. A finite differential campaign supports the specified tested scope; it neither proves all histories nor replaces D1/D4.

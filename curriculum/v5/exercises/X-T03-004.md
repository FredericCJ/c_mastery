# X-T03-004: Overlap and restrict

## Prerequisites

Complete X-T03-001 and read T03.09 and the overlap portion of T03.14. Bring same-array offset/extent proofs and the cursor artifact. Know that a pointer address is not an array's entire access contract. No existing byte-move library is a permitted implementation dependency.

## Environment

Apply [shared contract v1](shared-contract.md). Use real byte arrays with profile C. No unrelated-pointer relational comparison or integer-address ordering is used to infer overlap. Hosted tests may use an independent snapshot array or library memmove as an additional oracle, with its preconditions stated.

## Problem

Implement two distinct interfaces from `depth.h`.

`fd_transform(destination,source,count,mask)` writes source byte XOR mask to each corresponding destination byte. For positive count both windows must be live and disjoint. The restrict-qualified signature requires its valid-access association, not merely unequal base pointers. At count zero the function accesses no storage and permits null pointers.

`fd_move(base,length,destination,source,count)` performs snapshot-equivalent movement between offsets in one real array. Both starts may equal length only for an admitted empty window. Verify both extents before mutating. All bytes outside the destination window remain unchanged. A null base with length zero is admitted for empty valid offsets. Null base with nonzero length rejects as `FD_INVALID`; out-of-bounds windows reject as `FD_RANGE` without writing. Equal windows are an admitted identity operation. Constant temporary storage is required; no variable-length scratch copy.

On initial bytes `{0,1,2,3,4,5}`, movement from source 0 to destination 1 with count 4 produces `{0,0,1,2,3,5}`. The reversed direction must likewise preserve original source values, not values overwritten during copying.

## Necessity

A forward-only loop can be correct for disjoint ranges and wrong for one overlap direction. Different addresses do not imply disjoint extents. Replacing a restricted declaration or disabling optimization can hide symptoms without establishing a valid advertised contract.

## Reasoning

Draw accessed-object sets and restricted-pointer associations for each transform execution. Analyze adjacent windows, partial overlap, equal bases with zero count and a prohibited positive count. Do not assign expected runtime outputs to prohibited restrict calls.

For movement, derive a direction invariant from source/destination offsets inside the same array. Prove read-before-overwrite and preservation outside the destination. Bounds admission precedes all access and mutation. Give O(count) byte operations and O(1) temporary storage; include compiler-emitted memory helpers in the dependency audit.

## Deliverables

- **D1:** access-set diagrams, restrict authority ledger, movement invariant and invalid-execution analyses.
- **D2:** both implementations and a bounded cursor-driven compaction consumer.
- **D3:** snapshot-oracle enumeration, unchanged-state checks, killed forward-only mutant and regression.
- **D4:** equivalent-contract optimized-code comparison and delayed overlap-policy transfer.

## Verification

Run `foundation_depth.overlap`. For arrays of length 0–8, enumerate every valid source, destination and count; independently snapshot the complete original array and assign expected destination bytes from that snapshot. Include invalid offset/count neighbors and `SIZE_MAX` without forming bad pointers. Compare every byte, not just destination contents.

Test disjoint transforms at zero/singleton/larger sizes and masks 0/255; test valid overlapping movement in both directions, identity and adjacency. Keep prohibited transform calls analysis-only. Kill a compiling forward-only move with a positive-overlap regression. Compare restricted and nonrestricted disjoint transforms under -O0/-O2/-O3 where supported; identical output/assembly is a permissible observation. Report actual generated code and dependency closure, not an assumed vectorization benefit.

## Rubric

Each objective's metadata criterion separates restriction semantics, movement correctness and measurement. A working result from an invalid restricted call earns no credit. A repair that changes the admitted API silently fails. Level 3 adapts an in-place policy and re-derives every affected proof.

## Hints

1. Mark which original byte each destination must receive before drawing a loop.
2. Find the first source byte destroyed by a forward copy in the failing direction.
3. Restrict is about accesses through associations during execution; base inequality is only one incomplete clue.

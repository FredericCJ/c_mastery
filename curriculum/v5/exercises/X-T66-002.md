# X-T66-002: Scoped cleanup, conditional undo and publication by swap

## Prerequisites

Complete the earlier domain projects and retain the named prerequisite artifacts with their contracts, ownership ledger and tests. Required learner artifacts: memory.pool, containers.array, testing.faults, bytes.checked, io.async, errors.result. Do not import an assessor implementation.

## Environment

Implement mechanisms locally using declared typed storage/callbacks; hosted harness and diagnostic runtimes are separate. See laboratory contract for exact dependencies. Use C17 with extensions disabled and warnings treated as errors. A diagnostic extension is identified explicitly and does not become an ISO guarantee. The full platform, pointer, callback and concurrency preconditions are in [ownership/CONTRACTS.md](../../../labs/ownership/CONTRACTS.md).

## Problem

Implement an eight-entry OwScope with ow_defer(fn,context,when) and ow_finish(success), where when is ALWAYS, ON_ERROR or ON_SUCCESS and success is exactly0 or1. Reject a full stack or registration during finish without changing it. Pop each entry before calling its callback, execute applicable callbacks in reverse registration order, and empty the stack even when a conditional callback is skipped. Finish on empty is idempotent. Implement ow_publish for two disjoint valid owners: the staged owner must be fully constructed, publication transfers it to the destination and then releases the former destination. No callback failure, reentrancy or longjmp is admitted.

Concrete inputs and expected results: Register digits1 ALWAYS,2 ON_SUCCESS,3 ON_ERROR. Failure produces trace31; success produces21; a second finish appends nothing. Publishing three staged blocks over three old blocks leaves exactly three live blocks and consumes the staged owner.

Supplied artifacts: labs/ownership/include/ownership.h, compiling unsolved src/ownership.c, CTest ownership.scope, fixtures/ownership/PR-T66-02.json, and the shared contracts. State every additional backend assumption before running it.

## Necessity

Explain when a cleanup stack is a resource protocol, when an undo log is a semantic rollback protocol, and why neither automatically reverses already published external effects. The misconception and changed-condition case below are separately assessed; ordinary successful execution alone does not cover them.

## Reasoning

Implement conditional LIFO cleanup and publication-by-swap with explicit callback effects, stack capacity, transferred ownership and nonlocal-exit restrictions. Give the abstraction function, admitted states, pre/postconditions, ownership graph, failure effects and complexity before implementation. Identify the enforcement boundary of every safety claim using the shared modern-cost contract. Distinguish an invalid caller object from an operational failure admitted by the API.

## Deliverables

- D1: Explain when a cleanup stack is a resource protocol, when an undo log is a semantic rollback protocol, and why neither automatically reverses already published external effects.
- D2: Implement conditional LIFO cleanup and publication-by-swap with explicit callback effects, stack capacity, transferred ownership and nonlocal-exit restrictions.
- D3: Enumerate all success/failure policy combinations through depth4 against an independent reversed-list filter, test capacity8/9 and callback reentrancy rejection, inject failure before every registration, and trace publication before old cleanup. Kill a mutant that executes every conditional cleanup.
- D4: Integrate cleanup.scope with the T65 typed jump boundary through an adapter that converts a raised error before final cleanup. Delayed assessment introduces a cleanup action that can fail: derive an explicit recovery-required result and retained owner rather than silently pretending the old void-callback contract still applies. Complete all thirteen cost/enforcement dimensions with evidence or a mechanism-specific non-applicability.

## Hints

1. Success and failure policies select entries; they do not alter stack order.
2. Remove an entry before calling user code.
3. A callback that can longjmp breaks the exactly-once argument unless another boundary owns the remaining stack.

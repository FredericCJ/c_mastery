# X-T67-008: Lenses and prisms with falsifiable laws

## Prerequisites

Complete the earlier domain projects and retain the named prerequisite artifacts with their contracts, ownership ledger and tests. Required learner artifacts: . Do not import an assessor implementation.

## Environment

Implement mechanisms locally using declared typed storage/callbacks; hosted harness and diagnostic runtimes are separate. See laboratory contract for exact dependencies. Use C17 with extensions disabled and warnings treated as errors. A diagnostic extension is identified explicitly and does not become an ISO guarantee. The full platform, pointer, callback and concurrency preconditions are in [adt/CONTRACTS.md](../../../labs/adt/CONTRACTS.md).

## Problem

Implement ad_lens_x preserving the y field of ADPair, plus ad_review_number and ad_preview_number over ADValue. Preview is partial and leaves output unchanged on non-NUMBER. Enumerate x,y,replacements0..3 and all variant classes; state purity and equality assumptions explicitly.

Concrete inputs and expected results: Setting x of(1,2)to3 gives(3,2); setting it toitscurrent1 preserves bothfields. Preview(review(3))=3; preview(EMPTY)fails without publishing0.

Supplied artifacts: labs/adt/include/adt.h, compiling unsolved src/adt.c, CTest adt.optics, fixtures/adt/PR-T67-08.json, and the shared contracts. State every additional backend assumption before running it.

## Necessity

Derive lens get-put, put-get and put-put laws and prism review/preview round trips; explain how lawful optics differ from arbitrary field mutation helpers. The misconception and changed-condition case below are separately assessed; ordinary successful execution alone does not cover them.

## Reasoning

Write each law as an executable predicate and derive which information an update may change. Compare the C functions with the inspected lens type laws; C types do not enforce those laws. Distinguish field equality from raw struct memcmp because padding need not encode semantic identity. Give the abstraction function, admitted states, pre/postconditions, ownership graph, failure effects and complexity before implementation. Identify the enforcement boundary of every safety claim using the shared modern-cost contract. Distinguish an invalid caller object from an operational failure admitted by the API.

- D1: Derive lens get-put, put-get and put-put laws and prism review/preview round trips; explain how lawful optics differ from arbitrary field mutation helpers.
- D2: Write each law as an executable predicate and derive which information an update may change. Compare the C functions with the inspected lens type laws; C types do not enforce those laws. Distinguish field equality from raw struct memcmp because padding need not encode semantic identity.
- D3: Run adt.optics:256combinations assess get-put/put-get/put-put and prism round trips. Kill the collateral-y-write and EMPTY-as-NUMBER mutants. Add composition of nested pairs, identify a law violated by a clamping setter, and explain why exhaustive small domains are not proof for arbitrary callback optics.
- D4: Implement a lens into an optional nested configuration and a prism for a versioned error sum. Decide which updates are partial, state revised laws, and produce counterexamples to importing total-lens laws unchanged. Complete all thirteen cost/enforcement dimensions with evidence or a mechanism-specific non-applicability.

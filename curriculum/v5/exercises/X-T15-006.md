# X-T15-006: HyperLogLog ranks, numerical corrections and precision folding

## Prerequisites

Complete the named unsigned arithmetic and algorithm exercises. Bring an invariant notebook, independent test strategy and elementary expectation/probability reasoning. Read the exact registered primary passages and relevant CONTRACTS.md section; the assessor implementation is not a prerequisite.

## Environment

Use the declared C17/profileC contract. Implement only the original component; no third-party sketch or hash library may supply its mechanism. Keep hosted I/O and Python verification separate from the component. C23 mode supplies no automatic bounds, lifetime or statistical guarantee. Pointers, ownership, serialization and hash interpretation remain explicit caller premises.

## Problem

Implement sk_hll_init, sk_hll_add, sk_hll_estimate and sk_hll_merge in src/hyperloglog.c. Inputs are prehashed32-bit words; a domain/version identity labels their interpretation. High p bits select a register and the remaining suffix determines rank. Implement the explicitly disjoint correction ranges in CONTRACTS.md and an original logarithm approximation. Empty state must estimate zero; all-zero suffixes reach rank33-p. Identical input hashes must be idempotent.

## Necessity

Exact distinct counting requires retaining growing identity information. Rank summaries use fixed storage but discard identity and depend on hash behavior. Confusing the index prefix with the rank suffix, using arithmetic mean or forgetting the empty-state correction produces a different estimator. A legal register vector can exceed the real domain of finite-hash correction; refusal must preserve the caller output.

## Reasoning

Write the rank and harmonic-indicator equations, explain initialization and the three correction ranges, and derive a truncation bound for your logarithm approximation without confusing it with floating rounding. State the ideal independent-uniform model behind asymptotic standard error and explain why it is not a deterministic relative-error bound. Include validation scans in the actual operation cost; the supplied teaching API does not promise a constant-time trusted-state update.

## Deliverables

- D1: Derivation, invariants, at least two wrong explanations with counterexamples, exact source locators and assumption/enforcement table.
- D2: Completed ordinary C17 provider, explicit build/dependency manifest, state diagrams and storage/operation cost accounting.
- D3: Independent oracle, boundary and adversarial cases, unchanged-output snapshots, two compiling semantic controls and actual GCC/Clang profile records.
- D4: Required delayed mechanism, changed-condition proof, independent comparison and failure/cost analysis.

## Verification

Compare estimates with an independent logarithm implementation under declared tolerances; force all legal uniform rank vectors to exercise small/intermediate/large/refused cases. Test merge identity mismatch and active-register max equivalence, and demonstrate a collision-heavy stream that defeats a proposed unconditional accuracy claim.

Configure labs/corpus_sketch with CMake, build and run its selected anchor. The default src files must compile then fail SK_CHECK. Supply your external completed source directory through SK_PROVIDER. Record commands, compiler versions, input/source identities and raw outcomes; reject crashes as semantic controls. The public tests are necessary examples, not a complete solution certificate. Use the full procedure in CONTRACTS.md.

## Security

The only target is the original `labs/corpus_sketch` HyperLogLog provider (`src/hyperloglog.c`), fed prehashed 32-bit synthetic words and legal register vectors in a local process; no real hash function or external service is attacked.

Adversary. The attacker chooses the 32-bit words passed to `sk_hll_add` (hence index and rank), the identity and precision of the summaries given to merge or fold, and legal synthetic register vectors such as rank 28 and 29 at p=4. The attacker cannot see or change upstream hashing, or pass illegal pointers.

Violated property. The estimate must follow the specified small-range, large-range and refusal rules, and merge or fold must refuse unequal identity or a precision increase without changing output. In the anchor `corpus_sketch.hyperloglog`, all registers at 28 give an estimate above 1e9, all at 29 give `SK_OVERFLOW` with the output still 123, and unequal identity or a precision-increasing fold returns `SK_INVALID` with an unchanged snapshot. Build variants that skip each refusal and show the anchor rejects them.

Boundary. Synthetic words and register vectors, small p, a disposable build, and your independent Python oracle as judge. Success is a differing double or status, not a compromised host.

Evidence to capture. Run `ctest -R corpus_sketch.hyperloglog`. Capture the `SK_CHECK` line text for each rejected variant, the estimate against the oracle value, status codes and the destination byte comparison.

Impact class. `demonstrated-invariant-violation`, shown only by the variants you build (the supplied anchor only passes on a correct provider and rejects those variants; no flawed provider is supplied), not a crash or sanitizer finding, and not a proved impact since no confidentiality or authorization consequence follows.

Remediation and regression. Check identity and precision before writing and refuse at the threshold without touching output. The existing rank 28/29, identity-mismatch merge and precision-increase fold CHECKs in `corpus_sketch.hyperloglog` must reject your variants.

Limitations. The anchor uses legal synthetic register vectors, not a hash an attacker controls, so it does not show that real inputs can be forced to inflate an estimate; 1.04/sqrt(m) is an idealized-model figure and cross-target floating point is not examined.

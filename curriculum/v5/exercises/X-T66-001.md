# X-T66-001: Owning handles and the partial-initialization frontier

## Prerequisites

Complete the earlier domain projects and retain the named prerequisite artifacts with their contracts, ownership ledger and tests. Required learner artifacts: memory.pool, containers.array, testing.faults, bytes.checked, io.async, errors.result. Do not import an assessor implementation.

## Environment

Implement mechanisms locally using declared typed storage/callbacks; hosted harness and diagnostic runtimes are separate. See laboratory contract for exact dependencies. Use C17 with extensions disabled and warnings treated as errors. A diagnostic extension is identified explicitly and does not become an ISO guarantee. The full platform, pointer, callback and concurrency preconditions are in [ownership/CONTRACTS.md](../../../labs/ownership/CONTRACTS.md).

## Problem

Implement ow_construct and ow_destroy for OwOwner, which owns exactly three separately acquired int32_t arrays after success. The input lengths array has three positive counts, each representable as count*sizeof(int32_t). Validate every count before any allocator call. The output must initially be empty. Acquire in index order using the imported V4Allocator; on the first null return, release the acquired prefix in reverse order and leave the output unchanged. Publish only after all three acquisitions. Destroy releases the live prefix in reverse order, clears each pointer and count, and succeeds on an empty owner. Callbacks cannot reenter, fail release or exit nonlocally.

Concrete inputs and expected results: Lengths[1,2,3] with failure on take2 produce NOMEM, one release, zero live blocks and unchanged empty output. Failure on take1 releases nothing. Three successful takes publish count3; two destroy calls together perform exactly three releases. A zero middle count causes no allocator invocation.

Supplied artifacts: labs/ownership/include/ownership.h, compiling unsolved src/ownership.c, CTest ownership.frontier, fixtures/ownership/PR-T66-01.json, and the shared contracts. State every additional backend assumption before running it.

## Necessity

Derive the construction frontier invariant and distinguish acquired storage, initialized object state and published ownership; compare explicit C cleanup with automatic language destruction. The misconception and changed-condition case below are separately assessed; ordinary successful execution alone does not cover them.

## Reasoning

Implement transactional three-resource construction and idempotent destruction using the accepted typed allocator callback ABI, proving which prefix is owned at each failure point. Give the abstraction function, admitted states, pre/postconditions, ownership graph, failure effects and complexity before implementation. Identify the enforcement boundary of every safety claim using the shared modern-cost contract. Distinguish an invalid caller object from an operational failure admitted by the API.

## Deliverables

- D1: Derive the construction frontier invariant and distinguish acquired storage, initialized object state and published ownership; compare explicit C cleanup with automatic language destruction.
- D2: Implement transactional three-resource construction and idempotent destruction using the accepted typed allocator callback ABI, proving which prefix is owned at each failure point.
- D3: Inject failure on each acquisition, reject zero and overflowing lengths before any callback, instrument release order and exactly-once counts, and test repeated destruction. Kill the omitted-rollback mutant. Extend the anchor with a callback trace that proves reverse order, not just equal release totals.
- D4: Replace the prefix with a dependency graph: acquire A, then B and C independently, then D requiring B. Write an initialized-set representation and reverse dependency cleanup. Delayed assessment makes C initialization fail after its storage acquisition; distinguish storage release from destruction of a constructed value. Complete all thirteen cost/enforcement dimensions with evidence or a mechanism-specific non-applicability.

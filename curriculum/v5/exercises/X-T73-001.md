# X-T73-001: Scope-owned child tasks and cooperative cancellation

## Prerequisites

Explain C17 atomic ordering, POSIX wait predicates, existing queue ownership, async terminal completion and stable coroutine-frame registration; retain the named imported learner artifacts. Required learner artifacts: work.pool, sync.condition_queue, sync.spsc, io.async, io.deadline, testing.faults, coro.frame. Do not import an assessor implementation.

## Environment

Implement mechanisms locally using declared typed storage/callbacks; hosted harness and diagnostic runtimes are separate. See laboratory contract for exact dependencies. Use C17 with extensions disabled and warnings treated as errors. A diagnostic extension is identified explicitly and does not become an ISO guarantee. The full platform, pointer, callback and concurrency preconditions are in [messaging/CONTRACTS.md](../../../labs/messaging/CONTRACTS.md).

## Problem

Implement MsgNursery with eight stable child slots, one parent owning admission/join, borrowed contexts and atomic cooperative cancellation. Child failure requests sibling cancellation; join must wait for every admitted child and return the first nonzero result in creation order. Inject pthread creation failure at each one-based attempt, retaining previously admitted children. Closing rejects new tasks. Supply a work.pool adapter that transfers each accepted task into this lifetime scope and proves no child outlives its borrowed stack context.

Concrete inputs and expected results: Spawn result5 then result0: after join, both slots are joined, cancellation is true and result is5. Fail admission at attempt2: exactly one child remains admitted, its context is retained until join and no second thread handle is joined. An uncooperative infinite child is a bounded external-timeout experiment, not silently declared cancelled.

Supplied artifacts: labs/messaging/include/messaging.h, compiling unsolved src/messaging.c, CTest messaging.nursery, fixtures/messaging/PR-T73-01.json, and the shared contracts. State every additional backend assumption before running it.

## Necessity

Explain scope-owned task lifetime, failure aggregation and cooperative cancellation, including why a cancellation flag does not establish completion or a bounded join latency. The misconception and changed-condition case below are separately assessed; ordinary successful execution alone does not cover them.

## Reasoning

Derive admission/closing/quiescent states, implement spawn/join and deterministic error selection, then compose with the existing work.pool artifact without detached tasks or prematurely released contexts. Give the abstraction function, admitted states, pre/postconditions, ownership graph, failure effects and complexity before implementation. Identify the enforcement boundary of every safety claim using the shared modern-cost contract. Distinguish an invalid caller object from an operational failure admitted by the API.

## Deliverables

- D1: Explain scope-owned task lifetime, failure aggregation and cooperative cancellation, including why a cancellation flag does not establish completion or a bounded join latency.
- D2: Derive admission/closing/quiescent states, implement spawn/join and deterministic error selection, then compose with the existing work.pool artifact without detached tasks or prematurely released contexts.
- D3: Inject failure before every admission, record thread/context ownership, join zero/one/eight children, reject ninth admission and late spawn. Use a barrier-controlled failure with siblings acknowledging cancellation and compare accepted/completed counts. Reject both missing-cancellation and swallowed-result mutants. Run separate TSan and demonstrate that eventual cancellation needs child checkpoints.
- D4: Add nested nurseries with a parent deadline: propagate cancellation down while joining upward, retaining contexts until every descendant is quiescent. Delayed assessment supplies two failures racing in different orders; keep deterministic creation-order reporting while preserving both errors in a bounded aggregate. Complete all thirteen cost/enforcement dimensions with evidence or a mechanism-specific non-applicability.

3. Setting an atomic flag cannot interrupt arbitrary blocking code.

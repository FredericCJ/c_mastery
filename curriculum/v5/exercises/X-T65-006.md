# X-T65-006: Typed nonlocal-jump boundary with explicit cleanup ownership

## Prerequisites

Use the existing bytes.checked, parser.integer, io.stream and codec.records contracts as comparison boundaries. Complete C17 tagged-union, pointer-lifetime and function-pointer reasoning first. Preserve the learner's earlier implementations; do not import an assessor solution. Complete X-T65-005 first.

## Environment

Original C mechanisms; hosted setjmp/longjmp only for the explicit jump boundary. Host harness may use stdio/Python. No strict freestanding claim. C17, Linux x86-64, GCC and Clang with -Wall -Wextra -Wpedantic -Werror and extensions disabled. The exact shared contract is [errors/CONTRACTS.md](../../../labs/errors/CONTRACTS.md). C editions, language-level guarantees and implementation observations must be labeled separately.

## Problem

Implement er_run, er_defer and er_raise using the caller-owned zero-initialized er_frame. er_run rejects an active or cleaning frame, sets a live jump destination, calls body once and returns either its result or the raised error. Register at most four non-null cleanup callbacks while active, then execute each exactly once in reverse registration order after normal return or a jump. Registration failure preserves the stack. Popping precedes calling cleanup; callbacks may not reenter, raise or register on the cleaning frame. er_raise outside a live frame or with ER_OK/unknown code returns ER_INVALID. A valid raise stores the typed error in the external frame then longjmps. No cross-thread jumps, signals, escaped jmp_buf, variable length arrays or nested reuse of the same frame.

Concrete expected cases: Register callbacks appending digits1 and2, then raise ER_THROWN: return THROWN with trace21, count0 and inactive frame. Normal return with callback1 also cleans it. A raise after er_run returns is rejected before any jump.

Supplied artifacts: labs/errors/include/errors.h, compiling unsolved src/errors.c, the named CTest errors.boundary, and fixtures/errors/PR-T65-06.json. No installed package may supply the mechanism under assessment.

## Necessity

Classify setjmp placement, live destination, modified automatic locals, thread identity and variably modified scope requirements from the inspected draft clauses. An ordinary nominal call does not assess this distinction. The two isolated mutants and the changed-condition case expose different incorrect explanations.

## Reasoning

Implement a bounded explicit cleanup stack and typed jump-to-result boundary without pretending that longjmp unwinds C resources. State the preconditions, postconditions, valid representation states, ownership and failure effects before implementation. Derive operation and storage bounds; distinguish caller misuse from a reported operational failure. Compare the C protocol with the exact inspected source scope: C type compatibility and diagnostics do not supply automatic ownership, exhaustive matching or proof of a runtime predicate.

## Deliverables

- D1: Classify setjmp placement, live destination, modified automatic locals, thread identity and variably modified scope requirements from the inspected draft clauses.
- D2: Implement a bounded explicit cleanup stack and typed jump-to-result boundary without pretending that longjmp unwinds C resources.
- D3: Inject failure before and after each registration, capacity exhaustion, normal return and every admitted raised code. Count cleanup exactly once and compare reverse-order traces. Compile optimized GCC/Clang variants. Analyze deliberately invalid saved-frame and changed-local snippets without treating their execution as an oracle; kill cleanup-omission and FIFO-cleanup mutants.
- D4: Compose with a resource acquisition API that fails after the third acquisition and with T66 cleanup.scope when available. Distinguish local rollback from effects already published externally. Delayed assessment nests two separate frames and requires inner-error conversion while preserving outer cleanup order. Complete all dimensions of the shared modern-cost contract, with evidence or a justified non-applicability.

Run the named anchor separately from the complete suite. Preserve exact commands and expected/observed results. Every specified failure output and callback count is a pass/fail gate. Public anchors and source-bound author campaigns do not discharge independent inputs, reasoning or delayed transfer. Explain sanitizer, model-size and compiler limitations.

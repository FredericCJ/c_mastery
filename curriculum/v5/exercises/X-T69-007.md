## Problem

Implement the4-item circular intrusive DSList with DSLink as the first member of DSItem. Items stay at stable addresses while linked and belong to one list. Recover a genuine item from its first-member link only after excluding the sentinel. Add a separate external operation dictionary that processes item payloads without changing the link representation. Investigate conventional arbitrary-offset container_of in an isolated compiler probe with offsetof and explicit provenance/alignment assumptions; do not claim the first-member proof establishes every extension.

Supplied artifacts: labs/dispatch/include/dispatch.h, deliberately incomplete labs/dispatch/src/dispatch.c, executable anchors, fixture PR-T69-07.json and the shared CONTRACTS.md. Expected example: Appending values1,2,3 produces sum6. Removing2 repairs both neighboring links, clears its membership and produces sum4. Duplicate insertion and repeated removal reject. Removing all items restores both sentinel links to itself.

## Implemented extension contract: two hooks and moving storage

Use `dispatch_intrusive.h` and `src/dispatch_intrusive.c`. `DSDualItem` has two independent hooks and one int payload. Each `DSDualList` selects hook0 or hook1 and holds at most four items; a single object may belong to both lists. The explicit parent pointer is checked against the actual selected member before its payload is passed to the external `DSCombine`. Fold respects insertion order, starts at the supplied initial value, calls once per member and publishes only on complete success. Callback effects already performed are not undone. Duplicate membership returns DS_BUSY, removal from the wrong list returns DS_STALE, and a fifth distinct insertion returns DS_FULL without mutation.

X-T69-007-DELAYED now has a concrete index implementation target: a stable `DSIndexOwner` refers to four genuine `DSIndexSlot` objects, containing both hook chains. A handle carries owner identity, slot and generation. Relocation copies exactly four slots into a distinct nonoverlapping typed array, then changes the owner reference. The control object's address and handle values do not change. Clients must end every raw slot borrow before relocation; the former array is no longer authoritative. Release is allowed only after unlinking both memberships. Generations1 through3 are issued; generation4 is a permanent retired marker. At most12 successful acquisitions occur in an owner's lifetime. Reinitializing the control while old handles exist is prohibited. Full/stale/invalid rejection preserves caller outputs.

D2 supplies both representations and external payload operations. D3 runs the original four-item list through every length-seven word over its eight push/remove actions: 2,097,152 scripts and 14,680,064 checked transitions, including every shorter prefix. Independently recompute both link directions and the sequence from a separate array model. The new dual-hook enumeration uses two items, two hooks and all eight actions through length6, with four-item exhaustion tested separately. The Python oracle compares16,384 actual prefix transitions of the dual-hook and relocated-index implementations against two independent Python lists. Four compiled controls cover a single global membership flag, omitted inverse repair, ignored generation and failure to publish the relocated backing array.

# X-T70-001: Hot and cold columns with transactional numeric updates

## Prerequisites

Bring pinned contracts and fresh recall for containers.array, meta.reflect, measurement.capture; prerequisite exercises: X-T04-001. Required knowledge includes C object lifetime, checked arithmetic, ownership, typed arrays and the selected source passages. The shared contract and modern-cost contract are explicit parts of this exercise. Existing project estimates describe author accounting; they impose no learner time ceiling.

## Environment

Use C17 hosted Linux with GCC and Clang, CMake and host Python. Record compiler/ABI versions, integer widths, sizeof/alignment and optimization. Mechanism code uses no library implementing the mechanism. Allocator callbacks are supplied dependencies with separate ownership. A strict freestanding port requires its own generated-code/link audit and is not established by the hosted run. Compare C11 draft/C17/C23 only where inspected normative evidence supports the claim; exact published C17 access remains a reference gap.

## Problem

Implement d_columns_step for4 parallel typed arrays under the shared contract, then implement an equal-contract AoS adapter and generate both declarations and field visitors from one C17 field-list definition. Inputs are count0–4, int32 positions/velocities, ticks0–10 and cold labels. Outputs are updated positions or a rejection preserving every position. Never update a prefix before discovering a later overflow. Use the supplied4-record model for exhaustive small-range tests and an explicitly allocated large synthetic population for measurements; large-population code must retain the same numeric contract.

Supplied artifacts: labs/dod/include/dod.h, deliberately incomplete labs/dod/src/dod.c, executable anchors, fixture PR-T70-01.json and the shared CONTRACTS.md. Expected example: Positions[1,2,3,4], velocities[2,-1,1,0], ticks2 produce[5,0,5,4] with cold labels unchanged. If the last position is INT32_MAX and velocity1, ticks1 rejects without changing even the first position.

## Necessity

The label data-oriented design does not choose a layout. Access patterns, overflow semantics and conversion/identity costs determine whether splitting fields helps; removing overflow checks to obtain SIMD changes the correctness contract.

## Reasoning

T70.01.a: Derive AoS and SoA address/traffic models for a position-only update and a whole-record consumer, including padding, cache-line assumptions and the different identity of a record after splitting fields.

T70.01.b: Implement a staged SoA update and an equal-contract AoS version generated from a shared field list; distinguish token-driven generation from runtime or language reflection.

T70.01.c: Enumerate small signed input products and all failing record positions with an independent integer oracle; verify untouched columns and kill skipped-update and premature-prefix-commit mutants.

T70.01.d: Measure warmed and cold working sets, vectorization reports, code size and conversion costs under equal overflow semantics. Report crossover uncertainty; demonstrate a whole-record workload where SoA can lose.

T70.01.e: Transfer to an array-of-small-tiles layout with an optional cold column. Derive row/column bounds and schema evolution before changing the implementation; C diagnostics do not verify field-list semantic consistency.

State preconditions, postconditions, representation invariants, resource ownership, failure publication and complexity. For each guarantee identify ISO C rules, diagnostics, runtime checks, external verification and programmer discipline separately. Include a minimal counterexample to an overstated equivalence with the corresponding language/library abstraction. Apply all13 dimensions in modern-cost-contract.md, recording genuine non-applicability with reasons and unavailable measurements as gaps.

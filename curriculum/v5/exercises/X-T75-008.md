# X-T75-008: Idempotent effects, finite deduplication and storage fencing

## Prerequisites

Bring pinned contracts and fresh recall for ipc.local, io.stream, measurement.capture; prerequisite exercises: X-T04-001, X-T75-005. Required knowledge includes C object lifetime, checked arithmetic, ownership, typed arrays and the selected source passages. The shared contract and modern-cost contract are explicit parts of this exercise. Existing project estimates describe author accounting; they impose no learner time ceiling.

## Environment

Use C17 hosted Linux with GCC and Clang, CMake and host Python. Record compiler/ABI versions, integer widths, sizeof/alignment and optimization. Mechanism code uses no library implementing the mechanism. The T73 channel backend supplies its declared POSIX synchronization; the virtual-time model itself supplies no OS clock, sleep or hidden scheduler. A strict freestanding port requires its own generated-code/link audit and is not established by the hosted run. Compare C11 draft/C17/C23 only where inspected normative evidence supports the claim; exact published C17 access remains a reference gap.

## Problem

Implement RZReceiver for a checked synthetic integer total, four retained requests, two authenticated-model client IDs and finite retention1..16 ticks. A request has client,id,fence,delta. Replays within retention return the original result; changed parameters conflict; stale fencing tokens reject at the protected receiver. Publish effect and dedup record together. Add an append-only local teaching journal with explicit crash points around record/effect publication, then replay recovery without claiming the in-memory anchor is durable.

Supplied artifacts: labs/resilience/include/resilience.h, deliberately incomplete labs/resilience/src/resilience.c, executable anchors, fixture PR-T75-08.json and the shared CONTRACTS.md. Expected example: Client0/id1/fence2/delta3 at0 applies total3. Its replay at1 returns3 without another effect; delta4 with that ID conflicts. Client1 at fence1 is stale. With retention4, the same id at4 is no longer retained and may apply again, producing6. This bounded window is not indefinite exactly-once execution.

## Necessity

Deduplication needs an identity contract and retention limit. A timed-out lease or a unique random value does not establish that an old writer is fenced off after a newer owner acts.

## Reasoning

T75.08.a: Derive request identity versus payload equality, finite retention, authentication assumption and monotonic fencing enforcement at the actual effect resource. Identify which failures make a result uncertain.

T75.08.b: Implement atomic in-memory record/effect publication, original-response replay, parameter mismatch rejection, no live-record eviction and checked arithmetic.

T75.08.c: Demonstrate harmless replay/stale-writer violations using original mutants, then add a journal recovery model with crash injection at every write/flush/commit boundary and independently recompute recovered effects.

T75.08.d: Transfer to multiple clients, reordered messages, restarted token issuer and expired dedup entries. State durability, uniqueness and monotonicity assumptions necessary for each guarantee; reject claims of network exactly-once delivery from a local lookup table.

State preconditions, postconditions, representation invariants, resource ownership, failure publication and complexity. For each guarantee identify ISO C rules, diagnostics, runtime checks, external verification and programmer discipline separately. Include a minimal counterexample to an overstated equivalence with the corresponding language/library abstraction. Apply all13 dimensions in modern-cost-contract.md, recording genuine non-applicability with reasons and unavailable measurements as gaps.

# Follow two translation units from source to executable

## Prerequisites

Read the calling and definition translation units and review the C17 preprocessing and translation model.

## Environment

Use Linux x86-64 System V AMD64. From the exported workspace root run `python3 inspect_lab.py prepare --cc gcc`. Record the output directory, compiler version and manifest. The commands and answer-field conventions are in CONTRACTS.md.

## Problem

Rebuild the supplied record processor one stage at a time. Mark where the declaration, the macro replacement, the machine instructions and the storage definition first appear. Predict which command first needs the missing provider when you omit record.o.

## Necessity

Identify the first stage where the header macro disappears. An output value by itself omits the evidence that connects this claim to a particular build.

## Reasoning

Run `cc -E`, `cc -S` and `cc -c` separately. Inspect `record.i`, `record.s` and both object symbol tables with `readelf -Ws`. Link a copy of `driver.o` alone, retain its diagnostic, then add `record.o` and execute. Cite the actual producing and consuming command for each intermediate.

## Deliverables

- D1. Write your prediction before running the relevant inspection tools. Record the commands, file identities and observations in `answers/stages.json`. Include `prediction`, `explanation` and the fields `object_sha256`, `output`, `unresolved_call`, `missing_provider_stage`.
- D2. In your explanation, cite the bytes, instruction, header field or counter row supporting each inference in the reasoning exercise.
- D3. Change RECORD_WEIGHT in a scratch copy and rebuild the provider. Explain which artifacts can be reused and how the new executable relates to the old caller. Restore the distributed inputs before the checked run.

## Verification

Run `python3 inspect_lab.py check stages --cc gcc`. For a hosted Clang build prepare and check with `--cc clang`. Preserve the manifest with the submission. A reviewer reads the written reasoning alongside the machine-checked observations.

## Rubric

- R1. Identify the first stage where the header macro disappears.
- R2. Explain why the caller object can name an undefined function.
- R3. Reproduce the driver link from independently generated objects.

## Hints

Use the same compiler flags and inspect its recorded absolute path. A declaration in a header provides type information to the translator. An object can still require another object to define a symbol.

## Variants

V1 is a delayed independent transfer on a changed artifact, at least seven days after the first attempt. Derive the result from the supplied inputs and identify the evidence needed for each claim.

## Security

Use the supplied original program and locally generated files. Keep measured images, host details and observation logs in the local workspace.

## Validation

The checker compares selected artifact facts. The assessor separately evaluates the derivation, changed condition and whether an independent transfer took place.

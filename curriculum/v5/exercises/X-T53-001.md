## Security

Target: the shoot begin/ack/reclaim code in `labs/b045_systems` and the early-reclaim variant you build, run as a local process over synthetic metadata with frame labels OLD and NEW. There are no real page tables or host memory involved.

Adversary: you choose the order and generation of ACK events and when reclaim is attempted: ACK0 alone, a stale ACK1 from the previous generation, then the current ACK1. You do not choose the captured CPU set, the generation counter or the labels.

Violated property: a frame must not be reused for NEW while any captured CPU may still hold a translation to OLD.

Evidence to capture: run `depth-tests shoot` (CTest `b045_systems.shoot`) on the supplied-correct build and note the printed line `shootdown observation: delayed CPU sees synthetic label 1`, reclaim returning S_PENDING after ACK0, the stale `gen - 1` ACK returning S_CONFLICT with `s.pending == 2`, and reclaim succeeding only after the current-generation ACK1. Then build the early-reclaim variant the Problem describes (reclaim marks the frame reclaimed while CPU1 is pending) and record that the test prints `synthetic label 2` and fails with `DEPTH_CHECK:<line>:frame_label == 1 && reclaimed == S_PENDING && !s.reclaimed`. Build a second variant that ignores the generation and record the failing `gen - 1` CHECK.

Impact class: demonstrated-invariant-violation, shown only by the early-reclaim variant you build; the supplied test on a correct build prints label 1 and passes, so no supplied artifact demonstrates the NEW view. It is a logical stale-view access in a model, not a crash, sanitizer finding or undefined behaviour, and not proved-impact because no real translation cache or privilege boundary is modelled.

Remediation: snapshot the target set at begin, accept only current-generation ACKs, and gate reclaim on an empty mask. The regression test is the existing `b045_systems.shoot`; it must fail on each of your variants and pass on the repair.

Limitations: Shows a logical label in a finite model only: no real TLB, barrier, IPI or CPU hot-unplug behaviour (the hot-unplug quiescence handshake is variant V2, not in the supplied test); the host function trusts ACK meaning, and one fixed history is not a proof over all schedules.

# X-T36-002: Tree certificates and explicit duplicate-policy adaptation

## Prerequisites

Complete PR-T36-05 prerequisite knowledge in C17 lifetime, unsigned arithmetic, arrays and explicit representation invariants. For tree integration bring your own completed AVL component with recorded source/header hashes, insertion/deletion and failure policy. Missing prerequisites must be implemented before integration. The standalone scaffold never copies assessor code or silently imports a baseline library.

## Environment

Use the public header, compiling failure stub and complete shared CONTRACTS.md. Every input/control/output backing object is live and distinct under its documented alias rule. Host verification tools are not target dependencies. Record compiler/flags/data model. C17 semantics, original API policy, toy ISA and actual ABI evidence are separate layers; compare C23 changes only from inspected edition-specific passages, otherwise retain that reference gap.

## Problem

Implement sc_tree_check and sc_unique_insert. The three-node certificate has root20, children10/30, root height2 and child heights1. Accept it; reject an otherwise identical root height1, a shared child, wrong parent, cycle, disconnected live node, duplicate key and out-of-range child. Derive parents in an explicit adapter from actual child indices. For an existing key20, baseline algo_avl_insert returns ALGO_OK unchanged; the new adapter must return SC_DUPLICATE without calling insert. Compile tests/algorithms_integration.c against the named source/header of your completed algorithms component and certify after every insertion/deletion. This is an adapter and certificate extension; the full AVL mutation algorithm and its earlier proofs remain prerequisites.

## Necessity

The repository audit found a concrete contract/execution mismatch: the earlier algorithms family implements idempotent AVL duplicates and first-match bytes, and explicitly excludes a clocked instruction engine. This additive exercise preserves baseline contracts and accepted evidence while exposing the missing behavior. Selected A/B/C/D/F/H/I/J families assess derivation, construction, boundaries, diagnosis, falsification, resource arguments and changed assumptions without manufacturing irrelevant allocation or network failure modes.

## Reasoning

Local child comparisons alone miss a grandchild outside the ancestor interval. Carry strict int64 bounds so INT32_MIN/MAX remain admissible keys. Mark an index before recursion to bound cycle traversal, recompute height from children, then compare live and reached sets. A check-then-insert adapter is correct only under the shared single-owner callback contract. It cannot strengthen a callback that mutates before reporting failure. A read-only certificate emitted between rotation steps must explicitly relax only balance; it cannot waive ordering or parent consistency. State preconditions, postconditions, ownership, failure publication and complexity for each API. Identify what ISO C enforces, what the runtime checks, and what remains programmer discipline. Refute a plausible incorrect explanation with a minimal input.

## Deliverables

D1: Hand-derived state/representation proof for every objective-specific rubric criterion, including the API mismatch and contract conversion.

D2: Original C17 implementation, documented explicit adapters and source identities; no studied-mechanism library delegation.

D3: Public and new boundary traces, unchanged-failure canaries, two compiled mutant diagnoses, independent expected results, exact commands and resource/cost evidence under stated models.

D4: Unseen V1/V2 work after at least seven days, assessor reasoning record and explicit limits; no copied practiced solution.

## Verification

Configure the learner scaffold with CMake and run systems_certificates.tree. The author runner tools/run_systems_certificates.py executes six compiler/debug/release/sanitizer profiles, requires each compiled mutant to exit1 with SC_CHECK rather than crash or fail compilation, and confirms the compiling learner stubs reject. The independent Python oracle uses graph reachability, slice enumeration and mathematical transitions. Tree integration separately compiles the actual named algorithms component; learner evidence must use the learner revision. Pass D1-D3 only with every criterion at least level2, no unexplained check failure, exact postcondition/failure evidence and a fresh counterexample. D4 is required for independent transfer. Passing finite checks does not prove absolute mastery.

## Rubric

Assess every machine-readable criterion independently. Level0 is incorrect/no model; level1 is superficial replay; level2 is an explained implementation plus falsification; level3 requires independently demonstrated transfer under a changed assumption. Neither a test pass nor a source mention supplies a missing criterion.

## Hints

H1: separate the live set from the reached set. H2: carry the full ancestor interval into recursion. H3: store a visited bit before following either child; publish height only after the sets and metadata agree.

## Variants

V2: Adapt a red-black tree with color/black-height certificates and demonstrate why unchanged AVL height checks do not certify its balancing policy. After seven days receive an unseen multi-ancestor deletion trace and independently identify the first invalid certificate.

## Security

Only the original local teaching target and synthetic integer-index certificates, byte spans and instruction arrays are in scope. The adversary chooses those values, not arbitrary host pointers. A harmless violation is acceptance of a malformed certificate, missing/extra match, wrong synthetic register or forbidden partial commit. State exploitability premises and limits; a crash/UB finding is not arbitrary code execution. Demonstrate the mutant defect, repair, regression and residual live-storage/callback/serialization obligations. No external service, production data or physical equipment is targeted.

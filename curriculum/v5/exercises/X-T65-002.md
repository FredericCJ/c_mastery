# X-T65-002: Single-evaluation propagation and atomic parser publication

## Prerequisites

Use the existing bytes.checked, parser.integer, io.stream and codec.records contracts as comparison boundaries. Complete C17 tagged-union, pointer-lifetime and function-pointer reasoning first. Preserve the learner's earlier implementations; do not import an assessor solution. Complete X-T65-001 first.

## Environment

Original C mechanisms; hosted setjmp/longjmp only for the explicit jump boundary. Host harness may use stdio/Python. No strict freestanding claim. C17, Linux x86-64, GCC and Clang with -Wall -Wextra -Wpedantic -Werror and extensions disabled. The exact shared contract is [errors/CONTRACTS.md](../../../labs/errors/CONTRACTS.md). C editions, language-level guarantees and implementation observations must be labeled separately.

## Problem

Implement er_parse_pair over a borrowed byte sequence of known length, not a NUL-terminated string. Grammar is one or more ASCII decimal digits, colon, one or more digits, and exact end. Each field and their sum must be at most 65535. Leading zeros are permitted; signs and whitespace are not. On malformed input return ER_INVALID with the first offending byte offset; a missing digit or delimiter at end reports length. On an overflowing field return ER_RANGE at the first digit that exceeds the bound; sum overflow reports length. On failure sum is unchanged. Implement both explicit goto/out-parameter propagation and a C17 do-while macro variant, evaluating each supplied expression once.

Concrete expected cases: 1:65534 succeeds with 65535. 65536:0 fails RANGE at offset4; 1:2x fails INVALID at3; 1: fails at2; :1 fails at0. 1:65535 fails RANGE at7 and must not publish the first field.

Supplied artifacts: labs/errors/include/errors.h, compiling unsolved src/errors.c, the named CTest errors.propagation, and fixtures/errors/PR-T65-02.json. No installed package may supply the mechanism under assessment.

## Necessity

Explain which failure stage owns the error offset, and why early-return propagation is not transaction rollback or automatic cleanup. An ordinary nominal call does not assess this distinction. The two isolated mutants and the changed-condition case expose different incorrect explanations.

## Reasoning

Implement strict checked accumulation and two single-evaluation propagation forms without statement expressions, strto* or parser libraries. State the preconditions, postconditions, valid representation states, ownership and failure effects before implementation. Derive operation and storage bounds; distinguish caller misuse from a reported operational failure. Compare the C protocol with the exact inspected source scope: C type compatibility and diagnostics do not supply automatic ownership, exhaustive matching or proof of a runtime predicate.

## Deliverables

- D1: Explain which failure stage owns the error offset, and why early-return propagation is not transaction rollback or automatic cleanup.
- D2: Implement strict checked accumulation and two single-evaluation propagation forms without statement expressions, strto* or parser libraries.
- D3: Generate all strings of length0–6 over digits0,1,9,colon,x and compare with an independent grammar/integer model. Add UINT32 bounds and long zero prefixes. Record callback/expression counters to kill double evaluation and retain a canary output for every rejection; kill premature publication and trailing-input acceptance mutants.
- D4: Replace the complete buffer with two incremental segments and preserve an explicit consumed position. Decide when an error position is absolute and when publication may occur; show a case where blindly returning the old error loses partial progress. The delayed variant adds a signed first field and forbids negative totals. Complete all dimensions of the shared modern-cost contract, with evidence or a justified non-applicability.

Required non-equivalence assessment C12: Replace a proposed GNU statement-expression propagation macro with a C17 do-while statement macro taking an explicit output and goto label. Count argument evaluation, test a name collision, and compare a static inline function when early return from the caller is unnecessary.

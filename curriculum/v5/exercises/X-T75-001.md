# X-T75-001: Cancellation trees and budgets across clock domains

## Prerequisites

Bring pinned contracts and fresh recall for io.deadline, io.async; prerequisite exercises: X-T30-002. Required knowledge includes C object lifetime, checked arithmetic, ownership, typed arrays and the selected source passages. The shared contract and modern-cost contract are explicit parts of this exercise. Existing project estimates describe author accounting; they impose no learner time ceiling.

## Environment

Use C17 hosted Linux with GCC and Clang, CMake and host Python. Record compiler/ABI versions, integer widths, sizeof/alignment and optimization. Mechanism code uses no library implementing the mechanism. The T73 channel backend supplies its declared POSIX synchronization; the virtual-time model itself supplies no OS clock, sleep or hidden scheduler. A strict freestanding port requires its own generated-code/link audit and is not established by the hosted run. Compare C11 draft/C17/C23 only where inspected normative evidence supports the claim; exact published C17 access remains a reference gap.

## Problem

Implement RZScope init/cancel/check/remaining over immutable parent links, atomic cancellation flags and injected uint64 ticks. Limit depth to8, choose the earliest inherited deadline, and reject unrepresentable standalone addition. Then implement a request-budget envelope for two simulated hosts with unrelated clock origins: it carries remaining duration, never a raw local absolute deadline. Deduct local elapsed work and state the transport-delay assumption. Add a completion acknowledgement owned by each asynchronous borrower, retaining scope storage until all acknowledgements arrive.

Supplied artifacts: labs/resilience/include/resilience.h, deliberately incomplete labs/resilience/src/resilience.c, executable anchors, fixture PR-T75-01.json and the shared CONTRACTS.md. Expected example: Parent created at10 with budget10 expires20. A child at13 asking100 still expires20; at19 remaining is1 and at20 it is expired. Cancelling the parent makes the child CANCELLED. No borrowed storage becomes reclaimable solely because cancellation was requested.

## Necessity

A timeout is a local wait limit, not proof that remote work stopped. C has no automatic context-lifetime or deadline-propagation rule; both need explicit ownership and clock assumptions.

## Reasoning

T75.01.a: Derive deadline versus timeout semantics, cancellation precedence, parent lifetime and nonextension of inherited budget. Distinguish stopping admission from acknowledgement and rollback.

T75.01.b: Implement checked scope construction and cross-clock remaining-budget encoding, including zero budget, numeric horizon, depth exhaustion and stale parent-lifetime counterexamples without executing invalid access.

T75.01.c: Enumerate cancellation/expiry/finish orderings and verify output preservation, no later child deadline, idempotent cancellation and delayed borrower cleanup. Inject a completion after cancellation and retain its state until acknowledgement.

T75.01.d: Transfer to an RPC chain with queued transport delay and independent clocks. Quantify which latency assumptions bound end-to-end completion and show why repeated per-hop timeout resets or copying an absolute monotonic timestamp violate the intended budget.

State preconditions, postconditions, representation invariants, resource ownership, failure publication and complexity. For each guarantee identify ISO C rules, diagnostics, runtime checks, external verification and programmer discipline separately. Include a minimal counterexample to an overstated equivalence with the corresponding language/library abstraction. Apply all13 dimensions in modern-cost-contract.md, recording genuine non-applicability with reasons and unavailable measurements as gaps.

## Hints

3. Clocks with different origins can compare durations, not arbitrary local timestamps.

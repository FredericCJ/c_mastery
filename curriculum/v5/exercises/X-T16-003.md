# X-T16-003: Region cohorts: byte reclamation, cleanup and escaped aliases

## Prerequisites

Bring X-T04-001 extent reasoning and X-T16-002 mark/identity source. Read PR-T16-01 and PR-T16-02 cleanup obligations. Know actual versus logical lifetime, alignment, unsigned arithmetic and callback ownership. T16.05.c explicitly composes cleanup from PR-T16-02; other stack-allocation objectives are not silently transferred.

## Environment

C17 and the parent dependency profile remain in force. The anchor uses Linux x86-64, GCC/Clang, CMake and pthreads for host verification only. No libc mechanism implementation, ready-made arena/once/reclamation library, libatomic or hidden helper may enter a strict freestanding target. Record compiler/flags, data model, alignment, atomic lock-free properties, undefined symbols and disassembly. Source-language/library comparisons have their own cited contracts, not additional ISO C guarantees. N1570 is a C11 draft; exact C17 remains an access gap.

## Problem

Implement MBRegion over32 caller-owned character bytes and four cleanup entries. Requests (3,align1),(5,align4) produce offsets0,4, cursor9, payload8 and high9. Register synthetic resources1..4, reset and record cleanup4,3,2,1; old handles become STALE although the byte array still exists. Admit exactly three allocation generations, then retire the owner. Failed registration leaves its resource with the caller. During cleanup, initialized current bytes may be inspected, but allocation/reset/registration returns BUSY. Do not delegate policy to malloc, pmr or bumpalo.

Supplied artifacts: `labs/modern_bridge/include/bridge.h`, compiling unsolved `src/bridge.c`, `tests/tests.c`, `fixtures/modern_bridge/cases.json` and the incorporated `labs/modern_bridge/CONTRACTS.md` version1. The contract defines representation, operations, preconditions, error precedence, ownership, finite limits and complexity. Preserve the interface. Target adapters remain separate learner sources; retain imported learner source hashes rather than copying assessor code.

## Necessity

A correct bump cursor can coexist with leaked resources, resurrected stale handles or invalid typed access. Region allocation groups lifetimes: one long-lived member can retain an entire cohort. High-water and total requested payload differ.

## Reasoning

Prove disjoint extents, aligned addresses, checked padding admission, payload<=cursor<=32, monotone high and nonwrapping generation. Classify physically present bytes versus API-invalid handles and state live-owner/initialized-byte preconditions. Generation checks cannot rescue a dangling owner. Draw resource ownership when cleanup registration fails. Reset is O(callback count plus callback work), not unconditional O(1). Compare C++ monotonic_buffer_resource release/upstream growth with this fixed arena and bumpalo reset/Drop/lifetime behavior. C provides neither automatic destruction nor borrow checking; reclaiming bytes cannot perform arbitrary application cleanup.

For each operation state pre/postconditions, invariants, ownership and failure preservation. Assign guarantees to ISO C, compiler/ABI contract, runtime checks, external verification or caller discipline. Supply one plausible incorrect explanation and minimal counterexample. Complete the13-dimension modern cost review, with justified non-applicability; compare equal correctness and ownership contracts.

- D2: Implement the byte arena and a typed cohort of four actual resource objects with synthetic open/close counters. Record per-batch occupancy and lifetime peak; do not benchmark a cleanup-free cursor against cleanup-owning code as equivalent.
- D3: The procedure below, raw command outputs, independent expectations, minimized mutant failures, source hashes, resource measurements and separate simulated/host/target evidence.
- D4: The named delayed transfer at least seven days after the source-bound study event, with a fresh derivation of changed invariants, ownership, failure semantics and costs.

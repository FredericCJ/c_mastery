# X-T15-014: Statement synchronization with staged semantic results and diagnostic retention

## Prerequisites

Know typed arrays, half-open ranges, staged publication, source offsets and syntax/semantics separation. Recovery and formatting require your completed X-T15-012 implementation and its exact PdTree contracts. Bring grammar traces, failure snapshots and the public `parsing_depth` workspace; dependency import is explicit. Template evaluation additionally needs lexical scope and bounded graph traversal. No library implements the new mechanism for you.

## Environment

The explicit [text-composition contract1](../../../labs/text_composition/CONTRACTS.md) gives all input types, operations, exact grammar, capacities, ownership, failure/resource and local security rules. Implement `src/text.c`; configure the actual prerequisite workspace with CMASTERY_PARSING_DEPTH_ROOT. Host tools and models remain outside the target component contract. Inspect dependency identity and emitted resource costs; no runtime absence or language-level safety follows from the API spelling.

## Problem

Implement tc_recover by composing the actual Pd lexer, Pratt syntax tree and checked interpreter. Parse semicolon-terminated expression batches, discard only failed statements and retain absolute diagnostic spans. The concrete 1+;22;3*4; batch must yield22 and12 with one error. A syntactically valid overflowing statement must produce a semantic diagnostic instead of a fake value. Implement the named newline-synchronization transfer without changing the retained parser.

## Necessity

A compiler that stops at the first error cannot collect later independent diagnostics; a parser that resumes one byte too late loses valid input. Syntax success is distinct from safe evaluation. Recovery strategies discard context deliberately and can cascade after an inserted delimiter; binary-frame resynchronization does not establish this language contract.

## Reasoning

Prove every delimiter is consumed exactly once and the next statement begins at its successor. Explain the staged ownership of token/tree/result storage, and why no failed statement publishes a value. Derive separate512-byte scan admission,256-byte imported segment limits,16-result/16-diagnostic capacities and whole-batch failure atomicity. The budget counts scan positions, not every imported instruction. Give the counterexample to treating newline synchronization as a semantics-preserving optimization. Supply pre/postconditions, loop/stack invariants, ownership, failure and complexity arguments. Classify guarantees supplied by ISO C, diagnostics, runtime checks, external models and caller discipline separately.

## Security

A recovering parser makes a promise to the program that reads its results: every value in the published list came from a statement that really succeeded, and every statement that failed is accounted for in the diagnostics. Break either half and a downstream consumer acts on a number nobody typed or misses an error that happened. The only attacker input is the batch of at most 512 bytes: it decides where statements end, which ones are damaged and which valid ones overflow. The target is your own `tc_recover` in `labs/text_composition/src/text.c`, calling the completed `parsing_depth` lexer, Pratt parser and checked evaluator. The 16-result and 16-diagnostic capacities, the fuel budget and the caller arrays belong to the harness.

Why it matters here. `1+;22;3*4;` contains a damaged first statement. Recovery must consume that statement's `;` exactly once and resume at `22`; resuming one byte early re-reads the delimiter as an empty statement and one byte late eats the first digit of the next. `2147483647+1;9;` is syntactically valid but overflows when evaluated, so it must yield a diagnostic and no value. Finally, a batch that exceeds a capacity or the fuel is rejected whole, so the caller's arrays must be byte-identical afterwards.

What to try. Predict the published values, the error count and `begins[]` for the two public batches before running anything. Run `ctest -R text_composition.recovery`; the public test pins `1+;22;3*4;` (values 22 and 12, one error, `begins[0] == 3`), `2147483647+1;9;` (only 9, one error), fuel 2 giving `TC_FUEL`, 17 statements giving `TC_RANGE` and `NULL` with length 1 giving `TC_INVALID`, the last three with the batch unchanged. Then add what it lacks: 17 failing statements, and a 257-byte segment. Build two variants of your own, one whose resume point is wrong and one that loses the diagnostic or fabricates a value for a failed statement, and see which existing CHECK, if any, stops each.

What to capture and how to read it. Keep each `TC_ASSERT:<line>:<expression>` text from stderr; the expression names the property that failed (value list, error count, offset or snapshot). Snapshot the caller's batch before and after every refused call. Record commands and source hashes so someone else can reproduce the run. If a variant survives the public test, that is a gap in the test and you must add the check that kills it. The assessor's mutation set also checks this invariant.

Impact class. `demonstrated-invariant-violation`, only once you have built a variant that publishes a wrong or fabricated value on named bytes. Do not call it a crash, sanitizer finding or code execution; the effect is local to synthetic arithmetic text.

Remediation and regression. Take the half-open segment `[begin, delimiter)` before parsing, resume at `delimiter + 1` and publish only after the statement succeeds. Keep the failing inputs as regression tests beside the existing `recovery` CHECKs.

Limitations. This is a bounded original language only. It does not show an attack on a production compiler, and newline synchronization (the delayed policy) changes the admitted language rather than preserving it. Author execution is not independent learner mastery.

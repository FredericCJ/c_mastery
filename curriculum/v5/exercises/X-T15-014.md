# X-T15-014: Statement synchronization with staged semantic results and diagnostic retention

## Prerequisites

Know typed arrays, half-open ranges, staged publication, source offsets and syntax/semantics separation. Recovery and formatting require your completed X-T15-012 implementation and its exact PdTree contracts. Bring grammar traces, failure snapshots and the public `parsing_depth` workspace; dependency import is explicit. Template evaluation additionally needs lexical scope and bounded graph traversal. No library implements the new mechanism for you.

## Environment

The explicit [text-composition contract1](../../../labs/text_composition/CONTRACTS.md) gives all input types, operations, exact grammar, capacities, ownership, failure/resource and local security rules. Implement `src/text.c`; configure the actual prerequisite workspace with CMASTERY_PARSING_DEPTH_ROOT. Host tools and models remain outside the target component contract. Inspect dependency identity and emitted resource costs; no runtime absence or language-level safety follows from the API spelling.

## Problem

Implement tc_recover by composing the actual Pd lexer, Pratt syntax tree and checked interpreter. Parse semicolon-terminated expression batches, discard only failed statements and retain absolute diagnostic spans. The concrete 1+;22;3*4; batch must yield22 and12 with one error. A syntactically valid overflowing statement must produce a semantic diagnostic instead of a fake value. Implement the named newline-synchronization transfer without changing the retained parser.

## Necessity

A compiler that stops at the first error cannot collect later independent diagnostics; a parser that resumes one byte too late loses valid input. Syntax success is distinct from safe evaluation. Recovery strategies discard context deliberately and can cascade after an inserted delimiter; binary-frame resynchronization does not establish this language contract.

## Reasoning

Prove every delimiter is consumed exactly once and the next statement begins at its successor. Explain the staged ownership of token/tree/result storage, and why no failed statement publishes a value. Derive separate512-byte scan admission,256-byte imported segment limits,16-result/16-diagnostic capacities and whole-batch failure atomicity. The budget counts scan positions, not every imported instruction. Give the counterexample to treating newline synchronization as a semantics-preserving optimization. Supply pre/postconditions, loop/stack invariants, ownership, failure and complexity arguments. Classify guarantees supplied by ISO C, diagnostics, runtime checks, external models and caller discipline separately.

## Deliverables

- D1: Representation/grammar derivation, inspected-source comparison, exact invariant and a plausible wrong explanation with a counterexample.
- D2: Original C mechanism and actual prerequisite binding, resource/stack/work ledger, staged output and cleanup argument.
- D3: Independent oracle, complete concrete inputs/results, boundary/failure preservation snapshots and two causal semantic mutants.
- D4: Named delayed transfer implementation and predictions, changed assumptions, equal-contract comparison and evidence limits.

## Verification

Use an independent list-of-statements/value table on valid, malformed, empty, overflowing and missing-terminator cases. Check actual absolute offsets, survivors and diagnostic statuses; force17 successes,17 errors,257-byte segment and every fuel boundary. Kill the resume-one-byte-late and semantic-error-suppression mutants for different reasons. Run both delimiter policies on the same bytes and record changed acceptance. Run GCC/Clang debug, optimized and sanitizer profiles; retain exact commands, raw outputs and source hashes. Public `text_composition.recovery` must reject the compiling incomplete scaffold with TC_ASSERT. Passing public examples without D1/D4 is insufficient. The private oracle uses a different model and the reference campaign checks mutation sensitivity.

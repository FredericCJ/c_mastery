# X-T02-001: Semantic verdicts and repairs

## Prerequisites

Read T02.07–T02.08 and T02.12, with the T03 lifetime introduction. Bring a two-translation-unit build from PR-T02-01 and a typed-expression notebook; neither must include a solution to these cases. Know limits macros, full expressions and automatic object scope. The executable repair produces a new artifact and imports no library mechanism.

## Environment

Apply [shared contract v1](shared-contract.md), with profile A only for the deliberately isolated diagnostic/observation harness. The verdict/repair component remains profile C. C17 is authoritative for the required answers; GCC/Clang modes are observations, not a way to reconstruct historical standard wording. Include the inspected C17 temporary-object correction in the authority ledger without assuming it changes every lifetime rule.

## Problem

Implement `fd_verdict(FDCase)` for the ten named cases and `fd_repair_step(value,previous)`. First seal a prediction table with classification, type derivation, diagnostic obligation, missing premises and a rebuttal of a plausible incorrect explanation.

| Case | Source or execution under analysis |
|---|---|
| `FD_MIXED_SIGN` | `-1 < 1u` |
| `FD_UNSIGNED_WRAP` | `UINT_MAX + 1u` |
| `FD_UNSEQUENCED` | `int i=1; int r=i++ + i++;` |
| `FD_CALL_ORDER` | `emit('A') + emit('B')`; each call writes one character and returns 1; assume both writes succeed |
| `FD_NEGATIVE_SHIFT` | `-1 >> 1` |
| `FD_SIGNED_OVERFLOW` | `INT_MAX + 1` |
| `FD_SHIFT_WIDTH` | `1u << (sizeof(unsigned) * CHAR_BIT)`, with a representable size product |
| `FD_POINTER_CONSTRAINT` | `int *p = 1;` |
| `FD_ENDED_LIFETIME` | `int *p; { int x=7; p=&x; } int y=*p;` |
| `FD_SHORT_CIRCUIT` | `0 && (1/0)` |

The classes are defined, unspecified, implementation-defined, undefined and constraint; unknown IDs return `FD_UNKNOWN`. For CALL_ORDER classify the observable log order, not the numerical sum. Undefined source is text for analysis, never included in the ordinary runnable suite. Constraint source is separately translated only.

The repair operates on two distinct writable live `int` objects: store the old `*value` in `*previous`, increment `*value` exactly once, return `FD_OK`. At `INT_MAX` reject with `FD_RANGE` and preserve both. Null or identical pointers reject with `FD_INVALID`. Do not execute signed overflow even temporarily.

## Necessity

A plausible numeric answer can hide a wrong semantic model. “Parentheses force left-to-right effects,” “all compiler warnings denote undefined behavior,” and “undefined means one of several documented results” are specific claims to falsify. The repair tests whether classification transfers to construction.

## Reasoning

Give each expression's type before its value, identify which subexpressions are evaluated, and draw the sequencing graph. State lifetime of every object referenced. Distinguish unspecified choice from implementation documentation and lack of any required runtime result. Explain why dead-pointer reasoning must not depend on numerical address stability. Prove the repair precondition and transactional postcondition, with O(1) work/storage.

For a changed edition, compare exact inspected clauses/corrections; if an authority is inaccessible, label the conclusion unresolved. Do not infer that equal C11/C17 compiler output means the editions have identical rules.

## Deliverables

- **D1:** ten-row prediction/rebuttal/authority table and sequencing/type/lifetime diagrams.
- **D2:** verdict function, repaired operation, isolated diagnostic sources and defined observation harness.
- **D3:** actual diagnostic matrix, repair extrema/sentinel tests, and a minimized correction to one incorrect explanation.
- **D4:** changed-type and changed-output-contract defense, then a sealed delayed assessment.

## Verification

Public tests establish valid category values and the repair contract; the assessor independently reviews exact verdicts and reasoning. Compile the constraint example alone under both compilers, recording messages and status without asserting exact text. Run only already-classified defined/unspecified/implementation-defined examples with the relevant documented premises. Do not run the undefined entries hoping for a stable answer.

Test repair at `INT_MIN`, -1, 0, `INT_MAX-1`, `INT_MAX`, null pointers and identical pointers. Kill a compiling mutant that increments before checking the limit, using analysis plus a defined boundary rejection test. A sanitizer finding can corroborate a defect but is not required proof of the semantic verdict.

## Rubric

Apply the metadata criteria and shared six dimensions. A correct enum table with no derivation earns at most 1 for mechanism. Misclassifying the constraint as merely an optional warning or treating repeatable undefined results as guaranteed fails the gate. Independent level 3 requires an unseen expression and a justified repair before tool observations.

## Hints

1. Separate translation requirements from execution semantics before evaluating numbers.
2. Annotate operand types, then draw ordering arrows; absent arrows are not a promise of reverse order.
3. For the repair, ask whether both postconditions are simultaneously satisfiable if the output pointers are identical.

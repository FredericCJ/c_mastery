## Security

Why this matters here. A query result in this lab is a 32-bit mask of row IDs, and every later filter (phrase, range, the final composition) treats each set bit as a promise that the slot holds a live row that really satisfies the query. ISO C gives that promise no protection: the mask is an ordinary uint32_t, so a complement computed over all 32 bit positions also selects slots that were never rows or were deleted, and an incidence mask that is not rebuilt after qi_replace keeps naming a row for terms it no longer has. Both mistakes are silent: nothing crashes and a sanitizer says nothing, so this exercise measures result integrity against a model instead of waiting for a fault. Nullable comparison adds a third trap: a row without a value is neither yes nor no, so "not yes" is not "no".

What to try. On paper first. In the test's rows slot i is alive unless i is a multiple of 3 and has a value only when i is odd; list the slots an empty required/forbidden pair must select, and the slots that the complement of the yes mask for "value >= 15" would wrongly add. Then, once your qi_terms, qi_replace, qi_compare and qi_logic pass `query_tests bitmap`, build two variants of your own, each breaking one property: a result that can contain a slot outside the live universe, and a replacement after which queries still see the replaced row's earlier terms. Predict which check should fail before you run each variant.

What to capture and how to read it. For each variant keep the stderr line `QI_CHECK:<line>` and map the line to the check in labs/corpus_query/tests.c: the empty-set check, the check after replacing slot 7, the nine-pair AND/OR/NOT loops, the per-slot qi_compare loop, the invalid-truth admission with its sentinel output, or the 33-row admission. A variant that survives bitmap exposes a gap in the public test; record it and add the missing case instead of counting it as a pass. Then run the same rows through the supplied query_driver, which prints masks and compares nothing, and compare them with a model that scans the raw rows without using your index. The input that separates a complemented yes mask from the true unknown set is a dead row and a live row without a value placed beside a live match.

What this does and does not show. The consequence is a wrong mask on synthetic rows. No supplied artifact demonstrates it, so the impact class holds only once you build the variant. The assessor's mutation set also checks this invariant. Nothing here involves concurrency, persistence, forged index bytes or more than 32 rows, and finite cases do not prove the invariant for all inputs.

# X-T73-011: Quiescent coroutine cancellation before cleanup and terminal delivery

## Prerequisites

Complete X-T72-008, X-T73-003, X-T66-002 and retain the actual named learner artifacts. Reconcile their ownership and error contracts before writing the adapter.

## Environment

Actual learner errors/ownership/coroutines/messaging implementations via explicit source imports. No replacement parser, allocator or coroutine library. Python, CMake and sanitizers are host verification tools. Read the shared contract for platform, serialization and valid-pointer assumptions. ISO C does not enforce moves, borrow lifetimes or quiescent callbacks.

## Problem

Implement McRead as an adapter over the actual COAsync frame, OwScope and MsgOperation. It reads1..8 synthetic bytes through COAsyncPort, retaining the caller output until terminal completion. Poll may accept partial data and register a callback. Cancellation must establish port quiescence, run cleanup once and only then notify the receiver. The receiver may destroy the entire McRead. Preserve caller output on pending, cancellation and backend error while reporting the accepted partial byte count. All calls and callbacks are serialized; state the backend disarm contract explicitly.

Supplied files: composition.h, the compiling unsolved adapter, public CTests, the expected-state fixture and explicit source-dependency CMake options.

The supplied port returns bytea then AGAIN, data completingabc, or byteb plus error. Pending then cancel delivers CANCELLED with progress1 and unchanged output. Full completion publishesabc and delivers OK,3. Partial error delivers FAILED,2 with unchanged output. Every path has exactly one arm, disarm, cleanup and notification. Test both retained state and heap state freed inside the receiver; no adapter access may follow delivery.

## Necessity

Cancellation intent, callback quiescence, resource cleanup and terminal notification are four separate events. Each underlying component can pass its own tests while an adapter orders these events incorrectly. Generation matching rejects stale logical tokens but cannot make a freed callback context safe to read.

## Reasoning

Derive a composed ownership graph and partial order arm before quiescent disarm before cleanup before receiver; distinguish stop intent from completion and explain why a generation token is not reclamation.

Implement serialized init/poll/cancel using the real three component APIs, publish only complete bytes, preserve partial progress on failure and use no adapter field after the receiver may free it.

Predict pending/cancel, full completion and partial error traces for retained and receiver-freed states; test mismatched generations and duplicate calls on live terminal state, and reject skipped-disarm and skipped-cleanup mutants.

Replace synchronous quiescent disarm with asynchronous cancellation acknowledgement. Derive a retained operation reference and completion winner protocol, including a delayed callback, instead of freeing the frame when cancellation is requested. State entry ownership, postconditions on each failure, the publication/notification point and peak live resources. Compare C programmer/runtime discipline with the inspected language-level ownership/coroutine guarantees; provide a counterexample to automatic equivalence.

no-data cancellation, queued-notice cancellation, fragmented completion,

and retained state. Record request, worker exit, notice release, cleanup and
receiver order. Reject premature-quiescence and leaked-notice controls. Run
ThreadSanitizer separately from AddressSanitizer; neither proves all schedules.

before the existing synchronous-disarm COAsync contract can release its borrow.
A delayed variant may change acknowledgement delivery or require multiple
concurrent owner threads; that requires a new protocol, not removing the
single-owner precondition. The supplied implementation does not establish it.

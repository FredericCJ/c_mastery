# X-T69-010: Versioned plugin objects and borrowed code lifetime

## Prerequisites

Bring pinned contracts and fresh recall for io.stream, memory.pool, measurement.capture; prerequisite exercises: X-T69-001, X-T69-008. Required knowledge includes C object lifetime, checked arithmetic, ownership, typed arrays and the selected source passages. The shared contract and modern-cost contract are explicit parts of this exercise. Existing project estimates describe author accounting; they impose no learner time ceiling.

## Environment

Use C17 hosted Linux with GCC and Clang, CMake and host Python. Record compiler/ABI versions, integer widths, sizeof/alignment and optimization. Mechanism code uses no library implementing the mechanism. Allocator callbacks are supplied dependencies with separate ownership. A strict freestanding port requires its own generated-code/link audit and is not established by the hosted run. Compare C11 draft/C17/C23 only where inspected normative evidence supports the claim; exact published C17 access remains a reference gap.

## Problem

Implement DSLoaded open/acquire/release/close using only original test DSOs. Load an explicit local path with RTLD_NOW|RTLD_LOCAL, resolve the exported complete DSPlugin object, validate ABI1/sizeof/callbacks and maintain a bounded borrow count. Close must reject while API/code pointers are borrowed. Add original fixtures for missing symbol and incompatible size metadata, still backed by actual complete objects. Analyze constructor execution before validation and why version checks cannot sandbox malicious same-process code.

Supplied artifacts: labs/dispatch/include/dispatch.h, deliberately incomplete labs/dispatch/src/dispatch.c, executable anchors, fixture PR-T69-10.json and the shared CONTRACTS.md. Expected example: The ABI9 original fixture rejects and leaves the module empty. ABI1 opens; acquire then close returns busy. Its apply(17,3) returns20. Clear the borrowed pointer, release, and close empties handle/API. Never call a pointer after release/close to infer whether the loader really unmapped it.

## Necessity

A symbol address supplies neither semantic compatibility nor lifetime. A successful dlclose need not remove mappings, and a surviving address is not permission to keep using a logically unloaded API.

## Reasoning

T69.10.a: Separate ISO object/function pointer rules, the target ABI and Linux loader semantics, including dlsym error handling, constructor effects and logical invalidation after close.

T69.10.b: Implement failure-clean loading, exact version/size admission and borrowed-code quiescence using a typed exported object; define trusted fixture extent rather than pretending a size field proves memory validity.

T69.10.c: Run original good/bad/missing-symbol/size fixtures under GCC/Clang sanitizers, verify each acquisition prefix and reject ignored-version and premature-close mutants by intended assertions before an invalid call.

T69.10.d: Transfer to an ABI with optional trailing methods and independently built clients. Specify common-prefix compatibility, alignment/calling-convention/version negotiation and code/data allocator ownership; test with separate shared libraries and record unsupported ABI combinations.

State preconditions, postconditions, representation invariants, resource ownership, failure publication and complexity. For each guarantee identify ISO C rules, diagnostics, runtime checks, external verification and programmer discipline separately. Include a minimal counterexample to an overstated equivalence with the corresponding language/library abstraction. Apply all13 dimensions in modern-cost-contract.md, recording genuine non-applicability with reasons and unavailable measurements as gaps.

base declaration, while client2 understands optional bit1. Use all ten original
complete-object fixtures. State the admission matrix before running it. Verify
that required bits are understood, optional unknown bits are ignored, and no
optional member is read without its genuine object type and admitted extent.
Explain why a field claiming a large extent is not evidence of actual storage.

constructor increments, including libraries rejected for missing symbols or old
ABI sizes. Apply17+3 produces20; negative state leaves the sentinel unchanged.
The new description is exactly the two octets `v2`; a one-octet destination fails
without publication. Four simultaneously acquired features block close; the fifth
fails unchanged. Release each exactly once before close and never probe stale code.

copy, loader costs and target-specific stack/code observations in the cost dossier.

# X-T28-002: W1C acknowledgement and consuming-read traces

## Prerequisites

Read PR-T28-01 and labs/b03_depth/CONTRACTS.md version1. Required prior exercises are listed in metadata. Bring an event/state trace notebook and a C17 test workspace; no unlisted accepted artifact is imported. Knowledge: object lifetimes, integer bounds and the parent's I/O, concurrency or device model. State which earlier ownership arguments are reused and which platform assumptions are new.

## Environment

The default CMake build uses learner stubs. Components use C17/profile C; Python and libc are host verification tools. All experiments are unprivileged local models with synthetic bytes/events. C17 atomic mailbox code is distinct from the sequential device/I/O models. Record compilers, optimization, target data model and undefined symbols. Actual OS, ISA, ABI and board guarantees require separate evidence; the host run supplies none automatically.

## Problem

Implement the invented B3Device adapter. Status15, ack5 leaves10 after exactly one write and no read. Data read with bit0 clear returns WAIT unchanged; set bit0 with a synthetic event, then one read returns payload and clears only bit0. Mask16 is INVALID without access. Demonstrate a deliberately flawed read-modify-write acknowledgement clearing an unrequested bit; compare it to writing only the requested mask. Do not map this host struct to an actual address.

Use supplied include/depth.h, src/depth.c, tests/tests.c and fixtures/b03_depth/cases.json. The complete API, pointer, state, ownership and failure contract in labs/b03_depth/CONTRACTS.md is explicitly incorporated. Preserve all admission and termination rules.

## Necessity

A normal-looking assignment can have device-defined effects. Reading before writing a W1C mask changes which events are cleared. Volatile neither defines register semantics nor provides an atomicity/order proof for the device.

## Reasoning

Write a register/access contract and access trace: admitted masks, side effects, counts and reserved-bit policy. Explain synthetic logical width versus real bus width. Separate C volatile accesses, compiler emission, CPU/device ordering and peripheral behavior. Show an event arriving before/after acknowledgement and explain unavoidable coalescence when the same status bit was already set.

Distinguish enforcement by C, diagnostics, runtime state checks, proof/model and caller/environment discipline. Show one plausible wrong explanation and a minimal counterexample. State precisely what each experiment cannot establish.

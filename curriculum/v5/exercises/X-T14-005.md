# X-T14-005: Interval search with rotation-safe maximum endpoints

## Prerequisites

Read PR-T14-09 and the applicable T14/T15 module teaching. Bring your own array/bounds tests and invariant notebook; no unlisted accepted artifact import is required. Know unsigned arithmetic, half-open spans, typed object lifetime and asymptotic work. Interval work additionally requires AVL rotations; suffix work requires stable counting sort. Diagnose those prerequisites before attempting the integrated mechanism.

## Environment

The explicit shared contract is [corpus index contract1](../../../labs/corpus_index/CONTRACTS.md). It supplies the API, representation, ownership, null/disjointness premises, status precedence, execution profile, target restrictions and evidence limits. Use the supplied compiling learner scaffold; author solutions remain separate. Record actual compiler/data-model assumptions. ISO C type checking does not establish the semantic invariants or pointer preconditions.

## Problem

Build a64-node typed AVL interval tree keyed by (low,id), with subtree maximum endpoint. Implement insert, removal, one-overlap search and sorted all-overlap enumeration with transactional capacity failure. Start with [1,3),[3,5), nested[-2,9), and duplicate-low intervals distinguished by id. Delete a two-child node whose replacement changes an ancestor maximum, then reuse freed slots. A returned value is copied; there are no borrowed-node handles.

## Necessity

A balanced search tree alone does not justify pruning. Stale maximum metadata can make search falsely report absence even when rotations preserve key ordering. Closed versus half-open endpoint conventions change both overlap and pruning inequalities. An all-results API adds an output-ownership and partial-publication failure boundary absent from find-one.

## Reasoning

Prove key ordering, AVL height/balance, exact subtree maximum and one-to-one partition of live/free nodes. Derive both pruning directions before choosing a branch. Show the bottom-up repair order after single/double rotations and successor deletion. State key uniqueness precisely: id alone is not unique. Derive O(log n) mutation/find and O(n) worst-case enumeration plus scratch, rather than importing a stronger bound from a different algorithm. Include one plausible incorrect explanation and its smallest counterexample. Separate mathematical proof, ISO C guarantees, compiler diagnostics, dynamic checks and caller discipline. Fixed bounds make experiments tractable; they do not excuse a false general complexity claim.

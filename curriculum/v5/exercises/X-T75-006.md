# X-T75-006: Health breakers, bulkheads and stale completions

## Prerequisites

Bring pinned contracts and fresh recall for io.async, measurement.capture; prerequisite exercises: X-T03-005, X-T75-001. Required knowledge includes C object lifetime, checked arithmetic, ownership, typed arrays and the selected source passages. The shared contract and modern-cost contract are explicit parts of this exercise. Existing project estimates describe author accounting; they impose no learner time ceiling.

## Environment

Use C17 hosted Linux with GCC and Clang, CMake and host Python. Record compiler/ABI versions, integer widths, sizeof/alignment and optimization. Mechanism code uses no library implementing the mechanism. The T73 channel backend supplies its declared POSIX synchronization; the virtual-time model itself supplies no OS clock, sleep or hidden scheduler. A strict freestanding port requires its own generated-code/link audit and is not established by the hosted run. Compare C11 draft/C17/C23 only where inspected normative evidence supports the claim; exact published C17 access remains a reference gap.

## Problem

Implement RZGate with separate closed/open/half-open health state and active-permit limit1..2. Two consecutive backend failures open for4 ticks; a single half-open probe decides recovery. Each permit carries owner, slot and nonwrapping generation; completion also uses its saved admission epoch so an old success cannot heal a new open period. Add a sliding-window failure-rate policy and a two-tenant bulkhead variant with explicitly reserved capacity, retaining neutral client-error outcomes.

Supplied artifacts: labs/resilience/include/resilience.h, deliberately incomplete labs/resilience/src/resilience.c, executable anchors, fixture PR-T75-06.json and the shared CONTRACTS.md. Expected example: With limit1, a second simultaneous admission returns BUSY even while CLOSED. Two classified failures open. An older outstanding success releases capacity but leaves the newer OPEN state unchanged. At cooldown equality one probe may enter, a second is BUSY, and successful probe closes. Repeated completion is STALE.

## Necessity

Health decisions summarize observations, while a bulkhead bounds admitted resource ownership. Conflating them allows an otherwise healthy slow backend to exhaust callers or an old completion to erase newer failure evidence.

## Reasoning

T75.06.a: Derive distinct health and capacity invariants, permit ownership, epoch identity and neutral-versus-backend-failure classification; explain why a failure window is not a concurrency bound.

T75.06.b: Implement bounded admission/completion with generation and epoch exhaustion, including late old-epoch results and four-tick cooldown overflow retirement.

T75.06.c: Model every two-permit completion ordering, stale/duplicate completion and half-open race. Add and test a sliding-window policy with an independent recomputation of its retained observations.

T75.06.d: Transfer to two tenants and heterogeneous request costs. Derive isolation guarantees, starvation tradeoffs and cancellation acknowledgement, then compare recovery latency and retained resources under equal admission policies.

State preconditions, postconditions, representation invariants, resource ownership, failure publication and complexity. For each guarantee identify ISO C rules, diagnostics, runtime checks, external verification and programmer discipline separately. Include a minimal counterexample to an overstated equivalence with the corresponding language/library abstraction. Apply all13 dimensions in modern-cost-contract.md, recording genuine non-applicability with reasons and unavailable measurements as gaps.

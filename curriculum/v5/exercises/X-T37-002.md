## Problem

Implement sc_clock and sc_run for the exact original ISA in CONTRACTS.md. Program: LI r1,3; LI r2,1; SUB r1,r1,r2; BNZ r1,2; ST r1,5; LD r3,5; HALT. It commits11 instructions with r1 trace [3,3,2,2,1,1,0,0,0,0,0], final registers [0,0,1,0], memory[5]=0 and halted1. Run budget4 then resume budget7 and obtain the same final state. For SUB r0,r0,r1 with old values9,3, result6; reading an already updated destination is wrong. Invalid LD address16, unknown opcode, impossible register, out-of-program branch and nonhalt falloff must preserve state/control. Commit UINT32_MAX rejects before wrap. HALT is stable; zero budget is not a halt instruction. Invalid initial control rejects even at budget0.

## Necessity

The repository audit found a concrete contract/execution mismatch: the earlier algorithms family implements idempotent AVL duplicates and first-match bytes, and explicitly excludes a clocked instruction engine. This additive exercise preserves baseline contracts and accepted evidence while exposing the missing behavior. Selected A/B/C/D/F/H/I/J families assess derivation, construction, boundaries, diagnosis, falsification, resource arguments and changed assumptions without manufacturing irrelevant allocation or network failure modes.

## Reasoning

A transition snapshots old values, derives control and next state, validates every operand and next PC, then publishes once. A temporary is not merely an optimization: it expresses the commit boundary. Repeated clocks retain earlier successful commits on a later error; a whole-run transaction would be a different contract. Unsigned byte arithmetic models modulo256 explicitly. The count is committed model instructions, not real cycle timing, and the byte-register datapath says nothing about a commercial microarchitecture. State preconditions, postconditions, ownership, failure publication and complexity for each API. Identify what ISO C enforces, what the runtime checks, and what remains programmer discipline. Refute a plausible incorrect explanation with a minimal input.

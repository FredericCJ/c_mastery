# X-T15-003: Byte suffix ranks, LCP ranges and disjoint repeated spans

## Prerequisites

Read PR-T15-10 and the applicable T14/T15 module teaching. Bring your own array/bounds tests and invariant notebook; no unlisted accepted artifact import is required. Know unsigned arithmetic, half-open spans, typed object lifetime and asymptotic work. Interval work additionally requires AVL rotations; suffix work requires stable counting sort. Diagnose those prerequisites before attempting the integrated mechanism.

## Problem

Implement a copied byte-text suffix index for length0..64, including the empty suffix. Build ranks by stable integer-key doubling, then adjacent LCP. Provide exact pattern intervals, LCE and longest repeated spans with overlap permitted or forbidden. Reproduce the banana order/LCP/ranges in the contract, then use embedded0/255 and all-equal texts. Never use a zero byte as an implicit terminator or materialize n complete suffix copies in the component.

## Necessity

The retained specialized-algorithm project currently supplies run-length encoding evidence; it does not implement suffix indexing. Rank-pair stability, empty-suffix ordering and prefix-equal upper bounds are independent mechanisms. The longest adjacent LCP solves overlapping repetition but not all nonoverlap policies without further reasoning.

## Reasoning

Derive the rank equivalence for length2h from two lengthh ranks and justify stable secondary-then-primary sorting. Prove the permutation/sentinel invariant and adjacent-LCP scan bound. Derive LCE as an adjacent-minimum query, and explain the cost of the actual implementation. For disjoint repeats prove the length bound min(LCP,abs(offset difference)); state tie breaking. Contrast plain pattern search with the inspected accelerated algorithm without claiming its bound. Include one plausible incorrect explanation and its smallest counterexample. Separate mathematical proof, ISO C guarantees, compiler diagnostics, dynamic checks and caller discipline. Fixed bounds make experiments tractable; they do not excuse a false general complexity claim.

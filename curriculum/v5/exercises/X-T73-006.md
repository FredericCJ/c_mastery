# X-T73-006: Bounded work stealing with an explicit C memory-order proof

## Prerequisites

Explain C17 atomic ordering, POSIX wait predicates, existing queue ownership, async terminal completion and stable coroutine-frame registration; retain the named imported learner artifacts. Required learner artifacts: work.pool, sync.condition_queue, sync.spsc, io.async, io.deadline, testing.faults, coro.frame. Do not import an assessor implementation.

## Environment

Implement mechanisms locally using declared typed storage/callbacks; hosted harness and diagnostic runtimes are separate. See laboratory contract for exact dependencies. Use C17 with extensions disabled and warnings treated as errors. A diagnostic extension is identified explicitly and does not become an ISO guarantee. The full platform, pointer, callback and concurrency preconditions are in [messaging/CONTRACTS.md](../../../labs/messaging/CONTRACTS.md).

## Problem

Implement the eight-slot single-owner/multiple-thief deque with atomic unsigned payloads and sequentially consistent operations. Owner push/pop uses the bottom; thieves steal the top. Compete for the final item using CAS, return CONFLICT on loss without publishing output, and retire indices before wrap. Derive the SC linearization argument before comparing the published weaker-order algorithm. Integrate with work.pool using integer task IDs whose external lifetime is retained until exactly-once completion.

Concrete inputs and expected results: Push7,push8,pop,steal,steal returns OK,OK,8,7,EMPTY. Eight live entries fill capacity and a ninth push leaves state unchanged. Empty pop preserves its output canary. Starting quiescent top=bottom=SIZE_MAX-1 makes push return OVERFLOW. Two thieves plus owner process4000 distinct IDs exactly once in the supplied threaded anchor.

Supplied artifacts: labs/messaging/include/messaging.h, compiling unsolved src/messaging.c, CTest messaging.stealing, fixtures/messaging/PR-T73-06.json, and the shared contracts. State every additional backend assumption before running it.

## Necessity

Identify linearization and ownership in owner/thief races, last-item arbitration, finite-index exhaustion and stale slot reads; distinguish SC correctness from weak-order proof and actual lock-free progress. The misconception and changed-condition case below are separately assessed; ordinary successful execution alone does not cover them.

## Reasoning

Derive a circular representation with monotonic nonwrapping indices and atomic slots; implement push/pop/steal with a proof for empty, full, last-item and reused-slot states. Give the abstraction function, admitted states, pre/postconditions, ownership graph, failure effects and complexity before implementation. Identify the enforcement boundary of every safety claim using the shared modern-cost contract. Distinguish an invalid caller object from an operational failure admitted by the API.

## Deliverables

- D1: Identify linearization and ownership in owner/thief races, last-item arbitration, finite-index exhaustion and stale slot reads; distinguish SC correctness from weak-order proof and actual lock-free progress.
- D2: Derive a circular representation with monotonic nonwrapping indices and atomic slots; implement push/pop/steal with a proof for empty, full, last-item and reused-slot states.
- D3: Differentially compare1095 bounded sequential traces with Python deque, include repeated empty pops and capacity reuse, record concurrent invocation/response histories and check small histories for legal linearizations. Reject wrong-pop and omitted-steal-CAS mutants. Run TSan, inspect generated instructions and report atomic_is_lock_free; do not infer weak-memory correctness from x86 stress.
- D4: Weaken SC to acquire/release/fences one edge at a time, deriving a C memory-model argument and model-checker counterexamples before benchmarking. Delayed assessment changes payloads to pointers and permits array growth: add a reclamation scheme and prove a losing thief cannot dereference freed storage. Complete all thirteen cost/enforcement dimensions with evidence or a mechanism-specific non-applicability.

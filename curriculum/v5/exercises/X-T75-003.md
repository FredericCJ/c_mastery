# X-T75-003: Hashed timer-wheel collisions, cancellation and expiry work

## Prerequisites

Bring pinned contracts and fresh recall for containers.ring, io.deadline, measurement.capture; prerequisite exercises: X-T03-005, X-T30-002. Required knowledge includes C object lifetime, checked arithmetic, ownership, typed arrays and the selected source passages. The shared contract and modern-cost contract are explicit parts of this exercise. Existing project estimates describe author accounting; they impose no learner time ceiling.

## Environment

Use C17 hosted Linux with GCC and Clang, CMake and host Python. Record compiler/ABI versions, integer widths, sizeof/alignment and optimization. Mechanism code uses no library implementing the mechanism. The T73 channel backend supplies its declared POSIX synchronization; the virtual-time model itself supplies no OS clock, sleep or hidden scheduler. A strict freestanding port requires its own generated-code/link audit and is not established by the hosted run. Compare C11 draft/C17/C23 only where inspected normative evidence supports the claim; exact published C17 access remains a reference gap.

## Problem

Implement the four-bucket/four-slot wheel with delay1..16, absolute due ticks, intrusive index links and owner/generation identities. Tick advances one unit and returns every due slot as a bitmask; cancellation unlinks immediately. Extend to a two-level wheel that cascades coarse timers into fine buckets, preserving exact expiry and cancellation identity. Reopen the PR-T50-05 sealed scheduler decision and add this as a third measured alternative to its existing structures under the same timer contract.

Supplied artifacts: labs/resilience/include/resilience.h, deliberately incomplete labs/resilience/src/resilience.c, executable anchors, fixture PR-T75-03.json and the shared CONTRACTS.md. Expected example: At now0 a delay5 timer maps to bucket1 but must not fire at tick1; it fires exactly at5. Cancelling generation1 then reusing that slot at generation2 makes the old ID STALE. Simultaneous due timers all appear in the returned mask, without invoking callbacks during linkage traversal.

## Necessity

The important wheel tradeoff is not merely replacing a comparison with modulo. Collisions, cancellation frequency, finite identity and concentrated expiries determine correctness and latency.

## Reasoning

T75.03.a: Derive bucket index, full due identity, list invariants and generation retirement. Prove why modulo bucket equality alone is insufficient across revolutions.

T75.03.b: Implement bounded schedule/cancel/tick and a two-level cascade extension with no lost or duplicate expiries, explicit horizon, late tick and immediate timer policies.

T75.03.c: Enumerate delays1..16, cancellation/reuse traces and same-bucket collisions against an ordered due-event oracle; test numeric exhaustion and every link removal position.

T75.03.d: Compare heap, ordered list and wheel using equivalent ordering, horizon and cancellation guarantees. Measure worst expiry burst, empty-tick work, memory and jitter; distinguish per-timer output cost from constant bookkeeping claims.

State preconditions, postconditions, representation invariants, resource ownership, failure publication and complexity. For each guarantee identify ISO C rules, diagnostics, runtime checks, external verification and programmer discipline separately. Include a minimal counterexample to an overstated equivalence with the corresponding language/library abstraction. Apply all13 dimensions in modern-cost-contract.md, recording genuine non-applicability with reasons and unavailable measurements as gaps.

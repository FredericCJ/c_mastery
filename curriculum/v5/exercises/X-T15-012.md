## Problem

Write the source-located decimal/operator lexer, nud/led Pratt parser and separate checked tree interpreter. Preserve a valid syntax tree for 2147483647+1 while evaluation returns RANGE unchanged. Derive -2^2,1+2*3,2^3^2 and left/right exponent modes before running. Use the supplied typed postorder representation and exact byte/line/column contract; no parser or expression-evaluation library is permitted.

## Necessity

Binding-power mistakes often survive addition/multiplication examples because those operations can hide grouping. Prefix minus and right-associative exponent expose different call thresholds. Executing arithmetic during parsing destroys the distinction between a valid program and a failed semantic operation and risks C signed overflow.

## Reasoning

Explain the meaning of left binding power, caller right binding power and the strict continuation inequality. Prove that right-associative exponent lowers its recursive threshold while left association does not. Bound recursion from token admission, prove child-before-parent tree construction and separate source-location, syntax and arithmetic failure contracts. Derive widened intermediate bounds and the explicit exponent domain including0^0. Distinguish the teaching language arithmetic from ISO C expression evaluation. Give the smallest concrete counterexample to one plausible incorrect explanation. Separate ISO C rules, the teaching language/grammar, compiler support and programmer-maintained invariants. State every pre/postcondition and no-publication failure boundary.

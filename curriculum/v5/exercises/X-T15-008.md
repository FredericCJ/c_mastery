# X-T15-008: Derive and falsify bounded error-correcting codes

## Prerequisites
Bring X-T04-001 checked-arithmetic reasoning, PR-T04-01 bit operations, PR-T15-01 loop invariants and your own code-distance argument. The component imports no prior algorithm library. The historical PR-T15-10 elective label does not make this required expansion optional.

## Environment
Use C17 and the explicit octet/uint16 profile in the shared contract. Host-side Python codebook enumeration is independent verification. Cortex-M4 object/link audits establish dependencies only; no physical memory or communications target is used.

## Problem
Implement extended Hamming(8,4) and(16,11), bounded syndrome decode, known erasures, four-lane interleaving and rotating-phase transfer. The public header and shared contract define all bit positions, widths, statuses, immutable inputs, unchanged refused outputs and exact workloads. Start with payload1 encoded as135 in the eight-bit convention; independently derive it before viewing expected fixtures.

## Necessity
The corpus exposes coding theory beyond a checksum mention. Correcting a single flipped bit requires a representation and distance argument; blindly applying that decoder to two or more errors can corrupt data. This required refinement assesses those mechanisms without rewriting the retained generic advanced-algorithm leaf or historical acceptance.

## Reasoning
Derive parity equations, linearity and minimum distance4. Prove the0/1/2-error result and2t+s<4 uniqueness bound. Account for all output publication, backing lifetime and fixed-width shift bounds. Explain why a valid codeword can be forged and why interleaving requires known frame phase. Compare rate, work and buffering under equivalent error assumptions.

## Deliverables
D1: exact representation/contract and derivations. D2: all seven API implementations and independent codebook dossier. D3: complete bounded flip matrix, erasures/burst/phase cases, refusal-output evidence, compiled controls, native/target audit and counterexamples. D4: independently reconstructed V1/V2 after at least7days. The shared contract gives concrete inputs, outputs and costs for each item.

## Verification
Run the four named public tests and independent assessor protocol. All592 small and280576 changed-profile0/1/2-error cases must pass; the small nearest-codeword oracle covers all256 received values. Explicitly distinguish finite erasure sampling from the uniqueness proof. Stubs must compile and fail; each anchor has two distinct compiled controls. Compiler/target assumptions and exact commands must be recorded.

## Rubric
Score R1 derivation, R2 decoder/publication, R3 erasure/oracle, R4 interleave/cost and R5 limits separately. Every row needs its own mechanism and counterexample. The metadata and shared contract give0-3 levels; a passing reference campaign is not an independent learner attempt.

## Hints

## Security

The only target is the original `labs/corpus_ecc` encoder, decoder and interleaver, using local arrays and synthetic payloads in one process. There is no device, network, credential or real exploit.

**Adversary.** The attacker knows the public encoding and may flip or replace any or all bits of a codeword or of a four-lane frame, and may encode a payload of their choice. They hold no secret and cannot alter the decoder or the application policy. Because the code is public, anything the attacker can encode is, to the decoder, indistinguishable from a message that was merely noisy.

**Violated property.** Error correction is not message authority. Read it off the anchor `corpus_ecc.burst` (tests.c:101-183). Encoding payload 9 and decoding the result returns `EC_OK` with data 9 although a zero-only policy forbids it (tests.c:179-180). The word 7 is the zero word with three bits flipped; the decoder treats the odd-weight error as one flip and returns `EC_CORRECTED` with a nonzero payload (tests.c:176), because a nearest-codeword decoder at distance 4 can correct one flip but three flips sit nearer another word. The word 135 has weight 4 and is the valid encoding of payload 1, so four flips from the zero word are accepted as `EC_OK` (tests.c:177). A frame interleaved at phase 1 but deinterleaved at phase 0 decodes lane 0 as valid wrong data (tests.c:169-170), and phase 4 is refused with `EC_INVALID` (tests.c:171). The `corpus_ecc.8` and `corpus_ecc.16` anchors show that any two distinct flips return `EC_DETECTED` with the output untouched (tests.c:37-39). The anchors pin one three-flip and one four-flip instance only: derive the general behaviour yourself from minimum distance 4.

**Boundary.** Local arrays in one process; no file, device or radio. The registered anchors print only a marker (ECC_FULL, ECC_ERASURES or ECC_BURST_LIMITS), so success for your experiments is a status and payload that your own harness prints.

**Evidence to capture.** Predict first: for the eight-bit code, which payload does each of the words 7 and 135 decode to, and with what status? Then run `ctest -R corpus_ecc`. Write a small harness of your own and record, for each case, the input word, the flipped bits, the status, the decoded data and the corrected position, together with the distance argument.

**Impact class.** `demonstrated-invariant-violation`, shown by the supplied `corpus_ecc.burst` anchor for the specified words. It is not a crash or sanitizer finding and not a proved impact, because no secret, privilege or arbitrary execution is shown.

**Remediation and regression.** Restate the guarantee as at most two flips and known erasures with 2t+s<4 (t unknown flips, s known erasures). A range check can reject 9 under a zero-only policy but cannot stop a forgery in the authorized range; authentication, identity and replay protection need a separately specified trusted mechanism. The four `corpus_ecc` anchors retain the forged and miscorrected cases.

**Limitations.** This is not a channel or radio model and not an authentication scheme; interleaving bounds bursts of length at most 4 and does not eliminate errors.

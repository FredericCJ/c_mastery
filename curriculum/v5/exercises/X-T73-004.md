# X-T73-004: Actor incarnations, copied mailboxes and failure boundaries

## Prerequisites

Explain C17 atomic ordering, POSIX wait predicates, existing queue ownership, async terminal completion and stable coroutine-frame registration; retain the named imported learner artifacts. Required learner artifacts: work.pool, sync.condition_queue, sync.spsc, io.async, io.deadline, testing.faults, coro.frame. Do not import an assessor implementation.

## Environment

Implement mechanisms locally using declared typed storage/callbacks; hosted harness and diagnostic runtimes are separate. See laboratory contract for exact dependencies. Use C17 with extensions disabled and warnings treated as errors. A diagnostic extension is identified explicitly and does not become an ISO guarantee. The full platform, pointer, callback and concurrency preconditions are in [messaging/CONTRACTS.md](../../../labs/messaging/CONTRACTS.md).

## Problem

Implement a serialized actor with four copied messages, generation-tagged address, run-to-completion handler and explicit death/restart. Enqueue rejects stale incarnation before capacity. A failed handler marks the actor dead and discards queued unsigned messages. Restart is allowed only after handler quiescence and advances generation without wrap. Integrate channel delivery using an explicit single-executor adapter; do not claim the unsynchronized actor struct is safe for concurrent producers.

Concrete inputs and expected results: Enqueue2,99,3 for generation1, where handler99 fails. Step2 adds2, step99 fails and queued3 is discarded. Restart creates generation2; generation1 messages are STALE and cannot affect the new actor. Recursive step while a handler is active returns BUSY.

Supplied artifacts: labs/messaging/include/messaging.h, compiling unsolved src/messaging.c, CTest messaging.actors, fixtures/messaging/PR-T73-04.json, and the shared contracts. State every additional backend assumption before running it.

## Necessity

Explain mailbox ownership, actor identity across restart, run-to-completion serialization and the limit of let-it-crash recovery when effects have already escaped the actor. The misconception and changed-condition case below are separately assessed; ordinary successful execution alone does not cover them.

## Reasoning

Implement admission, dispatch, death and reincarnation with finite generation retirement; design the channel-to-actor executor boundary and message-drop ownership. Give the abstraction function, admitted states, pre/postconditions, ownership graph, failure effects and complexity before implementation. Identify the enforcement boundary of every safety claim using the shared modern-cost contract. Distinguish an invalid caller object from an operational failure admitted by the API.

- D2: Implement admission, dispatch, death and reincarnation with finite generation retirement; design the channel-to-actor executor boundary and message-drop ownership.
- D3: Test full mailbox, stale identity, nested step, failure with queued work, restart while alive and generation exhaustion. Reject stale-generation admission and retained-dead-mailbox mutants. Record effects before failure to show they are not rolled back. Compare actor serialization to a mutex-protected shared object under the same observable ordering.
- D4: Messages become owned buffers and handlers may enqueue to themselves: implement deterministic destruction of abandoned messages without recursive dispatch. Complete all thirteen cost/enforcement dimensions with evidence or a mechanism-specific non-applicability.

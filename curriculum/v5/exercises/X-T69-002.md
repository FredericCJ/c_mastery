# X-T69-002: Fat views, embedded tables and unsafe qualifier substitution

## Prerequisites

Bring pinned contracts and fresh recall for containers.array, measurement.capture; prerequisite exercises: X-T69-001. Required knowledge includes C object lifetime, checked arithmetic, ownership, typed arrays and the selected source passages. The shared contract and modern-cost contract are explicit parts of this exercise. Existing project estimates describe author accounting; they impose no learner time ceiling.

## Environment

Use C17 hosted Linux with GCC and Clang, CMake and host Python. Record compiler/ABI versions, integer widths, sizeof/alignment and optimization. Mechanism code uses no library implementing the mechanism. Allocator callbacks are supplied dependencies with separate ownership. A strict freestanding port requires its own generated-code/link audit and is not established by the hosted run. Compare C11 draft/C17/C23 only where inspected normative evidence supports the claim; exact published C17 access remains a reference gap.

## Problem

Implement ds_embedded for DSBox and compare its in-object table with DSView external table storage under the same measure contract. Construct arrays of1000 synthetic objects and1000 borrowed views, account for owner bytes versus view bytes and measure direct/embedded/fat calls with an equal workload. Compile the qualifier_reject.c fixture, then derive the counterfactual write that would become possible if T** could implicitly convert to const T**; analyze that write without executing it.

Supplied artifacts: labs/dispatch/include/dispatch.h, deliberately incomplete labs/dispatch/src/dispatch.c, executable anchors, fixture PR-T69-02.json and the shared CONTRACTS.md. Expected example: DSBox containing int17 measures17 through its embedded table. If its table returns DS_FAILED, output99 remains99. Assigning char** to const char** produces the intended diagnostic. A successful cast compilation is not permission to perform the counterfactual const write.

## Necessity

A pair of pointers is an implementation choice, not a universal language ABI. Indirection changes where metadata lives, and apparently harmless qualifier widening can make a const object writable.

## Reasoning

T69.02.a: Derive the two representations and their table/data lifetime and cache costs; distinguish logical two-part dispatch from an ABI promise of exactly two machine words.

T69.02.b: Implement an embedded-to-view adapter preserving concrete receiver address, const access and failure publication.

T69.02.c: Validate both representations against the same direct implementation and compile the double-pointer qualifier counterexample under strict C17; diagnose why one-level qualifier addition does not generalize recursively.

T69.02.d: Compare Rust trait-object representation and lifetime bounds with the C pair, then change to a borrowed subobject and multiple interfaces. Recompute pointer adjustment, owner storage and invalidation; no automatic variance or lifetime proof is inherited. Compile the supplied empty-struct probe under strict C17 and compare a one-byte marker field with the inspected Rust zero-sized marker rules. Record extension diagnostics and actual size separately; no zero-size or no-cost C guarantee follows.

State preconditions, postconditions, representation invariants, resource ownership, failure publication and complexity. For each guarantee identify ISO C rules, diagnostics, runtime checks, external verification and programmer discipline separately. Include a minimal counterexample to an overstated equivalence with the corresponding language/library abstraction. Apply all13 dimensions in modern-cost-contract.md, recording genuine non-applicability with reasons and unavailable measurements as gaps.

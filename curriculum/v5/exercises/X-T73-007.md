# X-T73-007: TL2-style software transactions over actual C17 atomics

## Prerequisites

Explain C17 atomic ordering, POSIX wait predicates, existing queue ownership, async terminal completion and stable coroutine-frame registration; retain the named imported learner artifacts. Required learner artifacts: work.pool, sync.condition_queue, sync.spsc, io.async, io.deadline, testing.faults, coro.frame. Do not import an assessor implementation.

## Environment

Implement mechanisms locally using declared typed storage/callbacks; hosted harness and diagnostic runtimes are separate. See laboratory contract for exact dependencies. Use C17 with extensions disabled and warnings treated as errors. A diagnostic extension is identified explicitly and does not become an ISO guarantee. The full platform, pointer, callback and concurrency preconditions are in [messaging/CONTRACTS.md](../../../labs/messaging/CONTRACTS.md).

## Problem

Implement the four-cell MsgStore/MsgTxn contract with atomic unsigned payload, version/lock stamps and global timestamp. Begin captures a snapshot; reads validate before returning; writes buffer locally. Commit tries write locks in index order, reserves a nonwrapping timestamp, validates reads, writes values and releases versions. Conflict or clock exhaustion restores acquired locks and publishes no buffered values. No speculative I/O or allocation side effect is admitted without a separate undo/commit mechanism.

Concrete inputs and expected results: TransactionA starts, B writes cell0=7 and commits: A reading cell0 returns CONFLICT without changing output99. If A reads7 before B commits8, then stages cell1=9, A commit conflicts and cell1 remains0 with its lock clear. Two concurrent increment transactions over two equal cells produce2000 committed increments and never expose unequal admitted reads.

Supplied artifacts: labs/messaging/include/messaging.h, compiling unsolved src/messaging.c, CTest messaging.transactions, fixtures/messaging/PR-T73-07.json, and the shared contracts. State every additional backend assumption before running it.

## Necessity

Derive snapshot validation, write-set locking, abort restoration and the distinction between transaction isolation, atomic C accesses and memory reclamation; explain inconsistent-read hazards before commit. The misconception and changed-condition case below are separately assessed; ordinary successful execution alone does not cover them.

## Reasoning

Implement bounded read/write sets, read-your-writes, nonblocking lock acquisition and validated commit using the declared SC baseline; prove failed commits leave payload unchanged while allowing timestamp gaps. Give the abstraction function, admitted states, pre/postconditions, ownership graph, failure effects and complexity before implementation. Identify the enforcement boundary of every safety claim using the shared modern-cost contract. Distinguish an invalid caller object from an operational failure admitted by the API.

## Deliverables

- D1: Derive snapshot validation, write-set locking, abort restoration and the distinction between transaction isolation, atomic C accesses and memory reclamation; explain inconsistent-read hazards before commit.
- D2: Implement bounded read/write sets, read-your-writes, nonblocking lock acquisition and validated commit using the declared SC baseline; prove failed commits leave payload unchanged while allowing timestamp gaps.
- D3: Force conflict before a read, after a read and during partial lock acquisition; test repeated writes, empty/read-only transactions and timestamp exhaustion. Reject missing read validation and missing commit validation mutants. Use an independent serial-history model for small schedules, TSan for actual threads and fault hooks for every commit phase. Explain why atomic individual loads alone do not provide a coherent transaction.
- D4: Introduce a retryable callback with a synthetic log effect: stage it for commit or supply compensation rather than replaying it blindly. Delayed assessment allows dynamically allocated nodes and privatization; show why the fixed-cell proof says nothing about reclaimed node lifetime and design a compatible reclamation protocol. Complete all thirteen cost/enforcement dimensions with evidence or a mechanism-specific non-applicability.

## Hints

1. Validation after commit is too late if an inconsistent read already caused an invalid operation.
2. A failed lock acquisition must restore every earlier lock.
3. Atomic cells do not make a multi-cell snapshot atomic by themselves.

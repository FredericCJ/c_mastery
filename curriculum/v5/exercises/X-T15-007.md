# X-T15-007: Permutation MinHash, exact finite resemblance and candidate bands

## Prerequisites

Complete the named unsigned arithmetic and algorithm exercises. Bring an invariant notebook, independent test strategy and elementary expectation/probability reasoning. Read the exact registered primary passages and relevant CONTRACTS.md section; the assessor implementation is not a prerequisite.

## Environment

Use the declared C17/profileC contract. Implement only the original component; no third-party sketch or hash library may supply its mechanism. Keep hosted I/O and Python verification separate from the component. C23 mode supplies no automatic bounds, lifetime or statistical guarantee. Pointers, ownership, serialization and hash interpretation remain explicit caller premises.

## Problem

Implement sk_mh_init, sk_mh_add, sk_mh_similarity and sk_mh_merge in src/minhash.c. Each row is an actual finite permutation, validated before publication. The signature stores minimum rank; a separate sentinel represents an empty set. Similarity is an exact fraction of matching positions, with explicit empty policy. Merge computes the signature of union under identical ordered permutations. Do not substitute a weak hash and silently retain a minwise guarantee.

## Necessity

Set resemblance differs from membership, frequency and containment. A bounded signature can estimate resemblance without retaining every element, but cannot reconstruct arbitrary intersections or multiplicity. The explicit small universe permits an exhaustive check of the mathematical probability identity instead of confusing a deterministic seeded sample with a distributional theorem.

## Reasoning

Prove that under a uniform permutation the earliest element of the union belongs to the intersection with Jaccard probability. Handle twoempty and oneempty cases separately. Derive union-by-minimum and construct indistinguishable signatures with different intersections. Distinguish sampling variance, repeated permutations and correlated row order. Give the actual O(k*universe) configuration validation and O(k) update/query work plus storage bounds.

- D1: Derivation, invariants, at least two wrong explanations with counterexamples, exact source locators and assumption/enforcement table.
- D2: Completed ordinary C17 provider, explicit build/dependency manifest, state diagrams and storage/operation cost accounting.
- D3: Independent oracle, boundary and adversarial cases, unchanged-output snapshots, two compiling semantic controls and actual GCC/Clang profile records.
- D4: Required delayed mechanism, changed-condition proof, independent comparison and failure/cost analysis.

Cover malformed permutations, out-of-domain updates, empty/duplicate/idempotent cases, configuration mismatch and unchanged outputs on failure. The ten-row ordered case deliberately lacks independent randomness; report observed candidate errors without asserting a probabilistic calibration.

Configure labs/corpus_sketch with CMake, build and run its selected anchor. The default src files must compile then fail SK_CHECK. Supply your external completed source directory through SK_PROVIDER. Record commands, compiler versions, input/source identities and raw outcomes; reject crashes as semantic controls. The public tests are necessary examples, not a complete solution certificate. Use the full procedure in CONTRACTS.md.

## Security

The only target is the original `labs/corpus_sketch` MinHash provider (`src/minhash.c`), with explicit permutation rows over a universe of at most 16 elements, using synthetic sets in a local process.

Adversary. The attacker chooses the configuration rows (a repeated permutation, a row with a duplicated or out-of-range rank), the elements added (inside or outside the universe), the group size given to `sk_mh_bands`, and the sets compared. The attacker cannot edit signatures, pass bad pointers or read any secret.

Violated property. A configuration must hold a true permutation in every row and refusals must leave output unchanged. The anchor `corpus_sketch.minhash` checks that a duplicated rank makes `sk_mh_init` return `SK_INVALID`, element 5 in a universe of 5 makes `sk_mh_add` return `SK_INVALID`, group size 3 for 10 rows returns `SK_INVALID`, and a merge across a modified rank row returns `SK_INVALID`, all unchanged. Build variants that accept each and show the anchor rejects them. Separately, from explicit sets and the ordered ten-permutation family of the contract, construct a pair with J below .5 that is a candidate and a pair at or above .5 that is missed, to show the filter is candidate-only.

Boundary. Universe of at most 16 elements, synthetic sets, a disposable CMake build and an independent set-based oracle. Success is a printed fraction or band count that disagrees with exact sets.

Evidence to capture. Run `ctest -R corpus_sketch.minhash`. Capture the `SK_CHECK` text for each rejected variant, your sets and permutations, the C fraction versus the exact set fraction, the band count, and the unchanged-snapshot comparison.

Impact class. `demonstrated-invariant-violation`, demonstrated only by a variant you build or by the explicit sets you construct (the supplied anchor passes on a correct provider and no flawed provider is supplied): the result contradicts the exact computation, with no fault, authorization effect or leaked data shown.

Remediation and regression. Validate permutations at initialization, refuse unchanged, and require equal configuration for merge. The anchor's duplicate-rank, add-5, group-size-3 and mismatched-merge CHECKs must reject your variants.

Limitations. Exact enumeration over a small universe is not a confidence bound for sampled permutations; band probability needs independent uniform rows; the mechanism is no defence against an adaptive adversary.

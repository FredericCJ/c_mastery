# X-T74-013: Retiring prototype shapes and weak caches across mutating accessors

## Prerequisites

Complete X-T74-003's immutable descriptors, X-T74-004's original cache and X-T74-008's typed moving pool. Retain their learner source revisions, invariants and accepted contracts. This later exercise uses actual ORXHeap identity, roots and strong edges. It is the required later prototype/reuse transfer for the earlier shape and cache work, with no reverse prerequisite edge. The explicit T66 workspace dependency is inherited through the pool implementation; a hash or JavaScript runtime library cannot implement the studied object model.

## Environment

C17 hosted GCC/Clang debug, optimized and sanitizer profiles. The controller is serialized. Objects and descriptors are original bounded teaching structures; caches are cooperative weak records, not safe handles against arbitrary memory corruption. Primary V8 passages compare hidden-class and handler invalidation concepts only. This contract deliberately differs from JavaScript's attribute and observable property rules.

## Problem

Implement object_runtime_shapes.h using SHAPES_EXTENSIONS.md. A stationary world owns the actual eight-cell heap, eight metadata rows and16 immutable ordered descriptors. Each live object holds one descriptor reference and one external root on creation. The heap's first strong edge is its prototype. Descriptor generations1..3 are reusable,4 retires; shape0 stays permanent. Keys are nonzero octets, fields at most4, and attributes are READONLY1 and ACCESSOR2. READONLY forbids replacement and deletion. Acquire the new descriptor before publishing fields and dropping the old one. Reject cycles before updating prototype edges.

A weak cache records world, receiver/holder generations, both shape identities, key, offset and structural epoch. Every guard must match. Read the current field, not a cached value. Structural mutation advances the epoch, refusing wrap at255. Copy getter/context and temporarily root receiver/holder before invocation. A getter may allocate, mutate or collect, but recursive lookup fails STATE. Stage its scalar result and release temporary roots on every exit. Its completed mutations remain even when its result status fails. An epoch change invalidates the old resolution.

Concrete witness: receiver inherits key1=10 from A, then changes prototype to B with key1=20 while A remains live with the same shape. A retained cache must return20. Next B's getter defines receiver.key1=99 but returns42: immediate lookup returns42 and the next returns99. If the getter instead reports failure, output777 remains777 while the next lookup still returns99. Original shapes_ext.json, C tests, compiling scaffold and separate dictionary oracle supply inspectable inputs.

## Necessity

Live holder and shape identity are insufficient when a prototype edge changes. A successful C callback can invalidate an offset during the call; output rollback does not imply rollback of committed callback side effects. Descriptor retirement and temporary rooting expose failures that an ordinary immutable-shape lookup cannot assess.

## Reasoning

Prove one descriptor reference per live object, immutable ordered layout, bounded acyclic chains and generation retirement. Derive which mutations change epoch and why same-layout value updates do not. Identify the callback's borrowed code/context lifetime and root ownership preconditions; ISO C does not enforce them. Compare the conservative global epoch with V8's described validity-cell mechanism and state the extra invalidations. Derive worst-case eight-object traversal with four key comparisons each,16-row descriptor search and finite-generation exhaustion. Account separately for cache counters, fields, shapes and root holds.

## Deliverables

- D1: Identity/ownership diagrams, shape and epoch invariants, failure-prefix tables and an explicit wrong-cache counterexample.
- D2: World/descriptors/prototype/lookup implementation consuming the actual pool, with callback reentry and cleanup behavior.
- D3: Independent3600 dictionary comparisons, focused stale/cycle/exhaustion/accessor witnesses, four compiled controls and exact source-bound sanitizer runs.
- D4: Delayed callback-failure variant, reset-cache versus retained-cache measurement under equal semantics and the shared13-dimension COST_REVIEW with one sealed design decision.

## Verification

Run object_runtime.ext_shapes, object_runtime.ext_cache and each anchor's two separately compiled controls. Compare independent dictionary results for all24 insertion orders, five deletion choices, three shadow states, two readonly policies and five queried keys. Additionally test shape sharing/reuse,45 retirement cycles, prototype reachability, field updates, weak stale objects, switching worlds, saturated counters and structural epoch exhaustion. Snapshot rejected state. On accessor exit verify temporary roots are released and callback count/result are correct; test both failure and success after mutation. A stale value produced by an intentionally flawed target is the observable failure, not a crash. Run the independent oracle with the built driver and retain exact command/source pins.

## Rubric

Six metadata criteria separate descriptor representation, failure boundaries, prototype ownership, cache guards, falsification/cost and mutating callback transfer. Require level2 on every criterion; independent changed-condition defense at level3 on cache invalidation and callback ownership. Passing nominal property tests alone remains level1.

## Hints

1. Draw receiver identity, holder identity and descriptor identity separately.
2. Build a replacement descriptor before changing a receiver; a cache owns no descriptor reference.
3. Save the callback before invoking it, then consider what remains valid if it deletes its own property and collects.

## Variants

X-T74-013-DELAYED after at least seven days: a getter installs an own property shadowing itself, triggers collection and reports failure. Preserve immediate output, retain its committed mutation, release temporary roots and resolve the next lookup afresh. Change the global invalidation scheme to explicit per-chain tokens only after proving which prototype/attribute transitions invalidate dependents; compare the additional bookkeeping. Independent assessment must disclose assistance and use a changed trace rather than edited constants.

## Security

Use only the original local world with synthetic integer properties. The adversary controls admitted property definitions, prototype changes and a cooperative typed getter, not arbitrary host addresses. Missing epoch validation can return a property from an obsolete prototype; rereading the pre-call offset can return a different value after mutation. Demonstrate these harmless wrong-property results using the supplied flawed controls. Repair all guards, temporary roots and staged callback result, then run positive and regression traces. The model rejects cycles and finite identity wrap, but does not sandbox malicious machine code or arbitrary memory writes. No current deployment, credentials or external target is involved.

## Validation

Authored implementation and independent host models are distinct from source-bound execution, external review, learner assessment and physical evidence. The original fixed-capacity model is not a complete JavaScript runtime or concurrent collector. Exact published C17 access remains unavailable; target compilation of an older allocation-free kernel does not validate this host integration.

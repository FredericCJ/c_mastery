# X-T25-002: Two-way publication and ordinary payload reuse

## Prerequisites

Read PR-T25-03 and labs/b03_depth/CONTRACTS.md version1. Required prior exercises are listed in metadata. Bring an event/state trace notebook and a C17 test workspace; no unlisted accepted artifact is imported. Knowledge: object lifetimes, integer bounds and the parent's I/O, concurrency or device model. State which earlier ownership arguments are reused and which platform assumptions are new.

## Environment

The default CMake build uses learner stubs. Components use C17/profile C; Python and libc are host verification tools. All experiments are unprivileged local models with synthetic bytes/events. C17 atomic mailbox code is distinct from the sequential device/I/O models. Record compilers, optimization, target data model and undefined symbols. Actual OS, ISA, ABI and board guarantees require separate evidence; the host run supplies none automatically.

## Problem

Implement the single-slot mailbox with exactly one producer/consumer. Producer writes ordinary payload only after observing empty, then release-publishes full. Consumer acquire-observes full, copies payload, then release-publishes empty; producer's next acquire must protect reuse. WAIT preserves consumer output. Use the order functions in every actual atomic operation. Public tests inspect order-policy choices and sequential state; they do not claim an exhaustive memory-model checker. Supply an execution graph for both directions and a separate actual threaded stress harness for candidate assessment.

Use supplied include/depth.h, src/depth.c, tests/tests.c and fixtures/b03_depth/cases.json. The complete API, pointer, state, ownership and failure contract in labs/b03_depth/CONTRACTS.md is explicitly incorporated. Preserve all admission and termination rules.

## Necessity

Forward publication alone does not protect the next overwrite from a prior consumer read. Race freedom, logical message order and atomic lock-free support are separate properties. A sequential smoke test can pass a relaxed-order defect.

## Reasoning

Name each sequenced-before, reads-from and synchronizes-with edge: producer payload write to consumer read, then consumer read to next producer overwrite. Prove no two owners access the same payload concurrently under SPSC assumptions. Show where a second producer breaks the proof. Analyze relaxed-only and seq_cst variants without executing a deliberate data race. Do not extrapolate C11 consume/fence wording to all later editions.

Distinguish enforcement by C, diagnostics, runtime state checks, proof/model and caller/environment discipline. Show one plausible wrong explanation and a minimal counterexample. State precisely what each experiment cannot establish.

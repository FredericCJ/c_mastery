## Security

Target `pt_post` and `pt_active_step` with the four-slot copied-event ring in `labs/protocols`, using only synthetic values. No network service or hardware is involved.

- Adversary: chooses the post sequence (including a post to a full ring) and the trace capacity offered to each step. It cannot forge pointers, change ring storage or alter quiescence facts.
- Violated property: no queued event is overwritten, dropped or reordered, and a failed dispatch leaves head, count and the active state unchanged so the event can be retried.
- Boundary: in-process host model; harmless success is the illegal state change or counter recorded by the harness, never a crash left running.
- Evidence to capture: run `protocols.active` (fifth post is PT_RANGE with count 4 and queue[0] still CONNECT; trace capacity 1 gives PT_RANGE with count 4, head 0 and OFFLINE; four steps with capacity 6 reach FAULT with count 0). Build an overwrite or remove-before-dispatch variant as `labs/protocols/CONTRACTS.md` asks and record the lost event.
- Impact class: demonstrated-invariant-violation, from the learner-built defective variant only (no flawed variant is supplied and the supplied test passes on a correct build, so no supplied artifact demonstrates it); not a crash, sanitizer finding or undefined behaviour, and not a proved impact.
- Remediation and regression: reject at capacity and remove only after success; `protocols.active` must fail the variant.
- Limitations: no fairness under sustained load, a poison event is retried by policy, and the ISR and scheduler adapter is outside the host model.

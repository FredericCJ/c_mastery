# X-T15-010: Thompson closure, whole/search semantics and bounded subset construction

## Prerequisites

Study T15.14 and PR-T15-09, T03 array/object lifetimes and T14 stack/set representations. Bring a hand trace of the shared grammar, bounds tests and a list of ordinary versus malformed inputs. LR additionally needs least fixed points and FIRST/FOLLOW; regular expressions need finite-state machines; Pratt needs expression trees; scannerless work needs rollback and three-result recognition. No unlisted accepted artifact import is required.

## Environment

The explicit [parsing depth contract1](../../../labs/parsing_depth/CONTRACTS.md) supplies the full typed API, exact languages, capacities, dependencies, ownership, admission/failure semantics and local security scope. Implement the supplied compiling `src/parsing.c` scaffold. The C mechanism cannot delegate to a mature parser library. Host independent oracles remain separate. ISO C type checks do not establish the semantic grammar/table or pointer-lifetime preconditions.

## Problem

Compile the explicit a/b/empty regular-expression grammar into typed NFA states, then implement whole-input and substring search. Derive epsilon closure that terminates on nullable cycles. Implement the delayed bounded DFA subset table with unchanged-output capacity failure and an explicit NFA fallback choice. The shared pattern (a|b)*abb, a**, (~|a)* and bytes outside a/b distinguish semantics. No regex library may perform the C mechanism.

## Necessity

Naive backtracking or duplicate active paths can grow dramatically even for a regular language. Nullable repetition can loop without a visitation invariant. A deterministic table trades construction/storage for repeated recognition, and capacity failure must not silently change the language. Regular-language matching is not equivalent to engines with backreferences.

## Reasoning

Prove fragment start/end meaning, epsilon-closure termination, current-state-set correspondence after each input byte and search restart semantics. Derive subset transition equivalence and exponential worst-case state growth. Account for pattern depth, typed-state capacity, worklist maximum, copied pattern representation and exact failure publication. Bound O(nS) simulation and table-build work without pretending fixed constants remove the mechanism. Explain a plausible false claim that every path must be executed independently. Give the smallest concrete counterexample to one plausible incorrect explanation. Separate ISO C rules, the teaching language/grammar, compiler support and programmer-maintained invariants. State every pre/postcondition and no-publication failure boundary.

## Security

A regular-expression matcher fails in two quiet ways. It can return the wrong answer, for example by losing one arm of `|`, and it can fail to return at all when an epsilon loop is followed without remembering where it has been. This exercise makes the pattern, the input and the DFA capacity the attacker's choices and asks you to show, with a smallest counterexample, what breaks when one safeguard is missing. The only target is your own `rx_compile`, `rx_match`, `rx_determinize` and `rx_dfa_match` in `labs/parsing_depth/src/parsing.c`, run on synthetic bytes; nothing outside the process is touched.

Why it matters here. In `a**` and `(~|a)*` the starred body can match the empty string, so the Thompson NFA contains an epsilon cycle. Marking a state when you enqueue it, before following its edges, is what makes the closure terminate and keeps one state from appearing twice in the active set. The 16-state limit on `rx_determinize` is the second safeguard: the contract (`labs/parsing_depth/CONTRACTS.md`, section X-T15-010) requires `PD_RANGE` with both the NFA and the output table unchanged, so a caller can fall back to the NFA. A table that is half written or an NFA that was modified while failing would silently change the language the caller sees.

What to try. Before running anything, trace `(a|b)*abb` on `aabb`, `abbc` and `cabbc` by hand, in whole mode and in search mode. Then run `ctest -R parsing_depth.regex`; the anchor pins those three strings, the failing compile of `a|` with an unchanged NFA, capacity 1 returning `PD_RANGE`, `(~|a)*` accepting the empty string and `aaa`, and `a**` rejecting `b`. Next build three variants of your own, each breaking exactly one property: an alternation that loses a branch, a DFA whose final states disagree with the NFA, and a closure that revisits states on a nullable cycle. For each, find the shortest pattern and input where it disagrees with your independent AST-language oracle.

What to capture and how to read it. Keep the `PD_ASSERT:<line>:<expression>` line from stderr: the expression tells you which property the anchor tripped on. If the anchor does not reject a variant, your oracle comparison is the evidence, and the gap is a finding about the anchor, not something to hide. A hang appears as a ctest timeout, never as a `PD_ASSERT`, so add a bounded visit counter to show the revisiting. `labs/parsing_depth/reject_mutant.py` is a supplied helper that runs a variant binary and requires exit 1 with `PD_ASSERT` on stderr (call it with the binary and the test ordinal; it has no timeout of its own). The assessor's mutation set also checks this invariant.

Impact class. `demonstrated-invariant-violation`, and only once you have built a variant and shown a wrong result on a named pattern and input; nothing supplied demonstrates it. A hang, syntax error or sanitizer report alone is not arbitrary code execution or privilege escalation, and none of this is a memory-safety claim.

Remediation and regression. Mark states before following epsilon edges, keep both SPLIT arms, derive DFA acceptance from the NFA and return `PD_RANGE` unchanged at capacity exhaustion. Keep each smallest counterexample as a permanent test next to the existing `parsing_depth.regex` assertions.

Limitations. Finite tests do not prove that every regular language fits in 16 DFA states, and the 16-state table bounds resources by refusal only. Backreferences would invalidate the finite-state argument and are not implemented.

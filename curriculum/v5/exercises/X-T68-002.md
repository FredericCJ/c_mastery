# X-T68-002: Constraint probes and constant storage parameters

## Prerequisites

Complete the earlier domain projects and retain the named prerequisite artifacts with their contracts, ownership ledger and tests. Required learner artifacts: containers.ring, bytes.checked. Do not import an assessor implementation.

## Environment

Implement mechanisms locally using declared typed storage/callbacks; hosted harness and diagnostic runtimes are separate. See laboratory contract for exact dependencies. Use C17 with extensions disabled and warnings treated as errors. A diagnostic extension is identified explicitly and does not become an ISO guarantee. The full platform, pointer, callback and concurrency preconditions are in [metaprog/CONTRACTS.md](../../../labs/metaprog/CONTRACTS.md).

## Problem

Implement mp_storage_bound(count,width,limit,out): positive count/width, multiplication representable in size_t, and product<=limit. Fail without output changes. Create positive/negative translation units using _Static_assert for compile-time capacity and type compatibility, with array extents derived from constant parameters. A runtime input must use the checked function rather than a false compile-time guarantee.

Concrete inputs and expected results: count4,width8,limit32 yields32;limit31fails. SIZE_MAX*2 fails before overflow; count0 or width0 is outside this storage contract.

Supplied artifacts: labs/metaprog/include/metaprog.h, compiling unsolved src/metaprog.c, CTest metaprog.constraints, fixtures/metaprog/PR-T68-02.json, and the shared contracts. State every additional backend assumption before running it.

## Necessity

Separate a required C constraint diagnostic, a chosen -Werror rejection, and a runtime range guard; show which properties constant-size generic storage can check before execution. The misconception and changed-condition case below are separately assessed; ordinary successful execution alone does not cover them.

## Reasoning

Derive count<=SIZE_MAX/width before multiplication and the independent budget bound. Explain why C17 _Static_assert requires an integer constant expression, VLA support differs from fixed arrays, and syntactically valid macros do not impose an abstract trait. Give the abstraction function, admitted states, pre/postconditions, ownership graph, failure effects and complexity before implementation. Identify the enforcement boundary of every safety claim using the shared modern-cost contract. Distinguish an invalid caller object from an operational failure admitted by the API.

# X-T14-003: Fenwick frequencies: rank boundaries and exact rescaling

## Prerequisites

Read PR-T14-09 and the applicable T14/T15 module teaching. Bring your own array/bounds tests and invariant notebook; no unlisted accepted artifact import is required. Know unsigned arithmetic, half-open spans, typed object lifetime and asymptotic work. Interval work additionally requires AVL rotations; suffix work requires stable counting sort. Diagnose those prerequisites before attempting the integrated mechanism.

## Problem

Implement the five Fenwick operations in index.h for a synthetic adaptive-symbol frequency table. Begin with [1,0,3], submit each prefix and each rank selection, then apply delta=-2 at index2 and reject delta=INT64_MIN at index0 without state change. The component must support every n from0 to64 and total UINT32_MAX. Implement both rescaling modes; no arithmetic coder is required or implicitly provided. The exact one-based representation, output semantics and examples are in the shared contract.

## Necessity

Cumulative counts are an advanced-structure omission hidden by the old choose-one project. Correct prefix sums do not establish correct inverse selection. Zero counts and rank exactly on a partial sum distinguish strict from non-strict comparisons. Rounding aggregate nodes can disagree with rounding individual frequencies; the inspected original also has a published correction.

## Reasoning

Derive the lowbit partition and why update ancestors cover exactly the changed point. For select, maintain the skipped-prefix sum and prove the next skipped block stays <= the requested zero-based rank. Prove total admission bounds every affected cell and safely handles INT64_MIN. Derive linear build and inverse-build rescaling; compare their work with n independent point queries. Explain why nonnegative counts are essential for selection monotonicity. Include one plausible incorrect explanation and its smallest counterexample. Separate mathematical proof, ISO C guarantees, compiler diagnostics, dynamic checks and caller discipline. Fixed bounds make experiments tractable; they do not excuse a false general complexity claim.

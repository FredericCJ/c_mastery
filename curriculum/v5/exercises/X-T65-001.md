# X-T65-001: Optional and Result representations without fictitious layout guarantees

## Prerequisites

Use the existing bytes.checked, parser.integer, io.stream and codec.records contracts as comparison boundaries. Complete C17 tagged-union, pointer-lifetime and function-pointer reasoning first. Preserve the learner's earlier implementations; do not import an assessor solution. Begin with X-T04-001 transactional arithmetic and the accepted T18 ownership vocabulary.

## Environment

Original C mechanisms; hosted setjmp/longjmp only for the explicit jump boundary. Host harness may use stdio/Python. No strict freestanding claim. C17, Linux x86-64, GCC and Clang with -Wall -Wextra -Wpedantic -Werror and extensions disabled. The exact shared contract is [errors/CONTRACTS.md](../../../labs/errors/CONTRACTS.md). C editions, language-level guarantees and implementation observations must be labeled separately.

## Problem

Implement er_ok, er_error, er_optional_pack and er_optional_unpack. The optional encoding is a uint32_t: zero means absence; a present zero is unrepresentable and must return ER_RANGE without changing the output. present is exactly 0 or 1. Absence ignores value and stores zero. All nonzero uint32_t values are representable. A result tag selects value or error offset as defined by the shared contract. Reject an unknown tag before interpreting a payload. Also implement a separate fully tagged optional representation that can represent present zero, and compare its contract and layout with the niche encoding.

Concrete expected cases: Packing (value=0,present=1) into an output initially 91 rejects with 91 unchanged; (17,0) stores zero; UINT32_MAX is a valid present value. Unpacking zero produces ER_ABSENT. The full tagged alternative must distinguish absent from present zero.

Supplied artifacts: labs/errors/include/errors.h, compiling unsolved src/errors.c, the named CTest errors.optional, and fixtures/errors/PR-T65-01.json. No installed package may supply the mechanism under assessment.

## Necessity

Derive the state cardinality of tagged versus zero-reserved optional values, including the lost present-zero state and valid result payload selection. An ordinary nominal call does not assess this distinction. The two isolated mutants and the changed-condition case expose different incorrect explanations.

## Reasoning

Implement total constructors and checked accessors while preserving output on rejected niche construction; do not copy uninitialized union members or compare padding. State the preconditions, postconditions, valid representation states, ownership and failure effects before implementation. Derive operation and storage bounds; distinguish caller misuse from a reported operational failure. Compare the C protocol with the exact inspected source scope: C type compatibility and diagnostics do not supply automatic ownership, exhaustive matching or proof of a runtime predicate.

## Deliverables

- D1: Derive the state cardinality of tagged versus zero-reserved optional values, including the lost present-zero state and valid result payload selection.
- D2: Implement total constructors and checked accessors while preserving output on rejected niche construction; do not copy uninitialized union members or compare padding.
- D3: Enumerate the reduced 8-bit model independently, then test actual UINT32_MAX and invalid discriminants. Measure sizeof and alignment on two available data models; a missing model is unavailable evidence. Kill premature-output-write and absence-uses-payload mutants.
- D4: Change the payload to an owning resource whose zero ID is valid. Derive an ownership-bearing tagged option and show why the old niche and byte-copy rules fail. Compare the exact documented Rust Option representation cases with this C design; no blanket ABI equivalence is allowed. Complete all dimensions of the shared modern-cost contract, with evidence or a justified non-applicability.

Required non-equivalence assessment C08: Analyze void as an incomplete type with no values and _Noreturn as a function specifier. Compile a struct member of type void and an expression attempting to use a void result as a payload under strict C17 diagnostics; do not execute a falsely returning _Noreturn function. Construct a named one-state enum payload as a protocol-level unit and explain why it is not an uninhabited type or a general coercion rule.

## Verification

Enumerate the reduced 8-bit model independently, then test actual UINT32_MAX and invalid discriminants. Measure sizeof and alignment on two available data models; a missing model is unavailable evidence. Kill premature-output-write and absence-uses-payload mutants. Run the named anchor separately from the complete suite. Preserve exact commands and expected/observed results. Every specified failure output and callback count is a pass/fail gate. Public anchors and source-bound author campaigns do not discharge independent inputs, reasoning or delayed transfer. Explain sanitizer, model-size and compiler limitations.

## Rubric

The four objective-specific metadata criteria assess representation reasoning, implementation, falsification and transfer separately. A candidate must satisfy every criterion at level2 or higher and at least two at level3 under the shared six-dimension rubric. A forbidden side effect, lifetime violation, unsupported dependency or overstated language guarantee fails the gate. Nominal tests alone earn at most level1.

# X-T65-004: Lazy Result composition and effect-sensitive laws

## Prerequisites

Use the existing bytes.checked, parser.integer, io.stream and codec.records contracts as comparison boundaries. Complete C17 tagged-union, pointer-lifetime and function-pointer reasoning first. Preserve the learner's earlier implementations; do not import an assessor solution. Complete X-T65-003 first.

## Environment

Original C mechanisms; hosted setjmp/longjmp only for the explicit jump boundary. Host harness may use stdio/Python. No strict freestanding claim. C17, Linux x86-64, GCC and Clang with -Wall -Wextra -Wpedantic -Werror and extensions disabled. The exact shared contract is [errors/CONTRACTS.md](../../../labs/errors/CONTRACTS.md). C editions, language-level guarantees and implementation observations must be labeled separately.

## Problem

Implement er_map and er_then with exact callback types. A valid error result passes through unchanged without invoking a callback. On OK, map invokes its uint32_t callback once and wraps the value; then invokes its result callback once and preserves that returned result. A missing required callback or unknown tag yields ER_INVALID. Callbacks borrow context and may update a counter but cannot retain it, reenter the operation or destroy the input owner. Derive identity and composition laws under pure, total callback assumptions; test and explain their failure when observable effects differ.

Concrete expected cases: Mapping increment over IO(offset7) invokes zero callbacks and preserves7. Mapping over OK(4) produces OK(5) after one invocation; then a rejecting callback produces RANGE(offset5). A subsequent then does not call its callback.

Supplied artifacts: labs/errors/include/errors.h, compiling unsolved src/errors.c, the named CTest errors.composition, and fixtures/errors/PR-T65-04.json. No installed package may supply the mechanism under assessment.

## Necessity

State the preconditions for map identity/composition and and_then associativity, distinguishing pure laws from callback side effects and evaluation order. An ordinary nominal call does not assess this distinction. The two isolated mutants and the changed-condition case expose different incorrect explanations.

## Reasoning

Implement typed callback composition with one active union member, error preservation and exactly selected callback invocation. State the preconditions, postconditions, valid representation states, ownership and failure effects before implementation. Derive operation and storage bounds; distinguish caller misuse from a reported operational failure. Compare the C protocol with the exact inspected source scope: C type compatibility and diagnostics do not supply automatic ownership, exhaustive matching or proof of a runtime predicate.

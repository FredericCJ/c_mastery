# X-T75-009: Resilient telemetry admission, committed effects and draining

## Prerequisites

Bring pinned contracts and fresh recall for io.deadline, io.async, ipc.local, io.reactor, communications.tcp_fault, containers.ring, measurement.capture, conc.channel; prerequisite exercises: X-T75-002, X-T75-003, X-T75-004, X-T75-005, X-T75-006, X-T75-007, X-T75-008. Required knowledge includes C object lifetime, checked arithmetic, ownership, typed arrays and the selected source passages. The shared contract and modern-cost contract are explicit parts of this exercise. Existing project estimates describe author accounting; they impose no learner time ceiling.

## Environment

Use C17 hosted Linux with GCC and Clang, CMake and host Python. Record compiler/ABI versions, integer widths, sizeof/alignment and optimization. Mechanism code uses no library implementing the mechanism. The T73 channel backend supplies its declared POSIX synchronization; the virtual-time model itself supplies no OS clock, sleep or hidden scheduler. A strict freestanding port requires its own generated-code/link audit and is not established by the hosted run. Compare C11 draft/C17/C23 only where inspected normative evidence supports the claim; exact published C17 access remains a reference gap.

## Problem

Implement RZService by composing the accepted deadline, limiter, breaker, receiver, pending queue and actual T73 MsgHub. Reserve notification capacity before committing a new synthetic effect; flush only consumes a pending ID when channel send accepts it. Then build the full local telemetry service through the existing IPC/reactor/TCP-fault artifacts, using the wheel for retries and deadlines, limiter for all original/retry/hedge work, breaker permits until terminal completion, and deduplication for repeated requests. Keep the executable anchor and this required integration as distinct evidence obligations.

Supplied artifacts: labs/resilience/include/resilience.h, deliberately incomplete labs/resilience/src/resilience.c, executable anchors, fixture PR-T75-09.json and the shared CONTRACTS.md. Expected example: A new delta2 request applies once and queues its ID. Flush to channel0 allows msg_select to observe that exact ID. Filling the four pending slots rejects the next request before changing receiver.total. A full/cancelled imported channel retains pending notifications. Cancellation after an admitted effect cannot make its already-reserved notification disappear.

## Necessity

Locally correct components can compose into lost committed notifications, duplicated effects, retry storms or premature cleanup. A service acceptance result needs a defined commit point and recovery policy, not a collection of successful unit tests.

## Reasoning

T75.09.a: Derive a composition contract with admission, effect commit, reply availability, notification enqueue, delivery and cleanup as distinct events. Account for every retained buffer, timer, permit and borrowed owner.

T75.09.b: Implement the bounded service anchor using actual conc.channel and all required local IPC/reactor/fault adapters; preserve exactly-once notification for a new retained request and explicit replay/expiry semantics.

T75.09.c: Inject allocation/partial-I/O/timeout/reset/cancellation/late-completion faults across the integrated service, checking effect and notification accounting with an independent event-sourced oracle and all declared capacity bounds.

T75.09.d: Run an independently designed workload with burst arrivals, long tails, correlated faults and slow consumers. Seal a composition decision, apply all13 cost dimensions, and explain changed results under different correctness contracts or clock assumptions.

State preconditions, postconditions, representation invariants, resource ownership, failure publication and complexity. For each guarantee identify ISO C rules, diagnostics, runtime checks, external verification and programmer discipline separately. Include a minimal counterexample to an overstated equivalence with the corresponding language/library abstraction. Apply all13 dimensions in modern-cost-contract.md, recording genuine non-applicability with reasons and unavailable measurements as gaps.

## Hints

1. Reserve the resource that makes a committed effect observable before committing it.
2. Cancellation can stop new work without undoing work already accepted.
3. A full queue requires a recovery decision; silently forgetting the head is not backpressure.

## Variants

X-T75-009-DELAYED: restart the service after journal commit but before notification acknowledgement. Define whether notifications are at-least-once or deduplicated at the consumer, implement the chosen recovery rule, and expose the limitation of relying only on the volatile pending queue.

Also change compiler/optimization and an available data model. Revisit integer availability, object layout, helper dependencies and performance arguments rather than assuming numerical output validates portability. Assessor technical analysis and withheld cases are separate from learner publication.

## Problem

Implement RZService by composing the accepted deadline, limiter, breaker, receiver, pending queue and actual T73 MsgHub. Reserve notification capacity before committing a new synthetic effect; flush only consumes a pending ID when channel send accepts it. Then build the full local telemetry service through the existing IPC/reactor/TCP-fault artifacts, using the wheel for retries and deadlines, limiter for all original/retry/hedge work, breaker permits until terminal completion, and deduplication for repeated requests. Keep the executable anchor and this required integration as distinct evidence obligations.

Supplied artifacts: labs/resilience/include/resilience.h, deliberately incomplete labs/resilience/src/resilience.c, executable anchors, fixture PR-T75-09.json and the shared CONTRACTS.md. Expected example: A new delta2 request applies once and queues its ID. Flush to channel0 allows msg_select to observe that exact ID. Filling the four pending slots rejects the next request before changing receiver.total. A full/cancelled imported channel retains pending notifications. Cancellation after an admitted effect cannot make its already-reserved notification disappear.

## Necessity

Locally correct components can compose into lost committed notifications, duplicated effects, retry storms or premature cleanup. A service acceptance result needs a defined commit point and recovery policy, not a collection of successful unit tests.

## Security

**Why this matters here.** This is the exercise where earlier guarantees are composed, and composition is where they leak. A request that commits an effect must also reserve its notification before it commits, or the effect happens and nobody hears of it. A pending notification must leave its queue only when the channel accepts it, so a full or cancelled channel retains it. Retries, hedges and originals must all spend from one token budget so the total work stays bounded, and a restart must neither lose a recovered notification nor announce one twice. Each of these is a statement about counts you can read off a trace.

**What to try.** Start with the in-memory service (tests/tests.c:`service`): a delta 2 request gives 2 and, once flushed, channel 0 shows value 1. After that first flush, four more admitted requests fill the four pending slots, and the next request is refused with RZ_FULL before it changes the receiver total. A flush into a full channel returns RZ_FULL with three notifications still pending, and after msg_hub_cancel it returns RZ_CANCELLED with the same three retained. Then read the durable path: the outbox with injected cuts, the local socket service where six queued frames produce four effects and two RZ_FULL replies, and the composed workload whose invariants are listed above. For each, decide what the trace must contain before running anything.

**Evidence to capture.** Build the two variants named in COMPOSITION.md as properties, a due time rounded down and a recovered notification lost on restart, predict which RZ_CHECK line in resilience.service_transport rejects each, and keep the stderr line. Record the host effects of what you ran: service_outbox forks and uses unlinked /tmp files, and service_io uses socketpairs and threads, so a passing run is one schedule, not all of them. The outbox and composition `oracle` modes and the layout mode print and compare nothing; use them only against a model you wrote, and compare all 19 fields of the composition oracle.

**How to read the result.** A rejected variant is a duplicated, dropped or unannounced synthetic effect, or work beyond the bound: a demonstrated invariant violation in well-defined C, with no consumer, durable store or remote system affected. This is a local bounded composition and says nothing about a deployed telemetry pipeline, end-to-end delivery or the resilience of a real network. Token spending is not rolled back on a later failure, by design, and the small finite permit identities bound the lifetime of the anchor. The assessor's mutation set also checks this invariant, but that set is not part of what you receive.

Only your own implementation and the synthetic data of this lab are attacked; the temporary files are unlinked as soon as they are made, the sockets are loopback socketpairs inside the process, and no external endpoint, credential, hardware or host setting is touched.

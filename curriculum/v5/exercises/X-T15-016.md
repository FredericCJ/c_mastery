# X-T15-016: Restricted template bytecode, scoped list application and contextual escaping

## Prerequisites

Know typed arrays, half-open ranges, staged publication, source offsets and syntax/semantics separation. Recovery and formatting require your completed X-T15-012 implementation and its exact PdTree contracts. Bring grammar traces, failure snapshots and the public `parsing_depth` workspace; dependency import is explicit. Template evaluation additionally needs lexical scope and bounded graph traversal. No library implements the new mechanism for you.

## Environment

The explicit [text-composition contract1](../../../labs/text_composition/CONTRACTS.md) gives all input types, operations, exact grammar, capacities, ownership, failure/resource and local security rules. Implement `src/text.c`; configure the actual prerequisite workspace with CMASTERY_PARSING_DEPTH_ROOT. Host tools and models remain outside the target component contract. Inspect dependency identity and emitted resource costs; no runtime absence or language-level safety follows from the API spelling.

## Problem

Compile the shared literal/field/presence/list/static-include grammar into typed operations, then interpret it over a readonly four-field model. Implement nested list item shadowing/restoration, include-cycle detection and whole-output staging. Compare plain-text and HTML-text modes using synthetic <tag>&. Preserve actual model bytes and ensure braces in model values are data, never new directives.

## Necessity

Template syntax, model computation and output-context encoding are different mechanisms. A readonly-looking interface does not automatically enforce formal model-view separation. Repeating a first list item can pass singleton tests; recursive includes or nested expansion can exhaust resources without a pointer defect. Escaping appropriate for an HTML text node is not a universal sanitizer.

## Reasoning

Derive paired block jumps, lexical item scope, active-include identity and byte/fuel/output bounds. State which separation properties the instruction set enforces and which require stable model construction discipline. Explain one-pass escaping and why already-escaped data is encoded again rather than treated as trusted syntax. Distinguish an observable local markup-shaped output violation from demonstrated script execution. Supply pre/postconditions, loop/stack invariants, ownership, failure and complexity arguments. Classify guarantees supplied by ISO C, diagnostics, runtime checks, external models and caller discipline separately.

## Deliverables

- D1: Representation/grammar derivation, inspected-source comparison, exact invariant and a plausible wrong explanation with a counterexample.
- D2: Original C mechanism and actual prerequisite binding, resource/stack/work ledger, staged output and cleanup argument.
- D3: Independent oracle, complete concrete inputs/results, boundary/failure preservation snapshots and two causal semantic mutants.
- D4: Named delayed transfer implementation and predictions, changed assumptions, equal-contract comparison and evidence limits.

## Verification

Compare compiled C evaluation against an independent immutable template-tree interpreter for absent/present-empty fields, multiple values, nested loops, includes, escaped braces and invalid directives. Force executed versus unexecuted cycles, missing includes, depth/fuel/output failure and model immutability. Reject the original no-escaping mutant on a local harmless string and the repeat-first-item mutant on a two-element list. Run GCC/Clang debug, optimized and sanitizer profiles; retain exact commands, raw outputs and source hashes. Public `text_composition.template` must reject the compiling incomplete scaffold with TC_ASSERT. Passing public examples without D1/D4 is insufficient. The private oracle uses a different model and the reference campaign checks mutation sensitivity.

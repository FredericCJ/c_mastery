## Security

A scannerless parser sees raw bytes that may arrive in pieces, so it must distinguish three answers: matched, definitely failed, and not enough input yet. Collapsing the third into the second makes a streaming parser reject valid input that has merely been split, and letting captures from a rejected alternative survive makes later code trust spans that the grammar never accepted. The only target is your own `ps_parse` in `labs/parsing_depth/src/parsing.c`, run over small expression DAGs and synthetic bytes.

Why it matters here. Ordered choice `(capture(a) x) / (a b)` first tries a branch that records a capture and then fails, so the interpreter must roll that capture back before trying `a b`; the anchor's zero-captures result on `ab` with EOF is the visible effect. With the EOF flag absent, `a` and `ab` end where the grammar could still continue, which must be `PD_PENDING` with the result untouched, not `PD_NO_MATCH`. The keyword grammar adds a second case: `let=2` must be rejected while `letx=2` is an ordinary identifier.

What to try. Trace the DAG in the anchor by hand for `ab` with EOF, `a` without EOF and `ab` without EOF, writing the capture list after each failed branch. Run `ctest -R parsing_depth.scannerless` and compare. Then write the let, letx and `let=2` tests and the `(a / ab) EOF` versus `(ab / a) EOF` contrast yourself, since the anchor does not contain them. Finally build variants of your own that leak a failed branch's capture, treat a nonfinal prefix as a definite failure, or accept the reserved word, and find the shortest input and node arrangement that exposes each.

What to capture and how to read it. Keep the `PD_ASSERT:<line>:<expression>` line, the input, the prefix length, the EOF flag, the status, the capture list with spans and the result snapshot after a refusal. A capture that is present when it should be zero shows that rollback is missing; `PD_NO_MATCH` where `PD_PENDING` was required shows that the prefix state is lost. If the anchor does not reject a variant, your own tests are the evidence. The assessor's mutation set also checks this invariant.

Impact class. `demonstrated-invariant-violation`, and only after you build a variant and show the wrong status or leaked capture on a named input. A leaked capture is a parsing-integrity defect, not a memory disclosure; a syntax error, sanitizer report or timeout alone is not code execution or privilege escalation.

Remediation and regression. Roll back captures on every failed alternative and lookahead, propagate `PD_PENDING`, and charge each node against the budget. Keep the let, letx and choice-order tests beside the existing `parsing_depth.scannerless` assertions.

Limitations. Stateless prefix retry makes no linear-time or packrat claim, and the finite cases do not prove the DAG interpreter universal.

# X-T15-013: Scannerless ordered choice, lookahead and speculative capture rollback

## Prerequisites

Study T15.14 and PR-T15-09, T03 array/object lifetimes and T14 stack/set representations. Bring a hand trace of the shared grammar, bounds tests and a list of ordinary versus malformed inputs. LR additionally needs least fixed points and FIRST/FOLLOW; regular expressions need finite-state machines; Pratt needs expression trees; scannerless work needs rollback and three-result recognition. No unlisted accepted artifact import is required.

## Environment

The explicit [parsing depth contract1](../../../labs/parsing_depth/CONTRACTS.md) supplies the full typed API, exact languages, capacities, dependencies, ownership, admission/failure semantics and local security scope. Implement the supplied compiling `src/parsing.c` scaffold. The C mechanism cannot delegate to a mature parser library. Host independent oracles remain separate. ISO C type checks do not establish the semantic grammar/table or pointer-lifetime preconditions.

## Problem

Implement the bounded scannerless expression DAG from primitives, then construct the keyword/identifier assignment grammar in the shared contract. Recognize let x=12 versus letx=2 while rejecting reserved let=2. Return copied capture spans only from a successful branch. Parse every prefix with EOF absent/present and require complete-input recognition via NOT ANY. Show the difference between (a/ab) EOF and (ab/a) EOF.

## Necessity

Ordered choice is not symmetric alternation, a boundary without EOF is not a definite mismatch, and successful lookahead must not commit capture side effects. Repetition of a nullable expression needs a progress check. Retained packrat work implements different cache/left-recursion mechanisms and does not supply these missing negative-lookahead and unified lexical-record semantics.

## Reasoning

Define each expression as status/end/captures, including PENDING propagation. Prove capture rollback across sequence failure, failed choice and NOT, and explain why retrying a lower-priority branch after PENDING can select a wrong grammar result. Derive the forward-DAG depth bound, explicit node budget and32-capture bound. Explain why retrying full prefixes has a different total-work contract from an incremental state machine or memoized packrat parser. Keep recognition/captured spans separate from numeric or symbol-table effects. Give the smallest concrete counterexample to one plausible incorrect explanation. Separate ISO C rules, the teaching language/grammar, compiler support and programmer-maintained invariants. State every pre/postcondition and no-publication failure boundary.

- D3: Independent model, complete test inputs/results, failure snapshots and two distinct compiled semantic mutants rejected for the intended reasons.

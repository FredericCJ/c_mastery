# X-T67-005: Branded pool handles with checked generations

## Prerequisites

Complete the earlier domain projects and retain the named prerequisite artifacts with their contracts, ownership ledger and tests. Required learner artifacts: memory.pool. Do not import an assessor implementation.

## Environment

Implement mechanisms locally using declared typed storage/callbacks; hosted harness and diagnostic runtimes are separate. See laboratory contract for exact dependencies. Use C17 with extensions disabled and warnings treated as errors. A diagnostic extension is identified explicitly and does not become an ISO guarantee. The full platform, pointer, callback and concurrency preconditions are in [adt/CONTRACTS.md](../../../labs/adt/CONTRACTS.md).

## Problem

Implement the fixed4slot ADPool API. init requires a live fixed-address pool with no surviving handles. acquire takes first free nonretired slot and returns owner pointer/index/generation; full pool fails unchanged. get/release validate exact live pool identity, index and generation. Release increments generation, or permanently retires a UINT_MAX generation slot. Caller controls synchronization; no concurrent calls.

Concrete inputs and expected results: A handle frompoolA is rejected bypoolB; release/reacquire invalidates the old generation; release atUINT_MAX retires its slot and reduces usable capacity to3.

Supplied artifacts: labs/adt/include/adt.h, compiling unsolved src/adt.c, CTest adt.brands, fixtures/adt/PR-T67-05.json, and the shared contracts. State every additional backend assumption before running it.

## Necessity

Separate nominal handle category, pool identity, slot generation and ownership; demonstrate why a C wrapper cannot create a compile-time fresh brand per runtime pool or enforce linear use. The misconception and changed-condition case below are separately assessed; ordinary successful execution alone does not cover them.

## Reasoning

Derive FREE/LIVE/RETIRED transitions and count available slots. Explain why copying a handle is permitted by C yet does not duplicate ownership. Pool objects must remain live at fixed addresses and cannot be reinitialized or reused while handles survive: pointer identity does not prevent ABA across object lifetimes. Compare PhantomData nominal/lifetime roles without claiming equivalent static checks. Give the abstraction function, admitted states, pre/postconditions, ownership graph, failure effects and complexity before implementation. Identify the enforcement boundary of every safety claim using the shared modern-cost contract. Distinguish an invalid caller object from an operational failure admitted by the API.

## Deliverables

- D1: Separate nominal handle category, pool identity, slot generation and ownership; demonstrate why a C wrapper cannot create a compile-time fresh brand per runtime pool or enforce linear use.
- D2: Derive FREE/LIVE/RETIRED transitions and count available slots. Explain why copying a handle is permitted by C yet does not duplicate ownership. Compare PhantomData nominal/lifetime roles without claiming equivalent static checks.
- D3: Run adt.brands and enumerate short acquire/release/get traces against an independent occupancy/generation model. Kill owner-check omission and generation-check omission independently. Compile a wrong-category handle probe; show that copying or explicitly constructing a valid public representation bypasses any unforgeability claim.
- D4: Replace the owner pointer with a nonreused externally assigned pool identity and implement relocation of the pool. Then introduce concurrent get/release: provide a reclamation/lifetime protocol, not just an atomic generation counter. Complete all thirteen cost/enforcement dimensions with evidence or a mechanism-specific non-applicability.

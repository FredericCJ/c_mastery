# X-T41-002: Complete coverage and bounded ownership for IPv4 fragments

## Prerequisites
Complete X-T41-001 with your own SChecksum source; bring T41.01 storage/ownership and T41.05 checked fixed-header parser. The shared contract specifies producer-before-consumer progression and actual original provider identities.

## Environment
Use the exact C17 hosted/strict Cortex-M4 profiles, explicit providers and disjoint-span rules in labs/network_followthrough/ip/CONTRACTS.md. Dedicated board observations remain a separate required protocol.

## Problem
Implement ni_init/receive/take/tick/expire with two1480-byte slots and the full supplied contract. Offsets0 and16 of a24-byte payload leave an8-byte hole. Last-first arrival must work; ICMP/TCP with the same ID must not mix. Strict overlap poisons; identical mode may accept only matching bytes. A60000ms absolute lifetime never refreshes. Supply a complete Time Exceeded report only under the documented first-fragment/unicast/error-suppression premises. All code interfaces, public cases, constraints, statuses and outputs are in the shared contract.

## Necessity
The old fixed profile rejects fragments. A fragmentation design paragraph or high-water counter does not establish complete coverage, atomic delivery or bounded lifetime. The six registered competency refinements make each mechanism separately assessable without duplicating the original leaf.

## Reasoning
Prove the bitmap/count invariant, final bound, copied ownership and no partial publication. Distinguish time advancement from successful admission, READY retention from incomplete expiry, and tombstone window from permanent replay defense. Derive per-operation resource costs and identify caller-enforced preconditions. Explain historical RFC791/RFC1122 differences precisely.

## Deliverables
D1: Hand-derived histories and six invariant arguments. D2: Original source and explicit checksum/old-parser adapter with resource audit. D3: Complete-field/overlap/identity/hole/deadline negative traces, independent set oracle and compiled mutant diagnostics. D4: Unseen changed-policy and capacity assessment after at least7 days. Exact evidence obligations and grading levels are in the shared contract and six rubric rows.

## Verification
Run the public network_followthrough.ip test, then the complete author protocol for independent expectations, all profiles, actual component composition and target closure. Reject the compiling learner stub and each named semantic mutant for its intended assertion. Physical protocol and independent assessment are unobserved, even when author reference tests pass.

## Rubric
Score R1 identity/admission, R2 coverage, R3 overlaps, R4 resources, R5 expiry/feedback and R6 integration separately. Level2 is necessary on every row; level3 requires an actual independent transfer attempt. One passing checksum test cannot satisfy any missing reassembly row.

## Hints
H1 draw byte-position ownership. H2 compare the highest offset with the set of covered offsets. H3 keep first-header, final-length, coverage and fixed deadline as separate facts. Preserve an unaided attempt before using hints.

## Variants
V1: Reduce to one slot and admit byte-identical partial overlaps; preserve conflict retirement and the original deadline. V2: Change input alignment and retained output layout; feed complete reassembled Echo through the actual old parser and compare the56/64-byte capture protocol. Both require new invariant and cost arguments, not changed constants alone. Assessor-only unseen histories are administered after at least7 days.

## Security

The target is the learner's IPv4 reassembler in `labs/network_followthrough/src/ip.c`, run only against local packet arrays or the project's emulator. The attacker controls fragment fields and arrival order: identification, protocol, offset, length, overlap bytes and time. The two 1480-byte slots, the 60000 ms absolute lifetime and the checksum provider are fixed.

**Property.** (1) Fragments with a different protocol or source/destination tuple never mix, even when the ID matches. (2) A datagram is delivered only when coverage is complete: offsets 0 and 16 of a 24-byte payload leave an 8-byte hole and must deliver nothing. (3) Strict overlap poisons the datagram, and identical mode accepts only matching bytes. (4) The lifetime counts from the first fragment and never refreshes.

**Experiment and evidence.** Predict the status and bytes for each schedule before running. The public test `reassembly` in `labs/network_followthrough/ip/tests.c` (CTest `network_followthrough.ip`) pins: offsets 0 and 16 return NI_WAIT and only the filling fragment returns NI_OK, then `ni_take` gives 44 bytes; a protocol-6 fragment with the same ID takes slot 1; a conflicting overlap returns NI_CONFLICT and poisons slot 0; the slot expiry stays 60000 after a later fragment; `ni_tick(60000)` frees it. No flawed variant is supplied: build ID-only keying, hole-tolerant delivery and lifetime-refresh mutants yourself, record which CHECK rejects each, and capture raw outputs and source hashes.

**Impact class.** A mixed identity or premature delivery in the local reassembler is a `demonstrated-invariant-violation` once you build and run a flawed variant; no supplied artifact demonstrates it. It is not a crash or sanitizer finding unless a sanitizer reports one, and no code execution or production attack is claimed.

**Repair and limits.** Repair by keying on the full identity, requiring full coverage and expiring on the original arrival time, and keep each failing schedule as a regression. State the limits: no real network traffic, no forwarding behaviour, and the Time Exceeded report depends on its documented premises.

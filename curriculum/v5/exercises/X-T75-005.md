# X-T75-005: Jittered retry schedules with a shared deadline and attempt budget

## Prerequisites

Bring pinned contracts and fresh recall for io.deadline, communications.tcp_fault, measurement.capture; prerequisite exercises: X-T75-001, X-T75-004. Required knowledge includes C object lifetime, checked arithmetic, ownership, typed arrays and the selected source passages. The shared contract and modern-cost contract are explicit parts of this exercise. Existing project estimates describe author accounting; they impose no learner time ceiling.

## Environment

Use C17 hosted Linux with GCC and Clang, CMake and host Python. Record compiler/ABI versions, integer widths, sizeof/alignment and optimization. Mechanism code uses no library implementing the mechanism. The T73 channel backend supplies its declared POSIX synchronization; the virtual-time model itself supplies no OS clock, sleep or hidden scheduler. A strict freestanding port requires its own generated-code/link audit and is not established by the hosted run. Compare C11 draft/C17/C23 only where inspected normative evidence supports the claim; exact published C17 access remains a reference gap.

## Problem

Implement RZRetry schedule with bounded attempts, capped exponential windows and injected full-jitter draws. Reject unsafe-to-repeat operations and starts at or beyond the inherited deadline. Implement a deterministic PRNG adapter with unbiased bounded selection using rejection sampling; keep its seed record and entropy limitations explicit. Connect scheduled attempts to the accepted communications.tcp_fault loss/duplicate/late-ack model, charging every dispatch to a common retry limiter at one chosen layer.

Supplied artifacts: labs/resilience/include/resilience.h, deliberately incomplete labs/resilience/src/resilience.c, executable anchors, fixture PR-T75-05.json and the shared CONTRACTS.md. Expected example: Base2/cap8 produces draw windows[0,2],[0,4],[0,8]. At now9 with deadline10, draw1 rejects and preserves attempt count. A non-idempotent request rejects before scheduling. Three admitted retries exhaust a maximum3 budget even if all draws were zero.

## Necessity

Backoff can amplify overload while making average latency look better. Randomizing when an unsafe operation repeats does not make its effects idempotent.

## Reasoning

T75.05.a: Derive bounded exponential windows, count the original attempt separately and explain why nested retries multiply work. Classify retryable outcomes without treating timeout as absence of side effects.

T75.05.b: Implement schedule, unbiased bounded PRNG adapter and actual fault-model dispatch with a common limiter, preserving ownership of outstanding attempts until completion.

T75.05.c: Enumerate every allowed draw for windows2/4/8, deadlines at each boundary and all capped attempt histories; use fault traces where an effect commits but its acknowledgement is lost.

T75.05.d: Compare no-jitter, full-jitter and a documented alternative under fixed seeds and equal retry/deadline budgets. Measure peak synchronized work as well as completion latency; transfer to correlated client seeds and expose why jitter is not a security or safety guarantee.

State preconditions, postconditions, representation invariants, resource ownership, failure publication and complexity. For each guarantee identify ISO C rules, diagnostics, runtime checks, external verification and programmer discipline separately. Include a minimal counterexample to an overstated equivalence with the corresponding language/library abstraction. Apply all13 dimensions in modern-cost-contract.md, recording genuine non-applicability with reasons and unavailable measurements as gaps.

# X-T41-003: Congestion, ACK evidence and loss recovery from first principles

## Prerequisites
Bring your checked sequence/retained-send ownership and RTT/RTO artifacts from T41.06/07 and your actual IP/checksum implementation from X-T41-002. Follow the controller-before-receiver-before-network progression in the shared contract. Reference execution does not validate your prerequisite implementations.

## Environment
C17 hosted finite packet model plus strict Cortex-M4 CPU controller; the exact API, dependency profile, runtime restrictions and toolchain assumptions are in labs/network_followthrough/congestion/CONTRACTS.md. Host oracles are not target dependencies.

## Problem
Implement NrControl from the supplied public header and src/congestion.c scaffold. Track committed flight independently of cwnd/rwnd; derive growth, loss collapse, fast recovery, Limited Transmit and idle restart. Implement the twelve specified synthetic packet schedules with8192-byte exact payloads, real out-of-order receiver state and the original IP/checksum providers. All input ranges, return statuses, copy boundaries, output equations and permitted primitives are in the explicit shared contract.

## Necessity
A fixed one-flight transport cannot demonstrate ACK-clock growth, congestion avoidance, multiple losses, duplicate-inflation attacks or meaningful competing-flow measurements. This required exercise refines T41.07.c without changing its historical evidence.

## Reasoning
Derive byte conservation and half-range sequence invariants, copied ownership, independent loss/recovery episodes, resource bounds and failure semantics. Refute cwnd=flight, every duplicate proves loss, and equal completed workloads prove fairness. Explain exactly what ISO C17/C23, diagnostics, runtime checks and caller discipline enforce.

## Deliverables
D1 invariant derivations and predicted traces; D2 all controller operations, strict target build/import/stack audit; D3 independent aggregate oracle and nine compiling semantic controls; D4 packet/receiver variants, exact bytes and finite-horizon measurements. Supply changed-condition evidence and criterion-indexed explanations. The contract specifies every concrete case and acceptance obligation.

## Verification
Run network_followthrough.congestion, the independent8255-case oracle, all twelve packet schedules, six hosted profiles and four CPU profiles through tools/run_network_congestion.py. Reject compiling stub and nine semantic mutants for their intended failures. The delayed-ACK and Limited Transmit variants must execute; a design paragraph does not substitute for code. Retain raw commands, source identities, outputs and all evidence limits.

## Rubric
Each of R1 admission, R2 growth, R3 loss, R4 extra-byte/idle policy, R5 composition and R6 adversarial/resources must attain level2 independently. Level3 requires a real independent changed-condition attempt; author execution cannot award it.

## Hints
First draw UNA..NXT and count only newly acknowledged bytes. Next separate ordinary window admission from two extra intervals. Finally retain one inflation budget across all window updates within the same recovery episode. Record hints used after preserving an unaided attempt.

## Variants
V1 changes segmentation and partially retires Limited Transmit intervals; V2 changes receiver ACK scheduling and queue admission priority. Both executable assessor variants and administration rules are separate from learner exports and require at least7 days before independent transfer credit.

## Security
Only the original local array controller/simulator, learner code or dedicated emulator; synthetic ACKs and bytes, no external traffic. Harmless success is an observed controller invariant violation under ACK division or duplicate inflation. Compare flawed/corrected implementations and residual unauthenticated-input assumptions; no code-execution or production attack claim.

## Validation
Author results are source-bound in reviews/v5/expansion/legacy_network_congestion. External review, learner/delayed attempts and physical observations are separate and unperformed. Finite passing traces do not establish absolute mastery, universal fairness or full TCP conformance.

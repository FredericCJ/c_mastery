# X-T15-004: Prefix codes, dictionary matches and optimal parsing

## Prerequisites

Complete the named integer and algorithm exercises. Bring your own bit-extraction tests, loop-invariant notebook and dynamic-programming derivation; no assessor implementation is a learner prerequisite. Know prefix trees, unsigned shifts, span lifetimes and shortest paths on an acyclic graph. Read the specific RFC passages in the source record and the entire shared contract before coding.

## Environment

Use the C17 and dependency profile in the JSON contract. The original component is allocation-free. Python oracles, C stdio and clock measurements run only on the host. Audit undefined symbols and linked code for the explicit Cortex-M4 compiler/optimization combinations. No libc or implicit helper is permitted in that closure. C23 changes neither this wire format nor the runtime's ownership enforcement; do not infer new bounds/lifetime guarantees from changing the language mode.

## Problem

Implement all ordinary functions in codec.h in the unsolved src/codec.c, leaving the delayed optimal-parser functions for their separate assessment. The shared contract defines exact representations, error priority, tie rules, size limits, bit packing and failure atomicity. Construct Huffman lengths from frequencies; derive canonical codes; encode/decode their explicit length table. Implement the 32-byte-window,16-byte-match LZ grammar, including overlapping copies. Compose LZ bytes through a high/low-nibble Huffman alphabet.

The supplied overlap stream 00 78 00 79 01 05 02 produces xyxyxyx. A distance-zero match fails without publishing any output. An empty symbol stream produces the18-byte zero header. Inspect cases.json, the public tests and driver. No compression library may implement any of these mechanisms. A correct self-round-trip alone is insufficient: mutually wrong encoder and decoder can agree.

## Necessity

RLE cannot assess prefix-space validity, greedy-code optimality, history-dependent overlapping copies or the distinction between shortest token streams and shortest final frames. Common errors include accepting three length-one codewords, copying matches from a frozen source window, ignoring tail bits and assuming every input compresses. Demonstrate each claim with a concrete counterexample or proof.

## Reasoning

D1 must prove the Huffman sibling/exchange reduction, derive canonical prefix-slot capacity and justify the one-bit singleton convention. Prove the decoder's produced-prefix invariant and the overlap recurrence. Derive the two stages' maximum sizes and simultaneous scratch lifetimes; classify checked domain errors separately from caller violations such as overlapping live spans. Explain why a capacity error need not certify payload validity. State ISO C, compiler, host-library and original-format assumptions separately. Ownership and disjointness remain caller discipline; runtime checks validate only stated bounds and grammar.

Configure cmake with labs/corpus_codec and an empty build directory, build, then run ctest --output-on-failure. The default stub must compile and fail CC_CHECK. ## Security

Why this matters here. A decoder is a parser of attacker-chosen bytes, and a lossless codec offers no authenticity, so the only protection is that the decoder says no to every malformed stream and says it without side effects. The contract ranks the checks: header and domain checks come before capacity, cc_hdecode checks the count against capacity before payload validity, and cc_lzdecode validates the whole token stream before looking at capacity. The consequence for a caller is that CC_SPACE is never evidence that the bytes were valid, and the consequence for you is that each failure path must leave the output span and the used counter exactly as they were, which the test checks with a 0xa5 sentinel.

What to try. Work three admission cases by hand. Lengths 1,1,1 give a prefix-space sum of 3/2, which exceeds 1, so the book is oversubscribed. A one-symbol frame uses one payload bit and seven padding bits, so setting the low bit of the last octet must be rejected. The token stream 00 78 00 79 01 05 02 is literal x, literal y, then a match of length 5 at distance 2, which must read bytes it has just produced and give xyxyxyx. Then write the inputs the public test does not cover. By the grammar a literal 'a' followed by eight matches of length 16 at distance 1 (00 61 followed by eight copies of 01 10 01) would expand to 129 bytes and must be CC_INVALID, while seven such matches plus one of length 15 reach exactly 128 and are valid; add a frame with a trailing whole octet and a frame with a truncated code. Feed these to the repaired decoder only, through codec_driver (the `ld` operation takes the token hex and prints a status, 0 for CC_OK and 1 for CC_INVALID) and through a C test that also checks the sentinel.

What to capture and how to read it. For each of your four controls keep the stderr `CC_CHECK:<line>` and map it to the public check: the oversubscribed book, the padding bit with n still 777, distance zero, the overlapped copy producing seven bytes, the failing capacities, the NULL and 129-byte compression, the 18-byte empty frame. A control that survives marks an input the public test lacks. Do not treat a decoder that fails with CC_SPACE on a malformed stream as having validated it.

What this does and does not show. A decoder accepting a malformed synthetic frame or publishing on failure. No supplied artifact demonstrates it, so the impact class holds only once you build a control. The assessor's mutation set also checks this invariant. A valid stream can be replaced by another valid stream undetected, the grammar is an original format rather than DEFLATE, and timing and resource side channels beyond the 128-byte cap are not studied.

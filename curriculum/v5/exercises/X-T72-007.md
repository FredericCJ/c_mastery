## Security

Target `co_packrat` and its caller-owned memo cells in `labs/coroutines` for the fixed S grammar, using only synthetic values. No network service or hardware is involved.

- Adversary: chooses the input (a run of a, then x, then the matching count of b or c) and may reuse the memo cells for a new input. It cannot change the grammar or cell storage.
- Violated property: a memoized answer agrees with the direct grammar, failures are memoized, and a mismatch leaves the caller's end unchanged.
- Boundary: in-process host model; harmless success is the illegal state change or counter recorded by the harness, never a crash left running.
- Evidence to capture: run `coroutines.packrat` (`aaxcc` ends at 5 with 3 evaluated cells; twelve a, x, twelve c ends at 25 with 13; `aac` is CO_NO_MATCH with end 91 and at most 4 evaluations; a 25-cell table is CO_INVALID). Build a variant without cached failures or without reinitialized cells as `labs/coroutines/CONTRACTS.md` asks and record the count or wrong accept.
- Impact class: demonstrated-invariant-violation, from the learner-built defective variant only (no flawed variant is supplied and the supplied test passes on a correct build, so no supplied artifact demonstrates it); not a crash, sanitizer finding or undefined behaviour, and not a proved impact.
- Remediation and regression: cache success and failure by position, reinitialize cells per input, keep end unchanged on failure; `coroutines.packrat` must fail the variant.
- Limitations: space grows with input; the work bound relies on the fixed grammar; a stale table after an edit is a separate case.

# Trace Cortex-M4 reset from vector bytes to C state

## Prerequisites

Complete X-T09-001 before beginning.

## Environment

Use ARMv7E-M Thumb on QEMU MPS2 AN386. From the exported workspace root run `python3 inspect_lab.py prepare --target cortex`. Record the output directory, compiler version and manifest. The commands and answer-field conventions are in CONTRACTS.md.

## Problem

On the MPS2 AN386 model, predict the initial SP, reset target and C state after startup from the linker script, the assembly reset handler and the image. Separate processor reset behavior from the code that initializes writable memory.

## Necessity

Decode the initial stack pointer and Thumb reset vector from the retained table. An output value by itself omits the evidence that connects this claim to a particular build.

## Reasoning

Read `arm/image.ld` and `arm/entry.S`. Use `arm-none-eabi-readelf -lSW` and `arm-none-eabi-objdump -s -j .vectors` to decode the two little-endian words. Match the reset entry's low bit to Thumb execution. Start QEMU paused and use gdb-multiarch to read SP, step through the copy/clear loops and inspect initial_size, record_calls and observed at result_ready. Compare load and run addresses.

## Deliverables

- D1. Write your prediction before running the relevant inspection tools. Record the commands, file identities and observations in `answers/cortex.json`. Include `prediction`, `explanation` and the fields `elf_sha256`, `initial_sp`, `reset_vector`, `post_startup`.
- D2. In your explanation, cite the bytes, instruction, header field or counter row supporting each inference in the reasoning exercise.
- D3. Identify which changes to `.data` initialization would alter the flash bytes, and which changes to `.bss` would only affect the memory extent. Explain which conclusions would require an observation on a named physical target.

## Verification

Run `python3 inspect_lab.py check cortex --cc gcc`. For a hosted Clang build prepare and check with `--cc clang`. Preserve the manifest with the submission. A reviewer reads the written reasoning alongside the machine-checked observations.

## Rubric

- R1. Decode the initial stack pointer and Thumb reset vector from the retained table.
- R2. Reconcile vector placement, .data copying and .bss clearing with the QEMU reset and post-startup observations.

## Hints

QEMU startup for this lab and a loopback GDB connection are described in CONTRACTS.md. Check `arm-none-eabi-nm -u` on the final linked image to audit freestanding dependencies.

## Variants

V1 is a delayed independent transfer on a changed artifact, at least seven days after the first attempt. Derive the result from the supplied inputs and identify the evidence needed for each claim.

## Security

Use the supplied original program and locally generated files. Keep measured images, host details and observation logs in the local workspace.

## Validation

The checker compares selected artifact facts. The assessor separately evaluates the derivation, changed condition and whether an independent transfer took place.

# X-T65-009: Canonical rational values and the boundary of runtime refinement

## Prerequisites

Use the existing bytes.checked, parser.integer, io.stream and codec.records contracts as comparison boundaries. Complete C17 tagged-union, pointer-lifetime and function-pointer reasoning first. Preserve the learner's earlier implementations; do not import an assessor solution. Complete X-T65-008 first.

## Environment

Original C mechanisms; hosted setjmp/longjmp only for the explicit jump boundary. Host harness may use stdio/Python. No strict freestanding claim. C17, Linux x86-64, GCC and Clang with -Wall -Wextra -Wpedantic -Werror and extensions disabled. The exact shared contract is [errors/CONTRACTS.md](../../../labs/errors/CONTRACTS.md). C editions, language-level guarantees and implementation observations must be labeled separately.

## Problem

Implement er_refine(numerator,denominator,output) for uint32_t inputs. Denominator zero rejects with output unchanged. Every valid output has a positive denominator and coprime numerator/denominator representing the same rational; zero is uniquely0/1. Derive Euclid reduction from remainder invariance rather than call a number-theory library. Add a checked consumer that validates a supplied public struct before use and compare with a private opaque representation. Copying or direct assignment to a public C struct can bypass the smart constructor.

Concrete expected cases: 6/8 becomes3/4; 0/13 becomes0/1; UINT32_MAX/UINT32_MAX becomes1/1. Failed3/0 preserves both prior fields. Explain why an observed valid object yesterday does not validate a mutable alias today.

Supplied artifacts: labs/errors/include/errors.h, compiling unsolved src/errors.c, the named CTest errors.refinement, and fixtures/errors/PR-T65-09.json. No installed package may supply the mechanism under assessment.

## Necessity

Prove value preservation, termination and canonical representation; distinguish a runtime predicate from a static refinement type. An ordinary nominal call does not assess this distinction. The two isolated mutants and the changed-condition case expose different incorrect explanations.

## Reasoning

Implement transactional rational normalization and a validated consumer, documenting public-struct mutation and alias ownership limitations. State the preconditions, postconditions, valid representation states, ownership and failure effects before implementation. Derive operation and storage bounds; distinguish caller misuse from a reported operational failure. Compare the C protocol with the exact inspected source scope: C type compatibility and diagnostics do not supply automatic ownership, exhaustive matching or proof of a runtime predicate.

## Deliverables

- D2: Implement transactional rational normalization and a validated consumer, documenting public-struct mutation and alias ownership limitations.
- D3: Enumerate numerator0–255 and denominator0–255 using Python fractions or an independently derived cross-product/gcd oracle. - D4: Introduce rational addition with bounded storage. Complete all dimensions of the shared modern-cost contract, with evidence or a justified non-applicability.

## Problem

Implement exact-length asynchronous reads with at most two reads per poll, arm-then-recheck, generation-scoped notifications, synchronous disarm and cancelled/error terminal states. Build an io.reactor/io.stream/io.deadline adapter.

The complete representation, operations, input bounds, state transitions, ownership, callback rules, failure behavior and output contract are supplied by the shared contract. Concrete inputs and independent expected result: The fake reader returns AGAIN until arm, then supplies all three bytes on the immediate recheck: one poll completes after2 reads,1 arm,1 disarm. A stale generation cannot mark the next frame ready.

Supplied artifacts are labs/coroutines/include, labs/coroutines/src, the coroutines.async CTest and fixtures/coroutines/PR-T72-08.json. Implement the mechanism from permitted primitives. Complete the required alternative/integration as well as this bounded executable anchor.

## Security

Target `co_async_poll`, `co_async_notify` and `co_async_cancel` on the `struct co_async` frame in `labs/coroutines`, using only synthetic values. No network service or hardware is involved.

- Adversary: scripts reader outcomes (data, AGAIN, EOF, ERROR), the arm and notification order and a replayed notification with an old generation. It cannot overrun the frame buffer, allocate generations or run callbacks inside poll and cancel.
- Violated property: no lost wakeup between the first read and registration, a stale-generation notification never marks a later frame ready, and a completed or cancelled frame does not publish again.
- Boundary: in-process host model; harmless success is the illegal state change or counter recorded by the harness, never a crash left running.
- Evidence to capture: run `coroutines.async` (one poll completes with 2 reads, 1 arm, 1 disarm and a second poll adds no read; with generation 8, notify(7) is CO_STATE and notify(8) is 0; cancel disarms once and a later poll is CO_STATE with no read). Build a variant without the recheck or the generation test as `labs/coroutines/CONTRACTS.md` asks and record the counters.
- Impact class: demonstrated-invariant-violation, from the learner-built defective variant only (no flawed variant is supplied and the supplied test passes on a correct build, so no supplied artifact demonstrates it); not a crash, sanitizer finding or undefined behaviour, and not a proved impact.
- Remediation and regression: arm then recheck, compare generation on every notification and disarm synchronously; `coroutines.async` must fail the variant.
- Limitations: relies on synchronous disarm and the documented registration contract; a read callback that overruns its buffer cannot be repaired by checking its returned count.

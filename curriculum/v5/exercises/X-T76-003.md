## Problem

Implement checked Lamport receive max(local,remote)+1, fixed3-replica vector merge-then-increment and partial-order comparison (-1 before,0 equal,1 after,2 concurrent). Implement HLC Figure5 using uint64 physical and uint32 logical components, local/send events via remote=NULL and receive events via a remote pair. Apply every max/tie branch; backwards wall time is allowed. Counter overflow returns RP_RANGE with output unchanged; do not wrap and silently violate causality.

Concrete inputs and expected results: Lamport(2,8)=9. Vectors[1,0,0] and[0,1,0] are concurrent; receive at replica0 gives[2,1,0]. HLC local(10,2),remote(10,7),wall9 gives(10,8); wall11 on a subsequent local event resets logical to0. UINT32_MAX logical overflow fails unchanged.

Supplied artifacts: labs/replicated/include/replicated.h, compiling unsolved src/replicated.c, CTest replicated.clocks, fixtures/replicated/PR-T76-03.json, and the shared contracts. State every additional backend assumption before running it.

## Security

Target only the Lamport, vector and hybrid-logical-clock functions in [labs/replicated](../../../labs/replicated), in a local process.

- **Adversary.** You control the remote and local timestamps handed to a receive, including uint64 and uint32 extrema, backwards wall time, duplicates and reordering. You do not control replica identity assignment, code or pointers. Worked case: a Lamport receive at local 2 of a remote stamp 8 must give 9 (tests.c:101); a receive that returns local+1 = 3 orders the receive before the send it depends on.
- **Violated property.** Causality: a receive is ordered after both its local predecessor and the remote send, concurrent vectors such as {1,0,0} and {0,1,0} compare as 2 (tests.c:103), and overflow fails with RP_RANGE and an unchanged output instead of wrapping to a small stamp that would sort before everything it follows.
- **Experimental boundary.** Three replicas, constant inputs and no clock reads, process creation, file or network (tests.c:96-116). Timestamps are plain integers you choose.
- **Evidence to capture.** Predict first: HLC (10,2) receiving remote (10,7) at wall 9 gives (10,8); a local event at wall 8 then gives (10,9); wall 11 gives (11,0); remote (11,UINT32_MAX) must return RP_RANGE with logical still 0. Run CTest replicated.clocks and record those CHECKs (tests.c:108-115). Build the two variants from the header and record the `RP_CHECK line N` each produces (the harness stops at the first failure). Derive causal order from message-graph reachability, not from timestamp order, because a wrong Lamport order can still look sorted.
- **Impact class.** demonstrated-invariant-violation, once you have built and run a variant. A wrongly ordered pair is a violated model invariant; unsigned arithmetic is defined, so it is not undefined behaviour, and it shows no effect on a deployed system.
- **Remediation.** Take the maximum of local and remote before incrementing, implement every HLC branch and check the logical increment before storing. The regression that rejects the original defect is replicated.clocks; run it against both of your variants.
- **Limitations.** Timestamps are unauthenticated; a forged remote value can exhaust the logical counter. Real clocks, skew bounds and message delivery are not shown.

Derive causal relations from message-graph reachability before comparing outputs; timestamp order alone is not the oracle.

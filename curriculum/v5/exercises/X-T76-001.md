## Problem

Implement RPLog and rp_log_init/append/get. The original in-memory log contains at most16 events (position1..16,key0..31,int32 value) and17 snapshot roots. Each append first updates the imported persist.hamt arena, then publishes the event and root together. get(position,key) queries the exact retained prefix; position0 is empty. Invalid key/position, log full and injected HAMT allocation failure preserve published state and output. Replay an admitted prefix into a fresh fixed-address arena; values are latest event payload per key, not accumulated balances. No filesystem durability is implied.

Concrete inputs and expected results: Append(3,7),append(3,9): prefix1 returns7 and prefix2 returns9. Inject each allocation ordinal1..3 on the next append: count stays2, used count is restored and prior roots still resolve. The17th append returns RP_FULL without consuming nodes.

Supplied artifacts: labs/replicated/include/replicated.h, compiling unsolved src/replicated.c, CTest replicated.log, fixtures/replicated/PR-T76-01.json, and the shared contracts. State every additional backend assumption before running it.

## Security

Target only the in-memory RPLog in [labs/replicated](../../../labs/replicated), over the imported persist.hamt arena, in one local process with synthetic keys and values.

- **Adversary.** You choose the append sequence (key 0..31, int32 value), the ordinal 1..3 at which the arena refuses an allocation (`arena.fail_after`, tests/tests.c:30-33) and the prefix position you query. A path-copying append makes three allocations (the lab contract counts 48 nodes for 16 appends), so the second and third cut are the interesting ones: earlier HAMT clones already exist when the failure arrives. You do not touch arena memory or the count field directly.
- **Violated property.** Atomic publication and prefix integrity. The log is the authority a projection replays from, so a count that advances past the last published root names a prefix that was never published, and a get that reads the newest root for every position lets an old prefix answer with today's values. Worked check: after append(3,7) and append(3,9) the newest root holds 9 for key 3, yet get(1,3) must still return 7 (tests.c:25-26).
- **Experimental boundary.** One hosted process and no child, socket, file or network. The durable tests tear writes only on an in-memory page medium (durable_test.c:15-24). At most 16 events, 17 roots and a 64-node arena. Success is a wrong value or an advanced count in the teaching log, nothing else.
- **Evidence to capture.** Predict first: for each fail_after 1, 2 and 3, what must `log.count` and `arena.used` be afterwards (2 and unchanged), and what does the 17th append return (RP_FULL with used == 48)? Then run CTest replicated.log and record the quoted CHECKs (tests.c:25-27, 32-33, 40). Next build the two variants named in the header and run replicated.log against each. The harness prints `RP_CHECK line N: <expression>` and stops at the first failing CHECK, so record the line number and say whether it matches your prediction; a variant that breaks two properties reports only the first until you repair it.
- **Impact class.** demonstrated-invariant-violation, and only once you have built and run a variant: no supplied artifact exhibits it. A wrong prefix answer or premature count is a violated invariant; it is neither a crash, a sanitizer report nor undefined behaviour, and without a deployed consumer it is not proved impact.
- **Remediation.** Perform all three HAMT path clones, publish event and root together, advance count last, and read the root retained for the requested position. The regression that rejects the original defect is replicated.log; keep it and run it against both of your variants.
- **Limitations.** The in-memory anchor says nothing about torn durable records on real media, concurrent publication or forged roots; a passing run does not establish arbitrary-code-execution resistance or durability. State residual identity, resource and concurrency limits.

Run replicated.log and the three allocation-cut assertions, compare every prefix against an independent key/value dictionary and rebuild into a fresh arena. Inspect source and link dependencies to establish that the real imported HAMT is used.

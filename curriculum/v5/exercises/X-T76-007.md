## Problem

Implement local SHA-256 for byte lengths0..65 directly from RFC6234 equations, and RFC9162-style Merkle roots over0..8 uint32 leaves encoded big-endian. Empty root is SHA256(empty), leaf is SHA256(00||four bytes), internal node is SHA256(01||left||right), split at largest power of two strictly below count. Implement recursive equal-subtree skipping and return a bitmask of differing leaf positions for equal-length trees. No target hash library, network service or certificate-transparency implementation may replace these mechanisms.

Concrete inputs and expected results: SHA256(empty)=e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855. Trees[1,2,3] and[1,2,9] differ only at bit2 (mask4); empty trees give mask0. Compare every count0..8 with a separately implemented Python hashlib construction.

Supplied artifacts: labs/replicated/include/replicated.h, compiling unsolved src/replicated.c, CTest replicated.merkle, fixtures/replicated/PR-T76-07.json, and the shared contracts. State every additional backend assumption before running it.

## Security

Target only the local SHA-256, Merkle root and anti-entropy diff in [labs/replicated](../../../labs/replicated), in a local process.

- **Adversary.** You choose up to eight uint32 leaves, tree counts, which leaf differs, and hash input lengths 0..65. You cannot find SHA-256 collisions and you do not control the hash code or memory. Worked case: the one-leaf tree {1} has root SHA256(00 || 00 00 00 01), the five bytes `00 00 00 00 01`, and the test pins exactly that equality (tests.c:202-203); the 00 and 01 prefixes give leaf hashes and internal-node hashes (SHA256(01 || left || right)) disjoint input domains, and an omitted leaf prefix changes this digest, so the pinned equality catches it.
- **Violated property.** Commitment integrity: leaf and node hashes are domain separated, the root commits to every leaf, and the diff reports exactly the differing positions. For {1,2,3} against {1,2,9} the tree splits at 2 (the largest power of two below 3), leaf 2 sits in the right subtree and the mask must be 4 (tests.c:204); an ignored right subtree gives 0 and reports the trees equal.
- **Experimental boundary.** One hosted process, counts 0..8, synthetic leaves. hashlib is your independent oracle, run from your own script; no network, transparency service, file or child process is used by the tests.
- **Evidence to capture.** Predict first: the empty-input digest begins e3b0c442, mask 0 for equal trees, and the root of an empty tree equals the empty digest. Run CTest replicated.merkle and record the CHECKs at tests.c:201-206. Build the two variants from the header and record the `RP_CHECK line N` each produces. Compare your implementation with hashlib for every count 0..8 and for the padding boundaries 55, 56, 63, 64 and 65 bytes.
- **Impact class.** demonstrated-invariant-violation, once you have built and run a variant. A root that does not commit to a leaf breaks the property on synthetic input; no hash collision is claimed and no deployed proof is forged.
- **Remediation.** 00 and 01 domain prefixes, the power-of-two split and a comparison of both children. The regression that rejects the original defect is replicated.merkle; run it against both of your variants.
- **Limitations.** No collision or preimage claim about SHA-256, no constant-time claim, no authentication of the root; equal-length trees only.

Include standard empty and abc vectors and all padding boundaries; benchmark nodes hashed against full leaf comparison under equal correctness contracts.

# X-T15-005: Weighted Count-Min and overflow-safe partition merge

## Prerequisites

Complete the named unsigned arithmetic and algorithm exercises. Bring an invariant notebook, independent test strategy and elementary expectation/probability reasoning. Read the exact registered primary passages and relevant CONTRACTS.md section; the assessor implementation is not a prerequisite.

## Environment

Use the declared C17/profileC contract. Implement only the original component; no third-party sketch or hash library may supply its mechanism. Keep hosted I/O and Python verification separate from the component. C23 mode supplies no automatic bounds, lifetime or statistical guarantee. Pointers, ownership, serialization and hash interpretation remain explicit caller premises.

## Problem

Implement sk_cm_init, sk_cm_add and sk_cm_query in src/count_min.c. The public contract specifies width, depth, bit-parity hashes, total/cell invariants and error publication. A zero-matrix row is legal and forces collisions: adding key1 weight7 makes key99 estimate7 even though key99 never arrived. Build an independent exact frequency table and a separate cell-grouping oracle. Prove which bound survives arbitrary fixed hashes and which bound needs independently sampled rows.

## Necessity

Exact hash-table counts grow with distinct keys. This bounded summary trades point-query error for fixed storage. A minimum is safe only under its nonnegative invariant; modulo overflow, saturation or undocumented deletion changes that invariant. Replacing a proof with a fixed-seed histogram cannot establish the probability of failure.

## Reasoning

Derive pairwise independence for uniformly random Boolean masks and biases, then the collision-mass expectation and Markov bound with width w and depth d. Name fixed-query/nonadaptive-stream and independent-row premises. Explain why an individual all-zero map is legal despite poor estimates. Derive O(depth*p*32) bit work for the present implementation, actual sizeof storage and merge cost. Identify the difference between overflow refusal and a successful but inaccurate collision estimate.

## Deliverables

- D1: Derivation, invariants, at least two wrong explanations with counterexamples, exact source locators and assumption/enforcement table.
- D2: Completed ordinary C17 provider, explicit build/dependency manifest, state diagrams and storage/operation cost accounting.
- D3: Independent oracle, boundary and adversarial cases, unchanged-output snapshots, two compiling semantic controls and actual GCC/Clang profile records.
- D4: Required delayed mechanism, changed-condition proof, independent comparison and failure/cost analysis.

## Verification

Use exact weighted counts and independently grouped cells for all64 query keys in each corpus. Cover empty, weightzero, maximum uint64 mass, overflow unchanged snapshots, deliberately singular matrices and configuration mismatch. Enumerate the tiny two-bit affine family independently. The count_min anchor and both compiling controls must behave as specified; memory faults are not successful semantic rejections.

Configure labs/corpus_sketch with CMake, build and run its selected anchor. The default src files must compile then fail SK_CHECK. Supply your external completed source directory through SK_PROVIDER. Record commands, compiler versions, input/source identities and raw outcomes; reject crashes as semantic controls. The public tests are necessary examples, not a complete solution certificate. Use the full procedure in CONTRACTS.md.

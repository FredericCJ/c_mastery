# X-T15-018: Shunting-yard translation and transactional token admission

## Prerequisites

Complete X-T15-012 and retain its actual lexer, token, tree and checked evaluator artifacts. Explain postfix evaluation, binary/unary arity, array bounds, C object lifetime and the difference between precedence and associativity. The supplied original refusing scaffold deliberately needs construction.

## Environment

Use the explicit C17 environment and runtime rules in [CONTRACTS](../../../labs/corpus_shunting/CONTRACTS.md). Supply the actual parsing_depth workspace through CMASTERY_PARSING_DEPTH_ROOT. Author substitution requires an explicit separate private provider. Hosted Python, stdio and clock are verification-only dependencies. Target core imports are separately inspected and linked to permitted original helpers.

## Problem

Construct the bounded operator-stack parser in shunting.h. Transform the actual earlier tokens into the exact earlier postorder tree without invoking Pratt parsing. Inputs, operations, capacities, status precedence, examples, output preservation and representation are defined in the shared contract. First derive and trace whole-input parsing, then implement capacity rejection and diagnostics, then implement resumable sy_begin/sy_push/sy_result with per-token rollback. Compare successful trees and evaluation with the actual earlier implementation and a structurally independent grammar oracle.

## Necessity

A Pratt parser does not teach the pending-operator representation or the equality rule in stack reduction. A uniform pop rule mishandles right-associative power; treating prefix minus as binary reduction can consume an absent operand. Balanced parentheses alone do not establish valid syntax, and a rejected EOF can corrupt a resumable prefix after private reductions. These are separate discriminating mechanisms.

## Reasoning

State the operator/value-stack and node-reachability invariants, prove child-before-parent emission and termination, and derive equality handling from associativity. Trace unary/exponent interactions and identify how this original grammar differs from the inspected Dijkstra priority table. Establish the publication point, state ownership, error precedence and per-token strong failure guarantee. Prove linear stack actions separately from full-state staging costs and compare ISO C runtime checks with language-level types that still do not prove semantic precedence.

## Deliverables

- D1: grammar, worked traces, invariant/termination arguments and historical-source comparison.
- D2: original whole and streaming parser using the actual prior token/tree/evaluator interfaces, with ownership and failure contracts.
- D3: independent expected trees/results, malformed/budget/rollback regressions, causal compiled controls, generated-code closure and equal-contract whole/stream resource measurements.
- D4: independently assessed changed-condition construction, including the named delayed admission variant and recorded hints.

## Verification

Configure CMake, build and run CTest with explicit prerequisite roots. All three public anchors must reject the compiling learner scaffold semantically. tools/run_corpus_shunting.py executes six compiler profiles, actual prior-provider differential checks, independent grammar/exact-integer cases, target object/link audits and cost measurements; tools/check_corpus_shunting.py --self-test rejects missing or overstated evidence. The actual CLI export producer checks source separation and both explicit author-provider root forms. Pass requires correct tree fields and offsets, left/right/unary distinctions, zero/exact/insufficient budgets, malformed inputs, rollback after reductions, post-EOF rejection and separate evaluator errors. A green build or sanitizer run alone is insufficient.

## Rubric

R1 assesses exact precedence/representation derivation; R2 construction, real component reuse and failure invariants; R3 independent falsification, generated dependencies, cost and transfer. The machine contract assigns each a distinct objective and levels0–3. Passing examples is level1; level2 needs the criterion-specific argument and discriminating evidence; level3 requires independent changed-condition work. No finite assessment establishes absolute mastery.

## Hints

First keep pending operators separate from already complete subtrees. Next mark whether the next token must begin an operand, and inspect equality in the reduction comparison. Finally separate private reductions from publication and count staging copies. Record which hint was used. Complete implementation and counterexamples stay in the assessor package.

## Variants

Switch power associativity, force exact capacities, and resume a rejected prefix instead of restarting. X-T15-018-DELAYED, released after at least seven days, requires transactional token admission with a rejection after private reductions, subsequent successful continuation, original prerequisite artifacts and a whole/stream copy-cost analysis. The reference variant exists now; actual delayed independent learner performance remains pending.

## Security

This is a local bounded parser robustness investigation with synthetic strings and no external target. Inputs may be malformed or exhaust admitted storage, but arbitrary corruption of the caller-owned internal state violates the explicit precondition. Demonstrate contract violations only in original compiled defect controls. A parse error, sanitizer observation or failed assertion does not establish code execution or a vulnerability in a deployed parser.

## Validation

Required authored refinement with source-current execution, mutation, oracle, export and generated-code evidence recorded separately. Retain exact seed, bounds, commands, outputs and source hashes. Non-author review, target execution/physical measurements and independent/delayed learner attempts are distinct. Historical Pratt/other parser acceptance records and hours remain unchanged.

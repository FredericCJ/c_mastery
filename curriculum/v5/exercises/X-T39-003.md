# X-T39-003: Untagged frame construction, padding and complete FCS validation

## Prerequisites

## Problem

Implement ed_frame_build, ed_frame_parse and ed_crc32. Use DA02:00:00:00:00:01, SA02:00:00:00:00:02, payload01 02 03 and length3. Produce64 bytes with FCS, including43 zero-pad bytes; parse meaningful length3 and stored length46. Compare EtherType0800, which cannot reveal true upper payload length here. Flip a pad byte and require IO with unchanged output. Reject insufficient1517 capacity for a maximum1518-byte frame.

## Necessity

A CRC over application payload alone misses header/padding changes. FCS stripping twice truncates valid payload. EtherType does not encode payload length, and excluded tagged frames are a scope decision.

## Reasoning

A CRC over application payload alone misses header/padding changes. FCS stripping twice truncates valid payload. EtherType does not encode payload length, and excluded tagged frames are a scope decision. State exact pre/postconditions, representation invariants, lifetime/ownership, failure effects and finite operation/storage costs. Separate ISO C17 from the original model, vendor device registers, protocol semantics and physical behavior. C2x syntax acceptance is not semantic equivalence or a C23 conformance test. Explain which guarantees are runtime checked and which require programmer discipline or external verification.

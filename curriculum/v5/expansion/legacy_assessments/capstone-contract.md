## Concrete system and admitted dependencies

The original teaching system transports synthetic telemetry using the exact A5/version/sequence/length/payload/CRC-32 contract in `curriculum/guides/integrations.md`. Maximum payload is 32 bytes; maximum frame is 42 bytes. The portable C17 core owns bounded parsing, framing and accepted-message representation. Implement its CRC and byte operations from permitted primitives. Python/zlib may verify on the host; neither becomes a target dependency. The existing `struct in_stream` signed-decimal record parser is a different protocol and cannot serve as evidence for this wire contract.

Linux Profile A uses original local processes and private pipes/socket pairs/files. The firmware Profile E adapter targets a dedicated STM32F439 teaching board or an explicitly identified model. It uses fixed storage after initialization, no hosted library, heap, file descriptor or POSIX API in the core. Inspect final target objects, symbols, relocations and link map for implicit compiler/runtime helpers. Each helper must be permitted and supplied; compiler flags alone are not a freestanding dependency audit. Compare host and target builds of the same core source identities.

The reference integration workload admits at most two input sessions, three queued complete frames and one active output frame. Each input owns at most one 42-byte candidate. The active output remains owned until complete delivery or an explicit terminal discard. Thus frame-byte backing alone is at most 252 bytes: two input candidates, three queued frames and one active frame. Add actual metadata, alignment, stacks, library/runtime and adapter memory separately; 252 is not total process or firmware RAM.

Successful framing alone grants no authority. A trusted adapter supplies an authorization decision outside attacker-controlled wire bytes. The protected teaching effect is admission to the output ledger and incrementing a synthetic accepted-message counter. Unauthorized requests have no such effect. A valid CRC establishes neither authorization nor authenticity. The supplied historical wire vector is a framing case, independent of application admission policy.

## Ownership, progress and shutdown

Queue admission transfers ownership only on success. Reject-newest is the initial overload policy; rejection leaves ownership with the producer and emits an explicit rejection result. Closing input forbids new admission while draining accepted work. At terminal completion, every accepted message has exactly one disposition: delivered or explicitly discarded with reason. Maintain `accepted = delivered + discarded + queued + active`; count active as zero or one. No implicit data loss, double release or claim of rollback after externally visible bytes is accepted.

A write adapter reports a positive accepted prefix, a retryable no-progress result, or terminal failure. Validate returned counts against the offered extent before advancing a cursor. Retain only the unaccepted suffix. EINTR policy follows the actual selected Linux call contract. A synthetic zero result while bytes remain schedules a future readiness attempt rather than spinning. The exact scripted output case in `fixtures/legacy_capstones/boundaries.json` has six calls and cursor history 2,2,2,2,5,13. This deterministic script is not a native I/O scheduling guarantee.

Edge-triggered adapters keep a software ready queue when a per-turn work budget expires before EAGAIN; they do not wait for another edge while known work remains. Cache a stable logical session generation as well as its descriptor number. Registration, close, cancellation and storage reclamation must obey the selected backend's quiescence contract. A cancellation request alone never releases callback/DMA-owned storage.

## Required evidence and assessment

Modern mechanisms are selected at the actual boundary. The Linux rollback criterion consumes the learner's registered `cleanup.scope` artifact from `PR-T66-02` / `LAB-OW-04`; compare its bounded LIFO/no-reentry cleanup with the original explicit ownership-state cleanup. The short-I/O criterion compares an adapter using `errors.result` from `PR-T65-04` / `LAB-ER-08`, preserving accepted-prefix progress separately from a tagged final result. A result wrapper supplies no automatic unwinding or static ownership enforcement.

An optional asynchronous variant may consume `coro.frame` from `PR-T72-09` / `LAB-CR-27`, but its actual read target is only 1-8 bytes and its disarm operation synchronously quiesces notifications. A 42-byte frame needs bounded chunk composition; an asynchronously cancelling backend needs a different acknowledged-lifetime adapter. State these mismatches explicitly before integrating. Firmware may select the fixed tagged-result representation, but must audit the actual producer headers and selected object dependency closure; the whole hosted API, including nonlocal-control facilities, is not automatically allowed by Profile E. If a strict-target adapter is necessary, publish its exact semantic mapping and independently test both sides.

Compare chosen modern and baseline implementations under equal output, failure, ownership and scheduling contracts. Use `curriculum/v5/exercises/modern-cost-contract.md` for all applicable resource dimensions, including representation bytes, stack, allocations, callback dispatch, failure cleanup, compilation and measurement assumptions. Record non-applicability with a reason. Library/platform enforcement, runtime checks and programmer discipline must remain distinct; no Rust-style static borrowing, language exceptions or compiler-generated coroutine equivalence is claimed.

Every project-specific criterion requires D1 prediction and contract argument, D2 implementation or specified architecture/analysis artifact, D3 independent discriminating validation with raw evidence, and D4 delayed changed-condition reconstruction. For implementation tasks, record representation, operations, invariants, ownership, failure semantics and time/space costs. In design tasks, give implementable interfaces and a concrete counterexample; a diagram alone does not pass.

Evaluate each criterion independently at rubric levels 0-3. All applicable mandatory dimensions require level 2; a performance result cannot compensate for incorrect effects, ownership, dependency closure or failure handling. Record assistance and whether the delayed task was completed without the old solution at least seven days after study. Supplied visible examples establish guided evidence only. The assessor chooses a new schedule, capacity or boundary condition from the separate analysis and evaluates the causal argument, not a remembered output.

The existing `integration.linux` gate covers CVM execution to a checked page; it does not implement a telemetry event loop, complete package consumer, durable log or shutdown protocol. The existing `integration.mcu` gate covers a host ADC/filter/watchdog slice; it does not verify reset vectors, deployed bytes, real DMA ordering, peripheral electrical behavior or physical timing. Preserve both as partial evidence and execute the additional applicable criteria. Source registration, author oracle execution, learner execution, independent assessment and physical validation remain separate states.

## Security containment

All security demonstrations use the original teaching service, original adapters or learner-owned components, synthetic bytes and disposable private files. No third-party endpoint, real secret, deployed equipment, arbitrary native control transfer, host security-setting change or privilege escalation is part of this contract. Bound adversarial input and injected work. The harmless success condition is a named synthetic effect, incorrect ownership transition or model resource violation; a crash or diagnostic alone is not arbitrary execution. Every demonstrated defect requires a corrected control, ordinary valid workflow, discriminating regression and residual-authority statement.

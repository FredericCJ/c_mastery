# T58: RISC-V and AArch64 execution ports

## Purpose and outcomes

Port execution boundaries by deriving exact ABI state and distinguishing it from instruction-set architecture trap state, memory translation and board startup. Cross compilation is evidence of encoding/link compatibility; only target execution can establish the tested context behavior.

## Entry check and remediation

Reconstruct an x86 call frame and an original linker map. Derive aligned downward stack growth without unsigned underflow. Explain why a C function-call save set is insufficient for an asynchronous trap.

## Study sequence and teaching

### T58.01 — Stack extent and ABI alignment

Rounding a stack address down consumes bytes. Subtracting first and checking later can wrap the address. Public-call alignment belongs to the selected ABI; it is not an ISO C stack guarantee.

Prove result<=top-bytes, alignment and nonwrap; account for consumed padding and live stack bounds.

Misconception and counterexample: A port aligns to8 because pointers are8 bytes, violating the16-byte call boundary. A linker-defined top is not proof that subtraction stays in the reserved stack.

Investigation: Implement po_stack(top,bytes,out): require bytes<=top, subtract and round down to16-byte alignment; publish only on success. Treat integers as modeled addresses, not dereferenceable C pointers. Then build both assembly entry stubs with a private aligned stack and inspect the map.

Evidence: Change to RV32E or Thumb and derive the appropriate ABI alignment from its specification rather than inheriting16. Add a guard region and test exact exhaustion.

### T58.02 — Callee state and platform registers

An ordinary call promises selected registers survive, not every machine register. AArch64 x18 is platform-specific; treating it as universally scratch or saved is not portable. A trap may interrupt a caller with temporaries still live.

Identify which owner saves each register and why the return-address register needs protection in nonleaf callees despite its caller-saved classification.

Misconception and counterexample: A context port omits the stack pointer or assumes Arm x18 is a temporary everywhere. Explain a source-level test that can pass while this latent ABI violation remains.

Investigation: Implement po_saved(arch,reg), with arch0 RV64 integer ABI and arch1 AArch64. Report saved integer registers: RISC-V x2,x8,x9,x18..x27; Arm x19..x29 and synthetic register31 for the stack pointer. Other fields return0. Independently compare hostile-caller assembly against the declared set; exclude x18 from portable allocation.

Evidence: Add floating-point state and compare only low64 preservation of selected AArch64 SIMD registers against full vector context requirements.

### T58.03 — Argument register exhaustion

A function with nine integer arguments crosses the register-to-stack boundary on both selected64-bit ABIs. Testing only two arguments hides stack-offset and alignment errors. Aggregate and variadic arguments require different classifiers.

Derive the first stack argument relative to entry stack pointer; distinguish entry stack-pointer offsets from offsets after the callee allocates its frame.

Misconception and counterexample: A callee reads the ninth argument one slot above its defined location. All eight-register tests pass; the hostile ninth argument must falsify it.

Investigation: Implement po_arg(index,reg,offset) for the deliberately restricted nine-or-fewer uint64_t scalar interface: index0..7 maps to abstract argument registers0..7 with offset0; index8..15 maps to regUINT_MAX and stack offset8*(index-8); index>=16 rejects transactionally. The assembly adapter translates abstract registers to a0..a7 or x0..x7.

Evidence: Return a large aggregate through a hidden result pointer and show why this scalar classifier cannot simply shift the same table on every ABI.

### T58.04 — Owned context images

A context image is an owned snapshot of a defined machine-state set. Copying arbitrary register bytes is not sufficient if the architecture tag, stack lifetime or asynchronous state differs. Its representation must reject cross-architecture restoration.

Prove a save/restore preserves exactly the declared set and leaves nonowned registers untouched. State stack ownership, resume-address validity and exclusion of asynchronous FP/trap state.

Misconception and counterexample: Repair restoration of an RISC-V image as Arm by rejecting mismatched tags before any register mutation. A C struct size match does not establish semantic compatibility.

Investigation: Implement po_save(dst,arch,registers) copying only po_saved registers into a zero-filled32-slot image; reject arch>1 before mutation. po_restore validates image arch equals requested arch and copies only saved slots into a live register model, preserving others. Destination/source are disjoint. Extend assembly context switches using the same documented offsets.

Evidence: Add two task stacks and a yield-return continuation; inject stack exhaustion and duplicate resume, and compare cooperative with asynchronous preemption save sets.

### T58.05 — Signed immediates and relocation ranges

Instruction immediate fields are bit patterns interpreted with instruction-set-specific sign extension. An unsigned C shift implements bit extraction; a shift of a negative signed C operand has different rules. Alignment and range checks precede truncation.

Derive sign-extension using unsigned extraction and subtraction in a range representable by int. Separate field representability, target instruction alignment and linker relaxation.

Misconception and counterexample: Truncating an odd branch displacement silently redirects execution. A range-only check is insufficient; a passing assembler can still hide linker-added veneers.

Investigation: Implement po_sign12(raw) for the low12 bits as a mathematical signed value -2048..2047, ignoring higher bits. Implement po_branch(delta,bits,align) accepting only bits2..30, align2 or4 and aligned signed delta in [-2^(bits-1),2^(bits-1)-align]. Use this as a relocation admission oracle, not as a complete instruction encoder.

Evidence: Encode RISC-V B/J immediate bit scattering and compare with an independent assembler, then force an out-of-range AArch64 call and inspect its veneer clobbers.

### T58.06 — Trap status versus call state

Supervisor trap entry saves prior interrupt enable and disables interrupts; trap return restores it. C function-call preservation does not capture these privilege transitions. Nesting without saving the prior trap frame overwrites the interrupted state.

Draw status before entry, after entry and after return. Explain which processor state is automatic, which is software saved and why a call-return instruction cannot replace a trap return.

Misconception and counterexample: Repair stale prior-privilege state after return and a nested handler that overwrites the first saved PC. The model cannot establish interrupt controller acknowledgement behavior.

Investigation: Implement po_trap(status,from_supervisor) and po_return(status): trap records spp, copies sie to spie and clears sie; return restores sie from spie, sets spie1 and clears spp. Inputs are boolean fields; invalid input rejects without mutation. Compare the explicit model to supervisor CSR traces in a dedicated RISC-V guest.

Evidence: Port the same logical event to an AArch64 exception level and identify every register/return difference from an inspected architecture manual before implementing.

### T58.07 — Privilege-aware memory access

Page permission bits are not sufficient by themselves: access type, current privilege and supervisor user-memory policy participate in the decision. Execute permission must not silently become write permission.

Derive each access decision before dereferencing and identify omitted page-walk obligations: validity, canonical address, superpage alignment, access/dirty updates, translation synchronization and fault cause.

Misconception and counterexample: Repair a supervisor execute path that assumes `SUM` permits executing user memory. A model allow decision never grants C pointer provenance or physical access.

Investigation: Implement po_access(user_page,supervisor,sum,mxr,r,w,x,operation), with boolean flags and op0 read,1 write,2 execute. User execution rejects supervisor-only pages. Supervisor execution always rejects user pages; supervisor reads/writes user pages require sum. Read requires r or mxr&&x; write requires w; execute requires x. This models the inspected supervisor access to user memory (`SUM`) and executable-page readability (`MXR`) controls, not a complete page walk.

Evidence: Implement a bounded three-level page-table walker with synthetic tables, then compare RV64 Sv39 and the selected Arm translation regime; inspect their full manuals and record unresolved differences.

### T58.08 — Link closure and changed-target defense

A freestanding compilation can still emit runtime helpers for division, atomics, copies or stack protection. A successful object build does not establish that a reset image links or that the dependencies obey target constraints.

Distinguish declarations, emitted references, linked providers and actually exercised target paths. Explain why hosted test libraries cannot be treated as target dependencies.

Misconception and counterexample: A port links only because the developer machine supplies libgcc or libc; removing the runtime reveals a hidden helper. Report this as missing target support, not a compiler bug.

Investigation: Implement po_closure(required_mask,provided_mask) returning true exactly when every required helper bit has an approved implementation. Bits represent memcpy, division, atomic fallback and stack protector for the synthetic map. Then derive the real closure from nm/readelf/map output for both ports and record every unresolved or policy-disallowed symbol.

Evidence: Change optimization, atomics width and instruction-set architecture extensions; regenerate closure and code-size/stack evidence and explain every new helper or inline expansion.

# T74: Managed-runtime object models

## Purpose and outcomes

Implement the planned mechanisms from first principles and compare the exact C guarantees with inspected language/library/ABI contracts. Preserve accepted baseline records. Hours describe newly authored work and impose no learner deadline.

## Entry check and remediation

Revisit C17 lifetimes, checked arithmetic, callbacks and predecessor artifacts before using them across suspension or protocol transitions. An integer state is not a safety proof.

## Study sequence and teaching

### T74.01 — Pointer tags, NaN payloads and representation trust boundaries

Derive disjoint number and integer bit partitions, pointer round-trip preconditions and negative decoding; classify portable arithmetic, implementation-defined pointer mapping and explicit IEEE-format assumptions.

0x7ff9000000000042 as numeric input canonicalizes to0x7ff8000000000000; int32 minimum round-trips as -2147483648; negative zero remains0x8000000000000000. A low-bit-misaligned pointer rejects without changing output.

Investigation: Implement numeric NaN canonicalization, int32 boxing/unboxing and checked two-bit pointer tags from the exact contract. Build a discriminated-union alternative and a character-copy double bridge with verified format assumptions; never truncate a pointer into a payload. Complete {ref}`X-T74-001`.

Misconception to resolve: Alignment is not a universal grant of unused address bits.

### T74.02 — Owned binary interning and collision-safe symbol identity

Explain canonical identity versus byte equality, table ownership, embedded-NUL handling and why collisions cannot prove equality. Distinguish strong intern retention from weak symbol tables.

Bytes00,01 intern asID1 and00,02 asID2; a repeat00,01 returnsID1 even with failure injected. A new string under failure leaves used and output unchanged. NULL with length0 interns the empty string.

Investigation: Implement the eight-entry copied-string table with first-insertion IDs and atomic admission failure, then implement a hashed table with explicit collision chains or probing and transactional resizing; compare both on the same byte-string contract. Complete {ref}`X-T74-002`. After the actual pool and T66 allocator, required {ref}`X-T74-012` composes weak membership, epoch sweeping and transactional rehash: retained symbols survive movement, while dead equal bytes receive a new generation. Compare table membership with ownership explicitly.

Misconception to resolve: An intern table owns retention unless a weak contract explicitly says otherwise.

### T74.03 — Immutable hidden classes and reusable property transitions

Derive ordered shape records and transition identity, distinguishing an equal property set from an equal storage layout. State ownership of shapes, receiver fields and transition caches.

Objects built with keys1 then2 share shape; keys2 then1 have different offsets and a different shape. Updating an existing key changes only its value; adding a fifth distinct key returns FULL unchanged.

Investigation: Implement immutable four-field shapes in a16-shape arena, transition reuse by parent-plus-key and atomic capacity failure. Add a dictionary-mode alternative for deletion and compare its explicit lookup/invalidation contract. Complete {ref}`X-T74-003`. After X-T74-008, required {ref}`X-T74-013` adds shape metadata record retirement, readonly/accessor attributes, own-property deletion and actual strong prototype edges. Acquire the replacement shape metadata record before publishing fields; a weak cache owns no shape metadata record reference.

Misconception to resolve: Equal key sets can have different offsets.

### T74.04 — Monomorphic and polymorphic inline-cache guards

Explain a cached lookup handler versus a cached value, and prove why owner, shape and property key jointly determine this model offset. Bound the cases in which immutable shapes remove invalidation needs.

After caching key1 at offset0 in layout[1,2], key1 in layout[2,1] must read offset1. Looking up key2 in the first layout must read20, not the cached key1 value10; the third distinct pair selects generic mode.

Investigation: Implement a two-entry polymorphic cache with monomorphic first state, sticky generic fallback, owner reset and current-receiver field loads. Compare always-generic lookup with the same output and missing-key effects. Complete {ref}`X-T74-004`. Required later {ref}`X-T74-013` demonstrates that a live old holder can still be wrong after a prototype change. Temporarily root receiver and holder across a mutating getter, preserve its staged result, and invalidate old resolution. A failed callback preserves immediate output but does not undo its committed mutations.

Misconception to resolve: A successful C bounds check does not prove the cached offset means the requested property.

### T74.05 — Incremental marking and root/store write barriers

Derive the no-black-to-white-edge invariant and distinguish incremental mutation between steps from concurrent mutation. Explain floating garbage and why root updates need their own barrier.

With live1..4 and roots1,2, one step blackens1. A subsequent1→3 store grays3, adding root4 grays4, and the remaining three scans finish with all four black. Budget0 performs zero scans.

Investigation: Implement begin, bounded scan steps, black-source stores and root insertion for the16-object graph. Build an explicit gray-worklist alternative with a capacity proof, and add immediate quiescent sweeping under a stated allocation policy. Complete {ref}`X-T74-005`.

Misconception to resolve: Finishing a snapshot does not authorize later mutation followed by an old sweep.

### T74.06 — Semispace evacuation, forwarding and promotion failure

Derive identity preservation under copying, forwarding uniqueness and the old-to-young root obligation. Explain the empirical generational hypothesis separately from the correctness of a minor collection.

Roots reference young object3, which reaches2; an old object also reaches2. The first collection copies exactly two cells and preserves sharing; the second promotes both. Old-capacity1 on that second collection returns FULL with original heap and copied output unchanged.

Investigation: Implement two young semispaces with first-survival aging, second-survival promotion, complete root/edge rewriting and atomic capacity failure. Replace the whole-state transaction copy with a preflight or rollback design while retaining the same failure contract. Complete {ref}`X-T74-006`.

Misconception to resolve: Failure after partial copying must not publish half-relocated roots.

### T74.07 — Card marking and conservative remembered roots

Derive old-to-young completeness and distinguish safe false positives from unsafe false negatives. Explain why overwriting one field cannot clear a card shared by another field.

Old object3 field1→young5 dirties card1; object2 field0→young7 shares it. Removing the first edge keeps the card dirty and root7 present; removing the second clears it after one four-field rescan.

Investigation: Implement two-object cards over eight old objects, store marking and dirty-card rescanning with retained young edges. Integrate it with the nursery through an explicit adapter, retaining full-old scanning as an independent reference. Complete {ref}`X-T74-007`.

Misconception to resolve: A clean card is a correctness assertion.

### T74.08 — Handle-based compaction and forwarding aliases

Distinguish object identity, handle identity and physical slot, and derive when outstanding raw borrows prohibit movement. Explain forwarding for aliased handles and nested handle fields.

Live physical slots2 and4 compact to1 and2. Two handles to slot2 both become1; a handle to4 becomes2, while payload fields naming handle3 retain that identity. Any outstanding borrow rejects unchanged.

Investigation: Implement stable physical packing of live payloads with old-slot forwarding and updating every handle alias, then add a pinned-object alternative with explicit fragmentation costs and a generation policy for reused handles. Complete {ref}`X-T74-008`.

Misconception to resolve: A borrow remains dangerous even if the current test never dereferences it after moving.

### T74.09 — Ephemeron fixed points and staged finalization

Derive conditional reachability of ephemeron values and why a value-to-key cycle cannot bootstrap liveness. Separate weak clearing, finalizer retention, resurrection and deterministic external-resource release.

Pairs2→3 then1→2 with strong root1 retain all three only after a fixed point. A pair4→5 whose value5 points back to key4 dies without an external key root. A queued object clears weak references before one finalizer event and may be rooted before the next collection.

Investigation: Implement repeated ephemeron closure, weak clearing before finalizer retention, an explicit pending queue and at-most-once finalization identities. Build a synthetic finalizer driver that may resurrect an object and compare the chosen policy with Lua and CPython. Complete {ref}`X-T74-009`.

Misconception to resolve: Finalization policy is observable and differs between runtimes.

### T74.10 — Trial deletion for reference-counted cycles

Derive residual external counts for a candidate subgraph, then prove why residual zero alone does not imply garbage. Preserve true counts while detecting a candidate reachability closure.

A1↔2 cycle with true counts1,1 and no external root is reclaimed. Counts2,1 mean an external reference protects1 and therefore2, even though2 has residual zero. An outside-candidate reference conservatively protects its target.

Investigation: Implement copied trial counts, candidate-internal edge subtraction, rescue from positive residual seeds, and reclamation with decrements to surviving targets. Integrate ordinary zero-count cascading separately and compare with a tracing oracle. Complete {ref}`X-T74-010`.

Misconception to resolve: Candidate selection affects completeness and work, not permission to free a reachable object.

### T74.11 — Precise root maps and derived-reference relocation

Derive complete root maps over initialized interpreter slots, distinguishing scalar lookalikes, duplicate copies and derived base-plus-offset references. Explain compiler statepoints versus manually maintained C roots.

Two root slots with base2 offsets0 and8 and length8 relocate to base5, while scalar2 stays2. A map omitting one tagged root rejects; offset9 rejects the entire frame unchanged. One-past offset8 may be represented but not dereferenced.

Investigation: Implement transactional map validation and relocation of every root copy, preserving scalar slots and one-past offsets. Integrate actual runtime.vm roots and temporaries through ADAPTERS.md, then construct and inspect an LLVM statepoint experiment as a separate compiler-dependent artifact. Complete {ref}`X-T74-011`.

Misconception to resolve: A stack-looking integer is not automatically a pointer.

## Precise vocabulary

**tagged pointer:** An integer representation carrying a tag that must be removed under a documented pointer-mapping contract before recovering a live pointer.

**NaN boxing:** A value encoding that reserves selected floating-point NaN bit patterns for other tags and payloads under explicit representation assumptions.

**string interning:** Canonicalizing equal byte sequences into a shared identity whose lifetime and retention belong to an owning table.

**hidden class:** An immutable shape identity representing an object's ordered property layout, distinct from the set of property names alone.

**shape transition:** A mapping from an existing layout and structural mutation to the resulting layout identity.

**monomorphic inline cache:** A lookup-site cache specialized to one guarded receiver layout and operation.

**polymorphic inline cache:** A bounded list of guarded receiver-layout handlers used before a generic lookup fallback.

**tri-color invariant:** A collector invariant preventing scanned black objects from acquiring unrecorded references to unmarked white objects.

**write barrier:** An operation coupled to mutation that preserves a collector invariant or records references requiring later processing.

**semispace:** One of two regions whose source and destination roles alternate during copying collection.

**forwarding address:** A record connecting an object old location to its new location so aliases can be rewritten consistently.

**promotion:** Moving a surviving young-generation object into an older generation under an explicit policy.

**remembered set:** Metadata recording references across a collection boundary so omitted regions need not be fully traced.

**card marking:** Recording potentially relevant writes at a coarser storage-region granularity, allowing conservative rescanning.

**ephemeron:** A conditional association whose value becomes reachable only when its key is independently reachable.

**finalization resurrection:** Making an object reachable again while processing a finalizer, requiring a defined later-reclamation policy.

**trial deletion:** Computing candidate external reference counts and reachability using temporary counts before deciding which cycles are collectible.

**precise root map:** Metadata identifying exactly the live reference-bearing locations at a permitted collection point.

**derived reference:** A reference described by an allocation base and an offset, so relocation can preserve its relation to the allocation.

**safepoint:** A designated execution state at which the runtime can enumerate and, where supported, update all live references required by collection.

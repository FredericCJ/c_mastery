# T12: Standard-library semantics and implementation literacy

## Purpose and outcomes

Learn library families by contract and implementation boundary. stdlib.h is one header, not the whole standard library. The breadth is organized into five laboratories: header/format inventory, bytes/text, allocation/conversion, streams/environment, and algorithm/source literacy. Selected routines receive deep implementation work; the remaining families receive explicit contract comparison and bounded probes.

## Entry check and remediation

Pass T03 memory/lifetime reasoning and T04 checked-size/conversion boundaries. Read the allocation/dependency profiles first. Before a library call, write valid argument domains, ownership, error result and effects; if those cannot be stated, inspect that contract before executing a speculative test.

## Component progression

**Library contracts as implementation experiments.** Separate the public contract, local implementation policy and your independent oracle. Exercise zero length, overlap, locale, failure and execution-environment assumptions only where admitted.

Before implementation, predict this discriminating case: **Two implementations disagree because the supposed test input violates one interface's precondition.** Carry its evidence into the projects below. Reuse one accepted component revision; new projects charge their new mechanism or experiment, not a second implementation of the old one.

Follow the [project route](../guides/project-route.md) for ordering. Domain numbers are reference categories. The [laboratory](../guides/laboratory.md) and [shared contract cards](../guides/component-contracts.md) separate automatic execution from reasoning, transfer and physical observations.

## Study sequence and teaching

### T12.01 — Library and header taxonomy

Inventory headers by facility and edition: declarations/types/macros can be compiler-provided while calls require linked support. ISO, POSIX, optional annex and implementation extensions are separate authorities. A freestanding build has a different promised environment from a hosted program, even if both can include a header.

Investigation: Create an edition-tagged header/family matrix and classify a deliberate mix of ISO, POSIX and extension interfaces.

Misconception to resolve: Removing stdlib.h does not remove the standard library or its linked implementation.

Observable evidence: A facility/authority/dependency inventory with compile-only versus linked evidence. Evidence is developed in {ref}`PR-T12-01`.

### T12.02 — Types, limits, and feature interfaces

Limits and format macros connect abstract types to actual ranges and variadic types. Use %zu for size_t and the appropriate inttypes macros for available fixed-width families. Feature macros describe a selected environment; optional typedefs and headers need detection. Declarations alone do not demonstrate runtime support.

Investigation: Build a limit/format report and compile negative mismatched-format examples separately.

Misconception to resolve: A type with the right measured width may still have a different required variadic format.

Observable evidence: Type/range/format mapping and compiler/header/library layer records. Evidence is developed in {ref}`PR-T12-01`.

### T12.03 — Memory operations

memcpy requires nonoverlap; memmove gives overlap-safe copy semantics as if through temporary storage. Both still require valid object/range arguments. Copying representations is not arbitrary typed construction. A zero count does not invent a universal permission to pass null to every library function.

Investigation: Write checked copy/move wrappers with explicit zero-length policy and compare overlapping ranges through a byte-array oracle.

Misconception to resolve: The size argument alone cannot rescue invalid pointer arguments or incompatible typed use.

Observable evidence: Range/overlap proofs, exact moved bytes and separately analyzed invalid calls. Evidence is developed in {ref}`PR-T12-02`.

### T12.04 — Byte strings and bounded buffers

A byte array, a null-terminated string and a pointer/length view have distinct invariants. Track capacity, logical length and termination separately. strncpy may pad and may fail to terminate; snprintf reports required output length. A wrapper should choose reject, truncate or grow explicitly instead of blending their policies.

Investigation: Implement bounded append and conversion from a view to a terminated string, including embedded-zero input.

Misconception to resolve: A buffer capacity is not its current string length, and bounded spelling does not guarantee safe semantics.

Observable evidence: Exact content/length/termination results for empty, exact-fit, truncated and embedded-zero cases. Evidence is developed in {ref}`PR-T12-02`.

### T12.05 — Character and locale handling

ctype inputs must be EOF or values representable as unsigned char. Convert a potentially negative plain char before classification, without confusing it with EOF. Locale affects byte classification and case conversion; neither supplies Unicode character properties for arbitrary multibyte text.

Investigation: Classify byte inputs under a named locale and demonstrate the safe unsigned-char boundary.

Misconception to resolve: A UTF-8 byte is not independently a Unicode character for ctype.

Observable evidence: Domain checks, locale identity and a byte-versus-code-point explanation. Evidence is developed in {ref}`PR-T12-02`.

### T12.06 — Multibyte and wide-character conversion

Restartable conversion carries mbstate_t across chunks. mbrtowc distinguishes completed null, completed character, incomplete input and encoding failure; after failure the state needs a deliberate recovery policy. wchar_t representation and locale encoding are implementation choices, whereas RFC UTF-8 defines interchange bytes.

Investigation: Feed a character across chunk boundaries, handle invalid bytes and bounded output, then compare with a strict UTF-8 validator.

Misconception to resolve: Each input chunk is not automatically a complete independently decodable string.

Observable evidence: State/result traces, invalid recovery and a locale/UTF-8 boundary table. Evidence is developed in {ref}`PR-T12-02`.

### T12.07 — Allocation API semantics

malloc acquires uninitialized storage, calloc initializes representation bytes, and realloc has distinct success/failure lifetime transitions. free releases owned allocated storage. Alignment APIs and zero-size behavior need edition-specific contracts; define empty logical objects without relying on ambiguous resize behavior.

Investigation: Write an allocation adapter with failure injection, nonzero resize and explicit empty release; compare aligned storage obligations.

Misconception to resolve: All-zero bytes do not universally initialize every typed value, and failed nonzero resize must not lose its owner.

Observable evidence: Allocation/lifetime ledger, checked sizes and exactly-once cleanup under each failure. Evidence is developed in {ref}`PR-T12-03`.

### T12.08 — Integer and floating conversion

strto functions expose conversion progress and range failure; a zero result alone is ambiguous. Clear/check errno for the documented range condition, inspect endptr, validate signs/bases and apply the application’s trailing-data policy. Locale affects floating parsing. C23 binary-prefix behavior must not be silently assumed in a C17 suite.

Investigation: Build strict decimal-integer and C-locale floating parsers around explicit token boundaries.

Misconception to resolve: atoi-style conversion cannot provide the same error/progress contract as a checked strto wrapper.

Observable evidence: No-conversion, trailing-junk, range, sign and locale tests with unchanged outputs on failure. Evidence is developed in {ref}`PR-T12-03`.

### T12.09 — Formatted output

Formatted output is a variadic protocol: argument types and length modifiers must match exactly. Width and precision alter presentation, not the source type. snprintf returns required characters excluding the terminator, or a negative encoding error; check negativity before converting to size_t, then compare with capacity.

Investigation: Implement bounded diagnostic formatting with a required-size result and a declared truncation policy.

Misconception to resolve: A nonnegative snprintf return does not necessarily mean the full output fit.

Observable evidence: Format/type audit, zero-capacity sizing, exact-fit/truncation and encoding-error policy. Evidence is developed in {ref}`PR-T12-01`.

### T12.10 — Formatted input

scanf reports successful assignments, not a complete parse proof. Field widths limit selected conversions but must account for destination storage and termination. Matching failure, input failure/EOF and leftover characters are different states. A line-plus-token-plus-strto design often gives clearer boundaries.

Investigation: Compare a width-bounded scanf example with an explicit parser on malformed, ambiguous and leftover input.

Misconception to resolve: A conversion count of one does not prove the entire record was accepted.

Observable evidence: Destination-size audit, count/EOF distinctions and exact remaining-input observations. Evidence is developed in {ref}`PR-T12-03`.

### T12.11 — Streams and buffering

FILE owns a stream state with orientation, buffering, position and indicators. EOF is a failed read condition to inspect afterward, not a prediction that the next read will fail. Update streams have required transitions between reading and writing. Closing ends FILE lifetime; fflush is not a universal storage-durability guarantee.

Investigation: Build a small stream copier and update-stream experiment with explicit transitions, then contrast FILE with an OS descriptor.

Misconception to resolve: while(!feof(f)) is not a correct read loop, and a descriptor is not interchangeable with FILE.

Observable evidence: Read-result/error/EOF traces, cleanup and documented flush/position limitations. Evidence is developed in {ref}`PR-T12-04`.

### T12.12 — Searching, sorting, and random numbers

A comparator must define consistent ordering without subtraction overflow. qsort specifies sorted results, not a universal stable algorithm or allocation profile; bsearch needs the compatible sorted order. rand supplies a reproducible pseudorandom facility under a chosen implementation, not security-sensitive entropy.

Investigation: Use a relational comparator, test duplicates/extremes, and compare pinned sorting sources plus a deterministic nonsecurity generator.

Misconception to resolve: The same qsort signature does not imply the same algorithm, stability or hidden effects.

Observable evidence: Comparator properties, sorted/search checks and a randomness-purpose classification. Evidence is developed in {ref}`PR-T12-05`.

### T12.13 — Mathematics and floating environment

math, complex, type-generic math and fenv cover different layers. Domain/range signaling and accuracy depend on facility and target assumptions; math_errhandling identifies supported reporting mechanisms. Complex and type-generic calls still need typed expectations and numerical criteria from T04.

Investigation: Map one scalar, complex and generic operation, probe a domain/range case and record observed errno/exceptions where supported.

Misconception to resolve: A returned finite value or nominal accuracy observation does not establish every exceptional contract.

Observable evidence: Facility map, supported reporting probes and justified independent reference tolerances. Evidence is developed in {ref}`PR-T12-05`.

### T12.14 — Time and execution environment

Calendar time, process CPU time and elapsed monotonic time measure different quantities. ISO time representations and precision are implementation-dependent; a Linux elapsed-time adapter is a separate contract. Environment strings have ownership/lifetime hazards, termination handlers have ordering rules and system executes an implementation-defined command interface.

Investigation: Compare time measurements, copy an environment value under a documented protocol and inventory termination/system effects.

Misconception to resolve: clock is not universally elapsed wall time, and getenv results are not caller-owned heap allocations.

Observable evidence: Measurement-role table, environment lifetime notes and a declared effects/dependency ledger. Evidence is developed in {ref}`PR-T12-04`.

### T12.15 — Signals, nonlocal jumps, and thread facilities

ISO signals offer a restricted handler environment distinct from POSIX signal contracts. setjmp/longjmp transfers control without automatic resource cleanup and can leave modified nonvolatile local state indeterminate. Thread and atomic interfaces must be located before assuming Linux behavior; language order is not the same as a platform API.

Investigation: Analyze a nonlocal-jump cleanup defect, design a restricted signal flag policy and inventory selected thread/atomic contracts.

Misconception to resolve: A jump is not exception unwinding, and a signal handler is not an ordinary callback.

Observable evidence: Control/lifetime trace, allowed-handler operations and bounded thread/runtime capability evidence. Evidence is developed in {ref}`PR-T12-04`.

### T12.16 — Implementation source literacy

Source reading begins at a pinned public entry point, then follows helpers and configuration. Compare glibc 2.41 and musl 1.2.5 qsort entries with their public sorting contract; an internal algorithm is not an API guarantee. Picolibc 1.8.10 supplies a concrete embedded comparison: tinystdio console streams use application-defined FILE objects and getc/putc callbacks, with an optional flush callback. Enabling POSIX-backed fopen/fdopen adds malloc/free and open, close, read, write and lseek requirements. Disabling posix-io narrows this file-I/O boundary; it does not prove the entire library allocation-free. Static inspection supports hypotheses, while runtime allocation or stack claims need separate evidence.

Investigation: Navigate the specified pinned qsort entries and compare the two specified Picolibc console/file-I/O configurations, distinguishing public guarantees from internal choices.

Misconception to resolve: Finding no malloc spelling in one function does not prove the reachable call graph allocation-free, and a library configuration option is not evidence that its target backend has been implemented.

Observable evidence: Pinned source/call-flow map, two-row Picolibc configuration/backend inventory and explicitly limited effect claims. Evidence is developed in {ref}`PR-T12-05`.

## Mastery gate and feedback

Given a library call, state argument domains, ownership, error and effects before using it. Demonstrate bounded parsing/text behavior, distinguish EOF from failure, and compare sorting implementation choices without promoting them to API guarantees. The five dossiers cover all families, while implementation depth remains explicit.

For independent study, make predictions before execution, compare an independent oracle, inspect one counterexample and defend the result aloud or in a short recorded review. Link each original objective to a specific artifact; use {ref}`guide-assessment` to score it. A failed gate requires a minimized cause, a corrected model and a fresh regression, not repeated nominal runs.

## Consolidation and transfer

Tighten one reusable component from profile A to B or C after a delay. Replace only the needed mechanism and audit transitive effects; do not equate avoiding a header with avoiding linked support.

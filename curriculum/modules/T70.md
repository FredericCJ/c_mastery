# T70: Data-oriented layout and persistent structures

## Purpose and outcomes

Derive layout from access patterns and persistence from observable snapshots. Implement structure of arrays (SoA), array of structures (AoS), small-buffer optimization (SBO), single-instruction multiple-data within a register (SWAR), an entity-component system (ECS) and a hash array mapped trie (HAMT) from ordinary C objects. A directed acyclic graph may share text subtrees without duplicating storage. These names do not establish safe ownership or universal speed.

## Entry check and remediation

Reconstruct checked arithmetic, typed object lifetime, pool generation and array allocation contracts without consulting a reference implementation. Diagnose a stale owner and an allocation-failure prefix. If the explanation relies on a successful run as proof, revisit X-T03-003, X-T03-005 and X-T04-001 before proceeding. Pin imported artifacts and repeat their critical recall.

## Study sequence and teaching

### T70.01 — Hot and cold columns with transactional numeric updates

A hot column contains a field visited frequently by the stated workload, such as position or velocity during the update loop; the classification can change when the workload changes. The label data-oriented design does not choose a layout. Access patterns, overflow semantics and conversion/identity costs determine whether splitting fields helps; removing overflow checks to obtain SIMD changes the correctness contract.

Implement d_columns_step for4 parallel typed arrays under the shared contract, then implement an equal-contract AoS adapter and generate both declarations and field visitors from one C17 field-list definition. Inputs are count0–4, int32 positions/velocities, ticks0–10 and cold labels. Outputs are updated positions or a rejection preserving every position. Never update a prefix before discovering a later overflow. Use the supplied4-record model for exhaustive small-range tests and an explicitly allocated large synthetic population for measurements; large-population code must retain the same numeric contract.

Supplied artifacts: labs/dod/include/dod.h, deliberately incomplete labs/dod/src/dod.c, executable anchors, fixture PR-T70-01.json and the shared CONTRACTS.md. Expected example: Positions[1,2,3,4], velocities[2,-1,1,0], ticks2 produce[5,0,5,4] with cold labels unchanged. If the last position is INT32_MAX and velocity1, ticks1 rejects without changing even the first position.

Observable evidence: complete {ref}`X-T70-001` D1–D4 and each objective-specific criterion. Its independent oracle must recompute the result from the mathematical model. A compiled anchor cannot establish the unexecuted extension.

### T70.02 — Inline bytes, allocator failure and explicit relocation

The small-buffer owner contains inline bytes or owns one separately allocated byte buffer. Its spill transition must allocate and copy successfully before publishing the external storage state; an allocation failure must retain the old inline value and ownership. Small-buffer optimization introduces two ownership regimes and an often-hidden object-type problem. An address satisfying alignment is not proof that a declared unsigned-char array may be accessed through any desired struct pointer.

Implement the DSmall operations: init, append, truncate, compact, move, reset and borrowed data access. Inline capacity16 and maximum128 are part of the shared contract. Supply a fixed-capacity, typed byte-array allocator adapter that records requests and fails each requested allocation in turn; a host malloc adapter is an additional test only. Construct a separate fixed-capacity16-byte variant that always rejects spill. Compare its contract and owner size with DSmall. No string terminator, generic typed placement, automatic copy constructor or raw-struct move is supplied.

Supplied artifacts: labs/dod/include/dod.h, deliberately incomplete labs/dod/src/dod.c, executable anchors, fixture PR-T70-02.json and the shared CONTRACTS.md. Expected example: Appending16 bytes performs no allocation. A failed17th byte preserves length16 and all bytes. Successful spill followed by move leaves the source empty and transfers exactly one allocation. Truncating to8 and compacting frees that allocation once; resetting both owners performs no second free.

Observable evidence: complete {ref}`X-T70-002` D1–D4 and each objective-specific criterion. Its independent oracle must recompute the result from the mathematical model. A compiled anchor cannot establish the unexecuted extension.

### T70.03 — Four saturating byte lanes without cross-lane carries

Each packed arithmetic lane represents an independent unsigned byte within the word. Lane saturation clamps that lane's mathematical sum to255 without carrying into a neighbor. Ordinary word addition is not lane-wise addition; carries and saturation require a proof. A benchmark over only identical lanes can miss a carry leaking into a different neighboring lane.

Derive and implement d_swar_add for four unsigned8-bit lanes inside uint32_t using shifts, masks and unsigned arithmetic only. No intrinsics, scalar per-lane loop in the assessed implementation or signed overflow is allowed. A separate scalar oracle extracts each lane, adds in unsigned int and clamps to255. The packed numerical lane convention is independent of how a uint32_t is stored as bytes.

Supplied artifacts: labs/dod/include/dod.h, deliberately incomplete labs/dod/src/dod.c, executable anchors, fixture PR-T70-03.json and the shared CONTRACTS.md. Expected example: 0xff00ff00 plus0x01010101 produces0xff01ff01. A255+1 low lane must saturate without adding1 to the adjacent lane. Every pair of byte inputs must agree with min(255,a+b).

Observable evidence: complete {ref}`X-T70-003` D1–D4 and each objective-specific criterion. Its independent oracle must recompute the result from the mathematical model. A compiled anchor cannot establish the unexecuted extension.

### T70.04 — Stable typed slots, dense iteration and finite identity

Segmented element storage keeps payload objects in stable pages while a separate index controls iteration. The dense/rank inverse must hold in both directions for every live slot: the rank identifies its dense-list position, and that position contains the same slot. Dense iteration and stable addresses can coexist only by choosing what moves. Many sparse-set bugs repair one mapping but forget the inverse; generation counters eventually wrap unless exhaustion is part of the contract.

Implement DSparse add/get/remove with4 typed slots, a dense ID list, rank inverse, owner-bound handles and generations1–3 followed by retirement. Derive a segmented extension with2 pages of4 slots allocated through a caller-supplied page table: page addresses remain stable while the table can move. Give the extension a complete acquire/release and exhaustion contract before implementing it. Contrast a pointer to a stable live slot with a handle that must be revalidated after deletion.

Supplied artifacts: labs/dod/include/dod.h, deliberately incomplete labs/dod/src/dod.c, executable anchors, fixture PR-T70-04.json and the shared CONTRACTS.md. Expected example: After inserting11,22,33 and removing22, the dense list contains the slots for11 and33; rank of33 is1. The removed handle rejects and preserves output. Removing/reusing slot0 through generation3 retires it; further insertion must choose another slot or report full.

Observable evidence: complete {ref}`X-T70-004` D1–D4 and each objective-specific criterion. Its independent oracle must recompute the result from the mathematical model. A compiled anchor cannot establish the unexecuted extension.

### T70.05 — Archetype migration with capacity admission and row repair

An archetype table groups rows having the same component set, while entity identity remains distinct from a row's current location. Migration changes that location and can move another entity during source-row removal. An archetype label does not teach migration atomicity or query invalidation. Deleting the old row before discovering a full destination loses an entity even though the numerical component code is correct.

Implement DEcs with4 entity IDs, component masks1(position),2(velocity),3(both), and2 rows per archetype. Set creates, replaces or migrates an entity; step updates only the both-component table. Build a query adapter for required/excluded masks and a structural version counter for cached table selection. Specify deletion/reuse as a separate generation-bearing extension, never silently reuse an ID while old views survive. All structural edits happen outside an active iteration borrow.

Supplied artifacts: labs/dod/include/dod.h, deliberately incomplete labs/dod/src/dod.c, executable anchors, fixture PR-T70-05.json and the shared CONTRACTS.md. Expected example: Create entity0/1 in mask1 and entity2 in mask3. Moving0 into mask3 succeeds and moves1 to row0 of mask1. Moving1 into now-full mask3 rejects without deleting it. Step changes both-component positions30,10 with velocities2,1 into32,11; a later overflow preserves the whole table.

Observable evidence: complete {ref}`X-T70-005` D1–D4 and each objective-specific criterion. Its independent oracle must recompute the result from the mathematical model. A compiled anchor cannot establish the unexecuted extension.

### T70.06 — Path copying, zipper contexts and retained-version costs

A persistent collection version is identified by a root whose reachable logical value remains unchanged after later updates. The retained root set determines which shared nodes are still needed, so allocated node count alone cannot establish reclamation eligibility. Cheap root copying shifts costs into path cloning and retained history. Const qualification does not freeze aliases, and a path-copy algorithm that silently mutates one old node breaks every older version sharing it.

Implement the8-cell persistent binary trie using a64-node typed arena. Root0 denotes all zeros. An update clones one leaf and three ancestors, returning a new root; old roots remain readable. Add an explicit zipper with a focus plus three ancestor/direction crumbs and reconstruct by path copying. The zipper may borrow a live arena and immutable root, but never retain raw pointers across arena reset. Implement a reachability census over a chosen root set and compare region reset with a separately specified reference-count reclamation design, including rollback if construction fails.

Supplied artifacts: labs/dod/include/dod.h, deliberately incomplete labs/dod/src/dod.c, executable anchors, fixture PR-T70-06.json and the shared CONTRACTS.md. Expected example: Updating root0 cell3=17 creates4 nodes; updating that root cell6=29 creates4 more. The first root still reads cell6=0. Each of the four allocation-failure ordinals rejects with the output root and previously reachable nodes unchanged.

Observable evidence: complete {ref}`X-T70-006` D1–D4 and each objective-specific criterion. Its independent oracle must recompute the result from the mathematical model. A compiled anchor cannot establish the unexecuted extension.

### T70.07 — Bitmap rank, full-hash collisions and persistent map updates

Bitmap child rank is the number of occupied branches below a selected branch bit; it maps a logical branch to its position in the compact child array. An insertion before that position shifts stored children, so lookup cannot use the raw hash chunk as an array index. A HAMT description hides three distinct equivalences: shared prefix, identical hash and equal key. Confusing them overwrites unrelated values. Sparse child packing also makes insertion rank as important as lookup rank.

Implement DHamt for keys0–31 with hash(key)=key&15, two2-bit levels, compact bitmap-indexed children, and equality-checked two-entry terminal collision buckets. Empty root0 and64 typed nodes bound the model. Update copies leaf and ancestors; lookup returns D_STALE for absence. Add a deletion operation with an explicit policy for empty internal nodes, and a tree-to-flat-map oracle. Do not use hash equality as key equality. Discuss extension to arbitrary-length keys by defining hash/equality contracts and ownership before substituting a hash function.

Supplied artifacts: labs/dod/include/dod.h, deliberately incomplete labs/dod/src/dod.c, executable anchors, fixture PR-T70-07.json and the shared CONTRACTS.md. Expected example: Keys1 and17 deliberately share the full4-bit hash but retain values10 and20. Updating17 to88 in a new root leaves20 in the old root. Inserting key0 changes bitmap rank and must not make key1 unreachable. Each of3 allocation failure points preserves old snapshots.

Observable evidence: complete {ref}`X-T70-007` D1–D4 and each objective-specific criterion. Its independent oracle must recompute the result from the mathematical model. A compiled anchor cannot establish the unexecuted extension.

### T70.08 — Shared text DAGs, editing alternatives and coordinate meaning

A rope concatenation node preserves left-to-right logical order and caches the sum of child lengths even when both edges share a child. A rope balance bound must constrain depth relative to logical size before logarithmic indexing can be claimed; repeated one-sided concatenation does not supply that bound. The text coordinate domain in this exercise is bytes, so a byte offset is not automatically a character, grapheme or display-column index. Ropes trade copying for metadata, traversal and retained sharing. Text-editing structures are not interchangeable until coordinate system, ownership, capacity, snapshot and failure contracts agree.

Implement the DRope leaf/concat/flatten anchor with64 typed nodes, leaf length0–8 and maximum expanded length128. A rope is an ordered shared directed acyclic graph: concatenating a root with itself must duplicate its logical bytes without mutating the shared leaf. Extend it with byte-index lookup and split, specifying allocation rollback and balancing separately. Implement two equal-byte-contract editing alternatives for a128-byte document: a gap buffer with explicit gap bounds and a piece table whose immutable original/add buffers are caller-owned and whose pieces are offset/length triples. Apply the same edit scripts to all three and a flat byte-list oracle. No Unicode scalar, grapheme or line-number equivalence is implied by byte offsets.

Supplied artifacts: labs/dod/include/dod.h, deliberately incomplete labs/dod/src/dod.c, executable anchors, fixture PR-T70-08.json and the shared CONTRACTS.md. Expected example: Leaves ab and cd concatenate to abcd; concatenating that root with itself flattens to abcdabcd while the ab leaf remains ab. Capacity7 rejects an8-byte flatten without touching the output canary or written. An empty leaf returns root0.

Observable evidence: complete {ref}`X-T70-008` D1–D4 and each objective-specific criterion. Its independent oracle must recompute the result from the mathematical model. A compiled anchor cannot establish the unexecuted extension.

## Reading guidance

The five primary records contain bounded inspected passages, not a claim to have read entire manuals. LLVM supplies specific container comparisons, im supplies persistent collection semantics, Flecs supplies archetype grouping, and the rope paper supplies ordered sharing and depth/balance analysis. SWAR is an original derivation from the already inspected unsigned arithmetic and shift rules in R-B01-N1570-OBJECT-ARITH; LLVM is not a SWAR authority. GNU gap-buffer pages were inaccessible; the original gap/piece contracts must not be presented as an inspection of those manuals.

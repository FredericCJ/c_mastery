This domain extends the completed T14/T15/T18 portfolio: full containers, sorting, matching and graph algorithms are reused. New work consists of narrow kernels, certificates and adapters, not a second complete implementation. ## Study sequence and teaching

### T36.01 — Specifications, invariants and resource bounds

A specification relates initial and final observations; an invariant relates every intermediate state to that specification. A decreasing measure supplies a separate termination argument. In the original Euclid trace `(1071,462) → (462,147) → (147,21) → (21,0)`, replacing `(a,b)` by `(b,a mod b)` preserves common divisors because `a=q*b+r`. The positive second operand decreases; the last nonzero first operand is 21. Three remainder operations is an exact count for this trace, not a bound for every input.

Choose the counted primitive before giving a complexity claim. A RAM comparison count ignores instruction encoding and caches; an expected hash cost requires a distribution; amortized cost covers an entire operation sequence. In a reused doubling vector starting at capacity 1, eight appends write eight new values and copy 1+2+4 old values: fifteen payload writes total, even though the capacity 4→8 append alone costs five. That sequence bound is not a promise that each append is constant-time. Charge queue failure checks as well as successful operations in {ref}`PR-T36-01`. For a capacity-three queue, a fourth insertion changes neither payload nor count. A sorted prefix alone is too weak: the transformation `[2,1] → [1,1]` is sorted but loses a value. Strengthen it with a multiset relation. Submit the first invalid transition of that mutation, a Euclid preservation/progress derivation and the queue cost ledger. Passing the final-output test alone does not establish an invariant.

### T36.02 — Arrays, links and frontier representations

An index is a representation choice, not an address. With three actual eight-byte records, payload offsets are 0, 8 and 16; addressability still requires that the corresponding objects and lifetime exist. A node-slot queue carries next links and a free-list invariant in addition to logical FIFO order. Its live payload can equal a circular array's while metadata and traversal costs differ. The operations put 11, put 22, take, put 33, put 44, failed put 55, take leave `[33,44]` in either representation. A contiguous ring may wrap physically even though its logical sequence remains consecutive.

Replay that sequence through the completed T14 implementations. Annotate head/tail/count, occupied node slots, ownership and failed-operation state. Reuse T18 contracts: a typed pool is an actual array of the right element type; a portable byte arena supports byte operations/copy in-out; genuine allocated storage has a different effective-type rule. Merely aligning `unsigned char[]` does not authorize an arbitrary record lvalue. A storage-policy change preserves logical order only if no stale pointer or iterator escapes it. {ref}`PR-T36-08` then makes two wrappers expose the same observations with deliberately different ownership. Evidence consists of both state traces, separately counted traversal/storage, and an invalidation experiment performed through a defined API rather than dereferencing a dangling pointer.

### T36.03 — Callable hand-written x86-64 and Thumb kernels

Assembly exposes the proof boundary one register and memory access at a time. Build two original scalar lower-bound kernels over sorted `uint32_t` arrays: SysV x86-64 and AAPCS32 Thumb for Cortex-M4. Use bounded 32-bit lengths/indices and a checked C wrapper; length zero performs no load and may use a null pointer. A nonempty array must be a live typed array of at least the declared length. Neither kernel may call `bsearch` or any equivalent routine. Compiler output can explain differences, but it is not the hand-written artifact.

Write a liveness table before choosing registers. On SysV, RBX/RBP/R12–R15 are preserved and entry `(RSP+8) mod16=0`; a caller aligns before a nested call. The 128-byte user red zone is not a Cortex-M or Linux-kernel rule. AAPCS has r0–r3/r12 scratch, a preserved set including r4–r8/r10/r11 and platform-specific r9; SP is word-aligned always and eight-byte-aligned at a public interface. BL changes LR, so a nested caller must preserve its return path. In {ref}`PR-T36-02`, use a leaf kernel plus a separate nested-call probe that poisons allowed scratch registers. Require sentinel, preserved-register and stack-alignment evidence alongside outputs. Successful output with a corrupted saved register is an ABI failure.

### T36.04 — Ordering, searching and partition boundaries

For half-open lower bound, maintain `0≤lo≤hi≤n`, every earlier element `<key`, and every element at or after `hi` `≥key`. Midpoint `lo+(hi-lo)/2` lies inside a nonempty interval. If `a[mid]<key`, the new lower bound is `mid+1`; otherwise the new upper bound is `mid`. Each step shortens `hi-lo`. On `[0,7,7,2147483648,4294967295]` with key 7, intervals `[0,5) → [0,2) → [0,1) → [1,1)` return the first duplicate at 1. For key 8 the path is `[0,5) → [3,5) → [3,4) → [3,3)`.

The contract orders unsigned 32-bit keys. An x86 signed less branch or Thumb signed LT is a different predicate around `0x80000000`; keep flag provenance visible. Element offset is four times an index, so the wrapper bounds length before target-width multiplication and pointer formation. An absent high key may return n without reading element n. {ref}`PR-T36-02` compares operation certificates and reused C results, including a signedness mutation and a one-element off-by-one mutation. State exactly which load establishes each partition update. A correct middle value is insufficient evidence for a first-occurrence search.

### T36.05 — Sorting, permutation and stability

Insertion preserves a sorted prefix by keeping one pending record while moving greater predecessors right. Equal keys must stop the shift if the policy is stable. For original tags `(3,A),(1,B),(3,C),(2,D),(1,E)`, the stable output is B, E, D, A, C by key. There are six strict inversions and hence six shift writes; the selected insertion convention makes nine key comparisons and four final placements. Changing `>` to `≥` reverses equal-tag order without violating sortedness or the multiset.

A merge transition needs the same tie policy: with left `(1,B),(3,A)` and right `(1,E),(2,D),(3,C)`, take B before E and A before C. Derive the remaining-input and output-prefix relation, rather than assuming stability follows from sorted inputs. In {ref}`PR-T36-03`, write only a bounded tagged insertion kernel in one assembly ISA, at most 32 records; retain the already completed T15 merge and heap sorts as differential subjects. Heap sort need not be stable and must not be graded against the stable-tag policy. Sorted/reverse five-key inputs give four/ten insertion comparisons under the declared convention. Submit prefix snapshots, tagged permutation checks and counted work; a shorter measured duration does not prove a lower asymptotic bound.

### T36.06 — Heap invariants and priority policies

Sift-down begins with both child subtrees already heaps and one possible violation at p. Choose the larger child (left on an equal tie); if it exceeds the parent, exchange them. The parent's old value becomes the only possible violation at the chosen child. In `[5,7,8,3,6,2]`, root children 7 and 8 select index 2, yielding `[8,7,5,3,6,2]`; at index 2 the only child 2 stops the walk. Count one sibling comparison and two parent/child comparisons: three key comparisons, one swap. For `[1,8,7,6,5,4,3]`, the moving path 0→1→3 yields `[8,6,7,1,5,4,3]`.

Translate only this kernel into original assembly in {ref}`PR-T36-04`, preserving the T14 heap API, max-order and duplicate policy. Check `p<n` before child arithmetic; for n>1 the integer predicate `p<n/2` identifies every node with a left child, including the final single-child parent when n is even. Thus n=6, p=2 has left child 5 and no right child 6; compare the right child only after proving its index<n. The milestone's declared n≤1024 bound, or suitably widened checked arithmetic, protects `2*p+1`. Height bounds the visited levels because p descends; building the entire heap has a different cost argument. The oracle checks supplied transitions and local invariants rather than shipping the target sift code. Acceptance includes no-child, one-child, equal-child and root-replacement cases, multiplicity preservation after every swap and a resource ledger. A final heap with a silently dropped duplicate is still wrong.

### T36.07 — Trees, rotations and representation-preserving change

A rotation changes links while preserving the inorder relation among whole subtrees. For 30 with left 10 and 10's right 20, the LR repair first rotates 10 left, making 20 the left child of 30 with 10 below it, then rotates 30 right. Final root 20 has children 10 and 30, all leaf heights 1, root height 2. Height updates must follow changed child links; updating only the new root leaves stale metadata. Parent links, unique reachability and a null-height convention are independent obligations.

Deletion can propagate a height change beyond one repaired node. In the original tree root 2, left 1, right 4 with children 3 and 5, deleting 1 leaves root 2 balance−2. A left rotation yields root 4, left 2 with right 3, right 5; inorder becomes 2, 3, 4, 5 and height remains 3. This trace uses a single repair but the reused T14 implementation must still traverse the complete recorded ancestor path. {ref}`PR-T36-05` adds certificates to that implementation, including LR/RL cases, duplicate rejection and a multiple-ancestor deletion selected by the learner. It does not rebuild the full AVL tree. Compare searching key 3 in balanced keys 1, 2, 3 (two comparisons) with a right chain (three). Equal answers do not imply equal worst-case depth. Submit recomputed heights/parents and the first stale-metadata counterexample, not just an inorder printout.

### T36.08 — Hash probes and bounded string matching

An empty slot proves the probe chain ended; a deleted slot only records a past occupant. In the original capacity-eight table, key 22 hashes to 6 and visits 6, 7, 0, 1, 2, 3. Slot 1 is deleted, so stopping there would make later occupants unreachable. Slot 3 is empty, so the answer is absent after six probes. A full table has no empty sentinel: cap the walk at eight probes even for an absent key. Capacity, step rule and hash reduction are representation contracts; low load in one trace does not establish a general expected bound.

Byte spans carry lengths, so embedded zero has no special termination role. Text `[0,97,0,97,0]` contains pattern `[97,0]` at 1 and 3, including overlaps for other patterns. Define empty pattern as all n+1 boundaries and require output capacity before mutation. {ref}`PR-T36-06` adds an original assembly bounded lookup over the prior hash representation and a small original C naive span kernel for this exact output API. Reuse the earlier T15 prefix matcher as a comparison implementation; do not rebuild its full preprocessing. Count first-mismatch comparisons and probe visits independently. Evidence must include wrap, tombstone, full table, empty pattern and embedded zero; tests over NUL-terminated printable strings do not exercise this contract.

### T36.09 — Graph frontiers, shortest paths and historical refinement

BFS settles hop layers because every edge contributes one unit. Weighted paths need tentative distances and selection of the smallest unsettled label. In the original graph A→B 4, A→C1, C→B 1, B→D 1, C→D 5, with E isolated, BFS reports hops 0, 1, 1, 2, unreachable. Weighted settlement A, C, B, D gives distances 0, 1, 2, 3 in that order: B improves from 4 to 2 through C and D from 6 to 3 through B. The predecessor equations reconstruct each finite path; an unreachable vertex has no predecessor or numeric distance.

Adapt the prior T15 solver and T14 queue/heap in {ref}`PR-T36-07`; add frontier certificates, checked finite-distance addition and an explicit tiny-graph API rather than implementing them again. With a maximum finite value 65534, candidate 65530+10 is a range error, not a wrapped short path. Reject negative weights before mutation. As a reasoning counterexample, A→B 1, A→C2, C→B−3 makes early B settlement wrong: a later route gives−1. The historical Dijkstra paper supplies the tentative/settled mechanism, not the modern C storage contract or a blanket origin for all graph ideas. An independent simple-path enumerator is intentionally exponential and restricted to at most eight vertices. Submit label/settle/predecessor evidence separately from hop results and timing.

### T36.10 — Higher C abstractions over invariant-preserving kernels

An abstraction exposes operations while hiding enough representation to protect an invariant. A typed value wrapper can store real `Record` objects and copy values into them. An opaque pointer collection instead stores borrowed addresses; freeing the collection does not free its elements unless that is an explicit ownership policy. The two may expose the same ordered `(id,rank)` sequence while requiring different client lifetimes. Comparator context belongs to the ordering contract: rank then id forms a deterministic total order; mutating a borrowed record's rank while it is stored can invalidate the structure even though the pointer stays live.

In {ref}`PR-T36-08`, adapt one completed container and a new assembly kernel through a typed interface and a context/callback interface. Bound capacity to three for the fixture. A full insertion and duplicate-id insertion preserve the previous state, with duplicate checking taking precedence. Record whether callbacks retain, allocate or reenter; forbid those effects in this component's Profile C boundary. Invalidate handles through a defined generation/status check rather than demonstrating UB. Reuse the T18 ownership ledger and audit undefined symbols/transitive helpers. Acceptance requires equal valid observations from both adapters plus different copy/borrow lifetime explanations, comparator counterexamples and unchanged failure snapshots. Header-level genericity alone does not establish representation independence or portable object access.

## Environment and limits

Profile C applies to the component, with a separately declared Profile A harness. Target educational algorithms cannot delegate to libc or equivalent compiler/runtime helpers without an explicit support allowlist; inspect object/final symbols and disassembly. Typed pools, byte-copy APIs and real allocator callbacks have different C17 storage contracts. Linux x86 execution must use SysV, not assume Windows x64 conventions. Thumb assembly must actually assemble and run under a declared Cortex-M4 ISA environment; a physical board is optional for ISA evidence. Emulator execution is not physical timing, DMA or interrupt-latency evidence.

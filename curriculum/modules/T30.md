## Purpose and outcomes

Make scheduling, rollover, resources and supervision explicit in a constrained application. Preserve the difference between a mathematical task model, a logical trace and a measured physical response.

## Entry check and remediation

Derive unsigned elapsed time across one rollover and label release/start/finish on a trace. Repair only integer modular arithmetic or ceiling/utilization algebra before analysis. Verify T29's bounded ownership/priority argument, and understand one FSM/service interface from T20 before adding releases or preemption.

Use {ref}`guide-entry` for the diagnostic policy and {ref}`guide-roadmap` for route order. Only the stated prelude leaves must precede a dependent project.

## Component progression

**An execution budget with interference.** Separate algorithmic work, release jitter, blocking, interrupt interference and deadline. Compare a recurrence with measured traces under stated scheduling assumptions.

Before implementation, predict this discriminating case: **A watchdog feed succeeding while a required task no longer makes useful progress.** Carry its evidence into the projects below. Reuse one accepted component revision; new projects charge their new mechanism or experiment, not a second implementation of the old one.

## Study sequence and teaching

### T30.01 — Superloop design

A superloop is a scheduler even without a task API. Its longest non-yielding activity delays every later service. Calculate a service bound from ordered activities, then split a long parse/send into bounded slices and retain periodic releases separately from event work. Implement a tick-driven superloop with a quota per iteration. 'No threads' does not mean 'no starvation'. Evidence is a release/start/finish trace and a counterexample from the unsliced version.

Apply this mechanism in [PR-T30-01](../projects/PR-T30-01.md).

### T30.02 — Cooperative scheduling

Cooperative work progresses only where tasks explicitly return/yield. Use ready records with period, deadline and per-dispatch work quota; release jobs from elapsed ticks and prevent unbounded catch-up after overload. Implement fair round-robin among equal-priority runnable work and a declared drop/coalesce policy for stale releases. Fairness is not a deadline guarantee. Trace queue depth and release counts under the supplied overloaded input.

Apply this mechanism in [PR-T30-01](../projects/PR-T30-01.md).

### T30.03 — Preemption and RTOS integration

An RTOS task boundary changes blocking, ownership and context assumptions; it does not automatically fix them. Read the selected CM4F port's PendSV/priority assertions and map which application operations may block. Implement a two-task producer/consumer integration using caller-owned bounded storage and the appropriate ISR API only where priority permits. The original scheduler implementation is assessed separately in T50; it is not required to pass this integration milestone. Evidence includes configuration, context/stack ledger and shutdown/error ownership paths.

Apply this mechanism in [PR-T30-02](../projects/PR-T30-02.md).

### T30.04 — Clock and deadline arithmetic

Unsigned counter subtraction gives elapsed time modulo 2^W; ordering absolute deadlines requires all compared distances to stay below half the range. With an eight-bit fixture, elapsed from 250 to 4 is ten ticks. Derive a future/due predicate without converting an out-of-range unsigned value to signed C. Implement explicit bound checks and test equality, wrap and half-range ambiguity. The misconception is that ordinary numeric less-than preserves time order across rollover.

Apply this mechanism in [PR-T30-03](../projects/PR-T30-03.md).

### T30.05 — Latency and jitter

Release latency is start minus release; execution is finish minus start; response is finish minus release; jitter concerns variation around a stated reference. The fixture has response equal to latency plus execution, which makes inconsistent logs detectable. Instrument these separately, budget interrupt/queueing interference and report distributions. A maximum from a finite test is an observed maximum, not a proved upper bound. Include timer resolution and trace disturbance in the result.

Apply this mechanism in [PR-T30-03](../projects/PR-T30-03.md).

### T30.06 — Scheduling analysis

Under fixed priorities, response-time iteration includes own cost, blocking and higher-priority interference: R=C+B+sum(ceil(R/Tj)*Cj). State independent periodic-task and deadline assumptions before using it. Compute the supplied model by hand and with an independent checker; explain why its result ceases to apply when a service can block without bound. Utilization alone cannot certify every task set. Evidence names each assumption and one deliberately violated scenario.

Apply this mechanism in [PR-T30-04](../projects/PR-T30-04.md).

### T30.07 — Memory and resource budgets

A resource budget is a worst-path composition, not the sum of observed averages. Reserve queue storage, persistent state, task stacks and nested interrupt frames, plus alignment and runtime helpers. Implement an admission check that fails before publishing a job whose budget cannot fit. A watermark only describes exercised paths. Evidence includes symbolic maximum depth and tested exhaustion behavior, with opaque library costs reported as unknown rather than zero.

Apply this mechanism in [PR-T30-02](../projects/PR-T30-02.md).

### T30.08 — Watchdogs and progress

A watchdog should witness meaningful progress, not a timer callback that keeps running while the application is stuck. Require every supervised task to advance its epoch before feeding once per window; missing progress leads to a bounded fault/recovery decision. The F439 IWDG has its own low-speed clock, whose variation matters to timeout selection. Inject a hung task and a repeatedly failing reboot. Evidence demonstrates withheld refresh and a finite recovery limit, not an exact timeout from simulation.

Apply this mechanism in [PR-T30-05](../projects/PR-T30-05.md).

### T30.09 — Low-power execution

Sleep entry has a lost-event window if the foreground tests 'no work' and then sleeps after an interrupt publishes work. Treat pending work, wake source and entry instruction as one architecture-specific protocol; use the inspected sleep rules, not a generic C lock. Build a logical interleaving counterexample and an actual board sleep/wake trial. Clock restoration and Stop/Standby are separate unassigned extensions. Energy claims require measured voltage/current and timing on the real setup.

Apply this mechanism in [PR-T30-05](../projects/PR-T30-05.md).

### T30.10 — Real-time evidence

Real-time evidence combines a cost model, generated-code inspection and bounded measurements. Record optimization settings, task priorities, timer frequency and uncertainty with each trace; inspect helper calls on the critical path. Compare analytical model bounds, observed maxima and requirements in separate columns. The misconception is that a long successful run proves WCET. The mastery artifact must state exactly which requirement is supported and which environmental interference remains unbounded.

Apply this mechanism in [PR-T30-04](../projects/PR-T30-04.md).

**Shared scope limit — Scheduling Algorithms for Multiprogramming in a Hard-Real-Time Environment:** Single-processor periodic independent tasks with period-related deadlines and constant/max execution costs. Does not by itself establish schedulability with blocking, jitter, arbitrary deadlines, DMA contention, or a real RTOS port.

**Shared scope limit — FreeRTOS Kernel GCC ARM_CM4F port:** Source symbols are locators because this is source code. A particular GCC CM4F port is not a generic RTOS guarantee; no port build or timing experiment was run. Assert checks and configuration assumptions remain essential.

**Shared scope limit — STM32F405/415, STM32F407/417, STM32F427/437 and STM32F429/439 advanced Arm-based 32-bit MCUs:** Inspected Rev21; newer Rev22 delta uninspected. F439 RCC is chapter6, not earlier-family chapter7. Additional authoring inspection supports bounded 7-bit I2C transmit/single-byte receive and full-duplex SPI sequencing; optimized I2C multibyte/NACK timing and full error chapters remain outside scope. ADC sampling/trigger/single conversion are inspected, but analog electrical accuracy and Stop/Standby recipes are not. Physical timings, package pins and device electrical conditions need DS/board evidence and measurement.

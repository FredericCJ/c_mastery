# T04: Integer, bit-level, and floating-point semantics

## Purpose and outcomes

Make numerical contracts explicit from type selection through serialization and tolerances. Mathematical formulas do not automatically survive finite width, promotions, rounding or compiler transformations. The projects implement checked integers and fixed-point mechanisms, then investigate floating behavior under stated formats and modes.

## Entry check and remediation

Revisit T01 finite patterns and T02 typed expression trees. Derive one mixed signed/unsigned conversion before coding. If rounding-error reasoning is unfamiliar, work with a small synthetic decimal precision model before using host floating-point measurements.

## Component progression

**Checked machine arithmetic.** Derive representable preconditions before addition, multiplication, conversion or shifting. Compare a mathematical reference with the actual C operation and its promoted operand types.

Before implementation, predict this discriminating case: **A size product that wraps to a small apparently valid allocation, followed by a narrowing conversion.** Carry its evidence into the projects below. Reuse one accepted component revision; new projects charge their new mechanism or experiment, not a second implementation of the old one.

Follow the [project route](../guides/project-route.md) for ordering. Domain numbers are reference categories. The [laboratory](../guides/laboratory.md) and [shared contract cards](../guides/component-contracts.md) separate automatic execution from reasoning, transfer and physical observations.

## Study sequence and teaching

### T04.01 — Integer type selection

Choose a type by required range and role. size_t represents sizes, ptrdiff_t represents certain pointer differences, and intmax_t is a widest signed integer type. Exact-width families are optional; a byte has CHAR_BIT bits rather than an assumed eight. A wire octet and a C byte may need an explicit portability condition.

Investigation: Inventory limits and optional typedefs on both target builds, then justify types for counts, differences and wire fields.

Misconception to resolve: int is not a portable 32-bit synonym and fixed-width typedef availability must be checked.

Observable evidence: A role/range table and compile-time assertions for deliberate target restrictions. Evidence is developed in {ref}`PR-T04-01`.

### T04.02 — Promotions and mixed arithmetic

Small integer operands promote before arithmetic and bitwise operations. Usual arithmetic conversions then reconcile mixed operand types. For signed -1 compared with an equal-rank unsigned type, conversion can produce the maximum unsigned value. Validate the source value before casting at a boundary.

Investigation: Annotate operand/result types and implement a signed-input-to-size conversion that rejects negatives and excess magnitude.

Misconception to resolve: Casting after a mixed comparison cannot undo the earlier conversion.

Observable evidence: Typed traces and accepted/rejected boundary cases, including a negative source. Evidence is developed in {ref}`PR-T04-01`.

### T04.03 — Overflow and checked arithmetic

Unsigned arithmetic is modular; signed overflow is undefined in the baseline. A checked operation asks whether the mathematical result is representable before publishing it. For sizes, check multiplication and addition separately. Compiler builtins and C23 checked arithmetic have their own support and result contracts.

Investigation: Implement checked add/subtract/multiply and allocation sizing, then compare them with a supported builtin or C23 probe.

Misconception to resolve: Unsigned wrap is defined but may still violate the application size contract.

Observable evidence: Independent mathematical results, unchanged outputs on failure and minimum/maximum operand tests. Evidence is developed in {ref}`PR-T04-01`.

### T04.04 — Division and remainder

Modern C integer division truncates toward zero, with a remainder satisfying a = q*b + r and a remainder sign matching the dividend when nonzero. Floor division is a different operation. Zero divisors and an unrepresentable minimum/-1 quotient must be rejected before evaluation.

Investigation: Implement a truncating division wrapper and a separate positive-modulus normalization policy; check all sign combinations.

Misconception to resolve: Remainder is not always a nonnegative mathematical modulo.

Observable evidence: Quotient/remainder identities, sign tables and explicit rejection of exceptional operands. Evidence is developed in {ref}`PR-T04-01`.

### T04.05 — Shifts and masks

Shift counts must be nonnegative and less than the promoted operand width. Prefer unsigned values for bit construction, then mask to the declared field width. Rotations need a zero-count path to avoid a shift by the width. Leading-zero operations may need a specified zero-input convention.

Investigation: Implement extract/insert/rotate and population/bit-width routines for a declared width, validating count and field boundaries.

Misconception to resolve: Masking a count does not automatically define the intended rotation or make signed left shifts safe.

Observable evidence: Exhaustive small-width checks and edge cases for zero, full width and highest set bit. Evidence is developed in {ref}`PR-T04-02`.

### T04.06 — Byte order and serialization

A wire format defines byte sequence independently of host endian order, padding and alignment. Decode octets with unsigned shifts into a suitably wide type rather than dereferencing a cast buffer. Packed structures remain implementation/ABI artifacts, not a universal interchange specification.

Investigation: Encode and decode a 32-bit field in network order under an explicit eight-bit-octet condition.

Misconception to resolve: The host structure layout is not the protocol, even when a nominal packet happens to match.

Observable evidence: Known wire bytes, round trips, malformed-length rejection and an unaligned-input test without cast access. Evidence is developed in {ref}`PR-T04-02`.

### T04.07 — Bit-fields and representation control

Bit-field allocation units, ordering and some type behavior are implementation-defined. They may be useful inside an ABI-controlled representation but should not define a portable wire format or unconstrained device register access. Explicit masks make field positions part of the specification.

Investigation: Compare a measured bit-field layout with a mask-based register model and document read-modify-write implications separately from hardware semantics.

Misconception to resolve: A field declaration does not guarantee one bus access or a particular register bit position.

Observable evidence: An ABI-tagged layout report and explicit mask operations checked against the synthetic register specification. Evidence is developed in {ref}`PR-T04-02`.

### T04.08 — Fixed-point arithmetic

A fixed-point integer represents value q/scale. Select range and resolution together; multiply in a sufficiently wide intermediate, then apply a named rounding and saturation rule. With nearest rounding, one conversion error is at most half a quantum, but subsequent operations require their own propagation bound.

Investigation: Implement a scaled multiply with ties-away-from-zero rounding and saturation; derive intermediate and quantization bounds.

Misconception to resolve: Changing scale is not a free precision improvement when it reduces range or overflows intermediates.

Observable evidence: Exact integer oracle checks, tie cases, saturation endpoints and an error-bound derivation. Evidence is developed in {ref}`PR-T04-03`.

### T04.09 — Floating-point representations

The floating type’s characteristics come from implementation macros and documented formats. IEEE-style NaNs, infinities, signed zero and subnormals need conditional investigation rather than universal assumptions. A finite binary fraction need not exactly represent a finite decimal fraction.

Investigation: Record radix/precision/exponent limits and classify conditional exceptional values on the chosen target.

Misconception to resolve: More printed digits do not make an inexact value mathematically exact.

Observable evidence: A format report, adjacent-value observations and clearly bounded assumptions for exceptional cases. Evidence is developed in {ref}`PR-T04-04`.

### T04.10 — Floating-point computation

Rounding accumulates, cancellation magnifies relative error near a small result, and fused multiply-add rounds differently from separate multiplication/addition. Choose absolute tolerance near zero, relative tolerance away from it and ULP-oriented checks only under a stated format. Tolerance follows analysis, not a failing test.

Investigation: Compare naive and compensated summation on cancellation-prone data and a fused/separate expression where supported.

Misconception to resolve: Reordering equivalent real arithmetic can change the floating result.

Observable evidence: Higher-precision or exact references, error tables and a justified criterion for each workload. Evidence is developed in {ref}`PR-T04-04`.

### T04.11 — Environment and compiler modes

Rounding mode, exception handling, evaluation precision and contraction policy are part of the environment. Fast-math can relax assumptions concerning NaNs, signed zero or reassociation. A benchmark comparing modes must first state whether both satisfy the same required contract.

Investigation: Build a strict and documented relaxed configuration, inspect supported environment operations and record semantic changes before timings.

Misconception to resolve: A faster numerical build is not interchangeable if it changes required exceptional behavior.

Observable evidence: Compiler flags, environment-support probes, exception observations and a contract comparison. Evidence is developed in {ref}`PR-T04-04`.

### T04.12 — Numerical boundary testing

Numerical tests should target adjacent values, extremes, underflow/overflow, ties and cancellation, not just random middle values. An independent reference can use exact rational arithmetic for integers/fixed-point and higher precision for floating calculations. Explain why a tolerance is appropriate at each boundary.

Investigation: Generate boundary partitions and minimize one numerical disagreement without loosening tolerance first.

Misconception to resolve: A relative tolerance alone is unreliable at zero and near cancellation.

Observable evidence: A test partition, independent references, minimized disagreement and recorded acceptance rationale. Evidence is developed in {ref}`PR-T04-04`.

## Mastery gate and feedback

Derive checked-operation boundaries and fixed-point error bounds without executing overflow. Defend one serialization contract and one floating tolerance. Reproduce strict/relaxed build differences while naming the assumptions each result requires.

For independent study, make predictions before execution, compare an independent oracle, inspect one counterexample and defend the result aloud or in a short recorded review. Link each original objective to a specific artifact; use {ref}`guide-assessment` to score it. A failed gate requires a minimized cause, a corrected model and a fresh regression, not repeated nominal runs.

## Consolidation and transfer

Change width, scale or rounding rule after a delay and revise the proofs before the code. Transfer integer checks to a size calculation and numerical criteria to a new accumulation workload.

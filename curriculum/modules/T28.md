## Purpose and outcomes

Turn documented peripheral transactions into bounded driver state machines and portable service contracts. Begin with side-effect models, then replace only the adapter with verified target accesses.

## Entry check and remediation

Derive a bit mask, distinguish volatile from publication, trace a callback failure, and calculate a divisor from a stated clock. Repair T04 bit/arithmetic or T18 contract/test skills selectively. Pin the exact board/package/pins and clock tree before connecting external buses.

Use {ref}`guide-entry` for the diagnostic policy and {ref}`guide-roadmap` for route order. Only the stated prelude leaves must precede a dependent project.

## Component progression

**A bounded peripheral transaction.** Read the device's register semantics before designing the driver state machine. Separate controller protocol, electrical interface, clock source and completion condition.

Before implementation, predict this discriminating case: **A read-modify-write accidentally clearing a write-one-to-clear status bit.** Carry its evidence into the projects below. Reuse one accepted component revision; new projects charge their new mechanism or experiment, not a second implementation of the old one.

Follow the [project route](../guides/project-route.md) for ordering. Domain numbers are reference categories. The [laboratory](../guides/laboratory.md) and [shared contract cards](../guides/component-contracts.md) separate automatic execution from reasoning, transfer and physical observations.

## Study sequence and teaching

### T28.01 — Register documentation

Registers are transactions, not just integers in a struct. Record access width, offset, reserved-bit policy, reset value and side effects for each selected register. In the synthetic adapter, reading DATA consumes a byte and writing one to STATUS acknowledges selected flags; reproduce these effects in a logged model. The trap is using a generic read-modify-write on a side-effect register. Evidence includes a minimal legal access sequence and a rejected illegal width/reserved-bit write.

Apply this mechanism in [PR-T28-01](../projects/PR-T28-01.md).

### T28.02 — MMIO access rules

Volatile makes selected accesses observable to the compiler under the implementation contract; it does not make a multi-access update atomic or publish ordinary shared data. GPIO BSRR provides a dedicated atomic bit operation, whereas reading ODR and writing a modified value leaves an interrupt window. Implement both against a scripted interleaving and demonstrate the lost update. Evidence is the access log plus the correct BSRR mask; do not claim a host RAM variable models all MMIO behavior.

Apply this mechanism in [PR-T28-01](../projects/PR-T28-01.md).

### T28.03 — Clock and reset control

A peripheral's baud/timer settings are meaningful only with its actual input clock. Enable/reset the selected peripheral, respect the relevant post-enable delay, and check readiness with a bounded timeout. The F439 RCC chapter is chapter 6. Derive each bus/timer input from a recorded clock tree, then invalidate configuration on a clock change. The misconception is that SystemCoreClock automatically equals every peripheral clock. Retain the calculation and scope or logic-analyzer measurement.

Apply this mechanism in [PR-T28-02](../projects/PR-T28-02.md).

### T28.04 — GPIO

GPIO mode, output type, pull and alternate function solve different electrical/routing problems. Write a configuration table before touching pins, then use BSRR for output set/reset and a stable-sample debounce state machine for input. A pull-up does not replace a documented external bus resistor requirement. Test bouncing samples and atomic updates in the fixture; on hardware inspect package pin/board routing and measure levels without driving an unknown external circuit.

Apply this mechanism in [PR-T28-01](../projects/PR-T28-01.md).

### T28.05 — UART

The initial UART contract is bounded 8N1 polling, then an interrupt/DMA adapter can preserve the same service interface. For OVER8=0, BRR encodes the rounded peripheral-clock/baud divisor; report the resulting baud error. TXE permits another data-register write, while TC means the frame has finished. Receive by reading data only when RXNE is set; capture ORE/FE/NF status and the documented clearing order. Evidence includes bytes, timeout/overflow outcomes and a physical waveform for any baud claim.

Apply this mechanism in [PR-T28-02](../projects/PR-T28-02.md).

### T28.06 — Timers and PWM

For an up-counting timer with known timer clock, frequency is f_timer/((PSC+1)*(ARR+1)); compare values define duty relative to ARR+1. Preloads separate the written value from the active value until an update event. Implement a configuration calculator and update protocol, test zero/full duty and rollover, then measure actual output. A register value that represents the desired frequency does not prove it occurs on the pin. Timestamp precision also includes capture/clock uncertainty.

Apply this mechanism in [PR-T28-03](../projects/PR-T28-03.md).

### T28.07 — SPI

SPI clocks both directions even when the application only wants to send. The contract specifies CPOL/CPHA, eight-bit words, MSB-first order, GPIO chip select and paired transmit/receive ownership. Wait for TXE before each write, consume RXNE, and finish the selected full-duplex transfer by waiting for TXE then BSY clear before release. A device command protocol is separate from controller sequencing. Test partial progress and timeout with deterministic byte pairs; validate actual clock/CS timing on a verified connection.

Apply this mechanism in [PR-T28-04](../projects/PR-T28-04.md).

### T28.08 — I2C

I2C has bus phases and application meaning. For the bounded seven-bit write-then-single-byte-read, send address/write, register byte, repeated START and address/read; configure ACK off before clearing ADDR for the single-byte receive and request STOP after that event. Bound every wait and distinguish NACK, arbitration loss and timeout from retry policy. A timeout is not permission to force the bus while another master owns it. Preserve a phase trace and hardware SDA/SCL evidence when available.

Apply this mechanism in [PR-T28-04](../projects/PR-T28-04.md).

### T28.09 — ADC and analog interfaces

An ADC result combines conversion settings with an analog source and reference. The bounded task uses one regular channel, explicit sample cycles, single conversion, trigger policy and a result/error record. For the documented twelve-bit path, conversion duration includes sampling plus twelve ADC cycles; that arithmetic excludes stabilization and analog settling. Derive an RC settling allowance from the supplied synthetic front-end, inspect the actual device/board electrical limits before wiring, and distinguish quantization from reference/source error. Simulated codes do not establish physical accuracy.

Apply this mechanism in [PR-T28-05](../projects/PR-T28-05.md).

### T28.10 — DMA driver interface

A DMA API transfers ownership, not merely an address and count. Validate accessible SRAM, width/alignment and capacity, then move CPU-owned to device-owned until completion or confirmed cancellation. CCM on this F439 is CPU D-bus-only and cannot be treated as a generic DMA destination. Return partial completion and errors explicitly. Evidence includes rejected buffers, no reuse-before-stop interleavings, and final ownership/byte-count traces across polling, interrupt and DMA adapters.

Apply this mechanism in [PR-T28-06](../projects/PR-T28-06.md).

### T28.11 — Peripheral abstraction progression

Progress from a documented register adapter to a minimal driver, then to a service that does not expose register details. Use generated headers as declarations, inspect relevant vendor HAL behavior as a dependency, and retain direct-register sequences where they are the studied mechanism. A RAM mock must explicitly emulate side effects; it is not a peripheral oracle. Run the same service tests with scripted and physical adapters, explaining which failures and timings only the latter can establish.

Apply this mechanism in [PR-T28-06](../projects/PR-T28-06.md).

### T28.12 — CAN, USB, and Ethernet

**Elective extension.** The elective Ethernet diagnostic service has separate controller, PHY, protocol-stack and application boundaries. Implement the fixed bounded application datagram and sequence/replay handling against a declared adapter, then inspect one verified board network backend and its hardware prerequisites. Reusing a stack does not establish controller or link conformance. Evidence must distinguish portable framing tests from actual link/stack observations; the core GPIO/serial route is complete without this extension.

Apply this mechanism in [PR-T28-07](../projects/PR-T28-07.md).

## Mastery gate and feedback

Demonstrate a legal register trace, bounded error return, preserved ownership and one actual selected peripheral observation. Show a deliberate wrong-clock/status-clear failure and explain its cause. Host protocol fixtures are prerequisites; physical baud/PWM/ADC claims require actual board evidence.

For every linked objective, retain a separately labeled explanation, implementation/analysis artifact and check. Use {ref}`guide-assessment` for the rubric; one passing fixture does not establish all three objectives of a topic.

## Consolidation and transfer

Retain a service contract while replacing polling with an interrupt or DMA adapter. Explain which tests transfer unchanged, which side effects require a richer model and which timing assumptions become invalid after changing clocks.

## Purpose and outcomes

Build **EDU7-v1**, an original seven-layer exchange with each responsibility visible in code, wire records and evidence. A and B communicate through router R on two separate RS-485 segments. It is deliberately a small educational suite rather than a claim to implement an ISO OSI protocol suite. The reference model explains where responsibilities belong; our versioned [wire contract](../../research/enhancement/networking_contracts.json) supplies the concrete fields and policies that a model alone cannot supply.

Successful work distinguishes local frame delivery, unreliable routed delivery, reliable message transfer, negotiated dialogue, canonical representation and application effects. A valid CRC establishes one check over a received frame. It cannot establish that a transfer reached B, that a session remains valid or that a setpoint operation is authorized. Conversely, a session checkpoint can suppress a repeated effect while saying nothing about voltage or physical timing.

The eight projects form one family and contribute **58 implementation and verification hours** once. Reading, the oral/reconstruction assessment and delayed transfer work have separate budgets. Complete host contracts first, then the declared bench; an absent bench leaves the physical and final whole-stack gates open.

## Entry check and remediation

Decode a big-endian signed 16-bit value, compute a maximum nested length without overflow, and explain the difference between a borrowed span and a retained buffer. Trace TXE versus TC on a UART and show why releasing DE at TXE can truncate the final byte. Implement only the deficient T15 serialization/framing leaves or T18 ownership exercises before continuing; existing UART evidence from T28 can be reused.

Mathematics is targeted: powers of two and masks for fields, polynomial XOR for CRC, division for baud timing, and bounded integer comparisons for clocks/checkpoints. If the CRC recurrence is unfamiliar, manually divide a two-byte bit string by a short polynomial and check a remainder before working with 0x1021. For timing, first solve ten bits divided by 115200 bits/s with units. This module requires neither a general algebra course nor probability theory.

Use {ref}`guide-entry`, {ref}`guide-profiles` and {ref}`guide-laboratory` to record the actual host, board, adapter and measurement setup. The initial diagnostic is short; it selects remediation, not a replacement for the eight implementations.

## Study sequence and teaching

### T40.01 — Model, service boundaries and ownership

A service interface joins adjacent layers locally; a peer protocol relates entities at the same layer across nodes. At A, an application record is encoded by L6, wrapped by L5, segmented by L4, addressed by L3 and framed by L2. L1 moves electrical symbols. At R, L1/L2 terminate on each segment and L3 forwards; R need not decode the application record. At B, the inverse operations validate before publishing upward. This explains why R changes link addresses and CRC while preserving end-to-end node IDs and transport ports.

Use a span `{bytes,length}` with a precise lifetime at every boundary. Receive callbacks borrow an immutable span until return. A layer that waits after return copies into its own bounded slot. A lower asynchronous send retains an immutable owned span until completion; BUSY consumes nothing. Router queues, transport reassembly and session replay records therefore have different owners. Document `submit`, `receive`, `tick` and `completion` contracts without making all layers share one global mutable buffer.

A worked capacity proof starts with the conservative L6 service envelope of 80 octets. L5 adds seven, giving 87; L4 capacity is sufficient for fragments 24, 24, 24, 15. This is a storage envelope, not a valid 80-octet schema-1 record. The actual canonical maximum is 1 schema octet plus five two-octet TLV headers plus values 1+2+2+1+16 = 33 octets. Its session SDU is 40 and fragments are 24, 16. Both proofs give a largest L4 PDU of 32 octets, L3 packet 38 and L2 unescaped body 45; the independent general L2 maximum remains 47 for any legal 40-octet link payload. Confusing capacity with accepted syntax can create an overflow or an invalid acceptance. Build this two-part boundary ledger in [PR-T40-01](../projects/PR-T40-01.md); retain an encapsulation trace and a rejected lifetime violation.

### T40.02 — RS-485 physical adapter and medium access

RS-485 supplies differential electrical behavior; it does not supply node addresses, frame delimiters or a collision-free application protocol. Wire A—R.left and R.right—B as two separate segments, with four THVD1400 adapters at 3.3 V, a common reference and a 120-ohm termination at each end. Read the actual adapter schematic and identify D, R, active-high DE and active-low RE. RE stays low, so an enabled transmitter can receive local echo; tag and filter that echo by local transmit ownership rather than feeding it into an apparent peer frame.

For 8N1, one octet occupies ten bit times: about 86.806 microseconds at 115200 baud. A worst-case 96-octet escaped frame occupies at most 8334 microseconds when the integer timing budget rounds upward. Assert DE 200 microseconds before data; keep it asserted through TC, then impose a 200-microsecond peer guard. TXE only permits another register write. A logic trace must establish which event occurs after the final stop bit.

Link address 1 is master on each segment. Every 25-ms turn it may send one DATA and then POLL; address 2 sends one DATA or EMPTY only after that grant. The reply starts within 2 ms after the complete POLL and guard and finishes within 10 ms of its first octet. The master distinguishes a start deadline from a completion deadline. Dropping a legal 8-ms reply at a 2-ms start deadline would be an arbitration bug. [PR-T40-02](../projects/PR-T40-02.md) combines synthetic event checks with actual voltage, termination, timing and disconnect captures; host octets cannot establish L1 success.

### T40.03 — Link framing and error detection

L2 uses 0x7e delimiters and escapes body bytes 0x7e/0x7d as 0x7d followed by XOR 0x20. The unescaped body is version, kind, link source, link destination, payload length, payload and big-endian CRC. CRC-16/CCITT-FALSE covers all bytes before the CRC with polynomial 0x1021, initial 0xffff, no reflection and xorout zero. The independent check vector `123456789` has remainder 0x29b1. Compute the CRC before escaping and validate after unescaping; a CRC over the escaped byte stream is a different protocol.

An incremental decoder has SEARCH, BODY, ESCAPE and DISCARD behavior. Empty delimiters yield no packet. A delimiter after an unfinished escape drops the candidate and begins resynchronization; overlong input stays in DISCARD until a delimiter. Version, actual length, legal kind, link destination and grant ownership are checked before upper delivery. A foreign frame still occupies the wire, but it must not mutate upper state.

Exercise every split of an escaped frame, truncated escape, 48-octet body, incorrect CRC and a valid frame after noise. The misconception is that CRC provides retransmission or security. Here L2 reports validated local SDUs and counters only; L4 recovers loss. [PR-T40-03](../projects/PR-T40-03.md) requires identical results for byte-at-a-time and coalesced input and no callback for a rejected candidate.

### T40.04 — Network addressing, routing and hop limits

Node IDs A=17, R=34 and B=51 persist across both segments. Link addresses are local: A=1/R.left=2, R.right=1/B=2. Ports 7 and 8 select endpoint services and never choose a route. A datagram for B starts with node source 17, destination 51, hop limit 4 and next protocol 4. R accepts the left frame, copies the packet, decreases hop limit to 3, and creates a right frame from link 1 to link 2. B consumes a positive-hop packet addressed to 51. It does not decrement the packet merely to deliver it.

The six-octet network header contains version, source, destination, hop limit, next protocol and payload length. The only routes are the four versioned entries in the contract. At R, hop limit at most one, unknown destination, an own-origin loop, invalid protocol or a length mismatch produces a counted drop. This is a fixed educational routing rule, not a dynamic discovery protocol.

A router's copy must outlive the input callback, particularly while waiting for its other segment's grant. Poison a released input span and verify the queued output remains correct. The common mistake is to store a pointer into a reusable receive buffer or to carry left link address 2 unchanged onto the right link. [PR-T40-04](../projects/PR-T40-04.md) requires exact preserved and changed fields, a rebuilt CRC and a private-buffer ownership trace.

### T40.05 — Reliable bounded transport and flow state

L4 turns unreliable datagrams into complete bounded messages, not a TCP-like byte stream. Its eight-octet header carries DATA/ACK/PROBE, two ports, a transfer ID, fragment index/count and credit. DATA contains 1–24 octets; all non-final fragments contain exactly 24. A message of 25 octets becomes two fragments of 24 and 1, while 120 becomes five of 24. One outstanding fragment and one reassembly tuple per direction keep both memory and protocol state inspectable.

An ACK matches nodes, ports, transfer ID and index before advancing the sender. The receiver remembers an accepted fragment and re-ACKs a duplicate without appending it again. Only the complete message is published. Retain one last completed receipt and a highest-completed ID; ACK an identical repeated last fragment, drop earlier IDs, and replace the receipt only on the next completion. IDs strictly increase within a session and never wrap. A completed SDU awaiting upper consumption holds credit zero. An index/count mismatch fails the candidate instead of stitching bytes from different transfers.

Start the 100-ms retransmission clock after the lower layer actually accepts the fragment for transmission, not while it is still BUSY waiting for a grant. At most three retransmissions use identical bytes and index. Credit zero pauses new DATA; a 100-ms PROBE asks for credit, and an independent 500-ms blocked deadline frees state with a failure event. Duplicate ACKs and probes cannot postpone that deadline indefinitely. ID wrap forces session reopen. In [PR-T40-05](../projects/PR-T40-05.md), show a dropped ACK, duplicate fragment, credit pause and timeout with no partial publication. A plausible retry count without an exact buffer/state trace is insufficient.

### T40.06 — Session dialogue and resynchronization

L5 adds schema/unit negotiation, dialogue ownership and checkpoints; these are distinct from transport delivery. OPEN and OPEN_ACK agree on nonzero session/epoch, schema 1, unit 1 and initial token A. Their checkpoint is zero, as are TOKEN/CLOSE/ERROR control records. DATA carries the next positive checkpoint for its direction. A cannot send another application DATA while B holds the token, even though transport buffers may be available.

Transferring the token is itself uncertain until transport completion. The sender enters TOKEN_PENDING and sends no new DATA. The receiver changes holder when the complete TOKEN arrives. If its ACK is lost, the former holder remains blocked and a repeated TOKEN changes nothing again. This may pause progress, but never gives both endpoints permission. After A's request and token transfer, B sends the reply and returns the token.

Retained RAM remembers the last committed per-direction checkpoint and payload/response. Same checkpoint plus identical bytes causes no new effect; same checkpoint plus changed bytes is an error. A transport reset can use RESUME only when both peers retain matching session/epoch/checkpoint state. A rebooted peer with no state refuses. Checkpoint wrap requires close/reopen. This is neither authenticated identity nor durable exactly-once processing. [PR-T40-06](../projects/PR-T40-06.md) asks for a state diagram and effect count that distinguish lost ACK, stale epoch, incompatible negotiation, retained resume and reboot refusal.

### T40.07 — Presentation syntax and typed representation

L6 begins with schema 1 and ascending unique TLVs. Tags encode verb, request ID, signed value, unit and optional UTF-8 label. Two octets `f0 60` mean signed -4000 in the declared two's-complement 16-bit representation; they do not depend on the host's native byte order or struct padding. Decode through unsigned arithmetic, then convert within a representable signed range. A 16-byte label limit counts UTF-8 octets, not displayed characters.

Stage a decoded record until all TLV syntax, lengths, required fields, units and canonical UTF-8 have passed. Reject duplicate/out-of-order tags, truncated values, overlong encodings, surrogates and unknown schema. A label is display data, never a format string. Presentation validation proves that a typed record can be represented; only L7 decides whether a SET value is allowed for this application.

Implement encode/decode without copying a native struct. Compare a boundary SET, reordered tags and a UTF-8 label split inside a multibyte code point. [PR-T40-07](../projects/PR-T40-07.md) requires unchanged output sentinels on failure and a round trip with a separately derived wire record. A decoder that silently replaces malformed UTF-8 would violate this canonical contract.

### T40.08 — Application exchange and seven-layer acceptance

GET returns a declared fixture plant value. SET changes the fixture setpoint only within -4000 through 12500 centidegrees Celsius; ERROR leaves it unchanged. Unit 1 is mandatory for SET and REPLY, and every response correlates the request ID. These are explicit original application semantics; no physical sensor is implied. An otherwise valid session cannot make an out-of-range setpoint acceptable.

Trace SET from A to B through representation, session checkpoint, transport fragments, routed packets and two link frames, then the reply in the reverse direction. Correlate address scopes without expecting identical wire bytes at R. Apply the effect once before replying and keep the recorded response for a valid duplicate checkpoint. The invalid-SET ERROR includes the retained setpoint and a state witness demonstrates unchanged state independently of the error text. GET still returns the separate fixture plant value, not the setpoint.

[PR-T40-08](../projects/PR-T40-08.md) integrates all eight milestones. Its host fixture deliberately lacks physical evidence, so a correct protocol transcript still reports an open physical gate. Actual acceptance adds two-segment relay captures, corrupt/noisy/truncated frames, dropped ACKs, blocked credit, dialogue violation, retained resume, reboot refusal and cable interruption. Each fault is attributed to the responsible boundary, rather than described vaguely as a network failure.

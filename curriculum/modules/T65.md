# T65: Error models and executable contracts

## Purpose and outcomes

Represent absence, failure and progress explicitly, then compose operations without losing ownership or evidence. A tag is a representation invariant; it does not make C perform exhaustive matching or cleanup. These projects extend the earlier T18/T19/T21 contracts with precise operational models, independent oracles and changed-condition assessments. All required work remains core; descriptive hours do not cap study or investigation.

## Entry check and remediation

Explain a failed transactional output, a callback signature and a borrowed buffer lifetime using earlier learner artifacts. If an error flag is being treated as proof of unchanged state, revisit X-T04-001 before this domain. Keep the accepted bytes.checked, parser.integer, io.stream and codec.records contracts; adapters disclose differences.

## Study sequence and teaching

### T65.01 — Optional and Result representations without fictitious layout guarantees

A result value carries either its success payload or its failure information, selected by the validated tag. Reading the success member after receiving a failure is not error handling; it violates the representation contract even if the storage happens to contain a plausible number.

Derive the state cardinality of tagged versus zero-reserved optional values, including the lost present-zero state and valid result payload selection.

Packing (value=0,present=1) into an output initially 91 rejects with 91 unchanged; (17,0) stores zero; UINT32_MAX is a valid present value. Unpacking zero produces ER_ABSENT. The full tagged alternative must distinguish absent from present zero.

Investigation: Implement total constructors and checked accessors while preserving output on rejected niche construction; do not copy uninitialized union members or compare padding. The assessed work is {ref}`X-T65-001`.

Misconception to resolve: A language layout promise for a listed type is narrower than an observed sizeof equality.

Observable evidence: Enumerate the reduced 8-bit model independently, then test actual UINT32_MAX and invalid discriminants. Measure sizeof and alignment on two available data models; a missing model is unavailable evidence. Kill premature-output-write and absence-uses-payload mutants.

### T65.02 — Single-evaluation propagation and atomic parser publication

Error propagation must preserve the failing stage and its offset while returning control to the caller. In this parser, propagating the second field's failure cannot publish the first field as a successful complete configuration; ownership cleanup and publication remain separate obligations.

Explain which failure stage owns the error offset, and why early-return propagation is not transaction rollback or automatic cleanup.

1:65534 succeeds with 65535. 65536:0 fails `RANGE` at offset4; 1:2x fails `INVALID` at3; 1: fails at2; :1 fails at0. 1:65535 fails `RANGE` at7 and must not publish the first field.

Investigation: Implement strict checked accumulation and two single-evaluation propagation forms without statement expressions, strto* or parser libraries. The assessed work is {ref}`X-T65-002`.

Misconception to resolve: A macro temporary must not capture a caller variable or evaluate a side-effecting argument twice.

Observable evidence: Generate all strings of length0–6 over digits0,1,9,colon,x and compare with an independent grammar/integer model. Add UINT32 bounds and long zero prefixes. Record callback/expression counters to kill double evaluation and retain a canary output for every rejection; kill premature publication and trailing-input acceptance mutants.

### T65.03 — Partial progress is a product, not an error alternative

Derive a state table in which progress and terminal/error status are independent, and distinguish accepted bytes from durable bytes.

With length4,next0 and backend (2,`AGAIN`), return (2,`AGAIN`). Retrying from2 with (1,IO) returns (3,IO). A backend count2 offered only one byte violates the contract and returns the original next. Empty input does not call the sink.

Investigation: Implement a one-call bounded adapter with overflow-free relative-to-absolute progress conversion and explicit borrowed-buffer lifetime. The assessed work is {ref}`X-T65-003`.

Misconception to resolve: A rejected backend report cannot erase side effects already produced by that backend.

Observable evidence: Enumerate lengths0–5, valid and invalid next positions, backend counts0–6 and all status tags using a fake sink. Assert call counts, offered spans, no retry duplication and unchanged next on contract violations. Kill error-discards-progress and status-erasure mutants. Use a separate actual pipe adapter only as an additional OS experiment.

### T65.04 — Lazy Result composition and effect-sensitive laws

Short-circuit composition invokes the next callback only for the admitted success alternative. Prove both the returned result and the invocation count: eager evaluation of a callback on an error may preserve the final number while introducing an otherwise absent effect.

State the preconditions for map identity/composition and and_then associativity, distinguishing pure laws from callback side effects and evaluation order.

Mapping increment over IO(offset7) invokes zero callbacks and preserves7. Mapping over OK(4) produces OK(5) after one invocation; then a rejecting callback produces `RANGE`(offset5). A subsequent then does not call its callback.

Investigation: Implement typed callback composition with one active union member, error preservation and exactly selected callback invocation. The assessed work is {ref}`X-T65-004`.

Misconception to resolve: Equality of final numeric results does not imply equality of effects.

Observable evidence: Exhaustively compare finite pure functions on payloads0–7 using an independent table oracle. Instrument observable callbacks and construct a counterexample to a proposed optimization that eagerly evaluates an unused branch. Kill error-callback and flattened-error-loss mutants; inspect indirect-call counts before timing.

### T65.05 — Bounded applicative validation and transactional configuration

Error accumulation evaluates independent predicates in the declared order and reports total failures separately from stored diagnostics. Capacity zero or truncation does not turn an invalid configuration into a valid one, and dependent predicates still require their own admission order.

Explain why independent validation may accumulate errors while dependent checks require an admission order; define truncation independently of validity.

Input (-1,1025,0), capacity2 yields total3,stored2,truncated1 and error IDs[1,2], preserving the old configuration. Capacity0 still reports three errors. (150,1024,1) publishes successfully and emits none.

Investigation: Implement bounded ordered diagnostics and all-or-nothing configuration publication, including structural-misuse behavior and output nonoverlap preconditions. The assessed work is {ref}`X-T65-005`.

Misconception to resolve: Dependency between predicates changes the validation graph.

Observable evidence: Enumerate boundary representatives [-1,0,1,150,151] for age, [-1,0,1024,1025] for quota and [0,1,4096,4097] for denominator across all capacities. Compare error IDs with an independent predicate list and byte/field canaries. Kill early-publication and first-error-only mutants.

### T65.06 — Typed nonlocal-jump boundary with explicit cleanup ownership

A nonlocal jump transfers control to a saved environment that is still valid; it does not invoke destructors or release the resources skipped on that path. The explicit cleanup stack therefore owns each registered action until the boundary consumes it, including when registration itself fails.

Classify setjmp placement, live destination, modified automatic locals, thread identity and variably modified scope requirements from the inspected draft clauses.

Register callbacks appending digits1 and2, then raise ER_THROWN: return `THROWN` with trace21, count0 and inactive frame. Normal return with callback1 also cleans it. A raise after er_run returns is rejected before any jump.

Investigation: Implement a bounded explicit cleanup stack and typed jump-to-result boundary without pretending that longjmp unwinds C resources. The assessed work is {ref}`X-T65-006`.

Misconception to resolve: Cleanup registration is itself fallible and must occur before publication.

Observable evidence: Inject failure before and after each registration, capacity exhaustion, normal return and every admitted raised code. Count cleanup exactly once and compare reverse-order traces. Compile optimized GCC/Clang variants. Analyze deliberately invalid saved-frame and changed-local snippets without treating their execution as an oracle; kill cleanup-omission and FIFO-cleanup mutants.

### T65.07 — Arithmetic policy and serial-number partial order

Serial-number ambiguity occurs at the exact half-range distance: in the 16-bit model, 32768 and 0 have no admitted ordering. This intentional refusal differs from arithmetic overflow, and avoiding that one pair still does not make unrestricted modular comparison a transitive sorting order.

Derive the difference between mathematical range, unsigned modular semantics, saturation and the bounded-window assumption of serial comparisons.

65535+1 gives rejection/0/65535 under checked/wrapping/saturating policies. Serial0 is forward of65535; 32768 versus0 is ambiguous. Derive a three-value cycle to refute use as an unrestricted sorting comparator.

Investigation: Implement transactional policy adapters and an explicitly partial serial comparator with representable intermediate expressions. The assessed work is {ref}`X-T65-007`.

Misconception to resolve: Three pairwise plausible comparisons need not form a transitive order.

Observable evidence: Exhaustively enumerate an analogous 4-bit serial domain in an independent model, proving antisymmetry outside ambiguous pairs and finding nontransitive cycles. Test actual16-bit half-range neighbors and UINT32_MAX admission. Compare C17 manual checks with the separately inspected C23-draft checked arithmetic contract; kill write-before-reject and half-range-acceptance mutants.

### T65.08 — Contract off, observe and enforce modes with safe violation traces

Contract observation records a failed predicate while the independently bounded teaching effect continues. Contract enforcement instead rejects that transition while retaining the specified reporting side effect; neither mode can make undefined C operations safe merely by logging a warning.

Separate diagnostic observation, enforced rejection and C undefined behavior; explain why disabling assert can remove argument evaluation.

Starting counter90/reports0, adding20 in `ENFORCE` returns `CONTRACT`,90,1; `OBSERVE` then produces OK,100,2; `OFF` adds no report. With reports=SIZE_MAX an observed violation rejects without wraparound.

Investigation: Implement explicit contract modes with bounded arithmetic, report-counter overflow handling and failure-side-effect accounting. The assessed work is {ref}`X-T65-008`.

Misconception to resolve: Keep the teaching effect total so observing a violated predicate is meaningful.

Observable evidence: Enumerate all legal initial counters, amounts and modes against an independent integer model, checking both outputs and returned status. Compile separate assert(++counter) probes with and without NDEBUG, explaining why they are unsuitable for essential updates. Kill missing-report and enforce-still-commits mutants; the harmless attacker input is amount20 at counter90.

### T65.09 — Canonical rational values and the boundary of runtime refinement

Prove value preservation, termination and canonical representation; distinguish a runtime predicate from a static refinement type.

6/8 becomes3/4; 0/13 becomes0/1; UINT32_MAX/UINT32_MAX becomes1/1. Failed3/0 preserves both prior fields. Explain why an observed valid object yesterday does not validate a mutable alias today.

Investigation: Implement transactional rational normalization and a validated consumer, documenting public-struct mutation and alias ownership limitations. The assessed work is {ref}`X-T65-009`.

Misconception to resolve: A private header boundary controls ordinary clients, not arbitrary memory corruption.

Observable evidence: Enumerate numerator0–255 and denominator0–255 using Python fractions or an independently derived cross-product/gcd oracle. Test actual extrema and consecutive Fibonacci values for worst Euclid step counts. Reject unreduced-output and noncanonical-zero mutants. Verify checked consumers reject fabricated denominator0 before division.

## Reading guidance

The primary research records identify bounded actual passages. Read Result and Option representation promises carefully: selected language guarantees do not transfer to arbitrary C unions. The N1570 diagnostic and nonlocal-jump passages are a C11 committee draft; exact published C17 access remains recorded as a gap. No census entry is a primary authority.

## Implementation projects

Follow PR-T65-01 through PR-T65-09 in order, retaining implementations and regression evidence. Each project has two authored units, a concrete exercise, a separate assessor analysis and two property-specific compiled mutants. The result artifact is exported after the final composition/representation review; allocation measurements using T66 remain a later integration obligation.

## Mastery gate and feedback

Assess all four leaf objectives per subtopic with their separate criteria. Reject wrong failure side effects, invalid jump destinations and claims of automatic C ownership. Passing an anchor does not demonstrate the full written verification matrix. Require independent changed-condition evidence and a delayed reconstruction; record assistance rather than awarding fabricated independence.

## Consolidation and transfer

C08 and C12 are required non-equivalence analyses: C void does not provide a general inhabited unit value or an uninhabited bottom type, and C17 has no general expression-valued block/try expression. Compare a status-plus-output API and a do-while macro with the desired language feature, including a context where the substitution cannot type-check or preserve control flow. These analyses must be assessed through the T65 recall and domain review; they are not excuses to omit executable error mechanisms.

## Environment and limits

Hosted C17, exact-width uint32_t available. The explicit setjmp boundary depends on the host library. No strict freestanding, board, concurrency or whole-program memory-safety claim is made. Diagnostics, external verification, runtime checks and caller discipline are separate enforcement classes. Author tests, independent review and learner mastery have different records.

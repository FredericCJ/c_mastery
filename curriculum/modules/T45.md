## Purpose and outcomes

Learn to diagnose and repair memory and resource failures with evidence that distinguishes object bounds, initialization, lifetime and capacity. The result is ten small original experiments and repair dossiers, built on earlier APIs and harnesses. Each gives a prediction, controlled negative observation, first-invalid-state argument, repair and new regression/transfer cases.

## Entry check and remediation

Before PR-T45-01 explain ownership after failed nonzero resize, a bounded NUL scan, a three-stage cleanup prefix and the difference between a model and actual tool evidence. Revisit selected T03/T21/T32 leaves when needed. PR-T45-04 adds T13 stack analysis and T23 checked process/limit setup; PR-T45-05 adds T27 layout/startup. PR-T45-09 adds the T29 DMA/ordering leaves. The front card records these selected imports; early hosted milestones do not require completing every firmware laboratory first.

Use {ref}`guide-entry` and {ref}`guide-assessment` for targeted feedback. Repair integer interval/multiplication reasoning in PR-T45-02/03, maximum path sums in 04, aligned interval placement in 05 and root reachability in 06. State the equation and one counterexample before returning to C; no unrelated mathematics restart is required.

## Study sequence and teaching

Reuse a prior implementation or write a small owned example; do not consume a supplied solved C program. Run one deliberately faulty mechanism per supervised hosted process. Preserve input, build identity and observation before repair, then repeat with identical controls. Native undefined behavior does not have a prescribed output, crash signal or address.

### T45.01 — Controlled observation and detection contracts

An experiment starts with a claim and its detection contract. An extent monitor checks permitted addresses; an initialization monitor follows valid values; a resource ledger checks acquired and retained objects. Each can miss a different kind of defect. Name the exercised path, monitored boundary, runtime dependencies and observations before running the faulty version. An unavailable tool is an unresolved observation; a setup failure is not evidence about the target.

Worked trace: a negative control produces a report, a repaired trial produces no report, and another negative trial is silent. These results establish detection for the first exercised trial and support the repaired trial's selected checks. The silent faulty trial remains inconclusive. They do not establish a universal memory-safety property. A report also needs a matching binary and an explanation of the first invalid state; later runs after corruption can obscure that state.

Reuse the T32 harness in PR-T45-01. Record exact compile/link commands, sanitizer options, symbols, supervisor limits and tool versions for native, ASan/UBSan and separate unsanitized Memcheck builds. Predict which checked invariant should fail, then record actual output and termination without imposing a portable crash value or diagnostic string. The misconception is that a clean dynamic report proves all paths or that an unsupported invocation counts as a pass. Evidence is a coverage matrix plus a negative/repaired pair and an explicit open-claim list.

Develop and assess the evidence in [PR-T45-01](../projects/PR-T45-01.md).

### T45.02 — Object extents, underflow, off-by-one and NUL boundaries

Capacity describes storage; initialized length describes valid payload; a string adds a terminating NUL within the object's extent. A signed external index must be checked before conversion or pointer formation. One-past permits a position used for a zero-length operation under this API's explicit contract, never a dereference. Check lower bounds, remaining extent and NUL space before touching the destination, so rejected input preserves sentinels and observable length.

For capacity 8, indices 0 through 7 name bytes. Index −1 is below the lower bound and index 8 with count 1 is beyond it. Index 8 with count 0 is accepted without access. Seven data octets plus one NUL fit; eight data octets plus NUL require nine bytes. A scan bounded to eight bytes can return missing-terminator without reading byte 8. Do not use strlen to discover the length of an untrusted unterminated array.

In PR-T45-02 build these checked operations and contrast them with separate faulty learner-owned copies in the hosted process. Add a legal C array access that writes the wrong logical field: it can violate an application invariant while staying inside addressable storage. The misconception is that any array-shaped or zero-filled data is a valid string, or that an addressability tool checks the application meaning of every write. Evidence includes preserved failure snapshots, explicit terminator bytes, exact-capacity success, lower/upper cases and an independent logical-field assertion.

Develop and assess the evidence in [PR-T45-02](../projects/PR-T45-02.md).

### T45.03 — Checked allocation sizes and integer conversions

A correct allocation extent comes from a checked expression, not the wrapped result. Validate nonnegative external counts before converting them, constrain representable inputs, check multiplication, then check the header or terminator addition. Do not compute an overflowing intermediate and attempt to validate it afterwards. Conversion to a narrower size can lose information before the allocator is called.

The supplied model uses a maximum of 65535, header 12 and stride 7. Count 9360 gives 65520 payload bytes and 65532 total. Count 9361 has a representable product, 65527, but its total 65539 fails addition. Count 9363 has product 65541, so multiplication fails first. Count zero with header 12 still requests twelve bytes; total zero is rejected by this lab contract. These numbers model a declared width; the learner's C uses its actual SIZE_MAX and selected interface limits.

PR-T45-03 repairs a count-to-storage helper and a caller that narrows a length too early. The API returns a status and publishes the size only on success; no allocation occurs on rejection. The misconception is that defined unsigned wrapping makes the requested storage sufficient, or that UBSan's default group detects every unsigned size wrap. Evidence is the first rejected arithmetic stage, unchanged output/owner, independent wide arithmetic and native boundary tests. Remediate division inequalities and representability before adding complexity.

Develop and assess the evidence in [PR-T45-03](../projects/PR-T45-03.md).

### T45.04 — Stack exhaustion, frames and nested execution

Stack-capacity exhaustion consumes the reserved stack through calls, recursion, dynamic storage and nested contexts. A buffer write outside a local object's bounds is a different failure, even if it corrupts the stack. Frames depend on actual compilation, alignment, spills and callees. A GCC dynamic entry without bounded cannot close the whole-path bound. Unknown recursive depth or indirect callees keep that claim open.

The synthetic single descending stack has frames 32 + 48 + 64 = 144 bytes. Its two permitted nested contexts contribute (32 + 48) + (32 + 40) = 152, for 296 total. A 320-byte reservation leaves 24. Replacing one 32-byte saved frame with a declared 104-byte extended frame makes 368, exceeding the reservation. Real MSP/PSP selection and floating-point/lazy-frame configuration must be recorded separately; this is not a universal frame formula.

Changed-pattern scanning measures bytes that no longer match the fill. In the fixture, 32 unchanged bytes become eight four-byte words; the recorded minimum SP reserves 48 bytes even though only 32 changed. Unwritten local space or a restored pattern can hide reservation. Reentrant logging and interrupt nesting can add paths absent from the trial. PR-T45-04 combines closed-path calculations, actual .su/object inspection, a bounded high-water experiment and child-only native exhaustion. The misconception is that the largest single frame, watermark or canary proves a maximum. Evidence separates conditional bound, tested observation, guard behavior and unresolved paths.

Develop and assess the evidence in [PR-T45-04](../projects/PR-T45-04.md).

### T45.05 — Fixed RAM sections, startup and collision failures

A .bss output section occupies a fixed linked interval. Startup initializes selected zeroed storage; it does not grow .bss as the program allocates. Four failures need different evidence: fixed sections exceeding a linker region; an incorrect copy/zero range; a custom heap violating its reserved interval; and a stray runtime write into another object. Link success cannot rule out the latter three.

In the synthetic 1024-byte region, aligned data 96, bss 400 and retained storage 64 end at offset 560. The declared descending 256-byte stack begins at 768. A 160-byte heap ends at 720, leaving 48; a 32-byte guard fits. A 192-byte heap ends at 752, leaving 16, so the reservation contract fails despite all fixed sections fitting. Changing bss to 900 also aligns the retained start to 1000 and ends fixed placement at 1064, a 40-byte region overflow. Those are distinct verdicts.

PR-T45-05 reuses startup and map work from T27 and checks boundaries before initialization. A wrong zero range ending at byte 13 would touch retained byte 12; the checked adapter rejects it before mutation. In a separate defined reserved-cell experiment, change a logical value with an incorrect legal-address write and show that section size remains unchanged. The misconception is that corruption means .bss grew, or that hosted heaps necessarily collide with a descending contiguous stack. Evidence includes the exact map/allocator policy, nonoverlap, retained sentinels and separate link versus runtime observations.

Develop and assess the evidence in [PR-T45-05](../projects/PR-T45-05.md).

### T45.06 — Leaks, retained storage and failure cleanup

A resource leak can come from a missing release, a lost owning handle, a failed acquisition prefix or a retained object whose lifetime is too broad. Build an ownership ledger with acquisition, transfer, borrow and exactly-once release. Report live payload, retained bytes and peak bytes separately. RSS includes effects beyond the application's live allocation count.

Three resources of 32, 48 and 16 bytes produce peak prefixes 0, 32, 80 and 96. Failure before resource 2 acquires resources 0 and 1 and releases 1 then 0. Publication occurs only after all acquisitions; cleanup errors preserve the first cause. In the finite graph, lost A retains child B, rooted C remains reachable and D has only an interior root. These are declared graph categories, not promised native Memcheck output. C's 24 reachable bytes exceed a retention budget of 16 even though reachability prevents a lost-root classification.

In PR-T45-06 reproduce forgotten free, direct owner overwrite on failed resize and cleanup failure in separate owned processes. The repair stages publication, retains owners until release, and exercises every failure prefix. Native leak tools use conservative roots and selected error policies; state those settings. The misconception is that reachable means acceptable retention, that every RSS increase is a leak or that process exit substitutes for bounded repeated-use cleanup. Evidence includes the ledger before and after every acquisition/failure, repeated cycles, separate leak observations and a resource budget.

Develop and assess the evidence in [PR-T45-06](../projects/PR-T45-06.md).

### T45.07 — Resize, invalid release and stale aliases

The resize protocol has two branches. Failed nonzero resize retains the original allocation and its owner. Successful resize ends the old allocation's lifetime and supplies a new owner; every old derived alias is invalid even if the allocator reuses the numeric address. Compute and save required lengths/contents before the call, retain the result temporarily, and publish it only under the chosen failure contract. Do not compare, dereference or release the old C pointer after success.

The finite history gives generation 1 eight initialized bytes. Refusal preserves generation 1 and size 8. Success supplies generation 2 and size 12, retains the first eight bytes and leaves four additional bytes uninitialized. Its address token can be 1000 again, yet the generation-1 alias is stale. Integer tokens are safe model data; they are not permission to examine an invalid C pointer.

PR-T45-07 repairs a resize wrapper and alias publication. It separately studies double release, interior/foreign release and use-after-free with own-program negative controls, never as expected production behavior. free(NULL) is valid and has no effect; clearing one owner does not clear another alias. Zero-size resize is excluded. The misconception is that a same-address return preserves old aliases, or that a null assignment repairs ownership everywhere. Evidence is failure preservation, success invalidation, initialized-tail handling and exactly-once release, followed by new relocation and alias tests.

Develop and assess the evidence in [PR-T45-07](../projects/PR-T45-07.md).

### T45.08 — Initialization state and delayed invalid use

Addressability and initialization are independent. Storage can be accessible while a field lacks an initialized value. A field or byte-state model tracks intended writes; a publication contract requires every semantically required field. A zero-byte fill is not a universal typed-object initializer for every pointer or floating representation. Use typed initialization and explicit field assignments where the object contract requires them.

The supplied record has length and mode. Writing only length leaves mode uninitialized, so consuming mode fails and publication is denied even though the address is accessible. Writing both permits publication; making their storage inaccessible still fails. The two supplied synthetic representations differ in nonsemantic bytes while length 7 and mode 1 compare equal. They model a reason to compare fields, without defining a real C struct layout or promising initialized padding.

PR-T45-08 repairs partial initialization and adds branch/output consumption controls. Memcheck can propagate invalid-value metadata before reporting an externally significant use; that reporting policy is not permission to evaluate an indeterminate C value. ASan alone is not a general initialization-use detector. Optional MSan needs a supported OS and correctly instrumented dependencies. The misconception is that malloc supplies valid values, a silent copy is legal C, or whole-struct memcmp expresses semantic equality. Evidence is the write/consume history, field-wise regression, fill-pattern variation and a declared coverage limit.

Develop and assess the evidence in [PR-T45-08](../projects/PR-T45-08.md).

### T45.09 — Asynchronous borrowing, DMA and reentrancy

An asynchronous borrower can retain a buffer or callback context after the caller stops waiting. A timeout changes waiting policy; a cancellation request changes intent. Reclamation requires confirmed quiescence under the adapter's contract. A request identity and generation prevent a late callback from accessing a new object at a reused address. Protecting allocation metadata does not establish this application lifetime.

In the fixture, request 7 times out and requests cancellation. Reclaim is busy until its completion confirms no further access. Reclaim advances generation 1 to 2; a later generation-1 completion is stale. Request 8 instead confirms cancellation, yielding exactly one cancellation completion before generation 3 reuse. Two simultaneous users of scratch buffer 1 conflict; buffers 1 and 2 do not under the declared nonoverlap contract.

PR-T45-09 reuses the T21 operation model and T29 adapter. Add reentrant callbacks, duplicate completion and expired callback borrows. Hosted atomics or TSan observations do not model independent DMA. F439 SRAM/CCM reachability, ordering, interrupts and actual device quiescence require qualified target evidence. Halting the core may leave a peripheral active. The misconception is that disabling interrupts, a mutex, timeout or debugger stop authorizes reuse. Evidence is the ownership interval, exactly-once completion, denied early reclaim and explicit physical claims left open until measured.

Develop and assess the evidence in [PR-T45-09](../projects/PR-T45-09.md).

### T45.10 — Causal repair, prevention and transfer

A crash site is where a symptom becomes visible, not necessarily where the contract first failed. Work backwards using a competing-hypothesis table: extent, initialization, lifetime, resource boundary and observation setup. Use the smallest reproducing prefix to find the first invalid state, then design a distinguishing experiment rather than changing several conditions at once.

The extent history fails at event 2 but exhibits its symptom at event 5; the lifetime history fails at 1 and exhibits a symptom at 4. Reporting event 5 or 4 as the cause loses the repair boundary. A watchpoint should target a live, bounded object and be re-established when its scope or allocation changes. Hardware slot/width limits and software stepping affect observation. Arm watchpoint events are asynchronous; a recorded PC alone is not a universal offending-store proof. Fault frames and addresses must be validated before interpreting them.

PR-T45-10 requires an unseen repair dossier, semantic regression and delayed transfer. Separate prevention by a checked extent/owner protocol from mitigation by canaries, guard regions or hardening. A mitigation may reduce damage without restoring the invariant. The misconception is that the first reported symptom, a new allocation layout or disappearance under debug proves the repair. Evidence connects prediction, minimum trigger, first invalid state, mechanism, repair and remaining limits. Transfer changes capacity, failure position, nesting or completion order after a delay.

Develop and assess the evidence in [PR-T45-10](../projects/PR-T45-10.md).

## Mastery gate and feedback

For each topic submit a prediction, original negative control, earliest-invalid-state argument, repaired invariant, semantic regression and explicit observation limits. A quiet tool run cannot replace the repaired contract. An unavailable environment leaves its observation open; move to a supported host or keep a clearly limited static result. Apply {ref}`guide-assessment` to the smallest failed criterion and rerun the relevant boundary/failure case. Explain allocation/lifetime and resource budgets even when a detector reports the symptom.

The final dossier must distinguish prevention from mitigation and survive new capacity, failure-prefix, address-token, initialization and completion-order cases. For independent unseen assessment, keep the selected variant's defect identity and semantic oracle withheld until the dossier is submitted. Self-authored delayed practice has weaker independence and does not close that criterion. Keep exact C-language and target assumptions in the report. Source declarations, finite fixtures, actual C execution and physical evidence have separate claims.

## Consolidation and transfer

After a delay, diagnose a changed mechanism with the same outward symptom, then the same mechanism with a different symptom. Vary count widths, retained roots, permitted nesting and cancellation order. Transfer to one existing container/parser/request pipeline and predict the first invalid state before enabling the tool. Compare the earlier and later evidence without editing original expected results to match a broken target.

## Environment and limits

The finite oracle verifies arithmetic and supplied identity/history contracts. It executes no learner C, sanitizer, debugger or board test. Hosted negative controls belong to disposable learner-owned processes with verified limits, bounded input and supervisor deadlines. Separate native and diagnostic builds; do not run Memcheck on an ASan binary. Disable core dumps for routine fault trials and record any evidence-retention variant explicitly.

Core hosted observation requires a supported Linux setup for the Memcheck comparison. The optional MSan experiment needs supported instrumented dependencies and is not a Windows claim. Native exhaustion uses child-only checked limits and a supervisor; it does not attempt recovery on the exhausted stack. Embedded extensions use qualified existing adapters after the named preludes. No undefined-pointer/double-free failure is required on a board. Host histories do not establish DMA, electrical or real-time behavior. F439 results do not generalize to cached Cortex-M7 targets.

## Study sequence and teaching

Work through the mechanism notes in order within each project, alternating hand prediction with observation. Preserve the first counterexample rather than only a final green test. Full implementations belong to the projects; these notes explain what they must establish.

### T15.01 — Search and partition

Binary search narrows a half-open interval while preserving a relation to the answer. lower_bound finds the first value not less than a key; upper_bound finds the first greater value.

Investigate: Implement both bounds and partition with lo+(hi−lo)/2 and explicit empty-range handling. A common mistake is: Any matching index is a correct lower bound. Evidence: Duplicate and empty-range cases match a linear oracle and each update preserves the stated invariant. Develop that evidence in [PR-T15-01](../projects/PR-T15-01.md).

### T15.02 — Elementary and comparison sorting

Insertion sort supplies a small stable reference; merge sort trades temporary storage for stable merging; heap sort supplies a comparison bound with different locality. Stability concerns equal-key identity.

Worked stable merge: sorted left [1A,3A] and right [1B,2B] have labeled equal keys. Taking the left element on equality produces [1A,1B,2B,3A], preserving the earlier 1A; taking the right equal key would violate stability. A four-element caller workspace receives one element per transition, and the two input cursors never pass their lengths. For heap sort, reuse PR-T14-05 build/sift-down: max-heap [4,3,2,1] has active length 4. Swap root with the final active element to obtain [1,3,2 | 4], shrink to 3, then sift to [3,1,2 | 4]. Next extraction gives [2,1 | 3,4]; the active root already dominates its child. The last exchange gives [1 | 2,3,4]. Each step preserves the active max-heap and increasing final suffix; heap sort has no stable-tie promise.

Investigate: Implement all three using caller storage and labeled equal keys. A common mistake is: Sorting equal values proves stability. Evidence: Results preserve the multiset; labeled ties, comparison counts and scratch-space budgets expose the differences. Develop that evidence in [PR-T15-01](../projects/PR-T15-01.md).

### T15.03 — Quicksort and hybrid sorting

Quicksort partitions around pivots but can degenerate under adversarial choices. Three-way partitioning groups duplicates; smaller-side recursion and a depth-limited fallback constrain stack/work.

Investigate: Implement a duplicate-aware quicksort with a justified heap-sort fallback. A common mistake is: Random-looking input proves a worst-case bound. Evidence: Sorted/reverse/equal-key vectors plus depth and comparison counters exercise the fallback. Develop that evidence in [PR-T15-02](../projects/PR-T15-02.md).

### T15.04 — Counting and radix methods

Counting sorts allocate by key range rather than item count; radix passes compose a stable digit order. Signed keys need an order-preserving mapping before unsigned digit extraction.

Investigate: Implement counting sort and least-significant-digit radix sort over a declared bounded integer domain. A common mistake is: Unsigned byte order automatically matches signed numerical order. Evidence: Negative/positive endpoints, stability and auxiliary-storage totals agree with a numeric oracle. Develop that evidence in [PR-T15-03](../projects/PR-T15-03.md).

### T15.05 — Selection and order statistics

Selection needs only a rank boundary, not a fully sorted array. Duplicate partitions can contain the requested rank; invalid ranks must fail before reading storage.

Investigate: Implement quickselect with a three-way partition and state its expected and worst-case behavior. A common mistake is: Quickselect always has deterministic linear worst-case cost. Evidence: Every valid rank equals a sorted-reference value, and invalid ranks leave inputs under the declared failure policy. Develop that evidence in [PR-T15-02](../projects/PR-T15-02.md).

### T15.06 — String matching

Naive matching compares at each candidate position. A prefix/failure table reuses information about matched prefixes to avoid restarting work; byte spans do not require a terminator.

Investigate: Implement naive and prefix-function matching with overlapping matches and embedded-zero input. A common mistake is: A zero byte necessarily ends the search input. Evidence: Match offsets agree with direct bounded comparisons and the linear method reports bounded fallback work. Develop that evidence in [PR-T15-04](../projects/PR-T15-04.md).

### T15.07 — Graph traversal

BFS discovers layers in an unweighted graph; DFS follows depth and records visitation state. Explicit work storage makes recursion and its resource bound visible.

Investigate: Implement BFS and iterative DFS over disconnected cyclic input. A common mistake is: Marking visited only after popping cannot create redundant work. Evidence: Reachable sets, BFS distances and work-storage bounds agree with an independent edge model. Develop that evidence in [PR-T15-05](../projects/PR-T15-05.md).

### T15.08 — Graph ordering and paths

Topological order exists only for a directed acyclic graph. Dijkstra requires nonnegative edge weights; Bellman-Ford can detect a reachable negative cycle. Unweighted shortest paths need neither weighted algorithm.

Investigate: Implement topological cycle detection and a bounded nonnegative shortest-path solver; analyze a negative-edge counterexample. A common mistake is: Dijkstra remains valid whenever there is no negative cycle. Evidence: Every reported path has valid edges and cost, and violated weight assumptions fail explicitly. Develop that evidence in [PR-T15-05](../projects/PR-T15-05.md).

### T15.09 — Greedy and dynamic programming

A greedy choice needs an exchange argument that replacing an optimum choice does not harm feasibility. Dynamic programming names a state, recurrence and evaluation order; in-place compression can overwrite a needed previous layer.

Worked recurrence trap: with one 0/1 item of weight 2 and value 3, capacity 4 admits value 3. Updating capacities upwards lets the same row’s value at capacity 2 feed capacity 4, incorrectly yielding 6 and using the item twice. Descending updates preserve the prior-item dependency; exhaustive subsets independently establish the correct tiny result.

Investigate: Implement interval scheduling and bounded 0/1 knapsack with a descending capacity update. A common mistake is: An ascending 0/1 knapsack loop preserves the same item-use contract. Evidence: A brute-force subset oracle checks tiny instances and exposes unintended repeated item use. Develop that evidence in [PR-T15-06](../projects/PR-T15-06.md).

### T15.10 — Byte primitives and spans

A span is a pointer plus a length, with a borrow lifetime and aliasing contract. Copy, search, split and trim should report bounds and output capacity independently of NUL termination.

Investigate: Implement a shared byte-span kernel without libc calls and connect it to the T11 support boundary. A common mistake is: A split operation can retain pointers after backing storage dies. Evidence: Zero-length, delimiter-only, overlap and exact-capacity vectors check both semantics and dependency closure. Develop that evidence in [PR-T15-07](../projects/PR-T15-07.md).

### T15.11 — Numeric parsing and formatting

Checked parsing accumulates only after proving the next digit fits: value≤(limit−digit)/base. A signed minimum magnitude must be represented without overflowing a signed negation.

Investigate: Implement bounded integer parsing/formatting with explicit base, sign, prefix and partial-consumption rules. A common mistake is: atoi-style conversion can diagnose overflow or incomplete input. Evidence: Limit−1, limit, limit+1 and minimum-value vectors agree with arbitrary-precision arithmetic. Develop that evidence in [PR-T15-07](../projects/PR-T15-07.md).

### T15.12 — Serialization and integrity

Serialization chooses byte order and field widths independently of host layout. A CRC is a parameterized polynomial computation, so a test vector must name reflection, initialization and final XOR.

Investigate: Encode a tiny versioned record and CRC-8/0x07 message checksum using byte operations. A common mistake is: Copying a C structure creates a portable wire format. Evidence: Known vectors, endian-independent round trips and reserved-bit rejection match a bit-polynomial oracle. Develop that evidence in [PR-T15-08](../projects/PR-T15-08.md).

### T15.13 — Framing and incremental parsing

An incremental parser preserves state across arbitrary chunk boundaries and distinguishes incomplete input from malformed input. Length and nesting limits also bound recovery work and queued storage.

Investigate: Implement a length-prefixed decoder with a bounded frame maximum and explicit backpressure. A common mistake is: One read supplies one application frame. Evidence: Every possible split of the fixture stream produces the same accepted frames and a bounded rejection trace. Develop that evidence in [PR-T15-08](../projects/PR-T15-08.md).

### T15.14 — Lexing and grammar processing

A lexer separates token boundaries and locations; a parser applies precedence and associativity; semantic validation is a later stage. A source slice must remain live as long as tokens borrow it.

Investigate: Implement an ASCII tokenizer and precedence parser for integers, +, * and parentheses with depth limits. A common mistake is: A successful parse implies the expression is semantically valid or safely representable. Evidence: Token offsets, malformed-input diagnostics and evaluated small ASTs agree with a separate grammar oracle. Develop that evidence in [PR-T15-09](../projects/PR-T15-09.md).

### T15.15 — Advanced algorithm engineering

Specialized algorithm engineering begins with a workload, a simple reference and a resource budget. A more complex compression/index/conversion method can lose on small inputs or increase failure modes. This topic is elective; its implementation project is optional.

Investigate: Choose one suffix-index or bounded compression experiment and compare against an exhaustive reference. A common mistake is: One fast benchmark makes the method universally preferable. Evidence: The elective report presents correctness coverage, complete workspace costs and workload-specific results. Develop that evidence in [PR-T15-10](../projects/PR-T15-10.md).

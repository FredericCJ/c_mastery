## Purpose and outcomes

Implement the packet and state work of a **custom minimal Ethernet-to-HTTP stack** on NUCLEO-F439ZI. The MCU provides an Ethernet MAC/DMA controller; the fitted LAN8742A, magnetics and cable provide actual physical signaling. Your original C owns the selected driver, Ethernet/ARP, IPv4/ICMP, passive TCP and HTTP adapter. Register definitions are permissible aids, while a vendor Ethernet driver, lwIP or an OS TCP/IP stack cannot perform the owned mechanism work.

This is a controlled, same-link interoperability profile, with board 192.0.2.2/24, peer 192.0.2.1/24 and server port 8080. The [original contract](../../research/enhancement/networking_contracts.json) excludes DHCP, DNS, routing, IP reassembly/options, general congestion growth and several TCP services. Successful exchanges with a declared cooperative client do not establish general RFC host or IEEE conformance. The Internet suite also does not map one-for-one onto OSI's seven layers: HTTP can include several upper-layer concerns, TCP supplies transport, and the PHY/MAC boundary still requires explicit physical evidence.

Eight milestones contribute **72 implementation and verification hours** once. The portable HTTP parser/serializer projects in T42 are prerequisite work reused here; their hours belong to T42 and are not added again. Physical bring-up and protocol logic remain independently reviewable.

## Study sequence and teaching

### T41.01 — Protocol subset, interfaces and bounded resources

Each input span has a local interpretation. Ethernet supplies an entire frame beginning with DA. IPv4 supplies a datagram whose total length excludes Ethernet padding. TCP supplies a sequence-space segment, but the HTTP consumer receives an ordered byte stream with no preserved packet boundaries. Do not cast all three into one native struct or use Ethernet receive length as an HTTP body length.

Declare immutable borrowed spans for synchronous receive; owned slots for queued transmit data; and explicit consume counts for the HTTP stream adapter. Packet validation publishes nothing on failure. A TX DMA completion permits reuse of that DMA buffer but does not acknowledge the TCP bytes: their immutable retransmission copy remains until valid ACK. A full queue returns BUSY without consuming caller bytes. Link-down invalidates the transport incarnation and reports an abort rather than pretending all queued data reached the application.

For a TCP payload of 3 octets with fixed IPv4/TCP headers, 20+20+3=43 IPv4 octets, plus 14 Ethernet octets gives 57. MAC padding brings the frame from DA through padding to 60, then FCS yields 64. Preamble/SFD and interframe gap are physical/MAC behavior outside the driver's DA-starting span. [PR-T41-01](../projects/PR-T41-01.md) produces the scope/API/length ledger and a bounded memory budget. The trap is labeling all exclusions as optional standards features instead of acknowledging that a full IPv4 host must do more.

### T41.02 — Ethernet PHY, RMII and physical readiness

The F439 Ethernet block speaks RMII to an external PHY. LAN8742A converts that digital interface to actual cable signaling through magnetics. Its 50-MHz reference and the selected board pins/bridges are functional dependencies, not observations proven by a packet fixture. Configure RMII during the documented reset/clock sequence, confirm actual reference operation, then use MDIO to read the fitted PHY's identity and status.

The inspected identity is register 2 = 0x0007 and register 3 masked by 0xfff0 = 0xc130; the low nibble records silicon revision. Reset bit 15 of control register 0 self-clears. Use a recorded finite reset/MDIO deadline rather than an infinite busy loop. Basic Status link bit 2 is latch-low: reading 0x0020 then 0x0024 means a down condition was latched and the current link is up, not that the second value erased the event. Negotiation completion also requires the selected status fields.

Register 31 has negotiation-done bit 12 and speed bits 4:2. Codes 001/101 mean 10 half/full, 010/110 mean 100 half/full. Thus 0x1018 indicates completed 100-Mbit full duplex. Only supported full-duplex results enable this profile; MAC DM/FES must match the actual outcome. [PR-T41-02](../projects/PR-T41-02.md) checks numeric decoding and actual clock/link/reset/cable captures. PHY IDs do not prove a clock exists, and a TAP or mocked status register cannot close this topic's physical gate.

### T41.03 — MAC and Ethernet DMA descriptor lifecycle

Use four RX and two TX normal, 16-byte descriptors, each paired with one 2048-byte buffer in DMA-accessible SRAM, not CCM. Disable enhanced descriptors and timestamps; DSL=0 gives contiguous descriptors. The final RX uses RER, the final TX TER; chained mode is off. Buffer 1 has the exact RX size or TX byte count, and buffer 2 is unused. This costs 6×2048+6×16=12384 bytes before higher-layer queues.

Initialize complete buffers/descriptor controls, apply the target's required ordering, then publish OWN. CPU may inspect payload/status only after DMA clears OWN. For TX, normal TDES0 holds OWN31, IC30, LS29, FS28 and TER21; DC27=0 and DP26=0 request MAC CRC/padding and CIC23:22=0 disables transmit checksum offload. DMA writeback resets transmit control fields, so reconstruct them on every reuse. The earlier generic operation paragraph's IC reference conflicts with the normal-descriptor detail; use the inspected normal description, not the generic reference.

For RX, require OWN clear, FS+LS, no error summary/descriptor error and FL in 64..1518. CSTF=APCS=0 retains FCS, so expose FL-4 bytes beginning DA. A minimum FL=64 exposes 60; do not subtract the four bytes again in Ethernet. Store-and-forward is enabled for RX/TX; bad/undersized forwarding and checksum offload are disabled. Configure list bases only while stopped. Poll status with defined W1C masks, refill a suspended ring before poll demand and stop service on fatal bus error. [PR-T41-03](../projects/PR-T41-03.md) combines the finite ownership oracle with actual ring wrap and descriptor reuse. Volatile alone does not order ordinary packet stores or grant CPU ownership.

### T41.04 — Ethernet demultiplexing and ARP neighbor state

Untagged Ethernet II carries DA, SA and a big-endian type. This profile accepts local unicast and ARP broadcast, types 0x0800/0x0806, and drops VLAN/foreign traffic. Hardware perfect filtering is an aid; the software contract still validates its inputs. The board's locally administered fixture MAC is 02:00:00:00:00:02; actual peer MAC is observed and recorded, not assumed from the fixture.

ARP does not use an IPv4 wrapper. Its 28-octet Ethernet/IPv4 payload declares hardware type 1, protocol 0x0800, lengths 6/4 and opcode 1 or 2. Check those and enclosing length before reading variable fields; require ARP sender MAC to equal Ethernet SA. Only the configured peer IP can enter the one-entry cache. Reply to requests for the local IP, expire learned state after 30 seconds, retain at most one queued datagram, and issue at most three resolution requests one second apart.

An unresolved neighbor is a bounded resolution failure rather than permission to overwrite the only queue. Learning a tuple establishes a local address association, not authentication. A poisoned source field must never silently redirect the queued TCP packet. [PR-T41-04](../projects/PR-T41-04.md) checks exact ARP wire bytes, mismatch/expiry/drop outcomes and an actual request/reply capture on the isolated link.

### T41.05 — IPv4, ICMP echo and Internet checksum

Accept version 4, IHL 5, total length 20..1500 within the received span, TTL positive, valid header checksum, local destination and configured peer source. Protocol is ICMP or TCP. Emit DF=1, MF=0, offset=0, ID=0, TTL=64. Dropping options and all fragments is an explicit restricted-profile omission: full-host reassembly requirements do not disappear merely because the lab avoids fragments.

The Internet checksum adds big-endian 16-bit words with end-around carry and then complements the folded sum. An odd final octet is the high byte of a zero-padded word. Byte `61` contributes 0x6100, not 0x0061. Bound accumulation or fold periodically so the host integer cannot overflow. TCP's checksum covers its IPv4 pseudo-header, TCP header/options and payload; IPv4 header checksum alone says nothing about transport integrity.

Echo accepts ICMP type 8, code 0 and at most 64 payload bytes with valid checksum. Reply type 0 preserves identifier, sequence and every payload octet, then recomputes the checksum. With five echoed bytes, IP length is 33; Ethernet length before padding is 47, requiring 13 zero pad bytes to reach 60. [PR-T41-05](../projects/PR-T41-05.md) independently derives those checksum/length expectations and adds default 56-byte real ping. A successful ping proves neither TCP nor HTTP framing.

### T41.06 — TCP handshake, sequence and close state

Listen passively on 8080 for one connection. Validate tuple, checksum, header/data offset and options before state mutation. Advertise MSS 256 and use min(256, peer MSS or default 536) for sending. Parse EOL/NOP/MSS and skip well-formed unknown length-coded options; malformed lengths drop. Do not negotiate scaling/SACK/timestamps/ECN. Unsupported urgent data or SYN payload has a recorded restricted-profile outcome rather than a false full-TCP claim.

Sequence numbers lie on a 2^32 ring; all live spans stay below 2^31. SYN and FIN each consume one, pure ACK consumes zero. Starting peer SYN at 0xfffffff0 gives RCV.NXT=0xfffffff1. Sixteen accepted bytes move it to 1. A repeated segment contributes zero new bytes; an overlapping segment starting at 0xfffffff9 with twelve bytes has eight old bytes and four new, moving it to 5. Ordinary unsigned less-than fails across this wrap. Use explicit modular interval predicates whose preconditions are checked.

Reject an ACK beyond SND.NXT before freeing output. Update the peer window only with the inspected SND.WL1/WL2 guards; stale ACKs cannot roll it backward. Trim to an admissible in-order span and ACK gaps without retaining an out-of-order queue. Exact-RCV.NXT RST aborts; an in-window unequal RST sends a challenge ACK and no effect, outside-window RST drops. This is not authentication.

Trace LISTEN→SYN-RECEIVED→ESTABLISHED and active/passive close, FIN-WAIT-1/2, CLOSE-WAIT, LAST-ACK, CLOSING and TIME-WAIT. A peer FIN is a half-close, not successful completion of an incomplete HTTP body. Hold active-close TIME-WAIT for 240 seconds using MSL=120; a repeated remote FIN restarts it. [PR-T41-06](../projects/PR-T41-06.md) requires a transition ledger, overlap bytes and separate reset/half-close observations, including actual packet captures after host state tests.

### T41.07 — TCP timers, flow pressure and conservative sending

Retransmission and flow state are separate. RTO begins at 1000 ms, estimates from unambiguous RTT samples and backs off after timeout; receiver window expresses storage, while cwnd expresses a sending restriction. The profile keeps at most one outstanding segment and fixed conservative cwnd of one effective MSS. This bounded policy is intentionally slower than a full Internet implementation and does not demonstrate congestion growth, fast recovery or all event obligations.

For the first 80-ms sample, SRTT=80 and RTTVAR=40. With the next sample 120, update RTTVAR first: 0.75×40+0.25×|80-120|=40; then SRTT=0.875×80+0.125×120=85. Raw RTO 85+4×40=245 becomes 1000 under the minimum. No ambiguous retransmitted sample enters this calculation. Timeout events after an initial send occur at 1000, 3000, 7000 ms with three retransmissions, then the explicit finite resource abort at 15000. Cap RTO at 60000; a SYN retransmission keeps post-handshake initial data RTO at least 3000.

Keep the unacknowledged byte copy until ACK, even after TX DMA completes. Zero peer window pauses new data; a probe on the current RTO/backoff schedule requests an update without consuming another application byte. Local advertised window follows actual retained RX capacity and reopens when the parser consumes it. [PR-T41-07](../projects/PR-T41-07.md) verifies clocked samples, ignored ambiguous samples, zero-window/reopen and no duplicate delivery. It also compares the omitted general behavior explicitly rather than calling a one-segment sender a complete congestion controller.

### T41.08 — HTTP reuse, independent interoperability and physical closure

Attach the existing T42 portable parser/serializer through a stream adapter. Its byte grammar, Content-Length/chunked rules, Host/target validation, trailer limits and error-close policy stay the same. Configure one connection, queue depth one, one request and Connection: close. GET/HEAD /health uses the three-octet representation hex 6f6b0a; POST /echo preserves bounded binary octets. The shared fixed-order response fixture is an original serializer policy, not a universal RFC field-order rule.

Set the adapter's configured authority to `192.0.2.2:8080`; the hosted profile uses its separately declared loopback authority. This changes configuration and I/O callbacks, not parser grammar or Host validation. The fixed epoch 1672531200 belongs only to deterministic fixtures. Actual cable responses use a recorded reasonable UTC callback or initialized clock for Date, separate from the monotonic TCP clock. If no reasonable UTC is available, omit Date as allowed by the inspected RFC9110 Date rule and record that response variant; do not call the fixture's historical date current.

TCP can ACK bytes retained for the parser before an HTTP request is complete. A callback passes arbitrary accepted prefixes; preserve each consume count and leftover octet. Serialize once, retain immutable response bytes while segmenting at effective MSS/window, and free them only under the declared acknowledgment/completion rules. Send FIN after all response bytes are acknowledged. Error requests close without interpreting optimistic trailing bytes as a second request.

[PR-T41-08](../projects/PR-T41-08.md) correlates independent captures for ARP, echo, handshake, exact HTTP semantics, loss/retry, zero window and close. Remove/reconnect the cable and reset the board; show link down aborts the old incarnation and new requests belong to a recorded new one. A replayed pcap or hosted TAP closes finite protocol tests only. The full family closes only with actual fitted PHY/clock, cable operation, original driver/state work and independent client evidence.

Profile C supplies packets/register mocks and virtual clocks. Profile E supplies actual PHY/RMII/MAC/DMA/cable measurements. Neither host mocks, QEMU, TAP, replayed captures nor a loopback client establishes physical L1 completion. Exact subset interoperability and full-host conformance are separate claims; the omitted-requirements matrix remains part of acceptance even when all cooperative-client tests pass.

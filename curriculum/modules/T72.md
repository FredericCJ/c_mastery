# T72: Iterators, coroutines and continuations

## Purpose and outcomes

Implement the planned mechanisms from first principles and compare the exact C guarantees with inspected language/library/ABI contracts. Preserve accepted baseline records. Hours describe newly authored work and impose no learner deadline.

## Entry check and remediation

Revisit C17 lifetimes, checked arithmetic, callbacks and predecessor artifacts before using them across suspension or protocol transitions. An integer state is not a safety proof.

## Study sequence and teaching

### T72.01 — Lazy fused pull pipelines and typed early termination

Derive evaluation order, consumption and side effects for filter-even/map-square/take, and distinguish external next from an internal fold with typed break.

range0..10, step1, take3 emits0,4,16 after1,3,5 source pulls; the next call returns `DONE` without a sixth pull. Breaking after two outputs leaves16 as the next output.

Investigation: Implement co_next, co_flow_next and co_fold without an iterator library, then build an unfused equivalent and compare exact source-pull and callback counts before timing. Complete {ref}`X-T72-001`.

Misconception to resolve: Fusion is equivalent only when it preserves evaluation and failure contracts.

### T72.02 — Volcano scan/filter/group operators with pull backpressure

Explain open/next/close and group-boundary ownership in a pull dataflow plan; distinguish iterator backpressure from unbounded eager materialization.

Rows(1,-1),(1,3),(1,4),(2,-8),(3,5),(4,6) produce(1,7),(3,5),(4,6). A first next stops at index3 and cannot consume group3.

Investigation: Implement the fused contiguous-key nonnegative-sum query, an unfused scan/filter/group operator chain and a bounded push adapter with identical error and order contracts. Complete {ref}`X-T72-002`.

Misconception to resolve: An ordering operator changes storage needs even when its next signature looks identical.

### T72.03 — Allocated coroutine frames and generator ownership

Derive frame state, suspension lifetime, allocation failure and destruction rules; distinguish compiler-generated C++ coroutine storage from an explicit C frame.

count3 emits0,1,1 then stable `DONE`. count47 ends at1836311903. Allocation failure leaves the caller output unchanged and performs no release.

Investigation: Implement allocator-backed Fibonacci generators with one owned frame, stable `DONE`, cancellation through destroy and exactly-once release, plus a caller-provided-frame alternative under an equal value contract. Complete {ref}`X-T72-003`.

Misconception to resolve: C++ allocation elision is conditional; the C frame location is an explicit design choice.

### T72.04 — Actual x86-64 stack switching, ABI state and sanitizer fibers

Derive the SysV stack-entry alignment and callee-preserved context, separating ABI obligations, ISO C, compiler extensions and detector annotations.

The callback sees its own128KiB stack, local17 then29 survive yields, caller rounding changes remain independent of fiber FE_DOWNWARD, and destruction while suspended rejects.

Investigation: Implement the assembly context switch plus fresh/resume/yield/completed/destroyed lifecycle on a caller-owned aligned stack; preserve FP control and integrate ASan/TSan fiber APIs. Complete {ref}`X-T72-004`.

Misconception to resolve: ASan fake-stack addresses and architectural RSP answer different questions.

### T72.05 — Defunctionalized continuations and a budgeted trampoline

Transform recursive factorial into continuation-passing form and then a finite continuation representation, explaining which control and environment values were made explicit.

factorial6 takes14 single-transition steps: six pushes, one base transition, six pops and one completion. Output stays91 until completion then becomes720.

Investigation: Implement the factorial0..12 frame with a bounded multiplier stack, one-transition budgets, stable completion and cancellation, without recursive calls or tail-call optimization assumptions. Complete {ref}`X-T72-005`.

Misconception to resolve: A constant native call stack can still have a growing explicit continuation stack.

### T72.06 — Cursor parser combinators with rollback and progress checks

Derive ordered-choice, sequence and repetition semantics over a cursor, distinguishing ordinary mismatch from resource/structural failure and identifying nullable repetition nontermination.

choice(sequence(a,b),a) parses ac through position1 and ab through2. many(empty) returns STATE with end unchanged; budget0 returns RANGE with zero visits.

Investigation: Implement literal/empty/sequence/choice/many on the bounded immutable parser DAG with a node-visit budget, output rollback and no parser library; integrate an explicit bytes.cursor adapter. Complete {ref}`X-T72-006`.

Misconception to resolve: A successful repeated parser must consume input.

### T72.07 — Packrat success and failure memoization with explicit cache identity

Derive the memo key and time/space bound for the fixed ordered-choice grammar; explain why mutable semantic state, input revision and hidden iterative work can invalidate a linear-time claim.

aaxcc succeeds at5 with exactly3 evaluated S cells. Twelve a characters, x and twelve c characters use13 cells despite repeated alternative attempts. aac fails without changing end.

Investigation: Implement the bounded S grammar with caller-owned success/failure cells, full-input acceptance and per-cell evaluation counts, preserving payload output on mismatch. Complete {ref}`X-T72-007`.

Misconception to resolve: Count cell evaluation separately from cache lookup and elapsed time.

### T72.08 — Readiness-based async frames and lost readiness notifications

Explain readiness as a hint, partial progress as frame state, and registration/quiescence lifetime; distinguish this model from completion submission rings and automatic Rust Future pinning.

The fake reader returns AGAIN until arm, then supplies all three bytes on the immediate recheck: one poll completes after2 reads,1 arm,1 disarm. A stale generation cannot mark the next frame ready.

Investigation: Implement exact-length asynchronous reads with at most two reads per poll, arm-then-recheck, generation-scoped notifications, synchronous disarm and cancelled/error terminal states. Build an io.reactor/io.stream/io.deadline adapter. Complete {ref}`X-T72-008`.

Misconception to resolve: Cancellation cannot reclaim a frame while the reactor still holds its address.

### T72.09 — Single-shot resumable effects with explicit continuation ownership

Derive a two-question effect program and its defunctionalized continuation environment, separating single-shot runtime tokens from effect typing and multi-shot control capture.

Answers12 then30 produce42. The copied question1 continuation rejects after the first resume. A rejected overflowing second answer leaves its continuation available for correction or abort.

Investigation: Implement start/resume/abort with owner+generation tokens, checked second-answer addition, consumed continuation handles and unchanged state on arithmetic rejection. Complete {ref}`X-T72-009`.

Misconception to resolve: Cloning control without cloning ownership is unsafe.

## Precise vocabulary

**pull iterator**: An interface in which the consumer requests each next value, allowing demand to control producer progress.

**iterator fusion**: Combining iterator stages while preserving their value, consumption, evaluation and failure contracts.

**internal iteration**: Iteration in which an operation drives traversal and invokes a consumer callback, including an explicitly typed early-exit policy.

**Volcano operator**: A query-processing operator with an open/next/close interface that produces values on downstream demand.

**coroutine frame**: Storage holding the control state and variables that must remain live across suspension.

**generator suspension**: A point at which a generator returns a value or pending status while retaining the state needed for later progress.

**stackful fiber**: A cooperative execution context with its own retained call stack and an explicitly specified context-switch ABI.

**fiber fake stack**: Sanitizer-managed storage that may hold locals for use-after-return detection independently of the architectural stack pointer.

**defunctionalization**: Replacing a finite family of continuation functions with tagged data describing their environments and a dispatcher interpreting those tags.

**trampoline**: An iterative dispatcher that advances explicit continuation states without requiring one native recursive call per logical step.

**parser combinator**: An operation that constructs a parser by composing smaller parsers under declared consumption and failure semantics.

**ordered choice**: A parsing operation that selects the first successful alternative and retries later alternatives only under its declared mismatch policy.

**nullable repetition**: Repetition of a parser that can succeed without consuming input, requiring an explicit policy to prevent nonprogress.

**packrat memoization**: Caching parsing results by rule and input position together with every other semantic dependency admitted by the cache contract.

**readiness notification**: A scheduling hint that an I/O operation may make progress, which does not reserve data or promise successful completion.

**single-shot continuation**: A resumable control-and-environment value whose contract permits at most one successful consumption.

The **free effect representation** matters because a structure with terminal results and explicit layers of a chosen effect shape, interpreted by a separate handler. Constructing a free effect representation records operations; an executed effect has already changed the chosen environment.

The **terminal substitution** matters because the bind operation that replaces each terminal result with a constructed computation while preserving surrounding effect structure. Integer mapping changes only a result value; terminal substitution may add an entire new effect computation.

The **resource-bounded law** matters because an algebraic equality whose use in a finite C implementation explicitly assumes successful construction and the stated effect policy. Equal denotations do not imply identical allocations, callback timing, pointer identity or failure results in an exhausted arena.

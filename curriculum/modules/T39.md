## Purpose and outcomes

Connect physical Ethernet and OSI responsibilities to a checked MCU frame channel. Derive actual frame/buffer boundaries, PHY management and DMA ownership before the finite Internet implementation in T41. The portable mechanisms use profile C and caller storage; target adapters/images use the prepared E route. This is a core foundation beyond the older optional T28 network-awareness exercise.

## Entry check and remediation

This route follows completed core prerequisites, including T38 architecture/communication timing and the T27/T28/T29/T31 target, MMIO, interrupt and ownership work. Diagnose byte-order/unaligned parsing, checked address ranges, bounded state machines and exactly-once token release. Use targeted prior remediation for a failed item. Before physical milestones, verify matching board/PHY/revision/clock/pins, prepared cable/peer and instrument capability. Incomplete equipment permits synthetic progress but leaves the physical receipt open. Use {ref}`guide-entry` and {ref}`guide-laboratory`.

## Study sequence and teaching

### T39.01 — OSI services, peer protocols and Internet layer mapping

A layer provides a service to its local user and follows a protocol with its peer. These are different relationships. An application can call a local send service without knowing a remote implementation's function names; the peer still must understand the transmitted PDU. A service data unit becomes payload inside a protocol data unit, which becomes the next lower service's input. In the original fixture,12 application bytes plus 8 transport,20 network and 14 link header bytes produce 20,40,54-byte PDUs. Those invented wrappers illustrate encapsulation; they are not a claim that the trace is valid UDP/IP/Ethernet.

OSI organizes responsibilities into seven conceptual layers. Physical moves signals/bits; data link supplies local frame/link functions; network deals with network paths; transport supplies end-to-end transport services. Session/dialogue and representation tasks may live inside an Internet application's libraries rather than as separate wire protocols. L2 bridges also relay frames, so saying that every kind of forwarding is IP routing is too broad. Likewise, a local socket call is a service interface above substantial work already performed by the OS, not a complete implementation of those lower layers.

Build a responsibility table and an original peer/service trace, then test matching and mismatching interfaces. The misconception is that equal layer numbers guarantee compatible protocols, or that seven OSI layers demand seven C libraries. Evidence includes the SDU/PDU boundaries, actual peer agreement, local service shape and a mapping of the later finite MCU Internet endpoint to the conceptual purposes.

Apply and verify this mechanism in [PR-T39-01](../projects/PR-T39-01.md).

### T39.02 — Ethernet physical media and PHY responsibilities

The F439 Ethernet block includes MAC and DMA, but the external PHY handles the selected media/signaling boundary. In a 100BASE-TX copper route, show MAC→RMII→PHY→magnetics→connector→cable→peer rather than drawing the MCU GPIO directly into the cable. The IEEE layer diagram separates reconciliation/xMII, coding and physical-medium functions; our assignment uses only the declared 10/100 foundation. Detailed PHY coding/analog internals and modern multi-gigabit modes are outside this scope.

RMII supplies two data bits on a shared 50 MHz reference clock, corresponding to 100Mbit/s at the digital interface. A10Mbit/s link still has the required reference-clock contract; link operation is not inferred by counting CPU loops. Preamble, framing, FCS, negotiation and application throughput occur at different boundaries. A byte copied into a DMA buffer does not prove that the PHY has established a link or that the cable peer received the frame.

Shared half-duplex Ethernet has collision/deference behavior; the selected switched full-duplex baseline uses independent directional links without that collision algorithm. A100 m media example in a historical workshop is not a guarantee for an arbitrary cable, board layout or connector. Record the exact PHY, board revision, clock source and prepared media. The misconception is that a MAC peripheral, virtual NIC or emulator supplies physical evidence. Evidence needs actual clock/link/cable observations and a declared topology; this prepares the frame and PHY-management milestones without hiding a full board bring-up campaign.

Apply and verify this mechanism in [PR-T39-02](../projects/PR-T39-02.md).

### T39.03 — Ethernet frame, padding, FCS and buffer boundaries

An untagged basic Ethernet frame begins with destination and source 6-byte addresses, then a 2-byte length/type field, payload/padding and 4-byte FCS. Preamble 7 bytes plus SFD1 byte precede the frame and are outside our frame buffer. A minimum frame is 14+46+4=64 bytes from destination through FCS. A3-byte payload needs 43 pad bytes. A basic 1500-byte payload gives 1518 bytes including FCS. The interpacket gap is timing, equivalent to 12 byte times for the declared basic accounting; it is not another 12 bytes to place in the buffer.

The length/type boundary is also a parsing rule. Values≤1500 are lengths, values≥1536 are types, and the intervening range is excluded by this local parser. VLAN-tagged frames are valid Ethernet but deliberately unsupported here. For a length interpretation, application data length differs from padding; for an EtherType packet, the upper protocol must determine its own true packet length. Do not pass Ethernet padding blindly into an HTTP parser.

FCS covers destination through padding, excluding preamble/SFD and FCS itself. The original arithmetic fixture declares reflected CRC32 parameters and checks an independent recurrence against zlib; the RFC appendix is an algorithm source, not normative Ethernet conformance. The physical MAC may generate/strip CRC or padding according to configuration. Build a checked parser/builder and record the exact driver buffer policy. The misconception is that every capture includes FCS or that 64 bytes means 64 application bytes. Evidence includes minimum/maximum/gap/tagged cases and a capture-point ledger.

Apply and verify this mechanism in [PR-T39-02](../projects/PR-T39-02.md).

### T39.04 — MAC addressing, filtering and switching boundaries

MAC address bits are interpreted in the first octet: I/G is its least-significant bit and U/L the next bit. Thus 02:00:00:00:00:01 is local individual,01:00:5E:00:00:01 is a group address, and all-FF is broadcast. Byte representation is not the same as the LSB-first order in which each octet is sent. A locally administered address must still be unique on the selected link; a source address, destination MAC, IP endpoint and CAN content identifier are different namespaces.

A small learning bridge learns the ingress port of each individual source, then uses the destination to choose forwarding. Unknown unicast and group/broadcast traffic flood the selected other ports. Known unicast goes to the learned port; if it is the ingress port, no forwarding is needed. Our fixture's 10-tick expiry is a declared educational policy, not a universal bridge standard. Expire entries before each lookup and refresh a valid source observation. A port is not an IP route, and learning source addresses does not establish an endpoint's IP identity.

Implement a three-port/four-entry table and an endpoint address classifier. Keep loops, spanning tree and VLAN outside this model rather than accidentally promising a production switch. The misconception is that promiscuous mode on one switched port exposes every network packet, or that the first bit printed in a hexadecimal octet is I/G. Evidence includes known/unknown/group forwarding, same-port filtering, expiry and the exact endpoint receive-filter/capture-point assumptions.

Apply and verify this mechanism in [PR-T39-03](../projects/PR-T39-03.md).

### T39.05 — MII/RMII, MDIO and PHY link negotiation

RMII data signals and MDIO/MDC management solve different problems. RMII moves the MAC's digital frame stream with a shared 50 MHz clock. SMI/MDIO addresses one PHY register at a time; MDC is limited to the inspected 2.5 MHz maximum with its own pulse/period conditions. At HCLK168 MHz, RM0090's CR100 selects divide 102, yielding about 1.647 MHz MDC. For PHY address 0/register 2, a read-start word is 0x91: address 0, register 2 shifted 6, CR4 shifted 2, MW0 and MB1. First check MB0 and never rewrite address/data while an access is busy; read data become valid only after MB clears.

PHY status has temporal semantics. LAN8742A register 1 link bit 2 is read-only/latch-low: two reads separate accumulated history from the current observation. A first 0x20 then 0x24 means historical link-low and current link-high with autonegotiation complete. It does not promise the link will remain up afterward. ID registers must match 0x0007 and masked 0xC130; silicon revision is the low nibble. Register 31 done bit 12 plus speed bits 4:2 code 110 describes 100/full; code 010 is 100/half. The selected route rejects half duplex rather than silently programming full duplex.

Implement bounded identity/status/negotiation queries and configure MAC mode only from an accepted current result. The misconception is that one old link bit or configured PHY preference proves negotiated speed. Evidence includes identity masking, latched/current reads, incomplete/unsupported results, actual RMII/MDC clocks and a pin/clock/bridge ledger tied to the inspected board revision.

Apply and verify this mechanism in [PR-T39-04](../projects/PR-T39-04.md).

### T39.06 — F439 MAC/DMA initialization and reachable memory

DMA accesses memory as a different bus master. A C pointer valid for the CPU is insufficient: F439 Ethernet DMA cannot reach CPU-only CCM. In the selected SRAM range,0x20000100 plus 64 bytes is reachable;0x10000100 is not. A region starting 0x2002FFF0 with 32 bytes crosses the declared end and fails even though its first address is in SRAM. The fixture additionally requires 4-byte alignment as a local descriptor/buffer policy; do not generalize that local policy into every silicon transfer-width requirement.

Initialization has dependencies, not just a list of writes. Set MII/RMII selection under Ethernet reset or before enabling its clocks. The selected recipe asserts reset, chooses RMII, enables the required clocks, completes reset, prepares descriptors/buffers, installs bases and accepted PHY speed/duplex, then starts the separately controlled MAC/DMA engines. A reset that fails to finish is an explicit bounded error, not permission to keep writing the rest of the recipe. Distinguish peripheral reset, DMA software reset and later reset/recovery ownership.

Publish ordinary descriptor/buffer stores before giving ownership to DMA, and use the declared compiler plus hardware ordering contract. Volatile MMIO alone does not order all ordinary memory or make shared ownership atomic. This Cortex-M4 route does not need an invented M7 data-cache cleaning sequence. Build a dependency checker and reachable-memory validator, then bind the minimal existing board image. The misconception is that correct descriptor values imply a correct sequence or that a DMB makes unreachable memory reachable. Evidence includes first violated dependency, address-end checks and actual map/order observations.

Apply and verify this mechanism in [PR-T39-05](../projects/PR-T39-05.md).

### T39.07 — Ethernet receive descriptors, validation and recycling

A receive descriptor is a handoff record. OWN1 means DMA owns it; CPU must not interpret unfinished status or recycle that buffer. After OWN clears, FS and LS identify frame boundaries, the final descriptor's FL is meaningful under its stated validity conditions, and ES/DE report errors/truncation. With CSTF=APCS=0 in the selected MAC configuration, retain FCS and validate FL before exposing FL−4 bytes beginning at destination address. FL64 therefore exposes 60 bytes, not 64 and not 56. Padding still remains for the upper protocol to interpret.

For a bounded chain, require its first FS and last LS, all descriptors returned, no error summary/descriptor error, and length 64..1518 within actual combined capacity. Partial chains, errors and oversized values must not yield a pointer/length pair to the consumer. The original fixture's two-descriptor frame uses only the last descriptor's length. A consumer borrowing accepted storage prevents recycling; returning a token once permits it. A second release or stale generation is an ownership error even when the address looks valid.

Implement a small validator and the `ethernet_frame_channel_v1` receive contract in PR-T39-06. A full receive ring can suspend DMA; backpressure must become a counted result or a declared drop, not silent overwrite of consumer-owned data. The misconception is that OWN clearing alone proves a usable frame or that every capture/driver has the same FCS policy. Evidence includes first failed validation, retained/recycled ownership, incomplete-chain handling and an actual descriptor/wire correlation when closing the target route.

Apply and verify this mechanism in [PR-T39-06](../projects/PR-T39-06.md).

### T39.08 — Ethernet transmit descriptors, completion and recovery

Transmit begins with CPU ownership of the buffer and descriptors, not with a wire delivery promise. Prepare byte counts, buffer addresses, FS/LS and the selected padding/CRC policy before publishing. With a multi-descriptor frame, prepare all descriptors and give the tail its ownership before publishing the first descriptor's OWN; otherwise DMA can consume an incomplete chain. An ordering barrier and compiler contract cover the publication point. A queued request or OWN1 means in flight, not completion.

The normal path is CPU-prepared→DMA-owned→completed→reusable. The fixture deliberately publishes a head before its tail and reuses a buffer before completion; both fail. An error completion can return local ownership if the descriptor/DMA state establishes it, but does not mean the peer accepted the frame. Reset returns ownership only after the engine is confirmed stopped; stale completion from the previous generation must not complete the next request. Full-ring backpressure is a normal bounded result.

Implement the fixed two-descriptor publication model, then use the selected bare-metal adapter without rebuilding the whole network stack. For a 3-byte payload, MAC padding supplies 43 bytes under the declared policy; a software frame that already contains pad/FCS needs a different policy and is outside this baseline. The misconception is that a request function returning or an interrupt count proves delivery. Evidence includes publication order, completion/error/reset timelines, no premature reuse and the actual frame/descriptor observation points.

Apply and verify this mechanism in [PR-T39-07](../projects/PR-T39-07.md).

### T39.09 — From Ethernet to IPv4, TCP and HTTP responsibility contracts

An HTTP exchange crosses several endpoint namespaces and checks. HTTP supplies a request/status/body framing contract. TCP supplies ordered byte sequence and connection/port state; its segment boundaries are not HTTP message boundaries. IPv4 supplies addresses, packet length, header checksum and a next-hop responsibility. On a local Ethernet route, ARP resolves the selected next-hop IP to a destination MAC; that MAC is not automatically the final IP destination on a routed path. Ethernet validates local frame/address/FCS properties before an IP parser sees bytes.

Walk one request from application bytes through TCP, IP and the frame channel, then back through receive demultiplexing. In the later finite T41 route, these headers/state/timers belong to the learner's MCU implementation above a real MAC/PHY adapter. An OS socket may serve as a peer/client or comparison oracle; using it inside the claimed lower-layer path would delegate the mechanism under study. The finite endpoint intentionally excludes mandatory general-host features such as IP reassembly, so it is an educational subset rather than a complete Internet host.

Specify frame/time/event interfaces with bounded capacity, checksum/length ownership and error propagation before adding protocol code. Reuse the T39 receive/transmit token contract; do not rebuild a second incompatible driver in T41. The misconception is that one successful GET proves a complete stack or that payload/frame/stream sizes are interchangeable. Evidence is a responsibility trace, exact handoff ledger and declared accepted/excluded inputs; T41 supplies the concrete finite protocol implementation.

Apply and verify this mechanism in [PR-T39-08](../projects/PR-T39-08.md).

### T39.10 — Cross-layer timing, fault localization and evidence

Cross-layer evidence has capture points and clocks. A host fixture describes a deterministic logical sequence; a target log records descriptor/control events; a PHY status read samples a physical link; an external capture records packets visible at its own point. Additive clock offsets can align timestamps only under a declared synchronization/uncertainty model. Equal-looking timestamps or a decoded packet do not prove that all layers used the same buffer or ownership generation.

For 32 application bytes, simple 20-byte TCP and 20-byte IPv4 headers yield 72IP bytes. Ethernet adds 14 header and 4FCS to make 90 frame bytes;8 preamble/SFD and 12 gap-equivalent byte times make 110 for the declared serialization accounting. At 100Mbit/s this is 8.8 µs, excluding processing, queueing, propagation and peer response. TCP ACKs and extra ARP/connection/HTTP packets are additional events, not silently included in that one-frame estimate. A minimum frame consumes 84 byte times including preamble/gap under the same model.

Localize the first failed contract: lost link, descriptor unavailable, invalid frame, unavailable next hop, transport timeout or malformed HTTP. Several later symptoms may follow one early failure. Implement budget/capture correlation and a minimal failure ledger, then exercise the frame-channel handoff with a synthetic upper-layer consumer. The misconception is that every timeout belongs to TCP or that raw line rate equals application throughput. Evidence includes units, first-failure priority, capture uncertainty and separate software, target and physical receipts.

Apply and verify this mechanism in [PR-T39-08](../projects/PR-T39-08.md).

## Mastery gate and feedback

Given a fresh frame/descriptor/PHY trace, identify the buffer boundary, owner, first failed status/length condition and allowed next action. Explain exactly when FL includes CRC and which configured policy lets the consumer use FL−4. Derive a fresh MDIO word/divider and negotiated mode, then diagnose missing link versus descriptor backpressure versus an upper-layer failure. Show no premature reuse or duplicate release across complete/error/reset generations. Apply {ref}`guide-assessment`: independent review or delayed blind replay, per-objective receipts and targeted repair. Host/C checks close arithmetic/state claims; board and external captures close their separately declared physical claims.

## Consolidation and transfer

After a delay, redraw MAC/RMII/PHY and OSI service/peer paths; reconstruct a minimum frame, an address-bit decision and a DMA publication order. Change FCS policy, PHY mode or consumer lifetime and identify the first interface requiring revision. Pass the unchanged `ethernet_frame_channel_v1` plus monotonic time/error events into T41, and compare actual multi-packet exchange accounting with the one-frame fixture.

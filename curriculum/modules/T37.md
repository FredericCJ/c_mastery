## Study sequence and teaching

### T37.01 — Architectural state and implementation models

An architectural state is the part of execution exposed by the ISA: registers, relevant memory, PC and documented status/control state. A transition consumes an instruction and any declared external input and produces another state. A datapath, instruction pipeline and cache can implement that relation in several ways. A Cortex-M4 and a contemporary x86-64 core therefore cannot be compared by assigning them the same textbook pipeline merely because both execute loads and adds.

Define a tiny original machine in {ref}`PR-T37-03`: four eight-bit registers, sixteen byte cells, an instruction-index PC and one commit per clock. Its arithmetic wraps modulo 256 by specification. External inputs are absent unless explicitly injected between commits. With r1=3 and r2=1, repeated subtract/branch transitions produce r1=2, 1, 0 before the store. This is a model observation. Captured disassembly establishes encoding, an emulator execution establishes behavior on its implemented ISA subset, and a physical probe establishes behavior of that particular system. Neither static nor emulator evidence proves a board's clocks, DMA reachability or energy. In {ref}`PR-T37-01` and the final experiment, label each claim by evidence class and list unresolved assumptions. A model that matches one output has not thereby become a faithful microarchitecture.

### T37.02 — Boolean logic, ALU slices and finite arithmetic

For a one-bit full adder, sum is `a xor b xor cin`; carry is the majority relation `(a and b) or (a and cin) or (b and cin)`. Chain four such slices and retain the carry-out separately. Subtraction can add a to the bitwise complement of b with initial carry 1. At width 4, 7+1 yields 8: carry 0 but signed overflow 1 because the positive signed range ends at 7. Conversely 15+1 yields 0 with carry 1 and signed overflow 0 because signed−1+1 is representable.

The result's high bit gives N and zero result gives Z. For 8−1 the four-bit result 7 has signed overflow 1; Arm C is 1 (no borrow) and x86 CF is 0. For 0−1 the result 15 has Arm C0 and x86 CF 1. The same English word 'carry' thus needs an operation and architecture qualifier. {ref}`PR-T37-01` implements gate-level slices, then checks all 256 operand pairs per operation against independent integer range arithmetic: 120 carry/borrow pairs and 64 signed-overflow pairs. Use unsigned C for the model or explicitly checked arithmetic; a machine's wrap instruction does not make overflowing signed C defined. Evidence includes the eight-row full-adder table, exhaustive flags and one smallest carry-versus-overflow counterexample.

### T37.03 — Registers, addresses and representation boundaries

Register width controls more than the value printed in a debugger. Starting RAX=`1122334455667788`, writing AL=AA preserves all other bits; writing AX=BBCC preserves the high 48 bits; writing EAX=`89ABCDEF` clears the high 32 and leaves `0000000089ABCDEF`. The selected Cortex-M4 core registers are 32-bit; do not import AArch64's W/X register naming from the conceptual logic textbook.

Little-endian bytes 78, 56, 34, 12 reconstruct the word `0x12345678`. Base `0x1000`, index 3, scale 4, displacement 8 gives address `0x1014`; a four-byte access ends at `0x1018`, so check both ends against the live object's extent. Alignment, bus reachability and permission to access through a C type are three separate checks. An aligned byte array can pass the first two yet fail an arbitrary `Record*` effective-type claim under C17. In {ref}`PR-T37-02`, reconstruct registers and addresses without executing invalid casts; {ref}`PR-T37-06` adds DMA placement as a fourth, independent obligation. Submit a boundary table with typed-pool, byte-copy and genuine-allocation examples and a rejected aligned-byte-storage cast. Seeing a hardware load succeed does not validate the source-language program.

### T37.04 — Instruction formats, decoding and branch targets

Instruction bytes determine boundaries before mnemonic intent does. The selected x86 sequence 48 3D FF FF FF FF has REX.W and accumulator CMP with a sign-extended 32-bit immediate: compare RAX against−1, length 6. A following 77 FE is JA rel8. At address `0x1006`, its next instruction is `0x1008`; displacement−2 targets `0x1006`. JA tests CF=0 and ZF=0, an unsigned relation. Counting from the instruction start instead would target `0x1004`.

Thumb halfword `0x2A05`, bytes 05 2A, has high bits 00101, Rn=2, imm8=5: the inspected CMP immediate T1. First-halfword high bits 11101, 11110 or 11111 announce 32-bit Thumb; the T1 example is 16-bit. Reading architectural PC generally gives the current instruction address+4 in this scope, which differs from the x86 next-instruction branch base; some forms align PC further. Do not apply a blanket '+4' to every assembler expression. In {ref}`PR-T37-02`, annotate actual fields, predict boundaries and cross-check with disassembly and the pinned vendor definitions. Decode no uninspected T2 modified immediate. A deliberate wrong-width/branch-base annotation must be rejected. Disassembly is a cross-check of selected bytes, not proof that arbitrary data is executable code.

### T37.05 — Datapath, clocked state and control

Combinational logic computes outputs from the current inputs; stored state changes at a declared clock edge. A datapath therefore needs both old state and next state. For a toy `SUB r1,r1,r2`, read both operands from the old register file, compute the byte result, then commit destination and PC together. Updating r1 before another same-cycle read accidentally creates a different machine. A load needs address selection and a memory read path; a store needs memory-write enable and source selection; a branch needs a predicate and PC mux.

{ref}`PR-T37-03` models LI, SUB, BNZ, ST, LD and HALT with at most 16 program instructions. The original seven-instruction loop commits eleven times: two loads of constants, three subtracts, three branch tests, store, load and halt. Trace fetch index, decoded operation, operand sources, ALU result, write enables and committed state. A taken BNZ sets the toy's absolute instruction index 2; this is not an Arm encoded branch rule. Reject invalid operands and addresses before any commit, and bound execution to detect a nonterminating input. Evidence must include old/next-state separation and a control-signal table, plus a mutation that incorrectly reads an already updated register. A plausible block diagram alone does not demonstrate the commit mechanism.

### T37.06 — Pipeline hazards, forwarding and control changes

A dependency describes a value relation; a hazard describes whether a chosen implementation can honor it on time. A sequential program's read-after-write dependence is not a concurrent C data race. Declare a five-stage IF/ID/EX/MEM/WB model with EX-end forwarding into next-cycle EX, load data available after MEM, and write-before-read register-file order. Two dependent ALU operations can occupy successive EX cycles with forwarding. A consumer immediately following a load must delay EX one cycle in this model.

The original {ref}`PR-T37-04` schedule has I3 load EX 5/MEM 6 and I4 consumer EX 7, not EX 6. Its branch I5 resolves taken in EX 8, squashes the younger ID/IF work and refetches target I7 in IF 9. Six instructions retire by cycle 13; two younger fetch instances are squashed. Without forwarding, the first four dependent operations require 14 cycles under the declared register-file rule, versus 9 with forwarding and the load-use bubble. Draw the schedule rather than adding penalties twice. Annotate the source of every consumed value and a deliberate same-cycle load-use error. Hennessy/Patterson's model explanations support this reasoning; they do not describe the exact pipeline of every Cortex-M4 or out-of-order x86. Accept only conclusions conditional on the stated model.

### T37.07 — Memory hierarchy, locality and cache costs

For a byte-addressed direct-mapped cache with four 16-byte lines, offset is address mod 16, index is floor(address/16) mod 4, and tag is floor(address/64). In trace 0, 16, 0, 64, 0, 16, 80, 16, 0 the third access hits; 64 conflicts with 0 and 80 conflicts with 16. There are six misses and three hits. With a fully associative LRU shadow of equal four-block capacity, the four distinct blocks fit: four misses are compulsory and two are conflict, not capacity.

For trace 0, 16, 32, 48, 64, 0, the last miss is capacity because even that shadow evicts 0. Miss categories depend on the declared reference model and replacement rule. If hit time 1 ns and additional miss penalty 30 ns, AMAT is 1+(6/9)*30=21 ns, not a prediction of an out-of-order program's duration. A separate declared in-order estimate of 100 instructions at base CPI 1.2, 24 memory references, miss rate 0.25 and penalty 20 cycles gives 120+120=240 cycles, or 120 ns at 2 GHz. In {ref}`PR-T37-05`, compute both models and compare original layouts with a normalized trace. Evidence includes tag snapshots, shadow classification and units. Physical misses can overlap or interact with prefetching/TLBs; a host timing result cannot be equated to this simple estimate.

### T37.08 — Microcontroller memory, buses and DMA reachability

CPU accessibility does not imply DMA accessibility. RM0090 Rev 21 distinguishes F405/407/415/417 from F42/43: the latter have ordinary SRAM banks 112 KiB, 16 KiB and 64 KiB, while 64 KiB CCM sits outside the bus matrix and is CPU-only. A CPU-local temporary can therefore live in CCM while a DMA buffer needs a reachable ordinary SRAM region. Placement must also keep the complete live object inside its declared region and meet peripheral/transfer alignment rules; a reachable numerical address is not an allocated object.

{ref}`PR-T37-06` reuses the T27 exact-target map and T29 DMA ownership protocol. It adds a linker/map decision and a static master/slave graph, not a new DMA driver. A supplied synthetic ledger rejects a CCM buffer, a bank-crossing allocation and an end-overrun. CPU ownership transfers to DMA before access and returns only on the protocol's completion; a foreground write while DMA owns it is rejected. RM0090 describes round-robin arbitration and APB narrow-write duplication: byte 12 hex becomes bridge vector 12121212 hex, but the peripheral register's access rules still decide the effect. Static fair grants do not prove worst-case throughput or latency; clocks, bursts, other masters and errata need separate evidence. Submit exact part/revision, placement and ownership separately, and disclose physical measurements that remain unavailable.

### T37.09 — Reset, exceptions and architectural boundaries

A subroutine call and an exception cross different boundaries. AAPCS assigns software obligations such as preserving r4–r8/r10/r11 and maintaining call alignment; BL updates LR. A basic Cortex-M exception automatically stacks r0–r3, r12, LR, PC, xPSR, not every general register. For a declared no-padding Thread/PSP frame with pre-entry PSP `0x20001000`, the eight words occupy `0x20000FE0` through `0x20000FFC`. EXC_RETURN `0xFFFFFFFD` selects basic-frame return to Thread using PSP in the scoped case.

Reset in the declared Flash-vector scenario loads MSP `0x20002000` and reset vector `0x08000101`, entering Thumb code at `0x08000100`. IRQ 5 is exception 21, so with VTOR `0x08000000` its vector entry is at `0x08000054`. Lower priority numbers denote higher urgency, but implemented bits/grouping/masks affect actual nesting. {ref}`PR-T37-07` reuses T27 startup and T29 frame tooling, adding a call-versus-frame comparison and a synthetic return trace. Reject unsupported frame variants instead of guessing offsets. Optional FP stacking, stack-alignment padding and device boot remapping lie outside the supplied anchor; scope them explicitly if observed. Evidence includes register ownership, frame offsets, restored PC/SP and an emulator or target observation whose identity is separate from the fixture.

### T37.10 — Performance equations and credible experiments

CPU time equals instruction count times average CPI divided by frequency. For 1.2 million instructions, CPI 1.5 and 2 GHz, time is 0.9 ms. If 60% of original time becomes three times faster and the rest is unchanged, remaining fraction is 0.4+0.6/3=0.6; whole-task time becomes 0.54 ms and speedup is 5/3. Even infinite acceleration of that part caps whole-task speedup at 2.5. Count fractions of baseline time, not fractions of source lines.

In {ref}`PR-T37-08`, compare one reused C kernel with its original T36 assembly counterpart after proving identical results. Declare CPU, ABI, compiler/options, input families, clock, warm-up and repetition/order. Keep at least 31 raw measurements per condition; report median and range with outliers retained and explain timer overhead, frequency changes, migration, interrupts and cache state. The supplied synthetic five-sample medians 100 ns and 95 ns merely demonstrate reporting: their ratio 20/19 is not a measured speedup claim. Algorithm comparisons/moves and elapsed time belong in different columns. A cross-compiled or emulated Thumb run can check selected ISA behavior but cannot establish physical Cortex-M cycles, WCET or energy. Submit conditional conclusions and unresolved confounders; faster on one input family does not imply safer or generally better.

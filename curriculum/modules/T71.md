# T71: Typestate, protocols and state machines

## Purpose and outcomes

Implement the planned mechanisms from first principles and compare the exact C guarantees with inspected language/library/ABI contracts. Preserve accepted baseline records. Hours describe newly authored work and impose no learner deadline.

## Entry check and remediation

Revisit C17 lifetimes, checked arithmetic, callbacks and predecessor artifacts before using them across suspension or protocol transitions. An integer state is not a safety proof.

## Study sequence and teaching

### T71.01 — Consuming typestate and explicit recovery after partial device writes

Derive a lifecycle transition table including partially configured RecoveryRequired, token generation retirement and storage lifetime; distinguish C wrapper diagnostics from Rust moves.

Failure after control3 consumes the old token, leaves ready output unchanged and returns RecoveryRequired. quiet0 retains control3; quiet1 clears it. Reusing the pre-failure token after recovery rejects.

Investigation: Implement pt_device_init/configure/close/recover with consumed matching tokens, unchanged success-output on failure, and externally certified quiescence before cleanup. Fail after each of the two control writes. Complete {ref}`X-T71-001`.

Misconception to resolve: A generation check presupposes live device storage; it is not a borrow checker.

### T71.02 — Staged builders, presence masks and cross-field admission

Separate required-field presence from value validity and cross-field constraints; identify what staged C wrapper types can diagnose and what a public struct can bypass.

address252,length8,timeout10 is fully present but rejects the extent. address4,length8,timeout10 succeeds. Repeating address does not silently overwrite it.

Investigation: Implement one-shot setters and atomic finish for address, length and timeout using the exact bounds in CONTRACTS.md, and construct a second staged-wrapper interface with the same admitted configurations. Complete {ref}`X-T71-002`.

Misconception to resolve: Construct the finished config only after all checks pass.

### T71.03 — Dual binary session automata with bounded dialogue

Derive dual send/receive traces for `HELLO`, ACCEPT, a bounded DATA/ACK loop and BYE; distinguish runtime protocol conformance from transport liveness and language-enforced session types.

At remaining0, `HELLO` and ACCEPT lead directly to BYE. A client receiving `HELLO` is rejected; an ACK reduces remaining exactly once.

Investigation: Implement pt_session_step for both roles, phase and remaining count, rejecting wrong direction/tag and terminal reuse without progress. Build an in-process two-endpoint trace driver using only synthetic messages. Complete {ref}`X-T71-003`.

Misconception to resolve: An automaton cannot prove that its peer will ever run.

### T71.04 — Hierarchical run-to-completion transitions and observable entry order

Derive least-common-ancestor exit/entry paths, inherited FAIL handling, external self transitions and internal PING; distinguish this bounded HSM subset from full UML semantics.

OFFLINE CONNECT emits exit OFFLINE, entry ONLINE, entry IDLE. `BUSY` START emits exit `BUSY` then entry `BUSY`. `BUSY` FAIL exits `BUSY` and ONLINE before entering FAULT.

Investigation: Implement pt_dispatch with inner-first exits, outer-first entries, a nonreentry guard, and transactional trace-capacity failure. Produce a table-driven independent transition oracle. Complete {ref}`X-T71-004`.

Misconception to resolve: A correct final state can hide a wrong cleanup/action order.

### T71.05 — Bounded active-object queue and failure-preserving dispatch

Explain serialized event ownership, run-to-completion scheduling and the difference between event admission and successful handling in an MCU active object.

The fifth post to a full ring rejects. If CONNECT cannot fit its trace, head/count remain0/4 and OFFLINE stays active. Four successful steps reach FAULT.

Investigation: Compose the HSM with a four-slot copied-event ring; reject overflow unchanged and retain an event whose dispatch fails. Integrate learner-owned execution.tasks and sync.copied_queue through an explicit adapter. Complete {ref}`X-T71-005`.

Misconception to resolve: Preserving a failed event forces a policy for poisoned queues.

### T71.06 — Stackless resumable functions with persistent explicit state

Explain switch-based continuation labels, automatic-local lifetimes, duplicate-label constraints and why suspension across an ordinary function return does not retain a C stack.

Available10, unavailable, available20, available30 produces60 only on the third value. UINT32_MAX followed by1 rejects without incrementing count.

Investigation: Implement the three-value checked summation frame and a PT_BEGIN/WAIT/END version; store every value live across suspension in the frame and reserve label0 and UINT32_MAX. Complete {ref}`X-T71-006`.

Misconception to resolve: Persist ownership and cleanup state along with the program counter.

### T71.07 — Memory behavior trees, running-child ownership and abort

Derive the different control rules of sequence and selector nodes, and distinguish a memory tree from a reactive tree that rechecks earlier guards.

A sequence with successful leaf1 and running leaf2 calls leaf1 once across two ticks, leaf2 twice, and aborts leaf2 exactly once on cancel.

Investigation: Implement bounded validated node traversal, per-composite cursors, running-leaf ownership bits and exactly-once abort on cancellation, with a callback-reentry guard. Complete {ref}`X-T71-007`.

Misconception to resolve: Repeated cancellation must not repeat a destructor-like abort.

### T71.08 — Typestate firmware driver with uncertain DMA ownership

Separate start failure, cancellation intent, hardware quiescence and buffer reuse; identify the trusted adapter facts needed to release an asynchronous loan.

A failed start leaves RecoveryRequired and keeps the exact borrowed pointer. quiet0 completion returns PENDING and cannot feed the watchdog. Successful quiescence permits one release and one normal completion watchdog event.

Investigation: Implement pt_driver_start/complete/recover over the supplied original register/DMA model, retaining buffers on partial start failure. Connect all specified firmware_io and task/queue imports in a source-bound adapter integration. Complete {ref}`X-T71-008`.

Misconception to resolve: A timeout says how long the caller waited, not what the device stopped doing.

## Precise vocabulary

**consuming transition**: A protocol operation that invalidates one admitted token and produces a token for the resulting state, or retains a separate recovery obligation.

**typestate token**: A wrapper identifying the currently admitted operations on a live object; this C model checks its generation at runtime.

**recovery-required state**: A state recording that partial effects prevent nominal reuse until an explicit recovery operation establishes its postcondition.

**presence mask**: A bitset recording which required fields have been supplied, separately from whether their values are valid together.

**staged builder**: An interface that exposes different construction operations according to which configuration stage has been reached.

**binary session**: A communication protocol between exactly two endpoints with a specified sequence of complementary actions.

**session duality**: The relation obtained by exchanging send and receive actions while preserving the corresponding protocol progression.

**hierarchical state machine**: A state machine whose nested active states share event handling and whose transitions have defined ancestor-based entry and exit behavior.

**run-to-completion step**: A dispatch interval during which one admitted event is handled before another event begins dispatch on the same machine.

**external self transition**: A transition whose source and target are the same state but which still executes that state’s exit and entry actions.

**internal transition**: An event reaction that does not exit and reenter the active state.

**active object**: A stateful object that owns an event queue and processes admitted events through a serialized dispatch policy.

**stackless protothread**: A resumable function that stores its continuation label and persistent data explicitly instead of retaining its native call stack.

**memory behavior tree**: A behavior tree whose composites remember the child at which execution suspended and skip earlier completed children on the next tick.

**running leaf**: A behavior-tree leaf whose action has started but has not yet returned a terminal outcome.

**abort callback**: An operation that releases or cancels the resources of a still-running behavior-tree action under a specified exactly-once policy.

## Purpose and outcomes

Turn asynchronous notifications into bounded state machines with clear buffer/descriptor ownership. Local-only transport labs separate stream framing, datagrams, readiness, signal safety and shutdown. The intended result is a mechanism you can explain, a bounded artifact you can inspect and an evidence trail someone else can reproduce. The published workload includes 6 h of explicitly elective project work; a core-only route subtracts those project hours, without removing core awareness.

## Study sequence and teaching

Work through the mechanism notes in order within each project, alternating hand prediction with observation. Preserve the first counterexample rather than only a final green test. Full implementations belong to the projects; these notes explain what they must establish.

### T24.01 — Signal model

Signals have generation, pending and delivery stages; a mask delays delivery and a disposition chooses its action. Restart policy does not make arbitrary interrupted operations safely repeatable.

Investigate: Install a minimal handler with an explicitly allowed action and compare masking with pending delivery. A common mistake is: Signal handlers can use ordinary stdio because only one handler runs at a time. Evidence: A timeline and safety allowlist explain every handler operation and retry decision. Develop that evidence in [PR-T24-01](../projects/PR-T24-01.md).
### T24.02 — Race-free signal integration

Checking a shutdown flag and then sleeping can lose a notification between the two actions. Atomic mask-and-wait, a self-pipe or a synchronous signal interface closes that gap under different contracts.

Investigate: Construct the lost-wakeup schedule, then implement one design with coordinated thread masks. A common mistake is: Adding a volatile flag closes the sleep race. Evidence: A deterministic schedule demonstrates the broken window and the repaired wakeup/ownership path. Develop that evidence in [PR-T24-01](../projects/PR-T24-01.md).
### T24.03 — IPC selection

IPC choice specifies isolation, message boundaries, storage ownership and failure discovery. Shared memory avoids some copies but moves synchronization and participant recovery into the application.

Investigate: Compare a bounded pipe, local socket and shared-record design for one request/reply workload. A common mistake is: The fastest nominal transport is always the simplest reliable choice. Evidence: A selection matrix includes stalled-peer backpressure and ownership after disconnect. Develop that evidence in [PR-T24-02](../projects/PR-T24-02.md).
### T24.04 — Socket lifecycle

Socket creation and connection are state transitions that each acquire or release a descriptor. Address resolution can produce several candidates, and IPv4/IPv6/local names need different representations.

Investigate: Implement a loopback/local-only client/server setup that cleans up every failed candidate. A common mistake is: connect success or accept failure leaves all descriptor ownership obvious. Evidence: A descriptor ledger and failure injection show exactly one owner for each live handle. Develop that evidence in [PR-T24-02](../projects/PR-T24-02.md).
### T24.05 — TCP stream protocols

TCP transports ordered bytes rather than application records. Frames may be split or combined; half-close stops one direction while queued work and the other direction can remain live.

Investigate: Run a length-framed protocol over arbitrary byte chunks with a bounded output queue and explicit reconnect policy. A common mistake is: One send corresponds to one receive. Evidence: All chunk splits preserve frames; half-close and stalled peers follow the stated queue bounds. Develop that evidence in [PR-T24-03](../projects/PR-T24-03.md).
### T24.06 — UDP and datagrams

UDP preserves datagram boundaries but delivery, duplication and order belong to a higher-level policy. Truncated reception must not be mistaken for a valid complete message.

Investigate: Implement a tiny sequence-numbered datagram exercise with declared drop/duplicate handling. A common mistake is: Local send success acknowledges remote processing. Evidence: A scripted loss/reorder trace produces the declared acceptance set and visible truncation errors. Develop that evidence in [PR-T24-03](../projects/PR-T24-03.md).
### T24.07 — Nonblocking execution

Nonblocking state machines retain cursors and ownership between readiness notifications. Would-block is a state transition, not a busy-wait invitation or an error that resets progress.

Investigate: Implement partial receive/transmit cursors and a per-turn work quota. A common mistake is: Readiness guarantees the entire pending operation completes. Evidence: The scripted backend verifies bounded turns, exact byte progress and eventual handling of another ready connection. Develop that evidence in [PR-T24-04](../projects/PR-T24-04.md).
### T24.08 — poll and epoll

Level triggering reports readiness while it persists; edge triggering requires consuming progress until would-block under its contract. Descriptor reuse can make stale events refer to a new logical connection.

Investigate: Implement an LT loop first, then analyze or add ET draining with generation-tagged connection state. A common mistake is: An event’s descriptor number permanently identifies one connection. Evidence: The event trace rejects a stale generation and explains every rearm/drain decision. Develop that evidence in [PR-T24-04](../projects/PR-T24-04.md).
### T24.09 — Timers and notifications

A timer expiry records a deadline event, while callback execution waits for scheduling. Counter-based notifications can accumulate more than one event between reads.

Investigate: Integrate a monotonic deadline queue and declared timer/event counter backend. A common mistake is: A callback ran exactly at the expiry timestamp. Evidence: Deadline, reported expiration count and actual dispatch time are recorded separately under cancellation/reschedule tests. Develop that evidence in [PR-T24-05](../projects/PR-T24-05.md).
### T24.10 — Serial and embedded transports

Serial bytes share framing concerns with sockets but also require transport settings and timeout policy. SocketCAN experiments need a controlled virtual or bench bus, not assumptions about live equipment.

Investigate: Reuse the same parser through a pseudoterminal and test backend; analyze a declared virtual-CAN frame. A common mistake is: Changing the transport makes parser state and buffer limits irrelevant. Evidence: Identical parser vectors pass both backends, while baud/line/CAN assumptions remain separate from protocol logic. Develop that evidence in [PR-T24-06](../projects/PR-T24-06.md).
### T24.11 — Graceful shutdown and overload

Shutdown is an ownership protocol: stop admission, decide whether queued work drains or cancels, notify blocked participants and release resources once. Overload needs a bounded policy before queues grow.

Investigate: Implement queue admission limits and repeated graceful-stop requests with a deadline. A common mistake is: Closing one listener automatically terminates every blocked operation. Evidence: A shutdown state trace accounts for every queued item, descriptor and cancellation result. Develop that evidence in [PR-T24-04](../projects/PR-T24-04.md).
### T24.12 — Advanced I/O

Advanced async I/O adds submission/completion and buffer lifetimes that differ from readiness loops. Copy avoidance may retain or pin buffers longer and does not erase ownership costs. This topic is elective; its implementation project is optional.

Investigate: Electively analyze a pinned io_uring version after inspecting its operation contract, or perform a bounded comparison with the existing event loop. A common mistake is: A newer API is faster for every workload. Evidence: The elective report names operation lifetime rules, complete-workload measurements and evidence limits; no uninspected operation is implemented. Develop that evidence in [PR-T24-07](../projects/PR-T24-07.md).

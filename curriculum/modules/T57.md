# T57: Linux kernel programming and lifetime boundaries

## Purpose and outcomes

Build inspectable Linux teaching modules by deriving the ownership and execution-context rules in a deterministic C model, then testing the actual adapter in a disposable VM. The model isolates ordering errors; it cannot establish Linux concurrency semantics.

## Entry check and remediation

Explain copy_from_user partial-copy convention, distinguish task context from hard interrupt context, and reconstruct reference ownership. If unable to justify a reference acquisition before publication, repair the bounded owner exercise before module work.

## Study sequence and teaching

### T57.01 — Failure-safe module initialization

A successful acquisition creates a cleanup obligation even when registration has not reached its final step. Encode ownership independently from the control-flow label so that every acquired resource is released once in reverse dependency order. Returning an error does not undo allocations.

Show each owned bit has exactly one release and no release precedes its dependents. Relate O(3) model work to the number of real acquisitions, including a failure before endpoint publication.

Misconception and counterexample: Repair forward-order cleanup and double release on a second failure label; a module that returns ENOMEM after leaking work is incorrect even if loading fails.

Investigation: Implement kl_unwind for an ownership mask whose bits0,1,2 mean buffer, workqueue and registered endpoint. Return the decimal release trace with resource numbers3,2,1 in reverse order; unknown bits return0. Derive the acquire/fail matrix, then apply it to the supplied teaching module init labels.

Evidence: Replace one acquisition by a managed device allocation and demonstrate which cleanup obligations migrate to the device lifecycle, including failure after publication.

### T57.02 — User-copy progress and ABI admission

A user copy may stop before transferring the requested span. Its result is a count of bytes not copied in kernel APIs, while a read/write method typically reports completed bytes or an error. Translate between these contracts without treating a user address as a trusted C pointer.

State ownership of unread input, modified prefix and untouched suffix. Explain why a partial-copy return cannot be reused as a negative errno and why cap admission precedes copying.

Misconception and counterexample: A faulty wrapper returns the requested count after a partial copy and exposes stale bytes. Demonstrate the stale sentinel in the original local teaching endpoint without touching other processes.

Investigation: Implement kl_copy into a live disjoint destination with capacity cap. Reject n>cap with -1 before writes; otherwise copy min(n,fault_after) bytes and return the completed count. The model input is ordinary accessible memory; a separate guest adapter must use copy_from_user and preserve its actual return convention.

Evidence: Change the ABI to all-or-nothing record publication using private staging; inject a fault after a valid header and show no record becomes visible.

### T57.03 — Reference acquisition before handoff

A count protects an object only if the operation accessing the count already has a lifetime guarantee. Starting work and incrementing afterward permits the worker to consume the last reference first. Protected lookup needs both table serialization and successful reference acquisition.

Associate every reference with a named owner; count conservation is initial plus successful acquires minus releases. Explain why a nonzero count cannot validate a pointer that may already be freed.

Misconception and counterexample: Reject resurrection after the terminal release and a get-after-handoff schedule. Delaying free alone masks the ownership race condition without creating valid ownership.

Investigation: Implement kl_ref with op0 acquire and op1 release for a live KLRef initialized to {1,0}. Reject unknown operations, zero/dead acquisition and UINT_MAX overflow; reject repeated release. Last release sets dead exactly once. Failed transitions preserve the struct. Map each transition to kref_init/get/put and protected lookup in the VM adapter.

Evidence: Add a lookup table and compare mutex-protected get-unless-zero with RCU-protected storage lifetime; show why refcount and grace period solve different obligations.

### T57.04 — Context-sensitive locking

Lock selection includes who can preempt whom and whether the operation may sleep. CPU-local interrupt exclusion does not serialize another processor. PREEMPT_RT changes ordinary spinlock behavior; a successful test without `PREEMPT_RT` does not establish the corresponding `PREEMPT_RT` behavior.

Derive preemption, migration, interrupt and inter-CPU exclusion separately. A lockdep trace is evidence for exercised lock-order paths, not a proof of all schedules.

Misconception and counterexample: Repair a `PREEMPT_RT` hardirq path that uses ordinary spinlock_t and a cross-processor race condition hidden by local interrupt disabling. The host truth table assesses policy only.

Investigation: Implement kl_lock_allowed(context,kind,rt) for conservative teaching policy: context0 task,1 hardirq,2 softirq; kind0 mutex,1 spinlock_t,2 raw_spinlock_t. Mutex is task-only; raw lock is allowed in all three; ordinary spin lock is allowed in all contexts without `PREEMPT_RT` and only task context in this restricted `PREEMPT_RT` exercise. Reject out-of-range fields. Defend why the policy is deliberately narrower than all Linux APIs.

Evidence: Move a callback from task context to threaded IRQ and then hardirq; revise allocation and lock choices and retain the failed and corrected guest traces.

### T57.05 — Work cancellation and terminal ownership

Cancellation is a request to prevent or stop future work, not permission to free storage while a worker can still access it. Teardown closes admission first, then drains or cancels work and only then releases its owner.

Prove release implies quiescence and closed admission. Compare cancellation return values with work ownership; do not hold a lock required by the worker while synchronously draining it.

Misconception and counterexample: A faulty release ignores running work after close; the sentinel release flag demonstrates premature destruction. A deadlock also occurs if teardown waits while holding the worker lock.

Investigation: Implement kl_work for serialized state {queued,running,closed,released}. Events0 submit,1 begin,2 complete,3 close,4 release. Admission fails when closed or occupied; begin transfers queued to running; complete requires running; close is idempotent; release succeeds only once when closed and neither queued nor running. Rejected events preserve state.

Evidence: Allow a worker to requeue itself; introduce a closure generation and prove no requeue survives the close linearization point.

### T57.06 — RCU read-side lifetime model

Read-copy-update separates removal from reclamation. A reader that began before removal may still hold the old pointer. A grace period concerns the relevant readers, not elapsed wall time.

Show removal prevents new lookup while preexisting readers retain storage lifetime. Identify how refcount acquisition extends ownership beyond a read-side section and why the section alone does not do so.

Misconception and counterexample: Repair immediate reclamation on unlink; delayed arbitrary sleeps are not grace-period proofs. Host bitmask traces cannot validate actual RCU memory ordering.

Investigation: Implement kl_grace with events0 enter reader bit id0..7,1 leave,2 retire,3 reclaim. Enter rejects duplicate IDs and admission after retirement; leave requires membership. Retirement is idempotent. Reclaim succeeds only after retirement with no readers and clears retired. This fixed-reader model is intentionally stronger than general RCU and must be mapped critically to the real primitive.

Evidence: Permit readers of a replacement object after retirement; tag reader epochs and show waiting for all new readers can cause unnecessary starvation.

### T57.07 — Versioned kernel control records

Kernel control interfaces outlive one process build. Parsing native structs imports alignment, padding and pointer-size assumptions into the interface. A version and exact-length rule let incompatible messages fail before changing state.

Demonstrate exact-length admission and byte-order independence; distinguish ABI versioning from ISO C object representation and kernel/user pointer validation.

Misconception and counterexample: Repair acceptance of a mismatched embedded length and a cast of unaligned user bytes to a native struct. A correctly decoded version does not authorize an operation.

Investigation: Implement kl_decode on octets [version=1,length=2,lo,hi]. Require exactly4 bytes, decode little-endian16 into unsigned output, and leave it unchanged on all rejection. Then design a fixed-width ioctl or read/write adapter without embedding host pointers, documenting compatibility behavior.

Evidence: Add a version2 optional field while preserving version1 bytes; compare strict rejection, ignorable extensions and per-operation authorization with adversarial tails.

### T57.08 — Unload defense and integrated lifetime audit

Object references, callback references and references to module text can have different owners. Unloading a driver requires closing all ways to acquire them and waiting for outstanding users; empty work queues alone do not prove that open handles disappeared.

Construct a global ownership graph and identify the linearization point of shutdown. Give separate evidence for module pinning, object release, callback quiescence and bounded wait policy.

Misconception and counterexample: A module unloads after the last open handle while a callback still retains its function pointer. Demonstrate rejection in the model; any guest fault stays inside the disposable VM.

Investigation: Implement kl_can_unload(open_handles,pending_callbacks,closed) returning true only for closed==1 and both counts zero. Reject closed>1. Integrate the previous model with the teaching module: enumerate every close, completion and last-put ordering and provide a guest unload dossier showing why no callback can reach released state or unloaded text.

Evidence: Add hot-unplug while two open handles remain: choose revoked operations versus retained detached objects, and justify error propagation and final cleanup under both close orders.

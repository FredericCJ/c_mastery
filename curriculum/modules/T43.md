### T43.01 — Cost contracts and observable work

A complexity statement needs a cost contract. The same sort can have n records, four-byte keys and a variable-size comparator payload: those are different size measures. “One comparison” is constant only in a model that fixes its cost. Declare successful and failed operations, output size and the case quantifier before counting. Then choose a work vector instead of prematurely collapsing comparisons, moves and probes into a time estimate.

For [4,2,5,2,1,4], each earlier key greater than a later key must cross it under insertion sorting. Eight inverted pairs explain eight shifts. The scan also makes stopping comparisons, giving eleven comparisons; five final placements add to thirteen destination writes. Equal keys illustrate why comparisons can occur with no shift. Trace these events on the accepted T15 kernel in [PR-T43-01](../projects/PR-T43-01.md), preserving stability.

The misconception is that a profiler number supplies the omitted model. It does not: instrumented event counts, retired instructions, target cycles and a static CFG measure have different definitions. Mastery evidence names all boundaries and predicts the count vector before running C.

### T43.02 — Asymptotic bounds and finite scaling evidence

Big-O says there exist a positive constant c and threshold n₀ bounding the named function above thereafter. Big-Ω supplies a lower bound; a tight Θ statement needs both. For f(n)=3n²+5n+7 and n≥1, n≤n² and 1≤n² give 3n²≤f(n)≤15n². The constants are witnesses; deleting lower terms without the quantifier is not a proof. The worst-case function is the maximum cost over valid inputs of a given size, so a lower bound on that maximum does not assert every input costs as much.

Output matters: a traversal contract 3V+2E+Z yields O(V+E+Z) under fixed record/edge work. If output generation emits Z records, an expression that erases Z may miss the dominant cost. Use [PR-T43-01](../projects/PR-T43-01.md) for the quantified proof and multi-parameter worksheet.

Measured slopes are finite evidence. A function equal to n through 128 and n² afterwards looks linear at 2,4,8,16, yet costs 16900 at 130. Construct that counterexample and explain why an upper bound is neither necessarily tight nor a universal finite-size speed ranking.

### T43.03 — Aggregate, accounting and potential analysis

Amortized analysis bounds a sequence without a probability distribution. A table growth may cost Θ(m) once while total cost over many appends is linear. Aggregate analysis adds actual costs; accounting precharges operations and keeps nonnegative credit; potential records stored work in state. Each method must name its initial state and cost primitive.

Twelve appends from an empty doubling table cost 27 unit insert/copy operations, with the ninth append alone costing 9. Charging 3 per append gives 9 credits left after twelve and no negative prefix. For Φ=2·live−capacity, Φ₀=0 and Φ₁₂=8, so Σĉ=Σc+Φ₁₂−Φ₀=35. The initial append costs amortized 2; later ones cost 3. This is a deterministic expansion certificate, not an expected average over workloads.

In [PR-T43-02](../projects/PR-T43-02.md), extend the accepted T14 table with prefix rows and a nonempty-initial-state variant. Preserve allocation-failure behavior separately. Unit copies exclude allocator latency, cache stalls and arbitrary destructor work. Show actual rows, the telescoping identity and the 96-byte transient old/new payload capacity before claiming mastery.

### T43.04 — From work to instructions, cycles and bottlenecks

An executed instruction count depends on the selected path and generated code. A cycle model additionally depends on the target's instruction/stall assumptions; elapsed time depends on clock and observation boundary. The processor equation IC×CPI/f helps separate these terms. A linear primitive count can cross cache/branch thresholds or run under different clocks, so it need not produce a universal linear-cycle relation.

The original mix 100×1+40×2+20×4 gives 260 cycles for 160 instructions: CPI 1.625. At 100 MHz, that is 2.6 µs, not 260 ns. Under a separate affected-fraction model, improving 40% of work by a factor two bounds total speedup to 1/(0.6+0.4/2)=1.25; untouched work remains. These are model calculations, not timings for either ISA.

Reuse the T36 callable kernel and T37 quantitative artifact in [PR-T43-03](../projects/PR-T43-03.md). Count an executed path, compare with identified measurements, and explain a residual. Include code bytes, branches and connected-function cyclomatic e−n+2 as distinct measures. Equal static graph complexity says nothing automatic about repeated loop work or processor cycles.

### T43.05 — Storage boundaries and lifetime peaks

Space is also a model with boundaries. Live payload, reserved capacity, retained inactive storage and scratch may overlap in time. A shared owned object is counted once, even if two views point into it. Peaks must be calculated on simultaneous states, not by adding independently occurring maxima. Static sections and measured resident/charged memory are other categories.

At time 3 the fixture has 64 live work bytes plus 80 scratch bytes: live peak 144. At time 7 work/result capacity is 128+96=224, while their payload is only 88. At time 10 work's 128 bytes remain retained although its live interval has ended. Summing 144+224+128 would count overlapping storage repeatedly and combine different times.

For stack, a .su record describes a function frame and qualifier. A feasible main/work/leaf chain is 32+48+16=96; main/other is 112. A stipulated 24-byte nonnested interrupt allowance makes 136 only for the declared known paths. Unknown callbacks, recursion or unbounded dynamic records remain unresolved. [PR-T43-04](../projects/PR-T43-04.md) pairs the original ledger with actual compiler/section evidence; a sampled watermark or .bss total cannot certify a whole-program stack maximum.

### T43.06 — Block transfers, locality and amplification

An external-memory model counts transfers of B fixed-size items between main memory M and a larger sequence N. The bounded activity fixes one disk/processor and a stated replacement/write policy. It is useful because locality can change transfer counts while comparison counts remain similar. It does not prescribe disk service latency or every bus transaction.

With four-byte items, B=2 and M=4, reading items 0..7 needs four eight-byte blocks: 32 bytes transferred for 32 useful bytes. A mixed read/write stream transfers 48 for 28 useful bytes, amplification 12/7. Dirty eviction and the final flush both matter. No-reference input has denominator zero and an undefined amplification ratio, including 0/0.

In [PR-T43-05](../projects/PR-T43-05.md), add a bounded traffic adapter to existing T37 reference reasoning. Show residents, recency and dirty status at each reference. Contrast model transfers with file/syscall/device observations: warm pages, buffering, readahead and shared writeback can change the mapping. A cache miss, syscall and physical block I/O are not interchangeable events. Mastery retains item/byte units and a named layer for every ratio.

### T43.07 — Component runtime, overlap and completion

Component runtime needs events rather than one undifferentiated duration. A blocking return can include completion. Asynchronous submission returns acceptance, while completion and safe buffer release have separate boundaries. A fast operation can complete before its submission function returns; event semantics, not a preferred diagram shape, decide validity. POSIX AIO is the bounded concrete comparison here, with one result collection after completion and valid borrowed request/buffer storage while pending.

Submission 0, return 2 and completion 12 yield call span 2 and latency 12. Overlapping phases [0,2],[1,11],[10,12] sum to 14 but cover a union of 12. Two threads can consume 15 CPU units in that 12-unit elapsed window. Wall-minus-process-CPU then becomes −3; it is not a universal waiting estimate. Serial nested attribution can calculate exclusive time under a complete call model, but that rule cannot blindly subtract concurrent phases.

[PR-T43-06](../projects/PR-T43-06.md) adds an event adapter to accepted components. Define throughput's completed-item numerator and observation window. Submit separate serial/overlap and CPU/elapsed evidence, including completion-before-return, rather than inferring hidden work from one timestamp.

### T43.08 — Read/write performance and persistence

A request count is not an accepted-byte count. Positive read/write results advance by exactly that many bytes; interruptions or nonblocking unavailability need explicit bounded policy. A zero read means EOF, while the chosen bounded write adapter stops on zero progress. Terminal errors preserve the already accepted prefix instead of replaying it or concealing it.

Writing eight bytes through returns 3,EINTR,2,EAGAIN,3 accepts eight in five attempts. Buffered write completion at 8 followed by successful requested fsync at 13 has a five-unit synchronization phase. A separate device-byte observation can exceed the logical file size; the synthetic 4096/8 ratio is 512. The file, buffered transfer and media/accounting layers answer different questions.

Extend T23 in [PR-T43-07](../projects/PR-T43-07.md). Preserve native file-byte verification, requested synchronization results and warm-state/file lifetime. Successful write alone does not establish durable storage; a delayed fsync error remains significant. Directory-entry synchronization is separate where creation/rename matters. No timing sample demonstrates survival under all crashes or power failures. Mastery reconciles these boundaries without an unbounded retry loop or a global cache flush.

### T43.09 — Experimental protocol, clocks and uncertainty

Choose a clock contract before collecting numbers. CLOCK_MONOTONIC can be frequency adjusted and excludes suspend; RAW avoids that adjustment and also excludes suspend; BOOTTIME includes suspend. Process CPU counts all threads, thread CPU one thread. Resolution is a stated granularity, not accuracy or bracket overhead, and consecutive valid timestamps can be equal. Integer conversion and return errors belong in the harness contract.

For paired A/B samples, analyze each pair before summarizing. The fixture medians 102 and 98 differ by 4, while the median paired improvement is 3. Nearest-rank p95 at N=5 selects the largest sample. An empty-bracket median 11 yields a 91-unit subtraction sensitivity; it does not prove a removable constant overhead. Small signals require a changed bracket or an inconclusive conclusion.

[PR-T43-08](../projects/PR-T43-08.md) adds one controlled condition and at least 31 raw pairs to existing harness work. Retain warmup, order, checksum, outliers and clock identity. Report observed deadline misses/reference jitter and confounders. Sample quantiles and maxima describe the recorded trials; they are not WCET or a universal deadline guarantee.

### T43.10 — Linux PMU counting and sampling boundaries

PMU counters observe selected events under hardware, kernel, privilege and scheduling constraints. Identify target, event meaning, binary and permitted user/kernel scope. Generalized cache references are not universally load counts; unsupported or denied events are unavailable rather than zero. The source baseline does not promise access on a stricter distribution/container.

When raw instructions=1200 and cycles=3000 with enabled=20/running=10, extrapolated values are 2400 and 6000. A co-scheduled matching group gives CPI 2.5. Positive running time is necessary; zero supplies no finite scaling. Matching numeric intervals on unrelated groups do not make their ratio trustworthy. Scaling assumes the observed partial interval represents the rest; a nonstationary workload can defeat that assumption.

In [PR-T43-09](../projects/PR-T43-09.md), extend the accepted T34 raw ledger and preserve permitted or denied actual output. Relate a usable event to the work contract, and compare grouped count/sampling evidence without treating attribution as ownership. The finite certificate checks result semantics. It does not prove PMU availability, target cache behavior or reconstructed unobserved counts.

### T43.11 — cgroup CPU, memory and I/O accounting

cgroup v2 supplies resource policy and scoped accounting. cpu.max configures temporal fair-class bandwidth; cpu.stat observes usage/throttling. memory.current is a charged-memory gauge; high/max are different control boundaries. io.stat reports keyed major:minor counters, whereas io.max configures limits. Delegation and ancestor constraints decide who can change what. A useful read-only investigation needs no new privileges.

The original snapshot adds 800 µs CPU in a 2000-µs window, fraction 0.4; a configured 500/1000 quota ratio is 0.5. They need not coincide. memory.current can decrease while historical memory.peak is 12288. Reset semantics apply to subsequent reads on the same open descriptor; without that reset no fresh-window peak is established. Per-device byte deltas and PSI totals have their own units; pressure is not exclusive component waiting.

[PR-T43-10](../projects/PR-T43-10.md) parses by key and distinguishes absent controllers from zero. Core route reads permitted files or records denial plus captured analysis. A prepared delegated experiment is optional and preserves/restores authorized state. Filesystem writeback support/shared-inode attribution, descendants and counter reset remain limits. Show policy versus observation and avoid a false isolated-memory claim.

### T43.12 — Compiler-based profiling and its perturbation

Compiler instrumentation observes a changed program. -pg needs matching compile/link boundaries and a supported runtime; --coverage counts selected execution arcs, not elapsed time. Entry/exit hooks can give a bounded serial call ledger, but must exclude themselves and avoid recursion/allocation/I/O hazards. Conceptual inline calls, code growth, dropped records and nonlocal exits limit completeness.

For complete work [0,9] containing child [1,4] and [5,7], inclusive work is 9 and exclusive work 4. A truncated buffer with open frames cannot supply exact durations. gprof samples self CPU time and propagates child time using an average-per-call assumption: two cheap/expensive caller populations can invalidate it. The original 20-ms child with two A/eight B calls predicts 4/16 ms, but declared actual 16/4 gives ±12-ms error. Off-CPU I/O delay is absent from that self-time estimate.

[PR-T43-11](../projects/PR-T43-11.md) uses a reused single-threaded component, matched baseline, bounded hooks and a supported/unavailable gprof comparison. Record measured perturbation and code/.su changes. Mastery separates counts, samples, inferred children and elapsed waiting boundaries rather than calling instrumentation transparent.

### T43.13 — Bare-metal cycle and timer measurement

CYCCNT is an optional 32-bit processor-clock counter. Exact Armv7-M architecture addresses/fields are the start of an access contract, not proof that every board has an available counter. DEMCR.TRCENA must make trace reads meaningful; with it clear, DWT reads are UNKNOWN. Counter presence, access, enable, clock, device errata, interrupt/debug conditions and setup ownership must be checked before a claim.

Endpoints 4294967280→48 have a modulo delta 64. Only an independent interval bound below 2³² rules out additional wraps. At 16 MHz that is 4000 ns; removing an eight-cycle empty bracket yields a sensitivity 3500 ns. Debug state stops the counter, so halt-spanning active cycles cannot simply represent wall time. An unknown/absent counter is not a zero-cycle result.

[PR-T43-12](../projects/PR-T43-12.md) requires the captured/static certificate. Optional silicon execution follows its firmware-specific gates and reuses existing setup/kernel/timer work. Preserve other debug bits and users; never reset a shared counter merely for a tidy sample. Timer/GPIO alternatives name their own clock/resolution observer. Emulators support correctness evidence, not measured silicon cycles, energy or sampled-tail WCET.

### T43.14 — Choosing useful measures and making a performance decision

Choose measures from requirements. Useful work units, cycles/time, completed-item throughput, per-item latency, peak/retained space, code size, branches/traffic and deadline jitter form a vector. A single score can conceal an unacceptable resource. Energy needs a documented observable/instrument or declared physical model; elapsed time alone is insufficient. Cyclomatic complexity is a static design/test aid, not either Big-O or runtime cycles; feasible paths and fault freedom remain separate.

Variant B is faster in the fixture's model (240 versus 260 cycles) but exceeds both code and retained-storage limits. A is the accepted candidate. Equal cyclomatic v=3 graphs have sequential 2n versus nested n² body work; that shared static number cannot settle a speed decision. A different traffic/jitter constraint could change the accepted choice again.

Complete [PR-T43-03](../projects/PR-T43-03.md)'s reserved decision dossier after the observation projects. It must cite the requirement, each accepted/rejected candidate, omitted measures and revision/build/workload. Label algebraic proof, finite fixture arithmetic, actual learner runtime and optional silicon/energy separately. A rigorous inconclusive or baseline-retention decision can pass; a fast number with missing boundaries cannot.

## Reading guidance

Use the front-card locators as bounded assignments. CLRS supplies formal quantifiers and deterministic prefix proofs; it does not predict allocator or target time. The architecture equation is a declared model; recompute its units and exclude the known inconsistent copied numerical examples. Vitter defines fixed-item block parameters; its historical device numbers are not today's measurements. NIST supplies the connected-function static CFG convention and its feasible-path limits.

Read Linux interfaces alongside the specific observation adapter: clocks/AIO/read/write/fsync before phase logs; PMU/security before permitted counts; cgroup/PSI before interpreting keyed snapshots. GCC/gprof scopes govern matching builds, stack qualifiers and perturbation. The exact Arm scopes govern only the optional counter certificate and ownership/presence/halt boundaries. Assigned reading cards total 15 hours; use the remaining 3 reading hours to recompute formulas, compare actual tool records and annotate the accepted source scopes. Wider chapters, additional PMU tables or board-specific setup recipes require fresh inspection before becoming an assigned authority.

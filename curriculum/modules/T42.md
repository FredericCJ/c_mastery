# From-scratch HTTP server over OS sockets

## Purpose and outcomes

Build an original bounded HTTP/1.1 origin server in C. It owns incremental octet parsing, framing, routes, serialization, descriptor/buffer lifetime, bounded queues and deadlines. It listens on loopback 127.0.0.1:8080. The OS supplies TCP/IP and lower layers. This is the third communication family; the first is the original seven-layer protocol and the second supplies its own Ethernet-to-TCP implementation. The portable HTTP core developed here is reused by the second family.

## Entry check and remediation

Demonstrate span bounds and retained-pointer lifetimes; predict short read/write/EINTR/EAGAIN behavior; trace an event-loop resource acquisition and cleanup; derive checked integer accumulation. Reuse T15/T18 parsing/ownership and T23/T24 Linux adapters. A failed prediction returns to those exact mechanisms before implementing a larger server. Inspect the shared contract and distinguish octets, TCP stream, HTTP message and application representation. Do not assume that one read contains a request.

## Study sequence and teaching

### T42.01 — Socket lifecycle and layer ownership

A socket delivers an ordered stream whose chunk boundaries belong to the current call, not to HTTP. OS TCP performs sequence/retransmission work. The application owns descriptor lifecycle, byte retention and message interpretation. Reuse the earlier Linux accept/event adapter, then attach four explicitly owned connection records. Accept readiness is only a hint: another action can consume the pending connection, so EAGAIN returns to the event loop. On Linux an accepted descriptor does not inherit the listener's nonblocking status; set and verify flags explicitly. A failed initialization must close the descriptor exactly once before publishing a record.

Trace accepted descriptors 11,12,13,14 into four slots. Descriptor 15 cannot acquire a slot and is closed. Releasing 12 allows 16 to enter; no reference to 12 may survive in a queued event. Add a generation number to distinguish a recycled descriptor number from the old connection. Record this invariant: every live descriptor has one owner and every published record has a valid descriptor. A readable listener does not guarantee a successful accept, and an open socket does not establish an HTTP session. Evidence includes flag inspection, an accept-race trace, injected exhaustion, resource counters and an explicit layer-ownership map.

### T42.02 — Incremental request grammar and target authority

Treat input as bounded octets. A recv call may stop between CR and LF, between a field name and colon, or inside a request target. Save state and the precise consumed offset; never append a NUL then assume all octets are text. The strict project grammar uses one SP between request-line elements and CRLF delimiters. Field names use the HTTP token alphabet and case-insensitive matching; whitespace before the colon, folding, NUL and invalid controls cause rejection before publication. Strict recipient policy is allowed here but is not a claim that the RFC has no tolerant parsing provisions.

For a GET header ending at offset 46, feed prefixes of lengths 0 through 46. Every proper prefix reports NEED_MORE with no complete request; the final LF completes the header once. Feeding two headers in one span completes only the first and returns its consumed length, leaving the second unchanged. Absolute-form http://localhost:8080/health selects authority localhost:8080, even if the syntactically valid single Host says other.example. Origin-form uses the single Host. Validate bounded configured host/port authorities; do not implement filesystem normalization. Missing/duplicate/malformed HTTP/1.1 Host returns 400 and close. A complete header is not yet a complete body. Retain split/coalescing, target-authority and smallest malformed-octet evidence.

### T42.03 — Header normalization and unambiguous message framing

After headers, select exactly one body mode. The method name does not define the wire boundary: a GET can carry framed content, while a POST without length fields has zero request-body length. This project consumes a framed body before routing even when a route later rejects it. NONE means zero body; LENGTH requires exact unsigned decimal syntax; CHUNKED means the decoder owns termination. Header lookup must retain duplicate occurrence counts rather than overwriting one field with another.

Derive a checked decimal accumulation condition before each multiply/add using the declared maximum 4294967295. Then apply the 1024-byte body cap. An overflowing numeral is 400; a representable declared body above the cap is 413. Identical duplicate Content-Length is conservatively400+close. TE+CL is always400+close, rather than choosing whichever parser seems convenient. Check syntax and framing before unsupported decoding: a request whose final coding is not chunked is 400+close. Thus gzip alone and chunked,gzip are 400. Repeated chunked, malformed token lists and chunked parameters are 400. A valid gzip,chunked list is framed but requires an unsupported decoder, so it is 501+close. The declared strict profile rejects other parameterized coding lists with 400; this is a syntax-subset policy. For LENGTH 5 and input abcdeGET..., consume exactly five body octets; GET belongs to the next message. Premature EOF after four bytes is incomplete and cannot dispatch a successful echo. Produce the framing-decision table, byte-conservation ledger and overflow counterexamples.

### T42.04 — Chunked decoding, extensions and trailers

Chunked transfer encoding is a framing grammar. Maintain SIZE_LINE, DATA, DATA_CRLF, TRAILERS and COMPLETE states with independent counters. Hex accumulation and aggregate size are checked before accepting bytes. A valid bounded unknown extension is syntactically parsed and ignored; rejecting every unknown extension would evade the receiver contract. Trailer fields are validated in separate bounded storage and discarded. They never replace Host, Content-Length or routing decisions.

Trace 3;x=y CRLF abc CRLF 2 CRLF de CRLF 0 CRLF X-Debug: ignored CRLF CRLF. The representation is the five octets abcde. The zero-size chunk ends data but does not finish the message until the trailer section's final empty line. A CR split across reads is still pending state, not an optional delimiter. The supplied invalid trace puts X where the data-ending CR belongs and returns 400+close; the incomplete trace has no terminal empty line and publishes no body. Check every byte split, extension/trailer capacities and EOF in every state. Keep decoded content separate from wire byte counts; the wire overhead is not echoed.

### T42.05 — HTTP semantics, routing and response serialization

Routing begins only after a complete admissible request, except that header-determined errors and 100-continue need early handling. GET and HEAD /health select the representation hex `6f6b0a`: three octets, including LF. HEAD sends its GET-equivalent Content-Length: 3 with no representation body. POST /echo returns identical bounded octets, including NUL and non-UTF8 values. Unknown route returns 404. A recognized method disallowed on the selected route returns 405 and route-specific Allow; an unknown method returns 501. Declare bounded supported methods GET, HEAD, POST and distinguish recognition from permission.

Every HEAD response suppresses content, including error responses. HEAD /unknown therefore reports the selected ten-octet error representation length and sends zero body octets. HEAD /echo reports 405 with Allow: POST and the selected nineteen-octet error length, again with no body. Preserve representation metadata separately from actual serialized content.

For an admissible POST with Expect: 100-continue and body not yet received, enqueue the interim 100 immediately, then wait for the framed body. If headers already establish an error, enqueue that final error instead. Waiting for the body before 100 can deadlock a cooperative client. Emit Date using a reasonable UTC clock; fixture epoch 1672531200 yields Sun, 01 Jan 2023 00:00:00 GMT in the required fixed-date format. Use a separate monotonic clock for deadlines. Length is an octet count, not Unicode character count. User data never becomes unchecked header syntax or a format string. Evidence includes exact serialization, binary echo, HEAD boundary, Allow and expectation traces.

### T42.06 — Partial output, persistence and pipelining

Keep immutable response storage until every queued byte is locally accepted or the connection aborts. A send of four bytes advances the offset by four; EINTR and EAGAIN advance it by zero. Sending again from offset 0 duplicates output. POLLOUT interest is needed only while pending bytes remain; a permanent writable interest can spin an otherwise idle event loop. Local send success is not evidence that the peer application consumed the response.

For nine output octets and results 4, EINTR, 2, EAGAIN, 3, the retained offsets are 4, 4, 6, 6, 9. A two-entry request queue holds requests 1, 2 and pauses parsing 3. Persistent responses remain FIFO even if their computation costs differ. The default maximum is four requests per connection; the fourth response announces close. If request 2 requests Connection:close, 3 is never dispatched. Drain the final response, shutdown the write direction, then receive/discard remaining bytes only until EOF or the 1000 ms drain deadline, and close. The discarded bytes are not new requests. Record read backpressure, output retention, FIFO and close-state transitions with tiny-send and coalesced-input tests.

Interim responses preserve association too. If a pipelined second request expects 100-continue, queue its interim response after the first request's final response and before its own final response. Decide on 100 as soon as the admissible headers are complete; that decision cannot preempt an earlier response's bytes. Apply bounded output backpressure while the client waits for the ordered interim response.

### T42.07 — Deadlines, resource limits and transport failure

Resource limits are part of the state machine. Idle activity and total elapsed request time are independent. A byte every four seconds can keep a five-second idle timer fresh while violating a fifteen-second total request deadline. Do not renew the total deadline on every byte. Bound headers at 8192 octets, 32 fields, target 1024 octets, body 1024 octets, extension 128 octets per chunk and trailer 1024 octets/eight fields; apply limits before storing. Track four connections, two complete queued requests and four requests per connection. Derive actual memory from chosen representations, including retained spans, output, queues and error paths.

With request start 0, progress at 4000, 8000, 12000, 14900 ms and now 15000 ms, idle has not expired but the total deadline has. A request timeout returns bounded 408+close where output remains usable; output timeout aborts and makes no completed-response claim. POLLHUP may arrive with readable buffered bytes: consume those before treating recv 0 as EOF. A half-close after a complete request can still allow its response; one inside a declared body remains incomplete. EPIPE/reset aborts output and releases ownership. Retain monotonic-clock traces, failure-state distinctions and allocator/descriptor high-water evidence rather than calling every close successful.

### T42.08 — Parsing security and independent interoperability

A parser boundary is a security boundary because two participants can disagree on where a request ends. Compare your exact framing decisions with an independent raw client and the current RFC contract. A mature client is an oracle peer, not permission to import an HTTP parser/server library. Reject unsupported CONNECT or Upgrade with a final error and close; optimistic following bytes never become another dispatched request. RFC 9931's inspected CONNECT proxy requirements are background authority, while this origin-server rejection policy is an original declared policy.

Run curl for GET, HEAD, binary POST and expected 100-continue behavior, and a separate raw-octet peer for duplicate lengths, TE+CL, invalid controls, chunks, pipelines and half-close. Packet segmentation, socket read chunks and HTTP messages are three different units. Save normalized status/header/body results and exact byte traces where framing matters. Test that the same request under all partitions produces one result and that a close/error prevents any second application effect. Publish component/source/dependency ownership, unresolved deviations and limits. Plain loopback HTTP has no TLS, proxy or production deployment claim. Static fixture checks cannot replace executing and inspecting the learner's original C.

## Reading guidance

Read UNP for the short-I/O mechanism, then extract the current Linux return/error and readiness rules. Its blocking helpers are explanation rather than event-loop code to copy. Read RFC 9112 in the order grammar → framing → chunking → persistence/teardown, constructing a decision table for the project instead of reading the entire protocol at once. RFC 9110 supplies method/expectation/Date semantics; it cannot replace wire-framing rules. RFC 9931 updates HTTP/1.1 transition security with explicitly scoped CONNECT proxy requirements.

The assigned table contains exact inspected passages. Adjacent RFC sections may be consulted as reference; assigning new obligatory passages requires inspection and registry extension. Distinguish the RFC obligation, a stricter original resource/syntax policy and an excluded capability in the evidence ledger. Current primary contracts take precedence over old textbook behavior.

## Environment and limits

The hosted executable uses profile A; parser/router/serializer components use profile C with caller storage, allowed type headers and explicit time/config callbacks. Audit compiler helpers and callbacks separately; no external HTTP library implements the studied mechanisms. Linux-specific MSG_NOSIGNAL, descriptor flags and poll behavior are declared platform contracts. curl and raw clients are verification peers only. The server is plain loopback HTTP with bounded routes, not TLS, a proxy, a filesystem server, a tunnel or a production deployment. Hardware lower-layer closure belongs to T40/T41 and cannot be claimed from these sockets.

# T48: A small isolated x86-64 operating system

## Purpose and outcomes

Build an original bounded kernel that runs isolated user programs, preempts them, provides checked services and persists a VM/store result through its own block driver. The supplied bootloader, emulator and packaging are explicit infrastructure. Fourteen small milestones contribute 138 implementation/verification hours; 26 reading, 10 assessment and 12 consolidation hours make a 186-hour module estimate. Actual time and remediation must be recorded, not hidden behind this estimate.

## Entry check and remediation

Before entering, derive a callable assembly ABI, inspect an ELF/map, implement checked span parsing, and account for fixed/stack storage. Complete the named foundations; T46/T47 are additionally required before projects 12/13. Earlier boot, interrupt, ownership, algorithms and debugger artifacts are reused by original ID and not charged as new implementations.

## Component progression

Boot and inspect first; validate boot data; establish traps and frames; construct isolated process memory; regain control through a timer; load bounded images; expose checked services; then add a real queue/block driver. The shell, VM and durable store are clients. The OS route is x86-64 with its necessary small 32-bit transition; Thumb remains the separate microcontroller/runtime target.

## Study sequence and teaching

### T48.01 — Boot contracts and the long-mode transition

GRUB supplies a 32-bit protected-mode entry, not a ready C environment. Preserve EAX/EBX, make the initial stack and page tables, load a GDT, enable PAE and long mode, then enter the 64-bit code segment. Our four-GiB supervisor identity map uses 2048 two-MiB entries; it includes the fixed PC MMIO window without exposing it to user mode.

Write the Multiboot2 header, original transition assembly and link layout. Inspect entry address, header checksum and map before stepping the transition. Audit undefined symbols and distinguish bootloader service from learner-owned entry code.

A discriminating failure campaign includes: wrong header checksum, lost EBX, malformed CR3 alignment, absent far jump, wrong C stack alignment and accidentally linked hosted startup. The gate is concrete: Boot the selected QEMU guest to the first serial marker and retain disassembly, register trace and ELF/map identities. Explain every supplied and owned operation.

Develop and assess the evidence in {ref}`PR-T48-01`.

### T48.02 — Bounded boot information and memory reservations

A boot tag carries a byte size; the following tag starts at its eight-byte-rounded end. Check the raw extent before rounding or reading fields. Preserve the module, boot structure and kernel physical ranges before giving any page to a process. Reserved overlapping map entries win over usable entries in this teaching allocator.

Decode tags by explicit field widths, accepting larger compatible memory-map entry strides. Require one bounded module and one map. Generate truncated headers, invalid strides and overflowing physical ranges before using actual GRUB input.

A discriminating failure campaign includes: size below eight, rounded tag beyond total size, overflowing base plus length, missing terminator, duplicate required tag and reserving only kernel .text. The gate is concrete: Pass kernel_boot and retain an actual boot reservation ledger. A synthetic tag at offset 8 with size 21 must advance to offset 32.

Develop and assess the evidence in {ref}`PR-T48-02`.

### T48.03 — Serial diagnosis and normalized exception frames

A trap enters asynchronously, so ordinary function-call preservation is insufficient. Normalize the hardware error/no-error cases, save all general registers and retain the interrupted CS/RIP/flags/stack. The kernel uses a separate double-fault stack and does not execute floating-point/SIMD instructions.

Implement bounded serial output, GDT/TSS/IDT setup and original assembly save/restore. Draw the 15 saved general registers, vector/error pair and five-word hardware frame before writing the C frame declaration.

A discriminating failure campaign includes: wrong pushed-word order, missing error placeholder, insufficient stack alignment at a C call, invalid TSS descriptor and returning with the wrong operand size. The gate is concrete: Retain a real saved-frame trace and successful return. In the declared frame there are 22 eight-byte words; the software declaration must agree with assembly.

Develop and assess the evidence in {ref}`PR-T48-03`.

### T48.04 — Physical frames and explicit page-table ownership

A frame belongs to exactly one allocation state: reserved, free or allocated. Alignment is necessary but not sufficient for release. Address translation is a separate structure: every process owns its user mappings while supervisor mappings remain inaccessible from ring 3.

Build the bitmap/state allocator from boot memory, then create per-process tables. Zero newly exposed frames. Roll back a partly fulfilled allocation and delay reclaiming an exited process until another address space is active.

A discriminating failure campaign includes: reserved-page release, double free, allocation of boot data, partial-allocation leak, stale mapping and exposure of nonzero reclaimed bytes. The gate is concrete: Exhaust a finite hosted map, show exactly 256 pages from [3 MiB,4 MiB), and execute zero-filled user allocation and process teardown in the guest.

Develop and assess the evidence in {ref}`PR-T48-04`.

### T48.05 — Ring-3 isolation and guarded user storage

A user-capable upper table does not grant access through a supervisor leaf. The selected process window is two MiB; static image, heap and guarded 128-KiB stack have separate regions. Kernel identity mappings remain supervisor-only. Writable user data is non-executable and executable text is not writable.

Construct the first privilege-return frame and enforce permissions at every mapping level. Run two instances that write different values at the same virtual address. Add a separate process that attempts to write the kernel load address.

A discriminating failure campaign includes: user bit propagated to a supervisor region, writable executable segment, wrapping extent, a cross-page buffer entering a guard and incorrect initial privilege flags. The gate is concrete: Show actual peer progress and a protection page fault at 0x100000 with present/write/user bits set, while both independent virtual data values survive preemption.

Develop and assess the evidence in {ref}`PR-T48-05`.

### T48.06 — Timer preemption with a nonpreemptible kernel

The timer regains control even when a user program never yields. Saving context and choosing the next runnable process are different mechanisms. The first scheduler is round-robin, one CPU and one thread per process; interrupts remain disabled inside the kernel. A long synchronous device operation therefore adds scheduler latency.

Configure the pinned PC timer/PIC, issue end-of-interrupt, retain each process frame, switch CR3 and kernel-stack ownership, then return to the next user. Separate explicit yield from timer-caused switches.

A discriminating failure campaign includes: no EOI, switching to a dead process, using another process kernel stack, dropping a register, confusing syscall frequency with cooperative yield and claiming hard real-time behavior from QEMU ticks. The gate is concrete: Two CPU-consuming workers that never call yield complete after observed timer ticks; their private memory values survive. Record timer-driven switches and nonpreemptible sections.

Develop and assess the evidence in {ref}`PR-T48-06`.

### T48.07 — Static ELF64 and a read-only boot archive

The loader consumes program headers, not section names. File bytes are copied into a checked virtual span and the remaining memory bytes start at zero. CMKA1 maps bounded unique names to non-overlapping image spans; it is a boot container, not a general filesystem.

Decode ELF64 little-endian x86-64 ET_EXEC images with at most eight load segments, fixed 4096-byte alignment and no interpreter, dynamic linking or TLS. Validate all segments before mapping. Package init, workers, fault control and shell.

A discriminating failure campaign includes: truncated header or payload, filesz greater than memsz, overlapping page mappings, entry outside executable storage, writable executable segment, duplicate archive names and payload/table overlap. The gate is concrete: Pass hosted truncation/extent cases and boot real independently linked ELF programs. Preserve zero-fill and rejected-image evidence separately.

Develop and assess the evidence in {ref}`PR-T48-07`.

### T48.08 — Bounded syscalls and revocable process handles

The syscall number selects a service; user data never selects an arbitrary kernel entry point. CMK uses int 0x80 with RAX number/result and three argument registers. Validate arithmetic and every page crossed before copying. A handle combines a slot and generation and becomes invalid after close.

Implement console, exit, yield, ticks/PID, page allocation, archive and block calls using the public header. Make the disk handle exclusive to init. Enforce read/write direction and reject high bits rather than silently truncating caller values.

A discriminating failure campaign includes: unknown call, foreign/stale handle, pointer into kernel memory, huge/wrapping byte count, read output into text and handle use after close. The gate is concrete: Actual user programs receive errors for kernel pointers, oversized allocation, unknown syscall and a closed handle; hosted generation checks reject stale tokens.

Develop and assess the evidence in {ref}`PR-T48-08`.

### T48.09 — Modern PCI virtio discovery and split queues

A device capability describes a register window, not permission to dereference arbitrary offsets. Discover the modern block device and required capabilities, negotiate VERSION_1 and FLUSH, then publish a split queue. One outstanding request makes descriptor and bounce-buffer ownership visible.

Inspect PCI capabilities with bounded traversal, reject unsupported transport/feature/extent cases, initialize an eight-descriptor queue and derive its DMA addresses from the declared identity mapping. Publish descriptors before advancing availability.

A discriminating failure campaign includes: treating a PCI access capability as a MMIO window, wrong feature bank, absent required feature, wrapped notification offset, premature buffer reuse and a completion naming the wrong descriptor. The gate is concrete: Retain actual negotiated status, queue addresses, descriptor identities and successful guest requests. A 16-bit index wraps from 65535 to 0 while the corresponding eight-slot position wraps from 7 to 0.

Develop and assess the evidence in {ref}`PR-T48-09`.

### T48.10 — Block completion, flush and persistence boundaries

The kernel block service moves exactly one 4096-byte page or reports failure. A virtio sector is a separate 512-byte unit. Successful completion of a write does not by itself close the declared durable-storage boundary; the store must request and observe flush.

Implement bounded read/write/flush requests with a static DMA bounce page. Validate capacity before multiplying a page index by eight. Poison the device on timeout and retain in-flight storage. Reboot with the same ordinary raw image.

A discriminating failure campaign includes: page beyond capacity, writable destination in kernel space, wrong sector units, missing flush feature, error status interpreted as completion and retry after losing DMA ownership. The gate is concrete: Write a patterned page, flush, read it, then boot a new guest and compare all bytes. Keep backend cache configuration and exact image identity; do not claim a physical power-loss test.

Develop and assess the evidence in {ref}`PR-T48-10`.

### T48.11 — Init, bounded console shell and teardown

Init and the shell are ordinary isolated ELF programs. The small shell owns a 64-byte command buffer, reads nonblocking console bytes and yields when no byte is available. The command set is help, echo and exit; overflow follows an explicit reset-and-report policy.

Package named init/shell images in the archive, implement a bounded line parser and exercise input through the real serial channel. Exit revokes capabilities and releases user frames after scheduling away.

A discriminating failure campaign includes: unterminated command, overlong input, duplicate image name, command-buffer reuse across an outstanding operation and freeing the currently active kernel stack. The gate is concrete: An automated interactive guest receives help and exit and produces the expected bounded response; hosted archive tests reject malformed tables.

Develop and assess the evidence in {ref}`PR-T48-11`.

### T48.12 — One portable VM core inside a user process

Porting means changing adapters while retaining the VM relation and bytecode. The kernel never interprets VM object references or accepts native addresses from bytecode. Its user process owns Cvm and program storage, supplies a bounded numeric callback and preserves separate instruction and host-call budgets.

Link the original T46 core into a freestanding ELF, audit compiler helpers and user stack usage, then execute a hand-encoded CVM1 program. Keep the hosted compiler outside this guest milestone.

A discriminating failure campaign includes: duplicated interpreter, silently linked libc, missing stack budget, arbitrary FFI pointer, failed callback returned as successful VM execution and an exhausted host budget ignored. The gate is concrete: Actual ring-3 execution computes 42 through a bounded callback and independently returns CVM_HOST_BUDGET with zero callback allowance. Record the shared source identity.

Develop and assess the evidence in {ref}`PR-T48-12`.

### T48.13 — VM, durable store and kernel reboot integration

The store owns B+tree pages, WAL and recovery; the kernel owns the block transfer/flush service. An exclusive adapter maps the 67-page store image to raw pages starting at 16. VM bytecode may request named store services but cannot choose a device page or kernel pointer.

Link T46/T47 cores in init with caller-owned static workspace. Execute bytecode that commits value 42, deliberately lose the callback success reply, restart the guest on the same disk, recover and read the value through bytecode.

A discriminating failure campaign includes: double-charged copied implementation, write without flush, bytecode raw-device access, unknown transaction outcome treated as definitely absent, wrong store-slice arithmetic and stack exhaustion from nested workspace. The gate is concrete: Preserve first-boot CVM_HOST_ERROR after the known committed callback, second-boot VM GET42, WAL recovery/store-check evidence and actual syscall/virtio image identities. This is a lost-reply experiment, separate from the store simulator crash matrix.

Develop and assess the evidence in {ref}`PR-T48-13`.

### T48.14 — Kernel diagnosis, negative controls and delayed transfer

A green image is one experiment. Diagnose entry failures, bad page permissions, malformed images, lost context and queue ownership at their first violated boundary. Keep host and guest results separate so a correct model cannot conceal broken assembly or an unexecuted device path.

Run the dual-compiler hosted matrix and real guest campaign, then introduce one controlled mutation at a time in a separate learner copy. Use GDB saved state and serial evidence to minimize the first causal divergence. Rebuild from a new directory.

A discriminating failure campaign includes: synthetic log substituted for guest output, source/image mismatch, timeout reported as pass, changed expected marker hiding a defect and a known fault reported as blind diagnosis. The gate is concrete: Reject learner stubs and corrupted ELF/handle variants; pass repaired host and guest gates. Complete a reviewer-held perturbation after seven days and annotate unresolved physical/SMP/general-OS claims.

Develop and assess the evidence in {ref}`PR-T48-14`.

## Environment and limits

The selected kernel is single-core, uses static ELF admission at boot and a nonpreemptible kernel. Synchronous bounded device polling may delay peers. There is no required SMP, general POSIX/filesystem/network stack, JIT, dynamic linker or physical-device conformance. User faults terminate the process; unexpected kernel exceptions stop the diagnostic image. QEMU-backed persistence and supplied crash models remain separately scoped.

# T61: Formal verification, falsification and fuzzing

## Purpose and outcomes

Construct verification arguments and deliberately falsify overstated claims. Prove small components under stated models, generate adversarial inputs, diagnose harness vacuity and distinguish a clean execution from a complete argument.

## Entry check and remediation

State a loop invariant and a decreasing variant for a bounded array search. Show a counterexample to the assertion that branch coverage proves correctness and explain signed overflow before enabling a solver.

## Study sequence and teaching

### T61.01 — Bitvector arithmetic and complete bounds

A checked operation needs both a successful arithmetic result and a failure contract. Proving only the success branch can hide output corruption on rejection. Solver bitvectors and mathematical integers must be related explicitly.

Derive the pre-add inequality without executing overflowing signed arithmetic. Prove unchanged output on failure as a separate postcondition and identify pointer validity assumptions.

Misconception and counterexample: Repair wrapping arithmetic that reports success and a harness that assumes away every overflow input. Demonstrate a witness satisfying the assumptions and violating the mutant.

Investigation: Implement vf_add(a,b,out) for uint32_t: return1 and sum when representable, else0 with unchanged output. Write a C Bounded Model Checker harness for every input and a sentinel output, with overflow checks enabled; separately exhaust a reduced8-bit domain and explain why that enumeration is not a proof for32-bit implementation code.

Evidence: Generalize to checked multiplication and mixed-width conversion, deriving a new precondition rather than mechanically substituting the addition predicate.

### T61.02 — Loop invariants and binary-search termination

Binary search correctness includes both location and termination. An interval representation determines how empty input, duplicates and the final insertion position behave. Comparing to a linear oracle independently checks the interval derivation.

Prove all indices below lo are<key, all at/above hi are>=key, and hi-lo strictly decreases. Derive memory bounds and handle duplicate values without changing the intended first-position contract.

Misconception and counterexample: A <= comparison implements upper_bound, which passes unique-key examples. An incorrect midpoint update can also loop forever on a singleton interval.

Investigation: Implement vf_lower_bound on a sorted nondecreasing uint32_t array, returning the first index with value>=key or n. Use half-open[lo,hi), calculate midpoint without overflow and retain O(log n) comparisons. Empty input permits a null array. Establish sortedness as a precondition, not a fact proved by a search test.

Evidence: Change to a descending comparator and an opaque record key; rederive the invariant and verify comparator consistency assumptions instead of copying inequalities.

### T61.03 — Stateful property harness and ownership

A stateful test must validate representation invariants after every accepted and rejected transition. Checking only final output lets transient corruption escape. Compare an implementation to a differently represented oracle.

Prove size conservation and rejection atomicity at each step; define ownership of queued elements separately from the scalar ring indices. Explain why an oracle sharing the same count representation could reproduce the defect.

Misconception and counterexample: The mutant permits a push into a full ring, producing size>capacity. A final pop-only test can conceal this intermediate violation.

Investigation: Implement vf_ring_step for VFRing with positive capacity, head<capacity, size<=capacity. op0 push rejects full and increments size; op1 pop rejects empty, advances head modulo capacity and decrements size. Reject invalid state or operation without mutation. Build a sequence harness using a Python list oracle and generation from valid/invalid transition classes.

Evidence: Add borrowed payloads with destructor callbacks and injected construction failure; extend the model to exactly-once lifetime obligations and reentrant callback restrictions.

### T61.04 — Parser fuzzing with semantic oracles

Coverage guidance steers execution toward new paths, but it does not define correctness. A fuzz target must reset state and check semantic properties rather than merely call a parser and wait for abnormal process termination.

Separate memory-safety, grammar, integrity and canonicalization properties; bound fuzz input processing without excluding empty, malformed or huge harness inputs.

Misconception and counterexample: The parser ignores checksum mismatch yet always returns normally, so sanitizer-only fuzzing misses the defect. The semantic oracle must reject the corrupted frame.

Investigation: Implement vf_frame for bytes[length,payload...,xor]. Require n>=2, length<=16, exact n=length+2 and bitwise exclusive-or of payload equal final byte; publish length only on success. Empty payload is valid with bytes[0,0]. Fuzz all inputs0..64 bytes, check round-trip canonical encoding on success and output sentinel on failure.

Evidence: Introduce streaming segmentation and state reset between repeated calls; compare every split with the single-shot decoder and minimize a split-sensitive mismatch.

### T61.05 — Counterexample minimization

A smaller reproducer helps identify the causal mechanism only if shrinking preserves the relevant failure predicate. Removing arbitrary bytes can change a memory bug into a parser error and lose the original finding.

Prove predicate preservation after each deletion and justify termination. Distinguish1-minimality from globally optimal shrinking and discuss order-dependent outcomes.

Misconception and counterexample: The faulty shrinker increments its index after deletion, skipping the shifted byte and leaving a removable element. A merely smaller result is not the stated minimality guarantee.

Investigation: Implement vf_shrink for an in-place byte vector of length at most65535 whose failure predicate is sum(bytes)>=threshold. Greedily remove each byte when the remaining sum still fails; retry the same position after removal. Return final length. If the original does not fail, leave it unchanged. The result is1-minimal under deletion, not globally shortest.

Evidence: Shrink an event schedule while preserving the same violated lifecycle invariant and first divergent transition, rather than preserving any nonzero exit.

### T61.06 — Bounded schedule exploration

A concurrency model must make atomic transitions and fairness assumptions explicit. Enumerating event permutations explores the model, not all compiler or hardware reorderings. A cancellation event does not establish terminal completion.

State the safety invariant released implies completed and derive every reachable state. Explain which liveness claims require a scheduler/environment assumption beyond finite enumeration.

Misconception and counterexample: The mutant releases on cancellation before completion, allowing a late callback to access released storage. A mutex alone does not fix the incorrect state transition.

Investigation: Implement vf_request for events0 submit,1 cancel,2 complete,3 release. Submit once; cancellation only after submit and before completion; complete once after submit whether or not cancelled; release only after completion and only once. Enumerate all event words through length6 and compare state/rejection to an independent transition relation.

Evidence: Split submission and publication into separate steps, add two actors and a weak-memory litmus; identify which additional ordering assumptions need model checking or target evidence.

### T61.07 — Deterministic fuzz harness composition

Fuzzing a stateful component in one process can make an input fail only after a prior input. Such history dependence is a real target property only when it is intentional; accidental global state corrupts reproducibility.

Derive the required isolation between fuzz invocations, including allocator cleanup and thread joining. Distinguish deterministic input-derived randomness from wall-clock seeding.

Misconception and counterexample: The mutant retains the prior hash globally, creating a history-dependent mismatch. A single fresh-process run passes and therefore misses the defect.

Investigation: Implement vf_digest(frame,n,out): validate with vf_frame, then derive a32-bit rolling digest starting from0 for that input only, digest=digest*33+byte across payload bytes. Preserve output on invalid input. Repeated A,B,A calls must give the same results for A. Keep corpus generation and sanitizer runtime outside the target dependency graph.

Evidence: Deliberately fuzz a multi-command protocol where history is meaningful; encode the entire session in one input and reset only between sessions.

### T61.08 — Proof claim audit and independent transfer

A tool reporting success is one item in a proof argument. Missing unwinding assertions or overrestrictive assumptions can make success much weaker than the claim. Verification coverage and semantic correctness are distinct.

Bind the claim to source, compiler/solver configuration, assumptions, model bound and checked properties. Explain why local self-reported flags cannot establish reviewer independence or tool honesty.

Misconception and counterexample: A receipt omits complete unwinding but labels a loop universally safe. Reproduce the missing iteration counterexample and narrow the claim before attempting a genuine inductive proof.

Investigation: Implement vf_claim(tool_success,unwinding_complete,assumptions_witnessed,unchecked_properties): accept a bounded-proof receipt only when the first three flags are exactly1 and unchecked count0. Use this predicate as a checklist, not a cryptographic verifier, and audit the saved C Bounded Model Checker/fuzz campaigns against actual logs and source hashes.

Evidence: Audit a new allocator or parser without the worked harness; choose proof, fuzzing and differential methods based on mechanisms and defend residual gaps after seven days.

# T47: Persistent storage engine and crash consistency

## Purpose and outcomes

Build a bounded B+tree store whose success and failure semantics survive a declared crash model. Derive byte encoding, ordered index invariants, memory/page bounds and persistence ordering before optimizing. This is one engine grown through small projects, not twelve independent database implementations. All values are length-delimited bytes; the C core has no SQL or external storage-engine dependency.

## Entry check and remediation

Implement a bounds-checked byte decoder, an ordered search invariant and a partial-I/O loop from memory. Explain object lifetime, unsigned conversion, stale cache data and why write return is not a persistence barrier. If these fail, return to T03/T15/T21 and reproduce the exact missing mechanism. T32/T43/T45 supply fault isolation, measurements and causal diagnosis. No prior database product experience is assumed.

## Study sequence and teaching

### T47.01 — A byte-exact page codec

Define the file before casting a pointer. Encode integer fields byte by byte into a 4096-byte page; a C struct is an in-memory representation whose padding and alignment are not a portable file format. Validate magic, kind, generation, page identity, count, key/value extents and CRC before interpreting references. CRC-32 detects the exercised tears but is not a cryptographic authenticity guarantee. The corruption model explicitly excludes checksum collisions. A fresh format and reopening an established image are separate operations: corrupted existing data must not silently become an empty database.

Complete [PR-T47-01](../projects/PR-T47-01.md). Keep three separate evidence items: derivation, executed implementation and repaired/transfer case.

### T47.02 — A bounded clean page cache

A cache hit means the requested physical page and the cached identity agree, not merely that two logical IDs collide in a slot. The four-entry direct-mapped cache retains only clean bytes. Transaction scratch owns dirty nodes separately. Publication switches reads from home to redo images; checkpoint switches them back. Both transitions invalidate cache entries. Count backend reads and hits rather than calling a warm run evidence of faster storage hardware. Bound cache memory as four full pages plus tags, independently of the transaction workspace.

Complete [PR-T47-02](../projects/PR-T47-02.md). Keep three separate evidence items: derivation, executed implementation and repaired/transfer case.

### T47.03 — B+tree lookup and ordered scan

All values reside in leaves. Internal separator i duplicates the smallest key in child i+1, so equality descends to the right child. Keys are length-delimited unsigned bytes: embedded zeros are ordinary data and shorter equal prefixes sort first. Tree descent and linked-leaf traversal are two independently checkable descriptions of the same ordered records. A cycle, dangling page or unreachable allocated node violates the representation even when one lookup succeeds. Bound descent and scan steps by the finite page count before following disk references.

Complete [PR-T47-03](../projects/PR-T47-03.md). Keep three separate evidence items: derivation, executed implementation and repaired/transfer case.

### T47.04 — Insertion, splits and root growth

Insertion maintains sorted keys within a leaf and increases height only when a root splits. With maximum seven keys, the eighth exists only in private split scratch. A leaf split yields four records on each side and copies the right minimum upward; an internal split promotes a separator and partitions child intervals. These are different operations. Reserve or recover capacity for propagation: a failed allocation cannot leave a half-published tree. This first implementation aborts the entire transaction on page exhaustion and refreshes separator minima over allocated nodes, explicitly adding O(P) work.

Complete [PR-T47-04](../projects/PR-T47-04.md). Keep three separate evidence items: derivation, executed implementation and repaired/transfer case.

### T47.05 — Deletion, redistribution and page reuse

Deletion may change an ancestor minimum even when no node underflows. Non-root leaves require four records and internal nodes require three separators. Borrow from a sibling with spare occupancy; otherwise merge, remove the corresponding parent separator/child and propagate the underflow. If an internal root loses its last separator, replace it with its only child. A freed page becomes reusable only after no tree or leaf-chain reference names it. The allocation bitmap and reachable-node set must agree after every transition.

Complete [PR-T47-05](../projects/PR-T47-05.md). Keep three separate evidence items: derivation, executed implementation and repaired/transfer case.

### T47.06 — Bounded no-steal transactions

Atomicity begins before logging: uncommitted nodes must never reach their home pages. store_begin loads live nodes into bounded typed scratch, records the prior root/allocation map and admits one writer. Input rejection leaves staged earlier work intact; capacity failure aborts the complete transaction. This explicit difference belongs in the API contract. The caller serializes all access, including readers; there is no hidden locking or snapshot mechanism. Scratch, clean cache, I/O buffers and C call stack have separate memory bounds.

Complete [PR-T47-06](../projects/PR-T47-06.md). Keep three separate evidence items: derivation, executed implementation and repaired/transfer case.

### T47.07 — Full-page redo and commit outcomes

A successful write callback reports transfer acceptance; only a successful flush establishes the declared persistence barrier. Invalidate and flush the prior marker before reusing redo space, write and flush every after-image, then write and flush the new commit marker. Before marker publication an error is a definite abort in this model; after attempting publication it is indeterminate. The caller may not infer absence from a lost acknowledgment. The live handle reads committed redo images until checkpoint. Full-image logging has a simple bounded recovery argument and deliberately high write amplification.

Complete [PR-T47-07](../projects/PR-T47-07.md). Keep three separate evidence items: derivation, executed implementation and repaired/transfer case.

### T47.08 — Checkpoint generations and reclamation

Checkpoint moves already committed state; it does not decide whether a transaction committed. Validate the complete redo batch before changing home pages, copy and flush all home images, write and flush the alternate generation record, then invalidate and flush the log marker. The old generation survives a torn replacement; retained WAL repairs incomplete home writes. Reclaiming the log earlier destroys the only complete explanation of a mixed home image. Two slots are sufficient for this serialized bounded design, not a general concurrent checkpoint algorithm.

Complete [PR-T47-08](../projects/PR-T47-08.md). Keep three separate evidence items: derivation, executed implementation and repaired/transfer case.

### T47.09 — Recovery and repeated interruption

Recovery is a state machine that may itself fail. A valid newer marker names a complete after-image batch; every image is checked before the first home write. Full-page replacement is idempotent, so a second crash during replay can restart from intact log evidence. Generation mismatches, corrupted committed images and I/O failure are errors. Invalid incomplete marker bytes before any home writes can be ignored under the declared ordering model. Corruption after acknowledged persistence is a different fault class and must not be turned into an old-or-new success claim.

Complete [PR-T47-09](../projects/PR-T47-09.md). Keep three separate evidence items: derivation, executed implementation and repaired/transfer case.

### T47.10 — Crash schedules and adversarial oracles

A crash test needs a semantic oracle and a persistence model. The model maintains stable and pending pages, permits reordering unsynchronized writes and can return an error after partial or complete persistence. The suite walks every write/flush boundary of selected transactions and applies five representative patterns. Its independent key/value oracle checks old/new state, not merely whether opening succeeds. These finite schedules do not enumerate every possible tear offset or pending subset; the ordering proof and measured test coverage have different roles.

Complete [PR-T47-10](../projects/PR-T47-10.md). Keep three separate evidence items: derivation, executed implementation and repaired/transfer case.

### T47.11 — Linux file I/O and amplification

The POSIX adapter translates one logical page operation into a loop of byte transfers. Positive short transfers advance progress; EINTR retries the interrupted operation; zero progress or an error terminates with failure. A successful fsync is the adapter persistence promise, conditional on the underlying stack honoring it. An existing preallocated file avoids mixing transaction recovery with file creation and directory persistence. Compare requested bytes, accepted bytes, synchronization count and useful changed payload; whole-image WAL naturally amplifies a tiny value update.

Complete [PR-T47-11](../projects/PR-T47-11.md). Keep three separate evidence items: derivation, executed implementation and repaired/transfer case.

### T47.12 — VM and kernel storage boundaries

The VM may invoke two narrow host services: encode an integer under vm-result and read it back. Host-call budget, storage capacity and persistence outcome are independent contracts. No arbitrary pointer or path crosses the bytecode interface. The kernel adapter exposes complete page read/write and flush operations for an exclusive image slice; it validates user buffers and device completion. Reusing the store core preserves its invariants only when the new adapter satisfies the same durability model. Component success does not automatically certify the VM or device integration.

Complete [PR-T47-12](../projects/PR-T47-12.md). Keep three separate evidence items: derivation, executed implementation and repaired/transfer case.

## Environment and limits

One exclusive caller serializes all accesses. Fixed capacities, seven-key nodes and full-image redo favor observable mechanisms over production throughput. Successful flush persists all preceding writes; tears affect only addressed pages; checksum collisions, lying flushes and later media corruption lie outside the atomicity argument. The harness samples five admitted persistence patterns at each selected write/flush boundary. It is not exhaustive over arbitrary subsets or tear positions and does not cut physical power. The preallocated-file route tests Linux API/reopen behavior; initial pathname durability and concurrent-process locking are separate. A complete runtime receipt records compiler/options/source hashes and actual results. Python contract checks do not replace those runs.

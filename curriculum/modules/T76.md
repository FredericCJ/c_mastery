# T76: Replicated state, event history and deterministic replay

## Purpose and outcomes

Build and explain the representations and state transitions below, preserving the imported artifact contracts. The complete exercises are core work; descriptive hours do not cap depth. Distinguish ISO semantics, implementation diagnostics, runtime checks and programmer discipline.

## Entry check and remediation

Derive ownership through a failed acquisition and a retained borrow using the prerequisite artifacts. State the backing lifetime, aliasing and failure contract before composing the prerequisite artifacts.

## Environment and limits

Use profile A: hosted Linux x86-64 and ISO C17 with 8-bit bytes, 32-bit int and uint32_t/uint64_t. The [replicated laboratory contract](../../labs/replicated/CONTRACTS.md) states exact aliasing, publication and stable-arena requirements. GCC and Clang debug, release, ASan/UBSan and separate TSan profiles are declared. Core state transitions are serialized; the supplied projection adapter uses one real pthread mutex across state and cursor publication. Python, CMake and diagnostic runtimes are host tools, and no target hash, CRDT or replication library may replace the implemented mechanisms.

The memory log retains at most 16 events and 17 roots in the actual imported persist.hamt arena, whose 64-node capacity and three-node update rule remain binding. Select the completed DOD learner workspace explicitly; assessor-selected dependencies are author validation only. Clock/PN models use three replica identities, the observed-remove set has two writers with eight nonreused add identities each, sequences have 16 nodes, and the original message grammar has at most eight fields. SHA-256 is assessed over the specified 0..65-byte inputs and Merkle trees over 0..8 leaves; these bounds do not establish a general-purpose cryptographic implementation.

Single-writer identity ownership, retained tombstones and live immutable snapshot roots are premises, not Byzantine admission or persistence mechanisms. Timestamp order does not imply causality; hash equality does not authenticate a sender; pairwise operational transformation checks do not prove a complete distributed editor. Required storage.pages, codec.records, io.frame, ipc.local and effect-adapter investigations need separate short-I/O, process-termination and recovery evidence under a declared persistence model beyond the in-memory campaign. Keep all experiments local with synthetic messages. Finite hosted tests establish neither deployment safety nor learner mastery; exact published C17/C23 text and physical/remote-system validation remain outside the inspected evidence.

## Study sequence and teaching

### T76.01 — Positioned event logs and persistent snapshot roots

Distinguish immutable event history, a current projection, a retained snapshot root and durable storage. Derive why replay requires event-version and external-query assumptions, not merely a list of bytes.

Append(3,7),append(3,9): prefix1 returns7 and prefix2 returns9. Inject each allocation ordinal1..3 on the next append: count stays2, used count is restored and prior roots still resolve. The17th append returns RP_FULL without consuming nodes.

Construction: Retain the actual PR-T70-07 learner artifact and its64node/3nodes-per-update contract. Prove16 appends use48nodes, every published root remains immutable and an interrupted failed append cannot advance count. Initialization requires no surviving borrowed roots; do not copy/relocate a live arena and interpret roots in another owner. Account for unpublished cells and allocation counters separately from reachable state. State a release/publication order for a future concurrent adapter. The full assessed work is {ref}`X-T76-001`.

Misconception: A retained root is a memory snapshot, not a durable transaction.

Evidence: Run replicated.log and the three allocation-cut assertions, compare every prefix against an independent key/value dictionary and rebuild into a fresh arena. Reject count-before-commit and latest-root-for-all-snapshots mutants. Inspect source/link dependencies to establish that the real imported hash array mapped trie is used. Separately implement the required codec.records/storage.pages adapter with short writes and process-stop schedules at write, flush and publication boundaries; the memory anchor does not validate that adapter.

### T76.02 — Command–query responsibility segregation projection admission and atomic position advancement

Separate query-model choice from delivery semantics. Establish exactly-once application only within one serialized projection and one retained immutable log identity; reject the stronger claim of exactly-once external effects.

Apply(1,0,7) twice yields total7,count1. Reuse position1 with8 conflicts; position3 before2 is a gap. Two synchronized threads each delivering values1..16 yield count16,total136;128 fresh concurrent runs test the adapter.

Construction: Prove the invariant count=k implies exactly the first k events contributed once and applied[i].position=i+1. A 16-term int32 sum fits int64 on the declared target. Retain history for conflict checks rather than trusting a reused position from a new log. The caller must associate a projection with one log identity. Explain why a mutex around cursor alone is insufficient, and why an external email/file effect cannot become atomic with this state by naming it command–query responsibility segregation. The full assessed work is {ref}`X-T76-002`.

Misconception: Command–query responsibility segregation separates models; it does not supply delivery or storage atomicity.

Evidence: Run replicated.projection, including actual pthread schedules under GCC TSan when available. Kill duplicate-reapplication and gap-acceptance mutants with semantic assertions. Record mutex boundaries and model process termination between query-state and cursor persistence. A TSan pass observes these executions only; it does not certify arbitrary effects or all schedules.

### T76.03 — Lamport, vector and hybrid logical clock boundaries

Derive three different clock contracts: Lamport timestamps preserve happened-before in one direction, vectors characterize causality under fixed known membership, and hybrid logical clock pairs retain a physical component without eliminating physical-clock assumptions.

Lamport(2,8)=9. Vectors[1,0,0] and[0,1,0] are concurrent; receive at replica0 gives[2,1,0]. For a hybrid logical clock, local(10,2),remote(10,7),wall9 gives(10,8); wall11 on a subsequent local event resets logical to0. UINT32_MAX logical overflow fails unchanged.

Construction: Show two concurrent events with ordered Lamport timestamps, two incomparable vectors and every hybrid logical clock equality case. Separate physical-clock closeness claims from the synchronization assumptions in Corollary1. On local overflow choose explicit failure; neither arbitrary sleep nor silently increasing physical time is equivalent. Outputs are ordinary C structs, so validity and per-replica serialization remain caller obligations. The full assessed work is {ref}`X-T76-003`.

Misconception: Timestamp order is not the converse of causal order.

Evidence: Run replicated.clocks and independent exhaustive small hybrid logical clock branch enumeration plus uint64/uint32 extrema. Kill ignoring-remote Lamport and incorrect equal-physical HLC-counter mutants. Build small message histories and derive causal relations from graph reachability before comparing clock outputs; timestamp ordering alone is not the oracle.

### T76.04 — Join-semilattice counters and deterministic registers

Derive convergence from explicit componentwise joins and globally unique writer identities, and distinguish state merge from replaying operations. A last-writer register resolves an order chosen by the protocol, not necessarily real-time recency.

Replica0 adds5; replica1 subtracts3. Merge yields2 and repeating the same merge remains2. Register(7,0,1) joined with(7,2,9) chooses9; another payload at(7,2) is a conflict. Adding UINT32_MAX to component5 fails unchanged.

Construction: Prove idempotence, commutativity and associativity on admitted compatible states, plus inflation of each grow-only component. Explain why sum of received states double-counts retransmission, why finite overflow must reject, and why a reused writer identity with forked state violates the ownership model. For registers identify conflict cases outside the unique-event assumption and the total-order tie rule. The full assessed work is {ref}`X-T76-004`.

Misconception: A unique replica label is an ownership obligation, not a property of an unsigned field.

Evidence: Run replicated.counters; enumerate small component states and three-way merge permutations, including duplicate, reordered and dropped-then-retransmitted messages. Kill additive-state-merge and missing replica tie-break mutants. Show a counterexample for unchecked uint32 wrap and for independent writers sharing one replica slot.

### T76.05 — Observed-remove sets and replayable delta state

Explain add-wins observed removal through unique add identities, retained tombstones and idempotent delta joins. Distinguish a causally self-contained delta representation from arbitrary partial operations or unsafe tombstone collection.

Replica0 adds value2; replica1 observes it. Replica0 removes while replica1 concurrently adds its own tag. Join retains value2. Removing after observing both tags and replaying either old add delta does not resurrect it. The ninth add by one replica fails without resetting its identity counter.

Construction: Define membership as adds minus removed. Derive why a concurrent unobserved add survives removal and why an observed add cannot resurrect when its delta arrives again. Treat one writer per replica as a premise. The bounded delta carries exact tag tombstones, so remove-before-add delivery is representable; do not infer this for all causal CRDTs. Explain the delta-interval causal precondition from the paper and specify acknowledgment/stability requirements before reclaiming history. The full assessed work is {ref}`X-T76-005`.

Misconception: Deleting tombstones is not ordinary memory cleanup; delayed messages can resurrect state.

Evidence: Run replicated.sets and enumerate two-writer add/remove/delivery traces against a mathematical tagged-set oracle. Include duplicate and remove-before-add delivery. Kill remove-all-possible-tags and omitted-tombstone-merge mutants. Inventory retained tags and show the exact full condition rather than silently dropping history.

### T76.06 — Replicated sequence identities and contextual transformation

Separate stable sequence identity from transient visible position, and compare a bounded parent-tree sequence with context-dependent operational transformation. Pairwise insertion agreement is a necessary local property, not a complete operational transformation correctness theorem.

Insert A(id1,parent0),B(id2,parent0),C(id3,parent1) in either admissible arrival order: render BAC. Delete id1: render BC, retaining descendant C. Two inserts at position0 with priorities1 and2 transform the higher-priority-number insertion to position1.

Construction: Derive acyclicity from parent<id and closure from causal admission. Prove insertion-order-independent rendering for a fixed admitted node set, including descendants of deleted anchors. Explain that this original tree contract is RGA-inspired, not a claim to implement every detail of Specification19. For operational transformation derive the two-branch diamond under distinct priorities and identify the state-vector/log context needed beyond it. The full assessed work is {ref}`X-T76-006`.

Misconception: Two correct transformed insertions do not establish a complete distributed editor.

Evidence: Run replicated.sequence; enumerate topological arrival orders and deletion subsets against a recursive tree oracle. Kill arrival-order sibling rendering and deleted-subtree omission mutants. Check full capacity, duplicate identity, missing dependency and output failure atomicity. Enumerate both paths of the two-insert operational transformation diamond, then provide a three-operation context counterexample to an unjustified generalization.

### T76.07 — Merkle commitments and bounded anti-entropy

Derive a domain-separated Merkle root for an exact ordered leaf sequence, distinguishing hash equality under a collision assumption from identity authentication, availability or a proof that arbitrary bytes are well formed.

SHA256(empty)=e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855. Trees[1,2,3] and[1,2,9] differ only at bit2 (mask4); empty trees give mask0. Compare every count0..8 with a separately implemented Python hashlib construction.

Construction: Derive padding across55/56/63/64/65-byte boundaries, uint32 modular arithmetic, round constants and endian conversion. Prove the tree shape for non-power-of-two counts and that a subtree comparison is meaningful only with the same position/range/domain. Account for hash collision and corrupt-peer assumptions; a matching root alone authenticates no sender and guarantees no retrievability. The full assessed work is {ref}`X-T76-007`.

Misconception: Content addressing does not authenticate who supplied content.

Evidence: Run replicated.merkle, standard empty/abc hash vectors, all padding boundaries and independent randomized hashlib differential cases. Kill omitted leaf-domain prefix and ignored right-child mutants. Inspect the generated code for the intended unsigned operations; benchmark nodes hashed versus full leaf comparison under equal correctness/security contracts.

### T76.08 — Field tags, minimal varints and canonical bytes

Distinguish a wire grammar from one canonical encoding and show why deterministic serialization under one binary is not a universal content identity. Derive portable signed ZigZag arithmetic without signed-left-shift assumptions.

Bytes18 07 10 01 08 96 01 (hex) decode and canonicalize to08 96 01 10 01 18 07. 08 80 00 10 01 is rejected as nonminimal. ZigZag(-1)=1, INT32_MIN maps to UINT32_MAX, INT32_MAX maps to UINT32_MAX-1.

Construction: For five-byte uint32 varints require the final payload<=15 and no continuation. Derive ZigZag using unsigned conversion/shift and a sign mask; decode odd values as -(value>>1)-1 to include INT32_MIN safely. Prove canonical decode/reencode idempotence and uniqueness for the admitted semantic map. Explain the tradeoff of rejecting duplicate fields compared with protocols that merge repeated occurrences. The full assessed work is {ref}`X-T76-008`.

Misconception: A serializer can be deterministic within one build without being canonical across versions.

Evidence: Run replicated.wire and an independent Python parser/encoder for boundary values and reordered field maps. Kill overlong-varint acceptance and incorrect negative ZigZag mutants. Enumerate every truncation, duplicate field, forbidden tag/wire type and output-capacity boundary; demonstrate two noncanonical orders producing the same canonical bytes.

### T76.09 — Pure reducers, explicit effects and rollback replay

Implement the T20.03 functional-core boundary: explicit state and recorded input produce new state and effect requests, while an adapter owns effects. Demonstrate rollback equivalence without replaying externally visible effects or claiming that ordinary C enforces purity.

Initial(0,0,0,1),movement-1 gives position15,random1015568748,score0; next movement1 gives position0,score3. Eight inputs[1,1,0,-1,1,0,1,-1] produce score12. Replacing input4 with1 and replaying from the prior snapshot equals a fresh corrected fold. All six checkpoint failure cuts preserve the published root and used count.

Construction: Prove determinism from complete state/input and defined unsigned arithmetic. Identify every effect boundary and distinguish speculative requests from committed presentation. Derive rollback of the hash array mapped trie used cursor after a failed second update while preserving old reachable roots; staged unreachable arena cells and allocation counters may differ. All arena users must be quiescent during the transaction, and roots from unpublished intermediate updates must never escape. Score overflow or invalid movement must not partially publish a state/effect. The full assessed work is {ref}`X-T76-009`.

Misconception: A pure core helps replay; it does not make a failing effect adapter transactional.

Evidence: Run replicated.replay and exhaustively compare all movement histories of length0..8 with a Python integer model; verify suffix rollback versus full replay. Kill omitted random-score contribution and failed second-update allocation-leak mutants. Build a synthetic effect adapter with idempotency key(timeline,tick) and injected failure; record one duplicate-effect counterexample if replay directly invokes the adapter. Inspect undefined symbols to confirm the core has no time/random/I/O dependency.

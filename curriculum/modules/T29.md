## Purpose and outcomes

Construct bounded communication protocols between foreground, interrupts and DMA. A correct queue or buffer lifecycle needs an ownership/order argument as well as observed latency.

## Entry check and remediation

Complete the selected T25 race, atomic-support and memory-order leaves below before projects. Draw a release/acquire publication and explain why volatile alone is insufficient; inspect target helper/lock-free support. Complete T27/T28 bring-up/driver contracts, then decode a basic frame and numeric priority. The full pthread, mutex and condition-variable laboratory route is not a prerequisite.

## Study sequence and teaching

### T29.01 — Exception entry and return

Exception entry saves an architectural frame before the handler's compiled prologue creates its own stack use. Decode the teaching eight-word basic frame as r0–r3, r12, lr, pc and xPSR, and inspect EXC_RETURN to decide which stack/frame variant applies. A backtrace that ignores an extended floating-point frame can read the wrong PC. Compare nested event/frame fixtures with an actual core trace and label which state hardware saved versus software preserved.

Apply this mechanism in [PR-T29-01](../projects/PR-T29-01.md).

### T29.02 — Interrupt routing and priorities

Routing and priority must be reasoned about in the target's convention: lower numeric Cortex-M priority values mean higher urgency, and only implemented priority bits matter. Enable/pending/mask states are separate. Build a nesting timeline and inspect the FreeRTOS CM4F priority validation before selecting ISR APIs. Giving every interrupt priority zero defeats threshold masking assumptions. Evidence includes the configured grouping, implemented-bit readback and the ordered handler trace.

Apply this mechanism in [PR-T29-01](../projects/PR-T29-01.md).

### T29.03 — ISR design

An ISR should acknowledge the hardware cause, capture bounded information and defer expensive work. A burst of interrupts can exhaust a queue even when each handler is short. Implement a handler that captures one event and increments a dropped-event counter when full, with formatting/processing in foreground. Reentrant callbacks or a printf in a handler can import hidden blocking and stack costs. Retain worst-path disassembly/call graph and a burst/overflow trace, with measured latency identified as measured.

Apply this mechanism in [PR-T29-02](../projects/PR-T29-02.md).

### T29.04 — Critical sections

Critical sections protect a stated invariant against particular participants. Save and restore the prior interrupt-mask state; unconditionally enabling interrupts on exit breaks a caller's outer critical section. A BASEPRI threshold can leave higher-urgency interrupts active and does not stop DMA. Model nested masking and an interrupt update, then audit the target primitive and generated instructions. Evidence names which accesses are excluded, which remain possible and why the region is bounded.

Apply this mechanism in [PR-T29-02](../projects/PR-T29-02.md).

### T29.05 — Shared foreground/ISR data

Foreground/ISR communication needs an ownership protocol and target-specific atomic support. Release publication followed by an acquiring observation is a useful hosted model, but embedded interrupt semantics and lock-free instruction/runtime behavior require the selected compiler/core contract. Check width/alignment and helper symbols before using atomics in an ISR. Volatile alone is not this argument. Draw the publication relation and test a deliberately premature publish that exposes uninitialized payload.

Apply this mechanism in [PR-T29-03](../projects/PR-T29-03.md).

### T29.06 — ISR-safe queues

For a one-producer/one-consumer queue, each context owns one index and publishes payload before exposing the new head. Use N slots with one deliberately unused slot, so usable capacity is N-1; choose drop-newest and count drops. Exercise wraparound and consumer pauses against a simpler sequence model. A modulo index equality cannot distinguish full from empty without a policy. Evidence includes no partially published elements, exact FIFO order and tested overflow behavior.

Apply this mechanism in [PR-T29-03](../projects/PR-T29-03.md).

### T29.07 — DMA ownership

DMA and CPU are different participants: prepare data/descriptors, publish only when the device can see them, then withhold CPU reuse until device completion or confirmed stop. A cancellation request is not cancellation completion. Implement generation-tagged buffer ownership and inject completion after cancellation request. Evidence must demonstrate one terminal outcome per generation, preserved partial byte counts and no new transfer reusing a still-owned buffer.

Apply this mechanism in [PR-T29-04](../projects/PR-T29-04.md).

### T29.08 — Ordering and coherency

Compiler ordering, CPU barriers, cache maintenance and mutual exclusion solve different problems. This selected F439 Cortex-M4 path has no CPU data cache to flush; that does not eliminate bus ordering or DMA-accessible-memory requirements. Compare its contract to a declared synthetic cache-equipped target without issuing fictitious cache operations on the F439. Evidence separates each visibility edge and documents barrier purpose; 'add DSB everywhere' is neither a protocol nor a performance argument.

Apply this mechanism in [PR-T29-04](../projects/PR-T29-04.md).

### T29.09 — Timestamp and event consistency

A multiword timestamp can tear if an interrupt updates one half between foreground reads. The fixture's hi-lo-hi method retries when high words differ; rollover interval bounds and event sequence numbers expose missed samples. Implement coherent snapshots and mark events whose relative order remains uncertain within the acquisition window. A stable number is not necessarily the exact physical event time. Retain counter-wrap, torn-read and missing-event traces with stated uncertainty.

Apply this mechanism in [PR-T29-05](../projects/PR-T29-05.md).

### T29.10 — Race and latency validation

Logical races need controlled schedules; physical latency needs a physical clock/trace. Delay servicing, pause foreground consumption and cancel near completion in the logical adapter, then replay relevant bursts on the board. Correlate software sequence numbers with scope/logic-analyzer edges while accounting for instrumentation. A passing stress run cannot prove all interleavings or establish WCET. Keep the written protocol argument beside observed distributions and every unreproduced assumption.

Apply this mechanism in [PR-T29-05](../projects/PR-T29-05.md).
